## Why

Upstream's Linux CI job now needs its self-hosted runner, so it skips on our PRs. Main has merged 93 PRs since our last all-PR Linux check (PRM-023/PRM-024, on 82ddae75b6 and 66e290f1c0), and most of our heads have moved since: merges of main, and review fixes. Every PR still merges cleanly with main on GitHub, but a clean merge can still break behaviour (on 2026-10-16, #6366's clean merge broke five of its own tests). This task is the CI Linux job for each PR below, on one fixed main.

## The main to use: e1ac3300d3

Use upstream main **e1ac3300d3** (Merge pull request #6224) for every PR, so the results stay comparable. cloud-3's READY run is its baseline: 1,328 tests, 1,256 passed, 65 skipped, 7 failed. The failures are the 5 IPv6 tests, `agc_driver_preparation_scope_settle` under load and `guest_kernel_fcntl` when stdin isn't /dev/null; `check_skips.py` flags only `guest_sce_net`. If you aren't cloud-3, or your machine lost that build, first build e1ac3300d3 in its own tree and run the same steps once for your own baseline. Keep main's tree separate from the PR tree.

Remotes: `origin` is the fork EagleBearerYS/AnyPS5; `upstream` is boykopovar/AnyPS5 (fetch only). PR heads are `upstream refs/pull/<n>/head`.

## For each PR, in the table's order

1. In a scratch tree: `git fetch upstream pull/<n>/head`, `git checkout -f --detach e1ac3300d3`, then `git merge --no-ff --no-edit FETCH_HEAD`. Write down the head you got. If it differs from the table, test it anyway and say so. If the merge isn't clean, report the conflicting files and go to the next PR.
2. Build incrementally with your baseline's configure: CI's flags, the wild linker, ccache.
3. `python3 tools/check_test_registration.py build`.
4. The full test run with the same command as your baseline (as `runner`, stdin from /dev/null, `--timeout 120`, 4 in parallel, `--output-junit ctest.xml`), then `python3 tools/check_skips.py build/ctest.xml`.
5. The PR's own tests with `--repeat until-fail:10`, unless the table says otherwise. That means the ctest names in the table, plus any other ctest whose executable is built from a test source the PR changes. Find those with `git diff --name-only e1ac3300d3...FETCH_HEAD` and `ctest -N -V`.
6. Rerun each failure that isn't in the baseline alone 5 times in the PR's tree and 5 times in main's tree. A failure is the PR's only if main passes it.
7. Where the table names main code the PR meets, read both sides and say in one line whether they compose (file:line on both sides).

Known noise: list it, don't chase it. That's the baseline's 7 failures and its `guest_sce_net` skip, and `agc_driver_tessellation`. This machine has no IPv6 and no /dev/udmabuf (shared direct memory is copied).
