## Decisions already made (don't revisit)

1. **Flush:** flush every staged file before the swap with the same calls libc uses (`FlushFileBuffers` on Windows, `fsync` on POSIX; see `core/libs/prx/libc/src/General.cpp` ~478 and ~498). On POSIX also `fsync` the staged directory and the backup root after each rename. Windows can't flush directory entries; the debt entry says so (decision 6).
2. **Links and reparse points:** before any delete or copy, every root (the `_sd` save store, the backup, staging and old dirs) and every entry being touched must be a real directory or file. A symlink (`std::filesystem::symlink_status`) or, on Windows, a `FILE_ATTRIBUTE_REPARSE_POINT` (the pattern in `core/libs/prx/libc/include/RemoveTree.hpp` and libc's `Directory.cpp`) makes the call return `SAVE_DATA_ERROR_INTERNAL` with nothing changed. Also check that `weakly_canonical(entry)` stays under `weakly_canonical(root)`. Copies become a recursive walk that refuses any link instead of following it (no `std::filesystem::copy(..., recursive)` over unchecked trees).
3. **Test hook:** add `void SaveDataSetFileStepHook_nid_no_patch(...)` to libSceSaveData.native, called before each copy and rename of the backup/restore paths with a step name, so a test can make a chosen step fail. It does nothing unless a test sets it, like `GuestArenaSetHostReadHook_nid_no_patch` (`core/libs/prx/libc/include/GuestArena.hpp:74`).

## The six commits, in order

1. **fix(libSceSaveData): validate backup metadata before Check and Restore read it** (point 4). An empty backup directory, a missing `.param` or a wrong-sized `.param` gives `SAVE_DATA_ERROR_INTERNAL` from `sceSaveDataCheckBackupData` and from `sceSaveDataRestoreBackupData`, whether or not the caller asked for `param`. Return the error instead of throwing, and check it before anything in the live save changes. Tests: those three corrupt-backup cases for check and for restore, the restore leaving the live save byte-identical.
2. **fix(libSceSaveData): restore a backup through a staged copy and roll back a failed swap** (point 1). Copy the backup, its `.param` and its blocks file to a staging path next to the save, and check the copy is complete. Then rename the live save aside, rename the staged copy into place and remove the old one. If a rename fails, put the old one back. Tests: a failed copy (hook) leaves the live save as it was; restoring into a missing save directory gives `SAVE_DATA_ERROR_INTERNAL`; a successful restore still matches the backup.
3. **fix(libSceSaveData): put the old backup back when the backup swap fails, and flush before removing it** (point 2). In `backupSave`, if `rename(staged, entry)` fails, rename `old` back to `entry`. Flush per decision 1 before `RemoveTree(old)`. Tests: a hook-driven failure at each rename step leaves a usable previous backup; repeated backups rotate correctly (three in a row, each replacing the last).
4. **fix(libSceSaveData): keep save and backup paths inside their roots** (point 5, decision 2). Tests: an outside sentinel directory behind a symlinked `_sd/<dir>` (POSIX) or a directory junction (Windows; reuse the junction helper in `core/libs/tests/GuestWindowsDirectoryLinkTypes.cpp` ~44-55, or `GuestFilesystem.cpp` ~1213). Restore and backup must return `SAVE_DATA_ERROR_INTERNAL`, and the sentinel and its files must survive. Skip the junction case only if creating it fails.
5. **test(libSceSaveData): cover the backup calls' guest errors and rotation**, for behaviour that already works:
   - a second `sceSaveDataUmountWithBackup` replaces the first backup;
   - a failed backup copy (hook) gives the event error `SAVE_DATA_ERROR_INTERNAL` while the call returns 0;
   - another title's `titleId` gives `SAVE_DATA_ERROR_NOT_FOUND`;
   - `..` and `a/b` as directory names give `SAVE_DATA_ERROR_PARAMETER` for all three new calls;
   - `static_assert` size and offset checks for the two new argument blocks in `core/libs/SceTypes.hpp` (keep the existing PS4-source / PS5-unverified note).
   If a case here fails on 5fed277cf2's code, it's a bug: fix it in the same commit and say so in your result.
6. **docs(libSceSaveData): say how a failed restore or a crash leaves the save** (point 3), in `docs/dev/debt/libSceSaveData.native.md`: what a failed restore leaves (live save untouched), what a crash mid-backup or mid-restore leaves, and that on Windows directory entries can't be flushed, so crash safety there rests on NTFS journaling and isn't shown. Keep the existing "follows shadPS4" lines.

Put the tests in `core/libs/tests/GuestSaveDataMountStatus.cpp` (its `CheckBackups()` at ~270) or a new case called from `main()`. Keep the ctest name `guest_savedata_mount_status`. If you add a new ctest, register it next to its siblings in every list they're in, the `if(WIN32)` PATH list included.
