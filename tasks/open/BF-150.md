## Why

Rush 2 Recompiled (PPSA69423) and Wave Race 64 Recompiled (PPSA69424) stop on Windows within 10 s with `AGC graphics: initial multisampled DCC contents require watched guest memory` (https://github.com/boykopovar/AnyPS5/issues/9724, MaxLikesCode).
- **The import:** their multisampled color target's memory (`0x4006200000+0xc4000`, 784 KiB) is host-imported by map. It's under the 1 MiB settle floor (`settleFloorBytes`, `GuestBufferMemory.cpp:860` on main 8b3e39832a), so it's compared.
- **The settle:** it returns to the write watch only when a later lookup reaps the deferred 4-byte settle read (`settleUnwatchedImports`, fcaa432840, our #6678). The title's first draw to the target comes before that.
- **The refusal:** `initialDccClear` refuses unwatched ranges (`MultisampleTarget.cpp:497`).
- **The reporter's experiment:** with `settleFloorBytes` = 0x1000 locally, both titles pass this stop and reach the FMASK stops that #7948 and #8429 cover.

**MarcZX10 prefers option 1** (https://github.com/boykopovar/AnyPS5/issues/9724#issuecomment-6338234700): settle synchronously when the initial DCC import needs the range.
- It needs a well-defined ordering point against earlier main-queue accesses.
- It should be coordinated with #8527.
- **His test:** a Windows regression where a genuine sub-1 MiB imported range still has a pending settle when initial DCC handling begins. Verify the clear result, and that later writes stay tracked. Keep the explicitly unwatched negative case (`AlphaToCoverage.cpp`).

**We offered to build it on #8527** (https://github.com/boykopovar/AnyPS5/issues/9724#issuecomment-6342460532). #8527 (eliasbruno124-dev) moves the deferred settle reads onto the main queue with barriers. That gives the synchronous settle its ordering point. eliasbruno124-dev hadn't answered by 16:00Z, so we go ahead.

**MarcZX10's matrix** (https://github.com/boykopovar/AnyPS5/issues/9724#issuecomment-6345204139, 15:58Z). babyhuey hit the same stop on Linux with lavapipe (https://github.com/boykopovar/AnyPS5/issues/9724#issuecomment-6340976890). Linux has no deferred settle: there the import-watch probe picks comparison mode. MarcZX10 asks:
- keep the reproductions split by the `[write-watch] host imports resolve write protection` result;
- cover (1) a Windows watched import with a pending deferred settle, and (2) a Linux comparison-mode import;
