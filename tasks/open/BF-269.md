## Why

On 2026-10-29 sktharunbalaji13-cmd reported a Ghost of Tsushima Director's Cut (PPSA02225) run, on our #9742 (comment 6491543723) and on I#5166 (6491557320). RTX 4060 8 GB, Windows.
- **Their env:** `APS5_HOST_IMPORT_MIB=0 APS5_WORKING_SET_MIB=0 APS5_HEAP_MIRROR_MIB=3328 APS5_TEXTURE_CACHE_MIB=256 APS5_HEAP_CACHE_MIB=256 APS5_UNIT_SHADOW_MIB=64`.
- **Their stack:** #9742, #9717, #10064, #10727, #12191, #12147, #7985, #12561, #12612 and #12617, plus a local change.
- **Their claim:**
  - `StorageTexture::markLayersPending` doesn't stamp `layerGeneration[layer] = collectedLayerGeneration(layer, now)`.
  - So a later `StorageTexture::Refresh` sees the layer as changed since generation 0, and re-uploads blank guest memory over GPU-rendered 3840x2160 `R16G16B16A16_SFLOAT` intermediates (`0x1500010000`).
  - The log line is `[gpu] storage image 0x…: guest memory changed while GPU results were pending; keeping the CPU's blocks`.
- **Their fix:** in `markLayersPending`, `now = GuestMemory::CollectWrites(...)`, stamp `layerGeneration[layer] = collectedLayerGeneration(layer, now)` for the marked layers, then `refreshGeneration()`.
- **Their result:** 0 of those lines, and a 98.7 % non-black disclaimer frame over 360 s.
- **None of their PRs changes this code:** I checked #9742 and #9717; neither touches `Texture.cpp`'s pending or generation code. So the path is `main`'s.
- **Claim check:** open PRs near it are #7048 (AlxcBTW: save the guest bytes of results that become pending over a surface no longer fully watched), #10026 (winstrex), #10886 (meh7an) and #8246 (MarcZX10). None is known to do this; confirm from their diffs.

   - Read `Texture.cpp`: the creation stamp ~L5305, the `assign(trackedLayers, 0)` at ~L1458, the upload and write-back stamps, alias borrows, and the `markLayersPending` callers ~L3773/L3788/L5462/L5625.

2. **Trace `Refresh`/`RefreshLayers` (~L2119-2470) for a pending layer at generation 0.** Find which branch it takes: `droppable` is false at generation 0, so `stored` is followed by `writeBackLayers`, and then `upload(&changed)`. Find whether the upload can read guest memory before the write-back lands (a staged write-back without a host import), and so lose the GPU results.
3. **Red on main:** an agc execution test (lavapipe) that:

   - then makes the image refresh, then checks that the GPU texels survive and the line isn't printed.
   - If no path reaches it on main, say so and stop. That is a valid result.
4. **Is their fix correct?** Stamping at `markLayersPending` hides any CPU write made between the layer's last upload and the GPU write.
   - Check a partial GPU write (a scissored draw, or a dispatch over part of the layer), and a CPU store before the pending mark.
   - Propose the narrowest correct fix (e.g. stamp only where the layer was current and fully covered, or capture the guest bytes as #7048 does) and test it against those controls.
5. **Branch:** if steps 3-4 give a red, put the fix and its test in one commit on fork `fix/agc-pending-layer-generation`, on `upstream/main`.
