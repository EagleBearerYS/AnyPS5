The user, 2026-10-31 06:32 PT (via the PM): "Start taking easy PRs like functions and fixes". Coverage batches resume on top of the upkeep of our open PRs. The last inventory is PM-088 (`results/cloud-3/PM-088.md`, 25 libraries, main a6dcea927) and PM-089 (`results/cloud-2/PM-089.md`, claims), both from 10-22, and it's stale.

A spot check on today's main shows how stale:

- The 12 CES-2 code-page profiles left are all claimed: #9912, #11614 and #10056.

So the next batches need a fresh list before anyone builds.

## Do

Fetch `upstream main` and record its sha.

1. **The todo rows.** Run main's `tools/progress.py --json` on main. List every todo row (a function that reaches `NotImplemented_nid_no_patch`) in **every** library, not only PM-088's 25. Give the count per library.

2. **The source per row.** Use PM-088's class definitions; read its result for them. A row counts as **sourced** only when a source names that function's own behaviour (the coverage source rule):
   - **FreeBSD 11 sources** for libkernel, libkernel_sys and libc POSIX or libthr functions;
   - **the matching open-source library** at the version our port follows (LibreSSL, ICU, zlib and the like);
   - **a published standard or mapping table** for the exact behaviour (a code page's Unicode mapping file, an RFC);
   - **a firmware reading posted** in an issue or PR that names this function, with a link;
   - **main's own established offline model** of a service, for the service-side answer only, and only once the module-side argument checks are measured.
   - **What doesn't count:** a sibling's answer, a twin's register shape, or a naming convention. Those rows are unsourced.

3. **Claims,** a row-by-row check. A claim is a PR that implements the function or changes its body:
   - **Open PRs:** a git scan of every `upstream refs/pull/N/head`'s added lines in `merge-base(main, head)..head`, for the function name and its NID. `gh pr list` caps at 400, so use the refs.
   - **PRs closed in the last 14 days and not merged:** the same scan of their heads.
   - **Authors at the open-PR limit,** for authors without a merged PR. Their limit-closed PRs and their fork branches, where the fork is public. Name the forks you scanned.
   - A PR that only declares a name (a pending export, `<lib>Unknown_<nid>_nid_no_patch`) is no claim.

4. **Active authors.** For each library with unclaimed sourced rows, list the other authors who opened or merged a PR in it in the last 7 days, with the PR numbers. For example, libSceLibreSsl/3 (alvaroelpob) and libSceCesCs (rooklz, SkillzTech1, KernelPanicNT, atharvjairath, zaryabzip). Flag such a family **"active author: PM first"**.

5. **The output:** a ranked table of **unclaimed, sourced families**. A family is one function family: one header group or one behaviour, about 3 to 25 functions.
   - **Columns:** library, family name, the functions, each one's source (a path or link and the line or section that names it), its class, a test idea that can be red on main, and the active-author flag.
   - **Ranking:** strongest source first, then families with no active author, then size.
   - **Counts:** todo rows in total, sourced, unclaimed sourced, and claimed (open / closed / fork).
   - **Separately, a short list of todo rows with a title stop:** a `<function> not implemented` line in an issue or discussion since 10-24, with the link.

## Constraints
