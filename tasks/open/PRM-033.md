## 2. The adversarial review, on r2

Read every changed line. For each area, say what you checked, how, and what you found:
- **Every present path:** drawn, direct and shared presents, and clear-only presents (which must skip FSR). Check the stage and swapchain images' layouts and barriers on each, and that nothing reads the stage before it's written.
- **HDR10 / PQ and SDR:** FSR runs on encoded values (sRGB-encoded for SDR, PQ codes for HDR10), clamped to [0, 1] after RCAS. Check the A2B10G10R10 and B8G8R8A8 swapchain formats, and what happens if the swapchain's format or colour space changes at run time.
- **Size changes:** swapchain recreation, a resize, a minimize (zero extent), a window larger and then smaller than the buffer, and a display buffer that changes size (the title re-registers). Look for stale per-slot images, leaks and a wrong EASU-or-not decision.
- **Synchronization:** run the tests and the VideoOut display tests under Xvfb (window larger than the buffer) with `VK_LAYER_KHRONOS_validation` and synchronization validation on (`VK_VALIDATION_FEATURE_ENABLE_SYNCHRONIZATION_VALIDATION_EXT`), unset, `fsr`, and `fsr` with `ANYPS5_FSR_SHARPNESS=2.0`. Report every message, and any new one is a finding.
- **Off is bit-identical:** with `ANYPS5_UPSCALE` unset, no upscaler object exists and the recorded commands equal main's. Check the test that claims it, and check by reading `VulkanDevice::present`.
- **Errors:** bad `ANYPS5_UPSCALE` and `ANYPS5_FSR_SHARPNESS` values stop the start with a message naming the variable; an empty value is unset. Look for any path that silently falls back.
- **The shaders:** compare `FsrEasu.frag` and `FsrRcas.frag` with AMD's v1.0.2 sample usage (constants from the push constants, per pixel). Check the 2x-per-axis limit and what happens beyond it.
- **Conventions:** docs/dev/CONVENTIONS.md, in particular **no comments in code** (line 13 allows only technical-debt markers added by a human, `#endif` ends and namespace ends; AMD's vendored headers keep theirs, as vendored). Count added `//` lines in our files. Run `tools/check_conventions.py --base upstream/main --head feat/agc-fsr1-upscaling-r2`, and check that the tests are registered (`tools/check_test_registration.py build`).
- **The vendored headers:** `license.txt` is AMD's MIT notice, unmodified; the three SHA-256s in `3rdparty/FidelityFX-FSR/README.md` match the files and tag v1.0.2 (a21ffb8f6c13233ba336352bdff293894c706575) of GPUOpen-Effects/FidelityFX-FSR. CONTRIBUTING asks for third-party code as a submodule; the PR states why it vendors them (the tag's nested Cauldron submodules, ~337 MB at depth 1). Say whether the README states it well enough.
- **The docs:** USAGE's "Upscaling" section must have the 2x-per-axis note (it does) and should disclose the two things a user may notice: RCAS's approximate reciprocal shifts flat areas by up to ~0.3% (0.5 → 0.4992 at sharpness 0.2), and `2.0` is RCAS's weakest setting, not off. Propose the wording if USAGE lacks them.
- **Anything else** a maintainer would push back on: naming, file size, a simpler design, a missing test.
