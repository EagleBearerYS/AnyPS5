## Why

Our PR #13263 (`perf(agc): copy a descriptor region behind pending GPU work on the GPU whatever its size`) lets `GuestBufferMemory::UploadFinish` copy a descriptor region on the GPU, behind the pending GPU work, when a pending GPU write, a pending storage result or a shadowed range overlaps it. That holds even when the region is over `APS5_GPU_COPY_MAX_KIB` (default 1024 KiB). On `main`, such a region takes the CPU copy, after waiting for the producer.

A reviewer asked for a test showing that this changes where the copy runs and drops the wait, not how many bytes are copied. Our reply (https://github.com/boykopovar/AnyPS5/pull/13263#issuecomment-6564100648) promised one: "a test with a small pending write inside a large region, counting the copied bytes". This task writes it.

## What to write

A new case, in the same test binary and registered as its own `add_test`, for example `agc_buffer_upload_pending_gpu_copy_bytes`:
- a region well over the 1 MiB bound (for example 3 MiB or more), with a small pending GPU write (for example 4 KiB) inside it;
- one upload of that region;
- assertions:
  - no wait for the producer;
  - the bytes copied for the region total exactly the region's size: no more (no double copy), and none on the CPU;
  - the readback matches the guest bytes with the producer's bytes in place.

For the counting, first look for an existing count you can read from a test, such as counters behind the `[upload]` trace phases (`classify`, `cpu-copy`), the recorder's copy commands, or a test hook already used in `tests/Recorder.cpp`. If counting needs new code outside the test directories, stop and report the options, with file and line, before writing any.

Follow `docs/dev/CONVENTIONS.md`. In particular:
- no comments in code;
- the test goes in one commit with a Conventional Commits subject, for example `test(agc): count the bytes an upload behind a small pending write copies`.
