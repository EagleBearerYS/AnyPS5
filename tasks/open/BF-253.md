## Why

Resident Evil Village (PPSA01556) on Windows (RTX 3070 Laptop, 16 GB) still aborts rarely in its intro under host-heap pressure. It happened once in three boots today (2026-10-28) on main 04fefebe90 + a local pad line + #11580 + #6146, and twice on 10-24/10-25 on main 85a4d7f8c8 without #6146.

Each time, it's this sequence within ~40 log lines (text from the run; no game data involved):

```
[gpu] host import of 0x2179c00000+0x1d60000 failed at vkAllocateMemory (-2); falling back to copies, requested by join
[gpu] host import budget lowered to the 6111.8 MiB live after vkAllocateMemory failed within an eighth of the budget
[gpu] host import budget: 6111 MiB live of 6111 MiB (lowered after vkAllocateMemory failed; host heap 1 reports a budget of 7237 MiB and a usage of 6958 MiB); 1 imports (8 MiB) refused so far, 0 of them remembered, last 0x2179800000+0x800000 by build
[gpu] driver failure: compute shader 0x207bef9400: AGC graphics: guest buffer has no GPU owner
```

- **Where it throws:** `GuestBufferMemory::Descriptor` (`core/libs/prx/libSceAgcDriver/Graphics/src/GuestBufferMemory.cpp`, `Require(found != nullptr, "guest buffer has no GPU owner")`).
  - `owner()` returned null: no region in `regions`, nor in `space->base`, begins at or before the view's address.
  - It's not the "exceeds its GPU owner" message.
- **Our merged #11148** (9da50eb84a, "write back a view whose space import a failed join retired") fixed a sibling: after the same failed join, a written view's copy was read-only and `WriteBack` failed with "write-back range exceeds its GPU owner".
  - Its test is `failedJoinWrittenViewTests` in `core/libs/prx/libSceAgcDriver/tests/BdaResources.cpp`. It imports two ranges apart, limits imports with `access.limitImports(large)`, then `AcquireRegistered`, `AddReadable(second - 16, 32)`, `AddWritable(written, 32)`, `Upload(true)`, and `Descriptor(written, 32, …)`.
  - The trees that aborted today contain #11148's change. So a path remains where a view gets no owner at all.
- **#6146** (ours, open) adds 17 lines to `GuestBufferMemory.cpp`:
  - `reads.emplace_back` in `AddReadable`;
  - `StoreDepthExpandWrites` and a `StorageTexture::FlushPending` over the read ranges in `UploadFinish`.
  
  The 10-25 aborts had no #6146, so it isn't the cause, but note whether it changes your path.
