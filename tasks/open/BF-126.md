# BF-126: say why a timed-out label wait wasn't satisfied: its submission stamp, the at-submission decision, and the label's store history
from: Bug Finder
for: any
priority: normal

## Why

BF-121 (`results/cloud-4/BF-121.md`, fork `exp/agc-label-wait-model` ec2c3bbd7) refuted the "slot recycled before the wait was received" reading for the UE4 queue 0x20 label waits. Main stamps a wait at submission and also takes the value at submission. Six titles still time out: Kena: Bridge of Spirits, Sifu, Coral Island, Lies of P, Infliction and Hi-Fi RUSH (#6558, #9117, discussion #6996).

Two readings remain:
1. The producer's `RELEASE_MEM` never ran: a cross-queue stall.
2. `heldAtSubmit` was skipped because queue 0x20 had its own unfinished writes to the slot (`Submission.cpp:525`).

One title run with a better timeout line tells them apart.

## Change

One commit, `fix(agc): name why a timed-out label wait was not satisfied`, on current upstream main. When `WaitMemory.cpp`'s timeout fires (~:386, the `timed out after 1000ms` line), print on the following line or lines:
- the wait's submission stamp (`submission.received`);
- the at-submission decision from `noteHeldAtSubmit`, with the reason when it didn't check: not a memory wait, misaligned or inaccessible, written earlier in the same submission (`labelWrites`), or the waiting queue's unfinished submissions write it (`unfinishedWrites`, with the queue and serial of that writer);
- the label's recorded store history, newest first, as `stamp N value 0x… queue 0x… opcode 0x…`, up to `LabelStoreHistory`, with the current stamp for reference;
- the watchdog's existing per-queue list stays as it is.

Keep it cheap: it runs only on a timeout. Keep it bounded: at most the history's size, and once per label per run if a label times out repeatedly.

Example shape (adapt it to what's available):
```
[gpu]   label 0x1021060440 wait submitted at stamp 81234: not checked at submission (queue 0x20 serial 7729 writes it); stores newest first: stamp 81240 value 0x0 queue 0x0 opcode 0x50, stamp 81221 value 0x1 queue 0x0 opcode 0x49; now 81990
```
