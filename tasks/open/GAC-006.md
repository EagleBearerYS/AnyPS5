## Context

The out-of-place DB depth expand (fork `fix/agc-db-depth-expand-out-of-place`, head e1a94e7735) fixes Resident Evil Village's blurred first 3D scene. That's verified in game today: the title is lit, the first scene is sharp, and both expand cases log once with no refusals.

One gap remains in game. GAC-003 and GAC-004 store the pending expanded plane before readers: an in-place bind, a mirror refresh, the flush hook, and ahead of address-based builds when the write base is imported. Village's GPU buffer reads of the write base still see zeros:

- **The copies:** each frame, two 8160x1x1 compute dispatches read `buffer(ro) 0x20298b0000`, the expand's write base, and write 0x2019730000 and 0x2018470000. A later pass samples 0x2019730000 as a 1920x2160 depth texture from guest memory.
- **What the trace shows:** a frame trace (CPU view, 4096 samples per 16 MiB range) shows 0x20298b0000 all zero at those dispatches, every frame, and 0x2019730000 stays zero. Sampled (texture) reads of 0x20298b0000 are correct: they come from the expand's storage image.
- **The likely reason:** Village's host import budget is full from the first report (5840 of 5840 MiB, over 1M imports refused), so the write base is probably not host-imported. The address-based build then reads it through the heap-mirror or copy path, and the pending plane isn't stored, or isn't seen, before that read.
