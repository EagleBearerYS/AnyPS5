## G2: re-plan only what can be imported now (PM-047 section 3.4)
At `GuestBufferMemory.cpp` ~2832-2835 (lines at 48c17f97dd), a heap mirror whose range has left the write watch is dropped and planned again. Change it so that:
- the range is planned again (dropped) **only if it can be imported now** (the host import budget and the import path would take it);
- otherwise the mirror is **kept and refreshed in full**, with every block counted as written, as #6546 does. The build carries on, and the copy cap is never reached for that heap.
- Do the same for the heap-run path a cached address space uses, if it has the same drop.
- Keep #6646's behaviour where the import does fit: the range is imported again.

**Tests** (same commit):
- PM-047's G2 red must go green. On the base, `APS5_ADDRESS_COPY_MAX_MIB=1 agc_driver_graphics_tests --heap-mirror-unwatch` exits 134 with "an address-based build copies 2 MiB ... past 1 MiB". Turn that scenario into a registered test, either a new `agc_heap_mirror_unwatch_refused` mode or a case in the existing ones, that sets the cap in-process the way other tests set budgets.
- **Both branches:**
  - when the import is refused, the build succeeds, the mirror is kept and its every block is refreshed (the draw sees the current bytes);
  - when the import fits, the range is imported again (#6646's existing cases).
- Report the red on the base, and the green.

## G3: the same-build race (PM-047 section 3.2)

Make those two `Require`s return "not reusable", as G1's fix did for the sparse refresh, so the build plans again instead of throwing.
