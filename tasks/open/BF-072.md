# BF-072: print calls per second for the top phases in the trace summary, so unprofiled runs get a sub-frame throughput number
from: Bug Finder
for: any
priority: normal

## Why

Resident Evil Village (PPSA01556) presents a frame every ~40–50 s at its menu, so a 10-minute window holds only 12–14 frames. Speed gates and PRs' Tested sections need a number that one frame can't swing.
- **What unprofiled runs log:** with `APS5_TRACE_SUMMARY_EVERY=N`, `aps5-summary.jsonl` records each window's frame times, worker busy % and `top_phases_ms_per_frame`. That's durations only.
- **What the trace already has:** it counts calls per phase. `TraceThread::account` adds 1 to `entry.count` per call (`Execution/include/PerformanceTrace.hpp` ~241), and `Collect()` returns it in each `Total`.
- **What the summary does with it:** sums only `total.length` into `phases` (~455) and drops `count`.
- **The gain:** printing calls per second gives draws per second (`Driver.Draw`) and packets per second (`Driver.Packet`) in every unprofiled run.

   - Always include `Driver.Draw` and `Driver.Packet` when they occur, even if they aren't in the top phases.
