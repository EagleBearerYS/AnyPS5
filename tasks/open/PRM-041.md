# PRM-041: game presets: answer `sceUserServiceGetGamePresets`'s priority from a setting, log the first call, with a test
from: AnyPS5 PR Manager
for: any
priority: high

## Why

Resident Evil Village (PPSA01556) and Planet of Lana (PPSA19450) import `sceUserServiceGetGamePresets`. Its `priority` field is, by its name, the PS5's system-wide "Performance Mode or Resolution Mode" game preset, which a title can use to choose between favouring frame rate and favouring resolution. Step 3 below checks the values. AnyPS5 answers 0 ("not specified") for every field (`core/libs/prx/libSceUserService/Export.cpp:78-96` at `upstream/main` 66702f1cff).

The PC will boot each title at priority 0, 1 and 2 to see whether either changes its render-target sizes or its GPU cost. That needs an override for the answer, plus a log line that shows the title really called it. If a title reacts, this branch becomes the core of a "Game Presets" feature PR, so build it to PR standard.

No game files, dumps or executables are involved. Everything here is source and tests.

## What to build

Base: `upstream/main`. Fetch it first; `origin` is the fork in this environment. Branch: `prep/game-presets-priority`. Push it to the fork, and push nothing else except the result below.

1. **The setting.** An environment setting for `priority`: `ANYPS5_GAME_PRESETS_PRIORITY`. The `ANYPS5_` prefix is for user-facing console settings (`ANYPS5_LANGUAGE`, `ANYPS5_GPU`, `ANYPS5_PRESENT_MODE`); `APS5_` is for debug switches. Model it on `ANYPS5_LANGUAGE` in `core/libs/prx/libSceSystemService/Export.cpp` (`ConsoleLanguage`, about line 31):
   - unset or empty: 0, today's answer;
   - a decimal number 0 to 2: that value;
   - anything else (another number, a sign, trailing text): throw a `std::runtime_error` that names the variable and the accepted range, as `ConsoleLanguage` does.
   Read it on each call; it's called rarely. Every other field stays 0, and so does `this_size` handling (it stays the caller's).
2. **The log line.** One line on the first call in the process, to stderr, with every field returned and `this_size`. Use a one-shot `std::atomic<bool>` like `loginReported` in the same file, and a `[userservice]` tag in the form other prx libraries use for one-off lines. Print it whether or not the setting is set, so a run shows the call either way.
3. **What 1 and 2 mean.** Look for the field's values in public sources: KytyPS5 (https://github.com/KytyPS5/KytyPS5, GPL-2.0; cite the commit), SharpProspero (https://github.com/SvenGDK/SharpProspero), shadPS4 and any public PS4/PS5 header. Interface facts only (names and values); copy no code. If a source names them, use the names in the docs and the error text. If none does, document the numbers only and say so.
4. **The test.** A guest test like `core/libs/tests/GuestSystemServiceLanguage.cpp` (it sets the variable with `setenv`/`_putenv_s`), registered with `add_test_executable` in `core/libs/prx/libSceUserService/CMakeLists.txt` next to the other user-service tests. Cases:
   - unset and empty: every field 0;
   - 1 and 2: `priority` is that value and every other field is 0;
   - rejected, with the error naming the variable: `3`, `-1`, `1x`, `x`;
   - a null pointer or another user id: `USER_SERVICE_ERROR_INVALID_ARGUMENT`, as today;
   - `this_size` is left as the caller set it.
5. **Docs.** A "Game presets" subsection in `docs/user/USAGE.md` after "Console language", in the same style: what the setting does, its values, the default. Add a line to `docs/dev/debt/libSceUserService.md` if the other presets staying "not specified" belongs there by the debt file's own rules.
