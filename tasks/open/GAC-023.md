## Context

Resident Evil Village aborts before its title on main-based trees (fork `test/village-fast-main` 142abd9ee1, and -ports bb37cc3367), 5 min after launch:

```
[libc] unhandled exception 'St13runtime_error' ... FATAL: abort() (SIGABRT)
what(): shader 0x207e88a300 stage 5: ShaderRecompiler::Recompile: GetImageResource dword 0 is not a valid runtime value; chain: LoadAddressU32@pc=0x000002c0(GetAddressResource(Phi(GetUserData(Void), CompositeExtractU32x4(Ballot(ULessThan32(Immediate, SelectU32(FPOrdGreaterThanEqual32(BitCastF32U32, Immediate), IAdd32(Immediate, SelectU32), SelectU32(FPOrdGreaterThanEqual32, SelectU32, SelectU32)))), Immediate)), Phi(...same...)), Immediate, Immediate, Immediate)
```

- **The stack:** the game's PSO creation (libSceAgc LinkShaders/PrimState) → `AgcDriverResolveGraphicsStagesAbi_nid_postfix` (EntryPoints.cpp:141, which catches only `ProcessShutdown`) → `Driver::ResolveGraphicsStagesAbi` (ShaderRegistry.cpp ~1164) → `PrepareGraphicsStages` → the recompile → `ResourceTracker::GetHandle` → `ValidateSource` fails (ResourceTracker.cpp:1448).
- **No `[image-table]` line appears at all.** The stage reads a lane-keyed T# through a waterfall loop, which only a draw's image tables can serve.
- **Why older trees ran it:** on the older e34 trees, a local early exit under `APS5_RE8_LAZY_PREPARE` (commit 518a8b2fef, ours, never upstream) left these stages to first use. There, `ReportPreparedAtUse` logged "... stage 5 has no artifact prepared at registration ...; preparing it at use", and the draw rendered.
- **Main's behaviour:** main's `APS5_LAZY_SHADER_PREPARE` still prepares an explicit ABI's stages (ARCHITECTURE.md: "Explicit ABI resolution still prepares its requested stages").
- **Registration already does this:** `PlanRegistered` defers to use with "could not be prepared at registration (...); preparing it when it is used".
- **The trap for a naive catch:** `ShaderPreparationTransaction`s nest and share a root. An uncommitted transaction's destructor sets `root->failed`, and `Commit()` then throws "shader preparation transaction was aborted". So catching inside `ResolveGraphicsStagesAbi` after the nested `PrepareGraphicsStages` threw leaves the root poisoned. `ResolveShaderAbi`'s graphics path (which nests `ResolveGraphicsStagesAbi`, then commits) would still abort.
- **Tonight's local unblock:** an env-gated early exit (`APS5_DEFER_ABI_PREPARE`). It's not the PR.
