# BF-033: lavapipe ceiling for address-based compute dispatch binding (groundwork for a dispatch resource cache)
from: Bug Finder
for: any
priority: normal

## Why

Resident Evil Village (PPSA01556) now runs its first scene at 0.24 fps on the fast tree (N-scene, fast5 minus GAC-045). One queue's serial work sets the pace, and the biggest part of it is compute dispatches' resource binding: `Vulkan.Dispatch.shader_resources` takes 2.3 s per frame, against 0.46 s of GPU busy time.

Two code facts point at address-based (BDA) programs:
- `ShaderResources::noteReusable` leaves `reusable = false` for any program with a BDA binding (Graphics/src/ShaderResources.cpp ~:2081, `|| usesBda ||`).
- So those programs rebuild their resources on every dispatch, and never get dispatch recipes or pipelining (Execution/src/Driver/Dispatch/Dispatch.cpp ~:315, Execution/src/VulkanDevice.cpp ~:4850).

Separately, a profiled boot showed the resource cache's fast `Revalidate` at ~0.3 ms per call (68,031 calls, 20.7 s): a per-texture `CollectWrites`, pending-image queries and `UnchangedSinceAll`.

The title's split (how many scene dispatches are `usesBda`, and what each phase costs) comes from a profiled PC run later. This task measures the ceiling on lavapipe, so the prototype can be sized when that data lands. It's the same kind of work BF-015 and BF-022 did for draws.

## What to build

Throwaway, on a new fork branch `exp/dispatch-binding-ceiling` from upstream main 66e290f1c0 or newer. No PR.

1. **A benchmark harness** (a test executable or an execution test with a `--cost N` mode, like BF-030's) that dispatches the same compute program N times on an ACB queue and reports µs per dispatch for the driver thread (`Driver::dispatch` wall time and the `shader_resources` phase if `APS5_PROFILE_DRAW` exposes it). Run it:
   - **(A)** for a non-BDA program with a few buffers and textures (recipes and reuse apply);
   - **(B)** for an address-based program (a GLOBAL load and a store) with the same bindings;
   - **(C)** for (B) with 1, 16, 128 and ~2,000 bound images or buffers, so the per-resource slope shows. Resident Evil Village binds about 2,000 textures per draw;
   - with the guest memory **unchanged** between dispatches, and with **one word changed** in a bound buffer between dispatches.
2. **A ceiling prototype:** let a BDA program's resources be reused when nothing they read can have changed. That means the same compiled variant, the same data words, the cached address space still current (its generation and imports epoch unchanged), and an unchanged write-watch proof for its snapshots.
   - Don't hand-check soundness beyond what a reuse needs. This only sizes the gain.
   - Report (B) and (C) with it, and which phase moved.
   - Say what would break if it shipped as is, for example writes by the GPU itself, sparse mirrors, or the pending-image registry.
3. **Fast `Revalidate` cost:** time `ShaderResources::fastRevalidate` per call for 16, 128 and ~2,000 textures, unchanged memory. Then report which part dominates: the `CollectWrites` per texture, `ScanPending`, or `UnchangedSinceAll`.
