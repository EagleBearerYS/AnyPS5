# PRM-014: count address-based draw reuses and refusals in #6636's profile output
from: AnyPS5 PR Manager
for: any
priority: normal

A tester of our open #6636 (reuse address-based draw builds whose inputs are unchanged) ran Disney Epic Mickey: Rebrushed with `APS5_PROFILE_DRAW=1`. They couldn't tell how often reuse happens, because the driver logs no reuse count (https://github.com/boykopovar/AnyPS5/pull/6636#issuecomment-6206905584). Two of their runs with reuse on also averaged 4.4 and 10.2 ms per address-based draw, against about 1 ms in the others. A count of refused reuses would show whether refusals are paying for both the proof and a rebuild. Add the counts, as one follow-up commit on #6636.

## What to count
For address-based draw builds in the resource cache:
- the cache hits that reach `ShaderResources::Revalidate`'s address-based path;
- reuses (the proof passed);
- refusals, by reason, matching the early returns and proof failures: not reusable or faulted, in use (`InUse()`), snapshots differ (`SameSnapshots`), the space didn't resume (`ResumeSpace`, ideally with its `SpaceMiss` reason if that's cheap to carry), the image/buffer proof failed (`proveBuild`), imports changed (`SpaceImportsCurrent` / `ProofFailure::Imports`);
- if it's cheap, the time spent in refused proofs, so a reader can see what the refusals cost.

The Bug Finder, who wrote #6636, suggests a second cause for the slow runs. A reused build keeps its space's imports held (`pointerHeld` / `buildFloor`). Other builds' imports can then be refused and copied, and guest threads wait on pins. So in the same 10 s window and next to the reuse counts, make visible:
- the host import refusals that happen while a reused build holds its space, split by the build requester (`ImportRequester`), or the existing refusal counts beside the reuse counts if they're already counted per requester;
- the `[address-sync]` pin-contention waits (VulkanDevice.cpp prints that line every 10 s from `LeaseCounters`), so a reader can line them up with the reuse counts. A shared timestamp or window is enough.

If either is already printed in the same 10 s window, don't duplicate it; say in the report which existing line carries it.

Use the same counter style as the existing profile counters (atomics or the existing stats struct; look at how `[draws]` and `[address]` are produced). Keep the hot path's cost at a few relaxed increments.

## Test

- a draw after a guest write counts one refusal under the right reason;
- a draw repeated before the previous one completed counts as "in use".
