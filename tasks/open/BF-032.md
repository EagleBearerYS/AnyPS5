## Why

PM-065 (`results/cloud-3/PM-065.md`) found a heap-use-after-free on main in the default configuration.
- **The bug:** `resolveGroupAhead` parks a data hit with copies, `parked.captured = captured; parked.liveWords = liveWords;` (Execution/src/Driver/Dispatch/Dispatch.cpp:386-387; still there on upstream main 66e290f1c0). The adopting dispatch's regions point into the freed local `liveWords`, so for an address-based program `ShaderResources::Complete` → `prepareAddressBindings` → `GuestBufferMemory::AddSnapshot` memcmps the freed words.
- **The fix:** fork `fix/agc-pipelined-dispatch-data-hit-words` ada526a206 (on 4524944396), which moves instead of copying. The new test is `DispatchDataHitWords` (`agc_driver_dispatch_data_hit_words`).
- **What's missing for a PR:** a red on a plain build. Today the test is red only under ASan, which MinGW doesn't have. On a plain build it passes and only prints "guest snapshot differs from registered memory", and with `APS5_SNAPSHOT_CHECK_FATAL=1` the rethrow path re-runs the dispatch, so it still passes. PRs here need red and green on both GitHub runners (Linux and Windows), and I'll run those from the PC.
- **The title:** Onimusha: Way of the Sword (PPSA27836) prints the same line on plain main 31cbb55d7 (discussion #5769, frankea, 2026-10-16T04:01). It shows small snapshots (0x10-0x38 bytes) inside writable host-backed or mirrored regions, often with "write generation N seen N", meaning nothing was written since the capture.

## What to build

On a new fork branch, `fix/agc-dispatch-data-hit-live-words`, from **upstream main 66e290f1c0 or newer**:

1. **The fix:** ada526a206's change, rebased onto current main, as its own commit.
2. **A deterministic plain-build red**, in the same commit as the fix or a following one (never a failing test before its fix). Pick one, and say why:
   - (a) A small read-only accessor for the snapshot mismatch count `AddSnapshot` already keeps (the "N mismatches so far" counter in GuestBufferMemory.cpp ~:3165), next to the existing profile accessors. `DispatchDataHitWords` then asserts that no mismatch was added across its data hits. Without the fix it must fail on a plain build, every run.
   - (b) A case where the adopted snapshot has no live owner, so `AddSnapshot` uploads the snapshot's own bytes (the copy at ~:3172). The shader output is then wrong without the fix. Use this only if it's deterministic (freed memory may still hold the old value), so prefer (a) unless (b) is reliable.
3. **Keep** ada526a206's pipelined-item hardening (`liveWords = std::move(liveWords)` in the Queue0 item) in the fix commit.
