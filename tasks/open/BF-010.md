# BF-010: widen the copy-cap fix to the gaps PM-037 found (non-budget failures, order, refresh throws)

## Why

The user, 2026-10-15 00:03 PT: our fixes must be comprehensive, so that no newer PR can post a better version.

The copy-cap fix `fix/agc-address-build-copy-cap` at `5ee93b98ad` (four commits on upstream main 6239ceffc) covers two causes:
- a budget-refused range whose copy would pass the cap now evicts idle imports and retries;
- a heap mirror whose range left the watch is planned again.

PM-037's audit (`results/cloud-2/PM-037.md` §3) calls it ready for that scope, with three MEDIUM gaps outside it. Read that section first: it has the line references.
1. **A non-budget import failure is never retried:** a cached `vkAllocateMemory` failure, a held window, or the page checks. Such a heap is copied, and the build can still abort past the cap.
2. **The retry depends on order:** only the range that crosses the cap is retried. Earlier budget-refused copies are never revisited, so the build can abort when evicting for an earlier, larger copy would have fit.
3. **A refresh after an unwatch the serial misses throws:**
   - the unwatches in question are a failed walk, or a Linux DirectMemory alias unregister;
   - sparse heap mirrors aren't covered by `heapMirrorWatched` at all;
   - an import made later in the same pass can exclude a mirrored heap's last block on Windows.

## Task

Implement PM-037's "a better version would…" list, items 1 to 3, and item 4 if it's contained:
1. **When the build's copies would cross the cap,** retry every budget-refused copy, largest first, with eviction, not only the crossing range. Keep the rule that imports this build already holds (`buildFloor`) are never evicted.
2. **Also retry a heap whose import failed for a non-budget reason,** after clearing that range's cached failure for this build. Only where a retry can succeed: not a held window that is still held (#5870 covers that case).
3. **A refresh that finds the range unwatched drops the mirror and plans the range again,** instead of throwing. That covers missed unwatches, sparse mirrors and the in-pass case.
4. **If contained,** apply the cap and the retry to cache-hit re-adds and descriptor-only builds. If not, give the reason for a scope line.

**Rules:**
- **Costs:** the retry runs only when a build would cross the cap or a refresh fails, so a normal build costs nothing extra. Measure it, and give the worst case.
- **Tests:** a red/green for each case, with the missing tests PM-037 lists:
  - a non-budget import failure (a cached allocation failure; a held window that is released);
  - two budget-refused copies where only the first is large;
  - a refresh after an unwatch the serial misses (a failed walk; a DirectMemory alias unregister on Linux);
  - a cache-hit re-add;
  - a descriptor-only build.
  Use forced `vkAllocateMemory` failures, or the existing test hooks.
- **Both platforms:** the Windows guest-arena setup must match Linux. Read 74640d655c's Windows setup: the ranges sit a block apart in the arena, and only the heap is watched. Avoid the Windows traps: no `far`, `near` or `small` as names, no `alignas` above 8192.
- **Build and test like CI's Linux job:** the configure flags, the build, `tools/check_test_registration.py build`, `ctest -R '^agc'` as an unprivileged user, and `tools/check_skips.py`. Every commit must build and pass its own tests, and each red/green test goes after its fix.
- **Conventions:** no comments in code (CONVENTIONS line 13), Conventional Commits subjects, the user's identity, no trailers.
- **Push** to the fork as `fix/agc-address-build-copy-cap-v2`, on top of 5ee93b98ad. Keep its four commits as they are, and add yours after them.
