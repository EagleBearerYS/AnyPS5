# PM-015: let the user choose the output resolution VideoOut reports to titles
from: AnyPS5 Project Manager
for: any
priority: high

A user-chosen feature (the user picked it 2026-10-14). Build it to the project's standard: read CONTRIBUTING.md and docs/dev/CONVENTIONS.md first.

## Why
- AnyPS5 reports the registered display buffers' size as the output resolution. `sceVideoOutGetResolutionStatus` in core/libs/prx/libSceVideoOut/src/Output.cpp returns `cfg->width`/`cfg->height`, which start at 0 and follow the buffers the title registers. So titles pick their own size.
- Resident Evil Village and Animal Well both pick 3840x2160, even on this PC's 1080p screens, where the presentation then downscales. Animal Well is GPU-bound at 4K on an RTX 3070: 17.2 ms of GPU time per present, 33 fps against 60 on PS5.
- If a title can be told the output is 1920x1080 (or 2560x1440), it may render a smaller display buffer: faster on GPU-bound titles, with no upscaler needed.
- Later, FSR 1 (our held branch feat/agc-fsr1-presentation-upscaling) would upscale that smaller buffer to a larger window, giving it a real use.

## What to build
- **The setting:** `ANYPS5_OUTPUT_RESOLUTION=<width>x<height>`. Accept the PS5's real output modes only: 1280x720, 1920x1080, 2560x1440 and 3840x2160. When it's unset, nothing changes.
- **What it changes:** report that size as the output resolution through every VideoOut call a title can use to learn it before registering buffers. That covers `sceVideoOutGetResolutionStatus`'s full and pane sizes, and any other call that reports output size or mode (check `outputStatus(*cfg)` in Output.cpp, `sceVideoOutGetOutputStatus`, device capability and safe-area queries, and libSceSystemService if it reports resolution). Report it from the first call on, before any buffer is registered.
- Don't change how registered buffers are presented. Whatever size the title registers is still presented and scaled to the window as today.
- If the title registers a different size anyway, log one line saying so, once.
- An invalid value stops the start with an error naming the variable, as `ANYPS5_PRESENT_MODE` does.

## Tests (required)
- Unit tests for parsing (valid modes, invalid strings, unset).
- A test that `sceVideoOutGetResolutionStatus` and the other changed calls report the chosen size before and after a buffer registration.
- A test that with the setting unset the reported values are exactly today's.
- Register tests as the project does; check_test_registration must pass.
