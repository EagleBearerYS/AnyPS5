# PRM-057: note a queued DMA_DATA fill's metadata before its GPU store (#9533, a Windows-only refusal on an RTX 3070)
from: AnyPS5 PR Manager
for: any
priority: high

## Why

#9533's commit dd7ad4638a ("note depth and colour metadata after a queued DMA_DATA fill") makes the queued >64 KiB DMA_DATA fill note depth and colour metadata. The note happens inside `storeBufferFill(..., noteMetadata=true)`, after `localDevice->FillBuffer` has stored it (`Execution/src/Driver/Memory/BufferFill.cpp`, `if (noteMetadata && uniform)` after the store). Its test `agc_driver_native_depth_driver_queued_fill` passes on GitHub's Linux runner.

On an NVIDIA RTX 3070 Laptop GPU on Windows (real device, driver 617.42), the same test fails 4 of 4, deterministically, with:

`AGC graphics: native multisample depth metadata fill over unwatched memory is not implemented`

That refusal is in `NoteDepthMetadataFill` (`Graphics/src/DepthSurface.cpp`, `!GuestMemory::Watched(metadata.address, metadata.bytes)`). On the same machine, `agc_driver_native_depth_driver_path` passes. It checks the same 128 KiB metadata allocation and goes through the same `FillBuffer`, but its note comes before the store.

The other fill paths all note before the store:
- the synchronous path notes in `preparePacketMemory` (`Packets/PacketMemory.cpp`, the `opcode == 0x50` block), then stores with `noteMetadata=false`;
- the queued ≤64 KiB branch of `enqueueDmaPacket` calls `NoteDepthMetadataFill`/`NoteColorMetadataFill` before `commitDmaStore`.

Our reading: on Windows, the host import made for the GPU store can leave the range unwatched afterwards. Either `ImportWatched(..., staysWatched=false)` unwatches it when `watchedHostPointer` is false (`Graphics/src/GuestBufferMemory.cpp`, the `ImportWatched(base, bytes, ...)` call), or the import-window walk unwatches a span. A note made after the store then sees unwatched memory. This is a reading, not a measurement. Part 1 tests it on Linux.

## Part 2: the fix

In `Execution/src/Driver/Packets/PacketMemory.cpp`, `enqueueDmaPacket`, the `source == 2 && DmaBytes > gpuStoreLimit` branch, inside the queued lambda:
- call `Graphics::NoteDepthMetadataFill(fillAddress, fillBytes, pattern)` and `Graphics::NoteColorMetadataFill(fillAddress, fillBytes, pattern)` before `storeBufferFill`, as the ≤64 KiB branch does before `commitDmaStore`;
- pass `noteMetadata` as `false`.

Then:
- The new unwatched test passes, and `agc_driver_native_depth_driver_queued_fill` still passes.
- **Red/green:** with the new test kept, revert only the PacketMemory.cpp hunk, rebuild, and show the red message. Then restore it and show green.

The body says what goes wrong (the post-store note sees unwatched memory when the store's import doesn't keep the write watch, seen on Windows on an RTX 3070). It names the paths it now matches, and says the new case runs the queued fill with imports unwatched.
