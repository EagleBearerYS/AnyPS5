- **Left out on purpose:**
  - `RSA_generate_key_ex` takes a `BIGNUM`, and `RSA_sign`, `RSA_private_encrypt` and `RSA_private_decrypt` need a private key that only it or the `BIGNUM` setters give here: they wait for #9446;

  - `EVP_DigestVerify{Init,Final}` need #9448's message-digest context.
  If one of the 8 turns out to need a `BIGNUM`, an `EVP_MD` that main doesn't have, or an object only an open PR adds, it stays a throw and you list it as waiting.
- **Taken by others, stay off:** `RSA_{flags,size}` (#10449, alvaroelpob), `EVP_PKEY_{new,free}` (#10570), `EVP_PKEY_id` (#10418), `EVP_PKEY_type` (#10398).
- **Base:** if #10449 defines the `RSA` object these calls fill, stack on `refs/pull/10449/head` (use its current head and say which), keeping alvaroelpob's commits as they are under their author's name. Otherwise current upstream `main`. If #10449 has merged by the time you start, use main. Do not merge #9446.
- **Semantics:** LibreSSL's `rsa/` sources and the OpenSSL 1.0.2 manual pages for behaviour and return values (give the URLs and the LibreSSL version). Build the arithmetic on the mbedcrypto the library already links. Padding modes: PKCS#1 v1.5, OAEP and none where the call takes a padding argument; refuse the others as LibreSSL does.
- **Tests:** in the library's existing guest test (or #10449's `GuestLibreSslRsa.cpp` if you stack on it):
  - `d2i_RSA_PUBKEY` on a published SubjectPublicKeyInfo (an RFC 8017 or NIST CAVP key, give the source), and a truncated encoding refused;
  - `RSA_verify` and `RSA_public_decrypt` with a known-answer PKCS#1 v1.5 signature for that key, plus a tampered one failing;
  - `RSA_verify_PKCS1_PSS` and `RSA_padding_add_PKCS1_PSS` with a CAVP PSS vector;
  - `RSA_public_encrypt` with OAEP and v1.5: the output length, and that two encryptions differ;
  - red/green per commit.
