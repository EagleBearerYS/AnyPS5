# BF-058: a memory bound for BF-052's CPU-path indirect draw-cache entries that keeps reuse
from: Bug Finder
for: any
priority: normal

**Posted ahead of a verdict.** Resident Evil Village (PPSA01556)'s pair decides BF-052 at ~06:15 PT. If that gate kills BF-052, the Bug Finder withdraws this task: check the task file before starting long work.

## Why

BF-052 keeps CPU-path indirect draws in the draw cache behind `APS5_CACHE_CPU_INDIRECT=1`. Its PR branch is fork `perf/agc-cpu-indirect-draw-cache` 2b23feb6a9, on upstream main 17cfb1f4cb.
- **What it costs at Village's menu:** on main the draw cache stays empty there, because every menu draw is a CPU-path indirect draw, and those are excluded. With the switch on, the cache fills toward its bound (4,096 entries, LRU, up to 4 variants per stage).
- **The first sample, on the PC (statistics only):** ~1.3 GB more private memory at the menu.
- **The rule, decided by the PM in the user's name:** if that memory is a flat offset and fps gains ≥10%, BF-052 gets a cap aiming at ≤1 GB extra at the menu. The PC is at its commit limit.
- **Two constraints on the cap:**
  - **It must count what an entry really holds.** Each stage variant pins a compiled `RecompileResult`, with its SPIR-V of ~0.2–0.3 MB for typical vertex and fragment programs. The cache's "~MiB" figure leaves those results out.
  - **It must keep reuse on a cycle.** Village's static menu cycles through the same ~850 draws per frame. An LRU whose capacity is under the cycle misses on every draw, so the cap must not evict that way. For example, refuse new entries when over budget, which keeps budget ÷ cycle of the hits, or shrink what each entry pins.

**No game data:** the harness and synthetic shaders only.

## Steps

1. **Measure per-entry memory, with the switch on.** Use the CPU-path indirect mode of the draw-record harness (fork `exp/cpu-indirect-draw-cache` fdb45156ca, `tests/execution/DrawRecordCost.cpp`), with a cyclic working set of distinct draws, for example 850 per frame repeating.
   - **Wait for the GPU after each frame**, as BF-055's `VILLAGE_GPU_SYNC=1` does (fork `exp/descriptor-set-release-measure` a41ab28ad). Otherwise the recorder's backlog dominates RSS.
   - **Report:** entries, variants per stage, and bytes by part: pinned results (count each distinct one once), resource captures, captured memory regions, and decode or state. Give RSS and the cache's own "~MiB" alongside.
2. **Add the bound on the PR branch, as a new commit on 2b23feb6a9:**
   - a byte budget for CPU-path indirect entries that counts pinned results, with a default sized so the measured per-entry bytes give ≤1 GB at the harness's 850-draw cycle;
   - a policy that keeps hits when the cycle exceeds the budget: admission control, fewer variants per stage, or sharing results the shader registry already holds, whichever step 1 shows matters most;
   - an environment variable to change the budget.

   Main's behaviour with the switch off must not change.
3. **The red/green test, as a new ctest on lavapipe, in the same commit as the bound:**
   - drive a cyclic set of distinct CPU-path indirect draws whose total exceeds the budget;
   - require the counted bytes to stay ≤ the budget, and hits per cycle to be at least budget ÷ cycle (minus a small margin);
   - **the red:** build the fix commit with its bound reverted, so the old code runs with the new test. It must fail on the bytes. Give its message.
   - **the green:** the fix commit as committed must pass both checks. Give the passing line.
4. **Checks:** `ctest -R '^agc'`, `agc_driver_indirect_draw_cache_(hit|guards)` ×20, and CI's Linux job mirrored on the new head.
