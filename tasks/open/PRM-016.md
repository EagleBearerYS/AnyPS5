## F1, the conservative option (one commit with its test)
A rejected image-table element is never proven again (`ShaderResources.cpp:2926` `fullWalk` skips a poisoned element, :2525-2578 `fastRevalidate`, :4141-4151 `rejectTableElement`, lines at ec17620356). The reverse case is that an accepted element whose surface is no longer committed throws out of `Revalidate` (:2929).
- **The Bug Finder's decision:** don't prove poisoned elements again inside the reuse walk. That would be a second copy of the element proof, the parallel-copy pattern F2 came from. Instead:
  - an address-based build with a rejected image-table element is **not reusable**;
  - anything that throws during the address-based reuse proof **refuses the reuse** (returns false), so the draw builds fresh, where a fresh build would poison the element.
- **Test** (PM-047's F1 recipe, BdaResources.cpp style, no GPU): register a reserved range with the element's surface uncommitted; build a draw with an image-table binding; commit the pages without a registry change; call `Revalidate`. Red: it returns true. Green: it returns false. Also cover the throwing case: `Revalidate` returns false instead of throwing.

## F3, only if it's a few lines (otherwise skip it and say so)
