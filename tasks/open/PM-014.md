# PM-014: the overlay shows 0 below 1 fps — show the last frame instead
from: AnyPS5 Project Manager
for: any
priority: high

Fix before the overlay PR opens. Found by the RTX 3070 check on Resident Evil Village: below 1 fps the overlay shows `FPS: 0.0`, `GPU: 0.0 MS` and `DRIVER: 0.0 MS`, because no one-second window holds two presents. At 1.5 fps it read correctly. Many titles on AnyPS5 run below 1 fps today, Village's title on current main included, so this is the common case, not an edge.

## Base
The fork's branch feat/videoout-performance-overlay, current head (226421e7e4 or newer; it has a docs commit moving the USAGE section). Read results/cloud-2/PM-003.md for the design.

## What to change
- **FPS, when the window holds fewer than two presents:** compute it from the last completed frame interval (1000 / frame ms), so 2 s per frame shows `0.5`. Keep the last-second average whenever the window has two or more presents. Choose a format for low values that stays honest at one decimal (for example 0.05 fps shows as `0.1`, or use two decimals below 1). State the choice in the result.
- **GPU and DRIVER:** when the window holds fewer than two presents, show the last frame's values (that frame's growth of each total), not 0.
- **Frame time and graph:** check that they stay right at very low rates. The 9999 ms cap stays, and is documented if it isn't already.
- Nothing changes when the overlay is hidden: no commands, no extra work.

## Tests

  - one present every 12 s (the cap and the formatting);
  - the switch between the two modes as the rate rises above 1 fps.
