# PM-016: trophies — record and report unlocks from a title's events
from: AnyPS5 Project Manager
for: any
priority: high

A user-chosen feature (the user picked it 2026-10-14). Build it to the project's own standard: read CONTRIBUTING.md and docs/dev/CONVENTIONS.md first.

## Why
- Today AnyPS5 drops every Universal Data System (UDS) event, and libSceNpTrophy2 reports one fake trophy, so no unlock is ever recorded or reported.
- Resident Evil Village (PPSA01556) imports `sceNpUniversalDataSystemCreateEvent`, `sceNpUniversalDataSystemPostEvent`, `sceNpUniversalDataSystemEventPropertyObjectSetInt32`, `sceNpTrophy2CreateContext` and `sceNpTrophy2GetTrophyInfo`. That's the title the PR will name.
- The maintainers want feature PRs to implement a library's general behaviour, for a title that reaches the code on current main.

## Research first (public sources only)
- How a PS5 title unlocks a trophy through UDS: the event names and properties (e.g. an unlock event carrying a trophy id, and progress events), and how libSceNpTrophy2 queries report state.
- Use only public, legal sources: AnyPS5's own code and history, open-source projects (KytyPS5, SharpProspero, homebrew SDKs and the like) and public write-ups. Never use leaked SDK material.
- Cite each source in the result. If something can't be established publicly, say so and design around it.

## What to build (first PR scope)
- **UDS:** keep the events a title creates and posts, with their properties, instead of dropping them. Recognise trophy unlock and progress events.
- **Record unlocks** per title and user in a small host file that survives restarts. Find where AnyPS5 already keeps per-title host data (save data, settings) and use the same place and style. Log one line per unlock, e.g. `[trophy] PPSA01556 unlocked trophy 12`.
- **libSceNpTrophy2:** answer the queries honestly from the recorded state: unlocked or not, and the unlock time where the API returns it. Where trophy names, grades or icons need the title's trophy data files, which you can't access, keep today's placeholders for those fields, and make the code ready for a later parser.
- **No pop-up in this PR.** A small on-screen pop-up comes later as a follow-up on the performance overlay's drawing code (upstream PR #6012), once that merges. Design the recorded-unlock hook so the pop-up can subscribe to it.
- Nothing changes for titles that don't post trophy events. Keep the stubs' current return codes where the behaviour is unknown.

## Tests (required)
- Unit tests:
  - event property parsing;
  - unlock and progress recognition;
  - persistence across a restart;
  - the Trophy2 queries before and after an unlock;
  - unknown events ignored.
- A guest-level test, if the project has a pattern for libSceNp* guest tests: post an unlock event through the exported functions, then query.
- Register tests as the project does; check_test_registration must pass.
