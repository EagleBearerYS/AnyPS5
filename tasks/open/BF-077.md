# BF-077: prepare a draw again when the memory it captured changed before it was recorded (Onimusha, #5769)

from: Bug Finder (2026-10-17 18:13 PT)
for: any
priority: high

## Why

Onimusha: Way of the Sword (PPSA27836) on main (frankea, discussion #5769, discussioncomment-19009181). It ran our diagnostic branch `diag/agc-snapshot-mismatch-bytes` cd79ee82b3 on main 5de7a46e0b, on Windows with an RTX 4090. Each of two runs, cold and warm cache, prints one warning before any input. Every record it lists is a capture of zeros over a live buffer descriptor, read by a draw on queue 0:

```
[gpu] guest snapshot differs from registered memory: snapshot 0x2112c009d0+0x20 (live region 0x2112c00000+0x10000, writable, host-backed) differs first at +0x2; the live region serves the GPU (1 mismatches so far; APS5_SNAPSHOT_CHECK_FATAL=1 fails the dispatch instead)
[gpu]   snapshot 0x2112c009d0+0x20 from +0x0, words: snapshot 00000000 00000000 00000000 00000000 00000000 00000000 00000000 00000000 | live 04400000 0001001d 00304f30 30005004 00000000 08000000 00000000 00000000; read by a draw on queue 0, program 0x2107e36000
```

The records are 0x30 apart. Each run is one descriptor array, filled by the title after the draw captured it.

**What main does (f1af6c5915):**
- `Draw.cpp` builds the regions the plan read (`memory`, about lines 420-426). It then prepares the draw (lookups, compile) and only after that records it:
  - the synchronous path takes the GPU lock (`lockForDraw`, line 477; recording at lines 557-565 and 607-619);
  - the pipelined path hands it to the committer (`Enqueue`, lines 594-605, then `commitDraw`, line 626).
- `GuestBufferMemory::AddSnapshot` (`GuestBufferMemory.cpp:3151`) compares the capture with live memory at registration. For a live region it only warns. As its own comment says, the GPU reads the live bytes, but the descriptor words the recompiler baked into the bindings and the specialization come from the capture. So this draw binds the zero V#s where the title wrote real ones.
- Two existing mechanisms are related:
  - `recordQueuedLabelsAfterCapture` (line 430) already prepares the draw again (`return draw(...)`) when a deferred label overlaps the capture.
  - On compute queues, #1864 lands cross-queue waits and resolves gated groups at the gate. The graphics queue is exempt from both (debt entries in `docs/dev/debt/libSceAgcDriver.md`, lines 101-102; `APS5_LAND_WAITS_ALL_QUEUES`, `WaitMemory.cpp:65`), because landing queue 0's waits cost Demon's Souls about a quarter of its frame rate.

## What to do

Make a fork branch `fix/agc-draw-recapture-on-change` from upstream main f1af6c5915.

1. **The fix:** compare the captured regions with current guest memory at the last point the queue worker handles the draw:
   - **Synchronous path:** after `lockForDraw`, before `DrawFromRecipe` or `Draw`, in both places.
   - **Pipelined path:** right before `Enqueue`. Read the pages directly, as `AddSnapshot` does: no flush hook and no sync.
   - **On a difference:** prepare the draw again from current memory, once per packet, the way line 430 does. Release the GPU lock first, since the re-entry would otherwise deadlock on `GpuMutex`. If the second capture also differs at its own check, record it as now: no loop. Count the retries in an existing stats line (like `captureRetries`).
   - **Keep the warning:** `AddSnapshot`'s live warning stays as the last check, for the committer.
   - **Comparing twice:** don't add a second memcmp per draw in `AddSnapshot` if you can skip it for regions this check just compared. If you can't, say so.
2. **Dispatches:** do the same in `Dispatch.cpp`, around its capture at line 399 and its recording under the GPU lock, if the same window exists there. Skip parked or ahead-resolved dispatches, which have their own checks.
3. **Tests:**
   - **The case:** a draw (and a dispatch, if you did step 2) whose descriptor table is in a live, host-backed or writable region. The test changes the table, for example a zero V# becoming a valid one, after the capture and before the check.
   - **What to check:** the draw's result shows which V# was bound, for example a buffer read written to a storage buffer or render target.
   - **Determinism:** use a seam that's deterministic (a test hook in the style of `Graphics::Recorder::SetQueuedLabelRecorder`), not a racing thread.
   - **Red:** with only the fix hunks reverted, the case binds the captured (zero) V# and prints the live warning.
   - **Green:** with the fix, it binds the new one. Put the tests in the fix's commit, or after it.
4. **Cost:** measure the check's per-draw cost on the Village-shaped harness from BF-046 and BF-055 (fork `exp/descriptor-set-release-measure` 1a90ccb64, `VILLAGE_GPU_SYNC=1`, 100,000 draws). Give ns per draw with and without the check, and the bytes compared per draw.
5. **Run the Linux check that mirrors CI:**
   - CI's configure flags;
   - the build;
   - `tools/check_test_registration.py build`;
   - `ANYPS5_REQUIRE_VULKAN=1 GALLIUM_OVERRIDE_CPU_CAPS=avx ctest --test-dir build --output-on-failure --timeout 120 --parallel 4 --output-junit ctest.xml`, run as an unprivileged user;
   - `tools/check_skips.py build/ctest.xml`.
   Then run the new tests with `--repeat until-fail:20`.
