## What
#9742 (ours, `fork/fix/agc-msaa-d32s8-depth-alias-htile-proof`, head b3e6311c1f; upstream `refs/pull/9742/head`) accepts one multisampled colour target over a native multisample depth plane when every HTILE word proves the depth clear. Its fix commit 219e925509 lists "a depth target whose HTILE carries stencil" as a limit. The gate is in `prepareDepthSampling` (`core/libs/prx/libSceAgcDriver/Graphics/src/DepthSurface.cpp`):

```
if (index == 0u && target.htileDepthOnly) {
    if (const auto sole = soleDepthAlias(range, target.samples)) {
```

A tester ran Dave the Diver (PPSA19115) on our `fork/test/7608-9717-9742` (e2eb3ff566, #9717 + #9742). It still stops at `depthAliasRefusal`, with:

```
[gpu] native multisample depth 0x237990000+0x10e0000 aliases multisampled colour target
      0x237990000+0x10e0000 (vk format 100 = R32_SFLOAT, 2 samples), newest clear 0x0 0x0 0x0 0x0
htileDepthOnly=0  format=130 (D32_SFLOAT_S8_UINT)  htileStencil=1  samples=2
aliasesOverPlane=1  aliasSamples=2  aliasActive=1  clearDepth=0.0
```

The colour side matches the accepted shape: one active alias of the target's sample count over the depth plane. Only `htileDepthOnly` diverts it. The pipe-aligned/VRS check above the loop passed, since the title reached the alias loop.

**Why the extension should be sound (check this yourself first, and stop and report if you find otherwise):**
- **Layouts:** `htileProvesClear(word, depthOnly, clearDepth)` already decodes both HTILE layouts:
  - depth-only: `|31 18| Max Z |17 4| Min Z |3 0| ZMask|`;
  - depth+stencil: `|31 12| Z Range |11 10| |9 8| SMem |7 6| SR1 |5 4| SR0 |3 0| ZMask|`, masked with `0xfffff00f`.
  These are Mesa radv's `radv_get_htile_fast_clear_value` layouts. ZMask is at bits 3:0 in both. A word that proves the clear has ZMask 0 and the clear's Z range, so the depth sample reads `DB_DEPTH_CLEAR` and none of the plane's bytes.
- **Stencil:** with the stencil in HTILE, the stencil is proven separately:
  - `htileProvesStencilClear` (SMem 0) is required on every word at import (L218 on #9742) and at a clear's completion (L494);
  - the stencil plane (index 2) still refuses any colour target over it, because `stencilPlane` is false there.
  So interleaving the stencil in the HTILE words doesn't touch the depth proof.
- **Completion:** the check at L453 (`sameDepthAlias`) is layout-agnostic.
