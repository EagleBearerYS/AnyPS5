## Why

Resident Evil Village (PPSA01556)'s profiled menu, P1 against A (2026-10-21, libs-fspa):
- `APS5_DIAG_SKIP_IMAGE_PROOF=1` (fork `diag/agc-vectors-split-a` d56bdc5155) cuts the lookup per recorded draw from **894.7 to 61.1 µs** (−93%);
- Revalidate falls from 63.5 s to 3.0 s per ~200 s. In A, the image tables are 50.7 s of that 63.5 s, and the full walks 58.5 s;
- presents 70 → 106 in the same 200 s.

So the image part of the template proof is nearly all of lookup. P1 is only a diagnostic (images go stale). This task makes the proof cheap *correctly*.

**BF-041** (fork `exp/table-o1-validation`, 2026-10-16, on main of that day; three commits):
- 0063b98265 `perf(agc): prototype a write-index reverse map for O(1) image table validation` (`APS5_TABLE_INDEX=1`):
  - a reverse index in the write tracker from 64 KiB blocks to subscriptions;
  - a subscription's generation is bumped by a stored tracker stamp (a collected CPU write, a fresh registration, a driver store or write-back), a GPU storage write noted pending, an unwatch, and a GuestAllocations free or remap;
  - a built `ShaderResources` subscribes its watched texture ranges and watched T# table spans;
  - Revalidate proves it with a sweep of the spans (one collect per span, memoized per epoch), a pending-registry scan when its serial moved, a compare of unwatched table spans, and one generation compare;
  - unwatched textures keep the byte compare, and storage-image views, DCC and depth elements keep their per-element predicate;
  - on a moved generation, only the bumped elements are proved again.
- ec08c6970d `test(agc): check the write index's invalidation sources` (`TableIndexValidation.cpp`, red per source under `APS5_TABLE_INDEX_BREAK`).
- be6fa03d8d `test(agc): measure per-draw image table validation with the write index` (the `DescriptorHeapCeiling` harness).
- **On its harness:** unchanged draws at 4,096 textures went from 5,326 to 1,229 µs, and Revalidate from 747 to 21.7 µs.

## Steps

1. **Read BF-041 against current main's `ShaderResources::Revalidate`, `fastRevalidate` and the full walk** (`Graphics/src/ShaderResources.cpp`). Two things are new since 10-16:
   - #8047's template audit: the periodic full walk, `APS5_TEMPLATE_AUDIT_MS`, default 1 s;
   - the fast proof's image checks: stamps, `KeyFastPath` key proofs, pending images (foreign / snapshot / T1), cache eviction and released objects, cleared views and register clears, DCC, depth (`FlushDepthPlanes`), the epoch gate (`APS5_NO_EPOCH_REVALIDATE`), and the template's own refresh (T1).
   - **Write a table:** each check, and whether the index replaces it (it's a memory-change question an index generation answers), needs its own event source (name it: eviction, DCC key store, depth flush, register clear), or must stay per element. That table goes in the result first.
2. **Port the index onto current upstream `main`** as `perf/agc-template-write-index`, behind `APS5_TABLE_INDEX=1` at first, default off.
   - Keep BF-041's split: the index, its invalidation tests, the harness measurement.
   - Adapt it to main's proof: every check the table says the index replaces is skipped when the subscription's generation is unchanged; every other check stays, for its elements only.
   - Add the event sources the table names, where they are small (for example, eviction bumping the subscriptions of the evicted object).
   - **The audit:** with the index on, say whether #8047's audit is still needed and at what interval. Don't remove it in this task; measure it on and off.
3. **Tests:**
   - Port `TableIndexValidation.cpp`, with each invalidation source going red under `APS5_TABLE_INDEX_BREAK=<source>`. Add a case for each new event source.
   - Run the existing proof tests with the index on and off (`ctest -R 'image_table|resource|revalidate|template|sampled|storage|texture'` under `APS5_TABLE_INDEX=1`). **No test may change result with the index on.** Report any that do.
4. **The harness, with P1 as the ceiling.** BF-117 found that the Village-shaped harness's `table` mode (fork 413c412595, `VillageDrawCost`) never makes templates on main: a T# load with a dynamic register offset isn't planned by the SRT walker, so every draw is an address-based build.
   - Make the table shape templatable the way Village's are. Village's draws are mostly template hits: `template hit 1910 µs (1967)` per 10 s at the menu, with tables of ~1,100-2,100 textures. For example, use a T# table at a fixed SRT offset keyed from user data. Say what you changed.
   - Run three arms, waited for the GPU (`AgcDriverWaitIdle` per frame, as BF-117 found): **main**, **the port with `APS5_TABLE_INDEX=1`**, and **main with `APS5_DIAG_SKIP_IMAGE_PROOF=1`**. The last needs the switch: cherry-pick the profile-only `chore(agc): a diagnostic switch that drops a template's image proof` from fork `exp/lane-p-proof-harness` 52abe5a31d onto a scratch copy, not the PR branch.
   - Report lookup per draw, Revalidate per call, full walks per second and their reasons (the `[rescache] revalidate` line), and the port's share of P1's saving.
   - Do it at 1,024 and 4,096 textures, with 0% and ~2% of the textures written per frame.
5. **The CI Linux mirror** on the final head:
   - CI's configure flags and the build;
   - `tools/check_test_registration.py build`;
   - `ANYPS5_REQUIRE_VULKAN=1 GALLIUM_OVERRIDE_CPU_CAPS=avx ctest --test-dir build --output-on-failure --timeout 120 --parallel 4 --output-junit ctest.xml`, as an unprivileged user;
   - `tools/check_skips.py build/ctest.xml`.
   Run it once with the index off (the default) and once with `APS5_TABLE_INDEX=1` set for the whole ctest. Add the conventions check. Your IPv6 baseline failures stay.
