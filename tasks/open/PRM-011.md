## 1. The unlock rules (PM-037 gap 6)
`NpTrophy2RecordUnlock_nid_no_patch` (TrophyStore.cpp:205-221 at 954118b817) records any id of 0 or more, including ids missing from the title's trophy data, the platinum posted directly, and progressive trophies posted directly. KytyPS5 (9e41d8320a, `src/libs/libTrophy.cpp` `RecordTrophyUnlock`, K:242-251; facts only, copy no code) ignores and logs an unknown id, ignores grade 1 (platinum), and ignores a progressive id unless the unlock comes from a statistic.
- Split the function in two:
  - an internal record that the statistics path (TitleTrophies.cpp:230) and the platinum award (TrophyStore.cpp:220) use, unchanged in behaviour;
  - the path UDS's `_UnlockTrophy` uses (Event.cpp:50). When the title's trophy data is loaded for that service label, it refuses: (a) an id not in the data, (b) a platinum, (c) a progressive trophy. Each refusal logs one line, in the style of the existing `[trophy] ...` lines and naming the id and the reason, returns false and records nothing. Listeners aren't called.
- Without trophy data for the label (a missing or malformed `trophyNN.ucp`), keep part 1's behaviour: any id of 0 or more is recorded. That keeps titles without the file working as before.
- Keep the change small (PM-037 estimates about 20 lines) and in the files that already own this logic.
