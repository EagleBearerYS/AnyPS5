# BF-074: find what BF-052's cached CPU-path indirect draws keep alive past their byte cap

from: Bug Finder (2026-10-17 17:17 PT)
for: any
priority: normal

## Why

BF-052 keeps CPU-path indirect draws in the draw cache (`APS5_CACHE_CPU_INDIRECT=1`) behind a byte cap, `APS5_CPU_INDIRECT_CACHE_KIB` (default 768 MiB). Fork `perf/agc-cpu-indirect-draw-cache-v2` is at 54bdd57ece.

**What happened in Resident Evil Village (PPSA01556) on this PC:**
- **Speed:** the median frame interval fell to 0.876× (p 0.0002).
- **Memory:** private memory rose ~1.7 GB from menu +1 to +16, more than twice the cap. It grew at 202 MB/min over the last 5 minutes, against ~62 MB/min with the cache off.
- **Result:** the PM killed it. It reopens only if a cloud harness finds a concrete cause and a fix keeps memory flat. No PC time is involved.

**What the code counts and doesn't** (54bdd57ece, `DrawCache.cpp`):
- `cpuIndirectCharge` counts each variant (`variantBytes`) plus the entry's shared parts: decode, compiled result, SPIR-V and ShaderMemory held bytes (`SharedParts`).
- It doesn't count Vulkan objects (pipelines, pipeline layouts, descriptor set layouts, descriptor resources a recipe holds) or driver memory.
- Nothing prints `CpuIndirectCacheSize()` at run time, so a game run can't show whether the cap ever filled.

**Two suspects:**
- holders the charge doesn't count grow;
- evicted entries' memory isn't returned, because something else still holds the same shared_ptrs (recipes, the dispatch cache, the pipeline journal).

3. **Arms**, always with `VILLAGE_GPU_SYNC=1`, 100,000 draws each:
   - OFF (`APS5_CACHE_CPU_INDIRECT` unset);
   - ON with `APS5_CPU_INDIRECT_CACHE_KIB=65536` (a 64 MiB cap, so eviction runs);
   - ON at the default 768 MiB.
   For each arm, give RSS (and VmData if easy) every 5,000 draws, next to the counted bytes and evictions.
4. **heaptrack** on the 64 MiB arm (and on OFF for contrast):
   - the top allocation sites by memory still held at the end, and by growth;
   - for each, whether `cpuIndirectCharge` counts it;
   - whether evicting an entry frees its allocations, or something else keeps them alive. Name the owner.
5. **If you find the holder:** propose a fix as commits on a new fork branch on top of 54bdd57ece. Either count the holder in the charge, or release it on eviction. Under the 64 MiB cap, memory must stay flat on the harness (RSS slope near OFF's over the last half of the run), and the cache must still hit. Add a test that fails without the fix.

Lavapipe's pipeline memory isn't NVIDIA's. Where heaptrack shows driver allocations, give their bytes per pipeline, so they can be scaled.
