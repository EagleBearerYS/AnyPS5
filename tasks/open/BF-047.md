# BF-047: lane C-1. Let address-based draws continue render passes on main (port of fable-void's bounded-access idea)
from: Bug Finder
for: any
priority: high

## Why

The AGC redesign is approved (`pr-drafts/arch/redesign.md`, "Lanes"; the user, 2026-10-16 21:54 PT). Lane C is the command stream: render passes that continue, and barriers only on real hazards.

**On upstream main,** `recordDraw` (`core/libs/prx/libSceAgcDriver/Graphics/src/Draw.cpp`) treats every address-based draw as touching unknown memory. The draw is address-based when `resources.HoldsLease()`. For such a draw:
- `passReads` is empty;
- `unknownMemory = addressBased || resources.UsesAddressTable() || resources.HasCopiedWrites()` goes into `PassAccess`;
- the queued DCC key and label stores are flushed before the draw (`HoldsLease()` → `FlushKeyStores` / `FlushStores`).

**What it costs:** at Resident Evil Village's menu, ~55% of draws are address-based, and ~590 render passes begin for ~850 draws per frame. Each pass loads and stores its attachments.

**fable-void fixed this in his tree:**
- **5d57298425** "order address-based builds by their known access ranges": a build reports its bounded reads and writes, and is "unknown" only when unbounded. A menu went from 33.5 to 48.6 fps, with draws from 702 to 359 µs, and 6,662 of 15,157 draws continued a pass instead of none.
- **f5afeb1817** "bound buffer accesses at a register soffset", in the recompiler's `ResourceTracker.cpp`.

His bounds come from his run-time pre-pass (`EvaluateBufferSites`), which main doesn't have. So this is a port of the idea onto main's capture path, not a cherry-pick.

His branch: `git fetch https://github.com/fable-void/AnyPS5.git wip/new-gpu-path` (head ed8f2d7a2e). **Fetching and reading his branch needs the user's OK in your own chat.** The PM is asking for it. If you don't have it, do the main-only parts (steps 1, 3, 4, 5) and say so.

## What to do

1. **Find what main knows** about an address-based build's accesses. Look at:
   - the capture's resolved pointers and SRT reads;
   - `GuestBufferMemory`'s `DeviceReads`, `InPlaceReads`, `Writes` and `WriteGrants`;
   - the BDA grants;
   - `ShaderResources::usesBda` and `HoldsLease`.

   Then report which accesses can be bounded at capture or build time, and which can't (pointers loaded from memory the capture can't evaluate, register offsets).
2. **Port f5afeb1817** onto main's recompiler (bound a buffer access at a register soffset that the capture can evaluate) if it applies; adapt it if needed. Note the disk-cache format bump it needs.
3. **Implement on current upstream main:**
   - an address-based build reports bounded reads and writes, and is unknown only when an access is unbounded;
   - `recordDraw` uses those bounds for `PassAccess` and for the queued-store flushes, as his `MemoryReadsUnknown` / `MemoryWritesUnknown` / `MemoryReads` / `MemoryWrites` do;
   - add the same to the dispatch path if it flushes stores for address-based builds;
   - `APS5_NO_BOUNDED_ADDRESS_PASSES=1` restores main's behaviour.

   If most accesses can't be bounded on main, implement the narrower rule instead and say why. The narrower rule: an address-based draw breaks the pass only when the open pass holds recorded GPU writes to guest memory that its unknown reads could see, or when its unknown writes could hit memory the pass reads.
4. **Tests,** each red on main and green with the change (or green both ways where they guard correctness):
   - two address-based draws with bounded, disjoint accesses continue one pass;
   - an address-based draw that reads a storage buffer the previous draw in the pass wrote still sees the write (the pass breaks, or a barrier lands);
   - an unbounded address-based draw still breaks the pass;
   - the queued key and label stores are flushed only when the draw's bounded ranges touch them.
5. **Measure** on the per-draw harness: `tests/execution/DrawRecordCost.cpp` on fork `exp/bf042-base` (9ac6d7dc8c), with address-based draws added if the harness has none. Report passes begun per 100 address-based draws, CPU µs per draw, and the flushes per 100 draws, before and after. Then run the CI Linux mirror and `ctest -R '^agc'`.
