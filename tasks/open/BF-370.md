## Why

mrfelek reports ([comment](https://github.com/boykopovar/AnyPS5/pull/7395#issuecomment-6685541901)) that #7395 at **014d1e30c3a298376e60842b641e9fbb69e186b6** still refuses an S# in Marvel's Wolverine (PPSA03671), compute shader 0x11d049aa00. His tree was upstream `main` c36ab99c74 + #12575 + #12746 + #7395, plus local driver patches. It fails the same way with and without #7395. His line, condensed by him (`x4` and `(...same...)` are his shorthand, not the printer's), is:

```
GetSamplerResource dword 0 is not a valid runtime value; chain: ReadConstBuffer@pc=0x0000b600(GetBufferResource(LoadAddressU32@pc=0x0000b5f0(GetAddressResource(ReadConstBuffer@pc=0x00002454(GetBufferResource(ReadConst(GetSrtResource, Immediate) x4), ShiftLeftLogical32(ReadFirstLane(SelectU32(LogicalAnd, IAdd32, Phi), Phi(LogicalAnd, LogicalAnd)), Immediate)), ReadConstBuffer@pc=0x00002454(...same...)), Immediate, Immediate, Immediate), LoadAddressU32@pc=0x0000b5f0(...same...), ...
```

So the chain is:
- a record table from the SRT;
- the record's 64-bit pointer, read with one `s_load_dwordx2` at offset `key << imm`, where the key is a waterfall `v_readfirstlane` of a value updated under EXEC;
- a V# read with `s_load_dwordx4` through that pointer at an immediate offset;
- the S# read with `s_load_dwordx4` from that V#.

#7395 is ready and approved. We need to know whether this is a regression on the branch, which must be fixed before it merges, or a shape #7395 never planned.

**What the PC has ruled out by reading** (no need to re-check):
- **967f0dbebb8 (BF-319)** only changes `TableSnapshotter::Run()`'s `hasIndirect` in `ResourceMaterializer.cpp`. That code runs at dispatch, so it can't cause a refusal at recompile time.
- **#7880's checks (merged into the branch at 319fa1f360b)** don't look relevant to this chain:
  - `AvailableAt`'s dominance check: the record reads at 0x2454 feed the V# load directly, with no Phi between them.
  - The `merged`/`UnwrapTableRead` change and the hop guard: the pointer words aren't Phis and there are no pointer hops.
- **mrfelek's other patches** (#12575, #12746 and his `ImageTableAbi.hpp` `Version` pick) are driver-side or run-time. The refusal comes from `ResourceTracker` planning.
- **Capmare's clean Wolverine run at the old head 59b319a779** presented no frame. mrfelek's run stops after the intro logos. So that run may never have reached this shader, and it isn't proof of a regression.
- **The existing test doesn't cover this key.** `agc_driver_nested_sampler_table` (`NestedSamplerCode` in `core/libs/prx/libSceAgcDriver/tests/execution/ImageTable.cpp`) takes its record key from a scalar load. No existing test feeds a `ReadFirstLane` waterfall key into record → pointer → V# → S#.

**The leading suspects:**
- **The waterfall key itself.**
- **The nested path's other-consumer refusals** in `TryMakeTableColumn` (`ResourceTracker.cpp`, ~853-869 at 014d1e30c3):
  - the V#'s handle has a use outside the S#'s reads;
  - an S# word has a user other than its `GetSamplerResource`;
  - the V#'s word loads feed another handle.
  These shapes are known to be unimplemented in #7395: commit d908758281f dropped the tests pinning them, and 9343a179b34 and ca146488060 dropped the S# cases. They're what #9790 adds, which is stacked on #9457 → #8939 → #7395. A material V# that also feeds constant reads, or a T# from the same V#, would hit them.
