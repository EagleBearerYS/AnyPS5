## Context

GAC-022 (cloud-2) measured the DCC label fix d71ef7b1e1: every one-value label (zero labels included) took the GPU mutex and ran `ClassifyFill`, which walks every live storage image twice. Added cost per zero label: +0.05 us at 0 live images, +1.7 us at 259, +117 us at 3,000, all under the GPU mutex, and 13-27 % of zero labels waited when another thread held the mutex. GAC-022 §2.4 proposed a gate on the live images' `dccAddress`es, checked before the GPU lock.

**8e5b0022cb** ("perf(agc): look a label's address up among live key addresses before the device lock", on top of d71ef7b1e1) does that:
- `LiveImages` (Texture.cpp ~165) gains `keysMutex` and `std::unordered_map<std::uint64_t, std::size_t> keyAddresses`, a count of live images per `descriptor.dccAddress`.
- `StorageTexture::Create` counts the image (if its `dccAddress` is non-zero) before it pushes it to `live.textures`. The destructor uncounts it only if `std::erase` found it in the list. So the map is always a superset of the listed images' key addresses.
- New `StorageTexture::KeysLiveAt(address)`: one lookup under `keysMutex`, which is never held across a walk of the list and never nested.
- `NoteKeysStore` (LabelHistory.cpp) returns before the GPU lock when `!KeysLiveAt(address)`. On a hit it runs as before (GPU lock, `ClassifyFill`, `NoteKeysFill`).

The explorer trees carry the same commit: fork `test/village-fast-ports-dcc2` a7bc16de04 and `test/village-fast-main-dcc2` 7789f4c4ed (for reference only; this PC builds those).
