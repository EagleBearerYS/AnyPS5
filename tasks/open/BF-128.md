# BF-128: what #9508's per-draw image-table map costs for Village-sized tables (BF-108's bench on #9508)
from: Bug Finder
for: any
priority: high

## Why

BF-127 (`results/cloud-4/BF-127.md`) found that #7642's GPU lookups only add value on #9508 if they replace #9508's per-element image-table map for large tables. That map is rebuilt on the CPU by `ShaderResources::writeHeapTableMap` (`core/libs/prx/libSceAgcDriver/Graphics/src/ShaderResources.cpp:5946-6033` on #9508's head) on every refresh, with one slot lookup per element. It reuses the ring span only when the words are identical and the chunk is still held (6035-6042). Resident Evil Village (PPSA01556)'s table has ~21,500 entries, i.e. ~86 KB of slot words per stage per refresh. Nobody has measured what that costs. The number decides whether #7642 is rebuilt on #9508 (route B) or parked.

   - Also check that the bench's stages actually go GPU-mode: `gpuResolvedImages`, the `[heap-slots]` / `[gpu-heap]` counters, `APS5_VERIFY_GPU_HEAP=1` once.

3. **If it's live:** run the bench in table mode with `APS5_GPU_HEAP=1 APS5_PIPELINE_STATS=1` (and `APS5_DRAW_PIPELINE=1`, which #9508 assumes, if the bench needs it). Use table sizes `VILLAGE_TABLE=4096`, `8192` and the ~21.5K-entry variant (21,504 or the bench's nearest). For each, report:

   - how often the ring span is reused versus rewritten;
   - the same draw with `APS5_GPU_HEAP` unset, for comparison (the per-draw path's descriptor cost for the same table).
4. **Verdict line at the top:** does the map cost for a ~21.5K table exceed ~100 µs per recorded draw (the lane A kill line), or less?
