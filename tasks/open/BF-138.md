# BF-138: a measurement-only port of the write index onto cf2c667060, so the Village pair runs on the PC's warm shader cache
from: Bug Finder
for: any
priority: high

## Why

The PC's Village pair for the write index (BF-124, fork `perf/agc-template-write-index` 8151a19d21 on a6dcea9279) runs I0 against I1 in one build, with `APS5_TABLE_INDEX` off and on. The PC's warm shader-cache folder is keyed by the recompiler sources' SourceVersion (`ShaderCacheVersion.cmake`). a6dcea9279 has different recompiler sources from the warm key's bases, so tree I would need a cold warm-up run (~25 min) and a new 5-8 GB cache folder.

cf2c667060 (the Coordinator's plain-main control libs-c2, and BF-123's base) has the warm key. The Coordinator tried replaying a6dcea9279..8151a19d21 onto the warm tree and hit a conflict in `Execution/src/GuestMemory.cpp`, a3c1b88aca's 264-line hunk. This branch is for measurement only; it's never meant for upstream. The PR branch stays BF-124's/BF-136's on current main.

## Do

1. **Port.** Cherry-pick BF-124's five commits (a3c1b88aca, a1fb8ce5a8, 63d992bfaa, 943d45f44b, 8151a19d21) onto **cf2c667060**, as fork branch `exp/agc-template-write-index-cf2c`.
   - Resolve the `GuestMemory.cpp` conflict, and any others, keeping cf2c667060's behaviour plus the index.
   - Say what conflicted, and what in cf2c667060 differs from a6dcea9279 there.
   - **The port must not touch `core/shader/`.** Otherwise the warm key moves. Check this with `git diff --stat cf2c667060 HEAD -- core/shader` (it should be empty) and say so.
2. **Test:**
   - build;
   - BF-124's invalidation tests with `APS5_TABLE_INDEX_BREAK`'s reds, as in BF-124, at least each source's red once and green ×5;
   - `ctest -R 'image_table|resource|revalidate|template|sampled|storage|texture'`, both with the switch off and on, matching per test;
   - the harness's 4,096-entry 0% row once, main against index, to confirm the port behaves like 8151a19d21.
3. **Push** the branch to the fork.
