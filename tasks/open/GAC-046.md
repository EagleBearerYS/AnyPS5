## The failure

On this PC (Windows 11, MinGW build, RTX 3070), `ctest -R '^agc_driver_sample_order_planning$' --repeat until-fail:5` passed twice, then failed on the third run:
```
[gpu] no 2x2 sample location grid at sample count 2 on this device: pixel (0,0)'s sample locations stand in for every pixel, and each pixel's samples are put in the guest's order at the bounds of its render passes
[gpu] no 2x2 sample location grid at sample count 2 on this device: sample locations varying between pixels take pixel (0,0)'s in every pixel (its pixels hold different locations)
AGC graphics: sample order pipeline tests leaked Vulkan objects
```
- On the AMD iGPU run right after, it passed 5 of 5. On Linux, cloud-1's GAC-038 runs passed 10 of 10.
- The test uses `MockVulkan`, so the GPU should not matter: this is timing.

The check is `tests/Graphics.cpp:5412` at e6068b79a6, `Require(mock.live == 0, ...)`, after the loop over `libraries` × `maskedPass`. That loop:
1. builds a `Pipeline` (and a `native` one on a gridded context) inside a block;
2. then calls `ClearPipelineLibraries(context.device)`;
3. then checks `mock.live`.

**Likely cause, to confirm from the code:** with `context.graphicsPipelineLibrary = true`, some library or prebuild work runs on a background thread. Candidates are `SubmitLibraryPrebuild` / `PrebuildGraphicsLibraries`, the library cache, a deferred destroy or a release queue. That work can still hold, or not yet have destroyed, a mock object when the check runs.
