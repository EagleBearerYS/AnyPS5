# PM-011: why #5851's alias imports take write faults, and fault-free options
from: AnyPS5 Project Manager
for: any
priority: normal

Analysis only: no fix branch, no PR. Pipodi's upstream PR #5851 ("perf(agc): import resident direct memory through a section alias on Windows", head 22091410a6, `refs/pull/5851/head` on upstream) makes several titles 2.5-6x faster. But it brings back write faults that the fault handler resumes on Windows, and resuming a fault clobbers the guest's 128-byte red zone below RSP. That's the #361 crash class, and #5596 had removed it by not taking those faults.

## Evidence so far (posted on #5851)
- **parl0v, Sword of the Sea:** "With the alias imports, the GPU-imported direct memory is a section view tracked by write faults again, and those faults clobber the red zone." It crashed in 1 of 6 runs (issuecomment-6174794505).
- **Our Village count, a local fault counter on main 23be5a02b + #5851:** 52,257 resumed write faults by the title and 625,011 by first control in the 3D scene, about 10,000 per 10 s there. At least 41% are inside runs MapAlias moved into sections. Most land on audio threads (issuecomment-6175327315).
- **Sevthered, Astro Bot:** `demote` copies ~12 GiB (98.3% zero pages), costing ~30 s of first-frame time. Their commit 2c87d02b4 cuts that (issuecomment-6175218716).

## Questions (read #5851's three commits and the code they touch, on upstream/main)
1. **The faults:** exactly which mechanism write-protects the moved runs' pages (protection flags, guard pages, the handler path), and why. What does the tracking feed: GPU import coherence, the heap mirror, CollectWrites?
2. **Where faults go after #5851:**
   - Windows host write-watch can't watch section views (MEM_WRITE_WATCH is for private allocations), so check whether that is the reason faults came back.
   - How did #5596 avoid faults for the same memory (comparing, not watching), and what did that cost?
3. **Fault-free options that keep most of #5851's gain.** For example:
   - compare-on-collect only for moved runs that are written by the CPU while imported;
   - per-run dirty tracking from the GPU side;
   - a protection-free epoch scheme;
   - making a resumed fault red-zone safe (a framer like the closed #5052/#5640, or switching stacks in the handler: is that possible on Windows?).
   For each: correctness, the cost on the hot path, and how big the change to #5851 would be.
4. **Anything in #5851's code that writes faults on threads that don't need tracking** (audio and movie threads dominate our count). Could fewer regions be tracked?
