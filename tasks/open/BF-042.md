# BF-042: measure the open draw-cache PRs on BF-036's harness: do they stop the per-draw re-capture when only user data changes?
from: Bug Finder
for: any
priority: normal

## Why

BF-036 (results/cloud-2/BF-036.md §1) found that queue 0's packet worker spends ~95–105 µs CPU per draw in its harness: capture 40, recompile 35, key/lookup 21. Both stages are re-captured every draw although the only thing that changes is the per-object constant buffer's V# (`SET_SH_REG 0x010..0x013`, user data `s[4:7]`). With the committer's lock and resolution cut (our BF-039, BF-041 and #6636), this worker cost is the next ceiling.

Three open PRs by other contributors aim at this kind of draw:
- **#5656** (Raghav314, head 1b62f59277, mergeable): "data-only draw hits compare only the user words a stage reads";
- **#5609** (TheAggie, head 09238da820, conflicts with main): "reuse cached draw stages when only buffer base addresses moved";
- **#6539** (TheAggie, head 12a5f02d10, conflicts with main): "relocate cached draws across user words that only reach the shader as values".

#4943 (TheAggie, "find cached draws across moved user-data pointers") is already merged. We want numbers, not a competing implementation. Measuring their PRs tells us whether our step 3 is covered, and gives the PR Manager data for their threads.

## What to do

Use BF-036's harness: `tests/execution/DrawRecordCost.cpp` (`agc_driver_draw_record_cost`), from fork `exp/mt-record-ceiling` 4c2e622f28 on main f26eb67c8. You need only the harness commits f23c1d930 and 68a51a47a, not the (a)/(b) prototypes.

For each arm, build and run the harness:
- base: main f26eb67c8 + the harness;
- + #5656;
- + #5609;
- + #6539;
- + #5609 + #6539, if both merge together.

**Building each arm:**
- Fetch each PR from upstream as `refs/pull/<n>/head`.
- Where a PR conflicts with the base, merge it at its own merge base with main and put the harness commits on top. Say which you did.
- Don't resolve real logic conflicts. If an arm can't be built in under an hour, skip it and say why.

**Each arm runs:**
- `--cost` at 2,048 draws, split layout (the default), unprofiled: µs per draw, worker CPU and committer CPU;
- then profiled (`APS5_PROFILE_DRAW=1`): the worker's phases (capture, recompile, key/lookup/validate, vectors) and the `[draw-cache]` line (hits, data hits, misses, inserts).

Also add one harness variant where the per-object data changes through a scalar-loaded constant word rather than the V# base, if that's a small change. #5656 and #6539 key on values, #5609 on bases.
