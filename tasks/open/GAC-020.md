## Context

The coordinator ran #6146's and v3's GPU tests on an NVIDIA RTX 3070 (Windows, MinGW). Two Windows/NVIDIA-only test failures came up, and both are fixed in the tests only.

1. **At #6146's head e252c03bc6:** `agc_driver_depth_expand_review` failed, "second expand: second read base does not hold the drawn depth".
   - The two far-corner texels of the second gradient (offset 0.5) were 4.05e-6 and 4.11e-6 low (68-69 ulps at 0.875), against a fixed 4e-6 tolerance. Lavapipe matches exactly.
   - **Fix: a4137dc3f1.** Both expand tests now accept half the gradient's x step (0.5 / 65536 ≈ 7.6e-6). That still catches a read one texel off, which is a full step.
2. **At v3 bac2e3285f:** `agc_driver_depth_expand_out_of_place` failed in the full run, at `split-copied-buffer-read` ("stored 0, expected 1"). The case passes when run alone.
   - The trace showed the heap-mirrored case's second range (16 MiB, left registered) being imported inside the copied case, after the case had set its budget to live + 1.5 ranges. That took the budget, so the case's first range was never imported.
   - **Fix:** each split case first runs an address-based copy with no budget, so earlier cases' leftovers are imported before the budget is set. It's folded into v3's test commit.

The new branch is fork **`fix/agc-db-depth-expand-v4` 6596a1d3a2**, on e252c03bc6:
1. a4137dc3f1 `test(agc): allow half a gradient step of depth error in the expand tests`;
