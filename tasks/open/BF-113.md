# BF-113: reserve a draw variant's words before tagVariantRuns fills them (stacked on BF-108's PR)
from: Bug Finder
for: any
priority: normal

Cloud 4 suits this best (it did BF-108 and has that tree), but any worker can take it.

## Why

BF-108 found that a draw variant built over a stride-48 table holds `words` at 1.33× their size: `tagVariantRuns` (`core/libs/prx/libSceAgcDriver/Execution/src/Driver/Draw/DrawRelocate.cpp`, the loop over `regions`) grows `variant.words` with one `resize` per region and no `reserve`. The dispatch insert reserves first (`Dispatch/DispatchInsert.cpp`, `fresh->runs.reserve(srtRegions.size()); fresh->words.reserve(capturedWords);`). BF-108's figures on the test file's `WideStride` table: 393,224 words held in a capacity of 524,304; a reserve brings it to 393,224 (−25%). Since BF-108 counts capacities, the draw cache's byte budget then holds more entries in the same bytes.

## The change

- In `tagVariantRuns`, before the region loop, add the regions' word counts and `variant.words.reserve(variant.words.size() + total)`.
- `runs`: reserve at least `regions.size()` more when `relocatable == 0` (one run per region there). For the relocatable path the run count isn't known up front; leave it unless a cheap exact count exists.
- Check the other vectors filled in the same function or its caller for draws (`shared`, `runBases`, `dataPositions`, `dataSlots`) the same way, and reserve where the final size is known before the fill. Say in the result which ones you changed and which you left, and why.
- No behaviour change apart from capacities.
