# BF-159: build a sampled 3D view at full extent, uploading only the slices with committed guest memory (Ghost of Tsushima's 20 GiB cap)
from: Bug Finder
for: any
priority: high

## Why

**The stop.** Ghost of Tsushima Director's Cut (PPSA02225), on milescoviello's stack (Linux, RTX 4070 Ti), binds this view about 9 minutes in:
```
[gpu] sampled view 0x1564050000 (320x1280 format 71, dimension 4, tile 7, slices 0..899) covers 4781 MiB
[gpu] view 0x1564050000 of 4781 MiB lies in the guest allocation 0x1500000000..0x1598600000 (2438 MiB, ...): 157 of its 900 slices fit in the range
```
- Building the view grows the host heap ~3 GB in 2 s, and the run dies at the 20 GiB cap at 563-572 s.
- His local cut kept only the 157 slices, which changes what a normalized z samples. With it, the run goes on to the intro cinematic. So this view is the one stopper there.
- Links: https://github.com/boykopovar/AnyPS5/pull/9318#issuecomment-6353408402 and #issuecomment-6353966706.

**The surface, decoded on `main`:**
- Format 71 is RGBA16F, and tile 7 is `kR64KBX`.
- A k3D surface in Z/R 64KB_X takes `DescribeSurface`'s per-slice branch (`TextureTiling.cpp:394`): `layers = depth = 900`, `layerBytes = guestBytes / 900`, not `thick`.
- Each slice is one contiguous guest range (`GuestLayerOffset`).

**What `main` does with it:**
- `cachedTexture` (`ShaderResources.cpp`) snapshots the whole `guestBytes` with `GuestMemory::ReadCommitted`, which reads uncommitted pages as zeros (`GuestMemory.hpp:31`, tested by `PartiallyResidentSnapshot.cpp`).
- The sampled upload (`Texture.cpp`, ~335-430) then allocates:
  - a host-visible staging `Buffer` (guestBytes);
  - a tiled `DeviceBuffer` (guestBytes);
  - a linear `DeviceBuffer` (900 × `sliceLinearBytes`);
  - the full VkImage.
- So one view costs ≈ 9.3 GiB of host memory (snapshot + staging) and ≈ 12 GB on the device.
- **The texels past the committed range are already defined as zero on `main`.** They're just materialized at full size.

**Why not a depth bound:** the depth coordinate is normalized, so trimming the depth moves every sample. MarcZX10's #9318 (`BoundArrayWindow`) trims 1D-array, 2D-array and cube views by layer, which is right for indexed layers. This fix must not trim, and must not touch array views, which stay with #9318.

## The change (option 1)

**Same texels as `main`, less memory.** For a sampled **k3D** view in `DescribeSurface`'s per-slice branch:
1. **Find the slices that hold committed guest memory,** from `GuestMemory::DescribeCommitted` over each slice's range (`GuestLayerOffset(slice)`, `layerBytes`), or an equivalent walk of the committed runs.
   - A slice with any committed page is **uploaded**. Its uncommitted pages still read as zeros through `ReadCommitted`, as on `main`.
   - A slice with no committed page is **skipped**.
   - Base the rule on commitment, not on the allocation: if some other mapping is committed past the allocation, `main` reads it, and so must we.
2. **Snapshot, staging and tiled buffers** cover only the uploaded slices, packed or as runs. Detile only those slices.
3. **The skipped slices must read as zero texels, exactly as `main`'s zero bytes detile.**
   - **Copy zeros, don't clear:** `vkCmdClearColorImage` can't take block-compressed formats, so copy a zeroed device buffer (`vkCmdFillBuffer` 0) into each skipped slice with `vkCmdCopyBufferToImage`. One slice's worth of linear zeros, reused. That reproduces `main` for every format, BC included.
   - If you can show a clear is bit-identical for the non-compressed formats, use the clear there and the zero copy for the BC ones. Say which you do.
4. **The cache entry:**
   - Its compare and generation cover the uploaded slices only.
   - A later commit or decommit anywhere in the surface's range must rebuild it. Check that the `Commitment` state the cache already keeps (`it->committed != committed`) covers the whole range, and say how.
   - Keep `untrackedKey`, the DCC-key path and `SampledTextureBudget` accounting consistent, and count the real bytes held.
5. **Scope:**
   - Apply it only where it's contained: the plain sampled upload. Leave the storage-image source, depth copy, sRGB expand and DCC paths exactly as on `main`, and say which of them can't take a partially committed 3D view.
   - Thick 3D layouts (slabs of `blockDepth` slices) can follow the same per-slab rule if that's contained; otherwise leave them unchanged and say so.
   - Arrays and cubes are unchanged (#9318's).
6. **Logging:** extend the existing `covers … MiB` and `lies in the guest allocation …` lines, or add one next to them, saying how many slices were uploaded and how many zero-filled. Log at the same rate-limited cadence as the existing lines.

## Tests

On lavapipe, in `tests/execution/`, next to `PartiallyResidentSnapshot.cpp` if that fits.
- **The reproduction.** A k3D R64KBX (or Z64KBX) RGBA16F surface of, for example, 64x64x64. Reserve its whole range, and commit only the first N slices' pages, with N not a multiple of anything convenient (say 23), and the last committed slice partial. Each slice gets a distinct pattern.
  - **Sample** with normalized z at slice centres across the whole depth, including the last committed slice, the first uncommitted one and the last one.
  - **The texels:** committed slices read their pattern, the partial slice reads its pattern with zeros past the commit, and uncommitted slices read zero.
  - **Byte-identical to `main`:** the same sampled values come out on `main` and with the change. Run the same test on both trees.
  - **Memory:** the snapshot or staging bytes held for the view cover only the uploaded slices. Use an existing counter (`SampledTextureMemory`, the cache's entry size) or a test-visible one. **This is the red:** on `main` it holds the full `guestBytes`.
- **Commit changes:**
  - committing more pages past the prefix after the first sample must rebuild the view and show the new slices;
  - decommitting a committed slice must rebuild it and show zeros;
  - unchanged memory must not rebuild.
- **Controls:**
  - a fully committed 3D surface is unchanged, with the same texels and memory as `main`;
  - a BC-format 3D surface partially committed gets zero blocks that decode like `main`'s, if lavapipe samples BC 3D;
  - a 2D array partially committed behaves exactly as on `main`, because this change doesn't apply to arrays;
  - the existing `PartiallyResidentSnapshot` test still passes.
