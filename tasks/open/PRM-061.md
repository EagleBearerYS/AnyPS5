## 1. Fix: a page decommitted inside a kept slab returns stale texels

A cache lookup hits when `it->slabs == slabs` (the set of slabs with any committed page is unchanged) and `equalsCommittedSlabs` passes. `equalsCommittedSlabs` calls `GuestMemory::EqualsCommitted` per slab run. That compares only the pages committed *now* (`EqualsCommittedUnsynced` walks `CommittedRanges`). Take a page that was committed when the snapshot was taken and is decommitted later, while its slab keeps other pages. It's skipped, the lookup returns the old texture with the old texels, and a fresh build would read zeros there (`ReadCommitted`).

Fix it on this PR's slab path. `CommittedSlabs` also keeps the view's committed byte ranges, relative to the view's base, as `committedSlabs` already reads them (`described.ranges` or the passed `committed`). Its defaulted `operator==` then compares them, so any change in which pages of the view are committed misses and rebuilds. Keep the change small; no new GuestMemory calls per lookup.

Out of scope, but say it in your result: main's full-size (non-slab) path has the same gap through the same `EqualsCommitted`. This task doesn't change it.

**Test for 1:** a new mode in `PartiallyResidentSnapshot.cpp` with its own ctest entry, following the existing `--committed-volume*` cases' style:
1. Commit two slabs of a k3D view.
2. Sample it (snapshot taken).
3. Decommit one page inside one of those slabs, keeping the slab's other pages committed.
4. Sample again. The texels of the decommitted page must read zero.

Red on 4a90a1a1d0 (give the failure message), green with the fix.

## 2. Tests the review found weak

- **`PatternElement`** (~lines 499-504) depends only on the format and the slab, and `CommitSlab` (~516-521) repeats one element across the slab. The `-samples` checks can't tell where inside a slab a texel came from, so a wrong per-slab packed detile offset (`slot.tiledOffset + mip.tiledOffset` in Texture.cpp) would still pass. Make the element encode its position within the slab (x, y, z, or its element index), and the expected values in the checks with it. Show that it catches the error: with the per-slab offset deliberately perturbed locally, not committed, a `-samples` case fails. Quote the message.
- **No case has every slab uncommitted**, so the `uploaded`-empty branch (Texture.cpp ~420-425 and ~443-447: no staging, tiled or linear buffers, zero snapshot bytes on the cache side) never runs. Add a mode in which the whole view is uncommitted. It must sample zeros without failing. Note that `committedSlabs` returns `nullopt` only when *every* slab is committed, so an all-uncommitted view takes the slab path with an empty slab list. Check that this is the path it takes.
- **`CommittedCaseFor` accepts `--committed-volume-mips` and `--committed-volume-bc`** (~474-475), but CMakeLists registers only their `-samples` variants, so the mip and BC byte accounting never runs under ctest. Register both, with the same properties as their neighbours, including the WIN32 `ENVIRONMENT_MODIFICATION "PATH=path_list_prepend:$<TARGET_FILE_DIR:libc>"` the neighbours carry.
