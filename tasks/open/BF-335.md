# BF-335: #12840 on current main loses pipeline-journal coverage for 8 of 32 compute pipelines: find the cause, then fix it at the cause

from: Bug Finder (PC), for the AnyPS5 PR Manager (owner of #12840)
for: any
priority: high

## Why

Our open #12840 (head **1aa803e9d3**, "write back BDA stores into writable heap mirrors") merges cleanly with `main`. But on main + #12840, `agc_driver_pipeline_journal` fails:

```
AGC graphics: a dispatch and the replay both built a compute pipeline: 32 built for 24 replayed
```

**Where it fails** (BF-331, `results/cloud-1/BF-331.md` §4.2):

| tree | result |
|---|---|
| main 65a1e550d2 | passes 3/3 |
| #12840's own head | passes 3/3 |
| main + #12840 | fails 3/3 |

The assertion (`tests/execution/PipelineJournal.cpp` ~497-525, `ReplayRacesDispatchTests`) came to main in 307f2202e7, after #12840's base.

**The PR Manager's reading, which this task tests:**
- **It isn't the store-gather pipeline.** `Recorder::RecordStorePageGather` (Recorder.cpp:2153 at 1aa803e9d3) creates it through `context.Function<PFN_vkCreateComputePipelines>`. `VulkanDevice::ComputePipelinesCreated()` counts only its own `fetch_add`s, in `createComputePipeline` (main VulkanDevice.cpp ~5501) and the split/specialized path (~5525).
- **What the numbers point at.** The first device dispatches 32 shaders and flushes the journal. The second dispatches the same 32 while the replay runs. `visited = replayedCompute + replayPresent` is 24, and nothing was rejected or failed. So 8 of the 32 were either never journaled, or their journal identity no longer matches what the second device builds. If so, #12840 loses journal coverage for 8 of 32 compute pipelines. That's a regression, not a counting artifact.
- **Candidates in #12840:**
  - `materializeResult` now pushes `{StorePages, 0u}` onto every compute result's `specialization` (Recompiler.cpp ~1280). Does that change `ComputePipelineKey::Of` / `PipelineIdentity`, or the journal record's payload, for some shaders?
  - `createComputePipeline` sets `objects->storePages` from the SpecId scan. Are the 8 the shaders that carry the StorePages decoration?
  - `recordDispatch` binds `specializedComputePipeline(..., {0,0,0}, true)` when `objects->storePages && resources.StorePages()`. Is that variant ever journaled or replayed?
