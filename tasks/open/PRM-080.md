# PRM-080: #13551: serialize event-callback registration with the final terminate (MarcZX10's CR)

from: AnyPS5 PR Manager
for: any
priority: high

## Why

#13551 (`feat(libSceSaveData): deliver backup completions to a registered event callback`) has head **629477b800**, fork branch `feat/libSceSaveData-event-callbacks`, on #12748's 46c8ff27a6. It was opened today from BF-311. MarcZX10's review, https://github.com/boykopovar/AnyPS5/pull/13551#pullrequestreview-5716776526, blocks on one finding:

> In `sceSaveDataRegisterEventCallback`, the `g_initializations` check happens before taking the callback locks and is not synchronized with the final `sceSaveDataTerminate` transition. If registration reads a nonzero count, then final termination sets it to zero and `DetachEventDelivery` clears the callback, registration can subsequently store the callback and return success with no worker. A later `Initialize3` starts a worker without clearing that callback, so events may call it after reinitialization even though it was unregistered by termination.

He points at two places at 629477b800, both in `core/libs/prx/libSceSaveData.native/Export.cpp`:
- registration: L1763-L1775;
- final termination and the callback detach: L1292-L1311.

## What to do

1. **Start** from 629477b800. Stop if the head differs.
2. **Fix the race.** Registration's initialized-state check and the callback store must be atomic with respect to the final terminate's transition to 0 and its detach.
   - For example, take the lock that guards `g_initializations` (or the one the final terminate holds while detaching) around both the check and the store.
   - Or have the final terminate and registration agree under one lock.
   - Keep the existing semantics:
     - NOT_INITIALIZED before initialization;
     - PARAMETER for a null callback;
     - replacement on a second registration;
     - unregistering needs no initialization;
     - a terminate from inside the callback returns BUSY;
     - completions not yet delivered are dropped on unregistration.
   - **No lock-order inversion with the delivery thread:** the terminate joins it, and the callback runs on it. A terminate from inside the callback must still return BUSY, not deadlock.
3. **A regression test** in `core/libs/tests/GuestSaveDataEventCallback.cpp`. It races registration against the final `sceSaveDataTerminate` in a loop of many iterations, with two guest threads. Each iteration must end in exactly one of these:
   - registration returned NOT_INITIALIZED;
   - or it returned OK and the callback was cleared by that terminate.

   Then `sceSaveDataInitialize3` again, trigger a backup completion, and assert the old callback is **not** called unless it was registered again.
   - **Red on 629477b800:** the race must show reliably. If it needs a test-only hook to widen the window, say so and keep the hook out of the library.
   - **Green with the fix.**
4. **One commit,** `fix(libSceSaveData): register the event callback atomically with the final terminate`. Push it to the same fork branch as a fast-forward: `feat/libSceSaveData-event-callbacks` **is** #13551's PR branch.
   - **Don't push the PR branch.** Push to a new fork branch, `prm/13551-terminate-race`.
5. **Verify on Linux:**
   - `guest_savedata_event_callback --repeat until-fail:50`, plus the SaveData suite;
   - the red on 629477b800's code with only the new test;
   - `tools/check_conventions.py` and `tools/check_test_registration.py build`.
