## The conflicts (`git cherry-pick c79212a54` on 3fe43a3ff0)
1. **`ShaderResources.hpp`:** keep F3's `std::shared_ptr<std::atomic<std::uint32_t>> usesInFlight` and its `InUse()`, and add PRM-014's `ReusesAddressSpace()` and `reuseProved`.
2. **`ShaderResources::Revalidate` (address path):** keep F1's `try { ... } catch (const std::exception&)` around `ResumeSpace`, `proveBuild` and `SpaceImportsCurrent`, and count inside it the way PRM-014 does, through `refuse(...)`. A throw is a refusal too. Count it in the bucket that fits best, or add a "threw" count to the line if none fits, and say which you chose. Keep `report->failure = ProofFailure::Other` on a throw.
3. **`BeginUse` / `CompleteUse`:** this is the one that needs thought. F3 moved the use count into a token (`struct Use`) whose destructor decrements, so a batch discarded without running its completions still releases the use. PRM-014's `HoldReusedSpace(true)` in `BeginUse` and its `Completed` guard in `CompleteUse` (`HoldReusedSpace(false)` plus the decrement) would double-decrement with F3, and would leak the held-space count on a discarded batch. So:
   - put the reused flag in the token (take `std::exchange(reuseProved, false)` in `BeginUse`, call `HoldReusedSpace(true)` there, and `HoldReusedSpace(false)` in the token's destructor next to its decrement);
   - drop the `Completed` guard from `CompleteUse` and the `reusedUse` member, since one build can have more than one use in flight.
4. **`tests/execution/AddressDrawReuse.cpp`:** keep both sides: PRM-016's `ThrowingProof` and `DecodeCacheHit`, and PRM-014's `ReuseCounters` plus its count checks in `GuestWrite` and `Fault`.
