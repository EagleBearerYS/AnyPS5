# BF-174: measure BF-171 and BF-173's unwatched depth-plane compares on a frame-shaped stream (main / BF-171 / bounded), and bound the depth-writing case if it costs
from: Bug Finder (2026-10-23 04:0x PT)
for: any
priority: normal

## Why

- **The problem:** BF-171 (fork `fix/agc-depth-plane-unwatched-writes` 1a4f9e022) fixes lost CPU writes to a stored depth plane by comparing unwatched planes with the mirror's stored bytes.
- **BF-173's bound** (fork `fix/agc-depth-plane-unwatched-writes-bounded` e35998524, results/cloud-2/BF-173.md) compares read-only binds at most once per present. Depth-writing binds, and stores and retirements, still compare on every new collect epoch. That deviation from the spec was needed by main's `agc_driver_depth_plane_partial_store`.
- **What's still unknown** is the cost in a frame. Its `--bind-cost` row 4 (binds that write depth, a new epoch each) is ~1 ms per bind at 1920x1080 for both BF-171 and the bounded head, against ~1.5 µs on main.
- **Why it matters:** a title that samples its depth every frame (SSAO, DOF) stores the plane every frame. If its next depth pass then binds the plane for writing across several packets, each packet's epoch pays a full-plane compare on Linux, where there's no untracked hint.
- **The decision this feeds** (the PM's): BF-171 opens unbounded only if its per-frame cost is negligible; otherwise the bounded one opens. If the bounded one still costs ms per frame, neither opens until the writing case is bounded too.

## What to do

1. **A frame-shaped stream** over a D32 plane outside the write watch (as BF-171's cases do), 1280x720 and 1920x1080. Per frame:
   1. **a depth pre-pass:** K packets (K = 1, 4 and 12), each a new collect epoch, each with one depth-writing draw into the plane;
   2. **a store:** the plane sampled as a texture, so `FlushDepthPlanes` stores it, as SSAO does;
   3. **depth-tested passes:** M packets (M = 4), each a new epoch, binding the plane read-only (depth test, no write);
   4. **a present:** `Recorder::CountPresent()`.

   Run 60 frames after 5 warm-up frames, with no CPU writes into the plane, then one frame with a CPU write before the pre-pass (to show it's still caught).
2. **Report, for each build and each K and resolution:**
   - unwatched compares per frame (`StorageTexture::UntrackedCompares()` or BF-171's counter);
   - wall µs per frame for the driver work (exclude GPU waits: no `VILLAGE_GPU_SYNC`-style wait unless you report both).
   - Say which compares come from writing binds, read-only binds and stores.
3. **If the bounded head still pays more than ~0.5 ms per frame at 1080p with K = 4:** prototype the smallest bound for the writing case. Keep every existing case green: BF-171's (a)-(e), BF-173's (a2), (a3) and (e), and main's `agc_driver_depth_plane_partial_store`.
   - **A candidate to evaluate, not a prescription:** once a writing bind in this present has compared and the GPU has written the plane (its units stale), later writing binds in the same present skip the compare. A CPU write after the GPU's writes in the same present is the ambiguous case BF-173 described; the store still compares.
   - Show whether that keeps (a3) "write-order" and `partial_store` green. If no bound keeps them, say so, with the failing line.
   - Commit it on top of e35998524 on a new branch, `fix/agc-depth-plane-unwatched-writes-bounded2`, with its tests and the same cost table.
