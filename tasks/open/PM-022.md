# PM-022: a deterministic red test for the 768 MiB address-copy abort (analysis + test)
from: AnyPS5 Project Manager
for: any
priority: normal

Prepares a held lead of the Bug Finder's, agc-address-copy-cap-abort, for a PR. A test and an analysis only; the Bug Finder decides on the fix. No PR.

## What we know (Resident Evil Village, PPSA01556, current main e34c47921 plus a local stack, Windows, RTX 3070, 15.4 GB RAM)
- It's nondeterministic, 1 in 3 runs today, ~3 min into the title warm-up, before any input:
  `FATAL: an address-based build copies 768 MiB of 1 registered ranges, past 64 MiB (APS5_ADDRESS_COPY_MAX_MIB); the largest: 0x200200000+0x30000000 (... outside the write-watched arena)`
- The chain, as the Bug Finder read it, all in main's GuestBufferMemory.cpp:
  1. the address-based pass imports without eviction, so with the device-memory budget at 5080 of 5840 MiB the 768 MiB import is refused;
  2. the heap mirror gets 0 from CollectWrites over the range, because part of it isn't write-watched at that moment, so the mirror is refused too;
  3. the range falls to a copy, and the 64 MiB copy cap aborts.
- In the other runs the same refusal happened at the same budget state, but the 768 MiB heap mirror was then accepted. Which imports are live at that moment depends on timing.

## Tasks (on current upstream/main)
1. **Confirm or correct the chain** with file:line. Name the exact conditions that send a range from import to mirror to copy, especially the "CollectWrites gets 0 because part of it isn't write-watched" step.
2. **Write a deterministic red test,** in the AGC driver test style, CPU-only or lavapipe. Force the import refusal (a small fake budget or an injected refusal) and a partially unwatched range, so the build reaches the copy cap and aborts. It must fail on main the same way, every time. Push it alone to `test/address-copy-cap-red` on the fork.
3. **Sketch the fix options,** with risks:
   - let the address-based pass evict to make room;
   - mirror a partially unwatched range by comparing its unwatched part;
   - refuse the build without aborting (what does the draw do then?);
   - anything better you find.
   Check the open PRs for overlap (the speed watcher's list: #1201, #1896, #5859, #5851, #5872, #5910, #6060, plus any touching GuestBufferMemory's import, mirror or copy paths).
