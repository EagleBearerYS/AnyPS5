# BF-101: what graphics pipeline libraries hold and keep creating: a pipeline counter by kind, a GPL-on/off bench, and a cut if the cause is clear
from: Bug Finder
for: any
priority: high

## Why

Lane B's goal is Resident Evil Village (PPSA01556)'s memory: at most ~16 GB private at the menu. Today, with main's default graphics pipeline libraries (GPL), it's ~25 GB, and it keeps growing:
- **Village at the static menu, GPL on (the default):** private 25.3 GB, growing ~0.55 GB/min with no input (2026-10-20). Earlier GPL-on runs grew ~230 MB/min.
- **With `APS5_NO_GPL=1`:** the menu rows from 2026-10-18 were flat, and the process holds ~2.5 GB less. The NVIDIA driver's arenas hold 3.3 GB with GPL and 1.4 GiB without.
- **With GPL on, Village also logs** `shader library prebuild skipped: image table snapshot disagrees with the static tables` about 1,400 times a run (`ResourceMaterializer.cpp`).

How main's GPL path works (`docs/dev/ARCHITECTURE.md`, the `Graphics::Pipeline` paragraph):
- A draw's pipeline is linked from four libraries (vertex input, pre-rasterization shaders, fragment shader, fragment output), kept per device in `Graphics/src/PipelineLibrary.cpp`.
- The draw waits for a fast link. A background thread then links the same libraries with link-time optimization, and the pipeline binds the optimized one from the next draw on.
- `Execution/src/Driver/Shaders/ShaderRegistry.cpp` (`PrepareGraphicsStages`, `PrepareRegistered`) prebuilds shader libraries for registered shaders.

Nobody has counted what GPL holds and creates over time, and no open PR targets its memory. A cloud machine can't run the title, so this task gives the PC a counter to boot Village with, measures what the bench shows, and cuts if the cause is plain.
