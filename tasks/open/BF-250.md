## Why

The 10-25 coverage census (BF-215, BF-216 and BF-217: `results/cloud-3/BF-215.md`, `results/cloud-2/BF-216.md`, `results/cloud-5/BF-217.md` on the fork's `cloud-results` branch, plus BF-188's `results/cloud-5/BF-188.md` and its rows file) classified 1,321 todo rows: 97 implementable, 24 of them free.
- **Since then:** main has moved by several hundred merges, many of them coverage and test PRs, and BF-221/BF-222 used part of the list.
- **This task:** before we post new coverage batches, recount which rows can still become PRs. Read-only analysis: no build, no code, no branch.

## Rules (they decide whether a row counts)

- **Source rule (since 2026-10-25):** a function is implementable only when a source or a measurement names its own behaviour. That means one of:
  - a console or firmware measurement posted in an issue, discussion or PR;
  - a title's bundled module run on a PC (as B-Howell did for libc);
  - another emulator's implementation of that exact function, with a commit link and line;
  - an SDK header comment quoted in a public place.

  A sibling function, a twin's shape or a naming convention is not a source; that row stays a throw. Say which source each row has, with a link.
- **No placeholder-throw tests:** a batch's tests may check measured behaviour and export presence only. A row whose only possible test is "it throws" is not a batch row.
- **Claim check, step 0 for every row.** Against:
  - current upstream main: is it already implemented, and by which commit;
  - open PRs: is it touched, and by whom;
  - unmerged PRs closed in the last 14 days: what was claimed and why it closed;
  - forks of authors who hit the open-PR limit (MatteoSid's closed #10407 is the precedent).

  Any claim drops the row.

## Do

1. Re-read the 97 implementable rows (and the 24 free) from BF-215, BF-216 and BF-217 (and BF-188's rows) against current `upstream/main`.
2. For each row that survives: library, function, the source (link + what it says), the claim-check result, and whether a title hits it.
   - **Title hits:** a `<function> not implemented` line in an issue, discussion or a title thread on GitHub, since those go first. Search the issue and discussion text for the function name.
3. **Propose up to three batches:**
   - one library each, small enough for one PR (at most 8 rows);
   - title-hit rows first, then the largest sourced groups;
   - for each batch, list the rows, the sources and the tests that would check measured behaviour.
4. **Also list:**
   - rows that main implemented since 10-25, with the commit;
   - rows now claimed, with the PR.
