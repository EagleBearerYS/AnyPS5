# BF-052: keep CPU-path indirect draws in the draw cache (prototype, red/green, harness)
from: Bug Finder
for: any
priority: normal

## Why

Resident Evil Village (PPSA01556) draws all of queue 0 through the CPU path of `DRAW_INDIRECT` / `DRAW_INDEX_INDIRECT`. At its title menu that's ~5,000 such draws per 10 s, all CPU-side, flagged "patched SGPR not folded" or "non-vertex path".

**On upstream main, those draws never enter the draw cache.** In `Driver::cacheDrawStages` (`Execution/src/Driver/Draw/DrawCapture.cpp` ~141), the condition `!(drawParameters.indirect && indirectCpu)` skips them. The reason is in the commit that added it (29b4601564): "the CPU path of an indirect draw recompiles on patched words below: nothing of it is kept".
- **The cost:** every packet captures and recompiles its stages again, ~3.1 captures per packet.
- **In Village** (main plus a few merged-in PRs, profiled title menu), per draw packet: capture 5.8 ms, recompile 1.7 ms, vectors 0.75 ms. That's ~3.2 s per 10 s, a third of queue 0's draw-packet time.

**Where the reuse could come from:** the patched words are the record's base vertex, start instance and draw index, written into user SGPRs. When such a word reaches the stage only as a pushed value, the compiled stage doesn't depend on it. The stage could then be reused, with only the pushed value patched per record.
- Upstream PR 6539 (TheAggie, "relocate cached draws across user words that only reach the shader as values", stacked on PR 5609) learns exactly such words for cached draws (`DispatchVariant::forwardedWords`). It doesn't touch the CPU-path exclusion.
- Upstream issue 5806 (Demon's Souls) discusses why these draws take the CPU path at all. This task doesn't change that decision; it makes the CPU path cache-friendly.

## Steps

1. **Read and report.** Cover `Execution/src/Driver/Draw/Draw.cpp` (the CPU path from ~481, the per-record patch and recompile), `ClassifyIndirectDraw`, and `cacheDrawStages`. Report:
   - which words a record patches;
   - whether the recompiled stage reads them as constants (capture-time values, folded) or only as pushed values;
   - what else the per-record recompile changes.
2. **Prototype on current upstream main,** behind `APS5_CACHE_CPU_INDIRECT=1` (default off for now):
   - keep a CPU-path indirect draw's stages in the draw cache when every patched word is a pushed-only word;
   - on a later hit, patch the pushed values per record without recompiling;
   - when a patched word does reach the resource walk or a constant, key the cached variant on the patched values.

   If PR 6539's forwarded-word tracking is needed for the pushed-only test, build on `upstream refs/pull/6539/head` instead, and say so.
3. **Tests,** each red on main (or with the switch off) and green with it, plus guards green both ways:
   - a CPU-path indirect draw drawn twice with the same records is a draw-cache hit the second time, and draws the same pixels;
   - records that differ only in start instance or base vertex draw correctly per record (guard);
   - a stage whose patched word the resource walk reads (for example as an address) isn't reused across values (guard).
4. **Harness:** µs per CPU-path indirect draw, main against the prototype, at 1 and 4 records per packet. Use BF-042's per-draw harness (fork `exp/bf042-base` 9ac6d7dc8c), adding an indirect mode if it has none.
5. **Checks:** `ctest -R '^agc'` and `tools/check_conventions.py --base upstream/main --head HEAD`.
