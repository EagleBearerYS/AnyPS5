  - 0x0 DISPATCH_DIRECT unknown: 145 syncs, 468 ms;

  - 0x20 DISPATCH_DIRECT unknown: 87 syncs, 355 ms;

- **Pending-write syncs:** 115 syncs, 1,233 ms in all.
  - 0x0 DRAW_INDEX_INDIRECT indirect-args: 28 syncs, 760 ms;
  - 0x0 DISPATCH_DIRECT buffer-upload: 65 syncs, 238 ms;

- **No usable frames:** every `[hooksync]` frame printed as `+0x0/+0x0/+0x0`, so `CaptureCallerOffsets` gave nothing usable on that Windows build. Say why if you can see it: frames outside the module, or the capture not taken.

## Do

**Base:** fork `diag/village-storage-alias-fix-on-41ef8ff856-v3` = **306fc4cfb4**. That is 41ef8ff856 plus Cloud 4's `[storage-alias]` trace plus the storage-alias PR's engine changes, and it's the tree the PC boots next. Measure on top of it, so the result shows what's left once the storage-alias fix is in.

1. **Name the sites** (one diagnostic commit on fork `diag/village-read-sites-on-306fc4cfb4`). Add a `ReadSiteScope` with a new `ReadSite` value at each unscoped read BF-295 listed as a candidate:
   - storage image capture: `captureGuestBytes`;
   - storage image compare: `compareUntracked`;
   - storage image upload: `StorageTexture::upload`'s reads;
   - DCC and metadata reads outside `TextureRead`;
   - fetch-shader vertex descriptors;
   - depth surface and HTILE reads;
   - the WAIT_REG_MEM loop's unscoped `FlushGpuWrites`;
   - any other unscoped read you find inside a dispatch's or draw's resource build.

   Scopes only change the `[hooksync]` attribution: no behaviour change, and a thread-local store per scope.
   If `CaptureCallerOffsets` is broken on Windows, fix it in the same commit, or say why it can't be.
2. **The design,** for the sites that carry the most wait. Use BF-295's verdicts (needed now / deferrable to the GPU / answerable from the GPU copy) and say which real change removes each wait. For example:
   - indirect arguments read by the GPU through the import (`vkCmdDraw*Indirect`) instead of a CPU read of a pending write;
   - buffer uploads as a GPU-ordered copy;
   - a storage image's pending results copied on the device for a sampled read.

   For each, give:
   - the proof that it's correct (what must be ordered, and by which barrier);
   - what it costs;
   - whether an open PR already does it. Search titles and bodies and the touched files; check fable-void's fork too.

   Rank them by Village's numbers above. Leave out what the storage-alias fix already covers, and say how much that is.
3. **No implementation of the fix in this task.** It's the next one, once the profiled boot names the sites.
