# PM-021: Village stop 24 — stale title-scene objects over the first 3D scene (analysis)
from: AnyPS5 Project Manager
for: any
priority: normal

Code analysis to prepare the Village team's trace run. No game data, no PR.

## What we know
- In Resident Evil Village (PPSA01556), with the blur fix (fork fix/agc-db-depth-expand-out-of-place), the first 3D scene (the Winters' dining room) renders correctly.
- But the title screen's foreground objects (fence posts, branches, the scarecrow field) stay visible, dimmed, over the dining room after the scene change. They look like the previous scene's image blended in.
- The Village team suspects a stale temporal or history target: TAA history, motion vectors, a previous-frame colour buffer, or an exposure/history texture. On the console it's reset or cleared on a scene cut, but on AnyPS5 it keeps the title's contents.

## Questions (on current upstream/main, libSceAgcDriver)
1. **How AnyPS5 handles a clear of a render target the title expects:**
   - CB fast clears (CMASK/FMASK/DCC metadata, the "clear color" path, fast-clear elimination);
   - clears done by compute shaders writing guest memory;
   - CP DMA fills;
   - CLEAR_STATE.
   For each: when does the guest image get the cleared contents, and could an AnyPS5 image cache keep serving old contents after the title believes it cleared it? Which debt entries already say so?
2. **When a title reuses the same memory for a new render target** of the same or a different format (common for history buffers on a level change), does AnyPS5's resident image or cache keep the old image's contents? Look at the image-cache keys and invalidation on writes by draws, DMA or CPU.
3. **History-style reads:** a pass sampling last frame's target (TAA) through a T# at the same address as a target written this frame. How does AnyPS5 order or alias them? Could a reset (a clear, or a compute dispatch writing zeros) be lost so that the history keeps blending the old scene?
4. **Plan a one-run logging plan for the PC:** which existing trace switches (APS5_TRACE_*), or which small debug lines, would show the culprit in one scene change. For example, log fast clears, DMA fills and compute writes over targets that are later sampled as history, with addresses.
