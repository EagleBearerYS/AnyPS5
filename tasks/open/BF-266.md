## Step 1: classify each row in part 1 under the source rule

A row is **implementable only when a source names that function's own behaviour.** Accepted sources:
- **A console measurement**, published in an issue, discussion or merged PR, and cited.
- **An emulator that implements the function's body:** shadPS4 at `7ea677e56d75bf3d90ace2b0a5144a665d1f38b6` or newer (pin the commit), fpPS4 `04cefd43e6`, Kyty.
  - It must not be a logged stub that only returns OK. `(STUBBED)`, `LOG_ERROR(... "(STUBBED) called")` and `return ORBIS_OK` with nothing else are not sources.
- **The upstream library the PS5 module is a build of,** at the version the tree's merged rows for that library already cite: FreeBSD 11.4 (`8c639945a4`) for libc, libkernel and libthr; LibreSSL 2.5.4 for libSceLibreSsl. Say which merged row sets that basis.
- **Not sources:**
  - a sibling or twin function's behaviour;
  - the tree's own conventions;
  - a header's signature alone;
  - a one-line summary;
  - "every other emulator returns 0".

**Output:** a TSV over every row in the part, with columns `library, function, class (sourced | sourced-blocked | weak | none | partial-on-main), source link (pinned commit + line), what the source says, blocker`.

## Step 2: claim check on the sourced rows (git only, as BF-250 did)

- **PR heads:** fetch every `refs/pull/*/head` from upstream above #10890, plus BF-250's lists.
  - Diff each against its merge base, and search the added lines for each sourced name.
  - Any unmerged PR head that implements or changes the function is a claim. That includes PRs closed in the last 14 days, and any PR with no merge ref.
- **Limit forks:** all branches of MatteoSid's and klosixgaming-arch's forks.
- **Output:** list each claim with the PR number, or `free`.

## Step 3: batches, then build the best one

- **Propose batches:** one library per batch, 4-12 free sourced rows, sharing objects or helpers so that one PR covers them. Give each batch's rows, sources, the tests that would check the sourced behaviour, and the open PRs in the same files.
- **Build the best batch now** as fork branch `feat/<library>-sourced-b266-1`, one or two commits on `upstream/main`. Implement exactly what the sources say:
  - every return code and side effect the source shows;
  - where the tree's model differs (no icons stored, synchronous instead of threaded, and so on), a debt entry that says so and links the source line.
- **Tests in the same commit:**
  - each sourced behaviour is checked;
  - **red:** the test against main's code. If the signature changes, keep the new signature, put main's throwing body back, and show the test abort on it;
  - **green:** `--repeat until-fail:10`.
  - **Never assert that a placeholder or unimplemented path throws.** Assert measured or sourced behaviour, and export presence.
- **Debt:** remove the rows from the pending list in the library's debt file, and add entries under 1,000 characters for every difference from the source.
- **If no batch reaches 4 free sourced rows in this part,** say so, and build nothing.
