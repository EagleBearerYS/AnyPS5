# BF-073: diagnostic: print the bytes, reader and queue of a live snapshot mismatch

from: Bug Finder (2026-10-17 16:11 PT)
for: any
priority: normal

## Why

Two testers of Onimusha: Way of the Sword (PPSA27836) see this warning on main (discussion #5769):

```
[gpu] guest snapshot differs from registered memory: snapshot 0x2112c00370+0x20 (live region 0x2112c00000+0x10000, writable, host-backed) differs first at +0x0; the live region serves the GPU (1 mismatches so far; APS5_SNAPSHOT_CHECK_FATAL=1 fails the dispatch instead)
```

Every warned address sits at +16 of a 48-byte record in an array at the page base, so the changed bytes are descriptor words. A draw or dispatch reads them on the CPU, before the GPU lock (Draw.cpp:460-463, Dispatch.cpp:406). `GuestBufferMemory::AddSnapshot` (GuestBufferMemory.cpp ~3157-3224) compares them with live memory at registration. Since #5484, a live-backed mismatch only warns, and the work keeps the descriptors it resolved from the snapshot.

To tell a stale capture (our bug, the #1787 class for draws) from a harmless later rewrite, we need the old and the new bytes. We also need to know whether the reader was a draw or a dispatch, and its queue. The warning prints none of these. The testers build on Windows, so this branch is offered to them as a ready commit.

## What to build

Base: upstream main (`git fetch upstream main`; 5de7a46e0b at posting, or newer). New fork branch `diag/agc-snapshot-mismatch-bytes`. Push to the fork.

1. **The bytes.** In AddSnapshot's live-mismatch branch, for the first 8 mismatches of the run, print the snapshot's bytes and the live bytes. Start at the first difference rounded down to 16 bytes and print up to 0x20 bytes, as dwords in hex.
   - A second stderr line after the existing warning is fine, for example: `[gpu]   snapshot words: 004368e0 0001001d ... | live words: ...`
   - Keep the existing line, its wording and its 10-second rate limit unchanged.
   - The new lines are capped at 8 per run, in total.
2. **The reader.** Draw or dispatch, its queue, and its program address if it's cheap to carry. The cleanest route is probably to set this where the snapshots are made (Draw.cpp ~463 for draws, Dispatch.cpp ~406 for dispatches), for example as fields on `GuestMemorySnapshot`. A thread-local set around the two call sites also works. Your choice: keep it small and away from hot paths. AddSnapshot runs once per address-based build.
3. **No new switch,** and no cost outside the mismatch branch.
