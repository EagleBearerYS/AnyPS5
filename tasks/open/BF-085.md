# BF-085: what the AGC driver's shutdown destroys while still in use, under the Khronos validation layer

from: Bug Finder (2026-10-17 22:04 PT)
for: any
priority: normal

## Why

Resident Evil Village (PPSA01556) has crashed seven times when its window closes on Windows with an RTX 3070, always with `APS5_NO_GPL=1`: `FATAL: unhandled exception 0xc0000005 on thread 'presenter'`, rip `nvoglv64.dll+0xe6b3f6`, a read of freed memory. The latest crash was on a tree that already has main's two shutdown fixes (966da79fc, 0ba4f056c). It loses only the last seconds before exit, but it's a real teardown bug.

**The path, read from main:**
1. The close's `SDL_QUIT` is polled on the presenter thread (`libSceVideoOut/src/VideoOutDriver.cpp:669-671`).
2. `presentLoop`'s exit calls `AgcDriverShutdown_nid_postfix()` on that thread (`VideoOutDriver.cpp:740`).
3. `Driver::stop()` (`libSceAgcDriver/Execution/src/Driver/Lifecycle.cpp:101-131`) then runs there, while guest threads still run and draw: it joins the queue workers, stops the draw pipeline's committer, closes registration preparation and stops the pipeline library worker. Then it takes the GPU lock and runs `device.Reset()`, `replacedDevices.clear()`, `FlushPipelineJournal()`, and only then `ShutdownGuestBufferWorkers()`.

A stack scan at the crash shows `Graphics::Recorder::endOpenRenderPass` (`Recorder.cpp:1415`) and `Recorder::Submit` (`Recorder.cpp:3296`). That suggests a render pass ended or submitted after something it uses was destroyed. NVIDIA crashes there; lavapipe may not. The validation layer should name it without the crash.

Record draws into an open render pass, leave them unsubmitted, then call the driver's shutdown from a thread that isn't a queue worker while another thread keeps submitting. Run it under the layer. It may stay on a measurement branch.

For example, end and submit the open pass, wait, and only then free the objects it uses; or keep the object in the draw's kept list until the pass completes. Add a test that's red under the layer without the fix and green with it. Also run the AGC tests (`^agc`) on the fix.
