## Why: Resident Evil Village's title menu, measured on the PC (2026-10-15)
- **#6243 (cut #3)** made the title 3.2x faster: frame p50 11,809 → 3,662 ms. With image tables off it ran 16x faster. The gap is essentially **26 per-lane whole-table columns, all over ONE heap:** 0x204d400000, 1.5 MiB, 32,768 T#s of 8 dwords at a 48-byte stride, the same shape all run (diagT). After #6243, 235 of 261 columns are selected records. There are no sampler tables.
- About **164 whole-table builds per frame against 941 draws.** Each one pays four times over:
  1. **Capture:** the 32,768-record snapshot. This is most of `capture_resources`' remaining ~1.7 ms per draw.
  2. **Image resolution:** `ShaderResources::resolveImageTables` binds every distinct T# of the column (requirement checks, texture lookup, `describedRanges`) at every build. Its `FindReusedTable` hit path still binds and checks each element. diagP, profiled and averaged over all builds: "images" ~650 µs per build, "guest memory upload" ~590 µs per build.
  3. **Descriptor writes** for the table binding's elements, at every build.
  4. **The draw-cache compare** of 1 MiB of captured table words: 77-81 µs per compare (cut #3's bench).
- **PM-028** (fork `perf/shader-image-table-unwritten-reuse-v2` 142bdd55a9, the user's "skip the read while unwritten" idea) **hits on every whole-table capture** in Village (`reused ~410 unwritten / 0 compared` per 10 s), **yet makes capture 58% slower:** frame p50 +25% against cut #3. That's ~5.7 ms extra per reused capture on Windows in Village, against ~0.4 ms per hit in its Linux bench. It's held.
- **The likely cost** (the Bug Finder's code reading, unmeasured; verify it): every reused capture runs `ShaderMemory::unchangedSince` over the whole range:
  1. `Driver::queryPendingWrite` (WriteEvidence.cpp), which scales with recorded-but-unfinished writes;
  2. `GuestMemory::FlushGpuWrites`, which is the recorder's `FlushForAccess` (Recorder.cpp:1002): queued labels, **the global GpuMutex**, `PendingWriteOverlaps`, and one or two storage-texture registry scans;
  3. `CollectWrites` (the tracker lock, GetWriteWatch on Windows);
  4. `UnchangedSince` (the tracker lock, 24 block checks);
  5. `supplyWords`, a 1 MiB copy into 384 pages.
  PM-028's bench has no recorder, so it can't see items 1 and 2. The Bug Finder's GitHub run 38701145952 times that bench on Windows and Linux runners (isolating items 3 and 4); its numbers will be added below.

## Design target
**One immutable table object per (heap, shape, write epoch), shared by every column, capture and build that reads it.**
- **Capture:** an O(1) epoch check. Cache "no pending write and nothing to flush over this range" per submission epoch, invalidated by a new recorded write or a deferred result over the range. No per-capture range scans, and no copy: the capture refers to the shared object (PM-032's shared column).
- **Resolution:** keyed by the object's identity. The bound texture array and its descriptor writes are reused whole while the object and the textures' state (residency, layout, format, views) are current. No per-element re-bind. Find exactly what invalidates a bound array.
- **Draw cache:** compare tables by identity (PM-032).
- **Correctness:**
  - PM-028's vouching rules, or a cheaper equivalent that's exact.
  - The `MarkWritten` contract under #6060: audit every GPU write path into imports, address-based builds included.
  - Labels, deferred results, DMA, CP and compute writes all invalidate.
- **Hard requirement:** no path (hit, miss, written every frame, many heaps) costs more than main's in Village. Memory stays bounded.
