# BF-096: capture a build's validation records in one pass instead of a backward log search per texture (#6944's follow-up)
from: Bug Finder
for: any
priority: normal

## Why

Our #6944 (merged) made the texture lookup log keep a build's own records past its bound, so builds with more than ~1,000 textures keep the fast proof.

What it left: `ShaderResources::captureValidation` (`core/libs/prx/libSceAgcDriver/Graphics/src/ShaderResources.cpp:2891` on today's main) still searches the whole log backwards once per texture:

```
for each texture i: for (it = log.rbegin(); ...) if (it->object == textures[i]) ...
```

That's O(textures × records) per build or full walk.
- **The cost:** at 2,000 textures it's ~0.3 ms per build (#6944's own measurement).
- **The ask:** CnRJay asked for the one-pass form on #6944's review: "a title with a bigger table than Village's pays more than 0.3 ms".
- **Prior trial:** BF-039's hash-map version took 470–510 µs against 1,100 µs at 2,000 textures, and 6.7 µs at 16. Node allocations dominated it, so a flat structure should do better.

Resident Evil Village (PPSA01556) draws bind ~2,000 textures.

## What to do

1. **One pass, newest record per object.**
   - Walk the log once from newest to oldest, keeping the first record seen per object in a flat structure. For example, a sorted vector of (object, record index), or an open-addressing table sized to the log, reused per thread like `lookupLog()` is.
   - Then fill `validatedTextures` from it.
   - Behaviour must match main exactly: the newest record wins, and an object with no record gets an empty entry.
2. **Tests.**
   - A test that pins the behaviour: duplicates where the newest must win, a texture absent from the log, and a build past the old 1,024 bound. It's green before and after, since this is a pure speed change.
   - A measurement mode in the same test, or in `LookupLogFitsBuild.cpp` (#6944's test), that times `captureValidation` at 16, 128, 2,000 and 4,096 textures, base against branch. Give the median of 5.
3. **Checks:**
   - CI's Linux mirror on the head:
     - CI's configure flags and the build;
     - `tools/check_test_registration.py build`;

     - `tools/check_skips.py build/ctest.xml`.
     Give the counts against the base's. The 5 IPv6 failures are the known baseline.
