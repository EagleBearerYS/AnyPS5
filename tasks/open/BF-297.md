# BF-297: APS5_TRACE_STORAGE_ALIAS, a census of Village's aliased storage-image pairs (diagnostic, counts only)

from: Bug Finder (PC)
for: any
priority: high

## Why

On Resident Evil Village's menu, two storage images over the same guest memory round-trip through host memory on every refresh:
- **"storage refresh" write-backs:** ~4.7 GB per 10 s;
- **"flushed" re-uploads:** ~4.8 GB per 10 s;
- **the device "alias" path** (`borrowUnits`, "units taken from an alias image on the device"): 0 bytes.

BF-290 (Cloud 4, the real fix) and BF-296 (the acceptance harness) need to know **which** image pairs these are on Village, and why the device path isn't taken for them. This census gives it to them in one PC boot tonight.

## Do

- **Base:** fork `diag/village-preresolve-on-fjseries-50c9bee85c` = **41ef8ff856**.
- **Branch:** fork `diag/village-storage-alias-census-on-41ef8ff856`, one commit with the user's noreply author and committer. It never becomes a PR.
- **The switch:** `APS5_TRACE_STORAGE_ALIAS=1` (presence). Counting and printing only: no behaviour change, and no cost when unset.
- **Every 10 s,** print one `[storage-alias]` line (and a continuation line if long), to the same log the profile lines use:
  - **Totals:** "storage refresh" write-backs and "flushed" re-uploads (count, MiB), as counted at the same points as the `[storage]` line.
  - **The top 8 (X, Y) pairs by bytes,** where X is the image whose refresh flushed and re-uploaded, and Y is the image whose pending results it flushed. For each:
    - both base addresses and byte ranges, and the overlap;
    - both descriptors: format, dimension, width × height × depth/layers, mips, tile mode / linear, pitch, DCC (yes/no);
    - counts and MiB of the write-back and the re-upload;
    - **why the device alias path wasn't used for this pair:** the first refusing condition in `pendingAlias()` / `borrowUnits` and their callers (`Texture.cpp` ~2142/2192 and `borrowUnits` ~5855 on 41ef8ff856). Name each condition as a short reason string, and say "not tried" if the path wasn't reached.
  - **The dispatch programs** (code addresses) that bound X and Y in that window, the top 3 per pair.
- **Keep the bookkeeping cheap,** for example a small fixed table keyed by (X, Y) address pairs, reset every 10 s. It must not change timing much in an unprofiled boot.
- **No change under `core/shader/recompiler/`.**
- **No comments in code.**
