# PRM-040: output resolution: what the console answers to Planet of Lana's and Animal Well's VideoOut calls on a 1080p output
from: AnyPS5 PR Manager
for: any
priority: high

## Why

`ANYPS5_OUTPUT_RESOLUTION` (fork `prep/videoout-output-resolution` 4560e2bdae, version B) refuses 3840x2160 display buffers for titles whose param.json `attribute3` sets bit 2 ("resolution detection"). The plan was that such a title falls back to 1920x1080, so it renders less and FSR has something to upscale.

The PC boots on 2026-10-17 07:13-07:31 PT showed the opposite. Planet of Lana (PPSA19450, attribute3 0x4) and Animal Well (PPSA22520, attribute3 0x1C0004) both register 3840x2160 at the 1080p setting, and on the refusal both abort with `VideoOut: wait buffer is not registered`. With the setting unset, both run normally.

The PM's direction, in the user's name: fix it at the cause. Find what these titles read before their first registration, and what a real console answers on a 1080p output. If AnyPS5 answers a query differently, so the title never sees 1080p, fixing that answer is the fix, and the refusal stays as a backstop.

This task needs text only. No game files, dumps or executables are involved: everything below comes from the PC's logs.

## What the titles call (from `APS5_TRACE_CALLS=libSceVideoOut`, NIDs mapped by tools/nid_names.py)

- **Planet of Lana**, at the 1080p setting, all 16 VideoOut calls in order:
  - sceVideoOutOpen;
  - sceVideoOutGetOutputStatus;
  - sceVideoOutAddFlipEvent;
  - sceVideoOutIsFlipPending;
  - sceVideoOutSetFlipRate;
  - sceVideoOutSubmitFlip (before any buffers are registered);
  - sceVideoOutIsFlipPending ×2;
  - sceVideoOutSetBufferAttribute2;
  - sceVideoOutRegisterBuffers2 (3840x2160, refused with VIDEO_OUT_ERROR_INVALID_RESOLUTION);
  - sceVideoOutConfigureOutput;
  - sceVideoOutGetOutputStatus ×3;
  - then, on other threads, sceVideoOutAddFlipEvent and sceVideoOutSetFlipRate, and the abort.

  It never calls sceVideoOutGetResolutionStatus, and it never registers a second time.
- **Animal Well**, at the 1080p setting, all 3 VideoOut calls: sceVideoOutOpen, sceVideoOutSetBufferAttribute2, sceVideoOutRegisterBuffers2 (3840x2160, refused), then the abort. It makes no status query before it registers.

## What AnyPS5 answers (version B, 4560e2bdae, `core/libs/prx/libSceVideoOut/src/Output.cpp`)

- `sceVideoOutGetOutputStatus` fills `VideoOutOutputStatus {u32 resolution; u32 dynamicRange; u64 refreshRate; u64 flags; u64 reserved[3]}` (SceTypes.hpp:2007):
  - resolution class 2 when the reported size is at least 3840x2160, else 1, which is class 1 at the 1080p setting and also on `main` (it reports 1920x1080);
  - dynamicRange SDR or HDR from the host;
  - refreshRate 59.94 (119.88 in the 119.88 Hz mode);
  - flags HDR or 0.
- `sceVideoOutConfigureOutput`:
  - takes any mode that `sceVideoOutIsOutputSupported` validates. Only `VIDEO_OUT_OUTPUT_MODE_DEFAULT` (1) and `_119_88HZ` (0xF) are defined (VideoOutDriver.hpp:89-90);
  - refuses 0xF unless attribute3 has 0x40;
  - stores the mode.
- `sceVideoOutIsOutputSupported` returns 1 for anything `validateOutputConfig` accepts.
