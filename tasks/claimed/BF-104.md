# BF-104: bound what #8926's rewatch of retired imports costs in a load: a Windows benchmark mode, run on GitHub's Windows runner against main
from: Bug Finder
for: any
priority: high

## Why

#8926 (ours, fork `fix/agc-retired-import-rewatch` **acc7b1792e**, one commit on upstream main 1ff5c8ac5c) fixes Resident Evil Village (PPSA01556)'s intro abort.
- On Windows, imports smaller than the settle floor are unwatched. When run growth retires such an import (`retireLeastRecent`, and the retire loop in `refreshImports`, `Graphics/src/GuestBufferMemory.cpp`), its ranges stayed unwatched, so the copy path later took them and passed the 64 MiB copy cap.
- #8926 collects each retired import's unwatched spans (`noteRetiredUnwatched`) and hands those no other unwatched import or live storage texture still covers to `GuestMemory::Rewatch` (`rewatchRetired`), once per refresh.

A merge request needs the fix's load-time cost, and the PC can't time Village's load tonight. So we bound the cost here.

What `GuestMemory::Rewatch` does per span (`Execution/src/GuestMemory.cpp`, Windows only; on Linux it does nothing, and imports are never unwatched there):
- `coverage.Covers`, `walkWrites` (the write-watch walk), `coverage.Restore`;
- `++tracker.generation`, `noteCpuStore` and a CPU stamp of every block in the span, so later validations see those blocks as written;
- once per call that restored anything, an `unwatchSerial` bump. That drops every collect memo (`collectWrites` compares `entry.unwatched` with the serial), so the next collects walk again.

**Village's workload** (the PC's traced run qf6457, main + #6457, up to its abort): 5,765 retirements, all with the trace line "retired: the range was mapped again". They were 5,279 pieces of 64 KiB and 487 of 4 MiB, 2,278 MiB in all, in about 2,077 retiring refreshes. Most of those refreshes retire 1 piece (1,648) or 2 (339), and the largest retires 1,412.

## What to do

Branch `exp/rewatch-cost` on top of acc7b1792e (fetch `refs/pull/8926/head` from `upstream`, or the fork branch). **Test code only:** the verify harness runs the test with main's product code, then with #8926's, by reverting non-test files. So the benchmark may use only APIs that main 1ff5c8ac5c already has.
- `GuestMemory::UnwatchSerial()` and `GuestMemory::Rewatch` are on main.
- So are the controls #8926's `retiredImportWatchTests` (`tests/BdaResources.cpp`) uses: `SetHostImportWindow`, `SetHostImportDeferredSettles`, `PrepareImportWatch`, `SetImportWatch(..., ImportWatch::Unwatch)` and `SetHostImportBudget`.

1. **A Windows-only benchmark mode**, beside `retiredImportWatchTests` in the same test executable. Register it only under `WIN32` as `agc_driver_retired_import_rewatch_cost`, `RUN_SERIAL`, and put it in the WIN32 `PATH` list. It runs on the mock device, like `retiredImportWatchTests`.
   - **The workload,** modeled on Village's:
     - a guest-arena heap registered as guest allocations;
     - unwatched 64 KiB imports;
     - refreshes whose run growth or budget retires them, about 2,000 retiring refreshes and ~5,800 retirements (mostly one or two pieces per refresh, a few hundred at once, some 4 MiB pieces);
     - CPU stores into a share of the pages between refreshes, so the write-watch walks have something to find.
   - **Size:** each ctest run must finish well under 120 s on a 4-vCPU Windows runner, since the harness times out at 120 s. Take the workload size from an argument or env var with a default that fits, and print the size used.
   - **Copy cap:** if main's arm would hit the 64 MiB copy cap's FATAL, the bench must stay under it, or set `APS5_ADDRESS_COPY_MAX_MIB` for both arms and say so. Main's arm must finish.
2. **What it measures,** with `QueryPerformanceCounter` or `steady_clock`:
   - **the refreshes that retire:** total and per-refresh median, p99 and max;
   - **`UnwatchSerial()` per refresh:** how many refreshes bumped it, and the total bumps. On main that's 0 from retirement; with #8926, at most one per retiring refresh;
   - **how many retired spans ended up watched again,** and their bytes, from any query main already has (or from the next collect seeing a CPU store made while unwatched);
   - **the collect after each bump:** `CollectWrites` over a range that was memoized before the bump, against the same collect with no bump between. That's the memo drop;
   - **the next build over a restored range** (a `GuestBufferMemory` lease and upload over it): time, against the same build where nothing was restored. That's the cost of the stamps;
   - **the whole workload's wall time.**
3. **Output:** append the results, one labelled block per run, to `%GITHUB_WORKSPACE%\verify-logs\rewatch-cost.txt` when `GITHUB_WORKSPACE` is set, and always to stdout.
   - Label each block by what the run saw ("retired ranges rewatched: N" or "left unwatched"), not by guessing which tree it is.
   - The harness keeps only failing tests' output, but it uploads `verify-logs/`.
4. **Check what you can on Linux:**
   - the mode builds and skips (exit 77, "Windows only") there;
   - `x86_64-w64-mingw32-g++-posix -std=c++20 -fsyntax-only -Wall -Wextra` on the changed test files, and a MinGW cross-build of the test target if your machine can;
   - `tools/check_test_registration.py build`.
   - Push `exp/rewatch-cost` to the fork. The PC runs it on GitHub's Windows runner against main and against #8926, and reads the file.
5. **From the code, before any run:** per retiring refresh, the work #8926 adds (lock, map lookups, `AnyLiveOverlaps`, write-watch calls per span and their page counts, stamps per block). Give your estimate for Village's 2,077 refreshes and 5,765 retirements, so the run has a number to confirm.
