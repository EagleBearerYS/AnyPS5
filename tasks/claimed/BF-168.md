## Why

MarcZX10 reviewed our draft upstream PR 9969 (review 5624054362) and found a real accounting gap in `core/shader/recompiler/Optimization/src/ResourceMaterializer.cpp`.
- `ImageTableColumnSnapshot` keeps `readRanges`: pairs of 64-bit values, 4 words each.
- `ResolutionMemoEntry` stores the snapshots, but `resolutionFootprint()` (~1729 on the PR head) counts only `16 + codes + words × 9 + pointers × 2` per table, not `readRanges`.
- So the LRU memo's 8M-word budget (`ResolutionMemoWords`) can be exceeded. A table can carry one range per captured pointer on the address path (`take`, ~1096), plus one per distinct child buffer in `NestedColumn` (~1329). That's up to ~16 MiB per entry uncounted, and up to 4 variants per shader.
- `ColumnRecords::Footprint()` (~499) already counts `readRanges.size() * 4u`. `resolutionFootprint` should match it.
- Upstream main has the same omission (its `resolutionFootprint` ~1625 has no `readRanges` term), but the PR changes this function and adds more ranges, so the fix goes on the PR.
