# BF-092: Lane B: count the host-visible device memory by owner on main, then cut the largest holder we don't need

## Why

Lane B's goal is Resident Evil Village (PPSA01556) at ≤ ~16 GB private at its menu (milestone 1), down from ~26 GB. Its fourth-ranked cut is the host-visible copies.

**What the PC measured at Village's menu (2026-10-17):**
- **The amount:** ~3.9 GB of GPU-visible system memory, stable. These are the driver's host-visible allocations, mapped write-combined in exact 32, 16 and 8 MiB blocks.
- **The holders:**
  - `BufferPool` keeps ~0.56 GB.
  - Most of the rest is probably heap mirrors: copies of guest memory that can't be host-imported.
  - Nothing reports their live bytes by owner, so the cut can't be chosen yet.
- **One holder is known:** `[buffers] image mirrors` reads "2 ranges (768.6 MiB, 1 writable, 1 heap 768.0 MiB) … 3660 heap mirrors released for imports (311.4 MiB)" through the whole menu.
  - One writable 768 MiB heap mirror replaced 3,660 small ones.
  - It exists because the import budget is full: "5390 MiB live of 5840 MiB (APS5_HOST_IMPORT_MIB); 209986 imports (115926 MiB) refused so far".

The PC can't take a Village run for a counter alone. So the counter is built here, and it rides the next Village memory run the Coordinator schedules.

**Others' open PRs already cut this memory** (checked 2026-10-20; the user's rule: measure others' work before building our own):
- #7647 (fma-rc): "bind heap mirrors only where the guest holds bytes";
- #8016 (xxLnolan): "fall back to device-local heap mirrors" (device-local memory doesn't count as host-visible private memory);
- #8762 (JJenkx): "prefer imported prefixes before sparse heap mirrors";
- #7292 (billythemenace2): "import registered ranges larger than the device's largest allocation in pieces";
- #8672 (eliasbruno124-dev) and #4472 (solbjorg1245): reclaim or stop pooling idle device buffers.

Since 10-18, main has merged #7870 (released image memory kept in the buffer pool for reuse by type and size) and #6479 (the import budget from the device's memory budget, ours). Both change what the pool and the mirrors hold.
