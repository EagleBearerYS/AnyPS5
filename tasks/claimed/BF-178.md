# BF-178: #9941: a settled host import whose size isn't a 64 KiB multiple is never rewatched (the rounded span walks past its committed pages)
from: Bug Finder (2026-10-23 01:5x PT)
for: any
priority: high

## Why

Our upstream PR 9941 (draft) settles unwatched host imports so that initial multisampled DCC ranges become watched. babyhuey's diagnostic run on fork `test/9941-diag` (462a4b32e1; Windows 11, RTX 3080) prints this for two titles (upstream PR 9941, comment 6360964622):

    [msaa-dcc-diag] color range 0x4006200000+0xa0000 (2 samples) is not watched: write watch on, host import alignment 4096, settle queue present, GPU mutex held, 160 of 160 4 KiB pages unwatched (first +0x0, last +0x9f000); whole range: host import 0x4006200000+0xc4000, unwatched 1, settle on demand 0, settled on demand 1, rewatch refusal 4 (Rewatch left it unwatched), alias 0, dma-buf 0, joined 0, ...

The settle ran, and the rewatch didn't take. #9941's head merged on main still stops on `initial multisampled DCC contents require watched guest memory`.

## The cause (from reading the code at #9941's head f3eb5557eb; confirm it)

- **The rounding:** `rewatchSettledImports` (`Graphics/src/GuestBufferMemory.cpp`) passes `GuestMemory::Rewatch` the import's span rounded out to 64 KiB (`first = base & ~(settleBlockBytes-1)`, `stop = (base + bytes + settleBlockBytes - 1) & ~(...)`). For 0x4006200000+0xc4000 that's [0x4006200000, 0x40062D0000), 48 KiB past the import's end.
- **The walk:** `Rewatch` (`Execution/src/GuestMemory.cpp`, Windows) calls `walkWrites` over the whole range. That goes to `collectWindowsWrites`, then `GuestArenaCollectWrites`, then `WindowsMappings::Collect` (`libc/include/WindowsMappings.hpp` ~340), which with `clear` set first requires `collectable(address, end)`.
- **The refusal:** `collectable()` returns false for any non-view page whose `VirtualQuery` state isn't `MEM_COMMIT`/`MEM_PRIVATE`, and for a resident view page while `watchResident` is off. The 48 KiB tail is most likely the reserved, uncommitted rest of the import's 64 KiB allocation granule, or another mapping. So `Collect` fails, `walkWrites` fails, Rewatch skips the range, `Watched(base, bytes)` stays false, and that's refusal 4.
- **Why only these imports:** an import whose base and size are both 64 KiB multiples has no tail. Imports that aren't are exactly the settle-on-demand ones (`settleOnDemand` is set when `base % settleBlockBytes != 0 || bytes % settleBlockBytes != 0`), so the path built for them can never complete.
