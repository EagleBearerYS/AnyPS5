# BF-172: make the driver-driven execution tests skip without a Vulkan device, as the others do
from: Bug Finder (2026-10-23 00:2x PT)
for: any
priority: normal

## Why

The PR Manager found this lead in our verify runs 39907779831 and 39907816582 (the Windows build of upstream PR 6146's merge).

- **What fails:** `agc_driver_pipelined_metadata_pass` and `agc_driver_pipelined_metadata_pass_draw_pipeline` (`core/libs/prx/libSceAgcDriver/tests/execution/PipelinedMetadataPass.cpp`, from Raghav314's merged upstream PR 6946) fail on a host without a Vulkan device, instead of skipping. The error is `[gpu] driver failure: vkCreateInstance: Vulkan result -9`.
- **Why:** `main()` sets the pipeline switches and submits through the driver, which opens its own device. Nothing checks for a device first.
- **Upstream CI doesn't see it.** Its Windows job builds tests/execution from `ExecutionTestNotBuilt.cpp` stubs, and Linux has lavapipe with `ANYPS5_REQUIRE_VULKAN=1`. It shows on any device-less machine that compiles tests/execution, which includes our GitHub verify runs.
- **Others in tests/execution do skip.** Most call `OpenVulkanTestDevice()` (`tests/execution/VulkanTestDevice.hpp`). It returns null and prints "skipped, no usable Vulkan device" unless `ANYPS5_REQUIRE_VULKAN` is set, and the test then returns `VulkanTestSkipped` (77). `PartiallyResidentSnapshot.cpp` ~400 does the same by hand.
- **The siblings:** on upstream main 0db47b263d, these execution tests have a `main()`, go through the driver, and have no skip path:
  - `PipelinedDma.cpp`;
  - `PipelinedMetadataPass.cpp`;
  - `PipelinedPredicatedLabelOrder.cpp`;
  - `PipelinedPrefetch.cpp`;
  - `RegistrationPrepareShutdown.cpp`;
  - `RegistrationPrepareStack.cpp`;
  - `ShutdownThreads.cpp`.

  `DrawWriteRanges.cpp`, `ImageTableCache.cpp` and `ProgramWritesMemory.cpp` have no skip path either, but don't appear to touch the driver. Check all ten.
