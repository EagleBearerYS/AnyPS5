# PM-088: system library coverage, where real implementations can raise it
from: AnyPS5 Project Manager
for: any
priority: normal

## Why
The README's "System libraries" badge stands at 42.33%: 4,670 of 11,032 declared functions in `core/libs/prx` (https://boykopovar.github.io/AnyPS5/progress.json, 2026-10-21). The user asked whether we can raise it.

`tools/progress.py` counts a declared `APS5_VABI` function as todo when its body calls `NotImplemented_nid_no_patch`, and as done otherwise. Trivial bodies (a constant return, an empty return) count as done but are listed as "inert".

We want **real implementations**, plus documented silent stubs only where the console's behaviour really is a fixed result. `docs/dev/CONVENTIONS.md`: unimplemented paths throw, and silent stubs are listed in the library's technical-debt file. We don't want to inflate the badge with guesses.

Read-only analysis on current upstream `main`. No game data exists here and none is needed. Don't use Sony libraries or firmware: semantics must come from public sources (open-source equivalents such as LibreSSL for libSceLibreSsl, the project's existing code, published SDK names and signatures already in the tree, FreeBSD for kernel calls).

## Steps
1. Run `python3 tools/progress.py --help` and use it (or its `collect_libraries()`) to list every todo function per library on current main.
2. Take the 25 libraries with the most todo functions. They hold most of the 6,362: libSceSystemService, libkernel_sys, libSceLibreSsl, libSceCesCs, libSceFsInternalForVsh, libSceFios2, libSceNpCppWebApi, libScePad, libSceNet, libSceNpManager, libSceNpCommon, libSceHmd, libmdbg_syscore, libSceGnmDriverForNeoMode, libSceMbus, libSceHmd2, libSceNpTus, libSceLibreSsl3, libSceAudioOut, libSceComposite, libSceBgft, libSceFont, libSceSaveData, libSceRegMgr, libSceDataTransfer.
3. For each todo function there, classify it:
   - **A. Forwarder:** the same function (same NID or an identical documented behaviour) is already implemented in another library in the tree, for example libkernel_sys against libkernel, or libSceLibreSsl3 against libSceLibreSsl once that exists. Give the existing implementation.
   - **B. Implementable from public semantics:** say from what (FreeBSD 11.x for kernel calls, the LibreSSL or OpenSSL API for libSceLibreSsl, the project's own neighbouring functions), and size it: S under 30 lines, M, or L.
   - **C. A fixed console result:** a setting, query or no-op whose safe answer is a known constant, an error code or "not supported", for example VR, HMD and remote-play absent on PC. These are documented silent-stub candidates; say what the result would be and why.
   - **D. Needs reverse engineering or hardware:** skip, with a one-line reason.
4. For the three largest classes of work, propose PR-sized batches (10-40 functions each, one topic each), with the tests each would carry.
5. Estimate the badge after the A batches, after A + B-small, and after A + B + C, using the script's formula.
6. Note any library where implementing needs a new third-party dependency (for example LibreSSL as a submodule) and what that involves under the project's rules ("new third-party code is a submodule built from source").
