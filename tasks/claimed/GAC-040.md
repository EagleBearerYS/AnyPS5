## Our existing fix (made 2026-10-14, held until a title showed the throw)

- **The commits,** on an older explorer tree. They're on the PC, so here is what they do:
  - 18c114bced `fix(agc): plan a heap again when its mirror's range has left the write watch`;
  - tests 31dee738fe `test(agc): a heap mirror whose range leaves the write watch is planned again` and ade3fa3a37 `test(agc): an address-based build of a partly unwatched heap over the import budget`.
- **The fix** (`GuestBufferMemory.cpp`, +22/−4):
  - `ImageMirror` gains `std::atomic<std::uint64_t> watchedSerial`;
  - a new `heapMirrorWatched(mirror)` compares it with `GuestMemory::UnwatchSerial()`, and re-checks `GuestMemory::Watched(base, bytes)` only when a range has left the watch since;
  - `acquireMirror` reuses a heap mirror only when `heapMirrorWatched` holds;
  - its `generation == 0` path drops the registry's stale heap mirror (`heapBytes`, `entries.erase`, `++version`) before returning nullptr, so the pass plans the range again: an import, eviction as the last resort, then a copy;
  - a new heap mirror stores the serial;
  - `AcquireRegistered`'s address-space cache hit requires every `heapMirrors` entry to pass `heapMirrorWatched`;
  - the debt entry "Host import windows and budget" gains: "a heap mirror whose range has left the write watch since its last use is dropped and its range planned again."
- **The original trigger,** per its message: a Windows host import of private memory took its blocks off the watch for good. Main's #6060 since settles direct imports of private memory and keeps them watched. That's why no main-based log showed the throw.
