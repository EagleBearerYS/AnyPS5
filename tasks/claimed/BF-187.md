## Why

BF-182 (cloud-4, `results/cloud-4/BF-182.md`) found that an S# read through a pointer-loaded V# A is refused when V# A has another consumer.
- **The fix:** a765ccece9 on fork `fix/shader-nested-sampler-vsharp-arm` allows a V# word used only as data. It's cherry-picked as c9707eeaf9 on `test/sm2-9969-sampler` for hugodearaujo.
- **Left refused on purpose:** the key word feeding something other than offset arithmetic (v4/v5), and another data read through V# A. #9969 pins both.

**hugodearaujo's run on c9707eeaf9** (Marvel's Spider-Man 2 (PPSA03016), [#9790 comment 6369875080](https://github.com/boykopovar/AnyPS5/pull/9790#issuecomment-6369875080)) **still stops**, at 128 s with the same text:
`compute shader 0x11e2b44200: GetSamplerResource dword 0 is not a valid runtime value; chain: ReadConstBuffer@pc=0x00009a9c(GetBufferResource(LoadAddressU32@pc=0x00009a20(GetAddressResource(Phi(Phi(Phi(Phi(ReadConstBuffer@pc=0x00001fc4, Phi), …`.
`agc_shader_replay` with that branch refuses the same way on his two earlier requests.

**His IR rules out both shapes we left refused.** Read his comment in full. The shape:
- **V# A** = `%14376..%14379`, loaded at pc 0x9a20 through the record pointer. It has exactly two users, both `GetBufferResource %14376, %14377, %14378, %14379`:
  - `%14381` → only `%14382 = ReadConstBuffer %14381, 0x0`, the key word;
  - `%14442` → only the four S# reads `%14443..%14446`, each used once, by `%14639 = GetSamplerResource`.
- **The key:** `%14382`'s only user is `%14384 = ShiftRightLogical32 %14382, 0x10`. Its only user is `%14390 = ShiftLeftLogical32 %14384, 0x5`, the offset of the eight T# reads `%14398..%14405`.
- **V# B,** loaded at pc 0x9a3c (he calls it a copy of the same V#, through the same pointer), feeds only those eight T# reads. The T# plans: this branch's base already got past the T# stop at 0x9a50.
- **T# dwords 1 and 2** (`%14399`, `%14400`) are also decoded into width and height (`%14407..%14420`). No other value touches V# A, `%14382` or the S#.
- **The record pointer** comes through four nested Phis from `ReadConstBuffer@pc=0x1fc4`, with `ReadConstBuffer@pc=0x9000` further in the chain (a loop-carried pointer).
- **Then** `%14638 = GetImageResource %14398..%14405`, `%14639 = GetSamplerResource %14443..%14446`, `%14641 = ImageSampleRaw %14638, %14639, %14640, %14395`.

So the refusal comes from a check BF-182 didn't hit. The candidates, read on a765ccece9 `ResourceTracker.cpp` `TryMakeTableColumn`'s nested branch (~L855-880):
- **(a) the parent column:** the recursive `TryMakeTableColumn(*heapHandle, …)` for V# A fails, for example on the four-deep Phi pointer or on V# B being a second load of the same address;
- **(b) the key read's handle:** `%14381` fails `SameHandle(*user, *heapHandle) && DescriptorWordReads(…)`;
- **(c) `ChildKeyWord` on the shift chain:** the key goes `>> 0x10` then `<< 0x5`, where 839741f458's test multiplies;
- **(d) something else.**
