## Commit 1: teardown — `fix(agc): stop host writes reaching the driver once it stops`

What's safe already: the hook pointer is atomic (`GuestArena.cpp:30/484/488`), `PrepareHostWrite` touches no `Driver` member and reaches the driver only through the atomic flush hook (`GuestMemory.cpp:2090/2101`) to `FlushForAccess`, which dereferences the recorder only under the GPU mutex; `stop()` resets the device and recorder under that lock and `~Recorder` clears `activeRecorder` (`Recorder.cpp:1123`).

What still runs after `stop()`: the queued-label branch (`queuedLabelRecorder`, installed once at `DeferredLabels.cpp:187`, never cleared) calls `Driver::recordQueuedLabelsFromHook` (`DeferredLabels.cpp:208`), which calls `Driver::Get()`, takes the GPU mutex and passes `driver.device.Load()` (null after `stop()`), whenever deferred labels remain (`stop()` doesn't clear `deferredLabels()`); the pending-texture registry calls; and on Linux `exit()` runs `~Driver` while title threads still run. Today only `~Driver` clears the host-write hook (`Lifecycle.cpp:90`).

Do (about 20 lines):
1. At the start of `stop()`, before the worker joins, clear the host-write hook (`GuestArenaSetHostWriteHook_nid_no_patch(nullptr)`).
2. Drain calls already inside the hook: `PrepareHostWrite` increments an in-flight counter (seq_cst), then checks a stopped flag and returns if set, and decrements on exit through RAII. `stop()` sets the flag, then waits for the counter to reach 0.
3. Bound that wait (about 1 s, like #6800's bounded flush): on Windows `ExitProcess` can kill a thread inside the hook before `~Driver` runs, leaving the counter at 1; an unbounded wait would be an exit hang like #6641's.

Test: after `Driver::Shutdown()` (public, `Lifecycle.cpp:95`), a host write over a range with a recorded write doesn't reach `FlushForAccess` (its `hookCalls`, `Recorder.cpp:1005`). Red at 082c3268ac. No existing test shuts the driver down, so make it its own case (its own ctest registration if the test binary's other cases need the driver afterwards).

## Commit 2: the lock check — `fix(agc): count a host write made under the GPU mutex`

The exact condition: `GuestMemory::GpuMutex().HeldByThisThread()` at `PrepareHostWrite`'s entry, after the `ownHostWrite` return. Host writes have no supported nested case (every `HostWrite` site is a guest I/O path: libc FileAndHeap.cpp:372; libkernel Aio.cpp:60, Apr.cpp:166, DescriptorControl.cpp:248/402/527, Open.cpp:262, Stdio.cpp:462/722/811/1044/1127, Udp.cpp:923/1018/1129; libSceNet Export.cpp:897/919; libScePosixForWebKit Filesystem.cpp:42; the driver's own macOS import at GuestMemory.cpp:1379 returns through `ownHostWrite`).

Do: when the condition holds, count it and log once (thread tag, address, bytes), then continue (no throw in release: with the mutex held the hook takes `FlushForAccess`'s nested locked wait, a hang only if completion needs another thread's GPU-mutex hold, so a throw would trade a possible hang for a certain crash). With `APS5_ASSERT_GPU_LOCK=1` (the switch `AssertGpuLockHeld` already reads, `GuestMemory.cpp:1938`), abort with a `[lock] ASSERT:` line instead. Add a small accessor for the count. Add one debt sentence (libSceAgcDriver debt, next to #6926's entry): no `HostWrite` under the GPU mutex or another driver lock; one that happens is counted and logged.

Test: a host write made while holding the GPU mutex returns, and the counter moves by one. Its red needs the accessor at the base, so build the red on a synthetic base (the accessor without the check) and say so in the report.

## Commit 3: the counters — `feat(agc): report host writes that waited for GPU work`

Under `APS5_PROFILE_DRAW`, in `PrepareHostWrite`: read the thread's waited milliseconds before and after `FlushGpuWrites` (`Recorder::ThreadWaitedMs()`; if GuestMemory can't see Graphics, use ShaderMemory's waited-ms provider that `Lifecycle.cpp:136` sets). Count calls, calls that waited, total and max waited ms. Print one `[hostwrite]` line every 10 s with the other profile lines (follow how the existing 10-s profile lines are printed). Test: a host write over a range with a pending recorded write counts one call that waited; one over an idle range counts a call that didn't.
