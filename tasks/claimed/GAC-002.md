# GAC-002: AGC: execute the DB out-of-place depth expand (Z_WRITE_BASE != Z_READ_BASE) instead of skipping it, with a red/green test
from: Game Agent Coordinator
for: any
priority: high

## Context

This is Resident Evil Village's top gameplay blocker: the first 3D scene renders as soft light discs on black. The cause is now found. The game runs a DB "expand" (decompress) blit that copies its main depth surface, uncompressed, to a second address. AnyPS5 silently skips that draw, so the second surface stays at the zeros the CPU wrote at boot. Lighting, fog and resolve then sample it as depth, and zero depth is the far plane in reverse-Z.

These are the game's own register values for the draw, as text (4 draws per frame, full screen, VS and PS do nothing relevant):

```
rc=00000060 view=00000000 zinfo=20000183 sinfo=20000181 zread=00202a8a00 zwrite=0020298b00 sread=0020294300 swrite=0020294300 htile=0020293e00 dctl=00000000 eqaa=00000000 cctl=00cc0000 shctl=00000000 tmask=ffffffff smask=00000000 aa=00108001 samples=2
```

- **DB_RENDER_CONTROL** = 0x60: DEPTH_COMPRESS_DISABLE and STENCIL_COMPRESS_DISABLE, no clear and no copy bits.
- **DB_DEPTH_CONTROL** = 0: no depth or stencil test, no writes.
- **Colour:** CB_COLOR_CONTROL mode 0 and CB_SHADER_MASK 0, so no colour writes.
- **Bases:** DB_Z_READ_BASE 0x202a8a0000 (the main depth Z), **DB_Z_WRITE_BASE 0x20298b0000**. The stencil read and write bases are equal (0x2029430000), and HTILE is at 0x20293e0000.
- **DB_Z_INFO** 0x20000183: Z_32_FLOAT, 1 sample, SW_MODE 24 = SW_64KB_Z_X, TILE_SURFACE_ENABLE. The surface is 1920x2160, and the Z plane is 0xFF0000 bytes.
- **On the console:** the DB rewrites every tile of the read surface uncompressed at the write base, in the same swizzle.
- **Later consumers of the write base:**
  - several passes sample it as an R32F 2D texture (format 22) with the same 64KB_Z_X swizzle;
  - a compute shader reads it as a raw buffer.

## What main does today

Use the remote named `upstream` for upstream refs; origin is the fork.

- **The skip:** in `core/libs/prx/libSceAgcDriver/Graphics/src/State.cpp`, `DecodeState` with DB_DEPTH_CONTROL = 0 takes the branch that logs "always-pass depth/stencil state is rendered without a depth target" (around line 784 on recent main). It never calls `decodeDepth`, which would throw "depth read and written at different addresses is unsupported" (around line 283). The draw then renders nothing.
- **Depth is host-only:** depth surfaces (`Graphics/src/DepthSurface.cpp`, `class DepthSurface`) live only in a device-local VkImage. `DepthSurface::Storage()` and `copyPlane` already copy a depth plane into a `StorageTexture`, and StorageTexture has the re-tiling write-back to guest memory (`Texture.hpp`: `WriteBack`, `MarkDirty`, `FlushPending`).
- **No overlap:** #5499 handles a different DB operation (DEPTH_COPY into an R32F colour target). #5113 and #5446 go the other way (storage writes into a depth surface). No open PR handles DB_Z_WRITE_BASE != DB_Z_READ_BASE.

## Task

1. **Red test on lavapipe,** in the style of the existing `core/libs/prx/libSceAgcDriver/tests/execution/` depth tests:
   - render known depth values into a 1-sample D32 depth target at address A (SW_64KB_Z_X);
   - issue the expand draw with the registers above, with Z_READ_BASE = A and Z_WRITE_BASE = B;
   - then (a) sample B as an R32F texture with the same swizzle, and (b) read B as a raw buffer, through a V# in a compute dispatch or a CPU read after a flush;
   - expect the depth values. It must fail on main.
2. **The fix:**
   - Recognise exactly this out-of-place expand: compress-disable bits only, no tests or writes, no colour writes, Z_WRITE_BASE != Z_READ_BASE, a full-surface viewport and scissor, and a live DepthSurface at the read base.
   - Execute it as a GPU copy of the read surface's depth plane into the write base's guest bytes, in the same Z swizzle. Reusing a `StorageTexture` for the write-base descriptor, filled like `copyPlane` and then marked written so the existing write-back stores it, is one way; pick what fits the code best.
   - Every other DB_RENDER_CONTROL / Z_READ != Z_WRITE combination must keep throwing. Per CONVENTIONS.md, unimplemented paths throw; nothing is silently skipped.
   - Note any console behaviour you can't confirm, such as stencil expand or HTILE after the expand, in `docs/dev/debt/libSceAgcDriver.md`, and update its "Reused depth storage" entry if it applies.
3. **Green:** the new test passes. Run `ctest -R '^agc'` with CI's flags and report any test that changes, against a main baseline.
