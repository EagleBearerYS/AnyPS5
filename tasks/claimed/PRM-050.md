## Context

**#8224** (savvaniss, "fix(agc): bind a strided buffer's last record only up to the render target it runs into"): upstream `refs/pull/8224/head` at **9d659c509d**, on main 32e88ad847. It's another contributor's open PR, and the standing OK for other contributors' PR heads covers reading and building it.

- A strided buffer that starts below the render target and runs less than one stride into it is now cut at the target, in two places:
  - `ShaderResources::addGuestBuffer`: the build binds the cut size and stores it as the allocation's `size`;
  - `CheckBufferAliases` in `Draw.cpp`: the check repeated for a cached build.
- **The gap, from reading the code:** `ShaderResources::MovedReadOnlyBuffers` doesn't cut. It's called from `Draw.cpp`'s cached-build hit path, and it compares the allocation's `item.size` with `descriptor.GetSize()`.
  - So a cached build that holds such a buffer sees a different size on every hit, and takes the buffer as moved.
  - Unless an overlap check refuses it, it then rebinds the buffer at the full size, which runs into the render target. The build path avoids exactly that overlap.

**#6636** (ours, fork `perf/agc-reuse-address-draw-builds` at **fc9c5416fc**) conflicts with #8224 in `CheckBufferAliases`.
- #6636 moves the size the build binds (the range-limit cut and the stride-overhang trim at the allocation end) into `ShaderResources::GuestBufferBytes`.
- Both cached-build checks, `CheckBufferAliases` and `MovedReadOnlyBuffers`, take that size.
- With #6636, a moved buffer refuses an address-based build's reuse (`usesBda && !moved.empty()`). So with both PRs and no cut in the moved check, such a draw's address-based build is never reused.
