# BF-063: commit the guest page-state and write-watch tables on first touch on Windows (lane B, memory budget)
from: Bug Finder
for: any
priority: normal

## Why

Memory is a goal of the redesign. The budget for Resident Evil Village (PPSA01556) on the PC is ≤ ~16 GB private at the menu, then ≤ ~12 GB. Private bytes on Windows are commit charge, and Village runs up against the PC's commit limit (47.4 GB; the menu needs 25.5–26.7 GB).

**Two fixed tables are committed in full but barely touched:**
- **The page-state table.** `PageSpan::allocate()` in `core/libs/prx/libSceAgcDriver/Execution/src/GuestMemory.cpp` (~line 372) reserves and commits one byte per 4 KiB page of the guest span: `VirtualAlloc(nullptr, count, MEM_RESERVE | MEM_COMMIT, PAGE_READWRITE)`. That's 250 MiB.
  - Its comment says untouched table pages cost nothing. That's true of RAM, but not of commit: the whole 250 MiB is charged at once.
  - A read-only census of Village's process on the PC (statistics only) found this block 250 MiB committed and ~16 MiB resident.
- **The write-watch tables.** Three of 62.5 MiB each, per the same census. Find where they're allocated, likely in libc's guest write-watch code, and check whether they're committed the same way.

Linux uses `calloc` for the page-state table, which is already lazy there.

## Steps

1. **Find the allocations.** Find each of these tables' allocations and every reader and writer: `load`, `store`, run scans such as the "end of the run of pages equal to a value", and any bulk clear.
2. **Change Windows to reserve the range and commit 64 KiB table pages on first write.**
   - **Reads:** a read of a table page that's never been committed must return the table's zero value without touching it. Use a small bitmap of committed table pages, checked before the load, or another way that doesn't fault.
   - **Writes:** commit before the first write to a table page, thread-safe, idempotent, and cheap after the first time.
   - **Run scans:** they must treat uncommitted table pages as runs of zeros.
   - **Keep the hot paths cheap.** Measure `load` and `store` cost before and after on a micro-benchmark, and give the numbers.
   - Linux stays as it is.
3. **Tests, in the same commit as the change:**
   - **The commit-charge check:** record N scattered guest pages, then require the table's committed bytes (from `VirtualQuery` over its reservation) to be at most a few table pages per touched region, not the full size.
   - **Equivalence:** loads, stores and run scans must return the same values as the committed version for the same sequence.
   - These are Windows-only checks, without a GPU. **The red** is the commit with its allocation change reverted, which must fail the commit-charge check. The Bug Finder runs it on GitHub's Windows runner through the fork's verify sweep. Push the branch and say which ctest names to run.
4. **Linux checks:** `ctest -R '^(agc|libc|libkernel|guest)'`, and CI's Linux job mirrored on the head.
