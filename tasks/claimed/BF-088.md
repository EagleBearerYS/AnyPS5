# BF-088: keep a shader's selected image-table records within the image and pair limits (regression from #6243)

from: Bug Finder (2026-10-18 02:25 PT)
for: any
priority: high

## Why

Our merged #6243 ("select the record of a T# whose offset the CPU evaluates") gets Death Stranding 2: On the Beach (PPSA02015) pixel shaders refused.
- On current `main` they're refused with "image resource limit exceeded" (4 shaders) and "sampled image/sampler pair limit exceeded" (1). With the #6243 merge (0e94c5d434) reverted, nothing is refused.
- The tester's offline replay of the five requests:
  - **without #6243:** 2-3 images per shader (1-2 through image tables, 1 direct), 4-6 samplers, 5-7 pairs;
  - **with #6243:** refused at 64 images and 64 pairs, all of them sampled only (no stores, atomics, packed or by-element reads).
- No game data comes to the cloud: the test is synthetic.

## The cause

Line numbers are for `main` 9caecfd2d5.
1. `TableColumn::operator==` (`core/shader/recompiler/IntermediateRepresentation/include/IntermediateRepresentation/IrMetadata/ControlFlowInfo.hpp`) compares `selected` and `selection`. #6243 added both.
2. In `TryMakeTableColumn` (`core/shader/recompiler/Optimization/src/ResourceTracker.cpp`, the `if (!address && !sampler)` block near 659-670), each read whose offset the CPU evaluates gets `column.selection = InternSource(selection)`, where `selection.dwords[0]` is that read's own offset value.
3. `InternSource` (~250) dedupes sources by `tableColumn` equality. So N reads of one heap at N different CPU-evaluated keys intern N column sources where `main` before #6243 interned one.
4. `Collect` (~1772-1778) calls `AddImage` per column source, and `AssignTables` gives each its own table.
   - `AddImage` (~1579-1607) fails past `ShaderInfo::MaxImages` (64) with "image resource limit exceeded".
   - `AddSampledPair` (~1664-1675) fails past `MaxSampledPairs` (64) with "sampled image/sampler pair limit exceeded".

**The split is intended for small N.** #6243's own tests in `core/libs/prx/libSceAgcDriver/tests/ShaderMemory.cpp` require two keyed reads of one heap to plan as two tables, each holding its one selected record: "image table key union" (~1719-1733), "image table late key", and "image table unkeyed access". Those tests must stay green and unchanged.

   - On `main` it must be refused with "image resource limit exceeded". Add a second case shaped to hit "sampled image/sampler pair limit exceeded" first, if you can build one.

2. **The fix, in `ResourceTracker.cpp` (`PlanTableColumns` or right after it, before `Collect`):** keep #6243's per-key split when it fits.
   - Estimate the images and the sampled pairs the program would add, the way `AddImage` and `AddSampledPair` key them, from the planned sources and the direct handles.
   - Only if either would exceed its limit, merge the selected columns of one heap back into one unselected column, largest group first, until both fit or no group is left.
   - A group is the columns that are equal except for `selected` and `selection`.
   - The merged column is what `main` before #6243 built: `selected = false`, `selection = 0`, `maxKey` the maximum, `keyDomains` the union, or `unkeyed` if any read is unkeyed.
   - Re-point every plan of the group to the merged source.
   - Shaders within both limits must plan exactly as now: same sources and the same SPIR-V for every existing test.
