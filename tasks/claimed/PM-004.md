A user-visible feature for an upstream PR. Build it to the project's own standard: read CONTRIBUTING.md and docs/dev/CONVENTIONS.md first, and follow them exactly.

## What to build
AMD FidelityFX Super Resolution 1.0 (EASU upscaling plus RCAS sharpening) as an optional scaler when the window or swapchain is larger than the game's display buffer. Example: a 1920x1080 display buffer shown in a 2560x1440 or 3840x2160 window.
- ANYPS5_UPSCALE=fsr turns it on. The default stays today's scaler, unchanged.
- ANYPS5_FSR_SHARPNESS=<0.0-2.0> is RCAS sharpness in stops (FSR's convention: 0 is sharpest), default 0.2.
- EASU runs only when the target is larger than the source on some axis. At 1:1 or when downscaling, keep today's path and apply only RCAS if FSR is selected.
- SDR (B8G8R8A8 sRGB) and the HDR10 swapchain from #5697 must both work. FSR 1 expects perceptual input, which both are (sRGB and PQ). State the PQ handling in the PR, and make sure nothing overshoots: RCAS output in PQ must stay inside [0,1].

## Where
Read upstream's core/libs/prx/libSceAgcDriver/Execution/src/PresentationScaler.cpp, PresentationPass.cpp, Graphics/shaders/PresentationPass.frag, the shader build in PostCompile.cmake and the AGC CMakeLists, and the merged HDR10 PRs #5696 and #5697 as the model for detection, defaults, tests and docs.

## Third-party code
- Use AMD's FSR 1 reference from GPUOpen (the FidelityFX-FSR repository, MIT license: ffx_a.h and ffx_fsr1.h), added as a **git submodule built from source**, which is what the PR checklist requires for new third-party code. Pin a release tag.
- Compile it to SPIR-V the way the project builds its other presentation shaders (glslang is already in the tree).
- Keep the license notice the submodule carries. If the project lists third-party licenses somewhere, add it there too.

## Tests (required)
- A lavapipe test that upscales a known synthetic pattern (edges, a thin-line grid and a gradient) from 960x540 to 1920x1080 with EASU, and checks: no NaN or Inf; values within [0,1]; a flat region stays flat; the edge transition is narrower than with today's bilinear scaler.
- An RCAS test: at 1:1 with sharpness 2.0 (the weakest), the result is close to the input; at 0.2, edge contrast goes up while flat areas stay flat.
- A test that the default path is unchanged: with ANYPS5_UPSCALE unset, the output is bit-identical to today's.
- An HDR10-path test if the existing tests make that possible (see #5697's tests).
- Register the tests the way the project does (tools/check_test_registration.py must pass).
