# BF-034: keep the CPU path exact for zero-record vertex descriptors (BF-031's caveat)
from: Bug Finder
for: any
priority: normal

## Why

BF-031 (`results/cloud-1/BF-031.md`) extended `VertexFetchOutOfRange` (Graphics/include/VertexInput.hpp) to records 0 with a nonzero stride and out-of-bounds select 0 or 1. So both paths through `prepareDrawInputs` now bind `zeroVertexBuffer` for that shape.
- **GPU path:** that fixes its abort ("empty or oversized vertex buffer descriptor").
- **CPU path (direct draws):** that changed it. It used to bind an exact zero-padded copy (`fetchValid` 0, `CopyZeroPaddedDrawInput`). It now binds a format-sized zero buffer with the descriptor's stride, so every vertex past the first reads Vulkan's robust out-of-bounds value. That's zero on lavapipe, but (0,0,0,1) is also allowed, so w could read 1 on some GPUs.
- **The rule:** the eventual stage-1 PR must not change direct draws.

## What to build

On both branches, as one new commit each, on top of their current heads:
- `exp/village-fast5-pass-continue-diag` (a941c63a67);
- `fix/agc-indirect-vertex-readable-extent` (b394f383a5, the main candidate).

1. **The fix:** restore the CPU path's exact behaviour for that shape, and keep BF-031's GPU-path zero binding. For example, apply the new arm only when `args != nullptr`, keeping `VertexFetchOutOfRange` as it was and adding a GPU-path predicate next to it. Or give the GPU path an exact stride-0 binding whose layout key allows it, without making `VertexInputCache` rebuild on record-count changes (`agc_vertex_input` must pass). Pick the smaller correct one, and say what the GPU path's fetch past vertex 0 returns with it.
2. **The test:** extend `IndirectVertexPastEnd.cpp` so the direct-draw case fails if the direct draw's attribute w is anything but 0 for vertices past the first, where the shader can make that visible. If lavapipe can't distinguish it (it returns zero), say so and assert what is observable instead, for example that the direct draw binds the zero-padded copy (`fetchValid` 0) rather than `zeroVertexBuffer`, through a counter or a test hook already in reach.
