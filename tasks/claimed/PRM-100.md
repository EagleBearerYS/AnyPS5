## The fix

**The design, decided:** keep the guard serial in the build (`BdaResources`) as the generation the table was filtered at.
- **On a space-reuse hit whose stored serial differs from `MultisampleTargetRangeGeneration()`:** run `ExcludeMultisampleTargetRanges` again over the build's cached space ranges, the ones its table was made from, and compare the result with the build's table ranges.
  - **Equal:** store the new serial and keep the hit.
  - **Different:** refuse the hit.
- **Use the same function a fresh build calls.** There must be no second copy of the exclusion logic.
- **Why not a blanket refusal on any generation move:** the generation moves on every target create, recreate and retire. A title that retires and recreates a multisample target each frame would otherwise lose every space hit, even with the target outside the space.

The design also has to:
- store the generation as `ExcludeMultisampleTargetRanges` wrote it back, not the value read before the call;
- the refusal reason is the existing "space or epoch change" (`AddressDrawReuse::SpaceChanged`), so the counters and the `[rescache]` line need no new reason;
- no production test knob.
