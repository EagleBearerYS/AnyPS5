## Goal

boykopovar/AnyPS5 PR #12792 (ours) makes a storage image's refresh and write-back compare guest bytes with the saved baseline when the surface's page walk fails part way. Reviewers showed that this loses a real CPU store whose value equals the baseline: the walk had seen the store in a block it reached, but the failed walk makes every stamp untrusted. Build the fix: keep the stamps for the pages the walk reached, and compare only the part it did not reach, in both `StorageTexture::refresh` and `StorageTexture::writeBackLayers`. ## The bug, as read at 81ad915d78

- `core/libs/prx/libc/src/GuestWriteWatch.cpp`, `scanWritten` (~:185-207): when `ioctl(PAGEMAP_SCAN)` fails at `cursor`, it calls `written(context, cursor, end)` and returns false. agc's `stampWrittenRun` (`core/libs/prx/libSceAgcDriver/Execution/src/GuestMemory.cpp` ~:1601) then stamps `[cursor, end)` as CPU writes (block stamp and `cpuPages`) at the walk's generation, the same generation as the genuine runs before `cursor`. Other failure points: `takeFresh` (protect failure → `written(begin, end)` for the whole range; `!covers` → false without `written`), `CollectArmed` (a failing armed sub-range leaves the later ones unscanned).
- `Graphics/src/Texture.cpp` `refresh` → `scanBlocks` (~:2321-2330): `tracked = current != 0 && ChangedBlocks(...)`; when false it marks every block written and compares the whole surface (`compareUntracked`). `writeBackLayers` (~:5999-6020): `tracked = walked && ChangedBlocks(...)`, then the same whole compare per saved unit run.
- Windows already separates the two: `noteRefusedWalk` (GuestMemory.cpp ~:1662) CPU-stamps `GuestArenaTakeUnreportedPages` and marks `GuestArenaComparedPages` as `tracker.refused[block]` without a CPU stamp.

## What to build (sktharunbalaji13-cmd's plan, made concrete)

1. **Report the unreached part separately on Linux.** Other callers rely on the conservative CPU stamps of an unreached range (for example VulkanDevice.cpp:844 ignores the collect's result), so keep stamping it as today; additionally record which pages were unreached, at which generation, and what the page's `cpuPages` value was just before, so an earlier genuine store in the same window isn't masked. A clean way is a second callback on new libc exports (for example `GuestWriteWatchCollectReporting_nid_postfix` / `...CollectArmedReporting...`) with the old exports delegating as `unreached = written`; any equivalent that tells agc exactly which range was synthetic is fine. `tests/CollectMemoGeneration.cpp` fakes the GuestWriteWatch exports and must gain any new one.
2. **A block-level answer with an "unknown" flag:** an overload of `GuestMemory::ChangedBlocks(address, bytes, generations, changed, cpu, unknown)`. Per block with unit generation g: g == 0 → unknown; no unreached page and no `refused` since g → exactly today's `changed`/`cpu`; otherwise CPU-confirmed when any page has a genuine CPU stamp after g (or the block's CPU stamp is newer than every unreached or refused mark in it; Windows refused blocks carry no synthetic CPU stamps), else unknown.
3. **Use it in both paths:** on a failed walk, compare only the unknown blocks (`compareUntracked` over runs of unknown blocks; changed bytes count as a CPU write there) and take the stamps for the known blocks; keep today's whole-surface compare only when the new query can't answer. Mind the flags downstream of `scanBlocks` (`compared`, `tracked`, `cpuBlocks = stampedBlocks`, `keptAtUnwatch`, the scoped fills) and in `writeBackLayers` (`compared[layer]`, `unknown`, `cpuBlocks` sized only when `drawn.drawn`).
4. **Debt entry** in `docs/dev/debt/libSceAgcDriver.md` (the one #12792 adds): say what stays open, for example that a same-value store in a page the walk never reached is still not seen. Name titles by their ID only (PPSA02225), as the rest of the file does.

## Tests (in `core/libs/prx/libSceAgcDriver/tests/execution/PendingUntrackedLayer.cpp`)

- **Case A, Refresh:** after the first store (guest and saved baseline hold `Stored`), hold the `StoreAgainCode` result pending; the CPU stores `Stored` again to the first result word, in block 0; `LoseWalk` remaps a page in block 3 so the walk succeeds over block 0 and fails later; `Refresh`. Pass: the CPU's word survives in guest memory and in the image (the GPU result does not overwrite it), as on a complete walk. XairRrR's probe shows this red on 5e106c566d 3 of 3: "image 8 StoredAgain, guest 8 StoredAgain, 0 Stored".
- **Case B, direct write-back:** the same, but no `Refresh`: write the pending results back directly (`StorageTexture::FlushAllPending`) and check that block 0 is left to the CPU's store.
