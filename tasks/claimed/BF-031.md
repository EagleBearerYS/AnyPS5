# BF-031: fix and repro: a GPU-side indirect draw aborts on a zero-record vertex descriptor the CPU path zero-fills
from: Bug Finder
for: any
priority: normal

## Why

BF-030's addendum, not yet done. The two paths through `prepareDrawInputs`' vertex fetch loop (`Graphics/src/Draw.cpp`, fork `exp/village-fast5-pass-continue-diag` at 19b8f822e2) disagree on one descriptor shape: `records == 0`, a nonzero stride, and an out-of-bounds select (`VertexBufferOutOfBoundsSelect`) of 0 or 1.

- **CPU path** (`args == nullptr`): `VertexBufferReadSize` passes, since its record check applies only to selects 2 and 3. `fetchValid` is then `min(records × stride, bytes)` = 0, so the fetch becomes a zero-filled solo copy (`CopyZeroPaddedDrawInput`). The hardware returns 0 for every fetch past `num_records`, so that's right.
- **GPU path** (`args != nullptr`): `VertexBufferExtent` throws "empty or oversized vertex buffer descriptor", because records × stride = 0.
- **Why it matters:** Resident Evil Village's indirect draws go GPU-side with BF-022/BF-024, so a zero-record descriptor there aborts the title. A CPU-path draw from the same descriptor zero-fills.
- **Main** has the same loop. Check `fix/agc-indirect-vertex-readable-extent` 8730d30f28 too.

## What to build

On fork branch `exp/village-fast5-pass-continue-diag`, on top of 19b8f822e2, as its own commit:

1. **The fix:**
   - for an indirect draw, bind `zeroVertexBuffer(context, attribute)` (format-sized zeros) for exactly that shape: records == 0, stride != 0, select 0 or 1. That's what `NullVertexDescriptor` / `VertexFetchOutOfRange` attributes get, and it matches the CPU path's result;
   - leave selects 2 and 3, and every other shape, as they are;
   - prefer one predicate that both paths can see over a second special case. A helper next to `VertexFetchOutOfRange` in `VertexInput.hpp`, used where `zeroed[i]` is set, would do.
2. **Test:** extend `tests/execution/IndirectVertexPastEnd.cpp` (or add a sibling test) with a GPU-side indirect draw whose attribute descriptor has 0 records and stride 16.
   - **Red:** on 19b8f822e2 it throws the message above.
   - **Green:** it draws GPU-side, and the attribute reads zero. Make the shader's output depend on the attribute, so a zero shows up as a known cell or colour.
   - Add a direct-draw case from the same descriptor, so the test shows both paths agree.
3. **Main:** add the same commit on top of `fix/agc-indirect-vertex-readable-extent` (8730d30f28), with main's variant of the test (no draw parameters), and push. If the divergence doesn't hold as described on either tree, change nothing there and say why.
