# BF-098: Lane B: stop every cached BdaResources from holding its own 32 KiB host-visible fault buffer
from: Bug Finder
for: any
priority: normal

## Why

BF-092's host-visible owner counter (fork `exp/lane-b-host-visible`, head `7e992a8e3`) splits the Village-shaped bench's host-visible memory. At `--cost 20` the peak is 246–268 MiB, and 225–263 MiB of it is "shader data". A large part of that is BDA fault buffers. Every `BdaResources` makes one, and the resource cache keeps a `BdaResources` per recorded draw. In one run before the shader-data owner existed, 3,403 of them were live as "other": 106 MiB. On Resident Evil Village (PPSA01556) the cache holds far more draws than the bench, so this is a lane B memory cut.

## Facts on upstream main (read them at the main you base on; line numbers drift)

- `Graphics/src/BdaResources.cpp`, the `BdaResources(const Context&)` constructor:
  - `fault = std::make_unique<Buffer>(context, ShaderRecompiler::BdaAbi::FaultBufferBytes, VK_BUFFER_USAGE_STORAGE_BUFFER_BIT);`
  - two `memset`s clear the report words and the SRT guard word.
- `core/shader/recompiler/BdaAbi.hpp`: `FaultBufferBytes = (SrtGuardWord + 1) * sizeof(std::uint32_t)`. Find out what lives in it: the report, the written list (`WrittenListWord`), the SRT guard word. Work out how much of it a draw can actually write.
- **Readers:**
  - `BdaResources::Fault()` gives the descriptor binding, bound in `ShaderAddressResources.cpp` (the `DescriptorRole::BdaPagetable ? bda->Table() : bda->Fault()` line).
  - `CheckFault()` reads and clears it after the batch: the report `memcpy`, the full `memset` after a report, the SRT guard read, and the written-list words. `SetImageTables` and `SetSrtGuards` attribute what it finds.
- **The resource cache** that keeps `BdaResources` alive across frames: find it from `ShaderAddressResources.cpp` and the draw-record cache. Say how many it keeps, and when it drops one.

## What to do

Count the live `BdaResources` and the fault-buffer bytes, for example with a local counter you don't commit. Report what share of "shader data" they are.
2. **Choose a cut that keeps every fault report exactly as it is.** That means per-draw attribution, image-table faults, SRT guard faults, the written list and the loop guard. Candidates, in the order I'd try them:
   - **(a)** A per-device fault arena: one host-visible buffer cut into `FaultBufferBytes` slots, or the smaller size from (c). A `BdaResources` takes a slot when it's bound for a batch and gives it back after `CheckFault` has read it. A cached `BdaResources` then holds no slot while idle. Bind with the slot's offset, which needs `minStorageBufferOffsetAlignment`.
   - **(b)** If the fault buffer must outlive the batch (check `CheckFault`'s callers), release it when the cache parks the `BdaResources`, and take one again on reuse.
   - **(c)** If a draw writes only a prefix of `FaultBufferBytes`, a smaller slot. This changes the shader ABI only if the recompiler's offsets move, so prefer a cut that keeps `BdaAbi.hpp` as it is.
3. **Measure again:** the same bench, with "shader data" and the total before and after, two runs each.
4. **Branch:** `perf/agc-shared-bda-fault-buffers` on the fork, based on current upstream main (fetch `upstream main`).
