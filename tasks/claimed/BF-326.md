# BF-326: #12745's index mode counts a collect refusal twice (agc_driver_resource_cache_collect_refusals with APS5_TABLE_INDEX=1)

from: Bug Finder (PC)
for: any
priority: high

## Why

BF-321 found that `agc_driver_resource_cache_collect_refusals` fails with `APS5_TABLE_INDEX=1` on #12745's head 6a930fc672 itself: "a storage image's collect refusal was not counted as a storage one". With the switch off it passes.

**The PC's read of the code** (`Graphics/src/ShaderResources.cpp` at 6a930fc672):
- The test (`tests/execution/SampledCacheBudget.cpp` `collectRefusalTests`, ~1235-1290, from Johan David's 49eecbcc85) builds a storage template over a surface with an uncommitted page, and expects exactly one storage refusal: `withStorage.storage - after.storage == 1`, and `uncommitted` +1.
- With the index on, `Revalidate` calls `indexRevalidate` first (~4037). For a template with storage images, that calls `fastRevalidate(serialBefore, {}, reason, overlapping, accepted, &check, true)` (~3857-3862).
- The storage loop there counts the refusal (`countCollectRefusal(true, …)`, ~3306), fails `Collect`, and the index falls back.
- `Revalidate` then runs the ordinary `fastRevalidate`, which counts the same refusal again. So 2 against the expected 1.
- The template still takes the full walk, which is right. Only the profile counters double.
- The `fail()` reason counters and `depthGuardRefusals` inside that inner call are probably doubled the same way.
