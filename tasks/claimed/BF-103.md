# BF-103: graphics pipeline libraries retain link-time-optimization info only where an optimized link will be made
from: Bug Finder
for: any
priority: normal

## Why

BF-101 (cloud-3, `results/cloud-3/BF-101.md`) read main's graphics pipeline library path:
- **The flag:** every library is created with `VK_PIPELINE_CREATE_LIBRARY_BIT_KHR | VK_PIPELINE_CREATE_RETAIN_LINK_TIME_OPTIMIZATION_INFO_BIT_EXT` (`Graphics/src/PipelineLibrary.cpp:198` on main 9be6ccf60).
- **Who needs it:** only the background relink, which links with `VK_PIPELINE_CREATE_LINK_TIME_OPTIMIZATION_BIT_EXT` (`PipelineLibrary.cpp:280-300`).
- **When that relink exists:** only when `optimize = backgroundLinking && context.pipelineLinkTimeOptimization` (`:183-184`). `pipelineLinkTimeOptimization` is false on `VK_DRIVER_ID_NVIDIA_PROPRIETARY` (`Execution/include/PipelineLinkOptimization.hpp:8-10`, `Execution/src/VulkanDevice.cpp:1526`) and with `APS5_NO_PIPELINE_LTO=1`.
- **So on NVIDIA,** every library keeps its LTO info until the device is destroyed, and no link ever reads it. Libraries are never evicted either.

On the PC (RTX 3070), Resident Evil Village (PPSA01556)'s NVIDIA driver arenas hold 3.3 GB with GPL on and 1.4 GiB with `APS5_NO_GPL=1`. How much of that is retained LTO info is for a PC pair to measure. This task makes the change and its test, so the pair can run.

   - Make `optimize` part of the library cache's context key, so a library made without the info is never named by an optimized link. That covers a device or test context that forces `pipelineLinkTimeOptimization`, and any path that sets `backgroundLinking` per link.
