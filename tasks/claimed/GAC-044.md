```
[gpu] host import budget: 3 MiB live of 3 MiB (APS5_HOST_IMPORT_MIB); 1 imports (0 MiB) refused so far, last 0x200400000+0x10000
```

The run is the "Verify finding" workflow on the fork, branch `verify/fix/agc-heap-mirror-replan-after-unwatch-4ec217c795`. Read its Windows job log for the whole output.

**Reading** (the coordinator's, unproven): the setup (`RunHeapMirrorUnwatchTests`, `tests/BdaResources.cpp`) sets a budget "one block short of all three" from the sizes the imports take on Linux:
- a 2 MiB heap;
- a 1 MiB idle range in a 2 MiB allocation;
- a 64 KiB busy range.

On Windows the first imports already fill 3 MiB, so the 64 KiB busy range (0x200400000+0x10000) is refused.
- **Likely causes:** the idle range's import is rounded to its whole allocation or to a larger import alignment on Windows (`hostImportAlignment`, WindowsMappings), or it is settled into a bigger import.
- **Find out which:** print or check the live bytes after each import.
