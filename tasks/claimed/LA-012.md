## Why

Two of LA-004's open problems (`results/cloud-5/LA-004.md` on `cloud-results`) are still open. They are numbered as in LA-004.

- **5, correctness: part (f) reads zeros without eager write-back.**
  - **Setup:** a heap cap of 2, host imports and `APS5_GPU_PATH=1`.
  - **What happens:** the warm draw reads zeros, "(f) the warm draw: pixel (0, 0) channel 0 is 0, expected 160", in 3 of 3 runs.
  - **The other configurations** pass without eager write-back. The harness parts all keep eager write-back on, so they never cover this case.
  - **What (f) exercises:** a program whose key finds no heap slot falls back to the CPU table path. Its warm draw then comes from the draw cache on the CPU table. In this configuration that warm draw reads zeros, and nothing reports it.
- **4, cost: every unwatched entry is re-checked every frame.**
  - **What it is:** with host imports, a host import unregisters its allocation from the write watch, so lane A re-checks every live entry once each time the collect epoch moves.
  - **What it costs:**
    - about 150–170 µs per entry on cloud-5;
    - 40–50 µs per draw at 256 entries, growing with live entries;
    - most of the difference between the import path's ~82 µs per draw and the copy path's ~30 µs on LA-004's Village-shaped bench.
  - **LA-004's suggested direction:** a finer test, using the driver's `NewestStamp` over the entry plus the storage cache's own state, without the epoch.
