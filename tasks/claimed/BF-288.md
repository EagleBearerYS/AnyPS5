# BF-288: cross-thread store cases for #12921's untracked hint proof

from: Bug Finder (PC)
for: any
priority: high

## Why

CnRJay's review of our PR #12921 (https://github.com/boykopovar/AnyPS5/pull/12921, review 5703274169), point 3, asks what guarantees a walk between an untracked surface's equal compare and its next fast check, and asks for "a case that stores into the range from another thread right after the compare".

The code (PR head fdc70046f8) already gives that guarantee. Your job is to turn it into tests, not to change product code.
- `currentUntrackedStamp` → `hintedProof` → `GuestMemory::UntrackedHint` (Execution/src/GuestMemory.cpp ~2195) walks the range's write-watch marks itself (`walkHints`: `GuestArenaCollectWrites_nid_postfix(..., clear=true)`, then `stampHint` under the tracker mutex).
- The only skip is `threadHintMemo`: a thread that already walked the range in its current collect epoch reuses that walk, the same per-thread epoch memo `collectWrites` uses for watched memory.
- `collectWrites` returns 0 for an uncovered range before walking anything, so nothing else clears a hinted page's marks without stamping them.
- `StorageTexture::compareUntracked` (Graphics/src/Texture.cpp ~2600) takes the hint (and its walk) *before* `EqualsCommittedUnsynced`. So a store racing the compare leaves a mark for the next walk.

If you find a case where that reasoning is wrong, stop and report it first, with the failing test. That would be a correctness bug and changes the plan.

1. **`agc_untracked_hint_proof`** (`tests/Recorder.cpp`, `untrackedHintProofTests`), before `sampled.reset()`:
   - **Case A: a store from another thread right after the compare, before the stamp is recorded.** It is the existing `walkStore` case, but `storeDuringWalk` does its `memset` (and the `UntrackedHint` call) on a `std::thread` it starts and joins inside the hook. Same assertions as the existing case: the next collect epoch's proof is not fast, and the image version moves.
   - **Case B: a store from another thread after a fast proof.** In one collect epoch, prove fast on the main thread (so its hint memo holds that epoch). A `std::thread` stores into the first surface and is joined. Then `BumpCollectEpoch` on the main thread. Require not fast and a new version.
   - **Case C: a check on another thread.** After a fast proof on the main thread, store on the main thread, then run `sampled->Revalidate` on a `std::thread` that calls `BumpCollectEpoch` first. Require that its report is not `Fast` and that the version moved. That thread's memo is empty, so it must walk.
   - On Linux the block has no hint and the test runs under the epoch rule ("the block has no write-watch hint" line). The cases must hold in both modes; write the assertions so they do.
2. **`agc_write_tracking`** (`tests/WriteTracking.cpp`, inside its existing `#ifdef _WIN32` hint tests, next to the cross-leaf `UntrackedHint` case): a device-free version, which can run on GitHub's Windows runner (no GPU there).
   - Read the hint on the main thread.
   - A `std::thread` stores into the range and is joined.
   - **Same epoch, other thread:** a third `std::thread` that calls `BumpCollectEpoch` reads a newer hint.
   - **Shared stamps:** back on the main thread in its old epoch, `UntrackedHint` also returns the newer value, because the stamps are shared.
   - **Next epoch:** after `BumpCollectEpoch`, the main thread reads the newer value.
   - Plus one racing case: a writer thread storing in a loop while the main thread reads the hint across 50 epochs. After the writer stops and one more epoch, the hint must be newer than any value read before the writer's last store.
3. **Reds, as patches only.** Don't commit them. Put each as a `git diff` in the result (text), and say which case each is meant to fail.
   - **R1:** `compareUntracked` takes `hint` after `EqualsCommittedUnsynced` instead of before. This should fail case A on Windows.
   - **R2:** `UntrackedHint`'s memo ignores the epoch (`entry.epoch == epoch` dropped). This should fail case B and the device-free cases.
   - Neither can show on Linux (no hints). Say so; the PC runs them on Windows.
