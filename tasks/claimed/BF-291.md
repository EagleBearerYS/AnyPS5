# BF-291: a dispatch's complete stage without the GPU mutex (the texture-cache locking redesign; real fix)

from: Bug Finder (PC)
for: any
priority: high

## Why

Resident Evil Village's menu is bound by queues 0x0 and 0x20 taking turns on the GPU mutex.
- Each waits 2.1–2.3 s per 10 s for it, behind the other's dispatches.
- Each holds it ~1.1 ms per dispatch, over ~2,600–2,700 dispatches per 10 s.
- **What fills the hold:** the dispatch's resource complete stage (`buildComplete`: image lookups, `UploadFinish`, descriptors) and the hit's `Revalidate`.

BF-284 (fork `perf/agc-preresolve-outside-gpu-mutex` c336ba2e77, `results/cloud-4/BF-284.md`) moved only the key, the lookup and stage A out of the lock for draws. It concluded that stage B and the proof need "the proof state readable without the GPU mutex":
- `StorageTexture::UploadedKeys` / `FilledKeys` / `KeyProof`;
- `GenerationFor` and `Version`;
- `Texture.hpp`'s "under GuestMemory::GpuMutex only" fields;
- and everything stage B mutates (texture caches, the import set, the recorder).

BF-293 measures the ceiling of that concurrency tonight. This task is the **real design**. A large PR is acceptable if the ceiling says it pays.
