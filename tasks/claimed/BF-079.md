## Why

On AMD's Windows driver, Demon's Souls (PPSA01342) and NHL 27 (PPSA34063) crash the shader compiler at boot: `amdvlk64.dll+0x9e251f` in `vkCreateGraphicsPipelines`. A pixel shader gets one `OpTerminateInvocation` per guest-memory read that can fault, up to 216, and AMD's compiler crashes on those.

The fix is on the fork: branch `fix/shader-pixel-bda-single-exit`, head 843a7d9a00, on upstream main 195d0d08a8. It's a port of poonasor's poonasor/AnyPS5@eb2e2309, and it works like this:
- **New form:** a pixel shader that can stop on a BDA fault now has its guest code emitted as a function of its own. A failed read sets a Private bool and returns, and the entry point calls the function and terminates once if the flag is set (`SpirvModuleEmitter.cpp`, `SpirvBdaFault.cpp`, `SpirvEmitterState.hpp`).
- **Primitive-ordered pixel shaders** keep the old per-site form.
- **The flag's interface listing:** it goes into the entry point's interface only for SPIR-V 1.4 and later, as `stencilRefVariable` does.
- **Test:** the same commit updates `orderedPixelShaderTests` in `core/libs/prx/libSceAgcDriver/tests/Graphics.cpp`. An unordered pixel shader with BDA reads now has one `OpTerminateInvocation` in the module, and it's in the entry point; without the extension that's one `OpKill` there plus the shader's own. The ordered cases are unchanged.

GitHub's Linux and Windows verify of `agc_driver_graphics` and `agc_driver_gpu_buffer_format` is running separately. This task is the full Linux check.
