## What to change, as one commit on top of 5a9d89179c

New fork branch **`fix/agc-sample-order-copy-sampled-only`**, created from 5a9d89179c, with one more commit:

1. **The copy image's usage** (your suggestion 2). In `SampleOrders::Depth` (`core/libs/prx/libSceAgcDriver/Graphics/src/SampleOrder.cpp`), create the sample-order copy with `VK_IMAGE_USAGE_TRANSFER_DST_BIT | VK_IMAGE_USAGE_SAMPLED_BIT` only, with no `DEPTH_STENCIL_ATTACHMENT`, so AMD's driver gives it no HTILE.
   - Check legality per format before relying on it: `vkGetPhysicalDeviceImageFormatProperties` for that format, `OPTIMAL`, 2D, that usage, must succeed and its `sampleCounts` must include the target's count (the spec takes `sampledImageDepthSampleCounts` for a depth format with SAMPLED usage). The format must also have `TRANSFER_DST` in its optimal-tiling features.
   - **If that is illegal for a format,** keep today's usage for that format and use the layout variant instead: after the copy, transition the copy to `VK_IMAGE_LAYOUT_DEPTH_STENCIL_READ_ONLY_OPTIMAL` for the draw, with the descriptor's `imageLayout` matching. Say in the result which formats, if any, took this path on lavapipe.
2. **Binding 1** (your suggestion 3). For `SampleOrderMethod::Depth`, write binding 1 too (the depth view is fine), so no descriptor the shader declares is left unwritten.
3. **Its test.** Extend your `--depth-copy-barriers` recording context, or add a sibling mode in the same executable, so it also fails when:
   - the copy image of a depth pass is created with `DEPTH_STENCIL_ATTACHMENT` usage on a format where TRANSFER_DST | SAMPLED is legal;
   - a depth-only pass's descriptor set leaves binding 1 unwritten.
   A new ctest name goes in the WIN32 `PATH` list, as your BF-110 modes did. A new mode name keeps `check_test_registration` clean.
