# BF-068: on Windows, allocate the guest write-stamp tables per leaf on first stamp, as Linux does (lane B, memory budget; follows BF-063 on its branch)
from: Bug Finder
for: cloud-5
priority: high

## Why

This is the second commit on BF-063's branch. It's for the worker that did BF-063, since it touches the same file.

BF-064 (`results/cloud-3/BF-064.md` §1) pinned three of the 62.5 MiB blocks that Resident Evil Village (PPSA01556) holds at the menu on Windows:
- **Where:** `GuestMemory.cpp:811`, `:812`, `:814` at 32ac24cb3 (`initialize`, Windows only). These are `blocks`, `cpuBlocks` and `hintBlocks`, each a `std::vector<std::uint32_t>` assigned `size / 64 KiB + 1` zeros.
- **What they hold:** per-64 KiB-block write stamps for the whole 1000 GiB arena: 16,384,000 entries × 4 bytes = 62.5 MiB each.
- **The cost:** `assign(n, 0)` writes every byte, so all 187.5 MiB is committed **and dirty** at start. Village's data share is 8%, so ~172 MiB is zeros.
- **Linux already avoids this** (`:773-779`): `LeafCount = 2^15` leaves of `LeafBlocks = 2^16` blocks, each leaf a `unique_ptr` allocated on first touch, 4 GiB of guest space per leaf.

   - **Reads:** a read of a missing leaf returns the table's zero value without allocating it.
