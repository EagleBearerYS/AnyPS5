## Why

Resident Evil Village (PPSA01556), Windows 11, RTX 3070. Our fast tree (main 44df216321 + #6366 + other open PRs) aborts in the save load, before control:

```
[Shaders/ShaderRegistry.cpp:791 operator()] Shader 0x231479ff00 could not be prepared at registration (its program address is not in the shader registers); preparing it when it is used
[libc] unhandled exception 'St13runtime_error' thrown from 00007fff1b5ece9e
  what():  AGC graphics: VGT_SHADER_STAGES_EN=0x2030: unsupported geometry input or output assembly
FATAL: abort() (SIGABRT) on thread 11780
```

What the PC found:
- `addr2line` on the `-g1` build puts the throw at State.cpp's `validate` inside `DecodeShaderStages`, the non-tessellation geometry branch's "unsupported geometry input or output assembly" check.
- The caller with no guard is `ResolveGraphicsStagesAbi`.
  - #6366 deferred a stage whose *preparation* (`PrepareShaderWithDiagnostics`) fails.
  - It did not defer a *decode* failure of the ABI call's state, which here is the registered state plus the call's context and primitive registers.
- An older tree that deferred every ABI stage to first use (a local `APS5_DEFER_ABI_PREPARE=1` experiment) passed the same point to control. So the draws that use these stages decode their own state fine.
