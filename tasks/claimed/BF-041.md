# BF-041: O(1) validation of a cached build's image tables (reverse index from write-tracker blocks to cached builds), lavapipe prototype
from: Bug Finder
for: any
priority: high

## Why

BF-037 (results/cloud-1/BF-037.md §2) showed that a cached draw's ceiling is set by validation, not by descriptors. On an unchanged draw at N = 4,096 table textures, `Revalidate` is 93% of the draw: 18.3 of 19.6 ms. It re-proves every texture at 2.3–4.5 µs per element, even below the lookup-log bound (2.4 µs per element at N = 128). With one texture changed, every draw is a full rebuild.

Resident Evil Village (PPSA01556) draws bind about 2,000 textures:
- **At its menu:** ~3,500 fast proofs and ~430 full walks per 10 s.
- **More coming:** reusing address-based draws (#6636) and dispatches (BF-040) will add thousands more revalidations per 10 s. All of it runs inside the GPU mutex.

BF-039 fixes the `no record` full walks. This task removes the per-element proof itself.

## The design to prototype

On a fork branch **`exp/table-o1-validation`**, on upstream main, or on BF-039's `fix/agc-lookup-log-fits-build` if it has landed (else run with `APS5_LOOKUP_LOG_BOUND=8192`). Throwaway, no PR.

1. **A reverse index** in the write tracker (`Execution/src/GuestMemory.cpp`), from tracker blocks to *subscriptions*:
   - **What a subscription is:** a cached `ShaderResources` (or one of its image tables) registers the set of ranges its validation covers. That's its textures' ranges, and its T# and table spans.
   - **What it gets back:** a generation counter that any change over those ranges bumps.
   - **What bumps it:** a CPU write the watch collects, a recorded or landed GPU write noted as pending, an unwatch, a remap or a free.
   - **The cost moves to the writers:** a collect that finds dirty blocks looks them up in the index. That cost is proportional to dirty blocks times the subscriptions over them, not to textures times draws.
   - **Compared ranges** (an unwatched or compared range: `GuestMemory::Watched` false) can't bump a generation. A subscription over any such range stays on today's per-element proof for those elements only. Count them.
2. **`Revalidate`'s fast path becomes O(1) per subscription:** if the generation is unchanged since the build, the build is current. That covers its textures' memory, its tables' T# words and pending writes. Today's per-element checks stay as the fallback when the generation moved.
3. **On a moved generation, re-resolve only what changed.**
   - Find which elements' ranges were bumped: record the bumped blocks per subscription since its last check.
   - Re-resolve only those elements, keeping the rest of the build. That's BF-037's skip, now driven by the index.
   - If the build's structure must change (an element's texture is replaced by a new `Texture`), re-bind just that element.
   - Measure what remains.
4. **Prior art and composition:**
   - #6454 (`perf/shader-image-table-reuse-v3-pr`, ours, open) vouches for a table's T# words with one `SrtWriteStamp` per span. Reuse its stamp if it fits, and say how the two compose.
   - fable-void's `0171a4ac80` (https://github.com/fable-void/AnyPS5, `wip/new-gpu-path`) keeps each device-image entry's last-checked state and checks only named entries. That's O(entries named), and the idea for item 3. Credit him if it is adapted.

## Checks

- **Correctness tests**, each red against a deliberately broken index (a skipped bump) and green with the change:
  - a CPU write to one texture's page invalidates that element only;
  - a T# word change in the table invalidates;
  - a pending GPU storage write over a texture invalidates, until it lands and is published;
  - a free or remap of a texture's range invalidates;
  - an element in compared (unwatched) memory still gets its per-element proof.
- `ctest -R '^agc' --parallel 4 --timeout 120`, with the prototype off (default) and on (an env switch), against main on the same machine.
