## Context

Resident Evil Village on the main-based explorer tree, fork `test/village-fast-main-ports` 4cd4260a9a, has `APS5_HOST_IMPORT_MIB=6864` and `APS5_TRACE_HOST_IMPORT=1`. Its first scene runs at ~0.07 fps. On the older e34 tree (common base with main: e34c479210) the same heap imported fine under the same budget.

**The log:**
- 33,395 `[gpu] host import of ... ok` lines.
  - 32,407 of them are `+0x10000` (64 KiB), over 27,636 distinct addresses spanning 0x1f00000000-0x23fbd50000.
  - Each 64 KiB range is four separate 16 KiB allocations: VirtualQuery shows `state 0x1000 protect 0x4 type 0x40000` (MEM_COMMIT, PAGE_READWRITE, MEM_MAPPED) for each. The title maps that memory in 16 KiB views.
- **Timing:**
  - The first small imports start right after boot's 4 MiB imports, among shader-registration lines, with no texture created yet.
  - Later bursts come with texture creation (3,380), 12,737 `[upload] ... guest memory changed` lines and 5,034 StorageTexture upload submits.
- **Failures:**
  - At 16,225 live imports (6,557.7 MiB live), 992 imports failed at `vkAllocateMemory (-2); falling back to copies`. That's likely Windows' shared GPU memory ceiling, about half of 15.4 GB RAM.
  - Then the budget filled: `6863 MiB live of 6864`, then `4541 imports (1087 MiB) refused so far, last 0x200200000+0x30000000`. That's a 768 MiB heap, whose address-based builds then mirror or copy it.
- 479 lines say `retired: the range was mapped again`. Only 119 imports end in ", joined at bind".
