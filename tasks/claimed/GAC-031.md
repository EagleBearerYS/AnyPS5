## Context

- **The symptom.** Resident Evil Village (PPSA01556), on main + simonbronk's open #5907 + fdfawef324's proposed change from #5907's thread (https://github.com/boykopovar/AnyPS5/pull/5907#issuecomment-6190948577), still stops with `the depth target's sample count differs from the rasterizer's`. The refused draw:
  - 2 raster samples (`PA_SC_AA_CONFIG` 0x00108001), a 1-sample depth target, no colour target;
  - `PA_SC_MODE_CNTL_0` 0x3 (MSAA_ENABLE), no PS_ITER_SAMPLE, `DB_EQAA` 0;
  - `SPI_PS_INPUT_ENA` = `SPI_PS_INPUT_ADDR` = **0x2301**: PERSP_SAMPLE, POS_X_FLOAT, POS_Y_FLOAT and ANCILLARY.
  - The proposal keeps PERSP/LINEAR_SAMPLE and ANCILLARY on #5907's sample-zero path, but refuses ANCILLARY together with POS_X/Y. Its reason: reading the sample index makes Vulkan shade per sample, which moves `FragCoord` from the pixel centre to the sample position.
- **Why, in main's code (2e5dd5aa14):**
  - `core/shader/recompiler/Optimization/src/ConstantFolder.cpp` (~389): the ancillary's sample-number field becomes `insertBuiltin(..., StageInputKind::SampleId)`.
  - `core/shader/recompiler/Translation/src/InstructionTranslator.cpp:354`: POS_X/Y_FLOAT are `gl_FragCoord` directly.
  - `core/libs/prx/libSceAgcDriver/Graphics/src/ShaderInputState.cpp:162`: `sampleShading = loaded(PerspectiveSample) && loaded(LinearSample)`, which becomes `psSampleShading` (`ShaderInputInfoBuilder.cpp:143`). Find what the SPIR-V backend does with it: a `Sample` decoration, or sample-rate shading.
  - `Graphics/src/Pipeline.cpp:464`: `sampleShadingEnable` follows the guest's `perSampleShading` (PS_ITER).
  - Vulkan: a fragment input decorated `SampleId` or `Sample` (and some others: check `SamplePosition`) makes the shader run per sample, with `minSampleShading` 1.0.
- **The console.** A pixel shader that the hardware doesn't iterate per sample (PS_ITER_SAMPLE clear, `DB_EQAA.PS_ITER_SAMPLES` 0) runs once per pixel.
  - The ancillary's sample field is the "iterated sample number", so 0.
  - POS_*_FLOAT follow `SPI_BARYC_CNTL.POS_FLOAT_LOCATION` (the pixel centre by default).
  - The PERSP/LINEAR_SAMPLE barycentrics of a non-iterated pixel are taken to be sample 0's. fdfawef324 infers this too; confirm it from the ISA or register docs where you can.
- **So on main:**
  1. such a shader runs once per sample on the host where the console runs it once per pixel: extra fragment work on every real multisampled target;
  2. POS_X/Y are off-centre under that forced per-sample shading;
  3. #5907 has to refuse those inputs.
- Same scheme in Resident Evil 4 (PPSA07411): fdfawef324's comment shows the 0x2001 pass (PERSP_SAMPLE + ANCILLARY).

## Task

On current `upstream/main`, fork branch **`fix/recompiler-once-per-pixel-sample-inputs`**:

1. **The fix:** when the guest pixel shader isn't iterated per sample, the host shader must not force per-sample shading.
   - Fold the ancillary's sample number to 0 instead of `SampleId`.
   - Interpolate PERSP/LINEAR_SAMPLE at sample 0. `InterpolateAtSample` with 0, `InterpolateAtOffset` with sample 0's offset, or another equivalent: weigh what each needs and forces in Vulkan and SPIR-V (capabilities, sample shading, custom sample locations).
   - `FragCoord` then stays at the pixel centre; honour `POS_FLOAT_LOCATION`.
   - The recompile request needs to know whether the guest iterates. Check the cache keys, and take the next unused `FormatVersion` by value if any plan or IR encoding changes. Main is 36, #6243's follow-up 37, PM-038 v3 maybe 38, so 39 if 38 is taken; check main and the open PRs at build time.
2. **Siblings:**
   - PERSP_SAMPLE and LINEAR_SAMPLE;
   - the ancillary's other fields (render target array index, primitive type);
   - `POS_FLOAT_LOCATION` centre, centroid and sample;
   - centroid inputs untouched;
   - iterated shaders (PS_ITER_SAMPLE, `DB_EQAA.PS_ITER_SAMPLES`) unchanged;
   - SAMPLE_COVERAGE and `SampleMaskIn`;
   - 1-sample targets;
   - alpha-to-coverage and dithered alpha-to-mask, which read coverage per sample.
3. **Tests**, red on main and green with the fix:
