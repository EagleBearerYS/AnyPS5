# BF-245: a profile-only memory census line: name every GB of the process by owner (Village pages on 16 GB, high)
from: Bug Finder
for: any
priority: high

## Why
- **The project's order for Resident Evil Village (PPSA01556) is now memory first.** On our Windows test PC (16 GB RAM, RTX 3070), every arm shows the same picture:
  - process private (commit) is about 16.5 GB at menu+1 and 17.5–22.8 GB at menu+15;
  - the working set is only 1–2 GB, with 300–550 MB of RAM free;
  - about 62% of the packet worker's time is `memory_wait`.
- **The aim:** bring private toward ~10–12 GB. Each cut needs a named owner, so we need a census of where the bytes go.
- **What's measured so far:** with the draw cache off (`APS5_NO_DRAW_SRT_ENTRIES=1`), private stays at ~17.5 GB rather than ~22 GB. Earlier rough breakdowns put the game's guest arena at ~6.2 GB at the menu, and live host imports at ~6–7 GB of RAM pinned as GPU-shared (`APS5_HOST_IMPORT_MIB=6400`).
- **What's missing:** our log lines give rates, not residency. Today's profiled lines (`[bufferpool] … retained`, `[heap-hold]`, `[buffers] image mirrors … heap … MiB`, `[gpu] sampled texture cache …`, `[texture] … storage images (… MiB)`) cover only a few pools.

## What
**Build:** on current upstream `main` (`git fetch upstream main`; use `upstream`, never `origin`), on fork branch **`diag/memory-census`**.
- One `[mem-census]` block printed with the existing 10 s profile summaries.
- **Gate:** only when `APS5_MEMORY_CENSUS=1` is set. With the variable unset, the only cost is one relaxed load or a static bool, and nothing else changes.
- Keep it to a few lines per 10 s.
- It's a diagnostic. It may later be offered upstream, so it follows `docs/dev/CONVENTIONS.md` (no comments in code), but it isn't a PR yet.

**Every figure in MiB, grouped by owner:**
1. **Process totals.**
   - Windows: `GetProcessMemoryInfo`'s PrivateUsage, WorkingSetSize and PagefileUsage, plus system free RAM.
   - Linux: `VmRSS`, `RssAnon`, `RssFile` and `RssShmem` from `/proc/self/status`, and commit (`Committed_AS` is system-wide, so use the smaps_rollup sums instead).
2. **The address-space walk.**
   - Windows: `VirtualQuery` over the whole address space. Linux: `/proc/self/smaps` or `smaps_rollup`, per region.
   - Sum the committed bytes:
     - **(a) Inside the guest arena's reservation(s),** split by what GuestAllocations knows (direct memory, flexible memory, stacks and others, if it can name them). Report committed and, on Windows, resident (via `QueryWorkingSetEx`) if cheap. Otherwise skip residency.
     - **(b) MEM_MAPPED / shared views,** such as host-import aliases (`GuestArenaMapAlias`) and file mappings.
     - **(c) MEM_IMAGE** (DLLs).
     - **(d) Other private,** outside the arena.
   - (d) is where the emulator's own heap and the driver's host-visible allocations live. Run it once per census. It must not run when the gate is off.
3. **Vulkan device memory**, per memory type and heap, as the driver allocated it:
   - wrap or tally at the existing `vkAllocateMemory` and `vkFreeMemory` call sites, or use the allocator the driver already has, by owner tag where the call site knows it:
     - buffer pool and slabs;
     - heap mirrors and image mirrors;
     - sampled textures;
     - storage images;
     - staging, upload and readback chunks;
     - recorder and command memory;
     - descriptor heaps and descriptor buffers;
     - host imports, which pin guest pages and add no commit; report their count and bytes separately;
     - other;
   - plus `VK_EXT_memory_budget`'s budget and usage per heap.
   - **Say which tags are host-visible:** on Windows/NVIDIA those count in process private.
4. **CPU-side caches and buffers in the emulator's heap**, each as bytes held:
   - the draw cache (`drawCacheVariantBytes` and the entries' own structures);
   - the dispatch cache;
   - the resource and table caches (`[rescache]` entries);
   - the template, recipe and relocation caches;
   - the pipeline journal and pipelines;
   - shader modules and SPIR-V kept in memory;
   - resource plans;
   - the recorder's fault and snapshot buffers;
   - `[buffers]` snapshots and CPU-copy buffers;
   - bufferpool retained;
   - the log queue.
   Use the counters that already exist. Where none exists, add a byte counter at insert and erase, without walking a cache.
5. **The allocator:**
   - Windows builds use mimalloc: `mi_process_info`'s current commit and peak, and `mi_stats` if cheap.
   - Linux uses glibc: `mallinfo2`'s `arena`, `hblkhd` and `uordblks`.
   - That lets "other private" be split into heap and non-heap.
6. **A remainder line:** process private minus the named sums, so we see what's still unattributed.

**Pipelines inside the driver** can't be counted from our side. Report the number of pipelines, pipeline libraries and shader modules alive. Name what `APS5_NO_GPL=1` changes, so a pair can measure it.
