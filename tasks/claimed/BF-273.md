# BF-273: BDA stores into writable heap mirrors (Ghost of Tsushima, PPSA02225): a write-back that keeps them, with red/green and cost

from: Bug Finder
for: any
priority: high

## Why

sktharunbalaji13-cmd's Ghost of Tsushima Director's Cut (PPSA02225) run (I#5166, comment 6492874290) stops a compute store with:
```
[gpu] deferred write-back failed: BDA access failed: address=0x1579d4e49e instruction=0x1284 bytes=1 stage=4 reason=2; the store hit 0x150c000000+0x8c600000, read-only in the BDA table: stores through GPU-selected descriptors and FLAT/GLOBAL addresses reach only writable ranges imported in place, not ones served by a mirror or a copy
```
The store targets a sparse heap mirror: 36 MiB backed across 16 runs.

**Their proposal is unsafe.** It grants `BdaAbi::Write` in `GuestBufferMemory::addressRange` (GuestBufferMemory.cpp ~L5968 on main) to writable mirrors too, not only to `region.direct`. But:
- `GuestBufferMemory::WriteBack` (~L6261) stores only `mergeWrites(writes)`: the declared write ranges, each diffed against the `heapReferences` captured for it.
- A BDA store elsewhere in the mirror would never reach guest memory, and the next refresh could replace it with guest bytes. That's silent data loss.
- Main's refusal is deliberate, as the message text says.

## Do

1. **Confirm the loss:** with only their one-line change, write a red test.
   - **Setup:** a shader store through a FLAT/GLOBAL (or GPU-selected V#) address into a writable heap mirror, outside any declared write range.
   - **Expected:** after `WriteBack`, guest memory doesn't hold the stored bytes, and/or a refresh reverts the mirror. Use the existing BDA and mirror fixtures in `tests/BdaResources.cpp` and `tests/execution/*`.
2. **Design the correct form:** when a program can store through BDA (it uses FLAT/GLOBAL stores, or V#s computed on the GPU) and its table includes writable heap mirror spans:
   - add those spans to the write-back set, with `heapReferences` captured for them at upload, so `WriteBack` diffs them and stores only the changed bytes (`storeChanged`/`storeSparse`);
   - mark them in the BDA table as `Write`;
   - keep the current refusal for everything else: copies, read-only mirrors, and ranges past `servedEnd`.
   - Say how sparse mirrors and unresident runs behave.
3. **Cost:** measure the extra reference capture and diff per dispatch for a 36 MiB, 16-run sparse mirror on lavapipe. Also give the time per MiB and the number of dispatches it would apply to. If the cost is large, propose the narrowest scope, e.g. only the runs the program's BDA table actually reaches.
4. **Branch:** fork `fix/agc-bda-store-writable-mirror`, the fix and its test in one commit on `upstream/main`.
   - **Red:** main refuses (the existing message) and the one-liner loses the bytes.
   - **Green:** the bytes reach guest memory and survive a refresh.
   - **Controls:**
     - a read-only mirror still refuses;
     - a CPU store elsewhere in the mirror during the dispatch survives the write-back (the diff keeps it);
     - a declared write range behaves as before.
