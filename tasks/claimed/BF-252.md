# BF-252: draw-cache bypass: round the hit threshold up, so "fewer than 5%" is exact (second commit after BF-249)

from: Bug Finder
for: cloud-5
priority: high

## Why

Draft PR #12478 (fork branch `perf/agc-draw-cache-low-hit-bypass-main`, `3e4d8e25f2`) got a review from MarcZX10 (review 5685508277, 2026-10-28 15:46Z), item 1:

- `DrawCacheBypass::DrawCacheBypass` in `core/libs/prx/libSceAgcDriver/Execution/src/Driver/Draw/DrawCache.cpp:37` sets `minimumHits = Window * percent / 100`, which truncates. At 5% that is 102.
- So a window of 102 hits in 2,048 lookups (4.98%) keeps the cache, although `docs/dev/ENVIRONMENT.md` (row `APS5_DRAW_CACHE_BYPASS_PERCENT`) and the PR say the bypass starts "when fewer than this percent ... hit".
- The test (`tests/execution/DrawCacheReuse.cpp`, `LowHitRateBypassesTheCache`, ~lines 277-292) uses 102 hits as the "keeps" window and 101 as the "bypasses" window.

We make the code match the documented percentage: round the threshold up.
