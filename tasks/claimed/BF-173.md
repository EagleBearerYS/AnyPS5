# BF-173: bound BF-171's unwatched depth-plane compare: always before a store or retire, at most once per present on binds
from: Bug Finder (2026-10-23 00:4x PT)
for: any
priority: normal

## Why

BF-171 (`results/cloud-2/BF-171.md`, fork `fix/agc-depth-plane-unwatched-writes` **1a4f9e022**) fixes lost CPU writes to a depth plane after its store. It does this by comparing unwatched planes with the mirror's `original`. The result's red/green is clean, but its cost on Linux is open:

- **Linux has no untracked hint,** so the `comparedRanges` memo lasts one collect epoch.
- **Every new epoch re-compares a stored, bound plane in full:** 0.9–1.2 ms for 1920x1080 D32 on the worker, against ~1 µs per bind on main.
- **Depth planes are stored whenever one is sampled as a texture** (`FlushDepthPlanes` from `ShaderResources.cpp` ~1140 on main), which many titles do every frame (SSAO, DOF). Epochs move per packet and wait. So this could add several ms per frame on Linux.

The PM's call (in the user's name):
- Build a bounded variant as a second commit, on its own branch, so the first commit stays measurable alone.
- The PC then measures all three arms (main, BF-171, BF-171 + this) on a frame stream.

## What to do

1. **The bound,** in BF-171's `DepthSurface::WrittenUnits` / `OverwrittenInMemory` path (`DepthSurface.cpp` ~852, ~589 on 1a4f9e022):
   - **Before a store or retire,** always compare. That covers `FlushDepthPlanes`'s store of stale units, `retireStoringStale`, and `OverwrittenInMemory` as the gate into it. This is what keeps a later store from writing the GPU plane over the guest's bytes, so it must not be bounded.
   - **On the bind path** (`SyncFromMemory` per bind, ~2006 on main), compare an unwatched plane **at most once per present**. Between presents, an unwatched plane reads as unwritten on that path, as on main.
   - **Keep both rules in the same comparison and memo.** A compare made for a store also counts as this present's bind compare.
   - **The present serial:**
     - use one that always advances, whatever the trace settings. `PerformanceTrace::presentCount` is private, and may advance only while tracing; check it;
     - if there's none, add a relaxed `std::atomic<std::uint64_t>` bumped once per present in `VulkanDevice`'s present path, and say where;
     - a test harness that never presents must still get the store/retire compare.
   - Change nothing else in BF-171's commit.
2. **The tests,** in `DepthPlaneBufferMemory.cpp`, the same file and registration style as BF-171's `agc_driver_depth_plane_unwatched_*`:
   - **(a) changes:** CPU write, then **a present** (or whatever advances the serial in the test), then the draw. It must still see 0.125, red with only the bound commit's fix hunks and BF-171's both reverted, as before.
   - **(a2) new, a same-frame write caught at the store:** CPU write, then a draw in the same present (the bind may miss it), then `FlushDepthPlanes`. Memory must hold the CPU's 0.125 in the written unit, not the GPU's value.
     - **Red:** with BF-171's fix reverted.
     - **Green:** with this commit.
     - It must also fail with the bound applied to the store path too (say how you showed that).
   - **(b), (b2), (c) and (d):** unchanged and still green.
   - **(e) new, the bind bound:**
     1. a store;
     2. N binds with no present in between and no CPU write, then one present, then N more;
     3. the plane must be compared exactly once per present on the bind path. Report the counter.
3. **Cost,** the same `--bind-cost` harness as BF-171, 1920x1080. Report, for main, BF-171 and this head:
   - binds within one epoch;
   - a new epoch per bind, with no present;
   - a new epoch per bind with a present every 16 binds.

   This head's "new epoch per bind" row should drop to about main's cost, except on the bind after a present.
