# PM-003: performance overlay (on-screen FPS, frame time, GPU and driver time)
from: AnyPS5 Project Manager
for: any
priority: high

A user-visible feature for an upstream PR. Build it to the project's own standard: read CONTRIBUTING.md and docs/dev/CONVENTIONS.md first, and follow them exactly.

## What to build
An optional on-screen performance overlay, drawn into the presented image after the game's frame:
- FPS: presents per second, averaged over the last 1 s.
- Frame time: the last frame in ms, plus a small graph of the last ~120 frames.
- When the data exists, GPU time per frame (from the existing APS5_PROFILE_GPU timestamp queries) and driver CPU time per frame (the packet worker's busy time, from the counters behind APS5_PROFILE_DRAW's [draw] line). Each line is shown only when its source is enabled.
- Off by default, with no cost when off (no extra pass, no per-frame work).
- Enabled with ANYPS5_OVERLAY=1, and toggled at runtime with F10 (F11 is fullscreen; check core/libs/prx/libScePad/include/InputMapping.hpp for free keys).
- A corner position (ANYPS5_OVERLAY_POS=tl|tr|bl|br, default tl), readable at 720p through 4K, scaling with the swapchain height.

## Where
Read upstream's presentation path: core/libs/prx/libSceAgcDriver/Execution/src/PresentationPass.cpp, PresentationScaler.cpp, Graphics/shaders/PresentationPass.frag, and core/libs/prx/libSceVideoOut/src/Output.cpp and VideoOutDriver.cpp.
- The merged HDR10 PRs #5696 and #5697 are a good model of a clean presentation feature: detection, defaults, tests and docs. Read their diffs.
- The overlay must work for both the SDR and the HDR10 swapchain. On HDR10, draw it at a modest, fixed brightness.

## Rules for the code
- Don't add a third-party library for this. Draw text with a small bitmap font you write yourself (digits, the letters the labels need, "." ":" "/"), as glyph data in the source, plus solid rectangles for the background and the graph.
- No comments in code, except technical-debt entries per CONVENTIONS.md.
- Keep the work off the game's critical path. Gather the numbers cheaply (atomics or per-frame snapshots) and draw in the presentation pass.

## Tests (required)
- Unit tests for the statistics: the FPS window, the frame-time ring buffer, and the min/avg/max of the graph.
- A Vulkan test (lavapipe in CI) that renders the overlay into an offscreen image of a known color, then checks that pixels change only inside the overlay rectangle and that the digits of a known FPS value render the expected glyph bits.
- A test that with the overlay disabled the presented image is bit-identical to today's.
- Register the tests the way the project does (tools/check_test_registration.py must pass).
