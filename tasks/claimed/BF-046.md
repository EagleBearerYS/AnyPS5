# BF-046: per-draw CPU and GPU cost of a GPU-side binding path against today's, on a Village-shaped harness (a redesign spike)
from: Bug Finder
for: any
priority: high

## Why

The user asked how possible a real architectural redesign of the AGC driver is. The draft is `pr-drafts/arch/redesign.md`, which the PM holds. Its premise: keep guest memory and images resident on the GPU and let shaders read V#, T# and S# at run time, so the CPU's per-draw work is a fixed, small list.

**Today:**
- Resident Evil Village's menu pays **1.8 ms of driver CPU per draw** on the RTX 3070 PC. ~988 µs of that is `Graphics::Draw` under the GPU mutex; ~460 µs is capture, recompile and vectors.
- Village's draws index bindless T# tables: ~5,800 image-table keys per draw.

**fable-void's prior art:** his branch `wip/new-gpu-path` (ed8f2d7a2e) does this, and reached **~360 µs per draw** on his title's menu (702 → 359 µs, 5d57298425). That's still under the mutex, with per-draw descriptor sets, target refreshes and guest-memory pre-scans.

**The design needs ≤~50–80 µs per draw.** This task measures, on one harness:
- what today's path costs per draw;
- what his path costs;
- what the floor is.

It also measures the GPU cost per draw of reading T#s in the shader through a device image table, on lavapipe. Those are relative numbers; the PC measures the absolute ones later.

## The harness

Start from the per-draw harnesses on the fork:
- **`exp/bf042-base` (9ac6d7dc8c):** `core/libs/prx/libSceAgcDriver/tests/execution/DrawRecordCost.cpp` measures queue-0 draw cost per thread and per lock holder. It has rotating object sets and per-object data in user SGPRs. Read its mode notes in `results/cloud-3/BF-042.md`: the vertex table goes through `s[8:9]`.
- **`exp/table-o1-validation` (be6fa03d8):** `tests/execution/DescriptorHeapCeiling.cpp`, BF-037's image-table harness, with N table textures.

**Village's menu shape, as close as the harness allows:**
- ~850 draws per frame;
- each pixel shader samples 1–4 textures picked per draw from a **2,000-entry T# table** reached through a pointer in user SGPRs;
- per-object constant V#s in user SGPRs 4–7, rotating every frame (BF-042's shape);
- about 90% small quads and 10% full-target draws at 1920×1080.

Report the frame shape you actually used.

- **K4:** arm B's GPU µs per draw is more than 30% above arm A's, or arm B's CPU per draw stays above ~80 µs.

Say which hold. Then say where arm B's remaining CPU per draw goes, by phase: descriptor sets, target refresh, the pre-pass over guest words (`EvaluateBufferSites`, `ExpectedDeviceImages`), the index scan, recording.
