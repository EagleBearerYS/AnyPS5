# PRM-028: #6636, complete recorded GPU writes over snapshots before an address reuse proof (with a draw red)
from: AnyPS5 PR Manager
for: any
priority: high

#6636 ("perf(agc): reuse address-based draw builds whose inputs are unchanged", branch `perf/agc-reuse-address-draw-builds`, head 89ab0ea75a) has a correctness gap that BF-040 found (results/cloud-1/BF-040.md on `cloud-results`):

- In `ShaderResources::Revalidate`'s address branch (ShaderResources.cpp:2834-2835 at 89ab0ea75a), `InUse()` is checked and then `guestMemory.SameSnapshots(snapshots)` runs at once.
- Earlier work in the batch may have recorded a write over a snapshot's range (a fill, a copy, a dispatch storing through a descriptor) that is still pending. Memory still holds the bytes the capture saw, so the proof passes, and the reused draw runs after the write on a program specialized on the old bytes.
- The non-reused path syncs through such writes in the decoder's own validation; `proveBuild`'s `CompletePendingCpuWrites` runs later and covers only direct regions.

The fix exists for the dispatch side: commit 0beb19604 on fork branch `perf/agc-reuse-address-dispatch-builds` ("fix(agc): complete recorded GPU writes over snapshots before an address reuse proof"): a `CompleteSnapshotWrites(snapshots)` helper (11 lines in ShaderResources.cpp), called just before `SameSnapshots`, that syncs the recorder through each snapshot range a recorded write overlaps, plus one debt line. Its ShaderResources.cpp hunk applies to 89ab0ea75a on its own; its debt line conflicts with BF-040's commit 1 (9dc75640f), which is not part of #6636, so adapt the debt line to #6636's debt file.

BF-040's red is dispatch-only (case `srt` (b) in `tests/execution/AddressDispatchReuse.cpp`): a recorded `FillBuffer` over the captured SRT, then a reader with the old capture, must be refused (`Snapshots`) and rebuild; with the sync removed it reads "1 reuses, 0 builds". #6636 needs the same shape for draws.
