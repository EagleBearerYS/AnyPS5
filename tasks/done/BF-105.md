# BF-105: why every address-based draw reuse proof at Resident Evil Village's menu is refused for snapshots: a refusal-reason line for one PC boot
from: Bug Finder
for: any
priority: high

## Why

#6636 (ours, "reuse address-based draw builds", head fc9c5416fc as booted; now 7cef9bcf8f) makes an address-based draw reuse the build of an earlier draw with the same content key while `ShaderResources::Revalidate`'s proofs hold. The PC booted it at Resident Evil Village (PPSA01556)'s static menu.
- **The run:** q6636p, tree = main 1ff5c8ac5c + #8926's fix + #6636 fc9c5416fc, with `APS5_NO_GPL=1 APS5_HOST_IMPORT_MIB=6400 APS5_PROFILE_DRAW=1`, lazy preparation, 6 minutes.
- **The result:** 0 reuses in 17,613 proofs.
- **A typical 10 s line:** `[rescache] address-based draws: 75 proofs, 0 reused; refused: in use 887, not reusable 0, snapshots 75, space 0 (...), images or buffers 0, imports 0, threw 0, moved buffers 0`.
- **Snapshots** refuse every proof that runs. **In use** (a repeat of the draw before the previous one's completion ran) refuses ~10 lookups for each proof.
- **The cost:** the same run's `[address]` line gives ~2,000 address-based builds per 10 s at `snapshots 214–286` µs per build, the largest phase of a build.

The refusal is `if (!guestMemory.SameSnapshots(snapshots)) return refuse(AddressReuse::Snapshots);` (`Graphics/src/ShaderResources.cpp`, in `Revalidate`). `GuestBufferMemory::SameSnapshots` (`Graphics/src/GuestBufferMemory.cpp`) returns false for any of:
1. a different snapshot count;
2. a snapshot's address or size differs from the build's `snapshotUses`;
3. a live snapshot whose bytes differ from guest memory now;
4. a copied snapshot whose region bytes differ.
5. It also fails when the region lookup itself fails.

The log can't tell these apart. Which one it is decides the next step:
- **Constants rewritten each frame with new values:** address reuse can't help this menu, and we look at the snapshot cost itself.
- **Addresses moving through a ring of per-frame buffers:** perhaps the proof could compare by content.
- **A count or size change from the capture:** a capture bug.

4. **Without `APS5_PROFILE_DRAW`**, the cost is one cached flag test.
5. **Test it on Linux:** a case where a reused draw's snapshot bytes change prints the bytes reason with the right offset, and one where the address changes prints the address reason. Extend #6636's `agc_driver_address_draw_reuse`, or add a mode beside it. Run #6636's reuse tests and `^agc` once.
