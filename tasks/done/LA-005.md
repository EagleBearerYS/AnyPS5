# LA-005: lane A, mesh and task stages on the device image table, plus two harness cases
from: AnyPS5 lane A (PC session)
for: any
priority: normal

## Why

Lane A's first piece reads image tables at run time through a device key table on PR 6947's heap. Its halves are on fork branches `exp/lane-a-recompiler` (385babcbf9, `results/cloud-5/LA-002.md`) and `exp/lane-a-driver` (a500d67c8, `results/cloud-4/LA-003.md`). LA-004 is joining them on `exp/lane-a-join` and limiting device columns to vertex, pixel and compute stages, because PR 6947's heap set and our set 3 have stage flags VS | FS | CS.

**The Bug Finder's count** over Resident Evil Village's 12,252 cached modules:
- 2,052 programs use image tables: 1,108 fragment, 472 vertex and 472 mesh;
- 28% of the mesh programs read tables, with a median of 2 and up to 10 twelve-way switches;
- about half of Village's CPU-path draws are mesh draws (its non-vertex path).

A mesh draw whose mesh stage has a table keeps today's CPU snapshot for that stage, so it gains less than the draws whose stages are all on the path. This task brings mesh and task stages onto the device path.

## What to do

1. **Stage flags.**
   - **Where:** set 3's layout (LA-003's code) and PR 6947's heap set layout (`BindlessHeap`'s constructor, `heapStages`).
   - **Change:** include `VK_SHADER_STAGE_MESH_BIT_EXT` and `VK_SHADER_STAGE_TASK_BIT_EXT` when the device has `VK_EXT_mesh_shader` enabled, or the flags main's mesh pipelines use (see `VulkanDevice` and the mesh pipeline code). Leave everything else in the heap set unchanged.
   - **Credit:** say in the commit body that it widens Raghav314's heap set from upstream PR 6947.
   - **Check:** the stage flags of every pipeline layout built from the heap set, with and without pipeline libraries, plus the pipeline journal's description of them.
2. **Tracker.** Let device columns qualify in mesh and task stages too, under the same rules, and keep tessellation and geometry stages on the CPU path. LA-004 writes the VS/FS/CS limit; extend that same condition.
3. **Binding.** Make sure a mesh pipeline whose mesh or task stage has `deviceImageTables` gets sets 2 and 3 in its layout and binds them at draw time.
4. **Tests,** on lavapipe (it has `VK_EXT_mesh_shader`; if not, say so, and test what you can):
   - (a) a mesh program that reads a T# from a 2,000-entry V# table and samples it: the first draw reads zeros and records the misses, and the second gives the CPU path's texels with no table snapshot;
   - (b) a tessellation or geometry stage's column stays on the CPU path;
   - (c) **a CPU write to a T# record between two draws**, in the same collect epoch and in the next one. The draw after the write samples the new texture once its key has been inserted, and never the old one. This checks that the table's V# buffer binding isn't reused stale.
   - (d) **CPU writes to the table buffer's memory between draws while PR 6947's space reuse is active** (`APS5_GPU_HEAP=1 APS5_DRAW_PIPELINE=1`) on a program that reads its table through a read-only address-based space. Each draw must see the current words. The Bug Finder suggested it as the other live suspect behind the Hades II report on PR 6947. If it fails, it's a real bug in PR 6947's space reuse: write it up in the result with the failing assertion, and don't fix it in this branch.
5. **Measure:** words and `vkCreateGraphicsPipelines` time for (a)'s mesh program, with the option off and on.
6. **The CI Linux mirror** on your head, switch unset (CI's flags, `check_test_registration.py`, the ctest command as an unprivileged user, `check_skips.py`), against the base's failures. Then the `^(agc|shader|recompiler)` scope with `APS5_GPU_PATH=1`.
