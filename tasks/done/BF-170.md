## Why

The user wants a detailed debugging page added to the performance overlay, our merged upstream PR 6012. In their words: "as comprehensive as needed. Esp if its a second f10 press and we can minimize any performance impact".

- **The cycle:** F10 goes off → today's overlay (page 1) → the detailed page (page 2) → off.
- **The variable:** `ANYPS5_OVERLAY=2` starts on page 2. `1` stays as today, `0` or unset is off, and any other value throws, as now.
- **Page 1 is unchanged,** line for line.

This becomes one upstream feature PR. The PC adds screenshots of both pages from a real title and a cost pair (Village or Planet of Lana, off vs page 2). Your part is the code, the tests and the Linux checks.

## What exists (read these first)

- **`core/libs/prx/libSceAgcDriver/Execution/include/PerformanceOverlay.hpp` and `src/PerformanceOverlay.cpp`:**
  - `ParseOverlaySettings` is at ~107.
  - `Visible()` is `settings().visible != (toggleCount & 1)`. `Toggle()` bumps `toggleCount`.
  - `restartIfToggled()` resets the statistics on every toggle.
  - `NotePresent()` samples VRAM and RAM once a second (`OverlaySampleDue`), and `PacketCounters::Sum()` on every present.
  - `ComposeOverlay()` builds the lines, and `LayOutOverlay()` places them.
  - **The panel is fixed at `OverlayMetrics::Columns = 27`.** `LayOutOverlay` throws on a longer line.
  - **The 5×7 font has only** digits, space, `. : /` and the letters A-I, K-P, R-X. No J, Q, Y, Z, `%`, `-`, `+`, `(`, `)` or `>`. `OverlayGlyph` throws on any other character.
- **Where it's called:** `VulkanDevice.cpp` ~3359 (`PerformanceOverlay::Visible()`) and ~3491 (`NotePresent`, then `Record`). F10 comes through `libSceVideoOut/src/PadInput.cpp` ~239, which calls `AgcDriverTogglePerformanceOverlay_nid_postfix()`.
- **Counters that already exist,** for you to reuse rather than duplicate (check each one):
  - **The trace:** `PerformanceTrace.hpp`, `TraceThread`. `Add()` always calls `account()`, the per-(scope, stage) totals table, and buffers slices only while `buffering` is set. `Collect()` returns the totals. The summary's `top_phases_ms_per_frame` and `worker_busy_pct` come from these. `PerformanceTimer` (`PerformanceTimer.hpp` ~261) feeds the trace only while `PerformanceTrace::Recording()`, which is configured once from `APS5_TRACE_FRAMES` / `APS5_TRACE_SECONDS` (~735).
  - **Queue waits:** `GpuMutex.wait` per lock site (`GuestMemory.cpp` ~2200 and ~2220), and the `Submission` stages in `QueueWorker.cpp` ~36-46 (`order_wait`, `flip_room_wait` and the rest).
  - **The draw cache:** `Driver::DrawCacheCounters()` (`DrawCacheStatistics.cpp`) returns a snapshot of `drawEntryCounters` (lookups, hits and the rest) under `drawCacheMutex`.
  - **Pipelines:** `PerformanceCounters::CountPipeline()`/`Pipelines()`.
  - **`ReadVramBudget` and `ReadProcessPrivateBytes`.**

## What to do

### 1. The page cycle

- **`OverlaySettings`:** replace `visible` with a starting page, 0, 1 or 2. `ParseOverlaySettings("2", ...)` gives page 2, and the error message lists 0, 1 and 2.
- **The current page:** F10 cycles through the three states (`toggleCount % 3`, offset by the starting page). `Visible()` stays true for pages 1 and 2. Add `Page()`.
- **Each change of page resets the statistics,** as a toggle does now.
- **Nothing else outside the overlay changes,** except where a counter needs it.

### 2. The detailed page

Give it its own composer, for example `ComposeOverlayDetails(const OverlayDetailSample&)`. Make it a pure function of one sampled struct, so tests can feed it values. It needs a wider panel:
- move the column count into the content (page 1 keeps 27), and derive `panelWidth`, `fits` and `OverlayScale` from it;
- or use two columns.

Either way it must fit at 1280×720 at scale 1, and the existing fit loop must still shrink the scale at 4K.

**Add the glyphs the page needs** (at least `% - + J Q Y Z`), and a test that every character the composers can emit has one.

**Lines.** Start from this list and add anything cheap and useful you find on the way. Every line names its unit. A source that isn't available in a run (Windows-only counters on Linux, a disabled path) leaves its line out rather than showing 0.

1. **Busy % per packet worker and per queue,** over the last second.
2. **The top driver phases** in ms per frame, the same names as the summary's `top_phases_ms_per_frame` (top 4 or 5).
3. **Queue-0 wait per frame,** split by memory, lock and GPU.
4. **Render passes per frame.**
5. **Pipelines compiling now** (the async backlog), and pipelines created in the last second.
6. **Hit rates per second** for the draw cache and the shader/pipeline cache.
7. **Guest flips/s against presents/s,** with dropped frames (flips never presented) and repeated ones (presents of an image already shown).
8. **Memory:**
   - **Windows:** the commit charge against the commit limit, from `GetPerformanceInfo`;
   - **Linux:** `Committed_AS` against `CommitLimit`, from `/proc/meminfo`;
   - **both:** page faults per second (`PageFaultCount`; `getrusage` on Linux).
9. **Host imports** (count and bytes) against their budget.
10. **CPU copies:** MB/s, and how much of the address-copy cap is in use.
11. **Unimplemented-function calls** (count, last second and total) **and refused shaders.**
12. **Title ID and present mode.** The upscaler mode belongs here too, but only if our upstream PR 10043 has merged into main by then. If not, leave it out and say so in the result.

### 3. Cost: zero while hidden or on page 1

- **No new work on any hot path while the overlay is hidden or on page 1.** Lines 1-3 should come from the trace's totals:
  - while page 2 shows, turn on recording with buffering off, so only `account()` runs;
  - read `Collect()` once a second;
  - turn recording off when the page changes;
  - an explicit `APS5_TRACE_*` run must behave exactly as today.
  If `Recording()` can't be switched at run time without a cost when it's off, say so and propose the cheapest way that keeps "zero when hidden".
- **A counter that has to be new on a hot path** follows the `PacketCounters` pattern: a per-thread relaxed load and store, no read-modify-write, folded once a second by the overlay. Give the reason for each one in the result.
- **OS counters** are read once a second, in `NotePresent`'s sample.
- **No GPU queries** unless `APS5_PROFILE_GPU` is already on. Gate GPU-time lines on `PerformanceCounters::GpuEnabled()`.
- **The page's composing** runs only on presents while page 2 shows.
