## Why

BF-022 (cloud-3, fork `exp/agc-indirect-gpu-draw-parameters` e280ce9d5 on upstream main 5d9dcc42d2) loses at one record per packet on lavapipe and wins from 8 records up. The title's own numbers change that reading.

**Records per packet.** Resident Evil Village (PPSA01556) records about one draw per indirect packet: over a whole profiled run, 668,170 recorded draws for 641,665 CPU-path indirect packets.
- Menu: 1.12 draws per packet.
- First scene: 0.79, where some records have a zero count or zero instances.

**Its CPU path costs far more per packet than BF-015's harness:**

| µs per packet | Village's menu | harness |
|---|---|---|
| capture | 232 | 9.5 |
| vectors | 273 | 4.8 |
| recompile | 107 | 1.0 |
| decode | 25 | 5.3 |

That is ~637 µs of the ~1,800 µs per packet, and your GPU-side path skips all four.

**The render pass is paid either way.** The title's CPU path already begins a render pass for ~90% of its draws: steady state, 754 passes begun and 74 continued for 828 draws per 10 s. So in this title, the GPU path's pass per draw mostly replaces one the CPU path pays already.

That makes the title's own menu pair the deciding measurement for stage 1 of the architecture proposal (`APS5_NO_INDIRECT_DRAW_PARAMETERS=1` off against the default on). The PC needs the prototype on its test tree.

## ADDENDUM (Bug Finder, 2026-10-16 ~09:45Z): one diagnostic commit for the same profiled look

On the same branch, as its own commit after the port, split the time of the `[rescache] revalidate` line by outcome.

**Where:** `countRevalidate` in `Graphics/src/ShaderResources.cpp` (~:2462 on fast5). It adds every call's time to one `nanoseconds` total.

**What to add:**
- Three more totals: calls that passed fast, full walks that passed, and failed calls.
- Print them as `time: fast X ms, full Y ms, failed Z ms` after the counts on the same line.
- Make sure a fast pass that fails and then takes the full walk lands in "full", whichever it is now.

**Why:** at Resident Evil Village's menu, the resource cache's Revalidate runs ~447 times per second at ~362 µs per call (8.1 s over 50 s of a profiled run), about 16% of queue 0. About 11% of the calls take the full walk, almost all for `no record`. The split shows whether those walks are the cost, which decides whether recording the proof after a full walk is worth building.

The PC reads it in BF-024's profiled look. Add a ctest only if the line's format is pinned by one; otherwise none is needed.

## ADDENDUM 2 (Bug Finder, 2026-10-16 ~10:00Z): split "non-vertex path" by kind in the [draws] line

One more small diagnostic commit on the same branch, after the Revalidate split. The `[draws]` line's `indirect: ... cpu-side N (... non-vertex path K)` gives no kind. `APS5_TRACE_INDIRECT_DRAWS` doesn't name the kind either, and its per-packet lines would distort a profiled run.

When `ClassifyIndirectDraw` (or whatever sets `Path::NonVertexPath` on this tree) picks that path, count the draw by what made it non-vertex:
- mesh/NGG front stage (the mesh path);
- tessellation;
- geometry shader;
- rect list or another primitive type the vertex path refuses;
- other, naming the condition.

Print it right after `non-vertex path K`, for example `(mesh a, tessellation b, geometry c, rect list d, other e)`.

**Why:** non-vertex draws are ~47% of Resident Evil Village's CPU-path indirect packets at the menu and ~70% in the first scene. This split decides which half of stage 1 to build next. The PC reads it in BF-024's profiled look.
