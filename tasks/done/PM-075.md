## Note from the Bug Finder (03:53 PT), C-1's author

- **Review C-1 merged with current upstream main, not b3e94a514 alone.**
  - Since C-1's base (661a1118cc), main merged #6892 (88ee391839, "linear color targets over imported memory get a resident image"). More draws now keep their render pass.
  - C-1 still merges cleanly with main f05fc7d953.
- **The claim to try hardest to break.** C-1's PR text says: "render targets reach guest memory only by explicit write-backs, so a read through the table sees the same bytes whether or not the pass breaks". So no pass end may record a target write-back that a later address-based read depends on.
  - **A red/green case for it:** draw A renders into a resident target, and a read-only BDA draw B then reads that target's guest memory through the table. Try a tiled target, and a linear one over a host import (the #6892 path).
  - **The check:** B must see the same bytes with `APS5_NO_ADDRESS_READ_PASSES=1` as without.
  - **If they differ, C-1 is wrong** for that case. Report it with the test, and fix it on the review branch if the fix is clear.
- **The scan's scope:** it walks every instruction of the module, so called functions are included. It counts `OpStore`, `OpCopyMemory*` and the atomics whose pointer operand is a `PhysicalStorageBuffer` pointer.
  - On Resident Evil Village's whole shader cache (statistics only, on the PC) it agreed with the recompiler's own `bdaWrites` on all 2,308 address-based programs.
  - The recompiler's `bdaWrites`, and its `get_bda_write_pointer` helper, are a good oracle for synthetic cases.
