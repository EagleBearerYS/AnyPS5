# BF-151: initial multisampled DCC import over a compared host import (Linux comparison mode, #9724 case 2)
from: Bug Finder
for: any
priority: high

## Why

Rush 2 Recompiled (PPSA69423) and Wave Race 64 Recompiled (PPSA69424) stop with `AGC graphics: initial multisampled DCC contents require watched guest memory` (https://github.com/boykopovar/AnyPS5/issues/9724):
- **Windows:** within 10 s.
- **Linux with lavapipe:** babyhuey saw it on `main` 8b3a6ba88, Mesa 25.2.8 llvmpipe, at 6.4 s and 1.5 s (https://github.com/boykopovar/AnyPS5/issues/9724#issuecomment-6340976890).

**The two platforms take different paths to the same refusal.** On Windows it's the deferred settle under 1 MiB; BF-150 covers that, stacked on #8527. Linux has no deferred settle:
- **The probe** (`decideImportWatch`, `core/libs/prx/libSceAgcDriver/Graphics/src/GuestBufferMemory.cpp:1148`) decides at device setup whether host imports are watched or compared.
- **On lavapipe** device accesses are CPU stores, which trip the write watch, so it logs `[write-watch] host imports resolve write protection: yes` (`:1189`) and every imported range is compared.
- **The refusal:** `initialDccClear` (`Graphics/src/MultisampleTarget.cpp:477-512`) then refuses at `:497`. It needs a write generation from `collectBlocks` for each of the color, DCC and CMASK ranges, used by `UnchangedSinceAll`, `absorbDccFill` and `checkDccCurrent`.

**MarcZX10** (https://github.com/boykopovar/AnyPS5/issues/9724#issuecomment-6345204139) wants:
- the reproductions kept split by the write-watch result;
- a regression matrix with (1) a Windows watched import with a pending settle (BF-150) and (2) a Linux comparison-mode import (this task);
- the explicitly unwatched negative case kept.
