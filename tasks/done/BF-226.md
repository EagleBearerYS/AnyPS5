## What
Our open PRs #10879 (`feat/npmanager-idmapper-requests`, head 5997af6c13) and #10890 (`feat/npmanager-int-getters`, head bad1a7994d) are stacked: #10890 contains #10879. They gave IdMapper and NpManagerInt calls answers modelled on their public twins.

BunnyFl has since measured firmware 13.42 `libSceNpManager.sprx`, running each call in an emulator on the module itself up to the point where it hands off to the NP service. That contradicts parts of both PRs. Quoted below because upstream pages give you 403:

- the result after the hand-off (the signed-out answer itself);

That's the stricter source rule from #10900's review: no answer modelled on a twin.

### Commit 1, for #10879
- **Branch:** `fix/npmanager-idmapper-measured` on the fork: one commit on 5997af6c13. Don't push to the PR's branch; the PR Manager does that.
- **`sceNpIdMapperNpIdToAccountId` and `sceNpIdMapperOnlineIdToAccountId`:** both take 7 arguments: request ID, user ID, an input pointer, an output pointer, a 32-bit value, a byte and a 7th argument.
  - A request ID of 0 or less gives `0x80553085`.
  - After that, user ID -1, a null input or output pointer, or the 32-bit value outside 1..1000 gives `0x80553083`.
  - The byte and the 7th argument aren't checked.
  - There's no init or signed-in check before these.
  - Past the checks the request goes to the NP service, so it throws.
- **IdMapper requests are created on the NP service** (`np::ipc::service_client::CreateRequest`). Abort goes to `sceNpAsmClientAbortRequest`, then the service's abort. Delete goes to `sceNpAsmClientAbortRequest`, `sceNpAsmClientDeleteRequest`, then the service's delete.
  - `sceNpIdMapperAbortRequest` and `sceNpIdMapperDeleteRequest` refuse a request ID of 0 or less with `0x80553085` before anything else; past that they throw.
  - `sceNpIdMapperCreateRequest` has no measured in-library check, so it throws.
- **NpManagerInt requests sit in a table of their own inside libSceNpManager.** `sceNpCreateRequest`/`Delete`/`Abort` use a third table.
  - `sceNpManagerIntCreateRequest`, `AbortRequest` and `DeleteRequest` have no argument checks.
  - Abort leaves the request live, and only delete frees it.
  - **Default:** the comment gives neither the IDs Create returns nor the answer for an unknown or deleted ID, so all three throw.
  - **Exception:** if the PR Manager tells you before you build to keep a table of their own with the numbering recorded as unmeasured, do that instead. The PR Manager knows this default.
- **Tests (`guest_np_manager`, `core/libs/tests/GuestNpManager.cpp`):**
  - **Remove** the tests that require IdMapper or NpManagerInt IDs to come from the `sceNpCreateRequest` pool (`shared > second`), and any test of an answer that is now a throw.
  - **Add one case per measured refusal**, each with only that one fault. For the lookups, also show the order: a request ID ≤ 0 together with a null pointer gives `0x80553085`.
  - **Refused calls write nothing:** fill the output with a canary and check it survives.
  - **Past the checks:** show that the call throws NotImplemented, and that IdMapper Abort and Delete do too after a valid ID.
- **Error names:** use the tree's names for `0x80553083`/`0x80553085` if they exist, otherwise add them where the library's other NP error constants live.
- **Debt (`docs/dev/debt/libSceNpManager.md`):** rewrite this PR's entries to say what is measured and what still throws. Credit it like our hardware measurements, e.g. "[measured on firmware 13.42 `libSceNpManager.sprx` by BunnyFl](https://github.com/boykopovar/AnyPS5/pull/10879#issuecomment-6397162725)". Drop the "shared pool" and "NP request convention" wording.
