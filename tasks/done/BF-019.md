## Why

Resident Evil Village (PPSA01556)'s first scene fills the 6400 MiB host import budget. After that, a range first needed by an upload is refused at every use and copied on the CPU. In bf-settle that was ~1 GB of CPU copies per present, plus 0.7 s of import rescans (BF-018 covers the rescans). Log line, text only:

```
[gpu] host import budget: 6399 MiB live of 6400 MiB (APS5_HOST_IMPORT_MIB); 5978411 imports (634831 MiB) refused so far, 5315222 of them remembered, last 0x2372400000+0x80000 by build
```

## The mechanism

Line numbers are at #6457's head 9c308c739b, `core/libs/prx/libSceAgcDriver/Graphics/src/GuestBufferMemory.cpp`, and main has the same code:
- **Eviction rules:**
  - `evictable()` (`:975`) needs `!pointerHeld && lastUse + 256 < useCounter`;
  - `pointerHeld()` (`:971`) is `lastUse >= buildFloor`.
- **Writes to `lastUse`:** an import's creation (`:1290`, `:1365`), a `HostImportFor` hit (`:2698`), and an address-space hit (`:2846`), which stamps every import the space maps with one fresh stamp. Uploads that take an import through `findImport` don't stamp it.
- **So the space's imports never age:** an address-based build (~72 per second in the scene) restamps every import its space maps, and none of them reaches `evictable()`. Once the budget is full, the import set is frozen.
- **Where the refusal happens:** a region that needs a direct import asks in UploadFinish (`:3827`, `ImportRequester::Build`, evict allowed). It finds nothing evictable and is refused every time.

- Say which in the result.

1. **Keep the space's protection and drop its stamp from eviction's recency.**
   - One way:
     - a space hit writes its stamp to a separate field such as `spaceUse`;
     - `pointerHeld` checks `max(lastUse, spaceUse) >= buildFloor`, so the build that stamped them still holds them;
     - `evictable()`'s age test uses `lastUse` only.
   - A better shape is fine if you find one. The rule to keep: an import a running build uses stays held, and one that only the address space has touched for `protectedUses` direct uses can go.
2. **Evicting an import the space maps must leave the space correct.**
   - Retirement bumps `epoch`, so the next address-based build rebuilds its space (`rebuiltEpoch`).
   - The rebuild's walk (`:2915`, no eviction) maps the evicted range by a mirror or a copy.
   - Check that nothing holds the old space's pointer to the evicted import past the epoch check that UploadFinish already does.
3. **Bound the thrash.** Count the evictions of imports that only the space kept young, and the space rebuilds that follow. Print both in the shutdown or `[address]` line.
   - A steady state of a frozen budget plus one hot range should cost one eviction and one rebuild, not one per upload.
4. **Tests (Linux, red/green),** with `SetHostImportBudget`, 64 KiB pieces and the address-space cache on:

   - Red (this branch with the fix taken out, test kept): R is refused at every upload while the builds keep stamping.
   - Green: R is imported after one eviction, the space rebuilds once, and later uploads hit R's import.
   - Also check that an import a running build uses is never evicted from under it, and that the space's reads of the evicted range still return the guest's bytes.
