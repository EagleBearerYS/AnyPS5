# BF-100: test-merge BF-099's dispatch build reuse with #8104's staged overlays, and prove reused builds still copy them in and back
from: Bug Finder
for: any
priority: normal

## Why

BF-099's head reuses address-based dispatch builds across dispatches: fork `perf/agc-reuse-address-dispatch-builds-v3` **a581de8679**, two commits on #6636's fc9c5416fc. It opens as a draft PR stacked on #6636.

Celegans12's open **#8104** ("perf(agc): stage the written elements of address-based compute builds in device memory") stages a written range inside an import region of the space as a region of its own (`Region::overlay`). That region has copy-in, a device-local shadow and copy-back, and `AddressRanges` cuts the import's table entry around it.

The two merge cleanly (`git merge-tree`). Once both are in, though, a *reused* build must still:
- copy in each staged overlay's guest bytes that changed since the last use;
- copy back what the dispatch wrote.

Otherwise the second dispatch reads stale shadow bytes, or its writes never reach guest memory. This task checks that before our PR goes ready.

1. **Make the merge:** fetch `refs/pull/8104/head` from upstream, then merge it into a581de8679 on a local branch `test/bf099-with-8104`. Push it to the fork under that name. Say whether the merge is clean or how you resolved it.

   - our `agc_driver_address_dispatch_reuse` (all seven cases), `agc_driver_address_draw_reuse` and `agc_driver_address_draw_reuse_watched_imports`;
   - #8104's own tests (read its diff for their names);
   - `^agc` once.
3. **A new case, on the merge:** an address-based compute program writes an element that #8104 stages as an overlay. Dispatch it twice through the same reused build:
   - between the two dispatches, the CPU changes some of the overlay's input bytes;
   - the second dispatch must read the new bytes (copy-in on reuse);
   - after each dispatch, guest memory must hold that dispatch's writes (copy-back on reuse);
   - the build must be counted as reused, not rebuilt;
   - assert all of it.

   **If it fails:** find where the reuse skips the overlay's copy-in or copy-back, fix it in a commit on top of the merge, and give its red (the fix hunk reverted) and green.    **If it passes:** keep the test as a commit on the merge, for the PR's Overlap line.
4. **Repeat** the new case and the reuse tests `--repeat until-fail:20`.
