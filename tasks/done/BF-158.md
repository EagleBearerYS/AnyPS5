# BF-158: a T# read from a pointer-loaded V#'s buffer at a runtime offset taken from a word of the same buffer (Spider-Man 2 after #9790)
from: Bug Finder
for: any
priority: high

## Why

Marvel's Spider-Man 2 (PPSA03016) with our #9790 gets past `ReadConstBuffer@pc=0x8fa0`. It then stops at 135 s in compute 0x11e2b40f00, later in the same shader:
```
GetImageResource dword 0 is not a valid runtime value; chain: ReadConstBuffer@pc=0x00009a50(GetBufferResource(LoadAddressU32@pc=0x00009a3c(GetAddressResource(Phi(Phi(Phi(Phi(ReadConstBuffer@pc=0x00001fc4, Phi), …
```
That's hugodearaujo's run, RX 9070 XT RADV: https://github.com/boykopovar/AnyPS5/pull/9790#issuecomment-6352612572.

**His IR, block $398** (it's the same program as his #8939 IR, issuecomment-6340144242):
```
%14375 = GetAddressResource %11969, %11968              ; the pointer pair: record dwords 2/3 on most edges, the +0x4c0 T#'s dwords 0/1 on the edge from $353
%14376..%14379 = LoadAddressU32 %14375, …               ; a V# (#9790 already handles this pair and V#)
%14381 = GetBufferResource %14376..%14379
%14382 = ReadConstBuffer %14381, 0x0                    ; a data word read through that V#
%14384 = ShiftRightLogical32 %14382, 0x10
%14385 = GetAddressResource %11969, %11968
%14386..%14389 = LoadAddressU32 %14385, …               ; pc 0x9a3c, the same address loaded again
%14390 = ShiftLeftLogical32 %14384, 0x5                 ; (word >> 16) * 32
%14397 = GetBufferResource %14386..%14389
%14398..%14405 = ReadConstBuffer %14397, %14390         ; pc 0x9a50: a T# at that runtime offset
%14442 = GetBufferResource %14376..%14379
%14443..%14446 = ReadConstBuffer %14442, 0x0            ; an S#
%14638 = GetImageResource %14398..%14405 ; %14639 = GetSamplerResource %14443..%14446 ; ImageSampleRaw
```

**The printed offsets are unreliable:** his dump predates #9907, and the IR printer showed every SMEM immediate as `0x0`. So the immediates of `%14382` (the key word) and `%14443` (the S#) are unknown; don't assume 0. Make the test cover a nonzero immediate for both.

**The shape:** the child buffer, reached through the pointer-loaded V#, holds a header word whose high 16 bits index an array of 32-byte T#s in the same buffer, plus an S#. The T#'s offset is a uniform runtime value derived from a data read through the same V#.

**Known neighbours:**
- **#7223** (yabanana, the base of our #7395 → #8939 → #9457 → #9790 stack) resolves "a scalar-buffer record, a runtime pointer, a V#, then a second independent key". Here the second key isn't independent: it's read from the child buffer itself.
- **#9790's body** lists "a data read through the V#" as still refused.
- **#2715** (Ghost of Yōtei, open issue) reports "loads its T# from a buffer at an index read from another buffer in a loop". Check whether your change also covers that shape, and say so; don't build for it separately.
