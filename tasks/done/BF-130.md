# BF-130: #9533 review items 1-3: the stencil plane aliased by a host-only colour target, a gate on the metadata-less descriptor, and a validation-layer comparison
from: Bug Finder
for: any
priority: high

## Why

#9533 is our draft (EagleBearerYS, branch `fix/agc-msaa-d32s8-separate-stencil`, head **5daa8cb7a9**; read it from upstream `refs/pull/9533/head`; use its latest head when you start and say which). It imports native multisample D32S8 depth targets with a separate cleared stencil plane.

A tester's Linux run of Ghost of Tsushima Director's Cut (PPSA02225) on 5daa8cb7a9 gets past every native multisample refusal, then stops in all three runs with:

```
AGC graphics: a CPU read of 0x1546eb0000+0x870000 overlaps multisampled color target 0x1546eb0000+0x870000 (2 samples), whose samples are only on the host: guest access to it is not implemented
```

- 0x870000 is the separate stencil plane's size (`MultisampledDepthBytes_nid_no_patch` of 1920x2160, 1 byte, 2 samples).
- A 2-sample R8 colour target of 1920x2160 with 64 KB tiles has exactly that footprint (MultisampleTarget.cpp `guard()`), so the title also uses the plane's memory as an R8 colour target whose samples live only on the host.
- The read is prepareDepthSampling's plane proof: `GuestMemory::Read(target.stencilAddress, plane)` (DepthSurface.cpp:158 at 5daa8cb7a9). It reaches `RequireNoMultisampleColorTarget` (MultisampleTarget.cpp:1124), which throws.

A reviewer (MarcZX10, review 5608366005, CHANGES_REQUESTED) asks for:
1. a plane clear proof that accounts for the overlapping colour target, without reading guarded or stale guest memory, with a regression for the alias path;
2. evidence and a regression for the guest sequence behind the metadata-less descriptor path (commit 5be005ea13, for The Grinch: Christmas Adventures, PPSA07656), or keep its refusal;
3. the same focused tests on main and the head under the Khronos validation layer, on one machine and GPU, with new `VUID-` messages compared.

## Commits

1. **No guarded reads at import (item 1).**
   - Add a non-throwing query to MultisampleTarget: whether an active host-only colour target's guarded range overlaps a given range, and if so that target's format, samples, footprint and newest content.
   - In `prepareDepthSampling`, ask it for every initial range (depth, HTILE, stencil plane) before any `GuestMemory::Read`. Never read guarded memory.
   - If an R8 (UNORM or UINT) colour target with the same sample count covers exactly the stencil plane, and its newest content is a known uniform value with no draw since, take that byte as the plane's initial stencil value, without reading guest memory. Known uniform value means a fill it absorbed and has not yet applied (`MultisampledColorFill`), or a recorded clear, or a CMASK fast clear. You'll probably need a "drawn since its last clear" flag on the target. Add one if there is none.
   - Otherwise refuse with `native multisample stencil plane aliases a multisampled colour target whose samples are only on the host`. Print one stderr line, at most 8 times, naming the colour target's address, format, samples and newest operation (clear with its value, or drawn).
   - The same query decides `CheckCurrent`'s plane checks: a plane fill over an aliased plane is proven from the colour target the same way, never by reading guest bytes.
   - **Regression,** in NativeMultisampleDepth.cpp (a new mode if needed, registered in CMake with the WIN32 PATH list): a 2-sample R8 colour target over the plane memory, then the D32S8 import and a depth sample:
     - colour target cleared (fill absorbed) and not drawn: imported, and the next draw's stencil test passes the cleared value;
     - colour target drawn into after its clear: refused with the new reason;
     - colour target of another format or sample count over the plane: refused with the new reason;
     - in all three, no guarded read happens.
   - **Red:** revert the product change, and the cleared case throws the guard text above.
2. **The metadata-less descriptor needs an observed expand (item 2).**
   - Find where the driver decodes DB_RENDER_CONTROL for a draw. A draw whose depth target is this native multisample surface and that sets both the depth and stencil compress-disable bits marks the surface expanded. These are the guest's in-place expand; a depth-only surface needs only the depth bit.
   - Any HTILE clear or fill, stencil plane fill, or `NoteHtileDepthClear` over the surface clears the mark.
   - `CheckResource` accepts a descriptor with no metadata (META_DATA_ADDRESS 0, not pipe-aligned) only while the surface is marked expanded. Otherwise it refuses with the old text, `native multisample depth sampled metadata or XOR mismatch`.
   - **Regression:** a bare sample with no expand is refused, and a bare sample after an expand draw gets the depth. After an expand and then a clear, it is refused again.
   - Update the existing separate-stencil test that samples through the bare descriptor, so it draws an expand first.
   - **Red:** revert the gate, and the no-expand case samples instead of refusing.
3. **Debt entry** (docs/dev/debt/libSceAgcDriver.md) for the copy path that's still missing: a plane drawn into as colour is refused, and taking it needs a GPU copy of the R8 samples into the depth image's stencil aspect.
