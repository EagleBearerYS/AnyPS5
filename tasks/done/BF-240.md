# BF-240: design read for a pad-driven on-screen keyboard in libSceImeDialog (name entry softlocks, high)
from: Bug Finder
for: any

## Why
The user's call, 10-25: "I saw someone else basically say they were softlocked because they couldn't type a name in PvZ, we can make a fix for this".

On `main`, libSceImeDialog's running dialog draws nothing. It takes text only from the host keyboard, through SDL keyboard events on the focused game window (#6504). A player with only a controller can't enter a name, so the title waits on the dialog forever.

**Titles:**
- **Plants vs. Zombies: Replanted (PPSA29802).** Its thread is D#6404 (https://github.com/boykopovar/AnyPS5/discussions/6404). It reaches the profile menu; the softlock report itself isn't on GitHub.
- **Octopath Traveler 0 (PPSA28495)**, at the favourite-food prompt. It imports libSceImeDialog's Init, GetStatus, GetResult, Term and Abort.

**What gets built later** (not in this task): one PR with the full pad-driven keyboard.
- It's drawn with main's overlay framework.
- While the dialog runs, pad input goes to it and the game's own pad reads are held back.
- Host keyboard text keeps working alongside it.

**This task is the design note that comes first.** Push no code and no branch.

## Source
shadPS4 **30f4170896** (shadPS4's PR #3973): `src/core/libraries/ime/ime_ui_shared.cpp` around L821-886, and `src/core/libraries/ime/ime_dialog_ui.cpp` around L872. Clone shadPS4 at that commit and read it there.

The pad mapping as we understand it:
- Cross types the selected key;
- R2 is Done;
- Square is backspace, and L1+Square clears;
- Triangle is space;
- L1/R1 move the cursor;
- L2 is shift, L2+Triangle gives symbols, and L3 specials;
- Circle closes.

**Check every one of these against the source, and cite the line per key.** Where the source differs from our list, the source wins; say so. Anything the source doesn't name stays as `main` has it. That's the project's source rule: no behaviour from a sibling or a convention.

## The design note (results/cloud-<n>/BF-240.md)
1. **Overlay hooks.**
   - How a plain panel gets drawn over the game's frame on both platforms, using what main already has: the text field with its cursor, the key grid with the selected key, and the button hints.
   - Which hook runs per present, and on which thread. What it can draw (a font? glyph atlas? rectangles?), and how it reaches the swapchain image.
   - What new pieces are needed, if any.
   - file:line for each.
2. **The input hand-off.**
   - Where pad state enters, from SDL to `PadInput` to the `scePadRead*` answers.
   - How to send it to the dialog while the dialog's status is RUNNING.
   - What the game's own reads return meanwhile. Cite what shadPS4 does, e.g. neutral buttons and sticks with the pad still connected. If the source doesn't say, give main's closest existing behaviour and flag it.
   - Edge handling: a press is seen once, and the held buttons when the dialog opens don't type.
   - How the host keyboard path (#6504) runs alongside it.
3. **What the dialog returns:**
   - `sceImeDialogGetStatus` states;
   - `sceImeDialogGetResult`'s end status for Done (R2) and for close (Circle);
   - how the text is written to the caller's buffer: UTF-16, the max length, the terminator;
   - what Term, Abort and ForceClose do while the keyboard is up.
   Give main's current code and the source side by side.
4. **Layout:** the key pages and the shift, symbol and special sets, as the source has them. Keep it plain and readable, close to the console's panel where the source shows it, with no extras.
5. **Build plan:**
   - files to change and new files;
   - a rough size;
   - commits in order. The project rules apply: no comments in code (docs/dev/CONVENTIONS.md), and each test goes in the same commit as its code.
6. **Tests plan:**
   - the pad mapping as a pure function from button edges to edit actions;
   - the hand-off: the game's `scePadReadState` is held while the dialog runs and returns to normal after;
   - accept and cancel results through the guest API, e.g. extending `GuestImeDialog.cpp`.
   Say what each would catch.
7. **Overlap:**
