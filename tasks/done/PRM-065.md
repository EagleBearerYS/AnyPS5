## Context

Our PR #12478 (boykopovar/AnyPS5, "perf(agc): bypass the draw cache while its hit rate is under 5%") bypasses the draw cache after two windows of 2,048 lookups in a row each have fewer than 5 % useful lookups.
- Commit c7981bcb3b made a lookup whose draw key `DrawKeySightings` has seen before count as useful: `drawKeySeen(drawKey)` in the `Note(...)` call at `Execution/src/Driver/Draw/Draw.cpp` L660, which reads `DrawKeySightings::Holds` (`DrawCache.cpp` L156-165). That fixed a cold-start warm-up (`ColdScenesKeepTheCacheLookedUp`).
- **Suspected side effect:** with a byte budget smaller than a scene (`APS5_DRAW_CACHE_BYTES`, default 256 MiB), every entry is inserted at its second sighting and evicted before its third, so it never hits. Its key still stays in the sightings table, so every later sighting counts as "useful", the windows stay at or above 5 %, and the bypass never starts.
- A Resident Evil Village pair on the current base showed no gain from the PR. A profiled boot on the PC will confirm or rule out this cause. Your branch is ready in case it's confirmed. If it's ruled out, the branch is dropped.
