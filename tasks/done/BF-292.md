## Why

This is tonight's top priority. The PM decided it in the user's name, because the user wants real speed gains.

- **The measurement:** a profiled Resident Evil Village menu boot (PROFILE_DRAW, main ebb4075168 + #12478) moves about 5 GB per 10 s each way between storage images and host memory. The `[storage]` line (`Graphics/src/Texture.cpp`, ~line 177) shows it:
  - **uploads:** `cpu 357 / 5,097 MiB`, by reason `flushed 356 / 4,819 MiB`;
  - **write-backs:** by reason `storage refresh 1,150 / 4,691 MiB`, `partial write-backs 1,585 / 6,558 MiB`, `shadow retiled 2,192 / 6,551 MiB`;
  - **the device-side alias path** moved `alias 0 / 0.0`.
- **What "flushed" means** (`Texture.cpp:97` comment): "another image's results were stored over the surface by this refresh". So two storage images over the same memory round-trip through host memory on every refresh.
- **Where the time goes:** inside each dispatch's locked "complete" stage, the B upload (0.6 ms per dispatch) and the hook waits (0.43 ms per dispatch). That stage sits under the GPU mutex, which queues 0x0 and 0x20 take turns on.

We want the **ceiling**: Village's menu fps if that traffic cost nothing.
