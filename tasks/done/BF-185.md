# BF-185: raise ShaderInfo::MaxImages from 64 to 128, stacked on #10000, with a refusal that names the count (Ghostrunner's next cap)

## Why

frankea replayed Ghostrunner (PPSA03685)'s compute shader 0x200c520000 offline, from the request the driver dumped at use (RTX 4090, Windows), on `main` + #9068 + #8070 + #9701-#9703 + #8939 + #9969 + #10000.
- **The new stop:** with #10000 the shader gets past `sampler resource limit exceeded` and stops on `image resource limit exceeded`.
- **What it is:** `ShaderInfo::MaxImages = 64` (`IrMetadata/ShaderInfo.hpp:15`). #10000 raised `MaxSamplers` to 64 and `MaxSampledPairs` to 256, with 64-bit sampler masks.

**Why a higher image limit is safe, read on #10000's head:**
- **Per-image spec-constant ranges have room** (`PipelineSpecialization.hpp`):
  - `ImageBase` 1024 + 5/image, up to `VertexBase` 4096 (614 images);
  - `CompareBase` 49152 + 6/image, up to `FoldOffsetBase` 57344;
  - `MipCountBase` 8320 + 1/image, up to `StoreQuantizeBase` 12288.
- **No 64-bit mask is indexed by image.** `directSamplers[image] |= 1 << sampler` (`ResourceMaterializer.cpp` ~1678) is sized by images with sampler bits.
- **Device limits are checked at layout creation** (`Graphics/src/ShaderResources.cpp` ~1844-1929).

Shaders with 64 or fewer images plan exactly as before. Confirm all of this; don't take it on trust.
