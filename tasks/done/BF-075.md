# BF-075: test the 32-bit depth-bits read from guest memory (NHL 26's stop), red/green and the Linux check

## Why

NHL 26 (PPSA26785) aborts 3 of 3 times on main, a few hundred frames after its window opens (frankea, discussion #7304; also seen on Linux, per issue #5398):

```
[gpu] driver failure: compute shader 0x1150101000: AGC graphics: 32-bit integer read of the depth-layout texture 0x11c10f0000, which is no depth surface drawn with, is not implemented
```

The fix is on the fork: branch `fix/agc-depth-bits-32-guest-memory`, head 43e601919d, on upstream main f1af6c5915. It changes one hunk in `core/libs/prx/libSceAgcDriver/Graphics/src/ShaderResources.cpp`, in `cachedTexture`, so that the case works like this:
- **Before:** a sampled T# with a 32-bit integer format (`Format32UInt` 20 or `Format32SInt`) in a Z swizzle mode (word 3 bits 20-24 = 4, 8, 16, 20 or 24) threw when no depth surface was drawn at its address.
- **After:** that T# is read from guest memory as a `Format32Float` (22) texture. This is the float view the shader is already specialized for (c1692bf939: `ResourceMaterializer` sets `depthBits`, and `SpirvImageEmitter` keeps the fetched bits).
- **The 16-bit case** (`Format16UInt`, read as `Format16UNorm`, bbf430e22d) works as before. The commit only joins the two cases.

No test covers either case over guest memory; `DepthSurfaceReuse.cpp` only covers drawn depth surfaces.
