# BF-037: architecture ceiling: a persistent device-wide descriptor heap against per-draw descriptor sets (lavapipe, throwaway)
from: Bug Finder
for: any
priority: high

## Why

The same architecture goal as BF-036: the largest gain across Resident Evil Village (PPSA01556), Planet of Lana (PPSA19450) and Animal Well (PPSA22520), all CPU-bound on queue 0.

Resident Evil Village's menu, profiled, per 10 s:
- **Resources:** `Graphics::Draw` resources = 1,651 ms, of which bindings 991, upload 125 and descriptors 57;
- **Lookup:** 1,290 ms;
- **The title's own heap:** it's bindless, 32,768 T# records with ~4,096 distinct textures. Main turns that into a per-draw Vulkan descriptor table ("bindless image tables in graphics stages", `Graphics/include/Context.hpp:204`).
- **#6454 (ours, open)** shares one immutable table per heap and write epoch, and keeps up to 8 freed descriptor sets for reuse.

The device already queries descriptor indexing (`Execution/src/VulkanDevice.cpp:305-310`: update-after-bind, partially bound, runtime arrays).

The candidate is a device-wide, persistent descriptor heap:
- every image view, sampler and buffer range the driver creates gets a stable slot, written once when created or changed;
- the heap is bound once per command buffer;
- a draw passes only a small index table (push constants or a per-draw slice of one ring buffer);
- so per-draw descriptor-set allocation, `vkUpdateDescriptorSets` and binding go away, along with the driver work that builds them.

This task measures its ceiling.

## What to build

On a new fork branch `exp/descriptor-heap-ceiling` from upstream main 66e290f1c0 or newer. Throwaway, no PR.

1. **Today's per-draw descriptor cost,** from a harness like BF-036's: M draws, each with N bound images for N = 8, 128 and 2,048 (and 4,096 through a title-style bindless table, which main's image-table path takes).
   - Time per draw, µs: `ShaderResources` build or lookup, descriptor-set allocation, the writes (`vkUpdateDescriptorSets` and building their arrays), the binds, and the validation that decides a table can be reused.
   - Do it with memory unchanged between draws, and with one image's memory changed.
2. **A ceiling prototype of the heap,** for the image-table path first, because it already indexes a table in the shader:
   - **The heap:** one update-after-bind, partially-bound sampled-image array (size from the device limit, at least 65,536 if allowed) plus a sampler array.
   - **Slots:** each `Texture` / view gets a slot when it's created, which is freed on destruction with a deferred reuse.
   - **The table:** a draw's table becomes an index array in a ring buffer instead of a descriptor set.
   - **The shader:** the recompiled shader's table access reads `heap[index[i]]`. For this prototype, a small change in the existing bindless-table emission is fine, or hand-built SPIR-V in the harness if that's simpler.
   - Measure µs per draw for N = 128, 2,048 and 4,096, against item 1.
3. **Non-bindless titles** (Lana and Animal Well bind T#/V# per draw through user data): say what the heap needs there.
   - Per-draw slot lookups and an index table, the recompiler's change from per-binding descriptors to heap-indexed access.
   - Estimate the per-draw cost from the prototype's numbers.
4. **Risks:** device limits on lavapipe and on typical desktop GPUs (NVIDIA and AMD `maxDescriptorSetUpdateAfterBind*`), nonuniform indexing, and how #6454's epochs map onto slot reuse.

## Addendum (Bug Finder, 2026-10-16 ~19:00 UTC): measure image resolution, not only descriptor writes

Resident Evil Village's profiled menu (`[resources]`, the difference between two consecutive lines, 1,000 builds) gives, per resource build:

| Phase | ms per build |
|---|---|
| stage B | ~0.6 |
| of it, images | ~0.4 |
| guest memory upload | ~0.15 |
| stage A | ~0.07 |
| bindings | ~0.05 |
| descriptors | ~0.03 |

So in the title, the Vulkan descriptor writes and binds are small. The per-draw image resolution is the big part: looking up and validating every bound texture, which `ShaderResources` does in `images`.

In item 1, time the `images` phase per draw (the same `[resources]` phase names with `APS5_PROFILE_DRAW=1`), next to allocation, writes and binds.

In item 2, the heap prototype must say what persistent views save on `images`. A view whose slot already exists, and whose memory hasn't changed since (#6454's write epoch), needs no per-draw lookup or validation, only its index. If the prototype can't skip `images` without a write-epoch check, add the minimal one (reuse #6454's stamp or the tracker's `UnchangedSince`), and report both:
- descriptors only;
- descriptors plus skipped image resolution.
