# PM-094: Research: a generic way to make titles render at 1080p or 1440p instead of 4K
from: AnyPS5 Project Manager
for: any
priority: high

## Why

Users in the AnyPS5 dev chat keep asking for "a parameter to make the game render only at 1080p or 1440p". Today everyone hand-patches each game. Most PS5 titles register 3840x2160 display buffers whatever the emulator reports (our 10-17/10-18 work: Planet of Lana and Animal Well register 4K even when told the output is 1080p, and refuse to fall back when 4K is refused; Village the same). A real PS5 on a 1080p TV accepts 4K buffers and scales them, so games have no reason to render lower.

Two data points from tonight:
- A Unity title (Planet of Lana, PPSA19450) takes its output size from one line of `app0/Media/boot.config`: `platform-ps5-video-out-width=3840`. A test with 1920 is booked on the user's PC tonight.
- A community member got another Unity title (Bendy and the Ink Machine) to 1080p by patching four `Screen.SetResolution(3840, 2160)` call sites in its `Il2CppUserAssemblies.prx`.

`main` already has byte-checked per-title patches at conversion time (`relinker-patches.toml`, `--patches`; `core/relinker/relinker/src/patching/GamePatch.cpp`, docs/user/USAGE.md "Game patches"; issue #6206, PR #6314 merged). It patches ELF bytes only, not data files like boot.config.

## What to find out (research and code reading only; no game files exist or are needed on the worker)

1. **Unity on PS5:** which boot.config keys set the render and output size (`platform-ps5-video-out-width` and any height or scale keys), and how the player derives height and render-target sizes from them. Public Unity docs, Unity's PS5 player behaviour as described publicly, other emulators' notes (shadPS4 issues/wiki, KytyPS5, etc.). Is boot.config read through a path our filesystem layer serves (find where `/app0/...` opens are handled in our code), so an emulator-side override of one key, or an app0 file overlay, would work without editing the dump?
2. **Unreal Engine 4/5 on PS5:** what decides render resolution (r.ScreenPercentage, r.DynamicRes.*, the console's resolution settings in DeviceProfiles/ini inside paks), and whether a console build reads a command line file (`UECommandLine.txt` / `UE4CommandLine.txt`) or loose ini overrides from the game directory, which would allow a generic `-ExecCmds`/cvar override. Cite sources.
3. **Other engines' common knobs**, briefly, if any are known (Decima, Frostbite, in-house): skip if nothing public.
4. **Other emulators:** how shadPS4, RPCS3, Ryujinx/yuzu and Xenia offer resolution control: per-game patch databases, internal resolution scaling of render targets, file overlays (LayeredFS-style mods folders). For internal-resolution scaling, what it takes (render targets, viewports/scissors, shader-side coordinates, CPU readback, copies/resolves) and its known failure modes.
5. **AnyPS5 feasibility:** read our AGC driver enough to estimate, in a paragraph each:
   - (a) an app0 file overlay (a directory whose files shadow app0's at open time);
   - (b) a Unity boot.config override (an env var that rewrites `platform-ps5-video-out-width` when the guest reads that file);
   - (c) an Unreal command-line or ini injection, if (2) shows one exists;
   - (d) generic render-target scaling in the AGC driver.
   For each: where it would hook (files and functions), rough size, risks, and how it would be tested (red/green) without game data.
6. **Search first:** open and closed issues, PRs and discussions on boykopovar/AnyPS5 for resolution overrides, overlays, mods folders, boot.config, render scale (issue #7009 and #2239 are closed with "no global render-resolution override"; PR #7011 documented that). List anything relevant, so we don't duplicate.
