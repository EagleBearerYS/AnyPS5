# BF-040: reuse address-based dispatch builds, stacked on #6636's draw reuse (PR candidate)
from: Bug Finder
for: any
priority: high

## Why

On main, an address-based compute object is never reused: `noteReusable` returns early on `usesBda` and on `HoldsLease()` (`Graphics/src/ShaderResources.cpp`). So every address-based dispatch rebuilds its resources.
- **BF-033's lavapipe ceiling** (results/cloud-3/BF-033.md), a reused object against main's rebuild:
  - 16 textures: 342-838 µs → 65 µs per dispatch;
  - 2,000 textures, with the lookup log fixed: 8.2 → 0.98 ms.
- **Resident Evil Village (PPSA01556):**
  - **First scene:** dispatch resource binding is the largest cost per frame (`Vulkan.Dispatch.shader_resources` 2.3 s of a 4.2 s frame).
  - **Menu:** dispatches cost 664 µs each in resource work. That's upload 368, hook waits 160, revalidate 112, images 104 and address bindings 56, all inside the GPU mutex.

BF-033's prototype was deliberately thin, and its §4 lists what breaks. The worst is the 11 `^agc` stalls: a cached object holds its address space's lease, so a guest free waits 60 s.

Our open **#6636** (fork `perf/agc-reuse-address-draw-builds`, head 89ab0ea75a) already makes this sound for **draws**:
- each draw takes the space for its own batch, and the build pins no guest allocation between draws;
- it brings the space's mirrors up to date as a build does;
- it reuses only while the cached space is the current one, its regions are unchanged imports, read-only mirrors or repeated snapshots, and the previous draw's completion has run;
- it refuses after rejections or a throw;
- it counts reuses and refusals (`[rescache] address-based draws: ...`).

Its debt entry says "Dispatches and draw recipes do not reuse address-based builds". This task extends it to dispatches.

- **Credit:** where you adapt fable-void's code or design (below), name him and the source commits in the commit body. A `Co-authored-by: fablevoid <340827264+fable-void@users.noreply.github.com>` trailer is allowed for adapted code; it's a human author, not AI attribution.

1. **Reuse for compute objects** under the same rules #6636 applies to draws: the space taken per batch, mirrors brought up to date, regions and snapshots proven unchanged, refusal counters. Keep #6636's switch semantics, or add `APS5_NO_ADDRESS_DISPATCH_REUSE=1`. A refused reuse must cost about one proof, not a stall.
2. **The fault buffer and written-page records per dispatch.** #6636 rebuilds a draw that repeats before its previous completion ran (two in one batch), because one build's fault buffer holds one draw's records. Dispatches of one program often repeat inside one batch, so that rule would refuse most of the gain.
   - Give each reused dispatch its own fault and written-page record. One way is from a pooled slab per batch.
   - Attribute faults to the dispatch that made them, and survive an overflow.
   - Prior art, fable-void's fork (https://github.com/fable-void/AnyPS5, branch `wip/new-gpu-path`):
     - `26ff0b4f28`: take each dispatch's BDA table and fault record from pooled slabs;
     - `a7015cd885`: share one fault record among the address-based builds of a batch;
     - `3b1828e0b5`: attribute faults in shared records by access ranges and survive their overflow.

     His design differs from main's, so read them for the idea. If the fork can't be fetched, design it from #6636's records.
3. **GPU writes pending over snapshot ranges** (BF-033 §4, item 3): before a reuse's snapshot proof, complete pending writes over the snapshot ranges as the dispatch cache's validation does. Add a test: a dispatch writes the SRT or a descriptor table that a later reused dispatch reads, and the reuse must rebuild or see the new bytes.
4. **Recipes stay off** for address-based objects, as BF-033 did. Note it in the debt entry.
5. **Tests**, red on #6636's head and green with the change:
   - a repeated address-based dispatch with unchanged inputs is reused, counted;
   - a changed snapshot word rebuilds;
   - a guest free while a reused object exists doesn't stall: BF-033's 11 stalling tests must pass with reuse on;
   - two reused dispatches in one batch each report their own fault: one faults, one doesn't;
   - pending writes over an SRT range, as in item 3.
