## Why

BF-290's fix (fork `fix/agc-storage-alias-device-handoff` = **a7e04ab973**, one commit on upstream main 08a10d2253) is headed for a PR. It is the device-side handoff for Village's aliased storage images when the surface has no host import: `perf(agc): take an aliased storage image's units on the device without a host import`.

BF-296 (fork `test/agc-storage-alias-roundtrip` = **ec7013a1c2**, on main 422f96b3a9) measures the round trip, but deliberately asserts no byte counts. Its acceptance section says the fix commit can turn the counts into assertions on `StorageTexture::CumulativeTraffic()`.

**What the fix covers,** by BF-290's refusal table:
- **Pair 2** (R32_UINT vs RGBA8 UNORM, both 256x256 R 64 KiB X): covered, the same shape as BF-290's own test.
- **Pair 1** (R32_UINT 256x256 vs 512x128): width and height differ, so it stays refused (row 5, D2/D3 territory).
- **Pair 3** (tiled vs linear): linear has no block units, so it stays refused (rows 2 and 6).

The PR's second commit should show, in bytes, what the fix removes and what it doesn't.
