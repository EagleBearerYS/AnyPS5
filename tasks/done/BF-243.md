# BF-243: let the native depth alias keep its proof through a run of identical same-value fills (Dave the Diver, follow-up to BF-236, high)
from: Bug Finder
for: any
priority: high

## Why
BF-236's commit **96cf351df8** (fork `fix/agc-msaa-depth-alias-same-value-fill`, on a2911ffb72) accepts a native multisample depth alias whose colour target went Clear → **exactly one** full fill of the same value since import. The rule is `current.fills == recorded.fills + 1` in `sameDepthAlias` (`DepthSurface.cpp:103-111` there).

tablefrogpillow ran Dave the Diver (PPSA19115) on the test branch on an RX Vega 56 (https://github.com/boykopovar/AnyPS5/issues/7608#issuecomment-6400671283). They added a local `fprintf` at `sameDepthAlias`'s return. Across the six index-0 samples before the abort:
- **5 of 6 were accepted:** two still Clear==Clear, and three single same-value fills (`fills` 11→12, `filledBytes==bytes`, `sameValue=1`).
- **The refused one:** `fills` 11→**13**, `filledBytes==bytes` (17694720 = 0x10e0000, the whole plane), `contents` unchanged, `sameValue=1`, `active` equal.
  - So it's **two consecutive same-value whole-range fills.**
  - `refilled` is 0 only because of the `+ 1` cap.

**Why a run of identical fills is as safe as one:**
- An absorbed full fill writes no guest memory (`BufferFill.cpp:391` on main). It only leaves the target's pending pattern, and it doesn't bump `contents`.
- A second absorbed full fill of the same bytes and the same value leaves the identical state. Repeating it changes nothing.
- **What `fills == recorded.fills + 1` guards against stays refused:** an earlier partial or other-value fill that a later full fill hides (BF-236's cases 20 `PartialThenSameFill` and 21 `OtherThenSameFill`), since `NoteFill` keeps only the latest full fill.

## What
1. **Track the run.** In `MultisampledColorFill` (`MultisampleTarget.hpp`/`.cpp` at 96cf351df8), add a count of the consecutive full fills that ended at the newest one, all with the same pattern. Call it `sameRun` or similar.
   - **A full absorbed fill** whose pattern equals the pending pattern increments it.
   - **A full fill with another pattern** sets it to 1.
   - **A partial fill, or anything that clears the pending fill** (an applied fill or clear, a recreate), sets it to 0.
   - `Alias()` reports it next to `fills`.
2. **`sameDepthAlias`:** `refilled` holds when all of these do:
   - `recorded.newest == Clear` and `current.newest == Fill`;
   - `current.fills > recorded.fills`;
   - `current.fills - recorded.fills == current.sameRun`, so every fill since import is in one run of the newest pattern;
   - `current.filledBytes >= current.bytes`;
   - `contents` is unchanged and `sameValue` holds, as now.
   Everything else refuses as before.
3. **Tests** in `agc_driver_native_depth_aliased_depth` (`NativeMultisampleDepth.cpp`), in every HTILE layout, as BF-236's cases:
   - **New accepted cases:** `DoubleSameFill` (two full same-value fills after import) and `TripleSameFill` (three). Same view returned, and every sample reads `DB_DEPTH_CLEAR`.
   - **New refused cases:**
     - `SameOtherSameFill`: same, then another value, then same;
     - `SamePartialSameFill`: same, then half the target, then same;
     - `SameDrawSameFill`: same, then a draw view, then same.
   - **The existing cases** 12-21 keep their expected results. Cases 20 and 21 must still refuse.
   - Report the new `cases checked=… unavailable=…` totals. The total without unavailable is what a GPU with 2, 4 and 8 samples should print.
4. **One new commit on top of 96cf351df8** on the same fork branch `fix/agc-msaa-depth-alias-same-value-fill`. Don't amend or rewrite 96cf351df8; it's already with the PR Manager.
   - Subject, for example: `fix(agc): keep the depth alias proven through a run of identical same-value fills`.
   - The debt entry's clause (`docs/dev/debt/libSceAgcDriver.md`, #9742's native-depth entry) is updated to say "one or more identical".
5. **Test branch:** `test/7608-9717-9742-fill2` = `test/7608-9717-9742-fill` (f73f8a0f77) with the new commit merged. As before, its only change from f73f8a0f77 is the library diff.
