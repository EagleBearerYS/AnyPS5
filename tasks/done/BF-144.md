# BF-144: native multisample depth, accept a colour alias over the depth plane when HTILE proves every tile cleared (Ghost of Tsushima Director's Cut's stop on #9533), a follow-up stacked on #9533

## Why

milescoviello ran #9533 at 514643ab16 on Ghost of Tsushima Director's Cut (PPSA02225), warm and cold (https://github.com/boykopovar/AnyPS5/pull/9533#issuecomment-6337725902). The title stops at import:
- first `native multisample depth 0x1544ed0000+0x1fe0000 aliases multisampled colour target ... (vk format 100, 2 samples), newest clear 0`;
- then `depthAliasRefusal`: "native multisample depth or HTILE aliases a multisampled colour target whose samples are only on the host".

GoT does two whole-range fills of 0 before the sample, over the HTILE (0x50000 bytes) and over the stencil plane (0x870000). On a depth-only HTILE, `prepareDepthSampling` already requires every HTILE word to prove the clear against `target.clearDepth`, the title's own DB_DEPTH_CLEAR (`DepthSurface.cpp:188-194` at 514643ab16). Where every tile proves the clear, depth reads the clear value and never the plane's bytes.

So the R32F target over the depth plane can't change the imported depth, whatever it holds. The refusal at `:175` (index 0) is stricter than it needs to be once the HTILE proof holds. The PM approved this rule (the HTILE proof, not the R32F's value) as a separate follow-up PR stacked on #9533.

## The rule

All line numbers are in `core/libs/prx/libSceAgcDriver/Graphics/src/DepthSurface.cpp` at 514643ab16.

1. **`prepareDepthSampling` (:164-176):** a multisampled colour alias over the **depth plane** (index 0) no longer refuses at `:175` when both hold:
   - its sample count equals the target's;
   - the depth target has a depth-only HTILE.

   The function goes on to the HTILE check (:188-194), which still refuses unless every word proves the clear against `target.clearDepth`. If the import succeeds, record the alias in the sampling state, with its `active` pointer and its newest content (clear or draw generation). Keep `reportAlias` for the log.
2. **`CheckCurrent` (:406-479, the alias check at :425-430):** an alias over the depth plane passes only if it's the recorded alias with no newer content since the import. A new alias, or a draw or clear into the recorded one, refuses with `depthAliasRefusal` as now.
3. **What stays as it is:** HTILE aliases (index 1), the stencil-plane rule (index 2, `aliasedStencil` and `unprovenStencil`), and every other refusal.
4. **Debt:** extend #9533's entry for native multisampled depth in `docs/dev/debt/agc.md` (or wherever #9533 keeps it) by one sentence. The sentence says:
   - which depth-plane alias is accepted, and why the alias's own samples aren't used;
   - that an alias over tiles HTILE doesn't prove still refuses.

## Tests

In `core/libs/prx/libSceAgcDriver/tests/execution/NativeMultisampleDepth.cpp`, as new cases next to #9533's alias cases. Use 4 samples on lavapipe; it has only 1 and 4. Loop over 2, 4 and 8 as the existing native tests do, and count unavailable counts as unavailable.

Each **acceptance** case must be red without the product change (`depthAliasRefusal`). Each **control** passes on both trees.

**Acceptance cases:**
1. **The title's shape.**
   - **Setup:** an R32F colour target with the depth target's sample count over the whole depth plane, cleared to 0.25, while DB_DEPTH_CLEAR is 1.0 (the alias value doesn't match). Then whole-range fills of 0 over the HTILE and the stencil plane, proving the clear.
   - **Expect:** the import passes, and one dispatch reads DB_DEPTH_CLEAR (1.0) in every sample of every pixel, never 0.25.
2. **A matching alias value:** the same with the alias cleared to 1.0. Same result.
3. **A partial alias range:** an alias over only part of the depth plane. Same result.

**Controls, which refuse with the existing texts:**
4. **One HTILE word that doesn't prove the clear:** "native multisample depth initial HTILE does not prove its clear value".
5. **HTILE words that prove a different depth than DB_DEPTH_CLEAR** (the mismatching depth clear): same text. Read `htileProvesClear` for what that means on a depth-only HTILE, and write in the result which words you used.
6. **An alias whose sample count differs from the depth target's:** `depthAliasRefusal`. It needs 2 or 8 samples, so it counts as unavailable on lavapipe. Write it so the RTX 3070 runs it later.
7. **After a passing import, a draw into the recorded alias:** the next `CheckCurrent` refuses with `depthAliasRefusal`.
8. **After a passing import, a new multisampled colour target over the depth plane:** `CheckCurrent` refuses.

**Controls that pass:**
9. **After a passing import, nothing changes:** a second dispatch passes `CheckCurrent` and still reads DB_DEPTH_CLEAR.
10. **A draw into the alias after the HTILE clear but before the import:** HTILE still proves every tile, so the import passes and depth reads DB_DEPTH_CLEAR. If the code you write can't support this safely, say why in the result instead of weakening the rule.

Cases 2, 3, 5, 6 and the after-import draw (7) follow JJenkx's review on #9533 (https://github.com/boykopovar/AnyPS5/pull/9533#issuecomment-6338020932): matching vs mismatching depth clear, exact vs partial range, sample-count mismatch, a draw after the clear.
