# BF-161: #9533's driver-path tests must stop the driver before they return (an abort at exit on macOS)
from: Bug Finder
for: any
priority: high

## Why

jotitadev ran #9533 (head 1582cf6cc0) on macOS: Apple M2 Max, macOS 27.2 under Rosetta 2, MoltenVK 1.4.2 and MoltenVK main + SPIRV-Cross #2704, on #8658's `feat/macos-port` c5fa39620a ([review 5623098779](https://github.com/boykopovar/AnyPS5/pull/9533#pullrequestreview-5623098779)).
- **Pass:** every `agc_driver_native_depth_*` case and `agc_driver_native_multisample_depth`.
- **Abort:** `agc_driver_native_depth_driver_path` and `agc_driver_native_depth_driver_queued_fill` abort **at exit, after their summary lines**:
  ```
  libc++abi: terminating due to uncaught exception of type std::__1::system_error: recursive_mutex lock failed: Invalid argument
  exit -> __cxa_finalize_ranges -> Driver::~Driver -> Driver::stop -> DevicePointer::Reset -> VulkanDevice::~VulkanDevice -> State::~State -> std::terminate
  ```

**The cause, in `core/libs/prx/libSceAgcDriver/tests/execution/NativeMultisampleDepth.cpp` on 1582cf6cc0:**
- `CheckDriverPath(bool queued)` (`:2034`) hands its device to the driver singleton with `AgcDriver::DriverDetail::DriverTestAccess::UseDevice(device)` (`:2044`). The helper at `:60` sets `Driver::Get().device`.
- Nothing hands the device back, so the last reference dies in `Driver::~Driver` (`Lifecycle.cpp:134`) at static destruction, after function-local statics that `~State` locks are already destroyed.
- glibc and Windows tolerate locking a destroyed mutex, and macOS returns EINVAL.

## The change (test only)

- **Base and branch:** a new fork branch `fix/agc-native-depth-driver-path-stop` from `refs/pull/9533/head` (1582cf6cc0; use the current head and say which), with one commit. Don't push to #9533's branch; the PR Manager does that.
- **In `DriverTestAccess`** (`:59`), add `static void Stop() { Driver::Get().stop(); }`.
  - `Driver::stop()` (`Lifecycle.cpp:145`) is idempotent (`stopped`), and it is what normally resets the device: under the GPU lock, after the workers are joined.
  - `Driver::Shutdown()` would also rethrow a stored failure, so use `stop()` for the release.
- **In `CheckDriverPath`, on every return after `UseDevice`:**
  - the Windows queued-fill skip;
  - the normal return `0`.

  Before each, release the test's own reference (`device.reset()`) and then call `DriverTestAccess::Stop()`. That way the driver drops the last reference inside `stop()`, under the GPU lock, as at a normal shutdown, and `~VulkanDevice` runs before `main` returns.
  - **One small helper is fine,** for example `int ReleaseDriverDevice(std::shared_ptr<VulkanDevice>&, int result)`.
  - **Prefer explicit calls over a destructor-based guard.** A throw from `stop()` inside a destructor would terminate.
  - **The exception path:** a failing `Require` throws to `main`'s catch, and the test is failing then anyway. Leave that path as it is and say so.
- **Nothing else changes.** No product code, and no other test.
