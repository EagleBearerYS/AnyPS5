# PRM-082: #13551: start the save-data event delivery thread at the first registration, not in sceSaveDataInitialize3

from: AnyPS5 PR Manager
for: any
priority: high

## Why

oneandonlydean reviewed #13551 (https://github.com/boykopovar/AnyPS5/pull/13551#issuecomment-6531738605) and asked for two changes.

- **Request 2** (the register/final-terminate race) is what PRM-080 already fixed: `bc6b4d76f9` on fork `prm/13551-terminate-race`. Build on it and keep it.
- **Request 1** is this task. In their words: "Please start the delivery thread when a callback is first registered, not in `sceSaveDataInitialize3`. As it is, every title that initializes save data gets a new guest thread at startup, even though nearly none register a callback. `sceSaveDataInitialize3` can also now throw where it always returned 0, if `scePthreadCreate` fails there. Starting the thread at the first successful `sceSaveDataRegisterEventCallback` leaves titles that never register exactly as on `main`; the last `sceSaveDataTerminate` would still join it when one was started."
- They also asked us to keep callback reentrancy, and to keep the join outside the library lock.

## Start

Fork branch `prm/13551-terminate-race` at **bc6b4d76f9** (`bc6b4d76f90dab36a47bc06789c11aa4d81bbeca`). Stop if it differs. The code is in `core/libs/prx/libSceSaveData.native/Export.cpp`, and the tests are in `core/libs/tests/GuestSaveDataEventCallback.cpp`.

## What to do

1. **`sceSaveDataInitialize3` no longer creates the delivery thread.** It returns as it does on `main` and can't fail on thread creation.
2. **`sceSaveDataRegisterEventCallback` starts the thread.** A successful registration starts it if this initialization session has none running. That means after the `g_initializations` check, under the locks bc6b4d76f9 takes there: `calling` → `g_slots_mutex` → `callbacks.mutex`. Keep that order, and add no path that waits for `calling` or for the thread while holding `g_slots_mutex`.
   - **When no thread starts:** a re-registration, a registration from inside a callback, or a registration after an unregister in the same session all reuse the running thread.
   - **A failed registration** (NOT_INITIALIZED or PARAMETER) starts nothing.
   - **If `scePthreadCreate` fails** in registration, keep whatever the current code does on that failure in Initialize3. Don't invent an error code (docs/dev/CONVENTIONS.md's source rule), and don't add a test that asserts a throw.
3. **The last `sceSaveDataTerminate` joins the thread only if one was started,** outside `g_slots_mutex` as now. A terminate that isn't the last one joins nothing.
   - **Take the handle out** under `g_slots_mutex` in the detach. Then an `Initialize3` → `Register` that runs between a terminate's detach and its join starts a new thread without clobbering the handle being joined.
4. **Keep:** callback reentrancy (the recursive `calling` lock), the BUSY terminate from inside a callback, FIFO delivery, bc6b4d76f9's race fix and its `CheckRegisterRacingFinalTerminate` test.
5. **Tests**, in the same commit as the change:
   - **Init/terminate without a registration:** a case where `Initialize3` → `Terminate` → `Initialize3` → `Terminate` runs with no registration and returns 0 each time.
   - **Restart:** after a full terminate, a new session's registration still gets completions. `CheckIdleTerminateAndRestart` may already cover this; say so if it does.
   - **No thread before a registration:** if the guest API or an existing test helper gives a way to observe that no thread runs before a registration (e.g. a thread count or a lookup by thread name), use it, red on bc6b4d76f9 and green after. If none exists without a test-only hook, say so in the result and don't add a hook.
   - **The race path:** the test's racing registration now also starts the thread. Make sure `CheckRegisterRacingFinalTerminate` still asserts what it did, and passes.
6. **Debt:** if `docs/dev/debt/` text for libSceSaveData mentions the thread starting at initialization, update it in the same commit.
7. **Run:**
