## Why

The Grinch: Christmas Adventures (PPSA07656, 01.000.003) aborts ~2 s in on plain main 892a4f132, before its first present. BunnyFl's report: https://github.com/boykopovar/AnyPS5/discussions/8606

```
[gpu] driver failure: AGC graphics: native multisample stencil or depth format import is not implemented
```

**The target** (BunnyFl's print of the `DepthTarget` in `prepareDepthSampling`, `core/libs/prx/libSceAgcDriver/Graphics/src/DepthSurface.cpp`):
- `VK_FORMAT_D32_SFLOAT_S8_UINT`, 2 samples, 2560x1440, one slice, `Z_X`, `pipeBankXor` 0, clear depth 0;
- a **separate stencil plane** (`stencilAddress` set) and a **depth-only HTILE** (`htileStencil` 0, `htileDepthOnly` 1), pipe-aligned;
- the depth plane (0x1e00000 bytes), the stencil plane (0x780000) and the HTILE (0x48000), which don't overlap and are all accessible and watched;
- **every byte of the stencil plane equal to the clear stencil (0)** at that point.

**The next stop:** with only this case let through (his experiment, not kept), the title then stops in `CheckResource` (~DepthSurface.cpp:373 on main) when it samples the depth:
```
AGC graphics: native multisample depth sampled metadata or XOR mismatch
```
The sampled descriptor has no metadata (`dccAddress` 0, not pipe-aligned) while the target has its HTILE. `pipeBankXor` and `iterate256` match.

**Why #6300 doesn't cover it:** Gashrod1's #6300 (`fix/agc-native-msaa-d32s8-clear`, head c11074be82, 2 commits) imports D32S8 only with the stencil in HTILE, and it refuses a depth-only HTILE and an unaligned stencil plane. The user's decision: we do this fix ourselves, as a PR stacked on #6300.

## Changes (ours, the user's identity)

1. **`fix(agc): import native multisample D32S8 targets with a separate cleared stencil plane`.** In `prepareDepthSampling`, accept `D32_SFLOAT_S8_UINT` when:
   - the stencil is a separate plane (`stencilAddress` set, aligned as the depth plane must be; check what alignment the hardware layout needs) and the HTILE is depth-only (`htileStencil` false);
   - the depth plane passes the existing depth proofs (the HTILE clear proof);
   - **the stencil plane proves cleared:** every byte equals the target's clear stencil at import. Scan it once, about 7.5 MiB here.
   - The stencil range joins the import's ranges, the way #6300 adds its stencil plane: accessible, watched, generation-checked, guarded against guest publication, and not overlapping depth or HTILE. That way a later CPU or GPU write to it is seen like any other.
   - The host image's stencil is cleared to that value.
   - Keep every other refusal, with its own text: a stencil plane that isn't all clear, D16S8, and non-cleared states.
2. **`fix(agc): sample a native multisample depth target through a descriptor without HTILE`.** In `CheckResource`, accept a sampled resource whose address and format match the target's depth plane and that has no metadata (`dccAddress` 0, not pipe-aligned), while the target has its HTILE, provided `pipeBankXor` and `iterate256` match.
   - **Why it's sound:** we keep the decompressed depth in the host image, so a descriptor that reads the plane without metadata reads the same values.
   - A descriptor with *other* metadata keeps refusing.
   - If the hardware semantics need more (for example, the guest is expected to have expanded the depth before sampling without HTILE), check `DrawExpand`/out-of-place expand handling on main (our #6146 area) and state the assumption in the commit message.
