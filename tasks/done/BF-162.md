# BF-162: #9159's compared-when-shared mark must survive a full unmap and remap (GTA V's remaining zlib faults)
from: Bug Finder
for: any
priority: high

## Why

**#9159** (ours, ready, head 99aeb0ac56, fork branch `fix/agc-rewatched-imports-compared-when-shared`) stops arming shared views of memory that a rewatch or an import kept watched while it was resident. It does this with `WindowsMappings::CompareWhenShared`, which sets `SharedPage::comparedWhenShared`. Armed views make each guest store fault, and AnyPS5 resumes the fault, which can overwrite the guest's red zone (#361, #9136: Grand Theft Auto V (PPSA04264)'s zlib `inflate_fast` crash in the "[RAGE] HDD Streamer" thread).

tibzejoker reports a remainder with #9181 and #9159 ([comment](https://github.com/boykopovar/AnyPS5/pull/9159#issuecomment-6355849767)):
- In 2 of 4 seven-minute open-world runs (Windows, RTX 4090), zlib's `inflate_fast` (eboot 0x28aa5e0, 0x28aa8a2, 0x28aa8ab) still takes resumed write faults into `MEM_MAPPED` 16 KiB views, one per 4 KiB subpage, 3-4 per run instead of hundreds.
- Across about 15 runs, 2 ended in #9136's crash.

**A gap found by reading #9159's head:**
- The mark lives on `SharedPage`.
- `Map`'s `pageOf` lambda (`core/libs/prx/libc/include/WindowsMappings.hpp`, ~`:96-102`) takes the physical slot's **weak** `page`, and makes a fresh `SharedPage` with `comparedWhenShared = false` once it has expired.
- It expires when every view of that physical page is unmapped. So memory that was marked, fully unmapped and mapped again (at the same or another address, as a streamer's buffers may be) loses the mark.
- `Collect`'s re-arm loop (~`:455-465`, "arm shared memory write tracking") then arms its aliases on the next clearing collect.
- `MapAlias` / `mapAliasRuns` may have the same `pageOf` pattern. Check it.
