# BF-258: census v3: count live Vulkan pipelines and shader modules by owner, and probe their driver bytes

from: Bug Finder
for: any
priority: normal

## Why

Census v2 (BF-247's branch `diag/memory-census-v2-11580` d87bfc91f6) booted Resident Evil Village (PPSA01556) on the PC today. At a static menu, private memory is flat at 14.2 GB. The guest arena is 6.5 GB of that and the process heaps 3.0 GB. The largest class the census can't name is **4.0 GB of "unattributed private"**: 99 blocks of 16-64 MiB, 220 of 4-16 MiB, 391 of 1-4 MiB and one of 324 MiB.

It grew in step with the recompiler's variant count during the load (no game data here, just the census lines):

| variants | unattributed MiB |
|---:|---:|
| 906 | 705 |
| 3,311 | 2,647 |
| 4,974 | 3,712 |
| 4,980 | 4,005 |

After that it stays flat. That's about 0.8 MiB per variant, which suggests the Vulkan driver's own memory per compiled pipeline or shader module. The census can't confirm it: it shows only the graphics pipeline store (213 cached of a 1,024 bound) and the dispatch cache's 8,192 entries.

## Do

Work on top of `diag/memory-census-v2-11580` (fork, d87bfc91f6), or on `upstream/main` with census v2's commits cherry-picked. Add to the `[mem-census]` block. It's a diagnostic only and never goes to a PR.

1. **Live object counts by owner:**
   - graphics `Pipeline` objects (store, draw-cache variants, anything else that holds them);
   - compute pipelines (dispatch cache, others);
   - pipeline-library parts;
   - **live `VkShaderModule` handles**: where `Pipeline.cpp` keeps `_modules` until destruction (L505, L724 on main), and every compute or other path that keeps a module past pipeline creation.

   Count them at the census point under the census lock, or with atomic live counters on create and destroy.
2. **Per-object driver bytes:** as the descriptor-pool probe does, create one probe pipeline (and its module) from a representative live variant of each kind under the census lock. Measure the process's private-bytes delta, destroy it, and scale by the live counts. Print an estimate line:
   ```
   [mem-census] pipelines (driver memory): graphics N live (store A, variants B), compute M live, modules K live; probe +X KiB per graphics pipeline, +Y per compute, +Z per module; est T MiB
   ```
3. **Code reading, in the result:** which owners keep modules alive after pipeline creation, and whether destroying them right after `vkCreate*Pipelines` is allowed. The Vulkan spec allows destroying a module once the pipelines are created (pipeline libraries excepted). Name the lines that would change. **No fix in this task.**
