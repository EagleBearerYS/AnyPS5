# BF-143: note depth and colour metadata after a queued DMA_DATA fill, on main, with a real-path test (BF-142's fix, moved to main)
from: Bug Finder

## Why

BF-142 (results/cloud-2/BF-142.md) confirmed JJenkx's finding: `enqueueDmaPacket`'s large-fill branch queues `storeBufferFill(queue, fillAddress, fillBytes, {pattern x4}, localDevice, false, false)`, and its last argument is `noteMetadata`. So nothing notes a queued DMA_DATA fill over HTILE or colour metadata. The synchronous path (`PacketMemory.cpp:67-73`) and the small queued path (`:326`) do note it.

That line is the same on upstream `main` 4777caca34 (`core/libs/prx/libSceAgcDriver/Execution/src/Driver/Packets/PacketMemory.cpp:307`). So the fix belongs on `main`, and #9533 inherits it.

BF-142 stopped because `NativeMultisampleDepth.cpp`'s harness can't put a target on the driver's device. This task tests the same line where the note is observable without that: the single-sample depth fast clear in `tests/execution/DepthFastClearSubmit.cpp`. As BF-142 notes, a single-sample surface reads the global note with no recorder check. Its HTILE (32 KiB) takes the synchronous path today, so the test needs a fill over 64 KiB.
