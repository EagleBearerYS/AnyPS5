# PM-032: image tables: make an unchanged column's reuse O(1) (share the memo's column instead of copying it), PR-ready
from: AnyPS5 Project Manager
for: any
priority: high

The user, 2026-10-14: "I need ALL the performance i can get on re8". PM-028 (the user's idea) skips the guest-memory read of an image-table column while its memory is unwritten. In PM-028's microbenchmark (results/cloud-3/PM-028.md §3), an unchanged capture still costs a lot with 0 words read:

| case | main | PM-028 |
|---|---|---|
| 32,768 keys, all distinct T#s | 6,007 µs | 478 µs |
| 32,768 keys, 16 distinct T#s | 2,231 µs | 393 µs |
| 65,536-record heap, all distinct | 15,355 µs | 997 µs |

Resident Evil Village misses its draw cache on nearly every draw, and its 26 lane-keyed shaders capture whole tables. So hundreds of µs per capture is still a large share of its queue-0 worker. This task removes what's left. It's our own code, stacked on our own PR branches. No PR; the PC opens it after Village numbers.

## Tasks
1. **Where do the 478 µs go?** Profile PM-028's benchmark: the dropped bench commit `f42558c9e8` on `perf/shader-image-table-unwritten-reuse`, applied locally only. Use `perf` or scoped timers on an unchanged 32,768-key capture.
   - Break it down. Candidates: copying the memo's words, per-record codes and distinct T#s into the capture's snapshot; rebuilding per-record resolution; the memo key hash and compare; `CollectWrites` / `UnchangedSince` over the ranges; the draw-cache compare of the captured words.
   - Give µs per part.
2. **Make the unchanged case O(1) in table size**, where sound. For example:
   - the capture refers to the memo's immutable column, through a shared, reference-counted, never-mutated column object, instead of copying it;
   - resolution results are reused by reference;
   - the draw cache compares two captures' whole-table columns by identity (same column object and generation) before falling back to the word compare.
   - Keep every PM-028 vouching rule exactly: stamps, pending GPU writes, flush before vouching, the guest mapping generation.
   - Memory stays bounded: the memo's limits still apply, and a shared column lives only while a capture or the memo holds it.
   - Thread safety: several queue workers capture at once. The memo is per thread today, so say what sharing changes.
3. **Tests**, in the same commit as the change or after it:
   - an unchanged table reused twice shares one column, with no copy (a counter);
   - a CPU write, GPU write, DMA fill, pending GPU write or unmapped memory between captures still gives fresh words, and the old shared column stays valid for the capture that holds it;
   - the draw-cache identity compare never matches two different contents;
   - PM-027's, PM-028's and the existing image-table tests, `agc_shader_table_snapshot_reuse` (watched and `APS5_NO_WRITE_WATCH=1`), and the full `^agc`.
4. **Benchmark** before and after, on the same cases as the table above plus the worst case: a store before every capture. Give µs and words per capture.
5. **Overlaps:** open upstream PRs on ResourceMaterializer, TableSnapshotter, ShaderMemory and the draw cache (#1193, #1201, #1202, #5181 follow-ups and anything newer), plus Celegans12's and SleglJan's public branches (read them for overlap only; copy nothing).
