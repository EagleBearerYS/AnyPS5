## Why

The profiled Resident Evil Village (PPSA01556) menu boot on fork `diag/village-c4-sites-on-306fc4cfb4` (c44f582bb4) puts the frame's chain on the resource build inside each draw commit, under the GPU mutex.
- **The committer:** it holds the mutex 6.9 s of every 10 s, about 0.9 ms per draw.
- **The build:** stage B is 631 us per build, 548 us of it `images`.
- **The storage round trip inside it, per 10 s:**
  - 363-379 storage-refresh write-backs (1.5 GB);
  - 113-118 flushed CPU uploads (1.5-1.6 GB);
  - 786-814 shadow retiles (2.2 GB);
  - 0 bytes on the device alias path.
- **Why the alias path takes nothing:** `[storage-alias]` refuses all 42 pairs as "base differs" or "size differs". The pool is format 36, tile mode 7 and 64 KiB-aligned, for example the 960x1080 (4 mips) / 1920x1080 pair. That's the case BF-308's commits (#13251's 1fc6a02b34 + aade147005) take one tile at a time.

The PC needs one tree with both, to profile it on Village.
