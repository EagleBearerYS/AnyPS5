## Why

BF-148 (results/cloud-4/BF-148.md) added fix 1 on #9457: one V# behind a record pointer may feed several T# handles. Its fork branch is `fix/shader-nested-table-shared-vsharp` = 0e78959001.

Spider-Man 2's real shader also moves T#2's dwords 0/1 into the pointer registers (hugodearaujo's IR, https://github.com/boykopovar/AnyPS5/pull/8939#issuecomment-6340144242: `%10988`/`%10989` into the Phis `%11182`/`%11181`). With fix 1 alone the title still stops at 0x8fa0, as BF-148's reuse variant shows. T#2's reads have Phi users, so the sibling fails `DescriptorWordReads`, and T#2 would refuse at `:739`.

BF-148 found why the `:739` check exists (commit d132754dbe):
- the T# read stays real when it has other users (`ResourceTracker.cpp:1770-1781`);
- but `Run()` rewrites its V# handle (`:154-160`);
- and the V#'s word loads become planning-only, so they aren't emitted (`SpirvMemoryInstructions.cpp:599-601`).
- So the kept read addresses a V# that only the snapshot holds. lavapipe segfaults.

BF-148's description of what taking it needs: "an unrewritten copy of the `GetBufferResource` for the kept reads, plus real loads of its four words through the record pointer, which are then no longer planning-only. In turn, the record-pointer reads must stay real and their hop reads must not be marked planning-only. The extra users would then read the guest's real T# words, while the descriptor handles take the snapshot."

This task does that.

2. **The change** (ResourceTracker.cpp, plus SPIR-V emission only if it's needed):
   - when a planned nested child's T# or S# read has users other than its descriptor handle, give those users the read through an unrewritten copy of the V# `GetBufferResource`;
   - keep that copy's four word loads, and the record-pointer reads and hop reads they depend on, as real (not planning-only) instructions;
   - the descriptor handles still take the snapshot.
   - Refuse anything else as before. That includes a V# whose words can't be re-read at run time, for example a V# that exists only in the snapshot.
3. **Safety controls**, which must still refuse:
   - a T# word with a use whose V# comes only from a snapshot-only source;
   - a handle with a data read through it (fix 1's existing refusal).
4. **Debt:** update #9457's "Nested image tables" line for what's accepted now, and that such reads re-read the guest's V# at run time.
