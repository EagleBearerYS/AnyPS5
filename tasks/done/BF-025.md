# BF-025: prototype: let a GPU-side indirect draw continue the open render pass when its records need no barrier (throwaway, lavapipe numbers)
from: Bug Finder
for: any
priority: normal

## Why

BF-022 (cloud-3, fork `exp/agc-indirect-gpu-draw-parameters` e280ce9d5) found that main's GPU indirect path records the argument barrier outside the pass, and begins a new render pass for every indirect draw.
- In its soak: 44,096 passes begun and 0 continued, against the CPU path's 2,595 passes for 163,486 continued draws.
- At one record per packet, that made the GPU-side packet cost more than the CPU path: `Graphics::Draw` 41-57 µs against 20, and wall time 68-91 µs against 49-65.

This applies to every title whose indirect draws already go GPU-side on main, not only to draw parameters. The architecture proposal lists it as stage 1's next step.

## What to build

On fork branch `exp/agc-indirect-gpu-pass-continue`, from e280ce9d5 (BF-022's head, so the numbers compare):
1. **Find where main's GPU indirect path breaks the pass:**
   - the argument barrier (the records' writes made visible to `VK_ACCESS_INDIRECT_COMMAND_READ_BIT` / `DRAW_INDIRECT`);
   - the `Constant` rewrite (a scratch copy plus `vkCmdUpdateBuffer` per record);
   - whatever else ends the pass for it.
   Say which one forces the new pass in BF-015's harness, for each of its two setups.
2. **Skip the barrier when nothing wrote the records since an earlier one,** so the draw continues the open pass like a CPU-path draw. "Nothing wrote them" must cover:
   - writes by an earlier dispatch, copy or `vkCmdUpdateBuffer` in the same recorder batch;
   - host writes the recorder already flushes;
   - a later batch that rewrites the records.
   If a range is ambiguous, keep main's barrier. A missing barrier is a wrong draw, while an extra one only costs a pass.
3. **The `Constant` rewrite:** with draw parameters that dimension no longer shapes the stage (BF-022's note). See whether such a draw can read its records in place, with no scratch copy, when the stage has no attributes at that dimension's rate and the device has `drawIndirectFirstInstance`. If that's more than a small change, leave it and say so.
4. **Count it.** The `[draws]` profile line should give, for GPU-side indirect draws, passes begun against continued and barriers recorded against skipped.

## Checks

1. **Correctness, new tests:**
   - two GPU-side indirect draws in one pass whose records a dispatch wrote before the pass: one barrier, one pass;
   - records rewritten by a dispatch, or by `vkCmdUpdateBuffer`, between the two draws: the pass must break and the barrier must be recorded, and the image must show the second draw's new records;
   - a record range written by the host between batches.
   Red when the skip ignores each kind of write in turn.
2. **No regressions:** `ctest -R '^agc'`; BF-022's `agc_driver_indirect_draw_parameters` ×10; the new tests ×10.
3. **BF-015's harness,** both setups, 1, 8 and 64 records:
   - wall time per packet (median of 9) and driver phases, against BF-022's table;
   - passes begun and continued.
