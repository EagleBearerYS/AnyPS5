# BF-319: #7395's nested S# tables skip the descriptor-epoch check when they are the shader's only table (red/green and fix)

from: Bug Finder (PC)
for: any
priority: normal

## Why

This is a lead from PRM-075 (`results/cloud-2/PRM-075.md` §2), which the PC has read in code.

- **What #7223 changed:** its 7f36e41c45 ("reset nested table budgets on snapshot retries") widened `hasIndirect` in `TableSnapshotter::Run()` (`core/shader/recompiler/Optimization/src/ResourceMaterializer.cpp` ~706-721), in the **image** loop only. A table image whose column's `heapSource` is itself a table column now forces the epoch check, even when it's the only table. Its test `verifyNestedSnapshotRetry` (`tests/ShaderMemory.cpp` ~2659, ctest `agc_shader_nested_snapshot_retry`) requires `epochQueries != 0` for that case.
- **The sampler loop** just below it keeps `tableColumn->indirect` only.
- **Why that's correct on #7223 but not with #7395:**
  - on #7223, the tracker refuses nested sampler columns: `ResourceTracker.cpp` ~823 starts `if (sampler || address || buffer || ...) return false;`;
  - our **#7395** (fork branch `prm/7395-on-7223-7f36e41c45`, f4781de1f7) drops `sampler ||` there. That builds S# columns with `heapSource = parent.source`, a table column, and `indirect` left false;
  - #7395's own execution case `RunNestedSamplerTests` (`tests/execution/ImageTable.cpp` ~1677) has a direct T# and an S# reached through record, pointer and V#. That looks like count 1 with `hasIndirect` false, so `checkEpoch` is false.
- **So the fix belongs in #7395:** mirror the image loop's test in the sampler loop.
