## Why

With `APS5_GPU_PATH=1`, a draw that is not recorded and whose stages read images through the device image table aborts in `Graphics::Draw` (Draw.cpp ~2404):

    a draw outside the recorder reading images through the device image table is not implemented

- **Which draws aren't recorded:** synchronous draws. That means a non-resident target, stencil replay with fault checks, or a debug switch (`APS5_SYNC_COMPLETION_DRAWS`, `APS5_NO_RECORDER_SYNC_DRAWS`, a dump limit).
- **Why the device path can't serve them:** it needs the recorder, because the miss ring is per recorder batch, and a key's first use misses.
- **Failures it causes today, with the switch on:**
  - LA-005's four: `agc_driver_heap_draw_sample`, `_heap`, `_nogpl` and `_nogpl_heap`;
  - since LA-010, Raghav314's two new tests: `agc_driver_heap_draw_sample_full_heap` and `_full_heap_pipelined` (`results/cloud-5/LA-010.md` §2).
- **Why it matters even though Village has none:** Village's `[draws]` lines show 0 synchronous draws, but other titles and the tests reach this path. As it stands, the lane A PR would have to state the limitation.

   - don't mark the program as fallen back;
   - the next recorded draw of the same program keeps the device table.
2. **Pick where to decide it.** Report both options' cost, and pick the one that keeps the change smallest and inside lane A's code and the draw path.
