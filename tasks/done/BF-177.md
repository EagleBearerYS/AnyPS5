# BF-177: let image tables over snapshots outside the write watch be reused, revalidated by their untracked key
from: Bug Finder (2026-10-23 01:5x PT)
for: any
priority: normal

## Why

Resident Evil Village (PPSA01556), profiled at the static menu on Windows (lane F tree 12aa911767, but the same gate is on main):

    [textures] ... stage-A records 105941: 101214 fast hits, 4727 full lookups; ... image tables 0 reused, 46055 resolved (refused at their first entry: view 0, keys 0, generation 0 13745, last lookup not this texture 0); untracked snapshots 102779 kept by the write-watch hint, 538 compared

- **Most sampled textures are snapshots over memory outside the write watch** (host imports). They're kept by the untracked key (`untrackedKey()`, `ShaderResources.cpp` ~629 on main: the write-watch hint, the newest stamp, the forget serial and the recorder's newest write note). Their lookups log `generation 0`.
- **Image-table reuse requires a non-zero generation** (`ShaderResources.cpp` ~5124 on main: `... && looked->generation != 0 && ...`). That's because a kept table is revalidated by `TableCurrent` (~1792) through `GuestMemory::UnchangedSinceAll(table.queries)`, which only works for watched memory.
- **So in Village not one table is reused,** and every draw resolves its tables in full (46,055 per 10 s here). That's per-draw CPU on the main speed track.
- **The snapshot cache already trusts the untracked key** for the same textures: `kept()` ~888, `it->untracked == untracked && !Recorder::SnapshotWriteOverlaps(address, bytes)`. A table entry can be revalidated the same way.

## What to do

1. **The change, in `ShaderResources.cpp`:**
   - **Logging:** where a sampled lookup is served from a snapshot kept by its untracked key, log that key in the `LookupRecord`, in a new field next to `generation`. Cover both the full path (~898) and the stage-A fast path (~4603), if the fast path can serve such entries; check.
   - **The gate (~5124):** accept an entry with `generation == 0` when its lookup logged a non-zero untracked key. Keep every other condition as it is (`object`, `source == nullptr`, `keys == Uncompressed`, `dccAddress == 0`).
   - **The table:** keep per entry either its generation query (as now) or its range and untracked key.
   - **`TableCurrent`:** for each untracked entry, recompute `untrackedKey(address, bytes)` and require it equal to the kept key, plus `!Recorder::SnapshotWriteOverlaps(address, bytes)`, exactly as `kept()` does. Watched entries keep `UnchangedSinceAll`.
   - **When the hint is missing** (`untrackedKey` returns zeros, for example `CollectEpoch() == 0`): the entry refuses reuse, as now.
   - **The profile line:** the refusal counter still classifies refusals. Add one count, "untracked entries kept", to the `[textures]` line behind `APS5_PROFILE_DRAW`.
2. **Tests** (red = the new case with only the gate/revalidation hunks reverted):
   - **(a)** a table of N sampled entries over memory outside the write watch. Use `APS5_WRITE_WATCH_IMPORTS=unwatch`, or whatever main's tests use to put a texture in an unwatched import. Two identical draws: the second reuses the table (`tablesReused` +1).
     - Red: 0 reused.
   - **(b)** the same, with a CPU write to one entry's texels between the draws (`GuestMemory::Write`). The table must not be reused, and the draw must sample the new texels.
     - This is the safety case: green on both trees.
     - Also show it fails if `TableCurrent` skips the untracked check (a mutant), to prove the test bites.
   - **(c)** a recorded GPU write over one entry's range between the draws: not reused.
   - **(d)** watched-memory tables behave exactly as before.
3. **Cost, on the cloud:**
   - Use fork `exp/descriptor-set-release-measure`'s `tests/execution/VillageDrawCost.cpp` harness, ported to this branch's base if needed, with its textures forced outside the watch.
   - Measure CPU per draw, main against the head, unsynced (as the harness's notes say), 3 runs each.
   - Report the reuse count and µs per draw.
   - Take any GPU number only with `VILLAGE_GPU_SYNC=1`.
