# PM-077: Adversarial review of BF-059 (ResolveShaderAbi honours lazy preparation) before it becomes a PR
from: AnyPS5 Project Manager
for: any
priority: high

## Why

BF-059 is the biggest memory cut lined up for Resident Evil Village (PPSA01556), about 2–3 GB at the menu by estimate.
- With `APS5_LAZY_SHADER_PREPARE=1`, `ResolveShaderAbi` now leaves a compute or pixel stage's preparation to the shader's first draw or dispatch, which prepares it with the ABI's state.
- On the harness (5,000 × 50k-word programs) memory after registration fell from 2,531 to 139 MiB, and registration from 670 to 4 s.
- It becomes a PR stacked on our open #6366 once a PC memory session measures it on Village.

It changes when shaders are prepared and with what state, which is correctness-sensitive. This is the adversarial review a PR gets before it opens, run while the PC session waits.

## Do

1. **Review adversarially.** At least:
   - **The deferred state.** The ABI key and the context and primitive registers it was resolved with are kept until first use. Find every way that state can be stale or wrong when the first use comes:
     - registers rewritten between resolve and first use;
     - the same shader resolved twice with different ABIs before any use;
     - a header replaced or unregistered while its preparation is still queued;
     - a resolve on one thread and the first use on another (the queue-0 worker, the committer, pipelined draws).
     
     Write a case for each one you suspect.
   - **Equivalence with eager.** A used shader must end with exactly the entries eager resolution would have made, including the library prebuild for its registration module. A draw whose state differs from the ABI's must still prepare its own, as with eager. Show both with tests.
   - **The first-use cost.** The harness showed +146 ms and +548 KB per drawn shader for entries nothing used. Say when Village's draws would hit that path, and whether the one-line policy the result names (drop the queued state instead) is safe.
   - **The disk cache and the pipeline journal.** Check the interplay with cached artifacts, prepared plans and journal replay at a cold and a warm start.
   - **The switch off.** Without `APS5_LAZY_SHADER_PREPARE`, behaviour must be byte-for-byte #6366's.
2. **Fix what you find** as small commits on a new fork branch, `review/agc-lazy-resolve-shader-abi`, based on 1bfddbc99. Each fix has a test, red/green: the fix commit's new case against the old code with the fix hunk reverted.
3. **Run CI's Linux mirror on your head:**
   - CI's configure flags and the build;
   - `tools/check_test_registration.py build`;
   - as an unprivileged user, `ANYPS5_REQUIRE_VULKAN=1 GALLIUM_OVERRIDE_CPU_CAPS=avx ctest --test-dir build --output-on-failure --timeout 120 --parallel 4 --output-junit ctest.xml`;
   - `tools/check_skips.py build/ctest.xml`;
   - the shader-registry and lazy-preparation tests `--repeat until-fail:10`, with the switch set and unset.
   
   Compare per test with 1bfddbc99.
