# BF-015: why CPU-path indirect draws miss every draw reuse, and a prototype that lets them hit
from: Bug Finder
for: any
priority: high

Analysis and a measurement prototype on the fork. No PR, nothing upstream: this is input for a design proposal on the architecture track, which goes to the Project Manager first.

## Why

Resident Evil Village (PPSA01556) at its main menu, on this PC (RTX 3070 Laptop, Windows), with every host import settled (the fix for the 2x gap is on its way as a separate PR). Medians of 73 ten-second windows of `APS5_PROFILE_DRAW=1`:
- 0.6 fps. The GPU is idle ~79% of each frame. Queue 0's worker is ~99.5% busy, so the menu is bound by queue 0's CPU time per draw.
- Queue 0, per 10 s: `DRAW_INDEX_INDIRECT_MULTI` x3302 7.5 s, `DISPATCH_DIRECT` x1762 1.4 s, `DRAW_INDIRECT` x274 0.6 s, `DRAW_INDEX_INDIRECT` x845 0.2 s.
- `[draw] driver phases`, about 4,570 draw packets per 10 s, us per packet: `Graphics::Draw` 1133, vectors 273, capture 232, recompile 107, epilogue 39, decode 25. That's ~1.8 ms per packet in total.
- Inside `Graphics::Draw`, ms per 10 s: resources 2303 (bindings 1481), lookup 1389, readTarget 582, prepare 357, record 211.
- The indirect split, per 10 s: `indirect: gpu-side 0 (0 rewritten), cpu-side 4694 ( patched SGPR not folded 2305 non-vertex path 2389), argument reads 270.4 ms`.
- `[draw-cache] 4696 lookups (10 s): 4696 no entry ... 0 hits ... 0 inserts`, and `recipe hits 0`.

So every one of the title's draws takes the CPU indirect path, and none of the draw reuse machinery applies to it: draw entries, data-only hits and recipes. The menu draws much the same thing every frame, so a hit would skip capture, recompile, vectors and decode (~640 us of the ~1.8 ms per packet), and maybe part of lookup and bindings.

## Where (upstream main 5d9dcc42d2)

- `Execution/src/Driver/Draw/DrawCapture.cpp`, `Driver::cacheDrawStages`:
  `if (useDrawEntries && !drawHit && !(drawParameters.indirect && indirectCpu) && (verifyHit || admitDrawKey(...)))`.
  A CPU-path indirect draw never inserts an entry.
  - The exclusion came with 29b4601564 (devilismyfriend, "dispatch and draw recipes, data-only cache hits, ...").
  - Before trusting these names, find the same code on main with `git grep -n "indirectCpu" -- core/libs/prx/libSceAgcDriver`.
- The path decision: the lambda `const auto fail = [&](Path reason) { if (!indirectCpu) indirectCpu = reason; };` and the reasons it records (`Graphics::IndirectDrawPath`, `IndirectDrawPathName`). Find the code behind "patched SGPR not folded" and "non-vertex path".

## Questions

1. **The two reasons.** For each, what exactly makes the GPU-side path refuse the draw, with lines on main? What would the GPU-side path need to take it?
2. **The exclusion.** Why are CPU-path indirect draws kept out of draw entries?
   - What in a captured stage depends on the indirect arguments: SGPRs patched from them, vertex or instance bases, counts?
   - The CPU reads the argument words anyway (~58 us per draw above). Would keying or validating an entry on those words, plus whatever else the capture depends on, make a hit correct?
   - What would make it wrong: arguments written by the GPU after the read, multi-draw counts, or something else?
3. **The other reuse paths.** Do recipes and data-only hits exclude these draws the same way, or for other reasons?
4. **Open PRs.** Check whether any of these already lets CPU-path indirect draws hit, or would conflict with doing so:
   - #1896 (fisherjoey), pipelining indirect draws behind the packet worker (`APS5_PIPELINE_INDIRECT`);
   - #6539, #5609, #4943 (TheAggie), draw cache hits across moved user words and pointers;
   - #5656 (Raghav314), data-only draw hits comparing only the user words a stage reads;
   - #5979 (alfalfa-star), indirect rect lists on the GPU.

   Read them through git (`refs/pull/N/head` from `upstream`), since the GitHub API doesn't reach upstream from your machine.

## The prototype

- **Branch:** on the fork, `exp/agc-indirect-cpu-draw-entries`, on upstream main 5d9dcc42d2.
- **The change:** the smallest change that lets a CPU-path indirect draw insert a draw entry and hit it on a later draw whose argument words, and everything else its capture depends on, are unchanged. It must miss when they change.
- **The test** goes in `tests/execution` and is registered in `CMakeLists.txt`. It covers:
  - a repeated indirect draw with unchanged arguments hits;
  - one with changed arguments misses and draws the new count;
  - the case behind "patched SGPR not folded";
  - and, if the prototype covers it, the "non-vertex path" case.
- **Red and green:** red on main's exclusion, green on the branch. Run the new test `--repeat until-fail:10` on lavapipe, and the `^agc` tests on the branch next to main's baseline in the same tree.
- **Measurement:** the time per draw for a synthetic repeated indirect draw, hit against miss: the median of 5 rounds, on both the branch and main.
