# PRM-036: why titles ignore ANYPS5_OUTPUT_RESOLUTION, and the smallest change that makes one render at the configured size
from: AnyPS5 PR Manager
for: any
priority: high

## Why

Fork branch `feat/videoout-output-resolution` (head **35f4fe60a0**: three commits from PM-015 plus a merge of upstream main 0906c64501) adds `ANYPS5_OUTPUT_RESOLUTION` (1280x720, 1920x1080, 2560x1440, 3840x2160). With it set, `sceVideoOutGetResolutionStatus` reports that size and `sceVideoOutGetOutputStatus`'s resolution class follows it (`Output.cpp`, `reportedResolution`). Main reports 1920x1080 / class HD until display buffers are registered, then their size.

On this PC tonight (text only, no game data leaves the PC), no title followed it:
- Animal Well (PPSA22520), at 1280x720 and at 2560x1440: the branch's own line `[videoout] display buffers registered at 3840x2160 although ANYPS5_OUTPUT_RESOLUTION reports 1280x720; they are presented and scaled to the window as before`, then only 3840x2160 presents.
- Planet of Lana (PPSA19450), same settings: it first registers **1920x1080** display buffers early in boot (`[mouse] video driver windows: guest 1920x1080 presented at ...`), then registers **3840x2160**, which stays for the rest of the run. The same two sizes appear on plain main.
- Resident Evil Village (PPSA01556) also registers 3840x2160.

This matters beyond the setting: the FSR presentation scaler (fork `feat/agc-fsr1-upscaling`) can only show its upscaling on a title whose display buffer is smaller than the window, and the setting is how a user would get one. Both stay held until a title follows the setting.

Remotes: `origin` is the fork EagleBearerYS/AnyPS5; `upstream` is boykopovar/AnyPS5 (fetch only).

## What to find

1. **Every way a title can learn the output size or capability** from our libraries, and what main and the branch return for each. Start with the libSceVideoOut exports: `sceVideoOutIsOutputSupported`, `sceVideoOutConfigureOutput`, `sceVideoOutInitializeOutputOptions`, `sceVideoOutGetOutputStatus`, `sceVideoOutGetOutputStatusWithVrr`, `sceVideoOutGetResolutionStatus`, `sceVideoOutAddOutputModeEvent` with `sceVideoOutGetEventData`/`GetEventId`, `sceVideoOutAllowOutputResolutionWqhdDetection`. Then anything else that can carry it: libSceSystemService parameters, libSceAgc/libSceAgcDriver GPU or display queries, and the open parameters. For each, file:line on main and on the branch.
2. **The likely title sequence.** Lana's 1080p-then-4K pattern suggests it registers at the size first reported, then re-registers after learning 4K is available (an output-mode event, `sceVideoOutIsOutputSupported` for a 4K mode followed by `sceVideoOutConfigureOutput`, or the status changing once buffers exist). Find which paths can produce that, using the public references for these calls' types and semantics (SharpProspero's VideoOut types, shadPS4's and KytyPS5's equivalents), and say which you think is most likely and why.
3. **A harness**, as a guest test in the style of `core/libs/tests/GuestVideoOutOutputResolution.cpp`, that plays each plausible sequence (open, query support or status, configure, register) and prints what each call returns on the branch with the setting unset, at 1280x720 and at 2560x1440.
4. **The smallest exact change** that makes a title following that sequence register at the configured size: for example, the setting making `sceVideoOutIsOutputSupported` report only modes up to it and `sceVideoOutConfigureOutput` refuse larger ones, as a console attached to a display of that size would. Implement it with its test in the same commit, on a new fork branch `followup/videoout-output-resolution-prm036` on top of 35f4fe60a0. Where the console's behaviour isn't known from a public source, don't guess: refuse, and say so in the debt entry (`docs/dev/debt/libSceVideoOut.md`).
5. **What the setting cannot reach**, stated plainly: for example, a title that always picks 4K and scales internally. That sentence goes into the PR as written.

If knowing exactly which VideoOut calls these titles make would settle it, say so in the report: this PC can boot them once with call tracing (`APS5_TRACE_CALLS=libSceVideoOut`) and send back the call list.
