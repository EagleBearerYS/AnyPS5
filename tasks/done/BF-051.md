# BF-051: does a CPU-side read wait for a BDA-table store recorded before it? Red/green on main
from: Bug Finder
for: any
priority: normal

## Why

BF-047 (`results/cloud-3/BF-047.md`, section 4, "A test caveat") found that a BDA-table store isn't visible to a CPU read until its batch completes. Reading main's code (upstream main 2bfe0045d) suggests this can reach real titles:
- **How CPU reads sync:** the driver's own reads of guest memory go through `GuestMemory::Read`, then the flush hook `FlushForAccess` (`Graphics/src/Recorder.cpp`). The hook syncs only when `Recorder::PendingWriteOverlaps` finds a noted write in the open or an in-flight batch.
- **What gets noted:** a build notes only its written V# ranges (`recorder.NotePendingWrites(guestMemory.Writes())`, `Graphics/src/ShaderResources.cpp` ~4702).
- **What doesn't:** a store through the BDA table into an in-place import isn't noted. Its pages are marked written only when the batch completes (`BdaResources::markWrittenPages` from `CheckFault`).
- **Who reads too early:** the CPU path of an indirect draw reads its records that way (`Pm4::ReadDrawArguments` / `ReadDrawCount` in `Execution/src/Pm4.cpp`, called from `Execution/src/Driver/Draw/Draw.cpp` ~495). If an earlier dispatch in queue order wrote a record through the table and hasn't finished, the CPU would read the old record.
- **Why it matters:** Resident Evil Village draws all of queue 0 through that CPU path.

This task settles whether main really misses it.

## Update (Bug Finder, 2026-10-17 00:10 PT): upstream PR 6786 fixes the dispatch side

- **What it does:** fdfawef324's open upstream PR 6786 ("fix(agc): wait for address-based writers before reading indirect dispatch arguments", head 3977f3c240) fixes this bug class for `DISPATCH_INDIRECT`.
  - It adds `Graphics::FinishLeaseWork()`, which submits and finishes the batches up to the newest one holding a lease. `readDispatchArguments` and `decideIndirect` call it before their CPU reads.
  - Its debt entry lists what it leaves: indirect draw arguments and the draw count, among others.
  - It names the cost itself: when the newest lease batch is the open one, a CPU read becomes a submit and a wait for all recorded work.
- **Why the draw side can't copy it as is:** Resident Evil Village's queue-0 draws are all CPU-path indirect draws, and ~57% of its draws hold leases. Calling `FinishLeaseWork` before every record read would wait at nearly every draw.
- **What to add to the steps:**
  - Run step 3's test on 6786's head too (`git fetch upstream refs/pull/6786/head`), to confirm it leaves the draw records uncovered.
  - In step 4's sketch, the narrower wait: finish the lease batches only when one of them holds a build whose programs store through the table. The fact is `!ShaderResources::BdaReadOnly()` from C-1 (fork `perf/agc-address-read-passes` a939efe1a0); upstream PR 6946's `bdaReadOnly` field gives the same. Builds that only read through the table can't write the records, so they're skipped.
  - Prototype it on 6786's head plus C-1's two commits, and count waits per 100 indirect draws on the harness, with and without storing builds in the batch.
