**The commit message:**

```
perf(agc): count a draw-cache window with only key sightings as low

A 2048-lookup window now also counts as low, toward the draw-cache
bypass, when none of its lookups was a whole-draw hit, a verify hit or a
stage reused through data candidates (a stage variant of a same-shape
cached draw that validated equal). Draw keys seen before still count as
useful lookups, but sightings alone no longer keep a window out of the
low run. A window with any of those reuses keeps today's rule: it is
low only when fewer than the bypass percent of its lookups are useful.

DrawCacheBypass::Note takes the reuse separately from usefulness and
keeps one bit per window for it. The [draw-cache] bypass line and the
APS5_DRAW_CACHE_BYPASS_PERCENT entry in ENVIRONMENT.md describe the new
rule.

agc_driver_draw_cache_sightings_bypass draws two windows of key pairs
whose used user words change every pair: each second draw is a sighting
that the cache admits, with no hit and no reused stage, and the draw
after them is bypassed. agc_driver_draw_cache_rare_hits keeps the cache
looked up through windows of such sightings with about 1% real hits.
```

## The change

**Library: BF-333's diff, with the second `Note` argument as the task asks.**
- **Signature:** `DrawCacheBypass::Note(bool useful, bool hit)`.
- **The hit bit:** `HitShift = LowShift + LowBits` (bit 27) holds `HitBit`, whether any lookup in the current window was a real use. The window's close writes only the streak and the bypass length, so the bit starts clear in each new window.
- **The `static_assert`:** now `HitShift < LeftShift`.
- **At a window's close:** `low` resets only when `usefulLookups >= minimumHits && hits`. Otherwise it advances, as before.
- **Unchanged:** `minimumHits == 0`, `LowWindowsToBypass` and the lengths.

**The call site** (`Execution/src/Driver/Draw/Draw.cpp` ~660) computes the candidate test once:

```cpp
if (stageEntries) {
    const bool reuse = drawHit || verifyHit || std::any_of(dataCandidates.begin(), dataCandidates.end(), [](const auto& candidates) { return !candidates.empty(); });
    drawCacheBypass.Note(reuse || drawKeySeen(drawKey), reuse);
}
```

The first argument is the same value as before, with the same short-circuit before `drawKeySeen`. The second argument is the real use.

**Two text updates, so they keep describing the rule:**
- **The `[draw-cache] bypassed` line** (`DrawCacheStatistics.cpp:81`) now reads "useful lookups stayed under %u%%, or none hit a draw or reused a stage, for two or more windows in a row". No test matches that text.
- **The `APS5_DRAW_CACHE_BYPASS_PERCENT` row in `docs/dev/ENVIRONMENT.md`** describes the low window: under the percent of useful lookups, or no whole-draw hit and no stage reused from a same-shape cached draw.

**Tests** (`tests/execution/DrawCacheReuse.cpp`).

- **Existing cases:** the 11 `Note(x)` calls became `Note(x, x)`, as in BF-333. No other line of an existing case changed.

- **Red: `SightingsAloneBypassTheCache`, mode `--sightings-bypass`.** Registered as `agc_driver_draw_cache_sightings_bypass`, plus `_sightings_bypass_off` with `APS5_DRAW_CACHE_BYPASS_PERCENT=0`.
  - **Each window:** 120 pairs of draws. Each pair writes a new value into both used user words: vertex user SGPR 0, which `VertexCode` reads as `s8` (NGG), and pixel user SGPR 0, which `PixelCode` reads as `s0`.
  - **What that gives:**
    - the second draw of a pair repeats the first one's key, so it is sighted and admitted;
    - no stage variant passes the used-word check, so there are no candidates;
    - no key repeats a third time, so there are no hits.
  - **It checks its own preconditions in both windows:**
    - 240 lookups;
    - 0 hits;
    - 0 `dataStagesReused`;
    - 120 inserts.
  - **Then:** it closes each window with not-useful notes. After the second window, the next draw must be neither looked up nor inserted, and `Skip()` returns true with `TakeBypassed() == 2`.
  - **Today's rule** never counts those windows as low, because 120 sightings in 2048 lookups is above 5 %.

- **Control A: `RareHitsKeepTheCacheLookedUp`, mode `--rare-hits`.** Registered as `agc_driver_draw_cache_rare_hits`.
  - **Each of 4 windows:** the same 120 pairs, plus 24 draws of one fixed key. That gives 22 hits in the first window and 24 in later ones, about 1 % of 2048. The case requires between 1 and 40 hits per window.
  - **After each window:** `Skip()` must be false. At the end, `TakeBypassed() == 0`.

- **Control B:** `StageHitsKeepTheCacheLookedUp` is unchanged and green, inside `agc_driver_draw_cache_low_hit_bypass`.

- **Registration:** the three new tests have `ENVIRONMENT "ANYPS5_NO_SHADER_CACHE=1"` (plus the percent for `_off`), `SKIP_RETURN_CODE 77`, `FAIL_REGULAR_EXPRESSION "FATAL:"`, and the WIN32 `PATH` list, as their neighbours have.
