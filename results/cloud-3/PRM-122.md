## 2. What the code does now

**`sceNetInetNtopWithScopeId`** (`Export.cpp:3030`):
- A null address or text sets errno 28 (`ENOSPC`) and returns null.
- A family other than 28 sets 47 (`EAFNOSUPPORT`) and returns null. Nothing throws.
- With a nonzero scope, it appends `%` and the name of the first interface id, in `sceNetGetIfName`'s table, whose host index is the scope.
- A result that does not fit (`length >= size`) sets 28.
- A nonzero scope that matches no interface throws `std::runtime_error`, because the module's answer for it is unknown (`Export.cpp:3044`). No test asserts it.

**`sceNetInetPtonWithScopeId`** (`Export.cpp:3056`):
- Another family returns `0x8041012F` with errno 47, and a null text `0x80410116` with errno 22, both through `fail()`.
- The `%` branch runs only when `scopeId != nullptr`. The zone must equal one of the ten names exactly. Its host index comes from `HostInterfaceIndex`.
- A decimal zone, an unknown name, an empty zone, or a name without a host interface returns 0 and writes nothing.
- With a null `scopeId`, the whole text goes to the parser, so `fe80::1%lo0` returns 0 and `fe80::1` converts.
- A null destination throws `std::invalid_argument` once the text has parsed, which is where the module would store (`Export.cpp:3072`).

**`sceNetConfigGetDefaultRoute`** (`Export.cpp:3240`):
1. `if (!g_net_inited) return fail(NET_ENOTINIT);` gives `0x804101C8` with errno 200.
2. No host gateway (`NetCtlHostIpv4Gateway_nid_no_patch` false) returns `0x8041130C` and leaves the output untouched.
3. Otherwise a null output throws `std::invalid_argument`, where the module faults.
4. Otherwise it stores the gateway and returns **1**.

## 6. Null outputs and faulting arguments

**Chosen:** throw `std::invalid_argument` where the module faults, and record it in the debt entry ("throws `std::invalid_argument`, where the module faults").
- **Pinned in tests:** the two places are pton's null destination and the default route's null output when a route exists. Both are pinned in the tests (S13 and D5), as e03a8b4dfb pins its exception.
- **Not a placeholder:** this is the documented treatment of a known console fault, not a placeholder throw for an unknown path.

**Where it is documented:**
- **The rule:**
  - `CONTRIBUTING.md:7`: "Every function either does exactly what it is supposed to or throws."
  - `docs/dev/TechnicalDebt.md:15`: "every function at every stage either **does exactly what it's supposed to or throws an exception**".
  - `CONTRIBUTING.md:80` says a debt entry states "what throws".
- **The exception type and wording:**
  - **Precedent:** commit **e03a8b4dfb**, "fix(libSceLibreSsl): throw the documented exception for faulting arguments" (rooklz, merged as #14178, b5705afa47). Its message reads: "Throw std::invalid_argument there as the debt entries record."
  - **Debt entry:** that entry is `docs/dev/debt/libSceLibreSsl.md:5`: "Null outputs, a null supported list and a null peer list with a non-zero length throw, where the module faults".
  - **Same wording elsewhere:** `debt/libkernel.md` uses it, for example "A null name throws, where the console faults in `strncmp`".
- **Not named in the rule files:** `CONVENTIONS.md` and `CONTRIBUTING.md` say "throw" but name no exception type. The type comes from that commit and its debt entries.

**rooklz's EINVAL suggestion for pton's null destination is not followed.** EINVAL would be an answer the module never gives. The project rule is to do what the console does or throw, and the recent precedent turns a faulting argument into `std::invalid_argument`. If the PR Manager prefers EINVAL, it is a one-line change, `return fail(NET_EINVAL);` at `Export.cpp:3072`, with S13's assertion to match.
