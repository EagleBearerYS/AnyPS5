
- Add it to whatever the PC already sets for the Village A runs; nothing else is needed.
- The lines go to stderr through the profile writer, so into the same log as the `[present]`/`[draws]` lines; `APS5_PROFILE_DRAW` is not required.
- There is one `[draw-key] frame N` line per flip that had draws; flips without draws are folded into the next line.
- If nothing flips for 10 s (loading), a `[draw-key] 10 s window N` line covers the window instead, and its repeat counts are against the previous window.

## What each key covers (103015a9ca)

All paths are under `core/libs/prx/libSceAgcDriver/`.

**Full draw key**, `Driver::drawRegisterKey` (`Execution/src/Driver/Draw/DrawRegisterKey.cpp:133-194`), built on `RegisterStateKey` (`:52-83`). It is an FNV hash of:
- the fingerprints of the context, shader and user-config registers in `Graphics::DrawKeyRegisters` (`Graphics/include/State.hpp:308`), minus the runtime user-data registers (`runtimeRegister`, `:14-16`);
- the user-data words (`:74-80`): for each base 0x00c, 0x08c and 0x10c, the first N words, where N is the user-SGPR count in the register before the base (bits 1-5 plus bit 27), at most 32 (all 32 with `APS5_DRAW_KEY_ALL_USER_WORDS`), plus 0x082/0x083 and 0x102/0x103;
- the device serial;
- for each stage's program address (0x008, 0x088, 0x0c8, 0x108, 0x148): the registered shader snapshots' identities and the program's offset in them (`:170-190`).

**Shape key** (`shapeKey`): the same, with the user-data words left out. That is, the register fingerprints (`:58-61`) plus the device serial and the shader identities, which are mixed into both keys (`mix`, `:156-161`). It is what `drawShapes` and the data-only hits look up (`Draw.cpp:462-468`).

**Shader set:** `DrawShaderSetKey` (`:86-101`), per stage: the shader snapshot identities and the offset in them, with no registers. It is computed only for the trace and now for the census.

**Relocation identity:** `drawIdentityKey` (`:103-131`): per stage, the program address registers, the user-SGPR count register, the snapshots and the offset. It keys `drawRelocations` and the trials.

**Relocation alias key:** `drawRegisterKey` with a learned `DrawRelocation` (`:134-155`, `:186-192`). It hashes:
- the shape key;
- every keyed user word, where each relocatable word is replaced by `relocatedContentKey` (`Execution/src/Driver/Draw/DrawRelocate.cpp:31-57`): its low two bits plus up to 64 words read through it at each learned offset;
- the device serial and the shader identities.

Two details matter for the census:
- It is computed only when `drawRelocations` holds the draw's identity and the trial is not idle (`Draw.cpp:404-415`, `:439-445`).
- It is zero when a read through a word is unmapped.

**Learning** (`DrawRelocate.cpp`):
- `tagVariantRuns` (`:59-110`) marks which user words a variant used as bases.
- `learnPendingRelocation` (`:132-177`) records, for the identity, which registers are relocatable and the reads behind them, and bans a register once a variant does not use it as a base.
- `relocateDrawEntry` (`:179-257`) rebases a donor entry's runs by the moved delta.
- The trial (`Execution/include/Driver/Draw/DrawCache.hpp:154-155`, `Draw.cpp:446-454`) turns a relocation unproductive if it gets fewer than 1 hit per 16 lookups over 1,024 lookups, then idles it for 16,384 draws.

**Admission:** `Driver::admitDrawKey` (`Execution/src/Driver/Draw/DrawCache.cpp:110-133`). In order:
1. a key already in `drawCache` is admitted;
2. a key seen before in the sighting table (`DrawKeySightings`, `:87-108`: 16,384 keys in 4-way buckets, 4× the 4,096-entry cache) is admitted;
3. a pending relocation trial within probation (alias sighted, at most 2 admissions until it hits), or the identity's second sighting while no relocation is learned, admits it;
4. otherwise it is refused when there is no shape key (shape 0: no register key, or data hits off) or when the shape already has an entry (`drawShapes`), because the data-only hit serves it;
5. otherwise the shape's second sighting admits it and its first refuses it.

**Who asks:** `cacheDrawStages` (`Execution/src/Driver/Draw/DrawCapture.cpp:212-216`) asks only for draws that use draw entries, did not hit, and are not CPU-path indirect (`!(drawParameters.indirect && indirectCpu)`).

**Draw recipes:** `findDrawRecipe` / `attachDrawRecipe` (`DrawCache.cpp:230-264`), keyed by the full draw key plus the matched variants.
- Draws use them only when the key is registered, the draw is not indirect, there are no patched stages and no tessellation geometry (`Draw.cpp:1216-1225`).
- They are recorded through `DrawFromRecipe` inline (`:1263-1271`) or in the pipelined commit (`commitDraw`, `:1294-1297`).

**CPU-path indirect:** `ClassifyIndirectDraw` (`Draw.cpp:950`) decides it.
- The records are read on the CPU and every record re-materializes the patched stages (`:1106-1213`).
- The last drawable record is queued to the draw pipeline when it can be (`:1187-1203`); otherwise it is drawn inline.
- These draws never reach admission (above).

**Resource cache:** `SharedResourceCache()` (`Graphics/include/ShaderResources.hpp:699-760`). It starts at `InitialEntries = 1024` (`:724`), doubles only when evicted keys come back (`ResourceCache::noteEvicted`, `Graphics/src/ShaderResources.cpp:3842-3866`), and halves back towards the base when few keys serve the uses.
- **Key:** `DrawResourceKey` (`Graphics/src/Draw.cpp:1008-1036`):
  - the device;
  - per stage, the compiled program's content key (`ShaderResources::AppendContentKey`, `ShaderResources.cpp:2742`, memoized per compiled program in `drawKeyMemo`): its bindings' layout, every guest V#/T#/S# word (the ShaderData words left out with movable buffers) and their flag bitsets;
  - the colour attachment count;
  - the target and index ranges only with `APS5_NO_DRAW_KEY_TRIM`.
- So a moved buffer base in a V# changes the key.
- **Lookup:** `resolveDrawResources` (`Draw.cpp:1704-1735`).

**Frame end:** the flip packet in `Driver::execute` (`Execution/src/Driver/Packets/PacketExecution.cpp:410`, `++flipsCounted` and `NoteHostImportFrame`), on the submission thread after the frame's draws.
- An unordered flip with no work counts in `Driver::Submit` (`Execution/src/Driver/Queues/Submission.cpp:441`).
- `Driver::Present` (`Execution/src/Driver/Presentation.cpp:73-187`) runs later, on the presenter thread, and `[present]` reads `flipsCounted` (`:206`).
- The census ends its frame at the same two `flipsCounted` sites.

## Counters (`APS5_DRAW_KEY_CENSUS=1`) and where each is counted

The line numbers below are on `1a91f1bcd6`; `Draw.cpp` is `Execution/src/Driver/Draw/Draw.cpp` unless the path says `Graphics/src/Draw.cpp`.

**Draws**

| line field | counted at |
|---|---|
| draws | `Driver::draw` entry (`Draw.cpp:312`) |
| cpu-indirect inline / queued | the two returns of the CPU indirect branch (`:1229` / `:1218`) |
| gpu-indirect | after `cacheDrawStages`, indirect without a CPU path (`:1013`) |
| empty indirect skipped | `EmptyIndirectSkip` return (`:552`) |
| at the draw-cache lookup, keys cached | the register-key lookup, after `drawCache.find` (`:478-484`) |

**Admission:** `cacheDrawStages` (`DrawCapture.cpp:218-224`).
- Each draw that reaches it is counted once:
  - not tried: entries off, hit, or CPU-path indirect;
  - by verify;
  - otherwise the reason `admitDrawKey` returns (`DrawCache.cpp:113-144`): cached / seen / shape seen / relocation trial / identity, admitted; first sighting / shape held / no shape key, refused.
- Shape entries replaced is counted there too (`replaceShape`).

**Hits**

| line field | counted at |
|---|---|
| draw cache | `drawHit` after `lookupDraw` (`:671`) |
| data | data-only hit kept after `DecodeProgramsCurrent` (`:496`) |
| recipes found / recorded | `findDrawRecipe` non-null (`:1243`) / `DrawFromRecipe` recorded, inline and in `commitDraw` (`:1284`, `:1316`) |
| relocations applied / productive | `userPatches` non-empty / with a hit (`:679` / `:682`) |
| shader sets learned | `drawRelocations.size()` at each lookup (`:480`) |
| resource cache hits / misses (invalidated) / uncacheable | `resolveDrawResources` (`Graphics/src/Draw.cpp:1724-1745`); a miss is any cacheable draw that builds, and invalidated is the subset whose cached template failed `Revalidate` |
| resource cache entries of capacity | `SharedResourceCache().Size()` / `Capacity()` when the line is printed |

**Key repeat against the previous frame:** `NoteLookup` (`Graphics/src/DrawKeyCensus.cpp`), called from `NoteDrawKeyCensus` (`DrawRegisterKey.cpp:104-109`) with the same keyed user words the key hashes (`forEachKeyedUserWord`).
- It keeps per-frame hash sets of the full key, the shape key and the shader set.
- It counts this frame's keyed draws whose key is in the previous frame's set.

**Shape-only repeats:** draws whose shape key repeated and whose full key did not.
- Each is compared with the previous frame's draw that had the same shape key at the same position among that shape's draws. That is the k-th draw of shape S in this frame against the k-th of S in the last one, up to 256 per shape and 131,072 per frame.
- Every register whose value differs adds one to that register's count; the line prints the top 8 as `0xREG:count`.
- **Address-like:** a differing word counts as address-like when `GuestAllocations::GuestAllocationsLookup_nid_postfix` (the guest range lookup `reportGuestAllocation` already uses) finds a mapped range for either:
  - the word with its low two bits cleared, as relocation reads it;
  - the word paired with the next register as `low | (high & 0xffff) << 32`, or with the previous one as the high half.

**Content behind them:** for keyed misses whose shape key repeated, the relocation alias of this draw and of the same-position draw last frame:
- **same**, when both are non-zero and equal: the pointer words moved but the content read through them did not;
- **changed**, when both are non-zero and differ;
- **not hashed** otherwise: no relocation learned for the identity, a trial idling, or an unmapped read.

The census never computes a content hash of its own; it reads the alias the existing code already made.

**Exclusions:** no memory contents and no addresses are printed; register offsets and counts only.

**Cost when off:** every hook is a call that checks one function-local static flag (`Enabled()`); the census's sets and lock are only touched with the switch on.

**Known looseness, for reading the numbers:**
- A draw `finishDraw` re-enters after queued labels (`Draw.cpp:1005`) is counted twice in `draws`.
- The fields counted in `finishDraw` (indirect paths, recipes, admission) can land in the next frame's line when the draw finisher lags behind a flip. The lookup-side fields (keyed draws, repeats, slots, content) are always counted on the submission thread before the flip.

The test checks every frame for consistency:
- repeats ≤ keyed draws;
- full-key repeats ≤ shape-key repeats, and shape-only plus full-key repeats equal the shape-key repeats;
- keyed draws = lookups ≤ draws;
- address-like words ≤ differing words;
- content verdicts ≤ shape repeats.

On the last frame it also checks:
- one full-key repeat (A) and two shape repeats;
- one shape-only repeat (B), whose one differing word is 0x08c and counts as address-like.

With the switch unset, the same binary checks that nothing was recorded. There is no throw assertion.

- **Harness:** `agc_driver_village_draw_cost --cost 130`, as BF-265 ran it: 130 frames of 850 draws, 256×256 (`VILLAGE_WIDTH/HEIGHT=256`), `VILLAGE_TABLE=4096`, `VILLAGE_WRITE_PERCENT=0`.

- **Trees:** the harness's two commits (c8461c3f14 and a1345c6917, from #12745's branch, single test files) are cherry-picked locally. They are not pushed and are not on the branch.
  - **base** = 103015a9ca + harness;
  - **off / on** = `1a91f1bcd6` + harness, the same binary, with `APS5_DRAW_KEY_CENSUS` unset or `=1`.
- **Order:** off and on alternated; base was run after them.
- **Measures:**
  - **Lookup** is the `[draws] … lookup=` ms ÷ draws of each 10 s profile window, median per run with the first and last window dropped.
  - **Wall** is the harness's own `wall median` µs per draw.
  - Each cell is the median of 3 runs, with the min–max of the 3 in brackets.

|---|---|---|
| base (103015a9ca) | 1,361.0 [1,346.7–1,406.2] | 1,703.7 [1,702.2–1,746.1] |

**Off:** nothing measurable. Off vs base is +0.6% lookup and +1.3% wall, and both medians lie inside the base runs' own min–max. That fits the code: off, each hook is a call that checks one static flag.

**On:** nothing measurable on this harness either.
- It is +1.0% lookup and +0.2% wall against off, inside off's range.
- Each lookup copies the keyed user words (at most 100), takes the census lock for a few set operations, and does a guest-range lookup only for words that differ. That is small next to a 1.4 ms draw.
- The harness never flips, so on it prints one 10 s window line instead of one line per frame (21 lines per run).
- It does exercise the whole path. In a mid-run window: of 4,999 keyed draws, 3,925 repeat their full key and all 4,999 repeat their shape and shader set. There are 1,074 shape-only repeats, with 2,008 differing words, all address-like (registers 0x010:1,024 and 0x08c:984), so about 2,000 guest-range lookups per window. All 4,999 shape repeats miss the draw cache, with the content not hashed.
