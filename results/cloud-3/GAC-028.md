## Summary

- **Village's chain now plans.**
  - On main, a T# read through `Phi(GetUserData, CompositeExtractU32x4(Ballot))` was refused with `GetImageResource dword 0 is not a valid runtime value`.
  - On the branch, the entry edge reads the real T# through ordinary SRT slots.
  - The back edge, where the loop's ballot sits in the pointer, is a poisoned copy. It reads nothing, returns zero, and reports a `PoisonedDescriptor` fault with the program counter only if an active lane takes it.
- **The read is split before the SRT plan** (§1, §3).
  - The descriptor-phi split looks through a scalar-address read and its `GetAddressResource`, and re-emits the read per incoming edge.
  - The plan gives the copies slots, so the materializer is unchanged and no BDA or late read appears.
- **Poisoning is narrow** (§2). An arm is poisoned only when:
  - all its edges are loop back edges;
  - every value it cannot rebuild is a lane mask;
  - another arm stays valid.
- **Everything else is refused as on main:**
  - a mask on a forward or entry edge;
  - an inductive pointer;
  - a pointer phi inside address arithmetic, which keeps main's image-table path;
  - stores and atomics.
- **The sibling path is covered by the same rule:** a T# whose own dwords hold the mask on the back edge, in the post-plan split. Main's web split keeps priority there.
- **FormatVersion 39** (§4). The compiled artifact gains `poisonedDescriptorReads`, which the driver uses so that a program with an image table still checks its faults. Known claims: 36 on main; 37 for #6243, #6280, #6412 and #6454 (PM-038 v3's PR, as opened); 38 for PM-038 v3, per the task.

## 1. Walk through the read

**The pass.** `ResourceTracker::SplitDescriptorPointers` (ResourceTracker.cpp:1869, `Tracker::SplitPointers` :109) runs in `PrepareResourceProgram` before `SrtWalker::BuildPlan` (Recompiler.cpp:293). Dead code is removed after it only when it split something. It reuses the descriptor-phi split with one flag, `m_lookThroughReads`, which three functions honour:

- **`CollectDescriptorPhis` (:786)** also walks through a scalar-address read and its `GetAddressResource` (`LooksThrough`, :782). `LookThroughRead` (:773) accepts a `LoadAddressU32` that `ScalarAddressMemory` accepts (32-bit, one dword, high offset 0, always active) with an immediate offset and a two-dword `GetAddressResource`.
- **`Rematerialize` (:888)** rebuilds such reads and pointers per edge, recursively, so a pointer loaded from the SRT is rebuilt too.
- **`SubstituteEdge` (:918)** copies them along the path from the handle to the phi.

**Read copies.** A re-emitted read gets a fresh `MemoryInfo` entry (`EmitCopy`, :876). Each memory index stays owned by one instruction, which `MemoryIndexBelongsTo` and #6232's pointer hops rely on.

**What it takes on.** `PointerPhisOnly` (:809) admits an image read only if every non-invariant phi its T# or S# dwords reach is a direct operand of the `GetAddressResource` of their scalar reads: the pointer itself is the phi. Anything else is left exactly as on main (no IR change):

- a phi in the T# dwords themselves (left to the post-plan split);
- a phi inside the address arithmetic (`base + i * 32`), where main's image-table path takes the loop-indexed pointer;
- a phi under `v_readfirstlane`.

**Village's chain after the pass** (`APS5_DUMP_IR`, the compute twin of the chain):

```
$2:  %18 = Phi [false, $1], [true, $5]      (back-edge selector)
     %19 = Phi [true, $1],  [false, $5]     (entry selector)
```

After the plan, the eight re-emitted reads are SRT slots 0-7 (`ReadConst`), and the pointer phis feed nothing but the fault op.

## 2. Poison the arm that can't be rebuilt

`SplitDescriptorEdges` (:1019) used to give up when any arm failed its dry run. Now an arm that cannot be rebuilt becomes a poisoned copy when `PoisonableArm` (:995) holds:

- **Every edge of the arm is a back edge.** Its predecessor is at or after the phi block in `BlockOrder`.
- **Each phi value on the arm that cannot be rebuilt is a lane mask.** `LaneMask` (:835) accepts a `CompositeExtractU32x4` of a `Ballot`, or bitwise ops of those with immediates. That is what the translator makes of a `v_cmp` destination, EXEC or VCC copied into SGPRs.
- **At least one arm stays valid.**

**A poisoned arm:**

- **No image op.** `ReplaceWithArmCopies` (:1096) emits no image op for the arm, and its operand in the select chain is the constant 0. The first valid copy keeps the original memory index, and later copies get fresh ones.
- **`EdgeSelector` (:940)** gives it a Bool phi that is true only along its own edges, so the entry arm reads the real T#.
- **A fault op.** `EmitPoisonFault` (:1011) emits `PoisonedDescriptor(taken && exec, pc)`, a new void opcode appended to the enum (IrOpcode.hpp:483, IrOpcode.cpp:524, side effects :896). It sets `usesFaultBuffer`.
- **SPIR-V.** `EmitPoisonedDescriptor` (SpirvImageEmitter.cpp:1921) records `FaultReason::PoisonedDescriptor` (BdaAbi.hpp:31) under the condition and does not stop the invocation. This is the image-table poison behaviour (`EmitTableFault`): the lane reads zero and goes on.
- **The driver** (BdaResources.cpp:282) reports: `shader stage S read an image at program counter 0xPC after a loop back edge that left a lane mask in its descriptor or in the pointer it is read through; the read returned zero`.
  - A dispatch logs it as a deferred write-back failure and drops that dispatch's buffer writes.
  - A synchronous draw fails, as an image-table fault does.
- **Fault checks with an image table.** The artifact counts poisoned reads (`poisonedDescriptorReads`, Recompiler.hpp:547, Recompiler.cpp:552, copied at :865). The driver checks faults when it is non-zero (ShaderAddressResources.cpp:27). Otherwise a program that also binds an image table would check only for table faults and never see this one.
- **No pointer in the record.** The record carries the program counter only. An earlier version also recorded the phi'd pointer, but on hosts whose subgroup is narrower than the wave the emulated ballot covers only the invocation's host subgroup. The "pointer" then differed from what the console would see (it read 0 on lavapipe's 8-lane subgroups), so it was dropped as misleading.

**The sibling path, a mask in the T# dwords themselves.**

- The post-plan split now tries, in order: the edge split without poison, the web split (`SplitDescriptorWeb`, now returning whether it split), then the edge split with poison. Main's web keeps every case it handled (`loopCode`, lane selects, phi webs).
- Main's entry-edge negatives (a T# holding the PC, EXEC or a compare mask on the loop's entry edge) are still refused: an entry edge is never poisoned.

## 3. The materializer: plan them before

- **Plan before.** The split runs before `BuildPlan`, so every re-emitted read is a raw scalar read with an immediate offset and a valid address. The plan gives it a slot (`PatchReads`), and the materializer evaluates and flattens it like any other SRT read.
- **No late reads.** No `LoadAddressU32` survives to the tracker unplanned, so the program does not become BDA-based (`usesDma` stays false), and the SRT guard and poison rules apply to these reads as to any other.
- **The alternative** was evaluating late reads in the materializer. It would have given them no slot or guard and made the shader use BDA loads, so it was not taken.

### Draw-time cost: one extra read per arm

**What a draw pays, by construction:**

- **A valid arm's descriptor:**
  - its own T# and S# slots, 12 more SRT dwords read and one more image and sampler bound per draw;
  - one image op per original read for every invocation, because every valid arm's read runs and a select picks one result, as in main's descriptor-phi split.
- **A poisoned arm:**
  - no read at all;
  - a branch on `taken && exec` per iteration, never taken in a working title;
  - the program uses the fault buffer, so each use checks it at completion, as image-table poison and guarded SRT reads already do.
- **Village's shape:** one valid arm and one poisoned arm, so exactly one image read per iteration, the same as a loop that keeps its pointer.

## 8. Adversarial review

**Is zero a safe stand-in on every path the arm can take?**

- **Only one kind of path reaches it:** control arrives at the phi block along a back edge on which the pointer (or the T# itself) holds a lane mask. On every other edge the read is the real one.
- **No memory is touched.** The arm emits no image op, so no descriptor or address from the mask ever reaches Vulkan: no out-of-bounds access, no invalid descriptor. Zero is what a poisoned image-table entry returns (`ZeroResult`), for every splittable read:
  - sample, gather and load give (0, 0, 0, 0);
  - a dimension query gives 0;
  - a LOD query gives 0.
- **Downstream it is a value, not a crash.** A shader that divides by a queried width gets inf or NaN. A shader that loops until a texel is non-zero could spin, as it could on any zero texel. `APS5_LOOP_GUARD` covers that, as for any loop.
- **Exec gating.**
  - The fault is gated by the image op's exec operand, so an invocation that already left the loop (and in this emulation keeps iterating with exec off) never reports.
  - Its result is dropped by the loop's own exec selects, as on main.
  - Helper invocations of a pixel quad are in exec as on hardware: one that takes the back edge reports the fault too.
- **The report is not lost.** It reaches the driver even when the program binds an image table (§2). The one exception is the merge with #6412 (§7).

**Can a structurizer artifact edge be taken at run time?**

- **Only back edges into the phi block are ever poisoned.** The structurizer builds each loop with one latch, so the back edge exists in the guest program (`s_cbranch_execnz loop`). It is taken whenever a lane is still active after an iteration, which is exactly when the console would re-read the T# through the mask.
- **Inactive invocations take it too,** because the emulation keeps a wave's finished invocations looping with exec off. That is why the fault requires exec.
- **Forward artifacts are never poisoned.** Guard and flag blocks, and edges whose value is undefined (an `Undef` is not a lane mask), keep main's refusal.
- **Two back edges.** If a loop has two back edges, the structurizer merges them into a latch whose value is a phi. A phi is not a lane mask, so a loop where one back edge keeps a valid pointer and another a mask is refused, not poisoned.
- **Unexpected paths still report.** An artifact edge that is taken at run time when the guest would not take it can only exist where the structurizer adds control flow. If such an edge carried a mask, the fault would report it rather than pass silently.

**What do hardware semantics say about the back-edge T#?**

- **What the console executes.** On RDNA2 (gfx1013 is a gfx10.3 part), the loop body's `s_load_dwordx8 s[8:15], s[0:1], 0` runs again after `v_cmp_* s[0:1]`. It runs once per iteration, with no dependence on EXEC (it is scalar), and SBASE is the lane mask. In wave64, s0 holds lanes 0-31 and s1 lanes 32-63, for example 0xffffffff_ffffff00 in the test after lanes 8-63 finished.
- **What it reads.** SMEM reads the T# from that 48-bit address, which is almost never a mapped T#:
  - on an unmapped page the access takes a GPU VM fault (on Linux amdgpu it reads the protection-fault default page; what the PS5 does is not known);
  - on a mapped one it reads unrelated memory.
- **What follows.** The `image_load` then uses that descriptor for the lanes still active. Nothing defined comes back.
- **What a working title implies.** A title that works on the console must not reach that read with active lanes. In practice its waterfall compare is uniform across the wave, so the loop runs once.
- **Why zero plus a report fits.** Zero is a defined stand-in for an undefined read, and the report makes it visible if that assumption ever fails. This is not measured on a console. It is recorded in `docs/dev/debt/shader.md`.
- **Synthetic loops in GAC-023's test shaders.** `v_cmp_lt_u32 s[0:1], 3, v2` against an interpolant leaves lanes with `v2 <= 3` looping forever on any hardware. Its draw never rasterizes, so it is harmless there.

**Other points.**

- **a. Pre-empting the table path.**
  - A pointer phi inside the address arithmetic stays on main's path, so loop-indexed descriptor arrays keep their image tables (`PointerPhisOnly`).
  - The refused `advancingCode` test (a pointer advanced by 32 each iteration) pins that an inductive back edge is not poisoned.
- **b. Valid arms both read.** As in main's descriptor-phi split, every valid arm's image op runs for every invocation, and a select picks one result.
- **c. Remaining limits** (listed in the debt entry), each still failing with "is not a valid runtime value":
  - pointer phis over more than one join (the web split does not look through reads);
  - a mask on a forward or entry edge;
  - image stores and atomics through a phi'd pointer (GAC-023's compute store shader stays deferred);
  - a T# loaded with `s_buffer_load` from a V# a phi chooses;
  - a handle mixing pointer phis with direct dword phis.
- **d. Pre-existing gap, not this branch.** With an image table bound, the driver polls only table faults. Unlinked calls and atomic fault sources in such a program are still not polled. Only the new fault was added to the condition.
- **e. Cost of the fault check.** A program with a poisoned arm makes every use of it check faults at completion. That is the cost image-table poison and guarded SRT reads already pay (§6). Stencil replay refuses it, since it uses the fault buffer without guarded slots.
- **f. Not handled: `Deserialize.cpp`.** This debug tool mirrors the pipeline and builds an SRT plan, but no target compiles it (it is only hashed into `SourceVersion`), so it was left alone.

## PR text draft

**Title:** `fix(shader): plan a T# whose pointer a loop's ballot overwrites`

### What

- **The shape.** A waterfall loop that writes its compare mask (`v_cmp` into `s[0:1]`) into the SGPR pair that holds a T# pointer leaves the loop's `s_load_dwordx8` behind `Phi(user data, CompositeExtractU32x4(Ballot))`.
  - The resource plan refused it, at the pipeline ABI call and at the draw: `GetImageResource dword 0 is not a valid runtime value`.
  - Resident Evil Village has pixel shaders of this shape.
- **Look through the read.** Before the SRT plan, the descriptor-phi split also looks through a scalar-address read and its `GetAddressResource`.
  - When the T# or S# pointer itself is the phi, the read is emitted again once per incoming edge.
  - The SRT plan then gives each edge's descriptor its own slots, and the materializer is unchanged.
- **Poison the back edge.** An edge whose value cannot be rebuilt becomes a poisoned copy when all its edges are loop back edges and the value is a lane mask (a ballot, EXEC or VCC copy).
  - This covers both the pointer and, in the existing split, the T# dwords themselves.
  - The copy reads nothing and returns zero.
  - If an active lane takes it, it records a new `PoisonedDescriptor` fault with the program counter. The driver reports it like an image-table fault.
  - Every other edge reads its own descriptor.
- **Everything else is refused as before:**
  - a mask on a forward or entry edge;
  - an inductive pointer;
  - a pointer phi inside address arithmetic, which keeps main's image-table path;
  - a store or atomic through a phi'd pointer.
- **FormatVersion 39.** The compiled artifact counts poisoned reads, so a program that also binds an image table still checks its faults.
- **Debt.** The zero stand-in and the remaining limits are recorded in `docs/dev/debt/shader.md`.
