## The failing case

**Failure line with the rule:**

```
AGC graphics: with the default 5% bypass: after a low window, the draw after a window whose only useful lookups were 103 draws whose keys missed but whose stages were reused from the cache was not looked up
```

**What the case does** (`tests/execution/DrawCacheReuse.cpp`):
1. It closes a useful window, then notes one whole low window. The streak is now 1.
2. It draws 103 draws of new user words. Their keys miss (`drawHit` stays false, and the case's own check `shapes.hits == start.hits` holds). Each draw gets the cached draw of its shape as `dataEntry` and reuses that draw's vertex stage. The case checks `dataHits` +103 and `dataStagesReused` +103, and both checks pass under the rule.
3. It pads the window with not-useful lookups.
4. It requires that the next draw, `ScaledDraws({32.0f})`, which hits the cached draw, is looked up.

**Why the rule bypasses there.**
- **The window counts as useful today.** All 103 lookups count as useful because their data candidates are non-empty, and 103 is 5 % of 2048.
- **The new rule makes it low.** None of the 103 is a real hit in the task's sense (`drawHit || verifyHit`), because a data-only hit (stage reuse through `dataEntry`) sets neither. So the window has no real hit and counts as low.
- **The result:** the streak goes from 1 to 2, a 2048-draw bypass starts, and the next draw is skipped, so its lookup never happens.

**The case's intent conflicts with the rule.** It exists to say that stage reuse with no whole-draw hit is real reuse that must keep the cache looked up. The requested rule treats that same window as one with no real hit.

## One data point for the decision (tested here, not on Village)

**A variant that keeps every case green.** I changed the real-hit argument at the call site to `drawHit || verifyHit || dataEntry != nullptr`, so a data-only hit counts as real. With that one-line change, all 15 `^agc_driver_draw_cache` tests pass, `StageHitsKeepTheCacheLookedUp` included.

**Whether it would still engage in Village's menu is not known from here.**
- **When `dataEntry` can be set:** only when the draw's key has no entry (`decode == nullptr`) and the cache holds a draw of the same shape.
- **What Village's numbers suggest:** the menu holds 255 of 256 MiB and nearly every insert evicts. So keys may be absent often enough for data-only hits to happen. If they do, the variant would keep the bypass off.
- **What settles it:** the `data-only hits (stages: N reused, …)` field of Village's `[draw-cache]` lines. If it is 0 through the menu, the variant engages there just like the requested rule.
