## Summary

- **Why they are uncacheable:** three separate refusals plus one structural one. The draw gate (`NeverReusable` on any `BdaPagetable` binding) and the build's `noteReusable` both refuse. Then `WriteBack` ends the object: the build drops its lease and space and is committed, so it can be used once. Its descriptor set holds a fault buffer made for that one use.
- **What the time is spent on:** of a BDA draw's 1,126 µs, about 955 µs is the per-build resource work. That is the `[address]` phases (265 µs) plus stage B (about 690 µs). In a static menu nearly all of it re-proves unchanged state rather than producing new state. The big parts are snapshots 170 µs (a `memcmp`), imports pass 81, and stage-B images about 600 (per-texture lookups that hit).
- **What an index needs:** a BDA object should **not** subscribe to its address space; that would put every stamp in the title on every BDA subscription. Instead:
  - the space's identity is already an O(1) key (device, registry generation, import epoch);
  - in-place imports are read live by the GPU and need ordering, not proof;
  - only the snapshot ranges, the copied ranges and the mirrors need content proofs, and those are what to subscribe;
  - images and table spans use #12745's existing per-element subscription.
- **Upper bound:** if every BDA draw became a template hit (508 µs), that is **618 µs per draw, 2.64 s of the committer's 6.95 s busy per 10 s.** A first step that keeps today's `memcmp` and per-use copies (S1) reaches about 355 µs per reused draw.
- **Exact change:** port our closed **#6636**, which already reused address-based draw builds, without BF-033's pinned-free stall. Then close the two gaps BF-105's PC lines found, then apply the index. Five steps plus one optional (§7):
  1. **S1, port #6636:** reviewed code, with its tests and reuse counters.
  2. **S2, a fault record per use:** #8971's mechanism with #8963's slots. It ends the "in use" refusals, about 12 per proof on the PC.
  3. **S3, a few builds per key chosen by snapshot addresses:** it ends sibling draws replacing each other.
  4. **S4, index-proved snapshots and copies:** it removes the 170 + 81 µs.
  5. **S5, storing draws:** composed with #12840 and #8104.
  6. **S6 (optional), a dynamic fault-record offset.**
- **Claims (§6):**
  - **No open PR makes BDA draws reusable on current main.** #6636 and #8971 (ours) did, and are closed.
  - #8963 and #12840 (ours, open) supply S2's slots and S5's store pages.
  - fable-void's `wip/new-gpu-path` builds `ShaderResources` once per program (2dc969248a): the same split at a larger scale. PM-086 found it does not cherry-pick onto main.

## 1. Why these draws are uncacheable

**The refusals, in order:**

| where | check | effect |

| SR:2705–2710 | `NeverReusable`: any stage with a `DescriptorRole::BdaPagetable` binding, or `FaultBuffer` under the loop guard | every BDA program |
| Draw.cpp:1893–1895 | a fresh `ShaderResources`; `outcome.addressBased = HoldsLease()`, kind `KindBda` | the `[draws]` BDA row |
| SR:2671–2676 | `noteReusable` returns with `reusable = false` on `HasCopiedWrites() \|\| HoldsLease() \|\| usesBda \|\| multisample sources \|\| (bda && LoopGuard)` | no reuse even if the draw gate were opened |
| SR:2681–2690 | every direct region needs an import serial or an image-mirror serial; a copied region has 0 | a second refusal for spaces with copies |

| Draw.cpp:3190 (insert), 3358 and 3808 (recipes) | only `Reusable()` builds are inserted or get recipes | |

**The object is single-use by construction:**
- **Completion is mandatory.** `faultChecks` is set whenever the program has a BDA table (SAR:141), so `NeedsCompletion()` is true. The non-reusable completion runs `WriteBackBuffers` (Draw.cpp:2176), which calls `CheckFault` and then `GuestBufferMemory::WriteBack`.
  - A reusable object with completion work already gets only `CheckFaults()` per use (Draw.cpp:2175).
  - So S1's per-use completion (check and reset a per-use fault buffer) has a slot in today's code.
- **`WriteBack` ends the object.** It sets `committed = true`, clears the lease and drops the space (GBM:6435–6437). After that, `DirectRegions` (6443), `AddressRanges` (6105) and `CachedAddressTable` (6181) refuse.
- **The descriptor set is bound as built.** `PrepareDrawBindings` returns nothing for `usesBda` (SR:6136), and the draw binds the object's own `_set` / `fragment.set` (`Bind`, SR:6295–6299). So nothing can re-point a set per use, and #12745's re-bind (SR:3777, 3781–3793) refuses BDA and non-draw objects for the same reason (BF-041 §7 item 6).
- **The fault buffer is per build.** `BdaResources(const Context&)` makes a new one (BR:108–111) and zeroes the written list and the SRT guard word. It is written into the set (SAR:159–161) and read and reset at completion (`CheckFault` → `markWrittenPages`, BR:242–243, 338–361).

**What a cached BDA build would have to keep alive between draws:**
- **The address space and its lease** (GBM:91–137). The lease pins every readable registered range. The pin waiter (`WaitForLeasesAndImports`, GBM:3441) drops only the space cache's own reference before it waits. **This is what stalled BF-033's prototype:** 11 tests waited 60 s on a free inside a cached space. #6636 avoids it: a reused draw re-takes the space per use, and its batch holds it only until completion.
- **Host imports**, through region `direct` pointers that are valid while `importsEpoch` stands (GBM:5560–5562).
- **Mirrors:**
  - writable mirrors, compared per use (GBM:4443–4446, 2858–2899);
  - heap mirrors, by tracker block (`refreshHeapRuns`, GBM:3087–3099; `ChangedBlocks`, 2909–2929);
  - sparse mirrors, by committed pages (`refreshSparseMirror`, GBM:3054–3062).
- **Copied ranges and snapshot-backed regions**, which are CPU copies made per build (`copyRegion` GBM:5734, `AddSnapshot` GBM:4929–4996, cap `APS5_ADDRESS_COPY_MAX_MIB` GBM:1713).
- **The BDA page-table buffer.** The table cache holds it only weakly (BR:25), so a cached object would keep it alive. That should also turn many of the 469 `[bda-table]` misses into hits (inferred: today the buffer dies with the last build using it).
- **One fault buffer per use** (or a ring slice), the image-table map buffer (SR:2117, filled at 5857), the descriptor sets, and the textures, storage images and samplers.

## 3. What an index over BDA objects would need

### Dependencies, and what covers each

| dependency | read by | covered by | under #12745 |
|---|---|---|---|
| space identity (device, registry generation, import epoch) | the table, the lease | an O(1) key, as BF-033's `SpaceCurrent` did; the same key the BDA table cache already uses (BR:129–142) | n/a: a key, not blocks |
| in-place imports | the GPU, live | nothing to prove: content changes need ordering only (the recorder's batches), not a re-bind | — |
| import retire (epoch) | `direct` pointers | the epoch in the key (GBM:4395) | **no bump**, but the key catches it |
| unmap, free, re-register | the lease | registry generation in the key; `Forget` bumps (GM:734–735) | `Forget` |
| copied ranges (`space->copied`, snapshot-backed regions) | a CPU copy per build | subscribe their blocks: `Cpu` and `Driver` bumps; compare if unwatched | `Cpu`, `Driver` |
| snapshots (SRT, code, table words) | `AddSnapshot` `memcmp` | subscribe the snapshot ranges (watched), compare the rest (imported) | `Cpu`, `Driver` |
| writable non-heap mirrors | compare per use (GBM:4443) | keep the per-use compare, or subscribe if watched | `Cpu`, `Driver` if watched |
| heap mirrors | `ChangedBlocks` by tracker generation (GBM:2909) | the same tracker blocks: already O(changed) | `Cpu`, `Driver` |
| sparse mirrors | committed pages re-queried | keep the per-use query: commit and decommit have **no bump** (`ForgetInaccessiblePages`, GM:743–746) | **none** |
| multisample-target ranges | the table (`MultisampleTargetRangeGeneration`, BR:121, 144) | a generation in the key | **none**, but the key catches it |
| images and T# table spans | stage B | #12745's per-element subscription and table-span markers (SR:3640–3667) | as for cached builds |
| pending storage images over address ranges | stage B, the GPU | `Pending` (Texture.cpp:3888), and `CompletePendingCpuWrites` over the direct regions | `Pending` |

**Whole-space subscription is the wrong design.** A Village space has about 1,200 ranges (GBM:92–94). A subscription over it would put almost every registered block under every BDA object.
- Every `stamp` in the title would then bump every BDA subscription, inside the tracker mutex (GM:1519 → 164).
- Its 1,024-entry bump list (GM:116, 170–173) would overflow at once.
- Subscribing alone would take more than 1,200 tracker locks (`Watched()` per range, GM:2148–2165).

Subscribe only the bounded sets above: snapshots, copies, watched mirrors, images and table spans.

### GPU stores through BDA addresses

- **Which stores are allowed:** a BDA table entry is writable only for writable in-place imports and the build's own write intervals (GBM:6053, 6138–6176). Mirrors and copies are read-only to BDA stores (fault text at BR:297). #12840 adds writable heap mirrors.
- **In flight: no bump.**
  - The written chunks go to the per-build fault buffer.
  - The recorder notes the space as `ReadKind::AddressBased` reads (SR:6331–6334), and `PendingWriterSerial` counts those as writes (`Graphics/src/Recorder.cpp:3157`, 3160, 3179).
  - But `PendingWriteOverlaps` checks only `batch.writes` (Recorder.cpp:3142–3151).
  - So a BDA-only store is invisible to `CompletePendingCpuWrites` (SR:3554–3571), and there is **no `Pending` source for address-based work**: `NoteGpuPending`'s only caller is Texture.cpp:3888.
- **At completion:** `CheckFault` → `markWrittenPages` → `MarkPossiblyWritten` per written range (BR:242–243, 338–361) → `markWritten` → a `Driver` stamp (GM:2299–2337, 1519).
  - That holds for covered memory only.
  - Uncovered memory (unwatched imports; on Windows, host-region overlaps, GM:1203) gets `noteUnstampedStore` and no bump (GM:2306–2309, 1322–1338).
- **Descriptor-bound writes in the same build:**
  - `NotePendingWrites` and `MarkDirectWrites` at record time (SR:6350–6351; GBM:6254–6264) give a `Driver` bump before the GPU runs.
  - Write-back of a writable mirror (`WriteChanged`, GBM:6389), a GPU copy (`Write`, 6411) or a CPU copy (`storeChanged`, 6421) gives `Driver`.
  - `WriteBack` also calls `BreakProofs` for a BDA build that is not read-only (SR:6316).
- **Aliasing:**
  - write intervals are carved out of read-only table entries onto the owning region (GBM:6146–6176);
  - overlay staging regions replace the base range (GBM:6116–6121), so one guest range can have two device copies until `RecordCopyBacks`;
  - heap mirrors of ranges that became imported are released (GBM:3327);
  - an aliased write to a non-writable page throws (GBM:6274–6279).
- **What a reused storing object needs:** each use must check and reset its own written list, and write back its own writes, **without committing the object**. Until then a use is not ordered with the next use's reads of a copy or mirror. Today's per-build copy has the same ordering, because it copies guest memory before earlier GPU stores are written back. So reuse adds no new hazard if each use refreshes copies the way a build does. The index bump arrives with the write-back.

### A descriptor set per use?

- **Today:** every BDA draw allocates and fully writes its own set (`DescriptorCache::Allocate`, SR:2303–2347, 4725–4801; one `vkUpdateDescriptorSets` SR:2479–2598) and returns it at release (SR:5963–5967).
- **A reused object needs one of these:**
  - **A fresh set per use**, copied from the object's writes with only the fault buffer changed. This is the existing `AllocateRewritten` path (SR:6239–6278 → 4803–4830), which non-BDA template hits already take. It is guarded off for BDA at SR:6136. Its cost is that of a template hit's prepare: BF-041 measured about 208 µs at N = 4,096, and it is inside the 508 µs template-hit cost.
  - **The same set with a dynamic offset into a fault-buffer ring.** The fault-buffer binding becomes `STORAGE_BUFFER_DYNAMIC`, and each use gets its own slice. That needs no per-use set, but it is a recompiler binding change, and so a disk-cache `FormatVersion` rung.
  - Update-after-bind is used only for image and sampler tables (SR:2221, 2402, 2426, 5564), and there are no push descriptors anywhere.

## 4. Which proofs it replaces, and the upper bound

- **Replaced for a reused read-only BDA draw:**
  - the space acquisition and imports pass: re-derived on every build, replaced by one O(1) key compare;
  - the stage-B image proofs: about 600 µs, replaced by #12745's O(1) element proof (or today's fast proof without the index);
  - the BDA table hash or key hit;
  - the full `vkUpdateDescriptorSets`.
- **Replaced only in step S4 (index):** the snapshot `memcmp` (170 µs) and the copied-range re-copy.
- **What stays:**
  - one fault buffer per use (or a ring slice) and its completion read;
  - the per-use mirror checks (12 µs);
  - the per-use set copy (or a dynamic offset);
  - record;
  - the draw key and `Find`;
  - the materializer's `[image-table]` snapshot, about 37 µs per draw.

|---|---|---|
| today, BDA | 1,126 µs × 4,276 | 4.81 s |

## 5. Risks

**Correctness: every writer path that can change BDA-reachable memory** (BF-230's method; S1's and S4's proofs shown):

| path | reaches | covered by |
|---|---|---|
| guest CPU store to a watched page | `Cpu` at the next collect (GM:1678, 1519); a collect in the same epoch is skipped (1779–1797) | sweep of the subscribed spans (S4); the `memcmp` (S1) |
| guest CPU store to an unwatched import | nothing | in-place: GPU reads live, nothing to prove. Snapshots and copies over it: compared, not subscribed |
| driver stores (`Write`, `WriteChanged`, `StoreOwnBytes`, labels) | `Driver` (covered parts) | S4 bump; S1 `memcmp` |
| GPU copy, fill, label, sample dump; DCC, HTILE, CMASK | `MarkWritten` → `Driver` (VD:2654–2660 …; DccMetadata.cpp:254; DepthSurface.cpp:1881, 2589; Draw.cpp:591) | as above |
| storage-image write-back / pending | `Driver` / `Pending` | as for cached builds |
| BDA stores of another draw or dispatch | `Driver` at its completion only | per-use refresh, same order as a build today (§3) |
| unmap, free, re-register | `Forget` + registry generation | key |
| page made inaccessible (sparse) | **no bump** | per-use sparse query (kept) |
| import made, unwatched, re-watched, retired | `Import` / `Unwatch` / `Cpu` / epoch | key + bumps |
| Windows private mapping, `Rewatch` | `Cpu` | bumps |
| multisample ranges change | **no bump** | generation in the key |

**Resources and platform risks:**
- **Memory per subscription:** BF-041's numbers apply: about 24 B per block, plus up to about 24 KiB of bump records. Bounded to snapshots, copies and mirrors, that is KiB per object, not the about 1 MiB per GiB a whole-space subscription would cost.
- **Locking:**
  - #12745 takes its index mutex inside the tracker mutex: `stamp` GM:1519 → `bumpSubscriptions` GM:164, `unwatchLocked` 1988/1993, `ImportWatched` 2077/2110.
  - BDA subscriptions over SRT, snapshot and copy blocks add subscribers to blocks the title writes every frame (the SRT), so the per-block lock is taken more often.
  - BF-041 §7 item 2's remedies apply: one lock per written run, and sharded lists.
- **Windows `GetWriteWatch`:**
  - Sweeps go through `collectWindowsWrites` (GM:1703–1728) and are proportional to pages.
  - `covers()` excludes host regions (GM:1203), so a sweep over an imported span returns 0 and the proof falls back.
  - An incomplete walk marks blocks refused (GM:1730–1745).
  - Snapshot ranges in imported memory must stay compared.
- **The draw finisher (`APS5_DRAW_PIPELINE`):**
  - BDA draws are built on the finisher thread (`Execution/src/Driver/Draw/Draw.cpp:743–753`), which moves to a fresh collect epoch per handoff epoch (DrawPipeline.cpp:275–280). So sweeps memoize per handoff.
  - A storing BDA draw is queued with an unknown write set (Draw.cpp:223–238, 241–293), so the finisher's overlap queries report overlap for everything (DrawPipeline.cpp:75, 103, 542–567). S5 must keep that.
- **The dispatch path:**
  - BDA compute builds share `AcquireRegistered` and the space (VD:5855–5890).
  - S1's per-use space re-take applies to both; BF-033's prototype, which held the space, stalled guest frees.
  - The look-ahead path treats BDA programs as writers (DispatchAhead.cpp:111–113).
  - BF-033's prototype is the compute counterpart and could follow the same steps.

## 7. The exact change, as PR-sized steps

**The base for this is #6636, not new code.**
- #6636 already reuses address-based draw builds behind a default-on switch.
- It has no pinned-free stall: the space is re-taken per use, and its batch holds the space only until completion. That is the fix BF-033's prototype lacked.
- It went through review (PM-047, PRM-016's F1–F3) and BF-105's refusal diagnostics.
- It is closed and 10,146 commits behind.
- So the change is: **port it to current main** (our own commits, authorship kept), then **close the two gaps the PC found** (one use at a time, one build per key), then apply the index.
