## Read first: what titles see today, before registering buffers, is 1920x1080, not 0

The task says `cfg->width`/`cfg->height` "start at 0". On upstream main they start at 1920x1080:

- `VideoOutConfig` initializes them from `VIDEO_OUT_DEFAULT_WIDTH`/`HEIGHT`, which are 1920 and 1080 (core/libs/prx/libSceVideoOut/include/VideoOutDriver.hpp:48-49, :129-130).
- `VideoOutDriver::Open` creates a fresh config for every open (src/VideoOutDriver.cpp:361).
- The existing test `guest_video_out_resolution_status` asserts 1920x1080 before any registration (core/libs/tests/GuestVideoOutResolutionStatus.cpp:49).

So, without the setting, a title that asks before registering already gets:
- 1920x1080 from `sceVideoOutGetResolutionStatus`;
- resolution 1 (the HD class) from `sceVideoOutGetOutputStatus`.

Resident Evil Village and Animal Well still register 3840x2160 on main. So at least one of these holds for each of them:
- they do not size their buffers from these calls before registering;
- they ask only after registering, when main reports the registered size back;
- they decide some other way.

What that means for the setting:
- `ANYPS5_OUTPUT_RESOLUTION=1920x1080` changes only what is reported after registration.
- 1280x720, 2560x1440 and 3840x2160 change it from the first call on.
- Whether either title follows any value is unknown until a PC boot (section 5). I could not test titles here.

## 2. Tests

- **`guest_video_out_output_resolution_{unset,1280x720,2560x1440,3840x2160,invalid}`** (guest; core/libs/tests/GuestVideoOutOutputResolution.cpp, one binary with a mode argument). Each mode opens the main output and checks `sceVideoOutGetResolutionStatus` (full and pane), `sceVideoOutGetOutputStatus.resolution` and the first 48 bytes of `sceVideoOutGetOutputStatusWithVrr`, before and after one registration.

The flip tests' `SDL_VIDEODRIVER=offscreen` does not help: this SDL build has no Vulkan in the offscreen driver ("Vulkan support is either not configured in SDL or not available in current SDL video driver (offscreen)"), so the flip tests skip too. I therefore left `SDL_VIDEODRIVER` unset, so the tests run wherever a display exists. `…_invalid` needs no display and runs everywhere.
- **Run with a display.** Under Xvfb (x11, lavapipe, `ANYPS5_REQUIRE_DISPLAY=1` so a skip would fail), all 6 new tests passed, plus the 4 neighbours (section 3).
- **Negative checks** (each must fail, and did):
  - the 2560x1440 and 3840x2160 modes without the setting, or with another value: abort, "… was not reported before registration";

## 4. Unsure which calls titles use

- **`sceVideoOutGetResolutionStatus`.** This is the obvious query. But if either title calls it before registering, it already gets 1920x1080 on main and still registers 4K (see the top section).
- **`sceVideoOutGetOutputStatus`.** Only a class (1 HD, 2 4K), so a title sizing from it can only pick between its HD and 4K paths: 1280x720 and 2560x1440 look the same to it as 1920x1080.
- **`sceVideoOutGetOutputStatusWithVrr`.** Its layout follows a clean-room description (#2746), and the debt entry names no title that calls it.
- **WQHD.** The console may report 2560x1440 only to titles that have called `sceVideoOutAllowOutputResolutionWqhdDetection`; the setting reports it to every title (recorded in the debt entry). It is also unknown whether the console's class for 2560x1440 is 1.

## 5. How a PC boot confirms whether a title follows it

1. **Import audit,** before booting. Get the NIDs with `python3 tools/nid_names.py --name sceVideoOutGetResolutionStatus --name sceVideoOutGetOutputStatus --name sceVideoOutGetOutputStatusWithVrr`, then look for them in the title's `*.registry.json`. A title that imports none of them cannot follow the setting.
2. **Boot with the setting.** On Windows: `$env:ANYPS5_OUTPUT_RESOLUTION = '1920x1080'` (or `'1280x720'`), then start the exe. A `--windows-gui` build writes its output to `anyps5.log` beside it.
3. **Read the registered size:**
   - `Select-String anyps5.log -Pattern 'display buffers registered'` (or search the console output);
   - `[videoout] display buffers registered at 1920x1080, as ANYPS5_OUTPUT_RESOLUTION reports` means it followed;
   - `[videoout] display buffers registered at 3840x2160 although ANYPS5_OUTPUT_RESOLUTION reports 1920x1080; …` means it did not.

   This line is new; main has no log line that shows the registered display-buffer size. The swapchain and window lines (`Swapchain created … extent=`) are host sizes.
4. **Try 1280x720 as well.** If the title registers 3840x2160 under both values, it ignores these queries.
5. **Measure.** If it follows, compare GPU time per present with and without the setting, using the performance overlay or a trace, against the 17.2 ms baseline (Animal Well).
