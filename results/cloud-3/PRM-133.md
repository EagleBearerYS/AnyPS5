## 1. Why a faulted dispatch's stores never reached guest memory

**Path.** In this test every dispatch takes the completion for a non-reusable resource set, and its output buffer is a copied one: a scratch print gave `WriteBackBuffers copied=1` for all five runs. The shader writes a device copy, and the CPU copies it back to guest memory when the batch completes. That copy-back is gated on the fault check (line numbers at `400b86ce93`):

- `core/libs/prx/libSceAgcDriver/Execution/src/VulkanDevice.cpp:6094-6097`: the dispatch's completion calls `kept->WriteBackBuffers()`.
- `core/libs/prx/libSceAgcDriver/Graphics/src/ShaderResources.cpp:7002-7011`, `ShaderResources::WriteBackBuffers()`:
  - it calls `bda->CheckFault()` (line 7006) before `guestMemory.WriteBack()` (line 7011);
  - only `BdaUnalignedAccess` is caught and deferred until after the write-back (line 7007).
- `core/libs/prx/libSceAgcDriver/Graphics/src/BdaResources.cpp:478-514`: `checkFault` turns an image-table fault record into `throw std::runtime_error("image table: ...")`.
- That exception skips `guestMemory.WriteBack()`. It is caught in `core/libs/prx/libSceAgcDriver/Graphics/src/Recorder.cpp:4835-4849` (the completion loop) and logged as `[gpu] deferred write-back failed: image table: ...`, and `Execute` returns normally.

**Result:** a faulted dispatch's output, the trace included, never reaches guest memory.

**The reusable path is different.** It records GPU copy-backs after the work and only checks faults in its completion (`VulkanDevice.cpp:6084-6087`). Its stores land whether or not the dispatch faults, so it needed no change. On Intel, which path runs depends on whether the output is imported or copied. The fix covers the copied case, the one that drops writes.

## 2. What changed

### `a79409256a` (driver, trace mode only)

`WriteBackBuffers()` now has a second catch:

```
} catch (...) {
    if (!TableTraceKeepsFaultedWrites()) throw;
    traced = std::current_exception();
}
...
if (!SkipWriteBack()) guestMemory.WriteBack();
if (unaligned) std::rethrow_exception(unaligned);
if (traced) std::rethrow_exception(traced);
```

- `TableTraceKeepsFaultedWrites()` is `getenv("APS5_DIAG_TABLE_TRACE") != nullptr`, read once.
- **With the variable unset:** the catch rethrows the same exception at once, so behaviour is unchanged.
- **With it set:** the fault waits until the buffers are written back, then is rethrown. The log line, `Faulted()` and the armed check see it exactly as before.

The same commit adds the `APS5_DIAG_TABLE_TRACE` row to `docs/dev/ENVIRONMENT.md` (core/shader section, both files that read it). PRM-132 had left it out, and the conventions check flagged it (`[env-reference]`).

### `a77347cc5f` (trace rows)

Rows grow from 20 to 24 words. The new words 20-23 are the lookup's table index and its column's addend, stride and offset, all constants of the build.

**Why:** the armed variant (run 4) reads its key as an immediate, so its column is one key at addend 0x60. Without these words the decoder had to assume addend 0 and stride 32, and called every armed row a departure. With them it recomputes any column.

The trace-off SPIR-V is unchanged (section 4). The test prints the four new names in its `trace rows:` header.

### `c9fafbb772` (decoder)

The decoder mirrors the emitted lookup step by step, including the poisoned-root path, where the child header falls back to the table header. So every row word is compared, faulted lanes included. It covers each point of step 4:

- **Faulted runs:**
  - It takes `selected the descriptor at 0x<D>[: reason]` from the log. A fault line before a run's `trace map:` belongs to that run; a copy repeated in a failure message is ignored.
  - It maps the reason to the reported word: `poison entry N` → `N | 0x80000000`, "outside the snapshot" → `0x80000000`, "outside the key domain" → `0x80000001`. For any other reason name it matches lanes on address and poison instead.
  - It lists the lanes holding that word, and in which field: `code`, `root.code`, `image.flags` or `driver.fault`.
  - It gives the first step where one of them departs from the recomputed lookup. When none does, it says so, then names the step the poison comes from.
- **Short report** (default, about 20-36 lines):
  - the bases line, the device subgroup size, the marker line, and one summary line per run;
  - for the first departing or faulting lane of a run: its row with field names, plus the map words its lookup read (root header, selected record, child header, `mapped` slot, image record, driver fault slot), each with its index.
  - Details are given for at most two runs; later runs keep their summary and fault lines.
  - `--full` prints every map word and row, marking the departing field with `!`.
- **Marker:** it counts rows whose bits 6-11 differ from bits 0-5. It reads the subgroup size from the driver's `Selected GPU ... subgroup=N` line, and skips the count when that size isn't 32.
- **Windows:**
  - It uses only the standard library, prints ASCII only, and runs under `python -W error`.
  - It reads logs saved as UTF-8, as UTF-16 with a BOM and CRLF (PowerShell 5's `>`), or as bare UTF-16LE. All three gave byte-identical reports.

- **Run 4 prints its map and rows:** the 90-word map, and 256 rows.
- **Group 0 lanes 0-63 fault, as the armed variant intends.**
