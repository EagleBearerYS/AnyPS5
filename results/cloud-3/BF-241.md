## What each commit does

1. **Model** (`libSceImeDialog/include/PadKeyboard.hpp`, `src/PadKeyboard.cpp`, test `ime_dialog_pad_keyboard`):
   - **Pages:** the six pages are generated from shadPS4 30f4170896 `ime_kb_layout.cpp`: Latin lower and upper (50 keys each), Symbols 1/2 (47) and 2/2 (44), and Specials lower and upper (56 each).
   - **Bindings,** as BF-240 §0/§4 lists them:
     - D-pad and left stick: deadzone 0.24 and threshold 0.5. The stick repeats after lerp(0.26, 0.16, tilt) s, then every lerp(0.20, 0.11, tilt) s. A wrap at the grid edge holds for 0.5 s on repeats.
     - Cross presses the key. Square is backspace, Triangle space, L1/R1 move the caret, R2 is Done and Circle cancels.
     - L2 cycles shift, L2+△ switches to Symbols and L3 to Specials.
     - Cross repeats only on a character, Space, Backspace or arrow key.
     - Done beats Cancel when both come in the same sample.
     - One-shot shift is used up only by an inserted character.
   - **Repeats** use `PadKeyRepeatDelay` 0.275 s and `PadKeyRepeatRate` 0.050 s, Dear ImGui's `KeyRepeatDelay`/`KeyRepeatRate` defaults.
   - **Seeding:** every button's previous state and repeat state come from the first sample, so a button held at open does nothing until it is pressed again.
   - **Options:**
     - The currency key follows `supported_languages`: Korean ₩, Japanese ¥, English GB £, US/Latin-American Spanish/Brazilian Portuguese $, otherwise €.
     - The enter key follows `enter_label`: 1 Send, 2 Search, 3 Go, otherwise Done.
     - The extended `priority` (2 Symbols, 3 Accent) with `SET_PRIORITY`/`PRIORITY_SHIFT` picks the starting page.
     - `disable_device` CONTROLLER turns shortcuts and navigation off. The pad is still captured.
   - **Empty cells:** the ⌨, "..." and R3 cells are left empty.
2. **Routing** (`libSceIme`, test `guest_ime_pad_route`):
   - `ImeHostPad` is the sample: buttons, left stick and L2.
   - `ImeCapturesPad`, `ImePublishPad` and `ImeSetHostPadSink` carry the pad to the dialog.
   - `ImeKeyboardView`/`ImeKeyCell`/`ImeKeySymbol` describe what to draw; `ImeSetKeyboardViewProvider` and `ImeReadKeyboardView` pass it on.
   - All of these are `_nid_postfix`/`_nid_no_patch` cross-library calls.
3. **Dialog** (`libSceImeDialog/Export.cpp`, scenarios added to `guest_ime_dialog`):
   - `sceImeDialogInit` opens the model and registers the pad sink and the view provider. `Term`, `ForceClose` and the end of the dialog clear all three sinks.
   - Pad edits go through the same `Apply` path as host typing. Done becomes Enter and Cancel becomes Escape.
   - The text is still written to the title's buffer once, when it is accepted.
   - New scenarios: typing, R2, Circle, Abort, Term, ForceClose, a button held at open, mixed host and pad input, the length cap, `disable_device`, and priority Symbols.
4. **Hand-off** (`libScePad`, `libSceVideoOut`; `pad_sdl` gains `HandOff`):
   - While the dialog captures the pad, `PadInput::handOff` publishes slot 0's buttons, left stick and L2 to the sink.
   - Every slot then publishes a neutral state with `intercepted = true`. `BuildData` turns that into buttons `0x80000000` only, sticks 128, triggers 0 and no touch, and ignores injected input.
   - Buttons held when the capture ends stay masked from the title until each is released; a held L2 or R2 also zeroes its analog value.
5. **Drawing** (`libSceAgcDriver`, `libSceVideoOut`):
   - **Recorder:** the performance overlay's rect recording is split out as `PerformanceOverlay::RecordRects(..., const OverlayLayout&)`, and `Record(content)` calls it. The pipeline cache is now keyed by the compatible render pass instead of the format: a pass ending in TRANSFER_SRC has a different subpass dependency, so a pipeline made for one is not compatible with the other.
   - **Palette:** `OverlayColor` gains Panel, Key, Accent and Field, so `OverlayColorCount` is 7. Both shaders take `vec4 palette[7]`, which makes the push constants 120 bytes.
   - **`KeyboardOverlay.hpp/.cpp`:**
     - The font: 225 glyphs of 5×9 (two rows above for diacritics), 8 key symbols and the fallback box.
     - `LayOutKeyboard(view, extent)` places the panel centred across the frame and centred in the bottom half. The scale is max(1, height/360), reduced until the panel fits, which gives 2 at 720p and 3 at 1080p.
     - The text field has a 1-glyph-pixel caret bar and a 44-character window that scrolls to keep the caret visible.
     - The keys sit in a 10-column grid. The selected key gets an Accent border.
     - Labels are drawn in Text and badges in Graph colour.
     - UTF-16 surrogate pairs count as one character. Anything without a glyph (CJK, emoji) draws the box.
     - `AgcDriverSetSystemOverlay_nid_postfix` (declared in `Presentation.hpp`) stores the view under a mutex. `SystemOverlayView()` reads it.
   - **`VulkanDevice::present`** keeps its own `PerformanceOverlay` instance for the keyboard. The keyboard draws after the frame and before the performance overlay. Its initial layout is COLOR_ATTACHMENT when the frame was drawn, otherwise TRANSFER_DST, and its final layout is COLOR_ATTACHMENT when the performance overlay follows, otherwise PRESENT_SRC. The passes before it end in COLOR_ATTACHMENT when the keyboard is shown.
   - **`VideoOutDriver::presentLoop`** reads the dialog's view before each `processFlip` and passes it to the driver, or passes null. So the keyboard is drawn on presented flips only.
6. **Debt** (`docs/dev/debt/libSceImeDialog.md`):
   - The `sceImeDialogInit` silent-stub entry is rewritten: it now draws a keyboard; the title, placeholder and type are still unused; line breaks still cannot be typed.
   - Two existing entries now say "when the text is accepted" instead of "on Enter".
   - New entries:
     - "Pad capture" (the `0x80000000` sample, unverified on PS5);
     - `GetResult`/`Term` while running (main's `0x80bc0002`/close, against shadPS4's `0x80bc0106`);
     - text written once on Done, with no filter calls;
     - redraw only on flips;
     - the repeat timings, named as Dear ImGui's defaults;
     - the extras left out.
   - Each entry is under 1000 characters; the longest is 962.
   - **Linking:** `check_conventions` files an entry by the first `core/` path it links. So "Pad capture" and "Keyboard redraw" link the dialog's `Export.cpp` first and then `PadState.cpp` and `VideoOutDriver.cpp`. That keeps them in this file, as the task asks.

**Not done, as asked:** the R3 mode, the right-stick drag, the prediction pane, the top ✕ panel and copy/paste are left out. There are no animations, gradients or fades, and no third-party font data.
