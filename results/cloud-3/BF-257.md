## Feasibility gate (pthread_suspend_np of a running thread)

- **Main can't do it with what it has.**
  - The `suspended` flag that #9573 added is only waited on before a thread's entry runs (`Pthread/src/Thread.cpp:803`).
  - `ResumeGuestThread_nid_no_patch` and `ResumeAllGuestThreads_nid_no_patch` (`:561-580`) only clear it and notify.
  - Nothing stops a thread that is already running.
- **The nearest machinery is `sceKernelRaiseException`'s delivery (`System/src/Exception.cpp`):**
  - **Linux** sends SIGUSR1 (`:887`, `:969`). The handler runs wherever the thread was interrupted (`:940`), emulator code included. There is no safe-point logic, so a thread parked there could hold a host lock and deadlock the emulator.
  - **Windows** suspends the thread and classifies its code (`RunningCode`, return breaks; `:325-760`), which is the waiting-for-guest-code part a suspend needs.
- **A new host mechanism is needed.** #12130 builds exactly that:
  - a Linux SIGUSR2 park signal that parks only when the interrupted address is in a guest code range (from `dl_iterate_phdr`), or in a libkernel wait;
  - a Windows APC plus frozen-code classification;
  - deferral at `sceKernelUsleep`, `nanosleep`, `usleep` and `sceKernelSleep` returns.
  - Its debt entry reports the cost: a median of 160-205 ms and at worst 1.3 s per suspend on Windows 11 for a target in back-to-back host calls; at worst 3 ms on Linux.
  - Size: about 545 lines over 12 files. That is not a small, contained addition, so per the gate there is no suspension code here.
- **Once #12130 merges:**
  - `pthread_suspend_all_np` becomes small. Per FreeBSD's [`thr_suspend_np.c#L104-L157`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/lib/libthr/thread/thr_suspend_np.c#L104-L157), it suspends every thread but the caller and waits for each.
  - `pthread_single_np` ([`thr_single_np.c#L40-L51`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/lib/libthr/thread/thr_single_np.c#L40-L51)) is that plus `return 0`.

## sceKernelSettimeofday

- **Code (`core/libs/prx/libkernel_sys/Export.Discovery.cpp`):**
  - `int sceKernelSettimeofday(const KernelTimeval* tv, const KernelTimezone* tz)` returns `settimeofday_nid_postfix(tv, tz) == 0 ? 0 : SceKernelError(*__error_nid_postfix())`, which is the `sceKernelMsync` pattern beside it.
  - The declaration in `include/Api.hpp` gets the signature.
- **Source:** shadPS4 7ea677e56d [`time.cpp#L565-L571`](https://github.com/shadps4-emu/shadPS4/blob/7ea677e56d75bf3d90ace2b0a5144a665d1f38b6/src/core/libraries/kernel/time.cpp#L565-L571).
  - It forwards to `posix_settimeofday` and maps a negative result with `ErrnoToSceKernelError` (0x80020000 + e).
  - That branch passes the return value rather than `errno`. It can't run there, because shadPS4's `posix_settimeofday` is a stub returning OK.
  - Every other shadPS4 wrapper passes `*__Error()` (for example `file_system.cpp:367`). The tree's resume entry also records firmware 13.42's sce forms adding 0x80020000 to a non-zero errno. So the errno form is used, and the debt entry says so.
- **Behaviour:** everything else is main's `settimeofday` (#9682):
  - EFAULT and EINVAL checks;
  - a zone-only call stores the zone;
  - a valid time keeps `settimeofday`'s refusal, so the host clock is never changed.
- **Test:** `CheckSceKernelSettimeofday` in `core/libs/tests/GuestKernelSys.cpp` (ctest `guest_kernel_sys`).
  - `(null, null)` returns 0.
  - An unreadable time or zone gives 0x8002000E.
  - `tv_usec` 1000000, `tv_usec` -1 and `tv_sec` -1 each give 0x80020016.
  - A zone-only call returns 0, and `gettimeofday` then reports 60/1. Setting the zero zone restores 0/0.
  - No case reaches the valid-time path, and no case asserts a throw.
- **Debt:** one entry in `docs/dev/debt/libkernel_sys.md` (Functional), with the shadPS4 link and the errno note.
  - I left out a suspension entry I had drafted: it would have collided with #12130's own entry.
