### Why it fails

1. **The device path still works.** The test's three vertex draws through `device.Draw` pass, since lavapipe enables shaderTerminateInvocation (`context.shaderTerminateInvocation` is true).
2. **The mesh case fails.** It runs because the device has `VK_EXT_mesh_shader`. The test validates that pipeline itself at `core/libs/prx/libSceAgcDriver/tests/execution/LayeredVolumeDraw.cpp:222`, `ValidateShaders(shaders, state, subgroup, false, …, true)`, and its `shaderTerminateInvocation` argument defaults to false. `ShaderValidation.cpp:338` then rejects the `OpExtension "SPV_KHR_terminate_invocation"`.
3. **Why the shader carries the extension.** Its pixel shader (`PixelCode`) has no BDA read, but `bdaStopsInvocations` is true for any non-mesh shader without a barrier, so the shader takes the new path. `EmitPixelEntryPoint` then always emits:
   - the stop branch;
   - `SPV_KHR_terminate_invocation` with `OpTerminateInvocation` when the target lists the extension, or `OpKill` when it does not.

   This happens whether or not any fault site stored `bda_stopped`.
4. **On 195d0d08a8** the extension and the exit appeared only at real fault sites, so this shader declared neither.

The optimiser drops the dead branch here, because the flag is stored false and never set. The `OpExtension` stays, so every unordered pixel shader without a BDA read now declares `SPV_KHR_terminate_invocation` on a device that lists it.

## Proposed fix

- **Branch:** fork `fix/shader-pixel-bda-exit-only-on-faults`, created from 843a7d9a00 and pushed.
- **Commit:** one, cd191e71305b17f195f1ad71e7fc7621f52508b4, `fix(shader): keep the pixel BDA exit out of shaders without fault sites`. It is authored and committed as Yunus Shaikh, unsigned, with no trailers.

```
 core/libs/prx/libSceAgcDriver/tests/Graphics.cpp   | 15 ++++++++++++
 .../include/SpirvBackend/SpirvEmitterState.hpp     |  1 +
 .../recompiler/SpirvBackend/src/SpirvBdaFault.cpp  |  1 +
 .../SpirvBackend/src/SpirvModuleEmitter.cpp        | 28 ++++++++++++----------
 4 files changed, 32 insertions(+), 13 deletions(-)
```

**What changes:**
- `SpirvEmitterState` gains `bool pixelStopStored`.
- `StopBdaInvocationIf` sets it where it stores `true` to `bda_stopped`.
- `EmitPixelEntryPoint` emits the load, the stop branch and the terminate or kill only when `pixelStopStored` is set. Otherwise the entry point is store, call, return, and no extension is declared. This is safe because the stop sites live in the guest function, which is emitted before the entry point, and the BDA helper functions stop through `bdaStopValue`, never through the flag.
- Pixel shaders with fault sites are unchanged: the BF-079 test still counts one `OpTerminateInvocation` in the entry point, and one `OpKill` in the entry point without the extension.

**The test.** It is in `orderedPixelShaderTests`, right after the existing unordered checks. It recompiles `OrderedPixelCode`, which has no BDA read, as an unordered BDA-ABI pixel shader, once with the terminate extension listed and once without. Each time it requires:
- no `OpTerminateInvocation` in the module;
- no `OpKill` in the entry point;
- that `ValidateShaders(…)` passes with `shaderTerminateInvocation` false. This is the condition `agc_driver_layered_volume_draw` hits, here on mock Vulkan.
