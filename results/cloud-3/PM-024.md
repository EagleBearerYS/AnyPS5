## 0. Bottom line

- **Why the pass doesn't evict.** No commit, comment or debt entry says. The likely reason is stability across builds; the hazards eviction could cause there (same build, in-flight batches, other queues) are already guarded (§1).
- **The fix is two commits, about 60 lines in one file plus one debt sentence:**
  - **(a) Evict only as the last resort.** An address-based build retries a range's import with eviction only when the budget refused it, no mirror serves it, and its copy would take the build's copies past `APS5_ADDRESS_COPY_MAX_MIB`. That is exactly when the build would otherwise abort.
  - **(b) Re-plan a stale heap mirror.** A heap mirror whose range has left the write watch is not reused, and a cached address space over it is not taken. The range is planned again (import with last-resort eviction, then copy), instead of throwing.
  - The copy reason now names what refused the range.
- **Not built: mirroring a partly unwatched heap by comparing.** It isn't clearly better than eviction (§2.3).
- **Red/green.** Both new tests are red on main and green on the branch. Fix (a) alone turns PM-022's test green; the new test needs (b) too.
- **The suite.** All 572 `^agc` tests on the branch head, with CI's Linux flags, as `runner`: 531 passed, 41 skipped (all expected), 0 failed. `agc_driver_graphics` passes.
- **Normal-case cost: about 0.**
  - Builds over an imported heap: 256.0 ns per build on the branch, 254.6 ns on main (best of three runs), within noise.
  - The added check costs 2.2 to 2.4 ns per cached heap mirror per build.
- **Overlaps:**
  - #6060 (now at f97762019; 2406c85f6 isn't in its history) and #5851 merge cleanly.
  - #4448, #1201 and #1896 gain no new conflict hunks. Two of #4448's existing conflict blocks now also hold this branch's lines.
- **Correction to PM-022 (experiment C).** With the address-space cache on (the default), the throw comes from `refreshHeapRuns` (main:1693), not `refreshHeapMirrors` (main:1556); 1556 is the path without the cache. ## 1. Why the address-based pass imports with `evict = false`

**History:**
- `evict = false` at main:2610 came with **e9249a0a4** (2026-10-12, "feat(agc): host import windows, least-recent eviction under the budget"), merged with PR #290 (0df6e295c).
- That commit introduced eviction itself; before it, nothing evicted. It opted two callers out:
  - imports made when a range is mapped (main:2434). The body gives the reason: "the map observer holds no GPU lock";
  - `AcquireRegistered` (main:2610). The body gives no reason.
- PR #290's other commits don't mention it either:
  - c871b5893, its tests, pins only that "an address-based build over the budget leaves the range's window in place";
  - c29e06c69 is about joined imports.
- Debt entry L140 ("Host import windows and budget") restates the rules and says nothing about the pass.
- No test pins the rule. In PM-022's experiment A, `evict = true` at main:2610 kept all of `agc_driver_graphics` green, including `importRefusedWholeRangeTests`.

**What eviction there could break, and what already guards it:**

| Hazard | Guard on main |
|---|---|
| Evicting an import the same build already took | Imports looked up or made since the build's floor count as held: `pointerHeld`/`evictable` (main:806-813), the floor at main:2588, new imports stamped at main:1092, a cache hit stamps its regions at main:2546. Held imports are never evicted. |
| Evicting an import an in-flight batch still reads | `retireImport` keeps the import alive through the recorder's hold (main:240) and moves the epoch (main:235). `Upload` then re-resolves every pointer (main:3504), and the address-space cache neither hits nor publishes across an epoch move. |
| A concurrent build on another queue | `buildFloor` is one global, but address-based builds run under the GPU lock (draws: `Execution/src/Driver/Draw/Draw.cpp:394-399`; compute defers its address builds to `Complete()`). Eviction already happens on every other import path (`importAccess` main:1168, `HostImportFor` main:2407, `Upload` main:3509), so nothing new. |
| **Thrash (the likely reason)** | None. The pass imports every registered GPU range whole, in address order. If it evicted on every refusal, an early range could evict the imports of later ranges (not yet stamped in this build, idle for 256 lookups). Those would then fall to mirrors or copies in the same build. Once the registered total exceeds the budget, every build would re-pin ranges, and pinning is expensive. Without eviction the pass is stable: what fits stays imported, and the rest is mirrored or copied the same way each build. |
| A short-lived double pin | An evicted import is freed only when its hold ends, so the old and the new import are pinned at the same time briefly. The budget's 2 GiB reserve exists for that. |

**So the fix keeps the rule and breaks it only where the build would abort anyway.**
- "Copying this range takes the build's copies past the cap" means the copy total at the end of the pass is past the cap, so the build aborts (main:2652-2656), because copies only add up.
- In that case eviction can only help:
  - imports the build holds can't be evicted, and that includes every import it has used so far in the pass;
  - eviction can take only imports the build hasn't used yet: those of later ranges, and windows it doesn't use;
  - a later range that loses its import is mirrored or copied in this build, and its own retry can again take only imports not used yet, so the cascade ends with the pass.
- Every other build keeps today's behaviour exactly.

## 2. The fix

### 2.1 Commit (a) 25c333e47: last-resort eviction and the copy reason

All in `GuestBufferMemory.cpp`:
- **A budget-refusal counter.** `HostImports::budgetRefusals` (branch:189) is incremented where `importRunAt` refuses an import for the budget (branch:977).
- **Knowing why the import was refused.** The pass reads the counter around its import, so it knows whether the budget refused it (branch:2637-2643).
- **The cap is known before the loop.** `copyLimit` is read before the loop (branch:2625), and the pass keeps a running total of committed copy bytes (branch:2631).
- **The last-resort retry.** When the budget refused the range, no mirror served it, and its copy would take the total past the cap (branch:2676):
  - the import is retried with `evict = true` (branch:2679);
  - on success, the copied region is replaced by the imported one (branch:2686-2693);
  - a `[gpu] host import budget: …imported by evicting idle imports…` line reports it, at most once per 10 s.
- **The copy reason** comes from `heapCopyReason` (branch:1712-1715). It says "import over the host import budget, heap not fully write-watched", "heap mirror refused", and so on, instead of "outside the write-watched arena" for every heap.
- **Debt entry L140** gains: "An address-based build does not evict either, except for a range the budget refused and no mirror serves whose copy would take the build's copies past `APS5_ADDRESS_COPY_MAX_MIB`."

### 2.2 Commit (b) b8cf1b510: re-plan a heap whose mirror left the write watch

- **A watch serial per mirror.** `ImageMirror::watchedSerial` (branch:77) records the `GuestMemory::UnwatchSerial()` value (an existing accessor, `Execution/include/GuestMemory.hpp:103`) at which the heap's range was last seen fully watched:
  - it is set when the mirror is made (branch:1760, 1782);
  - `heapMirrorWatched` (branch:1704-1710) looks at the watch again (`GuestMemory::Watched`) only when the serial has moved since.
- **The reuse path.** `acquireMirror` reuses a heap mirror only while it is watched (branch:1737). Otherwise it falls through to making a new one, which a partly unwatched heap is refused. That refusal now also drops the registry's stale heap mirror (branch:1771-1780), which would otherwise keep its buffer allocated.
- **The cache-hit path.** A cache hit requires every heap mirror of the cached space to be watched (branch:2566). The check runs before the hit stamps its imports, so the pass that follows can still evict them. Without this, the served path threw from `refreshHeapRuns`.
- **The resulting plan:** import (refused, over the budget), mirror (refused, not watched), then fix (a)'s last-resort import, then a copy.
- **Debt entry L140** gains: "a heap mirror whose range has left the write watch since its last use is dropped and its range planned again."
- **Left as they are:**
  - The `Require`s at branch:1559/1696 stay as backstops. Only something taking the range off the watch *inside* a build, between the check and the refresh, reaches them. Builds, fills and labels all hold the GPU lock, so another thread can't; within the build, only an incomplete collect in `MarkWritten` could (GuestMemory.cpp:1446-1447).
  - Sparse heap mirrors keep their own `Require` (branch:1661). Out of scope here.

### 2.3 Why not a mirror that compares the unwatched blocks

- **Cost.** On Windows, a heap that was ever host-imported (a window or the whole range) stays off the watch for good (PM-022 §1.2; debt L58: "restoring tracking on import retirement … remains unimplemented"). A comparing mirror would then compare the whole heap on every address-based build. On this machine, comparing 768 MiB in 64 KiB blocks takes **141 ms** on one thread (5.7 GB/s): several frames for every build. Eviction costs one re-pin, and only when it fires.
- **Coherence.** While a window import of the heap is live, the GPU writes guest memory directly while address-based draws write the mirror. That gives two device copies of the same bytes, and write-back must not overwrite either. Today the `Require` at main:1556 rules this out by throwing; a comparing mirror would have to handle it.
- **Where it would still help:** when nothing is evictable (every import used in the last 256 lookups, or held). The abort stays as the backstop there. It's a follow-up if Village still aborts with this branch.

## 5. Normal-case cost

**What the fix adds to a build where nothing is refused:**
- per imported range in the pass: two reads of `budgetRefusals`, under the import lock the pass already holds;
- on a cache hit and on a mirror reuse: one `heapMirrorWatched` per heap mirror. That's a call to `UnwatchSerial()`, one relaxed load and a compare;
- on the copy path: a test of `overBudget`, which is false here.
- The full `GuestMemory::Watched` look and the eviction retry run only after something left the watch, or after the budget refused a range.

**Measured** with a temporary benchmark mode (not committed):
- One 2 MiB heap, registered and watched, on the mock device.
- 2000 warm-up builds, then the best of 5 rounds of 50,000 address-based builds (`AcquireRegistered` + `Upload` + `WriteBack`).
- Each configuration ran 3 times, with main's `GuestBufferMemory.cpp` and with the branch's.

| configuration | main, ns/build (3 runs) | branch, ns/build (3 runs) | best main → best branch |
|---|---|---|---|
| heap imported, cache hit (**no refusal**) | 254.6 / 255.9 / 356.7 | 257.9 / 257.0 / 256.0 | 254.6 → 256.0 (+1.4) |
| heap imported, no address-space cache (**no refusal**) | 614.4 / 667.5 / 695.0 | 595.8 / 607.2 / 623.5 | 614.4 → 595.8 (noise) |
| heap mirrored (import over the budget), cache hit | 2314.7 / 2274.3 / 2193.4 | 2222.1 / 2341.1 / 2187.8 | 2193.4 → 2187.8 (noise) |
| heap mirrored (import over the budget), no cache | 2949.0 / 2867.6 / 2881.2 | 2874.0 / 2792.2 / 2936.9 | 2867.6 → 2792.2 (noise) |

**Micro-measurements**, 3 runs:
- The fast path of the new check (`UnwatchSerial()`, a relaxed load and a compare) costs **2.2 to 2.4 ns**.
- A full `GuestMemory::Watched` over the 2 MiB heap on Linux costs **33 ns**. On Windows, `WriteWatchCoverage::Covers` scans one byte per 64 KiB block (12,288 for 768 MiB). That's not measured here, but it runs only after a range left the watch.

So the normal-case cost is about 0: within run-to-run noise at the build level, and about 2.3 ns per cached heap mirror per build at the instruction level.

## 7. Debt-entry text

Committed in the fixes: one sentence added to `docs/dev/debt/libSceAgcDriver.md` L140, "Host import windows and budget". Its rule now reads:

> … and imports made when a range is mapped never evict. An address-based build does not evict either, except for a range the budget refused and no mirror serves whose copy would take the build's copies past `APS5_ADDRESS_COPY_MAX_MIB`; a heap mirror whose range has left the write watch since its last use is dropped and its range planned again. A refused import is tried again at its next use.

No new entry. The Windows root cause, that retiring an import never restores the watch, is already debt L58 ("restoring tracking on import retirement without replacing the backing remains unimplemented").
