## The short answer

His branch is a different architecture.
- It deletes main's capture, `ShaderMemory`, recipes, the draw and dispatch caches, the resource cache and the reuse proofs.
- Instead, it reads every V#, T#, S# and SRT word on the GPU: a two-level BDA page table, a device-wide descriptor heap, and a hashed device image key table the shader probes itself.

**What does not port.** Most of what would cut Village's ~2 ms per draw is that architecture, and none of it cherry-picks:
- every piece built on the run-time path conflicts or needs deleted code;
- main has also moved on in the same files (e.g. ShaderResources.cpp +2,398 lines since 10-13).

**What does port is smaller:**
- **About 25 fixes to code main still has**, mostly one to 30 lines. Several sit right in main's per-draw validation path (`Revalidate`, dispatch-cache validation, DCC refresh proofs).
- **Memory and compile-hitch work** that matters on the 15.4 GB PC.
- **Clean shader-IR passes** (smaller SPIR-V, faster creation, no CPU gain).
