## What #9293 does, against this task

| task item | #9293 |
|---|---|
| implement as FreeBSD 11.4 `uipc_sem.c` does | `ksem_open` follows `sys_ksem_open` + `ksem_create`: `EINVAL` for other `oflag` bits, then for `value > SEM_VALUE_MAX`. It allocates the descriptor and writes `*idp` before checking the name, which gives `EFAULT` for a null name, `ENAMETOOLONG` at 1024, and `EINVAL` without a leading `/`. A missing name gives `ENOENT` without `O_CREAT`; `O_CREAT\|O_EXCL` on an existing name gives `EEXIST`; past 30 objects, a new name gives `ENFILE`. `ksem_close` is `EINVAL` for an unnamed or unknown id, as `sys_ksem_close` is. `ksem_unlink` gives `ENOENT` for an unknown name and `EFAULT`/`ENAMETOOLONG`. `ksem_destroy` of a named id becomes `EINVAL`, as `sys_ksem_destroy` returns. |
| share main's model, don't add a second one | It extends main's `Ksem.cpp`: the same `Ksem` objects, the same descriptor table, and the same close observer, plus a name table and a `named` flag. The 30-semaphore limit counts objects. |
| errors the way libkernel_sys returns errno | `-1` with `__error()`, as the rest of `Ksem.cpp` does |
| leave unmodelled paths throwing | The permission checks are not modelled: `mode` is accepted unchecked, and the debt entry says the names are process-local. Nothing throws. |
| test: `ksem_open("/t", O_CREAT, 0600, 1)` gives an id | yes (L549) |
| test: `ksem_close` returns 0 | yes (L565, L568) |
| test: `ksem_unlink` returns 0, and a second unlink fails with `ENOENT` | yes (L559–L560) |
| test: `O_CREAT\|O_EXCL` on an existing name gives `EEXIST` | yes (L550) |
| debt docs | adds a "ksem_open, ksem_close and ksem_unlink" entry |

The line numbers are in `diffs/9293.diff`; the tests start at its `GuestKernelSysKsem.cpp` hunk.

**Two differences from `uipc_sem.c` d106002967, both open in #9293's review:**
- **A null name.** `sys_ksem_open` passes the name straight to `ksem_create` (L635), which creates an **anonymous** semaphore when the name is null (L494). #9293 instead returns `EFAULT`, and its test asserts that (L546, L609). harisibrar1 raised this on 10-24, and oneandonlydean asked for FreeBSD's behaviour on 10-26. There is no reply from the author yet.
- **The permission check** (`ksem_access` against `mode`) is not modelled. #9293 documents this in the debt entry rather than throwing. In FreeBSD it only bites when a non-root caller reopens a name whose mode lacks owner read and write.

oneandonlydean also asked for one typed public declaration in `Api.hpp` and for the `dup`/`dup2` throw assertions to go. Main's `GuestKernelSysKsem.cpp`, from #9284, still has those assertions in `Duplicates()`. They are against the 10-26 rule that no test asserts a placeholder throw.

**A note on the task's premise.** In FreeBSD 11.4, libc's `sem_open` (`lib/libc/gen/sem_new.c`) is not built on `ksem_open`. It opens and maps a file under `/tmp/SEMD` (L65, L158, L179) and waits with `_umtx_op`. Only the FreeBSD 1.0 compatibility `sem_open` in `lib/libc/gen/sem.c` (L243) calls `ksem_open`.

So in 11.4, the ksem name table and `sem_open`'s names are separate namespaces. Main's `Pthread/Posix/Sem.cpp` models the `/tmp/SEMD` one. #9293 is right to put the named ksem table on `Ksem.cpp`'s model and not on `Sem.cpp`'s.
