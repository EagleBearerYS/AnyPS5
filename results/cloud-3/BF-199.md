- **Error codes** come from 2.5.4's `err/err.h`: `ERR_LIB_ENGINE` 38, and `ENGINEerror(r)` = `ERR_PUT_error(ERR_LIB_ENGINE, (0xfff), (r), …)`, so the function code is 0xfff. `ERR_R_PASSED_NULL_PARAMETER` = `3|ERR_R_FATAL` = 67, and `ENGINE_R_NO_SUCH_ENGINE` = 116 (`engine/engine.h`).
- **Error queue:** main has a working queue (`src/Error.cpp`: `LibreSslPutError_nid_no_patch`, `ERR_get_error`, `ERR_peek_error`), so the ENGINE errors are pushed rather than left waiting on #9529/#9535/#9536.
- **Why a non-null engine throws:** the module exports no `ENGINE_new`, `ENGINE_add` or `ENGINE_load_openssl`, and `ENGINE_load_builtin_engines` adds none, so no valid ENGINE pointer can exist; LibreSSL would dereference whatever was passed. `ENGINE_get_id` and `ENGINE_set_default`, outside this batch, stay throws for the same reason, as PM-088's review moved them.
- **What is assumed:** a console LibreSSL build with its own engines, or an `OPENSSL_NO_HW_PADLOCK`-less build, is not ruled out. The debt entry says so.
- **Placement:**
  - The init calls go in `src/Runtime.cpp` (as #10475 places its siblings, but after the existing functions to stay off its lines).
  - The ENGINE calls go in a new `src/Engine.cpp`, added to the library's `CMakeLists.txt`.
  - `include/Api.hpp` gets the real signatures in place, and the 16 stubs leave `Export.cpp`.
- **Debt file:**

  - A new entry covers the init calls (729 characters).
  - A new entry covers the ENGINE calls (970 characters).
  - The error-queue entry now says the ENGINE calls are the only exports that add an error.
- **Note for the PM, on the init calls:** #10475 lists its three siblings (`CONF_modules_free`, `OPENSSL_load_builtin_modules`, `OPENSSL_add_all_algorithms_noconf`) under a new "Silent stubs" section.
