## 2. Red for (a) on main: none

**Case (a) passes on main.** Before writing the cases I probed driver write paths on main with the same fixture (a throwaway `--probe N`, uncommitted). Each variant writes into the stencil plane's first page, then reads that page from the CPU:

```
[probe] 1 StoreOwnBytes(span) 4 bytes: Read succeeded, 4092 of 4096 bytes as the host drew, +0x64 reads 0x77
[probe] 2 StoreOwnBytes(lambda memcpy) 4 bytes: Read succeeded, 4092 of 4096 bytes as the host drew, +0x64 reads 0x77
[probe] 3 direct write + MarkWritten 4 bytes: Read threw: AGC graphics: native multisample depth publication cannot distinguish an unwritten byte from a same-value guest store
[probe] 4 6 StoreOwnBytes pieces in the page: Read threw: AGC graphics: native multisample depth publication cannot distinguish an unwritten byte from a same-value guest store
[probe] 5 QueueTargetByteWrite (GPU fill, completion StoreOwnBytes): Read succeeded, 4095 of 4096 bytes as the host drew, +0x64 reads 0x77
[probe] 6 StoreOwnBytes 4 bytes in two blocks' pages: Read succeeded, 4092 of 4096 bytes as the host drew, +0x64 reads 0x77
```

**Why main already handles (a):**
- **The per-byte check** in `PublishToGuest` is `UnchangedSinceLastCollect(byte, 1, generation)`, which is `cpuUnchanged(byte) && rangeUnchanged(byte, walked=false)`.
- **For CPU stores it's page-granular,** through `cpuPages`.
- **For driver stores it's byte-exact:** `storedOver` checks each recorded complete piece (`DriverPieces::pieces`) against the byte, and ignores walk pages once the block has pieces.
- So a byte outside the recorded pieces of a page with no CPU, possibly-written or refused stores already keeps the host's value.

**The two variants that refuse on main are not this task's case:**
- **Probe 3, a direct write then `MarkWritten`:** `markWritten`'s fresh collect (`GuestWriteWatchCollectFresh` over the 64 KiB block) records the direct write's dirty page as a **CPU** store (`noteCpuStore`). By the tracker's own view that's a CPU-store page, which the task says must keep refusing.
- **Probe 4, more than 4 complete pieces in one 64 KiB block:** `noteDriverStore` keeps 4 pieces per block. The oldest piece's exact range is lost (`dropped` = its generation), and `storedOver` then treats the whole block as stored.
  - **Why this one can't simply keep the host bytes:** a dropped piece may have stored the snapshot's own value (§3).

## 3. The proposed rule

**What I tried:** I implemented the rule from step 2 locally (not pushed) as a non-collecting `GuestMemory::OnlyCompleteDriverStoresSince(address, bytes, generation)` under the tracker lock. It holds when the page:
- had no CPU store since the generation (`cpuUnchanged`);
- had no refusal (`refusedSince`);
- had no possibly-written whole, dropped or overlapping piece in any stamped block;
- and every block stamped since the generation has `driverPieces`.

`PublishToGuest` evaluates it once per page in the per-byte branch, and skips the refusal for bytes of such pages.

**Results with the rule:** cases (a)–(d) all stay green. Three extra local cases go to stderr:

```
[driver-page] case 4: Read succeeded, +0x64 reads 0x77 (host 0x20), 4072 of 4096 bytes as the host drew
[driver-page] case 5: Read succeeded, +0x64 reads 0x20 (host 0x20), 4076 of 4096 bytes as the host drew
[driver-page] case 6: Read threw: AGC graphics: native multisample depth publication cannot distinguish an unwritten byte from a same-value guest store
```

- **Case 4 (6 complete 4-byte pieces in the page):** it now publishes.
- **Case 5 loses data.** The **first** driver store writes **0x5a** (the snapshot value) at +0x64, a byte the host drew as 0x20. Five more pieces then push that piece out of the tracker.
  - **With the rule:** the read returns **0x20**, the host's byte, so the driver's later store is lost.
  - **On main:** the same case refuses (cases 4, 5 and 6 all throw on main).
  - **Why:** a dropped complete piece is exactly a "possibly stored, same value unknown" range, which the task itself puts on the refusing side.
- **Case 6 (direct write + `MarkWritten`):** still refuses, as on main, because the dirt counts as CPU.
- **The safe version is a no-op:** adding "no dropped complete pieces since the generation" makes the rule safe. But it then makes exactly the same decisions as main's per-byte check, so there's nothing to commit.

## Summary for the Bug Finder

1. **No red:** on main 1c8c0efc8c, a stencil page that only complete driver stores (`StoreOwnBytes`, including a GPU-queued completion store) changed already publishes. The host's bytes are kept around the stored ones, because the per-byte check is byte-exact against recorded driver pieces.
2. **The proposed rule is unsafe.** It changes only blocks with **more than 4 complete pieces** (dropped ranges). There it publishes the host's byte over a dropped driver store of the snapshot value: case 5 reads 0x20 where the driver stored 0x5a. With "no dropped pieces" added, it equals main. **Nothing was pushed as a fix.**
3. **Pushed:** `fix/agc-depth-publication-driver-pages` = **100cf78b61**, the test cases (a)–(d) only, all green on main.
   - **Tests:** 28 pass, 1 skip, ×3, the same on main and the branch.
   - **Checks:** registration and conventions pass, 0 comment lines.
   - **Mutations:** the cases catch dropping the keep-host path (a) and dropping the CPU check (d, and b with the pieces check gone).
4. **What makes the titles' pages ambiguous is still unknown.** On main, an ambiguous page in a host-drawn plane comes from one of four things:
   - **(i) A CPU-classified store,** including a driver write through a dirtying mapping followed by `MarkWritten`, whose fresh collect counts it as CPU (probe 3).
   - **(ii) Dropped complete pieces** (more than 4 per 64 KiB block, probe 4).
   - **(iii) A possibly-written mark.**
   - **(iv) A refusal.**
5. **Suggested next step:** extend `diag/native-depth-publication-9533` so each ambiguous page also prints which of (i)–(iv) holds, using a small tracker query.
   - The fix then depends on the answer:
     - **(ii):** keep more exact ranges, for example more pieces or the dropped ranges as possibly-stored bounds, rather than keeping host bytes.
     - **(i) from a driver write-back:** make that write path attribute its dirt to the driver (`storeOwn` or shared-backing writes) instead of changing the publication.
