## 6. Two gaps in behaviour the merge leaves (no test fails; a decision for the PR Manager)

**1. The GPU-heap draw path doesn't take main's converted-sample retry.** It only matters with `APS5_GPU_HEAP=1` on top of the GPU path.
- **Main's retry:** 8545c2301 (ps54all, "sample converted unorm images in the shader") prepares shaders without converted-sample modes. `ResourceMaterializer` throws `ConvertedSampleRequired` when a descriptor turns out to be an 11_11_10 image. Main's `CaptureInvocation` (`ShaderRegistry.cpp`) catches it and retries on a request with `convertedSamples` set. Every capture site on main goes through it, and the merge routes lane A's heap-verify capture through it too (section 2, `DrawCapture.cpp`).
- **What escapes it:** lane A's heap-direct capture, `MaterializeHeapStage` (`HeapStages.cpp`, `invocation.Capture(plain)`), is called from `materializeDrawStage` without a catch. Such a draw is refused with the exception instead of retrying.
- **Untested:** no test reaches it. `agc_driver_image_converted_unorm` drives `VulkanDevice` dispatches directly, not the driver's draw path.
- **Proposed fix** (not in the tree), in `DrawCapture.cpp`: fall back to the capture path, which does retry.
  ```cpp
  std::shared_ptr<const ShaderRecompiler::RecompileResult> direct;
  try {
      direct = MaterializeHeapStage(invocation, program.userData, program.binary.codeAddress, words.get(), &reusedWords);
  } catch (const ShaderRecompiler::ConvertedSampleRequired&) {
  }
  if (direct == nullptr) goto heapCapture;
  ```
  It needs a driver-level draw test with an 11_11_10 texture and `APS5_GPU_HEAP=1`, so I left it for whoever takes #7642's main merge.

**2. #6566's no-copy saving is lost on lane A's tail path.**
- **On main:** #6566 copies a draw's programs only when a mesh index-buffer word or an indirect user-data patch writes them (`writablePrograms`).
- **In the merge:** lane A's `DrawTail` must own the programs once the finisher may run the tail, so it always copies them into `tail.programs`, and main's two patch sites write that copy.
- **Cost:** behaviour is unchanged, but an unpatched draw now pays for one programs-vector copy again. That's an allocation per draw, the thing #6566 removed.
- **To get it back:** the tail would hold the draw's programs by reference while no patch is needed, and copy only on the first write. Lane A's finisher hand-off would then also need the copy before it hands off.
