## 1. b37ae00e68: AnyPendingOverlaps consults the pending image range index first

**What it changes, and the cost it removes:**
- `StorageTexture::AnyPendingOverlaps` (main:3568) takes a list of guest ranges and answers whether a pending storage image (GPU results not yet stored) overlaps any of them. It walks every pending image and tests each range against it.
- The registry keeps a sorted, merged range index of the pending images, `PendingList::MayOverlap` (main:1165, class at main:1149).
  - Its sibling queries already ask that index first and skip the walk when it rules the range out: `FlushPending` (main:3218), `PendingStorageOverlaps` (main:3558), `overlappingPending` (main:3600) and `ScanPending` (main:3763).
  - `AnyPendingOverlaps` never asks it.
- The commit asks the index for each range first, and walks the images only when one may overlap. The images a `FlushPending` is still storing (`pending.flushing`) are walked as before.
- **Who calls it:** descriptor table reuse on every draw (`ShaderResources.cpp:1454`, `:4281`), dispatch variant validation (`Execution/src/Driver/Dispatch/VariantValidation.cpp:96`, `:105`), copies (`Execution/src/VulkanDevice.cpp:2034`, `:2402`, `:2549`) and import retires (`GuestBufferMemory.cpp:2599`).
- So every query that overlaps nothing, the common case, cost one test per pending image. After the commit it costs one binary search.

**Whether main still has the cost:** yes, unchanged since the merge base. Main:3568-3585 is the explorer base's code line for line.

**What it touches:**
- `Graphics/src/Texture.cpp`: `StorageTexture::AnyPendingOverlaps`. It reads `PendingList::MayOverlap`, which is unchanged.
- The port also adds:
  - `StorageTexture::PendingOverlapWalks()` (`Graphics/include/Texture.hpp`, next to `UntrackedCompares`, and `Texture.cpp`). It counts the calls that walk the pending images.
  - `tests/Recorder.cpp`: `PendingImages`, `pendingOverlapIndexTests`, `pendingOverlapIndexBenchmark`, and two modes in `main`.
  - `core/libs/prx/libSceAgcDriver/CMakeLists.txt`: the `agc_pending_overlap_index` test.

**The port:** one commit, 9ec8f2104c, 4 files, +101/−2.
- The explorer's three changed lines are applied unchanged. The counter's increment sits on the walk.
- The commit message credits the original author, Scott Schuster.

**The test**, `agc_pending_overlap_index` (`agc_driver_recorder_tests --pending-overlap-index-only`):
- Eight 64×64 storage images are made pending, 64 KiB apart, with host imports off.
- A range inside the fourth image is found with exactly one walk.
- Three ranges, two in the gaps between images and one past the last image, are refused 64 times with no walk.
- The last byte of an image is found with a second walk.
- The images are then stored back.

## 2. 9d10311382: compare a writable image mirror once per collect epoch unless the driver stored into it

**What it changes, and the cost it removes:**
- An address-based build served from the cached address space (`GuestBufferMemory::AcquireRegistered`, main:2675) refreshes every writable image mirror. The loop is at main:2739-2742, over `space->writableMirrors`, built by `planSpaceMirrors` at main:1781.
- **Writable image mirrors** are non-releasable, writable, GPU-mapped ranges outside the write-watched arena: GPU-mapped exe data.
- **The refresh:** `prepareRefresh` (main:1610), then `appendBlocks` (main:1616), then `compareBlocks` (main:1627). Every build compares every 64 KiB block of the mirror with guest memory, because nothing else tells it which blocks changed.
- **The memo:** the commit keeps, per mirror, the stamp of its last whole compare (`ImageMirror::compared`, a new field; `compareStamp`, a new function). The stamp has four parts:
  - the thread's collect epoch;
  - `GuestMemory::NewestStamp` over the range, which records the driver's own stores;
  - `GuestMemory::ForgetSerial`;
  - the recorder's `NewestWriteNote`.
- A later build of the same epoch with the same stamp skips the compare. The refresh's sync still runs.
- **The ordering it relies on:** a CPU store between two builds of one epoch is seen in the next epoch. That is the collect memo's documented ordering (`Execution/include/GuestMemory.hpp:85-91`), which it says matches real hardware.
- **The switch:** `APS5_NO_COLLECT_MEMO=1` makes `CollectEpoch()` return 0 (`Execution/src/GuestMemory.cpp:1274`). The stamp is then empty, and every build compares again.

**Whether main still has the cost:** yes. Main:2733-2742 still compares every writable mirror on every build. Its comment reads "Writable mirrors are compared with guest memory per build".
- Every primitive the commit uses exists unchanged on main: `CollectEpoch`, `ForgetSerial`, `NewestStamp`, `NewestWriteNote`.
- `StorageTexture::compareUntracked` (`Texture.cpp:2108`) memoizes with a 5-part key that includes `UntrackedHint`. The explorer's 4-part, epoch-only stamp is the more conservative of the two, and I kept it.

**What it touches:**
- `Graphics/src/GuestBufferMemory.cpp`:
  - `struct ImageMirror` (main:61): the new `compared` field;
  - the new `compareStamp`, after `prepareRefresh`;
  - `GuestBufferMemory::AcquireRegistered`: the served path's writable-mirror loop (main:2739), and the stamps stored after `compareBlocks` (main:2896).
- The port also adds:
  - `MirrorStats::blocksCompared` (`Graphics/include/GuestBufferMemory.hpp`) and its value in `MirrorCounters` (main:2251);
  - `tests/Recorder.cpp`: `ImageData`, `MappedImageData`, `writableMirrorCompareTests`, `writableMirrorCompareBenchmark`, and two modes in `main`;
  - `CMakeLists.txt`: the `agc_writable_mirror_compare` test.

**The port:** one commit, 4267241f61, 4 files, +104/−2. The explorer diff cherry-picked cleanly onto main.

**The test**, `agc_writable_mirror_compare` (`agc_driver_recorder_tests --writable-mirror-compare-only`):
- **Setup:** it registers the test binary's own image (`RegisterMainImage`) and GPU-maps two 64 KiB blocks of a static array in it (`Protect` with `gpu`). With host imports off, an address-based build then makes a writable image mirror, as a title's exe data does.
- **Checks:**
  1. In one collect epoch, a third build compares nothing.
  2. A driver store into the range (`GuestMemory::MarkWritten`) makes the next build of the same epoch compare both blocks.
  3. A CPU store, then a new epoch, makes the next build compare both blocks and copy the one written.
- **Isolation:** each recorder mode is its own process, so the image registration touches no other test. The fixture clears the image mirrors (`ClearImageMirrors`) before the device goes away.

## 3. ccbc69741f: look past an emptied buffer pool size class

**What it changes:**
- `BufferPool::Take`'s device tier looks for a retained buffer in the size classes up to twice the request (main:230, loop at main:246).
- The explorer's port of the pipelined draws (d0dafcd4c, from #1201's 449e69422a) kept a size class in the free map once its last buffer was taken. It did this to save a map node allocation per recorded draw ("buffer pool size classes kept").
- The search then stopped at the first class it found, empty or not, and missed a larger class that still held a buffer. ccbc69741f makes the search go on past an empty class.
- d0dafcd4c also guarded `evictOldest` against an empty class (a `lastUse` of max for empty entries).

**Whether main still has the cost:** no, because main never keeps an emptied class.
- #1201's own commit on main, 3b34d1fdb, does carry the "size classes kept" change: it removes both erases.
- But the merge of #1201, e49ec591d, resolved `Graphics/src/BufferPool.cpp` to main's side: `git diff e49ec591d^1 e49ec591d` on the file is empty. So main still erases an emptied class in `Take` (main:253) and in `evictOldest` (main:266), and the search can never meet an empty class.
- **Its test on main** (local only; this branch's `BufferPool.cpp` is main's): ccbc69741f's `EmptiedClass` test passes ("buffer pool tests passed").
- **For the PM, if anyone re-applies "classes kept" to main**, it needs two things together.
  - Local runs of main's buffer pool test, with the test added:
    - only the erases removed, as in 3b34d1fdb: **segfault** ("FAIL: an unknown buffer was destroyed"), because `evictOldest` reads the front of an emptied class;
    - plus d0dafcd4c's `evictOldest` guard: **fails**, "a 7 MiB request whose own class was emptied did not take the retained 12 MiB buffer";
    - plus ccbc69741f's search: **passes**.
  - So 3b34d1fdb's pool change was unsafe on its own, and the merge that dropped it kept main safe.

**What it touches:** `Graphics/src/BufferPool.cpp`, `BufferPool::Take` (the size-class search loop), and `tests/BufferPool.cpp` (`EmptiedClass`). Nothing is ported.

## 4. 237166cb15: an address-based build evicts idle imports instead of copying past the cap

**What it changes, and the cost it removes:**
- `GuestBufferMemory::AcquireRegistered`'s per-build pass (main:2768-2823) imports each registered GPU range without eviction (`importAllocation(..., false)`, main:2777).
- A range that the import budget refuses and no mirror serves is copied on every build.
- Copies past `APS5_ADDRESS_COPY_MAX_MIB` (64 MiB by default) abort the process (`AddressCopyOverflow`, main:2235; the abort at main:2819).
- The commit retries such a range's import with eviction only when its copy would take the build past the cap, that is when the build would otherwise abort.
- The copy reason of a heap also names what refused it, instead of "outside the write-watched arena" for every heap.
- This is PM-024's commit (a): `git patch-id` of 237166cb15 equals that of 25c333e47 on the fork's `test/address-copy-cap-fix`.

**Whether main still has the cost:** yes. Main:2768-2823 is the explorer base's pass with the same no-eviction import and the same fatal cap.
- #5542 and #5906, which the task names, are already in the merge base, so they are not differences.
- Since the base, main's #6060 (watched private imports, the 1 MiB settle floor), #5870 (7b06e7594, promote a held import window) and several address-space cache fixes changed `GuestBufferMemory.cpp` around this pass.
- None of them evicts there or lifts the cap.

**What it touches:**
- `Graphics/src/GuestBufferMemory.cpp`:
  - `struct HostImports` (main:165): the new `budgetRefusals`;
  - `importRunAt` (main:1043): one increment on its budget refusal;
  - the new `heapCopyReason`;
  - `GuestBufferMemory::AcquireRegistered`: the per-build lease loop, which now reads the copy cap before the loop, keeps a running copy total, and retries with eviction.

- The test commit touches `tests/BdaResources.cpp` (`RunAddressCopyCapTests`), `tests/BdaTests.hpp`, `tests/Graphics.cpp` (the `--address-copy-cap` mode) and `CMakeLists.txt` (`agc_address_copy_cap`).
