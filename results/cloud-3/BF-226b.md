```
fix(libSceNpManager): follow the measured IdMapper checks and NpManagerInt request table

BunnyFl measured firmware 13.42 libSceNpManager.sprx. The IdMapper
account-id lookups take seven arguments: a request id of 0 or less
gives 0x80553085, then user id -1, a null pointer or a value outside
1 to 1000 gives 0x80553083, and past the checks they answer signed out
as main's offline model does. IdMapper abort and delete refuse a
request id of 0 or less with 0x80553085, and IdMapper requests get a
counter of their own instead of the sceNpCreateRequest pool.

NpManagerInt requests sit in a 64-slot table of their own: the 65th
live request gives 0x80559D05, delete gives 0x80559D0A for an id the
table does not hold, and abort answers from the offline service.
```

- **Error names:**
  - `NP_ID_MAPPER_REFUSED_ARGUMENT` (0x80553083) and `NP_ID_MAPPER_REFUSED_REQUEST_ID` (0x80553085) come from e722b5a50d.
  - `NP_MANAGER_INT_REQUEST_DUPLICATE` (0x80559D03), `NP_MANAGER_INT_REQUEST_TABLE_FULL` (0x80559D05) and `NP_MANAGER_INT_REQUEST_NOT_IN_TABLE` (0x80559D0A) are new, with no `SCE_` prefix because the SDK names are unknown.
- **Edge paths and how far the offline model reaches them:**
  - **Negative or zero service ID:** implemented. They are reachable only after this family's 32-bit counter wraps (2^31 creates), so they are untested.
  - **Duplicate ID:** implemented. It is reachable only after a full 2^32 wrap with the old request still live, so it is untested.
  - **Record allocation failure (`0x80559D03`):** not modelled. A host allocation failure throws `std::bad_alloc`.
  - **In-use delete** (marked deleted, left in place, the service answer returned): never reached, because no call holds a request. Per the ruling, the getters answer for any ID without a lookup. The debt says so.
- **Not initialized:** left out for all 14 calls, per ruling 2. The debt's new "NP service client initialization" line records BunnyFl's `0x80550002` (M2, M3) and that main doesn't model it.

## For the PR Manager

### #10879: What

> BunnyFl measured firmware 13.42 `libSceNpManager.sprx` ([arguments](https://github.com/boykopovar/AnyPS5/pull/10879#issuecomment-6397162725), [request table](https://github.com/boykopovar/AnyPS5/pull/10879#issuecomment-6397362281)), and this PR now follows those measurements exactly; where the module hands off to the NP service, the answer follows main's offline model, as `sceNpCreateRequest` and the public `sceNpGet*` calls already do. `sceNpIdMapperNpIdToAccountId` and `sceNpIdMapperOnlineIdToAccountId` take the measured seven arguments: a request ID of 0 or less returns `0x80553085`, then user ID -1, a null input or output pointer or a 32-bit value outside 1..1000 returns `0x80553083`, and past those checks they answer `SCE_NP_ERROR_SIGNED_OUT` without writing. IdMapper requests get a counter of their own; `sceNpIdMapperAbortRequest` and `sceNpIdMapperDeleteRequest` refuse a request ID of 0 or less with `0x80553085`, then abort leaves a live request live and delete frees it. NpManagerInt requests sit in the measured 64-slot table: the 65th live request returns `0x80559D05`, `sceNpManagerIntDeleteRequest` returns `0x80559D0A` for an ID the table doesn't hold, and `sceNpManagerIntAbortRequest` answers from the service without a local lookup. The measured `0x80550002` before the NP service client exists isn't returned, since main doesn't model NP initialization; the debt records it.
