**3. A vouch stays cheap under queued draws** (commit 28).
- **The drain.** On main, `queryPendingWrite` drains queue 0 when a queued draw writes into the asked range. v3 asks it about a table's whole span: in the validation vouch, the capture's stamp and the capture's unchanged-since check. The span includes the gaps between records, so a queued draw writing only into a gap would drain where main's per-record checks never do.
- **The fix.** These three checks now use `Driver::QueryPendingSpan`, which treats a queued draw writing into the span as a pending write and refuses instead of draining.
  - The variant or capture then takes the per-record path, which drains exactly where main does.
  - With draws queued, the cost is one `Overlaps` scan: the pipeline mutex, at most 8 items.
- **Tests, red without the fix and green with it:**

## 1. Design: one table object per heap, shape and write epoch

**The object.** A column's words live in one immutable block, `SrtGuestWords`:
- the runs and words read;
- the span `[low, high)` the runs cover;
- `ordered`, set once when the memo keeps the block: the runs are sorted, aligned, don't overlap and add up to the words;
- a shared `SrtStampCell`, a seqlock holding the stamp `{generation, layout}`, which is the write epoch.

The memo (`TableSnapshotter`, per thread, 16 entries within 4 Mi words) builds the block once per `ColumnKey`: the heap's base, size and record count, the key count, stride, addend, offset, dword count, max key, the folded addend and carry, and the address and sampler flags. That key is the "(heap, shape)" part; the stamp cell is the epoch. Everything downstream holds the block, or values built from it, by reference:

| Consumer | What it shares | How it is checked |
|---|---|---|
| Capture (`TableSnapshotter::Reuse`) | the block and the column built from it (`SharedValues`: codes, distinct T#s, read ranges) | one `ShaderMemory::Vouched` call over `[low, high)` with the block's stamp, before any stamp is taken; no copy, no scan of the runs |
| Shader memory (`supplyWords`) | the block, kept by reference and reported page by page | `ordered` block: one `Accessible` call over the span |
| Recompile result memo (`ResolveImageTablesShared`) | the resolution, keyed by the column's shared values by identity | identity of the codes and distinct T#s |
| Draw and dispatch cache variants | `SharedWords` (a weak reference to the block, with the regions it covers) | hit: `VouchSharedRegions`, one vouch per block over its span, then the block's regions are skipped by range. Insert: `SameCapturedWords` treats words copied from the same place of the same block as equal |
| Bound table (`ShaderResources::resolveImageTables`) | `ReusedTable`: per element, the texture, the bind outcome and the sampler key it was bound with | `FindReusedTable` (table words, shapes, depth compare, `TableState`), `TableCurrent`, `CachedTableTextures`; replay when the sampler masks and sampler words are unchanged |
| Descriptor set (`DescriptorCache`) | a kept dedicated set with the table descriptors it holds | same layout, sizes and variable count to take the set; same runs, views and layouts to skip the table's writes |

**Stage 1, capture.**
- **Hit (`Unwritten`).** `LoadStamp`, then one `unchangedSince` over the block's span. That runs `ShaderMemory::Vouched`: the layout equals the stamp's layout, no pending write over the span, `FlushGpuWrites` over it, a successful `CollectWrites`, and `UnchangedSince(span, generation)`. Then `supplyWords` hands over the block.
- **Cost of a hit.** It is O(1) in the record count. The one size-dependent part is the tracker's walk over the span's 64 KiB blocks: 24 for Village's 1.5 MiB heap.
- **Miss.** The capture stamps the column (flush, layout and generation first, the pending query last; see gap 2), then `Compared` reads the runs and compares them with the block. If they are equal, it stores the new stamp into the block's cell, so every variant and capture sharing the block sees the renewed epoch. If they differ, the walk takes the words just read (each word is read once) and builds a new block: a new epoch, a new object.

**Stage 1, compare** (the draw and dispatch cache hit):
1. `VouchSharedRegions` vouches each live block a variant references, once, over its span.
2. A vouched range is dropped if the pending view overlaps its span.
3. The other checks run over the variant's other runs plus one span per vouched range: `syncPendingRuns`, the storage-texture registry, unit shadows and queued labels.
4. `validateCaptured` skips the vouched ranges.

A released block's weak reference fails and the variant compares as before. `PendingList::SurelyClear` answers "no pending image over this range" from a published snapshot without the registry mutex; that answer was most of the flush hook's cost under contention.

**Stage 2, resolution.**
- The recompiler side reuses a resolution by column identity (`ResolveImageTablesShared`).
- The driver side keeps the last four resolved tables per thread (`ReusedTable`, from #757). On a reuse, it now replays each element's recorded bind outcome when the binding's sampler masks and the stage's sampler words and flags match. That skips the filter-minmax, border-swizzle, cube and per-sampler decode checks.

**Stage 3, descriptor writes.**
- A freed dedicated set (one table of 4,096 T#s needs one) is kept: up to 8, set with `APS5_KEPT_DESCRIPTOR_SETS`.
- A build with the same layout, sizes and variable count takes a kept set instead of creating a pool.
- If the set's recorded table descriptors equal the new ones (same runs, views and layouts), the table's writes are left out of `vkUpdateDescriptorSets`. `descriptorWrites` stays complete for draw snapshots.
- The record is made when the resources are released (commit 25), only after the build's writes were issued.

### What invalidates what

| Event | Capture (block) | Compare (variant) | Bound table | Kept set |
|---|---|---|---|---|
| CPU store into the span, between records included | collected stamp > generation: refused, then compare | the block's vouch is refused: compare | n/a (table words are compared by `SameTable`) | n/a |
| Driver store (`StoreOwnBytes`, `GuestMemory::Write`) | driver stamp: refused | refused | element texture stamped: `TableCurrent` false | new view or layout: writes made |
| GPU write recorded, pending (packet store, CP `WRITE_DATA`, `RELEASE_MEM`, DMA fill or copy, compute) | pending query: refused | pending view overlaps the span: range dropped, run-by-run checks | `StorageTexture` pending over an element: false | n/a |
| GPU write completed (`MarkWritten` at completion, reap or copy-back) | stamp > generation: refused | refused | element stamped: false | n/a |
| Deferred results kept on the GPU (storage images, unit shadows, queued labels) | `FlushGpuWrites` stores them first (0431419d1), then stamped: refused | same | pending storage: false | n/a |
| Label kept behind completions (reason 5) | noted before stamping (gap 2, e1c312fd8) | same | n/a | n/a |
| Partly watched store (an import edge) | the watched blocks are stamped (c886c28d1) | same | same | n/a |
| Mapping change (unmap, remap, protection) | `layout` differs: refused; `Accessible` | refused | `TableState.allocations` | n/a |
| Range unwatched (import on Linux, failed collect) | `CollectWrites` returns 0: refused | refused | `TableState.unwatched` | n/a |
| Texture replaced in the texture cache | n/a | n/a | `CachedTableTextures` false | different view: writes made |
| Texture state (layout, first-layer view) | n/a | n/a | n/a | different layout or view: writes made |
| Sampler masks or sampler words change | n/a | n/a | bound again with every check (no replay) | n/a |
| A new collect epoch (submission start, satisfied `WAIT_REG_MEM`, drain) | n/a | n/a | the table is dropped (inherited from #757; see §4 and follow-up 1) | n/a |
| Block released (memo eviction) | n/a | weak reference fails: compare | n/a | n/a |

## 3. Bench and per-stage tables

**The bench** (drop commits 21 and 23, `agc_driver_image_table_village_bench_tests --village-bench`) models Village's title-menu load on the table paths:
- one heap of 32,768 T# records at a 48-byte stride (the shader multiplies the key by 48, so every record is its own run);
- 4,096 distinct T#s;
- three queue workers (DCB queue 0 and two ACB queues), each submitting rounds of 8 table dispatches over 16 outputs, plus a storage-image store per submission, so the recorder is active, the storage registry is populated and results are pending;
- 25 s per run.

## 4. Correctness

**PM-028's vouching rules, or an exact cheaper equivalent.**
- The rules are unchanged: the stamp's layout, no pending write, `FlushGpuWrites`, a successful `CollectWrites`, and `UnchangedSince(generation)`.
- They are applied to `[low, high)`, a superset of the runs, instead of to each run. So the answer is the same or more conservative. A store between two records (not read by the column) refuses the vouch; the column is then compared and, if equal, kept with a renewed stamp.
- The block's stamp lives in one shared seqlock cell. A reader that races a renewal sees no stamp and compares.
- A released block's weak reference fails, so its identity is never reused.

**Gap 1 (partly watched store), from PM-037.**
- Folded in unmodified as commits 1–2: same patch-ids as 89343ba7f and b7c33252c.
- `MarkWritten` and `storeOwn` now stamp the watched blocks of a store that also covers unwatched memory.
- #6060 (watched private imports) has since merged into upstream main. Its compare-free vouch for Windows private imports has the same gap, so commit 1 is worth landing on its own, ahead of this PR.

**Gap 2, closed** (commit 12, with a two-thread test):
- `stampWrites` now flushes, takes the layout and generation, and asks for pending writes last.
- The label path (reason 5) notes the completion before stamping.
- `CopyBuffer` stamps, notes and stamps again. Its ring entry carries the second generation, so the known-value ring's "stamp before note" order holds.
- Red before the fix: `table stamp race: a GPU write stamped while the table was stamped, before it was noted pending, was hidden by the table's stamp`. Green after.

**Gap 3 (BDA stores stamped only at reap), weighed, not changed.**
- `markWrittenPages` (BdaResources.cpp:307-329) stamps a buffer-device-address store only when its batch is reaped, and never notes it pending. The ranges are known only after the dispatch.
- Window: between the GPU finishing such a store and the reap, a vouch can pass over pre-store words. Main has no vouch, but it reads such a table at record time and so sees whatever the GPU has written by then. The vouch adds only the window between completion and reap. At the reap the store is stamped, the next vouch is refused and the column is read again.
- Closing it exactly needs the BDA write ranges before the dispatch, which the driver does not know. Cheaper options:
  - refuse every vouch while a BDA-writing batch is unreaped (a global count). Exact, but it disables the vouch in titles that write through BDA every frame;
  - stamp at completion instead of at reap.
- Neither is in this PR; it is follow-up 3.

**`MarkWritten` audit under #6060.** Every GPU write path from PM-037's table, re-checked on v3:

**Stage 2's reach, and a pre-existing #757 gap.**
- A bound table is reused only within one collect epoch. The epoch advances at every submission start, satisfied `WAIT_REG_MEM` and drain.

- In the bench's default configuration (8888 UNorm in imported memory) 99 of 100 resolves were therefore never kept. With `APS5_NO_SAMPLED_FROM_STORAGE=1`, as Village's block-compressed textures behave, the replay hits (§3, "snapshot textures").
- Pre-existing, also on main: `resolveImageTables`' reuse branch calls `CompletePendingCpuWrites` for each element *after* `TableCurrent` has judged the textures unchanged. A recorded writer (copied buffer, draw writer or pending label) over an element's memory is synced after that decision, so the table can bind the texture from before the write. The miss path syncs first. Replay keeps the existing order, so v3 neither adds nor closes this window.
- Fix: complete the pending CPU writes for every kept element before `TableCurrent`. It is a prerequisite for follow-up 1, which keeps a table across epochs, and I did not put it in this PR.

## 8. Limits and follow-ups (the better version)

1. **Keep a bound table across collect epochs.** Measured potential: in the snapshot-texture runs about 1 build in 5 still resolves (9.1 ms against 0.3 ms for a replay). In a diagnostic run, 19 of 20 resolves followed a table dropped for a new epoch. When a table's epoch differs, collect its textures' merged ranges and then check `UnchangedSinceAll`; that is what the miss path does element by element. It first needs the `CompletePendingCpuWrites` reorder (§4), or a writer still recorded from the previous submission is synced after the decision.
2. **Bound tables of storage-viewed textures.** A table whose surfaces live in host imports with non-BC formats is never kept. Keeping it needs the per-element storage source's version and pending state in `TableCurrent`.
3. **Gap 3:** stamp BDA stores at completion instead of at reap, or count unreaped BDA-writing batches.
4. **O(regions) left on a hit:** `appendEntryRegions` (~160 µs) and the dispatch hit's `captured` copy. Cache a variant's entry regions, or reference the block's regions instead of materializing them.
5. **First-capture variants have no block,** so they validate by compare until a capture through the memo replaces them. Seeding the memo from the first walk would vouch them from the start.
6. **One memo per worker thread.** A table used by three queue workers is three blocks with three stamps. A process-wide memo keyed by `ColumnKey` would share one epoch object, at the cost of a lock.
7. **64 KiB tracker blocks.** GPU outputs that share a block with the heap refuse every vouch. Finer stamps for heaps would fix that.
8. **Kept sets** hold up to 8 tables' textures alive until the cache goes (`ClearCachedTextures` runs only at teardown). An LRU tied to the texture cache's eviction would release them earlier.
9. **`DescriptorBinding` identity.** The recompiler still compares the table's words (~10 µs) where the column's identity would do.
10. **The descriptor cache unit test** should read `APS5_KEPT_DESCRIPTOR_SETS` like the reuse test does (§5).
11. **Ask the draw pipeline once per vouched table.** Main's `validateVariant` drains first if a queued draw writes into any of a variant's runs. With draws queued, that is one locked scan per run: 4,096 for this table. After the vouch it could ask once per vouched span. It's not in this PR: Village's queue 0 seldom has draws queued, and the check is main's own.
12. **A branch for the clean PR history** (636753bfb, see the header), so the PR opens without the drop commits.

## 9. Draft PR

```
Title: perf(agc): share one image table per heap and write epoch through capture, compare, resolution and descriptors

### What
A bindless heap like Resident Evil Village's (32,768 T# records at a 48-byte stride, 4,096 distinct textures) was read, compared, resolved and written again for every dispatch or draw that used it, even when nothing had written it. With three queue workers, a cached dispatch spent about 21 ms comparing the table, a resource build about 10 ms resolving it and about 8 ms creating a descriptor pool for it (lavapipe).

This keeps one immutable object per heap, record shape and write epoch, and has every stage hold it by reference:
1. Capture. A table column is kept once per queue worker as an immutable block of words with a shared stamp cell (the write epoch). A capture that finds the column unwritten checks that with one write-tracker query over the block's span, before taking any stamp, and takes the block by reference: no read, no copy. A compare that finds the words unchanged renews the epoch for everyone sharing the block. The column memo this builds on (reuse of an unwritten column, and sharing its column, words and resolution by reference) is included as the first commits.
2. Compare. A cached draw or dispatch variant remembers which words came from a block. A hit vouches for each block once and skips its regions by range; the words around it are compared as before, and anything pending over the span falls back to the per-run checks.
3. Resolution. A reused bound table replays each element's recorded bind outcome instead of rerunning the per-element checks, while the binding's sampler masks and the stage's sampler words are unchanged.
4. Descriptor writes. A freed dedicated descriptor set (a 4,096-element table needs one) is kept, up to 8. A build with the same layout and sizes takes it instead of creating a pool, and leaves the table's writes out of vkUpdateDescriptorSets when the set already holds the same views and layouts.

With pipelined draws, a vouch never waits for queued draws. A queued draw that writes anywhere in a block's span refuses the vouch, and the per-run checks then drain exactly where they did before.

It also closes two stamp ordering races found on the way:
- a store over memory that is only partly watched stamped nothing, a gap #6060's compare-free vouch for private imports shares;
- a GPU write was stamped before it was noted pending, so a capture on another worker could vouch past it (two-thread test).

It answers the flush hook's "is an image pending here" from a published snapshot instead of the storage registry's mutex, which three workers contended at 65-81 us per call. And the two reuse switches no longer change the shader disk cache's keys, so turning them off doesn't rebuild the cache. FormatVersion is unchanged: no plan or table encoding changes.

Every check uses the same evidence as before over a superset of the bytes. So a store anywhere in a block's span (between records included), a pending or finished GPU write, a label, a DMA fill or copy, CP WRITE_DATA, a compute or storage-image result, an unmapped or remapped page, or an unwatched range falls back to reading and comparing exactly as before.
```
