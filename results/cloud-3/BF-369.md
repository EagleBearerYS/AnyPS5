## 3. The new cases

`CheckReusePublication` gains `ReuseCase::ShaderBufferRead` (7) and `ReuseCase::TextureRead` (8). They use the same fixture: a 4-sample D32S8 target with a separate stencil plane and a depth-only HTILE, where the host draws depth and stencil.

**What they do:**
- **No CPU store.** They run after the draw and before the fixture's CPU store, so nothing on any page is undecided.
- **Case 7, the `requireGuestBuffers` call form:** `RequireNoResidentDepthRead_nid_no_patch(target.address, depthBytes, std::nullopt)`, then `RequireNoMultisampleColorTarget(target.address, depthBytes, "a shader buffer access")`, over the whole depth plane.
- **Case 8, the "a texture read" call form:** `RequireNoMultisampleTarget(target.address, depthBytes, "a texture read")`.

**What they check:**
- The guest stencil plane equals the host's.
- Every depth sample equals the host's value, 0.25 + (sample+1)/16.
- The owner is resident (`DepthSurfaceAt`).
- A rebind returns the same view, with `DepthSurfacesSerial()` unchanged, so nothing was retired or re-imported.

**Why the call form for the texture read.** The real `CachedSampledTexture` path with a texture of another identity over a resident multisample owner goes on, after the publication, into `DepthSurfaceTexture` → `CheckResource`. That refuses ("native multisample depth sampled identity or format mismatch"). So it isn't a legitimate read that can keep an owner. The native target's own sampled view takes the `k2DMsaa` branch, which never reaches line 860.
