## The detection rule (step 1)

`AgcDriver::FusedThreadHandleSharing(driverID, driverInfo, minSubgroupSize, computeFullSubgroups)` lives in `Execution/include/SpannedWaves.hpp` and is pure:

| condition | answer |
|---|---|
| no `computeFullSubgroups` | no |
| `VK_DRIVER_ID_INTEL_PROPRIETARY_WINDOWS` | yes, at any version |
| `VK_DRIVER_ID_INTEL_OPEN_SOURCE_MESA` with `minSubgroupSize >= 16` | no (Xe2 and later) |
| ANV with a Mesa version parsed below 25.3 | yes |
| ANV at Mesa 25.3 or later | no |
| ANV with no Mesa version in the info | yes; `versionUnknown` is set and the device logs it |
| any other driver | no |

- **Version parsing:** the parser finds the first `Mesa <major>.<minor>` in the info, so `Intel open-source Mesa driver Mesa 25.2.7` (`driverName` + `driverInfo`, as `VulkanDevice` stores it) parses too.
- **The minimum subgroup size** is read where the subgroup properties are already queried, in the `VK_EXT_subgroup_size_control` block.
- **The Gfx12 filter was added, for ANV only.** Mesa's ANV source (`src/intel/vulkan/anv_physical_device.c` at tag `mesa-25.3.0`, `get_properties_1_3`, lines 1180-1185, SHA-256 `606e7559fff426c1bd908f6d53918f1459262e3a63ce08438012886f3f44a7dc`) reads:

  ```
     if (pdevice->info.ver >= 20)
        p->minSubgroupSize = 16;
     else
        p->minSubgroupSize = 8;
     p->maxSubgroupSize = 32;
  ```

  - So ANV reports 16 from Xe2 (ver 20) on and 8 before.
  - 8 also covers Gfx9 and Gfx11, which have no fusion. Those devices are still flagged below 25.3, which costs only the narrow span.
  - Intel's Windows driver is not filtered: what it reports per generation is not in any source I have.
- **Mesa fix, checked on GitLab's API:**
  - !37394 ("nir/brw: Fix texture/sampler accesses with EU fusion on Gfx12.X HW") was merged to main on 2025-10-10.
  - Its commits, for example `37a9c5411f` "brw: serialize messages on Gfx12.x if required", are in `25.3-branchpoint`, `mesa-25.3.0` through `mesa-25.3.6`, and every 26.x tag. They are in no `mesa-25.2.*` tag, so "below 25.3" is right.
  - The one miss: a 25.3.0-devel snapshot built before 2025-10-10 counts as fixed.
  - Mesa issue 16622 is "anv: compute shader with requiredSubgroupSize = 32 and local_size_x = 32 uses the sampler of workgroup 0 for other workgroups when the sampler array has more than 2 elements", closed.
- **Device log:** the decision is logged once at device creation. On lavapipe:

  ```
  Fused EU threads share texture and sampler handles: 0 (driver 13, minimum compute subgroup 0, full compute subgroups 0)
  APS5_SPANNED_WAVE=(unset): single-wave wave64 compute spans two full 32-lane subgroups: every program 0, programs that read an image or sampler table 0
  ```

## The switch (step 2)

- **Parsing:** `ParseSpannedWaveMode` reads unset → `FusedThreadTables`, `1` → `All`, `0` → `Never`, `tables` → `Tables`. Anything else is `nullopt`.
- **Resulting flags:** `SpannedWaveTargetsFor(mode, computeFullSubgroups, fusedThreadHandles)` gives `{all, tables}`. Both are false without full compute subgroups.
- **Refusal:** an unknown value throws at device creation:

  ```
  APS5_SPANNED_WAVE is "yes"; it takes 0 (never span), 1 (span every single-wave wave64 compute program) or tables (span those that read an image or sampler table), or stays unset
  ```

- **Docs:** the `ENVIRONMENT.md` row is now kind `string` with the four values; `tools/env_reference.py` infers `string` for the new read. The debt entry is rewritten for the default and the guard.

## The predicate (step 3)

- **Function:** `ReadsWorkgroupTables(program)` in `SpirvEmitter.cpp`, read before emission. It is true when any `program.Info().samplers[i].table != NoTable`, or any `program.Info().images[i].table != NoTable` whose `program.Resources().descriptorSources[source].tableColumn` is not `selected`.
- **Why it is the cheapest:**
  - It is the same metadata `EmitModuleHeader` reads to declare `table_images_*` and `table_samplers`.
  - It is the same test `EmitTableAccess` applies before `DecorateTableNonUniform`. An image column that is `selected` has a uniform index (`tableAccess.uniform`). A table sampler is decorated unconditionally, so every table sampler counts.
- **Span condition:**
  - `state.spannedWave = spannable && (target.spannedWaves || (target.spanTableWaves && ReadsWorkgroupTables(program)))`.
  - `spannable` is today's condition: halfHost, compute, no derivatives, 64 threads.
  - `state.spannedExchangeGuard = state.spannedWave && !target.spannedWaves`.
- **Where the option travels:**
  - `SpirvTarget` and `SpirvTargetOptions`;
  - `CacheKey.hpp` (appended after `deviceScopeLdsMemoryBarriers`);
  - `RequestSerializer` v47: the last byte, read from 47;
  - `VulkanDevice::buildTarget`.

## The guard (step 4): the per-lane constructs it knows

- **Mechanism:** a `PerLaneConstruct` RAII marker in `SpirvEmitterState.hpp` pushes a name on `state.perLaneConstructs`.
- **The check:** `SpannedBarrier` (`SpirvSubgroup.cpp`) throws `SpannedWaveUnsupported("a spanned wave exchanges lanes inside <construct>, which not every invocation of the workgroup reaches")` when `spannedExchangeGuard` is set and the stack is not empty.
- **The fallback:**
  - `Recompiler.cpp` catches it as before, clears `spannedWaves` **and** `spanTableWaves`, and re-emits.
  - For a span from the table option the log line now reads `[spanned-wave] 0x… falls back to two lanes per invocation: <reason>; the fused-thread texture and sampler handle hazard remains for this program`.

Constructs marked (each opens a selection or loop on a per-invocation condition and runs a caller's code inside):

| construct (name in the refusal) | where |
|---|---|
| `EmitIfCondition`, `EmitValueOrDefaultIfCondition` / `EmitValueOrZeroIfCondition` and both arms of `EmitValueIfElse` ("a per-invocation selection") | `SpirvEmitterHelpers.hpp`; about 100 callers, all on exec, bounds, alignment, fault or elect conditions |
| `AtomicUpdateTyped`'s CAS loop ("a compare-exchange retry loop") | `SpirvEmitterHelpers.hpp` |
| `LockedLdsUpdate`'s lock loop ("the LDS lock loop") | `SpirvMemoryInstructions.cpp` |
| `EmitElectedBdaRange` ("an elected BDA range search") | `SpirvBdaRead.cpp` |
| `EmitImage`'s mode switch and sampler guard when the selector comes from a table ("an image table's mode switch") | `SpirvImageEmitter.cpp` |

Audited and not marked:
- **Uniform conditions:**
  - `AccessNarrowedWindow` (`SpirvAluEmitterRegisters.cpp`, an M0 index);
  - the non-table image mode switch (a specialization constant or resource metadata);
  - the guest's structured branches (`SpirvFlowEmitter`: EXEC/VCC conditions go through `EmitWaveAny`, scalar ones are wave-uniform).
- **Fixed bodies that reach no exchange entry point:**
  - the BDA fault and lookup selections and loops (`SpirvBdaFault.cpp`, `SpirvBdaLookup.cpp`, the other `SpirvBdaRead.cpp` sites, several of them separate SPIR-V functions);
  - `EmitSampleOp`'s unnormalized select;
  - `LookupTablePointer`'s loop;
  - `EmitStorageImageWrite`;
  - the format switch in `SpirvRuntimeBuffer.cpp`;
  - the pixel and mesh-only selections in `SpirvModuleEmitter.cpp`.
- **Exchange entry points:** `SpannedBallot` and `SpannedShuffle`, reached through `EmitSubgroupBallot` and `EmitSubgroupShuffle` from:
  - `ctx.Ballot`, `ctx.Shuffle` and `ctx.ShuffleInHalf`;
  - `EmitWaveAny`;
  - `EmitSubgroupLaneActiveBool`;
  - `AppendConsume`.

  All are emitted at instruction level, outside every marked construct. `SpirvValueEmitContext::Def` never emits lazily. So no guest program known today trips the guard, and the guard test drives the emitter state directly (below).

## What the two GPU variants print on lavapipe

```
image table per workgroup: 8 wave64 workgroups of 64 threads alternate two T#s under one direct S#, each read its own image (spanned 0)
wave32 sampler per workgroup: 8 wave32 workgroups of 32 threads alternate a clamping and a wrapping table S#, each sampled with its own
```

- **What the variants are:**
  - (a) is `TableDirectSamplerCode` (T# from the table record of `Keys[workgroup]`, one direct S#) over 8 workgroups that alternate `FloatTexels` and `OtherFloatTexels`.
  - (b) is a 31-word copy of `TableSamplerCode` (`Wave32TableSamplerCode`). It adds `v_add_f32 v1, 1.0, v1` so a clamping and a wrapping S# give different texels, and its output index is `workgroup << 5`.
- **On lavapipe** neither spans (subgroup 8). (a) prints `spanned 1` on a device where the default spans.
- **On an Intel GPU:**
  - with `APS5_SPANNED_WAVE=0`, a failure of (a) means image handles are hit too;
  - a failure of (b) means wave32 workgroups are hit. Wave32 behaviour is unchanged in this task.
