## The fix (`ResourceTracker.cpp`)

Both changes apply only to pointer-keyed columns (`merged && !buffer`). Buffer (nested V#) columns and the non-Phi path keep the old checks.

1. **The Ballot word.** `PointerRecordOrigin` takes a new `pointerKeyed` flag. For a pointer-keyed column it skips a leaf that is `CompositeExtractU32x4(Ballot(…), immediate)` (new `LaneMaskWord`), as it already skips U32 immediates. Any other foreign leaf still makes it return null, so the column is refused.
2. **Copies under another key.** For a pointer-keyed column, a record-read leaf no longer has to be `EquivalentValue` to the origin. The new `SameRecordColumn` asks for:
   - the same `MemoryInfo` offset;
   - an equivalent buffer handle;
   - offsets that `MatchAffineOffset` reads with the same stride and addend, under any key.

   The high-word read is checked against the low word the same way, at offset +4.
3. **Where the column takes its table and offset from.** A pointer-keyed column now takes its buffer handle and record offset (`plan.offset`) from the high-word read, which dominates the descriptor load.
   - Without this, a low word from a copy inside a branch became the handle's argument 0. That failed `value IR instruction definition does not dominate its use`.
   - The GPU path for pointer-keyed columns (`EmitTableWord` → `LookupTablePointer`) only uses the handle's arguments 1 and 2, the actual pointer words. So the key never reaches the lookup.
4. **Debt note.** `docs/dev/debt/shader.md`: the pointer-keyed line now names the lane-mask and other-key arms, and says that an uncaptured pointer, such as a lane mask, faults.

## The test

There are two new ctests on `agc_driver_image_table_tests`: `agc_driver_pointer_phi_ballot_table` (`--pointer-phi-ballot`) and `agc_driver_pointer_phi_copies_table` (`--pointer-phi-copies`). They are registered next to `agc_driver_pointer_phi_sampler_table` with the same properties.

**The shader.** Both run `RunPointerArmTests` on synthetic wave64 compute shaders, `PointerBallotCode` (63 words) and `PointerCopiesCode` (66 words). I assembled them with `llvm-mc -mcpu=gfx1030 -mattr=+wavefrontsize64` and checked them with its disassembler. They are a waterfall loop over a record table whose 64-bit record pointer leads to a T#:
- Lanes 0–31 take key K0 and lanes 32–63 take K1, through a `v_cndmask` (`SelectU32`). Groups use the keys (1,2), (2,1), (1,1) and (2,2), so two groups run two passes.
- A per-group selector word picks an arm in three nested if/else levels that overwrite the pointer's low SGPR.

The ballot shader's loop:

```
  s_mov_b64 s[46:47], exec
loop:
  v_readfirstlane_b32 s20, v3
  v_cmp_eq_u32_e64 s[48:49], s20, v3
  s_and_saveexec_b64 s[50:51], s[48:49]
  s_lshl_b32 s21, s20, 4
  s_buffer_load_dwordx2 s[44:45], s[4:7], s21 offset:0x8
  v_cmp_ne_u32_e64 s[52:53], 0, v3
  s_cmp_eq_u32 s18, 1 / s_cbranch_scc0 second / s_mov_b32 s44, 0xea / s_branch join1
second:  s_cmp_eq_u32 s18, 2 / s_cbranch_scc0 third / s_mov_b32 s44, s52 / s_branch join2
third:   s_cmp_eq_u32 s18, 3 / s_cbranch_scc0 join3 / s_mov_b32 s44, 0x10
join3: s_nop 0
join2: s_nop 0
join1:
  s_load_dwordx8 s[36:43], s[44:45], 0x40
  image_sample_lz v[4:7], v[1:2], s[36:43], s[32:35] dmask:0xf dim:2D
  s_andn2_b64 exec, s[50:51], s[48:49]
  s_cbranch_execnz loop
  s_mov_b64 exec, s[46:47]
```

The copies shader replaces the `s_mov_b32 s44, s52` arm with a second read of the record's low word, keyed by another lane value:

```
v_xor_b32 v11, s19, v3
v_readfirstlane_b32 s22, v11
s_lshl_b32 s23, s22, 4
s_buffer_load_dword s44, s[4:7], s23 offset:0x8
```

**The chain on 4a4db4bf94 has the game's shape.** The pointer's low word is a three-level Phi tree over an immediate, a `Ballot` word, the record read and another immediate. The high word is the record read keyed by `ShiftLeftLogical32(ReadFirstLane(SelectU32(…), Phi(…)), Immediate)`:

```
GetImageResource dword 0 is not a valid runtime value; chain: LoadAddressU32@pc=0x000000c0(GetAddressResource(Phi(Immediate, Phi(CompositeExtractU32x4(Ballot(LogicalAnd(INotEqual32(BitwiseAnd32, Immediate), INotEqual32(Immediate, SelectU32))), Immediate), Phi(ReadConstBuffer@pc=0x00000074(…, ShiftLeftLogical32(ReadFirstLane(SelectU32, Phi), Immediate)), Immediate))), ReadConstBuffer@pc=0x00000074(GetBufferResource(ReadConst(GetSrtResource, Immediate) x4), ShiftLeftLogical32(ReadFirstLane(SelectU32(UGreaterThan32(…), ReadConstBuffer@pc=0x00000024(…), ReadConstBuffer@pc=0x00000024(…)), Phi(Immediate, LogicalAnd(…))), Immediate))), Immediate, Immediate, Immediate)
```

The game's Ballot leaf is `Ballot(LogicalAnd(Phi, INotEqual32))`; here the exec term is an `INotEqual32` of the exec word. The fix accepts any `Ballot` operand.

**What each case checks:**
- **Both:**
  - all four groups sample the right T# for each lane's key through the waterfall, with no fault;
  - selector 1 (`0xea`) and selector 3 (`0x10`) fault as "outside the snapshot", publish no output, and keep the artifact id.
- **Ballot:** selector 2, the lane-mask arm, faults as "outside the snapshot", with no output and no recompile. The log shows the pointer built from the mask: `selected the descriptor at 0x7fff000000ff: outside the snapshot`. This is the required run-time path.
- **Copies:**
  - selector 2 with the same key gives the same result as the record read;
  - with the xor word set to 3, so the copy reads the *other* record's low word, group 0 samples the other record's T# (looked up by the pointer's value), the other groups are unchanged, and there is no recompile.

## Disk-cache format: no bump (stays at 38)

A shader that planned on 4a4db4bf94 gets the same plan:
- **Non-pointer-keyed paths** are byte-for-byte the old code.
- **Pointer-keyed leaves.** A leaf the old code accepted was `EquivalentValue` to the origin. For two reads that means equal `MemoryInfo` (so the same offset) and equivalent arguments (so an equivalent handle, and offsets that `MatchAffineOffset` reads with the same stride and addend). So the new check accepts exactly what it accepted before.
- **The high-word check** is implied the same way.
- **The column itself.** The handle and offset the column now takes from the high-word read were the identical handle and an equivalent offset under the old checks. So the source, stride, addend, offset, `maxKey` (0xffffffff) and the absent key domain are unchanged.
- **Only refused shaders change**, and they now plan for the first time. `TableColumn` and the snapshot structs are unchanged, so the plan encoder's `static_assert`s still hold and the image-table ABI stays at 4.

Separately, entries written by 4a4db4bf94 are not reused anyway: the cache's source version is a SHA-256 manifest of the recompiler sources, and `ResourceTracker.cpp` changed.
