## 3. The rule and the retirement

**The rule (commit 2, `PublishToGuest`'s per-byte branch).** Where main had `else Require(UnchangedSinceLastCollect(byte), "…cannot distinguish…")`, the branch has:
```cpp
} else if (!GuestMemory::UnchangedSinceLastCollect(plane.range.address + offset, 1u, plane.range.generation)) {
    Require(cause == DepthReadCause::Reuse, "native multisample depth publication cannot distinguish an unwritten byte from a same-value guest store");
    tookGuest[index] = true;
    result[index][offset] = current[index][offset];
}
```
- For an access publication, this is the same check with the same message.
- For a reuse publication, the guest's byte is taken, and `tookGuest` is set as for any other guest byte.
- Nothing else in the publication changed. These are all decided as before:
  - pages with no change since the generation;
  - bytes the guest changed;
  - bytes equal to the host's;
  - bytes covered by driver stores (`StoredAllSince`).

**The retirement (commit 3, the guard loop at the end of `RequireNoResidentDepthRead_nid_no_patch`).**
- **Under `depthGuardMutex`:** for each overlapping, active guard, a `Reuse` read deactivates the guard even when the owner was host-written. Main deactivated only owners that were never written. A host-written owner's `active` flag goes into a `published` list. Inactive guards are erased from `depthGuards()`, and `anyDepthGuard` is refreshed.
- **Then, with that lock released:** the code takes `GuestMemory::GpuMutex()` → `surfacesMutex()`, the existing lock order, and calls `retire(*surface)` for every surface whose `active` flag is in `published`.
- **An access read** (CPU read, DMA copy) still leaves a host-written owner active and resident, as on main.
- **Same-identity rebinding is unchanged.** The existing-surface path at the top of the lookup returns the resident view without publishing. The Rebind negative checks the view, the serial and the guest bytes.

**The `retire()` call alone isn't what the tests pin.** Dropping only the `retire(*surface)` loop, while keeping the guard deactivation, stays green (`cases-mut-no-retire.log`). The deactivated `active` flag, which the surface shares with its guard, is already enough for the lookup to drop the stale owner and re-import. The explicit `retire` releases the surface and its stencil ownership at publication time, as the task asked, rather than at the next lookup.
