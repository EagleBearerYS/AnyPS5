## Commit 1: the child key

**Tracker** (`ResourceTracker.cpp`)
- `DescriptorWordReads(buffer, rereadable, vsharp)` also takes a **child key word** (`ChildKeyWord`) when the V# is rereadable. A child key word is:
  - a scalar read through a sibling handle at an immediate offset;
  - with no store or atomic through any handle on the same V# words (`WrittenThrough`);
  - whose every use chain ends in the offset of a T# or S# read through the same V#;
  - where that offset parses as `stride * key + addend` (`MatchAffineOffset`), and `key` peels back to exactly this word.
- **Accepted key forms:** `key = (word >> s) & m`, `(word & m) >> s`, `word >> s`, `word & m`, or `word`, where s and m are constants. The offset is then `stride * key + addend`, with a constant stride ≥ 4 that is a multiple of 4 (a shift or an IMul) and a constant addend.
- **The T# or S# column** gets a **child key domain**: `KeyDomain{source = parent column, child, offset, shift, mask}`.
- **`possibleU32Bits`** now follows a constant right shift, so `maxKey` for `word >> 16` is 65,535.

**Materializer**
- `Narrow` handles a child domain per child buffer. It reads the word at `offset` from the child's own buffer (0 past `num_records`, as the hardware load returns), applies `(word >> shift) & mask`, and maps only that record plus key 0.
- If the word's page is unmapped or has a pending write, it skips narrowing and maps the whole child, as other domains do.

**Bound**
- The child table spans `min(num_records / stride, maxKey + 1)` records: the V#'s size, and at most 65,536 for a 16-bit field. #7223's caps (1,048,576 nested key slots, 32 MiB map) still apply.
- Inside that, only the snapshot's key is mapped.
- **Past it:**
  - A key the dispatch reads differently from the snapshot faults with "outside the key domain".
  - A key past `num_records` reads a null T# (zeros, no fault). That is what `s_buffer_load_dwordx8` returns past `num_records`, and it is the existing nested rule `agc_driver_nested_image_table` checks ("a scalar load past the nested buffer did not read zeros").
  - In neither case is a wrong T# read silently.

**Runtime and stores**
- At run time the key read keeps its own handle and the V#'s four loads, so the dispatch reads the guest's word through the real V#, as BF-149 does for re-read T# words.
- A store through the child buffer is refused statically when it goes through a handle on the V#'s words. An address-based store elsewhere can't be matched to the child statically. If one changes the key word, the dispatch's key leaves the snapshot's domain and faults. A write to the child buffer by another V# is caught at dispatch by the existing "table written by its own dispatch" check, since the child buffer is in the table's read ranges.

**Disk cache:** `KeyDomain` gains `child`, `shift` and `mask`, so `FormatVersion` moves 46 → **50** (above #9749's 48 and BF-156's 49, as asked).

**Still refused, each tested:** a key adding two child words, a key word read at an offset taken from another child word, a store through the V# into its own buffer, and a key word that also feeds the output. #9790's own "data read through a third handle" control still refuses too. Deeper buffer nesting is unchanged (still refused).

## Commit 2: the T#-word arm

- **Tracker:** a merged V# pointer now goes through `PointerRecordPairs`, the edge-paired walk pointer-keyed T#s already use. It replaces `PointerRecordReads`, which walked only the low word and is now removed.
- **New arm kind:** `PointerFreeWord` also takes a word that is a T# or S# read (`DescriptorWordArm`: a `ReadConstBuffer` with a `GetImageResource`/`GetSamplerResource` user), skipped like a constant or a lane mask.
- **V#s only:** the record reads on all edges must be one equivalent read per word, the same restriction `PointerRecordReads` had.
- **Why it is safe:** the nested child is looked up by the actual 64-bit pointer, which the snapshot never captures for such an arm. A lane that takes it faults with "outside the snapshot" instead of reading a T#. The arm's words stay real, because their Phi user keeps them out of planning, as 53523163d's re-read path does.

## A crash I found in #9790's re-read path (not fixed here)

- **Symptom:** a read through a V# whose words are loaded from an unmapped pointer crashes lavapipe (a null byte load in JIT code) instead of faulting.
- **Shown with #9790's own `PointerSharedVsharpReuseCode`:** with record 1's pointer set to an unmapped 0x7f12345000 it crashes. The plain shared shader, which reads nothing through the guest's V#, faults cleanly ("selected the descriptor at 0x7f12345000: unmapped"). My key read and the T#-word arm hit the same path whenever the arm is taken with the key read.
- **Where it probably sits:** the address read through a GPU-only descriptor (`SpirvRuntimeBuffer.cpp`, `EmitBdaRead` behind a V# from LoadAddressU32 words). It needs its own look; I didn't widen this branch for it.
- **For the game:** this matters only if the $353 edge is actually taken at run time. On hardware that edge would load a V# from a T#'s base address, so it is presumably not taken.
