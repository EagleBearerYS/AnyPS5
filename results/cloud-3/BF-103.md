# BF-103: graphics pipeline libraries retain link-time-optimization info only where an optimized link will be made (cloud-3)

Base: upstream main **27c88a8d7** (Merge pull request #8224), fetched 08:33 UTC. It is 59 commits past BF-101's 9be6ccf60, and none of them touch `PipelineLibrary.cpp`, `Pipeline.cpp`, `PipelineJournal.cpp` or the pipeline tests.

## 1. The change

Fork `perf/agc-library-lto-info-when-optimized` = **1a0c43b69** "perf(agc): retain link-time optimization info only where a link is optimized", one commit on 27c88a8d7. Yunus Shaikh is author and committer, with no trailers. The fix is two hunks in `core/libs/prx/libSceAgcDriver/Graphics/src/PipelineLibrary.cpp`:

- **The flag (`:199`):** `create.flags = optimize ? VK_PIPELINE_CREATE_LIBRARY_BIT_KHR | VK_PIPELINE_CREATE_RETAIN_LINK_TIME_OPTIMIZATION_INFO_BIT_EXT : VK_PIPELINE_CREATE_LIBRARY_BIT_KHR;`
  - `optimize` is unchanged (`:183-184`): `backgroundLinking && context.pipelineLinkTimeOptimization`.
  - `backgroundLinking` is false with `APS5_NO_PIPELINE_LTO`.
  - `pipelineLinkTimeOptimization` is false on `VK_DRIVER_ID_NVIDIA_PROPRIETARY` (`Execution/include/PipelineLinkOptimization.hpp:8-10`, set at `Execution/src/VulkanDevice.cpp:1526` and copied to the context at `:3779`).
- **The key (`:188-189`):** the library cache key is now `Combined(part key, context key)` plus one byte holding `optimize`. A library made without the info is never found by a link that will be optimized, and the reverse holds too. This covers a context that forces `pipelineLinkTimeOptimization` on a device whose other contexts don't: the pipeline readback test's `--force-lto`, and `tests/Graphics.cpp:7083, 9823`, which force it off. It also covers any future path that decides `optimize` per link.
- **Unchanged:**
  - With `optimize` off, the shader modules are destroyed after the create (`Pipeline.cpp:571-572, 591-592`); with it on, they are kept in `DeviceLibraries::modules` (`PipelineLibrary.cpp:245-253`).
  - The fast link's flags (0) and the relink's `VK_PIPELINE_CREATE_LINK_TIME_OPTIMIZATION_BIT_EXT` (`:287`) are as before.
- **No new `APS5_*` name.**

**Every library creator.** There is one place that creates libraries, the part loop of `LinkPipelineFromLibraries` (`PipelineLibrary.cpp:186-256`), and every path reaches it with the context it was given:

| creator | path to the loop | flag it now passes |
|---|---|---|
| a draw | `Draw.cpp:2466/2470` → `CachedPipeline` → `Pipeline::Pipeline` → `LinkPipelineFromLibraries(..., partsOnly = false)` (`Pipeline.cpp:576`) | LIBRARY, plus RETAIN only when the draw context's `optimize` is true |
| a journal replay | `PipelineJournal.cpp:982` → `CachedPipeline` → the same constructor call | the same. The replayed pipeline's relink is held in its slot until a draw binds it (`PipelineLibrary.cpp:302-307`, `OptimizedPipeline::Schedule` at `:317`). That slot exists only when `optimize` is true, and its relink names the libraries that same call found or made, which are keyed with `optimize` = true, so they all retain the info |
| a shader library prebuild | `VulkanDevice::PrebuildGraphicsLibraries` (`VulkanDevice.cpp:3835-3871`) → `Pipeline::Prebuild` (`Pipeline.cpp:602-610`) → `LinkPipelineFromLibraries(..., partsOnly = true)` (`Pipeline.cpp:570`) | the same, with the device's own context. Prebuilt libraries carry the same `optimize` byte as that device's draws, so draws still find them |
| the background relink and the fast link | not libraries; they link libraries (`:268`, `:287`) | unchanged |

#5925's submission lookahead (not on main) also builds through `CachedPipeline`, so it would take the same path.

## 2. The tests

Two tests, both in the same commit as the fix:
- **`agc_driver_pipeline_optimized_readback_tests`** (`tests/execution/PipelineOptimizedReadback.cpp`):
  - Its `vkCreateGraphicsPipelines` hook now counts the libraries it sees and how many carry `VK_PIPELINE_CREATE_RETAIN_LINK_TIME_OPTIMIZATION_INFO_BIT_EXT` (`:95-100`).
  - After the fast-linked draw it requires at least one library, and all of them retaining the info when `optimize` is true, none when it is false (`:227-231`).
  - Its existing checks still run around that: the drawn pixels for the fast-linked draw and for the completed link, which pipeline each draw bound, and the number of optimized creations.
  - It is registered 8 ways (`d32`, `d16`, `color32`, `color64`, each with `_fast` = `APS5_NO_PIPELINE_LTO=1`). On lavapipe `d32` and `d16` run; `color32` and `color64` skip, as on the base, because they need 32-lane subgroups.
- **`agc_driver_recorder_tests --pipeline-library-lto-info-only`** (`tests/Recorder.cpp:9679-9766`), registered as `agc_pipeline_library_lto_info` and `agc_pipeline_library_lto_info_fast_only` (`APS5_NO_PIPELINE_LTO=1`). Both new names are in the WIN32 `PATH` list.
  - A `LibraryCreateFlags` probe hooks `vkCreateGraphicsPipelines` through `Context::deviceProc`, in the style of the file's other probes, and counts library creates and retain flags.
  - First a lookup with a context forced to `pipelineLinkTimeOptimization = false`. It must create libraries, none retaining the info, and the pipeline must not be optimized.
  - Then a lookup of the same shaders and state with a context forced to `true`. A different attachment layout gives it its own store entry while every library key is the same.
  - With LTO on, the second lookup must create as many new libraries as the first, all retaining the info, and its pipeline must be optimized in the background.
  - With `APS5_NO_PIPELINE_LTO=1`, it must create none and optimize nothing.

**Green** (lavapipe, LLVM 20.1.2):

| run | result |
|---|---|
| recorder mode, LTO on | 4 libraries without the info, then 4 new ones with it; the second pipeline optimized |
| recorder mode, `APS5_NO_PIPELINE_LTO=1` | 4 libraries without the info; the second context reuses them and nothing is optimized |
| readback `d32` and `d16`, LTO on | `libraries 4 (4 retaining link-time optimization info)`; fast draw 1, optimized draw 1, optimized creations 1; pixels right in both phases |
| readback `d32` and `d16`, `_fast` | `libraries 4 (0 retaining link-time optimization info)`; 2 fast draws, 0 optimized; pixels right |

**Red** (`PipelineLibrary.cpp` replaced in the head tree, the tests unchanged; rebuilt and run each time):

| `PipelineLibrary.cpp` | recorder, LTO on | recorder, LTO off | readback `d32`, LTO on | readback `d32_fast` |
|---|---|---|---|---|
| **as on 27c88a8d7 (the fix reverted)** | fails: "4 of the 4 libraries made for a context without optimized links were created to retain link-time optimization info" | fails, same message | passes | fails: "4 of the 4 libraries were created to retain link-time optimization info, expected none, since no optimized link will be made" |
| the flag hunk only (no key byte) | fails: "a link that will be optimized made 0 libraries, expected 4: it reused libraries made without link-time optimization info" | passes | passes | passes |
| the key hunk only (the flag always set) | fails like the full revert | fails like the full revert | passes | fails like the full revert |
| the head | passes | passes | passes | passes |

So each hunk has a test that fails without it.
- In the "flag only" case on lavapipe, the optimized relink of libraries that lack the info didn't crash. It's still invalid Vulkan usage, which is why the key byte is needed.
- The readback with LTO on passes in every row because it only checks that libraries retain the info, which they do whenever LTO is on.

## 4. Memory on lavapipe

Measured on a local merge of the head with BF-101's counter (below), with BF-101's churn harness and fork 413c412595's Village bench applied locally and not committed.
- **Settings:** `APS5_NO_PIPELINE_LTO=1 APS5_PROFILE_DRAW=1 LP_NUM_THREADS=2 GALLIUM_OVERRIDE_CPU_CAPS=avx`.
- **"Before"** is the head with only the flag hunk put back, so every library retains the info. With `APS5_NO_PIPELINE_LTO` the key byte makes no runtime difference.
- Two runs per arm.

| | before (retained) | after (not retained) |
|---|---|---|
| churn harness, 3,000 blend-constant variants: VmHWM at 500 / 1,500 / 3,000 lookups | 100 / 117 / 131 MiB, both runs | 101 / 117 / 132 MiB, both runs |
| churn: library counts at 3,000 | fragment output 3,000, fast-linked 1,024, optimized 0 | the same |
| Village bench `--cost 20`: end VmHWM / VmRSS | 913 / 872 and 896 / 869 MiB | 878 / 856 and 888 / 861 MiB |
| Village `[pipelines]` | 1/1/4/1 libraries, 4 fast-linked, 0 optimized | the same |

- **lavapipe saves nothing measurable.** The churn harness is within 1 MiB.
- **The Village bench** is 8 to 35 MiB lower after the change, but its two runs per arm differ by up to 17 MiB, so I don't count that as a saving.
- lavapipe's retained info is evidently small. As the task says, the PC pair on the RTX 3070 is the real measurement: Village's NVIDIA driver arenas, 3.3 GB with GPL against 1.4 GiB with `APS5_NO_GPL=1`.
