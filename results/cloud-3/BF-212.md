What it does:
- **Layout:** it gives `NetCtlNatInfo` the fields `{u32 size; s32 stun_status; s32 nat_type; u32 mapped_addr}`.
- **No IPv4 interface:** returns `NOT_CONNECTED`.
- **Otherwise:** it sends RFC 5389 binding requests from the host's IPv4 interface to `stun.playstation.net:3478`, then Cloudflare and Google STUN servers, with a 300 ms timeout and a cached result.
  - It reports `stun_status` 2 and the mapped address when a server answers, and `stun_status` 1 with `mapped_addr` 0 when none does.
  - It always reports `nat_type` 0. Its debt line says this is "because PlayStation's NAT classification procedure and field semantics are unverified on hardware".
- **Its first commit message** ("reports STUN status OK (2), NAT type 2 (moderate) … Unblocks session creation in Aliens: Fireteam Elite (PPSA03393)") names a second title that calls this function.

So this function is claimed by an open PR. A branch here would compete with it.

### One console run that would settle it

On a PS5 (or a PS4, whose libSceNetCtl exports the same call) running a homebrew payload, log the return code and all 16 bytes after each call, with the struct pre-filled with 0xA5 and `size` set to 16:

1. Before `sceNetCtlInit`: `sceNetCtlGetNatInfo` (expected `NOT_INITIALIZED`; it shows whether fields are written).
2. `sceNetCtlInit`, then with the network cable unplugged or networking disabled: `sceNetCtlGetState`, then `sceNetCtlGetNatInfo`. This is the disconnected answer main can model.
3. Plug in, and wait for `sceNetCtlGetState` to reach 3 (IP obtained). Call `sceNetCtlGetNatInfo` immediately, then again every second for about 30 s. This shows whether `stun_status` starts at 0 (unchecked) and when it turns 1 or 2.
4. Run Settings → Network → Test Internet Connection and note the NAT type the UI shows. Call again and compare `nat_type` and `mapped_addr` with the UI and the router's public IP.
5. Repeat 3-4 behind a router with UPnP off, and a double-NAT if possible, to see type 2 against type 3.
