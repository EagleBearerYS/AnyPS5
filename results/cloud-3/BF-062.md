## 1. The counter (step 1)

**Commit:** fork `perf/agc-lazy-resolve-shader-abi` **b883c9d58**, `feat(agc): count whether a deferred ABI's first use finds its artifact`. It is one commit on 1bfddbc99c, pushed. Author and committer are Yunus Shaikh, unsigned, with no trailers. It touches four files (+132 −16): `Driver.hpp`, `ShaderRegistry.hpp`, `ShaderRegistry.cpp` and `tests/execution/LazyResolvedAbi.cpp`.

**What counts as a first use.** A first use is a `SourceHandleFor` or `InvocationFor` call that took the shader's queued ABIs and prepared them (`PrepareDeferredAbis`). Only the call that takes the queue counts; a racing call that finds it empty does not. Each first use is classified one of three ways:
- **found:** the artifact the use then matched is one of the entries that preparation just added (compared by handle);
- **own:** nothing matched, so the use prepared its own artifact;
- **neither:** the use matched an entry prepared earlier, not by this preparation. It counts in N but not in F or O. Under lazy preparation that needs an earlier own preparation at the same code offset; the test never produces it.

**What counts as an entry.** Every entry `PrepareDeferredAbis` adds is counted and marked `fromDeferredAbi`. Duplicates of existing entries are not added and not counted. The first lookup that matches a marked entry marks it `matched`. Unmatched = entries − matched.

**Cost.**
- The counters are relaxed atomics.
- Only a lookup that prepared queued ABIs, or that first matched an entry from them, touches them.
- Every other matched lookup tests the entry's `fromDeferredAbi` flag and an empty `std::optional`, and nothing else.
- The lookups run when a draw or dispatch misses its caches, not per draw. 1bfddbc99c already locks the snapshot there.
- Without `APS5_LAZY_SHADER_PREPARE` no entry is marked and no counter moves.

**The line** goes to stderr with no profile switch:
```
[shaders] deferred ABIs: N prepared at first use, F found their artifact there, O prepared their own; U of the E entries prepared from them never matched a use
```
- **When it prints:** at the first change, then at most once every 60 s, and only when a counter changes.
- **So it can lag** by up to a minute. For a reading at the menu, take the last line after a minute of play in which new shaders appear.
- `Driver::DeferredAbiUses()` returns the exact counts; the test reads it.

**The test,** `agc_driver_lazy_resolved_abi`, is extended in the same commit:
- **Own:** after the existing two draws, whose state differs from the empty-register ABI, it requires 2 first uses, 2 own, 0 found, and every queued entry unmatched.
- **Found:** it then registers a fifth program and resolves its ABI with exactly its draw's context registers and primitive type (`DrawContext` and `PrimitiveType`, now shared with `Commands`). It checks that this shader holds no entries after resolution, draws it, and requires +1 first use, +1 found, unchanged own, and exactly one more entry matched.

**Red.** I deleted the four counting calls (`NoteMatchedEntry` and `NoteOwnPreparation` in both lookups), rebuilt, and ran the test. It failed (rc 1):
```
AGC graphics: lazy resolved ABI: draws whose state differs from the resolved ABI did not count as preparing their own artifact (0 first uses, 0 found, 0 own, 4 of 4 entries unmatched)
```

**Green,** as committed (rc 0):
```
[shaders] deferred ABIs: 1 prepared at first use, 0 found their artifact there, 1 prepared their own; 2 of the 2 entries prepared from them never matched a use
lazy resolved ABI: a draw with the resolved ABI's state found its artifact among the 2 entries prepared at its first use (3 first uses, 1 found, 2 own, 5 of 6 entries unmatched)
lazy resolved ABI: 2 of 4 ABI-resolved shaders drew; the 2 that never drew hold no prepared entries, and a drawn one drew the same 65536 bytes as with eager preparation
```

### The two added commits

**d81d8ca0b, the residency test did not build on base3a.**
- `tests/execution/ShaderResidency.cpp` (from 6d77adfe90) calls `AgcDriver::DriverDetail::AwaitLibraryPrebuilds()`.
- Upstream added that function in MarcZX100's 81e3db853 ("fix(agc): drain library builds before device replacement"). The residency branch's base (5f61879a9) has that commit; base3a does not.
- The first arm 4 build stopped at `ShaderResidency.cpp:386: error: 'AwaitLibraryPrebuilds' is not a member of 'AgcDriver::DriverDetail'`.
- **Fix:** I ported only the wrapper: the declaration plus the same three lines from 81e3db853, which await the prebuild pool's submitted tasks. base3a already has the pool and `AwaitSubmitted()`. The commit message credits 81e3db853.
- I did not take the rest of 81e3db853 (draining library builds before device replacement). That would change driver behaviour in a memory A/B, and nothing outside the test calls the wrapper.

**4b3fc2da7, the residency test failed with the session's own environment.** `agc_driver_shader_residency` failed under `APS5_RELEASE_SPIRV=1 APS5_RELEASE_SPIRV_BUDGET_MIB=256` with "the new pipeline did not reload the released SPIR-V".
- **Cause:** the test's default mode expects a released module to be reloaded by the next pipeline, which only holds without a budget. With 256 MiB exported, the modules stay resident under the budget.
- **Not caused by the arm:** the residency branch's own build of `agc_driver_shader_residency_tests` (wt-mem's `build-proto`, built from the tree committed as a3bf3fa29) fails the same way with those two variables (rc 1) and passes without them (rc 0).
- **Fix:** outside `--measure`, the test now sets the budget itself (64 for `--budget`, 0 otherwise), as it already sets `APS5_RELEASE_SPIRV`.
- **Result:** after the fix, `agc_driver_shader_residency` and `agc_driver_shader_residency_budget` pass both with and without the exported variables.
- `exp/shader-memory-residency` itself still has this test bug; I did not push there (the task's rules).

**Needs at run time:** `APS5_LAZY_SHADER_PREPARE=1 APS5_RELEASE_SPIRV=1 APS5_RELEASE_SPIRV_BUDGET_MIB=256`. Add `APS5_PROFILE_DRAW=1` if the `[spirv]` and `[buffers]` lines are wanted. The `[shaders]` line needs no switch.
