## 0. Bottom line

- **The bar is now explicit.** On 2026-10-14 oneandonlydean closed #5635, #5637 and #5641 with these words:
  - "Closing: no title is known to reach this."
  - "With the queue at 700+ open PRs, please hold off on new PRs that don't name a title needing the change until it's down."
  - "If a title stops on this on current main, reopen with the title ID and the log line."

  CONTRIBUTING.md adds that PRs naming a title (`Unblocks: PPSA… #discussion`) are reviewed first. In practice, a new feature PR needs three things: a title that reaches the code on current main, the log line that shows it, and a change that implements the library function's general behaviour. Host-side extras with no title (settings files, launchers, filters, Discord, device pickers) are on hold until the queue drops.
- **Much of what users usually ask for already exists:** DualSense support, controller hot-plug, keyboard and mouse remapping, 120 Hz output, HDR10, a shader disk cache, language selection, GPU selection and present modes (section 1).
- **The largest user-visible gaps are things titles call that are faked today:**
  - trophies (UDS drops every event; NpTrophy2 reports one fake trophy);
  - system dialogs: MsgDialog always answers yes, SaveDataDialog always answers OK, and the IME dialog types "Slayer";
  - screenshot and content export (not supported, or throws);
  - one user and one pad.
- **Ranked top five** (section 5):
  1. Trophy unlocks: record, report and announce them.
  2. Real message and save-data dialogs.
  3. Photo-mode and screenshot capture to a host folder, built on #4891.
  4. IME dialog text entry.
  5. DualSense haptics over Bluetooth (#2056).
- **Do this first on the PC.** One 20-minute pass with no new code (section 6) settles whether Village can be the named title for 1, 2 and 3:
  - an import audit for about 15 functions;
  - three greps of existing Village logs;
  - one Photo Mode try in the opening.

  Village runs at about 5 fps in menus and 0.35–0.5 fps in its first 3D scene (#5169), so "play until X happens" checks are impractical. Every check below stays in the opening and the menus.

## 1. Inventory: user-facing features today

### 1.1 Converting and launching

- **Online relinker,** in the browser, "files stay on your device" (docs/user/USAGE.md:3). It comes from the maintainers' `feat/web-relinker-ui`, which is fully merged (0 commits ahead of main).
- **Relinker CLI** (USAGE.md:16-79):
  - outputs: Linux ELF, Windows PE (`--windows`) and macOS x86-64 Mach-O (`--macos`, Rosetta);
  - `--to-intel` and `--to-rosetta` for Intel hosts and Rosetta;
  - `--windows-gui` for a build with no console, which logs to `anyps5.log` beside the exe (USAGE.md:125; core/relinker/cli/src/CliArgs.cpp:14, :106);
  - `--module-dir` for loadable modules such as Unity plugins;
  - `--executable` for second executables started with `sceSystemServiceLoadExec`;
  - fixed image bases, and `--autorun`.
- **Import audit.** `--registry` together with `tools/import_audit.py` lists each import as implemented, stub, absent or module before launch (USAGE.md:198-230). `tools/nid_names.py --name <symbol>` computes a NID (#5355).
- **CPU check.** At start-up the title stops and names any missing CPU extensions (USAGE.md:40).

## 2. How merges are decided (calibration)

- **CONTRIBUTING.md:**
  - "Every function either does exactly what it is supposed to or throws." (line 6)
  - "A silent stub is allowed only when it unblocks a title and only affects the UI" (line 8)
  - "Implement the general behaviour of a function, not what one title happens to need." (line 10)
  - "If a pull request fixes a stop or a wrong result seen on a title, name it on the checklist line with the title ID and its Game bring-up discussion … Reviewers review these first." (line 58)
  - "Run the tests before opening the pull request and describe what was tested (OS, title or homebrew)." (line 61)
  - AGC, recompiler and VideoOut changes name every GPU tested.
  - Speed claims need summary lines and traces from the same machine and scene, for main and for the change.
  - The open-PR limit is "1 with none merged, 20 with at least 1".
  - Authors say whether AI helped.
- **Today's closures:** see section 0.
  - #4891 was still being reviewed the same day. My reading, an inference: host-side work already in review continues, while new PRs without a title wait.
- **What got in:**
  - Our clone's first-parent history (shallow, merges from 2026-10-13) has 717 merges, 246 of them `feat`. Nearly all implement library exports or GPU behaviour.
  - The user-visible ones each implement something titles call (pad, IME, guest mouse, VRR status, PQ buffers) or fix a host integration:
    - #5697: HDR10, named PPSA01317;
    - #5448: haptics to rumble;
    - #4756: IME;
    - #4704 and #4217: mouse;
    - #3664: Wayland;
    - #3972: VRR.
  - GitHub search on 2026-10-14: 100 open `feat` PRs, and 685 closed unmerged.
- **Scale used below:**
  - **high:** a title stops or shows a wrong result on current main, the PR names it with the log line, and the change implements the general behaviour;
  - **medium:** a title reaches the code and the change makes it behave as on the console, but nothing stops today;
  - **low:** a host-side extra with no title that needs it, or a change that is very large or overlaps other open work.

## 3. What users value in comparable projects

This is from general knowledge of these projects; I did not re-check it for this report.

- **RPCS3:** trophy pop-ups and a trophy manager, per-game configuration, resolution scaling, a frame limiter, asynchronous shaders with a cache, a save-data manager, a game list and Discord.
- **shadPS4:** trophy pop-ups and a viewer, per-game configuration, a game list GUI, DualSense light bar and motion, and Discord.
- **Ryujinx and Yuzu:** per-game configuration, resolution scaling, an asynchronous shader cache, local multiplayer with several controllers, save management and a game list.
- **Cemu:** graphic packs for resolution and frame rate, asynchronous shader compilation, and several controllers.
- **Dolphin:** internal resolution, post-processing shaders, ubershaders, per-game INIs, achievements (RetroAchievements) and netplay.

Across them, the most-valued items are achievements or trophies, smoothness (shader stutter and frame rate), resolution, per-game settings, controller features, local multiplayer and a library UI. In AnyPS5 the first and the controller features are the ones titles call directly.

### 5.1 Trophy unlocks: record, report, announce

**What to build.** Three PRs, one topic each.

- **(a) `feat(libSceNpUniversalDataSystem)`: keep event properties and post events.**
  - The property-object and array setters store typed values (EventPropertyObject.cpp:22-120 currently validate and return OK).
  - `CreateEvent` keeps the event name (Event.cpp:13).
  - `EventToString` and `EstimateSize` serialize the real JSON instead of `{}` and 3 bytes (Event.cpp:40, :48; NpUniversalDataSystem.hpp:15-16).
  - `PostEvent` (Event.cpp:36) logs the first posts of each event name, in `APS5_HIT` style, and passes each event to registered consumers.
- **(b) `feat(libSceNpTrophy2)`: record unlocks posted through UDS.**
