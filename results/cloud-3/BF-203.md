## Per function

All three are in `core/libs/prx/libSceFont/src/Render.cpp` and share one helper, `RenderGlyph`. Each piece of argument handling follows a function already in the tree:

| Argument or step | Follows | How |
|---|---|---|
| glyph | `sceFontGlyphDefineAttribute`, `sceFontDeleteGlyph`, `sceFontGlyphRefersOutline` | `TryGetGeneratedGlyph`. A null pointer or one that is no generated glyph returns `SCE_FONT_ERROR_INVALID_GLYPH`. |
| glyph scale | `sceFontGlyphRefersOutline` (`BuildTrueOutline`) | It draws at the glyph's `scale_x` and `base_scale`, the size `sceFontGenerateCharGlyph` recorded. The owner font's later scale changes do not apply. |
| renderer | `sceFontBindRenderer` | A null renderer, or one whose `RendererNative::magic` is not `RENDERER_MAGIC`, returns `SCE_FONT_ERROR_INVALID_RENDERER`. It stands in for the bound renderer. In the char path a bound renderer is only checked for presence (`RenderCharGlyphImageCore`'s `NOT_BOUND_RENDERER`), so the glyph draws whether or not its font has one bound. |
| style frame | `sceFontRenderSurfaceSetStyleFrame` and the surface-frame rule of `sceFontRenderCharGlyphImage` (`ResolveSurfaceStyleState`) | That rule now lives in `ApplyStyleFrame`, unchanged: scale and dpi, slant and weight. The argument frame is used, else the surface's own frame. A frame that fails `ValidStyleFrame` returns `SCE_FONT_ERROR_INVALID_PARAMETER`, as `sceFontRenderSurfaceSetStyleFrame` does. |
| surface, metrics, output | `RenderDirectional`, `sceFontRenderCharGlyphImage` | A null pointer returns `SCE_FONT_ERROR_INVALID_PARAMETER`, and every failure clears the metrics and output (`ClearRenderOutputs`). |
| owner font | `RenderDirectional` | It takes the owner font's lock (`AcquireFontLock`). A closed or invalid owner returns `SCE_FONT_ERROR_INVALID_FONT_HANDLE`. |
| rasterizer | `sceFontRenderCharGlyphImage` | `RenderCodeWithStyle` is the second half of the old `RenderCharGlyphImageCore`, split out unchanged. It covers the glyph lookup, set-char-size with the given style, the fallback face, the surface rules and the output fill, and it now takes the style as an argument. The char path calls it with the same style as before. |

- **`sceFontGlyphRenderImageHorizontal`** follows `sceFontRenderCharGlyphImageHorizontal` (`RenderDirectional` with direction 1): it uses x and y as given and sets direction word 1.
- **`sceFontGlyphRenderImageVertical`** follows `sceFontRenderCharGlyphImageVertical` (direction 2): it uses x and y as given and sets direction word 2.
- **`sceFontGlyphRenderImage`** follows the generic `sceFontRenderCharGlyphImage`'s branch for a surface with a scale frame:
  - A horizontal owner font (`flags` as int16 ≥ 0) adds `ComputeHorizontalLayout`'s baseline to y and sets direction 1.
  - A vertical owner font adds `ComputeVerticalLayout`'s column offset to x and sets direction 2.
  - Both layouts are computed with the glyph's (framed) style, since the glyph has its own size. They are not the font's cached baseline.
- **Not copied:** the generic char path also writes the computed offset into the surface's `catchedScale` system-use field when the surface has a frame. Nothing in the tree reads that field, so the glyph path does not write it.
- **Sources outside the tree:** shadPS4 only stubs all three (`font.cpp` L2397-2410: "(STUBBED) called", returns OK), so there is no second implementation to compare. Nothing was measured on a console.
- **Assumed, and listed in the debt entry:**
  - the argument frame wins over the surface's;
  - the error order (glyph, renderer, frame, pointers, owner font);
  - `INVALID_FONT_HANDLE` once the owner font is closed;
  - the generic form takes its direction from the owner font.
- **Glyph forms:** a glyph generated with form 1 detail also draws from its codepoint. That is assumed, and only form 0 is in the tests.
