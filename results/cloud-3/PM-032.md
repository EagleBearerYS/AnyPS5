- **Changed tables cost what they did.** A store before every capture, and a table outside the write watch (read and compared every time): see §5.
- **Design, one line each** (§2):
  1. A column is built once into immutable shared values (`SharedValues`): codes, distinct T#s, read ranges. The memo and every snapshot that reuses it hold references. A column's codes index its own distinct T#s, so every column of a shader is shared whole.
  2. The memo keeps the column's raw words in one immutable block (`SrtGuestWords`). `supplyWords` hands the block to `ShaderMemory`, which reports its runs as regions, page by page as a read would, without copying them into pages.
  3. The result memo hashes each shared value once and keeps the hash in it.
  4. A result memo miss with unchanged tables takes the table resolution (map, elements, poison) by reference.
  5. A cached variant records which of its words it copied from which block (`SharedWords`, a weak reference); two captures' words from the same place of the same block are equal without a compare (`SameCapturedWords`).
  - Every PM-028 vouching rule is unchanged: stamp before the first read, no stamped block since, no pending GPU write, flush before vouching, the guest mapping generation.

## 2. Design (task 2)

### 2.1 Shared column (commit 1)

- `ResourcePlan.hpp` gains `SharedValues<T>`: a `std::shared_ptr<const Block>` holding a `std::vector<T>` and a lazily cached content hash. It reads like a const vector (`size`, `[]`, `at`, `begin`/`end`, `==`), so readers did not change. `Shares()` is identity; `==` is identity first, then contents; `Hash()` hashes the contents once and stores the result in an atomic in the block.
- `ImageTableColumnSnapshot` holds `codes`, `words` (new) and `readRanges` as `SharedValues`. `ImageTableSnapshot::words` (one list for all columns of a shader) is gone: a column's codes index its own distinct T#s. `ResolveImageTables` reads `column.words`; the resolution is the same, because its element and poison indices were already keyed by the words, not the codes.
- `TableSnapshotter` seals a column once (`Seal`: codes, poison counts, the three shared values). The memo keeps the sealed column. A reuse (`Apply`) copies three shared pointers. The per-record `states`/`words` vectors are now allocated only when the column is walked.
- `snapshotHash` mixes `codes.Hash()`, `words.Hash()` and `readRanges.Hash()` per table instead of every word. Equal contents hash equal whether shared or not, so the result memo keys did not change meaning.

### 2.2 Shared words in the shader memory (commits 2 and 5)

- The memo keeps a column's runs and raw words in one immutable `SrtGuestWords` block. `SrtMemorySupplier` now takes `const std::shared_ptr<const SrtGuestWords>&`.
- `ShaderMemory::supplyWords` validates the runs (aligned, ascending, counts match, not over the initial regions, the pages accessible, as before) and keeps a reference (`Supplied`). `Regions()` and `TakeRecentRegions()` merge the supplied runs with the page segments and the initial regions in address order. Since commit 5 each run is reported in 4 KiB-page pieces, exactly the regions a read of the same words reports, each piece a span into the block.
- A second stage that supplies the same block marks it recent again. A block that overlaps pages already fetched, or another block's runs, is copied into pages as before (`place`).
- A later read in the same `ShaderMemory` that touches supplied words (`read`, `readWords`) first moves the whole block into pages (`spill`, overwriting with the vouched words), so no word is reported twice and later reads see the same words the snapshot used. A spilled block stays referenced until the `ShaderMemory` goes, so spans already handed out stay valid.
- `ShaderMemory::Supplies()` counts words shared, copied and spilled.

### 2.3 O(1) result memo key (commit 1)

See 2.1: the hash of a shared value is computed once, on the first `Recompile` that needs it, and then read.

### 2.4 Resolution reused by reference (commit 3)

- `ResolveImageTablesShared(info, snapshot, variantId)` keeps the last resolutions and returns one by reference when the variant, the reducing state of each direct sampler paired with a table image, and every column match: base, size, records, keys, fault, outside, and codes and words **by identity** (`Shares`). `materializeResult` uses it.
- Identity, not contents: a column read again after a write is a new block and resolves again, even when its words came back equal. The memo holds the shared values it compares, so a compared block cannot be freed and its address reused.
- Bounds: 4 resolutions per variant, 256 in all, 8 Mi words including the columns the keys keep alive; least recently used first out. `APS5_NO_TABLE_RESOLUTION_REUSE=1` turns it off.
- What a miss still pays is mostly `DescriptorBindingBuilder::Populate` copying 32,768 elements into the bindings, and the result's own copies: about 1.6 ms for 32,768 distinct T#s.

### 2.5 PM-028's rules, memory and threads

- **Vouching is unchanged.** The same `Unwritten` → `Compared` → walk order; the same stamp, pending-write, flush and mapping-generation checks in `stampWrites`/`unchangedSince`. Sharing only changes what a reuse costs, never whether it happens.
- **Memory stays bounded.**
  - The column memo keeps its limits (16 columns, 4 Mi words per thread); its footprint now counts the shared column.
  - A block outlives the memo only while something that used to hold a private copy of the same words holds it: a snapshot (`ResourceCapture`, per draw or dispatch, plus the dispatch-ahead map), a `ShaderMemory` (per draw; a dispatch variant keeps one only under `APS5_DISPATCH_STAMP_VALIDATE`), a draw's `StageCapture` (until the draw is cached), or a resolution memo entry (counted in its 8 Mi words). Apart from that new memo (at most 8 Mi words, 32 MiB), sharing replaces private copies with references, so memory can only go down.
  - A cached variant holds its blocks weakly (§2.6): once the last strong reference goes, the block's words are freed and the variant keeps only the block's single allocation (its control block and the two destroyed vectors' headers, about 80 bytes) until the variant is evicted. Variants stay bounded by the draw and dispatch caches' limits, and `variantBytes` counts the 40-byte `SharedWords` entries.
- **Thread safety.**
  - Before: every snapshot and every `ShaderMemory` owned its words, and the memo was per thread, so nothing was shared across threads.
  - Now: one block may be referenced by the memo of the thread that read it, by snapshots and shader memories on other threads (a pipelined draw, a dispatch variant), weakly by cached variants, and by the global resolution memo.
  - That is safe because a block is fully built before its `shared_ptr` is published and is never written afterwards (`shared_ptr<const ...>` everywhere). The only mutable state, the cached hash, is an atomic, and two threads that race compute the same value. Reference counts are atomic, and the last owner frees the block on whichever thread it is. A variant's `shared` entries are written while the variant is built, before it is published to the cache, and only read afterwards; `weak_ptr::expired` and `owner_before` are const and thread-safe.
  - The column memo itself stays per thread (`ThreadOwned`). A refresh after a compare changes only the memo's own stamp, and a re-read replaces the memo's pointer instead of writing into the old block. A test keeps a `ShaderMemory` alive across a write and checks it still reports the old words; a mutation that writes into the shared block turns that test red (R6).
  - The resolution memo is global, under one mutex held only for the lookup and the insert; a resolution is immutable once made.

### 2.6 Draw-cache identity compare (commit 6)

- **Where the cache compares two captures.** On a draw-cache miss, `cacheDrawStages` copies each recompiled stage's captured regions into a new `DispatchVariant` (runs and words), and `insertDrawEntry` looks for a kept variant of the stage with the same push offset, runs and words before inserting it (`present`). `insertDispatch` does the same against the entry's front variant. With an unchanged 32,768-record table that compare went through 262,156 words per kept variant with equal runs, about 61 µs each.
- **What the variant records.** While copying, `AppendSharedWords` checks whether each region's bytes lie inside a block the shader memory holds (`ShaderMemory::SuppliedBlocks()`, the supplied and spilled blocks; the draw path keeps them in its `StageCapture` until the draw is cached). If so, the variant records `SharedWords {first, count, offset, weak block}`: its words `[first, first + count)` were copied from the block's words at `offset`. Consecutive pieces of one block join into one entry, so a table is one entry again after commit 5's page split.
- **The compare.** `SameCapturedWords(left, leftShared, right, rightShared)` walks both lists; where both have an entry at the same `first` with the same `count` and `offset` and the same block (owner-equal weak references to a live block), it skips those words; it compares every other word as before. Draw and dispatch insert use it in place of `words ==`; `runs ==` is still compared first.
- **Why it is sound.** A block is never written after it is published; the variant's words at `[first, first + count)` are a copy of the block's words at `offset`, made in the same loop that recorded the entry; so two variants whose entries name the same block at the same place hold equal words there. Nothing writes a variant's words after it is built: the two build loops are their only writers (checked by search), and `DispatchVariant` cannot be copied (it holds atomics), so `shared` cannot outlive the words it describes. A new write makes a new block ("same column object and generation" is block identity: a new generation is a new block). The reference is weak and compared by owner, not by address: a released block's control block stays allocated until its last weak reference goes, so a new block can never take its identity, even if its words land at the old address. An entry without a block, or whose block is gone, never vouches. Two blocks with equal words, words read into pages, and words outside entries are compared word by word.
- **What it does not do.** A draw-cache *hit* compares the variant's words with guest memory (`validateVariant` → `validateCaptured`), about 77-81 µs for a whole 32,768-record table (PM-027's measurement). Identity cannot skip that: the hit path runs no capture, so "same block" can only be established through the write tracker. The sound follow-up: record, per shared entry, the stamp the block was supplied under; on a hit, skip those runs while `unchangedSince(run, stamp)` holds; keep pending writes, storage images, labels and the publish, pending and forget serials checked first. That changes the draw cache's validation, which today trusts only word compares by default (the analogous `APS5_DISPATCH_STAMP_VALIDATE` is opt-in), and needs driver-level tests with real draws, so it is not in this PR. Sketch: pass the stamp through `supplyWords`, keep it in `SharedWords`, give `validateCaptured` a per-region skip mask that keeps its word-position accounting, and a draw test that writes the table between two hits.

### 2.7 Regions of a reused table equal a read's (commit 5)

- Before commit 2, PM-028 copied a vouched column into pages, so its regions were page segments like a read's. Commit 2 reported each supplied run as one region. The draw and dispatch caches compare `runs` before words, so a capture that reused a column and a kept capture that had read it never matched: the cache kept a second variant holding the same table, once per table and draw key.
- `collect()` now splits each supplied run at 4 KiB guest-page boundaries. The pieces are spans into the block, so nothing is copied; the reserve estimate counts the pieces.
- A table next to other read words in the same page is still reported as two adjacent regions where a read would merge them into one; that only costs the same duplicate in that rare layout.

### 2.8 Variant words reserved (commit 8)

- `cacheDrawStages` and `insertDispatch` grew a new variant's `words` one region at a time; a page-split table is 256 regions, so the 1 MiB vector was reallocated about eight times. Both now sum the regions first and reserve the runs and the words once. Content and accounting (`variantBytes` counts sizes) are unchanged.

## 3. Tests and red/green (task 3)

All in `tests/ShaderMemory.cpp`, `verifyTableSnapshotReuse` (`agc_shader_table_snapshot_reuse`, write-watched and with `APS5_NO_WRITE_WATCH=1`). Its table has 4,096 records of 32 bytes (32,768 words) in write-watched guest arena memory.

- **Sharing without a copy (counters):** an unchanged table reused twice: both snapshots share the fresh column's three blocks, `TableReuse().shared` is 1 per reuse and `columns` (columns built) stays 0. Watched: `ShaderMemory::Supplies()` counts 32,768 words shared, 0 copied, 0 spilled per reuse, the table's regions are consecutive slices of one 128 KiB block, and both captures' regions point into the same block.
- **Regions equal a read's (commit 5):** the fresh read, the reuse and the second reuse report the same 32 table regions.
- **Two stages on one shader memory:** both share the column; each `TakeRecentRegions()` and the union hold the table once, sorted and disjoint, with the table's words.
- **Spill:** a third capture on the same shader memory reads half the table through another V#: the block moves into pages once (32,768 words spilled, none copied), and `Regions()` still holds each word once and equal to memory.
- **Write paths give fresh words, the old column stays valid:** CPU store, driver store (`GuestMemory::Write`, the CP/DMA path), stored GPU result (`StoreOwnBytes`), pending GPU write with a known value and with a sync, flush-hook GPU result, and an unmapped page (`GuestArenaSetProtection` + `GuestAllocationsInvalidate`). Each builds a new column that shares nothing with the old one and is not equal to it; the snapshots sharing the old column, and a `ShaderMemory` kept alive across all the writes, still hold the old words. After the unmapped page comes back, the old column is compared and shared again.
- **Identity never matches different contents (snapshots):** a changed table's distinct T#s neither share nor equal nor hash like the old ones; a table written back to its old words is a new column, equal to and hashing like the old one but not sharing it; `SharedValues` unit checks.
- **The draw-cache identity compare never matches two different contents (commit 6).** Variants are built from real captures exactly as `cacheDrawStages` builds them (`TakeRecentRegions()`, `SuppliedBlocks()`, copy, `AppendSharedWords`):
  - two captures of the unchanged table match, and only the 12 words outside the table are compared (watched; unwatched: every word, no entries);
  - a capture with another output V# in the SRT shares the table block and still does **not** match;
  - a capture after a CPU store does not match (every word compared);
  - the table written back to its old words matches by its words alone, both when read and when its new block is supplied again; the new block is not taken for the old one, which is released (`expired`);
  - unit checks: words copied from a plain copy, a misaligned or empty span are credited to no block; consecutive pieces of one block join and pieces of two places or two blocks do not; equal words from two blocks match by words; a difference outside a shared entry is found; entries without a block, at another offset, past the words, or of a released block never vouch; captures of different sizes never match.
- **Resolution reuse:** a result for another output buffer (result memo miss, table unchanged) shares the resolution (`resolutionsShared` +1, `resolutions` +0) and gets the same map and table binding; after a CPU store the resolution is made again and holds the stored record.

## 8. Draft PR text

Title: `perf(shader): share an unchanged image table column instead of copying it`

```markdown
### What
#PM028 skips reading an image table column while the write tracker vouches that nothing wrote it, but the capture still copied the column every time: its 262,144 words into `ShaderMemory`'s pages, the memo's states, codes and distinct T#s into the snapshot, the codes rebuilt again, and `Regions()` found the words bit by bit. Every `Recompile` then hashed the table word by word for the result memo, and on a draw-cache miss the cache compared the whole table again with each variant it kept. For a 32,768-record column of distinct T#s that was 497 µs per capture and 1.15 ms per draw stage (capture, `TakeRecentRegions()`, `Regions()`, result memo hit), for a table nothing wrote.

This makes an unchanged column's reuse O(1) in the table's size:
1. A column is built once into immutable shared values (`SharedValues`: codes, distinct T#s, read ranges). The column memo and every snapshot that reuses the column hold references; nothing is copied. A column's codes index its own distinct T#s (`ImageTableColumnSnapshot::words`), so every column of a shader is shared, not only the first. The result memo hashes each shared value once and keeps the hash.
2. The memo keeps the column's words in one immutable block (`SrtGuestWords`) that `supplyWords` hands to `ShaderMemory`, which reports its runs page by page, as a read reports them, without copying them into pages. A later read of those words in the same `ShaderMemory` moves the block into pages first, so no word is reported twice.
3. A result memo miss whose tables did not change (another buffer or user data word changed) takes the table resolution by reference: same variant, same direct-sampler reduction, same column blocks by identity. 4 per variant, 256 in all, within 8 Mi words; `APS5_NO_TABLE_RESOLUTION_REUSE=1` turns it off.
4. When the draw cache sets a fresh capture against the variants it keeps (and the dispatch cache against its front variant), the words both captures copied from the same place of the same block are equal without a compare; the rest is compared as before (`SharedWords`, `SameCapturedWords`). A variant holds its blocks weakly and compares them by owner, so it keeps no block alive and a released block's identity is never reused. A new variant's words are also reserved once instead of grown per region.

#PM028's vouching rules are unchanged: whether a column is reused is decided exactly as before; only what a reuse costs changed. A column read again after a write is a new one, and snapshots holding the old one keep it. Blocks are never written after they are published and are shared between threads read-only.

SleglJan's `share/007-perf-v2` experiments (e25f7b7f7, 16c4c7466, c9d00c7f1) explored sharing page images, whole-snapshot reuse with its hash and a hashed table result memo; this is an independent implementation, per column and keyed by identity.
```
