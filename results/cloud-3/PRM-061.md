## 1. The fix (0fbea36bc), and where it departs from the task

**The defaulted `operator==` the task proposed breaks this PR's own test.** I first did exactly that: kept the committed ranges in `CommittedSlabs` under the defaulted equality. It made `agc_driver_partially_committed_volume_compare` fail:
> the partially committed small volume was not kept by a compare of its committed slices after zero pages were committed in them (196608 bytes read)

That case comes from this PR's own cd60c6916. It commits zero-filled pages into the partially committed slab, and expects the view to be kept through a compare. Under range equality, any newly committed page is a miss and a rebuild.

**What goes stale is narrower.** Only a page committed when the snapshot was taken, and decommitted since, does. A page committed since holds zeros in the snapshot, so the existing compare already covers it.

**So the fix (`ShaderResources.cpp`, line numbers at the head) is:**
- **`CommittedSlabs`** gains `ranges`: the view's committed byte ranges, relative to its base, clipped to the view. `committedSlabs` fills them from the same `ranges` it already reads, `described.ranges` or the passed `committed` (`:725-728`). There is no new GuestMemory call.
- **`CommittedSlabs::operator==`** still compares only `slabs` and `slabBytes` (`:110`).
- **`stillCommitted(now, snapshot)`** (`:732-740`) requires that the ranges committed now cover every range of the snapshot. Both lists are sorted and merged, because `describePages` joins adjacent runs, so the check is one linear walk.
- **The sampled-cache hit** (`:1001`) now requires `it->slabs == slabs && stillCommitted(slabs, it->slabs)`. On a hit the entry keeps its snapshot-time ranges, which is the set that matters.

**What it covers:**
- **A page decommitted inside a kept slab** misses and is rebuilt; the fresh build reads zeros there through `ReadCommitted`.
- **Zero pages committed later** are kept by the compare, as the PR intends.
- **Non-zero data committed or written later** is caught by the compare, as before.
- **A page decommitted and recommitted** is caught by the compare too: it reads zeros now, against the snapshot's old bytes.

**Out of scope, unchanged: main's full-size path has the same gap.**
- A view that is not on the slab path (any 2D or 2D-array view, and a 3D view whose slabs are all committed) is accepted on a hit through `GuestMemory::EqualsCommitted(address, it->bytes)` (`:1009`).
- `EqualsCommittedUnsynced` (`GuestMemory.cpp:2481`) compares only the pages committed now, through `CommittedRanges`.
- So a page decommitted inside such a partially committed view is skipped there too. The lookup keeps the old texels where a fresh build reads zeros.
- `unchanged()` and `kept()` don't save it: the first refuses once the committed ranges differ, the second needs an untracked key. That leaves the comparison.
- This task doesn't change that path.

## 2. The tests

**1. Position-encoding pattern** (3871b5eb6).
- **`PatternElement(format, slab, element)`** (`PartiallyResidentSnapshot.cpp:508`) now gives each 8-byte element its position. For 16x4 float, the halves are `slab + 1`, `element % 1024 + 1`, `element / 1024 + 1` and `1`, all exact in half precision. A BC1 block keeps its slab's red, and puts an 11-bit hash of its block index in green and blue. `CommitSlab` writes each element with its own index.
- **Expected texels** come from `ReferenceSamples` (`:765`): the same samples of a fully committed copy of the view. That copy takes the full-size path (`committedSlabs` returns `nullopt`), not the per-slab packed offsets under test.
- **`SameSlab`** (`:520`) also requires each reference texel to hold the sampled slab.

**2. Page decommit** (0fbea36bc): `--committed-volume-page-samples`, registered as ctest `agc_driver_partially_committed_volume_page_samples`, with `SampleDecommittedPage` at `:779`.
1. It commits slabs 21 and 22 of the 64×64×64 16x4-float R64KBX volume, samples, and checks.
2. It decodes the first slab-22 sample's reference element offset (`ElementOffset`, `:516`), and decommits that 4 KiB page of slab 22.
3. It samples again. Every slab-22 sample whose reference offset lies in that page must read zeros. Every other slab-22 sample must read its texel, and both kinds must occur.

**3. All slabs uncommitted** (c36790ee5): `--committed-volume-empty` and `--committed-volume-empty-samples` (`:484`), registered as `agc_driver_partially_committed_volume_empty` and `_empty_samples`.
- **The CPU case** shows it takes the slab path with an empty slab list:

  ```
  [gpu] sampled view 0x200040000 (64x64 format 71, dimension 4, tile 7, slices 0..63) uploads the 0 of its 64 slabs holding committed guest memory (0 of 4 MiB) and 64 zero-filled slices; 1 such views
  the uncommitted volume read 0 of its 4194304 guest bytes and kept 65536 bytes of upload buffers
  ```

  It reads 0 guest bytes, where the full-size path reads all 4194304. The kept 65536 bytes are the one zero slice, with no staging, tiled or linear buffer: the `uploaded`-empty branch.
- **The samples case** reads zeros at every sampled texel.

**4. Registrations** (83c9480ec): `committed-volume-mips` and `committed-volume-bc` are added to the same CMake `foreach`, so they get their neighbours' properties, including WIN32's `ENVIRONMENT_MODIFICATION "PATH=path_list_prepend:$<TARGET_FILE_DIR:libc>"`.
- **Once registered, the BC1 case failed** with "AGC graphics: device does not support BC compressed textures". The test's own `Device`, which the non-sampling cases use, never enabled BC texture compression; the `-samples` cases use `VulkanDevice`, which requires and enables it.
- **The fixture now enables it** when the device has it (`:152`, `:168`), and the BC1 case skips with "skipped, the device has no BC texture compression" when it doesn't. `check_skips` accepts that wording.
- **With that,** both run on lavapipe:

  ```
  the partially committed BC1 volume read 1507328 of its 4194304 guest bytes and kept 4587520 bytes of upload buffers
  the partially committed mipmapped volume read 4521984 of its 12582912 guest bytes and kept 15335424 bytes of upload buffers
  ```
