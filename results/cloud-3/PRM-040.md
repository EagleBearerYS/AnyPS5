## Summary

**One public console measurement answers the main question, and it goes against version B's refusal:**
- On 2026-10-04, PS5_Vulkan registered three buffer sets through `sceVideoOutRegisterBuffers2` on a base PS5 (firmware 13.40) connected to a 1080p screen: 3840x2160, 2560x1440 and 1920x1080. All three were accepted, and VideoOut scaled each one to fill the screen ([PS5_Vulkan HARDWARE_FINDINGS.md:3773-3791](https://github.com/mihawk-99/PS5_Vulkan/blob/5b5e4fc2d80fdb67a4f61ba9e6a8a424026bb8a5/docs/HARDWARE_FINDINGS.md?plain=1#L3773-L3791)).
- The title that did it, PS5 RetroArch, had param.json attribute3 0x80040 at the time ([PS5_RetroArch sce_sys/param.json:9](https://github.com/mihawk-99/PS5_RetroArch/blob/bfc2bf9b55fd86c4ef4fd7ed96c8b39a9580e118/sce_sys/param.json#L9)). That value has bit 2 clear.
- ps5-opengl's documentation says the same in prose: "a 4K render looks sharp on a 1080p TV" ([docs/display-modes.md:13-14](https://github.com/blackbearreloaded/ps5-opengl/blob/a519561626933257213d64a4a8bd5e02b55dceb2/docs/display-modes.md?plain=1#L13-L14)).
- KytyPS5 accepts any size up to 16384x16384 on any output and scales it to the window when presenting.

**Only SharpProspero says 3840x2160 is refused:**
- Its claim: 0x80290005 (INVALID_RESOLUTION) "unless the console [is] set up for it", and only 1920x1080 is accepted on every console ([DisplayDevice.cs:107-113](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Graphics/DisplayDevice.cs#L107-L113)).
- It names no setting and cites no measurement.
- Its titles carry attribute3 0 by default.
- The PS5_Vulkan measurement contradicts it on two points: 3840x2160 was accepted at 1080p, and so was 2560x1440, a size SharpProspero says the output never takes.

**No public source has measured a title whose attribute3 has bit 2 set.**
- The only meaning given for bit 2 is KytyPS5's: "resolution detection". It was added in [61761b65f2](https://github.com/KytyPS5/KytyPS5/commit/61761b65f2ae033fbdf5b4aa734036f66c116f18) with no source and no measurement.
- KytyPS5 uses the bit only to change what `sceVideoOutGetOutputStatus` reports. It never uses it to refuse buffers.
- So nothing in the public sources supports refusing Planet of Lana's or Animal Well's 3840x2160 registration at 1080p. Every source that registers 4K buffers at 1080p, as code or as a measurement, has them accepted and scaled.

**What a title could use to pick its render size, besides its own choice:**
- the resolution class from `sceVideoOutGetOutputStatus`: 1 = HD, 2 = 4K;
- the sizes from `sceVideoOutGetResolutionStatus`, whose layout comes from AnyPS5 and the projects its debt file names; KytyPS5 and SharpProspero do not implement it;
- possibly the `priority` field of `sceUserServiceGetGamePresets`, whose values no source defines.

No source found a SystemService parameter or a sysctl for display size. `sceVideoOutGetDeviceCapabilityInfo_` exists only as a stub name.

## 1. sceVideoOutGetOutputStatus

**The structure:** 0x30 bytes, `{u32 resolution; u32 dynamicRange; u64 refreshRate; u64 flags; u64 reserved[3]}`. KytyPS5 ([videoOut.cpp:143-150](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/graphics/presentation/videoOut.cpp#L143-L150)), SharpProspero ([VideoOutTypes.cs:373-393](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/VideoOut/VideoOutTypes.cs#L373-L393)) and AnyPS5 ([SceTypes.hpp:2007-2013](https://github.com/EagleBearerYS/AnyPS5/blob/4560e2bdae34936f43be3ddd018b4bdb551ae4e8/core/libs/SceTypes.hpp#L2007-L2013)) all agree.

**Enumerations,** named by SharpProspero:
- `resolution`: 0 Unknown, 1 Hd ("1080p and similar"), 2 UltraHd4K ([VideoOutTypes.cs:148-159](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/VideoOut/VideoOutTypes.cs#L148-L159)).
- `dynamicRange`: 0 Unknown, 1 Sdr, 2 Hdr ([:161-172](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/VideoOut/VideoOutTypes.cs#L161-L172)).
- `flags`: bit 0 is HDR ([:174-183](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/VideoOut/VideoOutTypes.cs#L174-L183)).
- `refreshRate`: 0 Unknown, 3 = 59.94 Hz, 13 = 119.88 Hz ([:212-223](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/VideoOut/VideoOutTypes.cs#L212-L223)). KytyPS5 uses the same values 3 and 13 ([videoOut.cpp:65-66](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/graphics/presentation/videoOut.cpp#L65-L66)).

**4K-capability field:** none. The structure has only the resolution class of the current output. No source names a "4K capable" bit in `flags` or `reserved`.

**What each source fills in:**

- **KytyPS5** ([videoOut.cpp:1788-1822](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/graphics/presentation/videoOut.cpp#L1788-L1822)):
  - **resolution** = 1 only when attribute3 has bit 2 and the window is smaller than 3840x2160 in both dimensions. Otherwise it is 2 ([:1801-1809](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/graphics/presentation/videoOut.cpp#L1801-L1809)). The window size is `--screen-width`/`--screen-height`, 1280x720 by default ([emulatorConfig.h:52-53](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/common/emulatorConfig.h#L52-L53), [agc.cpp:77-81](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/libs/agc.cpp#L77-L81)).
    - At 1080p: a title with bit 2 gets 1; a title without it gets 2.
    - At 4K: every title gets 2.
  - **dynamicRange** = 2 when param.json `attribute` has bit 0x20000000 (or has no `attribute`) and the host supports HDR; otherwise 1 ([:1803-1810](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/graphics/presentation/videoOut.cpp#L1803-L1810)).
  - **refreshRate** = 13 when the output mode is 0xF or the vblank rate is at least 119 Hz; otherwise 3 ([:1811-1814](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/graphics/presentation/videoOut.cpp#L1811-L1814)).
  - **flags and reserved:** always 0 ([:1815-1818](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/graphics/presentation/videoOut.cpp#L1815-L1818)).
  - The VRR status call (`gWT7X8H0bYs`) fills the same 0x30 bytes and then zeroes 8 more ([libVideoOutVrrStatus.cpp:42-62](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/libs/libVideoOutVrrStatus.cpp#L42-L62)).
- **SharpProspero** only calls the function and fills nothing ([VideoOut.cs:153-155](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/VideoOut/VideoOut.cs#L153-L155)).
- **A console:** no public source records what it reports at 1080p or at 4K.

`sceVideoOutAllowOutputResolutionWqhdDetection` returns OK in KytyPS5 ([videoOut.cpp:1824-1829](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/graphics/presentation/videoOut.cpp#L1824-L1829)) and changes nothing there. No source says what it changes on a console.

## 2. sceVideoOutConfigureOutput and sceVideoOutIsOutputSupported

**Signature,** the same for both: `(int handle, u64 mode, const SceVideoOutOutputOptions* options, void* reserved, u64 reserved)` ([SharpProspero VideoOut.cs:120-139](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/VideoOut/VideoOut.cs#L120-L139)).

**The options struct** is an opaque 64-byte block, `u32 internalData[16]`, filled by `sceVideoOutInitializeOutputOptions` ([SharpProspero VideoOutTypes.cs:362-371](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/VideoOut/VideoOutTypes.cs#L362-L371), [KytyPS5 videoOut.cpp:152-154](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/graphics/presentation/videoOut.cpp#L152-L154)). The sources disagree on what initialization writes:
- KytyPS5 zero-fills it and refuses any nonzero word with VIDEO_OUT_ERROR_INVALID_OPTION ([videoOut.cpp:1866-1872](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/graphics/presentation/videoOut.cpp#L1866-L1872), [:1881-1891](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/graphics/presentation/videoOut.cpp#L1881-L1891)).
- AnyPS5 writes 0x00FF0000 to word 0 (see section 6).

**Modes every source knows:**
- 0 is Unknown (SharpProspero only).
- 1 is Default.
- 0xF is 119.88 Hz.

Sources: [SharpProspero VideoOutTypes.cs:225-236](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/VideoOut/VideoOutTypes.cs#L225-L236) and [KytyPS5 videoOut.cpp:63-64](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/graphics/presentation/videoOut.cpp#L63-L64).

**The console's answers for selectors 0-63** (PS5_Vulkan, [HARDWARE_FINDINGS.md:3376-3385](https://github.com/mihawk-99/PS5_Vulkan/blob/5b5e4fc2d80fdb67a4f61ba9e6a8a424026bb8a5/docs/HARDWARE_FINDINGS.md?plain=1#L3376-L3385)):
- `IsOutputSupported` answers 1 for selectors 1 and 15 only.
- Selectors 4, 7, 8, 12-14 and 16-19 answer 0x80290016 (UNSUPPORTED_OUTPUT_MODE).
- Every other selector answers 0x8029001E.
- These answers do not change with the title's high-frame-rate declaration.
- `ConfigureOutput(15)` returns 0x80290016 for a title whose attribute3 lacks 0x80040.

**KytyPS5's answers:**
- Every mode other than 1 and 0xF gets 0x80290016 ([videoOut.cpp:1856-1879](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/graphics/presentation/videoOut.cpp#L1856-L1879)). KytyPS5 never returns 0x8029001E.
- `IsOutputSupported(0xF)` returns 1 when the vblank rate is at least 119 Hz and 0 otherwise. Every other valid mode returns 1 ([:1893-1910](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/graphics/presentation/videoOut.cpp#L1893-L1910)).
- `ConfigureOutput` turns an answer of 0 into 0x80290019 (UNAVAILABLE_OUTPUT_MODE). On success it stores the mode and raises the output-mode event, with the mode as the event's data ([:1912-1939](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/graphics/presentation/videoOut.cpp#L1912-L1939)).
- KytyPS5 does not check attribute3 for 0xF.

**A 4K mode on a 1080p output:** no source defines a 4K mode, so no source gives an answer.

**Whether a mode encodes a resolution:** no source says one does. The only mode values any source defines (1 and 0xF) differ only in refresh rate. The ps5-payload-dev SDK exports `sceVideoOutConfigureOutputEx`, `sceVideoOutConfigureOutputMode_`, `sceVideoOutConfigureOutputModeEx_` and `sceVideoOutGetCurrentOutputMode_` ([libSceVideoOut.c:110-124](https://github.com/ps5-payload-dev/sdk/blob/f5d40f02770e9b0001dd9e18056eca70b3da8b40/sce_stubs/libSceVideoOut.c#L110-L124), [:246](https://github.com/ps5-payload-dev/sdk/blob/f5d40f02770e9b0001dd9e18056eca70b3da8b40/sce_stubs/libSceVideoOut.c#L246)). No source gives their arguments.

## 3. sceVideoOutRegisterBuffers2 and sceVideoOutSetBufferAttribute2

**The attribute structure, SceVideoOutBufferAttribute2:**
- Fields: `reserved0, tiling_mode, aspect_ratio, width, height, pitch_in_pixel` (u32 each); `option, pixel_format, dcc_cb_register_clear_color` (u64 each); `dcc_control, pad0` (u32); `reserved1[3]` (u64).
- Sources: [KytyPS5 videoOut.cpp:101-114](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/graphics/presentation/videoOut.cpp#L101-L114) and [SharpProspero VideoOutTypes.cs:320-360](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/VideoOut/VideoOutTypes.cs#L320-L360).
- `SetBufferAttribute2` clears the structure, sets `aspect_ratio` and `pitch_in_pixel` to 0, and copies the other arguments ([KytyPS5 :1329-1359](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/graphics/presentation/videoOut.cpp#L1329-L1359)).
- Tiling: 0 is tiled and 1 is linear ([SharpProspero VideoOutTypes.cs:95-103](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/VideoOut/VideoOutTypes.cs#L95-L103)).
- Options: 8 is strict colorimetry and 32 is alpha-premultiplied ([:278-298](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/VideoOut/VideoOutTypes.cs#L278-L298)).

**Fields that affect whether a size is accepted:** no field encodes an output or a resolution class. SharpProspero records two refusals that are not about size:
- A nonzero `pitch_in_pixel` is refused ([DisplayDevice.cs:174-178](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Graphics/DisplayDevice.cs#L174-L178)).
- Linear tiling is refused with 0x80290007 unless the debug setting "Enhanced Display Buffer Attribute" is on ([:181-190](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Graphics/DisplayDevice.cs#L181-L190)).

The SDK exports a `sceVideoOutAddBuffer4k2kPrivilege` ([libSceVideoOut.c:10](https://github.com/ps5-payload-dev/sdk/blob/f5d40f02770e9b0001dd9e18056eca70b3da8b40/sce_stubs/libSceVideoOut.c#L10)). The name suggests 4K buffers can be gated by a privilege, but no source says who calls it or what it changes.

**Error codes:** 0x80290001-0x8029001D, 0x802900FE and 0x802900FF ([KytyPS5 errno.h:296-325](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/libs/errno.h#L296-L325)). 0x80290005 is INVALID_RESOLUTION ([:300](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/libs/errno.h#L300)). KytyPS5 defines it but never returns it.

**Accepted sizes, source by source:**
- **KytyPS5:**
  - `RegisterBuffers2` checks the handle, the pointers, the indices, `option == NULL` and the category ([videoOut.cpp:1420-1467](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/graphics/presentation/videoOut.cpp#L1420-L1467)), then validates each buffer ([:1490](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/graphics/presentation/videoOut.cpp#L1490)).
  - The validation takes any width and height from 1 to 16384 and stops the emulator, rather than returning an error, on anything it does not support ([:547-559](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/graphics/presentation/videoOut.cpp#L547-L559), [:578-581](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/graphics/presentation/videoOut.cpp#L578-L581)).
  - There is no check against the output. The flip is a linear-filtered blit of the whole buffer to the whole swapchain ([swapchain.cpp:801-819](https://github.com/KytyPS5/KytyPS5/blob/6aa3846fb2b810fc0b7d75d8296e19d391c1a705/src/graphics/presentation/window/swapchain.cpp#L801-L819)).
  - So 3840x2160 is accepted at any window size and scaled.
- **SharpProspero:**
  - Documents the sizes the output takes: 1920x1080, 3840x2160, 720x480, 720x576, and widths that are multiples of 32 from 1280 to 1888 with height = width x 9/16 ([DisplayDevice.cs:107-113](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Graphics/DisplayDevice.cs#L107-L113), [:213-217](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Graphics/DisplayDevice.cs#L213-L217)).
  - Says only 1920x1080 is accepted on every console. The others "need the console set up for them" and are otherwise refused with 0x80290005, the same answer as a size not on the list ([:24-26](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Graphics/DisplayDevice.cs#L24-L26), [:191-197](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Graphics/DisplayDevice.cs#L191-L197); repeated in [docs/application.md:93](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/docs/application.md?plain=1#L93)).
  - Does not say which setting "set up" means.
  - Its packages carry attribute3 0: its samples set it ([samples/prospero-game/sce_sys/param.json:20](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/samples/prospero-game/sce_sys/param.json#L20)), and its packager writes 0 when the field is absent ([tools/SharpProspero.Prx/ParamJson.cs:167-172](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/tools/SharpProspero.Prx/ParamJson.cs#L167-L172), [:398-403](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/tools/SharpProspero.Prx/ParamJson.cs#L398-L403)).
- **PS5_Vulkan, measured on a base PS5 (firmware 13.40) at 1080p** ([HARDWARE_FINDINGS.md:3773-3791](https://github.com/mihawk-99/PS5_Vulkan/blob/5b5e4fc2d80fdb67a4f61ba9e6a8a424026bb8a5/docs/HARDWARE_FINDINGS.md?plain=1#L3773-L3791)):

## 7. 4K display buffers on a 1080p output

**Does RegisterBuffers2 accept 3840x2160 at 1080p and scale it?** Yes, for a title without attribute3 bit 2. For a title with bit 2 there is no data.
- **Measured:** a base PS5 (firmware 13.40) on a 1080p screen accepted 3840x2160 (and 2560x1440 and 1920x1080) and scaled each one to fill the screen ([PS5_Vulkan HARDWARE_FINDINGS.md:3773-3786](https://github.com/mihawk-99/PS5_Vulkan/blob/5b5e4fc2d80fdb67a4f61ba9e6a8a424026bb8a5/docs/HARDWARE_FINDINGS.md?plain=1#L3773-L3786)). The title's attribute3 was 0x80040.
- **ps5-opengl:** says the same ([display-modes.md:13-14](https://github.com/blackbearreloaded/ps5-opengl/blob/a519561626933257213d64a4a8bd5e02b55dceb2/docs/display-modes.md?plain=1#L13-L14)).
- **KytyPS5:** accepts the buffers and scales them at flip whatever attribute3 holds (section 3). For a title with bit 2 at 1080p, it reports resolution 1 and still takes the 4K buffers.
- **SharpProspero:** says the opposite: 0x80290005 unless the console is "set up" for 4K (section 3). It cites no measurement, and its titles have attribute3 0.

**Does any title-facing value change a title's render size?**
- **`sceVideoOutGetOutputStatus.resolution`** (1 HD or 2 4K) is the only value any source fills that a title could use.
  - KytyPS5 makes it depend on attribute3 bit 2 and the window size.
  - No source says how a console fills it at 1080p.
- **SystemService parameter IDs:** none for display size in any source.
- **UserService:** `GetGamePresets.priority` has undefined values. The link to Sony's "Performance Mode or Resolution Mode" preset is my inference only (section 4).
- **`sceVideoOutGetDeviceCapabilityInfo_`:** a name only.
- **A 1080p or 4K flag in the output mode:** no source defines one. The known modes differ only in refresh rate.
- **`sceVideoOutGetResolutionStatus`:** exists in AnyPS5 (section 4). No public console measurement of its values was found.

**Output modes a title passes to ConfigureOutput after a refused registration:**
- No source traces a title doing this.
- The mode values the sources know, and their console answers (section 2):
  - **0** Unknown (SharpProspero's name). The console answers 0x8029001E.
  - **1** Default, 59.94 Hz. Supported.
  - **0xF (15)** 119.88 Hz. `IsOutputSupported` answers 1 on a 120 Hz-capable display. `ConfigureOutput` needs attribute3 0x80040, otherwise 0x80290016.
  - **4, 7, 8, 12, 13, 14, 16, 17, 19** have no known meaning. The console answers 0x80290016 (PS5_Vulkan).
  - **18 (0x12)** answered 0x80290016 on one console and 0x8029001E on another, per AnyPS5's debt file ([debt/libSceVideoOut.md:17](https://github.com/EagleBearerYS/AnyPS5/blob/4560e2bdae34936f43be3ddd018b4bdb551ae4e8/docs/dev/debt/libSceVideoOut.md?plain=1#L17)).
  - **Every other value up to 63** answers 0x8029001E.
  - **0xd000000a**, probed by PPSA12544, answered 0x8029001E per the same debt line. No source gives its meaning.
- Planet of Lana's mode value is not in any source; the PC trace will give it.

## What this means for version B

These follow from the facts above. They are not measured.
- Refusing 3840x2160 at 1080p has no support from any source for titles with bit 2.
- The one console measurement shows 4K buffers accepted and scaled at 1080p for a title without bit 2.
- The one implementation that reads bit 2 (KytyPS5) changes only the reported resolution class and never refuses buffers.

A version that keeps the setting's effect on `GetOutputStatus`/`GetResolutionStatus` and always accepts and scales the buffers would match every source except SharpProspero's unmeasured claim. A console run of a title with bit 2 at 1080p, for example a homebrew title with attribute3 0x4, would settle the question.
