### `Export.cpp`

- **`GamePresetsPriority()`** is modelled on `ConsoleLanguage`. It reads `ANYPS5_GAME_PRESETS_PRIORITY` on each call:
  - unset or empty gives 0;
  - `std::from_chars` into `uint32_t` must consume the whole text and give 0 to 2;
  - anything else throws `std::runtime_error`: `sceUserServiceGetGamePresets: ANYPS5_GAME_PRESETS_PRIORITY must be a game preset priority from 0 to 2, not "<value>"`.
- **Order of checks:** the null-pointer and user-id checks come first and return `USER_SERVICE_ERROR_INVALID_ARGUMENT` as before, even when the setting is invalid. The setting is read before any field is written, so a rejected value leaves the caller's struct untouched.
- **Fields:** every field other than `priority` stays 0, and `this_size` stays the caller's.
- **The log line:** a one-shot `std::atomic<bool> gamePresetsReported`, next to `loginReported`. On the first call that answers, one line goes to stderr, whether or not the setting is set:
  `[userservice] sceUserServiceGetGamePresets: this_size 40, difficulty 0, priority 0, invert_vertical_view_for_1st_person_view 0, invert_horizontal_view_for_1st_person_view 0, invert_vertical_view_for_3rd_person_view 0, invert_horizontal_view_for_3rd_person_view 0, display_sub_titles 0, audio_language 0`
  - The values are the ones returned; `this_size` is whatever the caller passed.
  - A call rejected for its arguments or its setting prints nothing and does not use up the one line.
- **The removed comment:** the function's old comment ("a fresh console has none set: every field is 0") is gone, since CONVENTIONS allows no comments in code. What it said now lives in USAGE.md and the debt file.

### `GuestUserServiceGamePresets.cpp`

1. **The first-call line.** stderr is redirected to a temporary file, using the AGC Flip test's `dup`/`freopen`/`dup2` pattern, around the process's first calls:
   - a null pointer, `USER_SERVICE_INITIAL_USER_ID + 1` and `USER_SERVICE_USER_ID_INVALID`: each returns `USER_SERVICE_ERROR_INVALID_ARGUMENT` and prints nothing;
   - an unset answer;
   - an answer with the setting at 2.
   The test requires the capture to be exactly the one line above (with `this_size` = `sizeof(UserServiceGamePresets)`, 40) followed by a newline. So the line is printed exactly once, and only for the call that answered.
2. **Accepted values.** Unset, empty and `0` give `priority` 0; `1` gives 1; `2` gives 2. In every case all other fields are 0 and `this_size` is unchanged. The struct is filled with 0xa5 before each call, so a field the call forgot to write would show.
3. **Rejected values:** `3`, `-1`, `1x`, `x`, `+1`, ` 1`, `1 `, `4294967297`. Each must throw `std::runtime_error` whose message contains `ANYPS5_GAME_PRESETS_PRIORITY`, `from 0 to 2` and the quoted value, with the struct byte-for-byte untouched.
4. **Argument errors** with the setting at `x` and at `1`: a null pointer and another user id still give `USER_SERVICE_ERROR_INVALID_ARGUMENT`, with the struct untouched.

**Red/green:** against the unchanged `Export.cpp` (upstream main's), the test aborts (`Subprocess aborted***Exception`). With the change it passes.

## What 1 and 2 mean: sources

**No source I could check names the values**, so the code, the error text and the docs use the numbers only. In detail:

- **shadPS4** (https://github.com/shadps4-emu/shadps4, shallow clone at e6c79a5fe0ea2f3d03fcb9c5c50cf61af063f3f5): a case-insensitive search for `GamePresets`, `game_presets` and `GamePreset` over its `.h`, `.hpp` and `.cpp` files found nothing.
- **KytyPS5** (https://github.com/KytyPS5/KytyPS5) and **SharpProspero** (https://github.com/SvenGDK/SharpProspero): not checked.
  - The environment's permission classifier refused to attach either repository ("Untrusted Code Integration").
  - It also refused a second, narrower read of shadPS4's user-service sources after the first search.
  - I did not try to get around it.
  - If the PM wants these checked, the session owner needs to allow `add_repo` for those repositories, or the PC can look.
- **Web searches** for `sceUserServiceGetGamePresets` with "priority", and for `SceUserServiceGamePresets` / `SCE_USER_SERVICE_GAME_PRESETS_PRIORITY`, found no SDK names or values.
- **Sony's public support page** "How to customize game presets on PS5 consoles" (https://www.playstation.com/en-gb/support/games/how-to-customize-game-presets-on-ps5-consoles/, fetched 2026-10-17) names the setting "Performance Mode or Resolution Mode": "Make motion in your game smoother with performance mode, or have higher graphic quality in resolution mode. This applies only to games that offer these modes." It gives no numbers.
  - That supports the field's meaning, but not which of 1 and 2 is which.
  - It also does not say whether 0 is "game default" on the console; the code keeps 0 as before.
