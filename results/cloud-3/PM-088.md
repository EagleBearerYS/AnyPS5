# PM-088: system library coverage, and where real implementations can raise it (cloud-3)

Read-only analysis of upstream main **a6dcea927**, the same tree the 2026-10-21 badge was measured on.
- `tools/progress.py` (`collect_libraries()`) gives **4,670 done of 11,032 declared, 42.33%**, and 6,362 todo in 360 libraries.
- The 25 libraries the task names hold **4,172** of the 6,362 todo.
- No game data, Sony libraries or firmware were used. Semantics come from the tree and from public APIs (FreeBSD 11, POSIX, LibreSSL/OpenSSL, unicode.org/RFC charset tables).

## Method and files

- **Classification:** every one of the 4,172 todo functions got exactly one class (A, B-S, B-M, B-L, C, D), with a one-line basis.
  - The basis gives the existing `path:line` for A, the public source and in-tree neighbour for B, the result and why for C, and the reason for D.
  - Six parallel read-only passes did the classifying, one per group of libraries, under one shared guide.
- **Checks:** a script checks that each table holds exactly that library's todo names, once each. I spot-checked rows in every library.
- **My changes to the passes' output:**
  - LibreSSL's `ENGINE_get_id` and `ENGINE_set_default` moved from C to D: no valid call exists and they stay a throw.
  - In libkernel_sys, the two `pthread_switch_*` rows are counted as real-behaviour C; the word "silent" in their basis is only "not a silent stub".
- **Attached files:**
  - Per-function tables: `results/cloud-3/PM-088/<library>.tsv` (columns `function, class, basis`).
  - Per-library notes, with families, dependency notes and batch proposals: `results/cloud-3/PM-088/<library>.notes.md`.

**What the classes contain:**

- **A (25)** is small, because almost nothing is implemented twice under the same NID.
  - The only name-level match anywhere is libkernel_sys `fstat`/`pwrite` against libkernel's `fstat_nid_disambig1`/`pwrite_nid_disambig1`.
  - Of libkernel_sys's 21 A rows, 3 are exact equivalents: those two, and `lchmod` = `fchmodat(AT_FDCWD, …, AT_SYMLINK_NOFOLLOW)`.
  - The other 18 are two-line forwarders onto a libkernel function using its existing errno↔SCE conversion (`scePthreadBarrierDestroy` → `pthread_barrier_destroy`, `sceKernelMsync` → `msync`, and so on).
  - SystemService has 2 (`sceLncUtilGetAppIdOfRunningBigApp`, `sceLncUtilLoadExec` onto their implemented SystemService twins). SaveData has 2 (`sceSaveDataAbort`, `sceSaveDataInitialize2` onto existing helpers).
- **B-S (664)** is mostly two libraries: libSceCesCs (225, conversions over tables the library already has or public tables) and libSceLibreSsl/3 (253, on the mbedtls the tree already builds). Then libkernel_sys has 113 (FreeBSD 11 calls next to libkernel code).
  - The B-S size is per function. Each family's first batch also carries shared setup: the LibreSSL EVP/descriptor layer, and moving CesCs's converter helpers out of anonymous namespaces.
- **C (320)** splits by the CONTRIBUTING rule:
  - **269 real behaviour:** the console's answer when the device or service is absent. NpTus 95, Hmd2 66, NpManager 37, SystemService 27, Pad 13, LibreSSL `ENGINE_*` 11, Hmd 10, NpCppWebApi 6, Gnm 2, libkernel_sys 2.
  - **51 silent stubs:** SystemService 32, NpCppWebApi 17, Net 2. CONTRIBUTING allows these only when they unblock a title and only affect the UI, so each needs a title.
- **D (2,901)** covers four groups:
  - private system-service IPC (most of SystemService, FsInternalForVsh, mdbg_syscore, Mbus, RegMgr, DataTransfer, Bgft);
  - libraries with no prototypes in the tree (Fios2, Composite, NpCommon);
  - formats not derivable from public sources (the Gnm Neo command stream, the Font Graphics renderer);
  - console-state predicates the tree refuses to guess (`sceKernelIs*`/`Has*`).

## Functions that already behave but count as todo

`progress.py` counts a function as todo if any branch calls `NotImplemented_nid_no_patch`. Some rows are todo only because of an unreachable or partial branch. These are maintainer decisions, not new code. They are listed so the badge is not read as missing behaviour.

- **libSceHmd2, 66 C rows:** these already return the pre-initialisation answers measured on the console. `sceHmd2Initialize` always fails here, so the post-initialisation branch that calls `NotImplemented` cannot be reached.
  - Replacing it with an explicit throw would make them count as done with no change in behaviour.
  - That only holds if the project accepts that Initialize never succeeds on a PC.
- **libSceNpCppWebApi, 34 D rows:** these work offline already. A shared release helper still calls `NotImplemented` on one path, an object without a deleter, and closing that path needs object layouts from a title's bundled module.
- **libkernel_sys, 5 partial functions** (`fork`, `fchown`, `symlink`, `readlink`, `readlinkat`): one branch of each still throws. The rows describe only that gap.
- **libSceSystemService:** `sceSystemServiceLoadExec` is the same case. Only unconverted executables and paths outside `/app0` still throw.

## Batch proposals for the three largest classes of work

Each batch is 10–40 functions on one topic. The tests extend the library's existing guest test executables where they exist; the per-library notes give the exact registration lines.

- Tests: `guest_kernel_sys_tests` (`core/libs/tests/GuestKernelSys.cpp`) compares each forward with its libkernel target, on one success input and one error input, including the errno → 0x8002xxxx mapping.

## Dependency notes

- **libSceLibreSsl / libSceLibreSsl3.**
  - **Tier 1 needs no new dependency.** It covers digests, AES/DES, EVP digest/cipher, HMAC, CMAC, RAND, ERR, and BN/RSA/EC/ECDSA/ECDH/EVP_PKEY as guest-layout mirrors. It builds on `3rdparty/mbedtls` 3.6.7, which libSceSsl already uses; its config already enables DES, CMAC, NIST_KW, GCM, CFB/CTR, PKCS1_V21, ECDH and ECDSA.
    - Build change: move `configure_ssl_backend()` from `libSceSsl/CMakeLists.txt` into a shared cmake file, and give libSceLibreSsl its own CMakeLists.txt linking `mbedcrypto`.
    - Not in mbedtls 3: MD4, standalone EMSA-PSS, RSA recover and compressed-point decode. Those are B-M by hand.
  - **Tier 2 (B-L, 173 rows) needs LibreSSL as a new `3rdparty/` submodule built from source.** It covers BIO, the ASN.1 codec and X509 object graph, verify, PKCS#12, OCSP, CONF and libssl. mbedtls has no OCSP, PFX parser, OBJ/NID table, BIO, TLS 1.0/1.1, DTLS 1.0, NPN or OpenSSL cipher strings.
    - **Release pin:** a 2.x release whose public structs match the console's export set, which is 2.x-generation (`SSLeay`, `SSL_library_init`, caller-allocated `HMAC_CTX`/`EVP_MD_CTX`). The exact console release is not known: `SSLeay` returns 0x20000000.
    - **Build:** its CMake, building static libcrypto/libssl with hidden symbols, as mbedtls is linked today. It is not one of the distro-packaged `ANYPS5_USE_SYSTEM_DEPS` libraries.
    - **Layouts:** guest-visible structs must keep the guest's LP64 layout, pinned with static_asserts as `libSceSsl/SslTypes.hpp` does.
    - **Windows:** LLP64 shifts every struct with a `long` field, so objects a title reads directly need guest-layout copies there.
    - **Glue:** guest `FILE*` is libc's FileStream, guest paths go through libc path resolution, guest sockets map through the libkernel/libSceNet tables, guest callbacks and `BIO_METHOD` tables need `APS5_VABI` thunks, and memory released with `OPENSSL_free` must come from the guest libc heap.
    - Keys made by tier 2 must be converted into tier-1 objects at the boundary, unless tier 1 also moves to LibreSSL.
- **libSceCesCs:** no runtime dependency. The new tables are generated offline from public files (unicode.org ISO8859/MICSFT/GB2312/CP936, RFC 1468/1489/2319, x0213.org) into headers like the existing `Cp949.hpp`. ICU or iconv would only be a table source.
- **libSceFont:** the three B-M glyph-render rows use the existing freetype submodule.
- **Everything else:** no dependency. libkernel_sys needs only host POSIX/Win32 and libkernel code.

## Other findings

- **libSceSaveData:** 0x809F0005 is defined twice with different meanings.
  - `SD_ERROR_NO_PERMISSION = sd_error(0x05)` in `libSceSaveData/SaveDataCore.hpp:49`.
  - `SAVE_DATA_ERROR_ALREADY_INITIALIZED = -2137063419 // 0x809F0005` in `libSceSaveData.native/SaveData.hpp:13`.
  - Neither is used in a `.cpp` today, but one of them is wrong.
- **Split mount state:** mounts made through `sceSaveDataMount3` are kept in libSceSaveData.native, so libSceSaveData's IsMounted, GetMountedSaveDataCount and GetAllSize would read the wrong state. They stay D until the state is shared.
- **Signatures from other open-source emulators:** some B/C rows depend on argument lists from shadPS4, RPCS3 or Orbital, none of them measured on a console. The rows say so: NpTus (95 C), SaveData backup/progress, and the CesCs prototypes the done exports already use.
- **libkernel_sys `sceKernelWrite*Command` (18 B-S):** the signature is inferred from the two kernel writers already in `Apr.cpp`. It should be confirmed before relying on it.
