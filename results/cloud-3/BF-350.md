### 4.2 Can #13581's eviction drop a mirror that holds #12840's pending stores?

**No.** Line numbers are at 6abdcdeb6a. `GuestBufferMemory.cpp` is `Graphics/src/GuestBufferMemory.cpp`; the header is `Graphics/include/GuestBufferMemory.hpp`.

**#12840's side: where the pending stores live.** All of them are on the build's own `GuestBufferMemory` object, which lives until its `WriteBack`:
- **Store spans** are entries appended to `writes` by `addAddressStoreSpans()` (`.cpp:6544–6561`). Only regions with a writable heap mirror get one:
  ```
  6548  if (region.mirror == nullptr || !region.mirror->heap || !region.mirror->writable || !region.writable) return;
  6558      for (const auto& region : space->base) add(region);
  6560  for (const auto& region : regions) add(region);
  ```
- **Stored pages** are `storedPages = mergeWrites(std::move(pages));` (`.cpp:6523`, `NoteAddressStores`). **Page contents and masks** are `storePageEntries = std::move(pages);` (`.cpp:6528`, `NoteStorePages`). Both are copies of addresses and bytes, not mirror references (`.hpp:557–558`).
- **`WriteBack` consumes them** through each range's owning region (`.cpp:6636`, `const auto* found = owner(begin, end);`). It stores runs only when that region still has a writable heap mirror:
  ```
  6639  const bool storeRuns = addressStores && region.mirror != nullptr && region.mirror->heap && region.mirror->writable;
  ```
- **The region holds the mirror by `shared_ptr`.** `.hpp:464–465`: "Kept alive here for recorded work." / `std::shared_ptr<ImageMirror> mirror {};`. So from `addAddressStoreSpans` to `WriteBack`, every mirror with a pending span has a reference held by a live region, either in `regions` or in the build's pinned `space->base`.

**#13581's side: what eviction can pick.** `sweepMirrors(neededBytes, protectAddress)` (`.cpp:3313–3383`) evicts only over the heap mirror budget:
```
3347  for (const auto& block : *buildingBlocks) queued.insert(block.mirror);
3352  if (!it->second->heap || it->first == protectAddress || queued.count(it->second.get()) != 0) continue;
3353  const bool buildingHolds = buildingBufferMemory != nullptr && buildingBufferMemory->HoldsMirror(it->second);
3354  const auto allowedCount = (buildingHolds && !it->second->writable) ? 2 : 1;
3355  if (it->second.use_count() == allowedCount) {
```
- **A writable mirror is a candidate only when `use_count() == 1`,** that is, when the registry entry is its only owner. Any live region holding it, in the building `GuestBufferMemory` or in any earlier build still waiting for its `WriteBack`, makes the count at least 2. So such a mirror is skipped.
- **The one case with a count of 2 is a non-writable mirror held by the building memory.** That is the only path to `buildingBufferMemory->EvictMirror(victim->second)` (`.cpp:3371`), which resets `region.mirror` (`.cpp:4436–4454`). A non-writable mirror never gets a store span (6548) and never stores runs (6639).
- **Two more exclusions:** mirrors with queued refresh blocks (3347, from ed3b5393f1) and the mirror being acquired (`protectAddress`).
- **Even when it runs, eviction only unlists the registry entry** (`unlistMirror` plus `entries.erase`, 3374–3376). The memory goes only when the last `shared_ptr` drops.

`releaseImportedMirrors` (`.cpp:3385–3423`) is older than #13581, and #12840 doesn't change it. It likewise only unlists registry entries.

**So:** between `addAddressStoreSpans`/`NoteAddressStores`/`NoteStorePages` and the `WriteBack` that consumes them, the mirror is held by the build's region. #13581's victim test (3354–3355) excludes it, and `EvictMirror` is reachable only for non-writable mirrors, which carry no stores.
