## 1. The fix

**Rule 1: a set budget wins.**
- `HostImportBudgetWith(configured, set, reported, allocationFailed, ceiling)` (`Graphics/src/GuestBufferMemory.cpp:2738`) never takes the device report when `APS5_HOST_IMPORT_MIB` is set. A test's `SetHostImportBudget` counts as set too.
- The failure ceiling still applies to a set budget. A `vkAllocateMemory` failure within an eighth of the budget, or the third in a row, still lowers it to the live imports, as before.

**Rule 2: no setting means main's default until a failure.**
- Main's default rule is unchanged (`importBudget`, `:1031`): the larger of 6 GiB and half the physical memory, at most the largest host heap less 2 GiB.
- The device report can lower that default only once an import's `vkAllocateMemory` has failed. Any failure counts: `state.allocationFailed`, set at `:1323`.
- Once lowered, the budget is `min(default, report)`. A report above the default never raises it.
- The flag clears wherever the ceiling clears: device change, `ClearHostImports`, `SetHostImportBudget`.

**The lower-on-failure path is as it was.** Only its `if` is split so that every `vkAllocateMemory` failure also sets the flag. The ceiling condition and its message are unchanged.

**The report itself is still read at most once a second.** `effectiveBudget` (`:1059`) now also keeps the host heap's index, its reported budget and its usage for printing. `HostImportBudgetFor` (`:2728`, the formula) is unchanged.

**The print:**
- The first time the report would lower the budget, one sibling line (`noteReportedBudget`, `:1050`) prints. For a default budget it prints once more if a later failure makes the report apply.
  ```
  [gpu] host import budget: host heap H reports a VK_EXT_memory_budget budget of B MiB and a usage of U MiB with L MiB of imports live, which leaves imports R MiB of the C MiB APS5_HOST_IMPORT_MIB sets; the setting stays, as the report never lowers it
  ```
  - For a default budget, the line reads `... of the C MiB of the default; the default stays until an import's vkAllocateMemory fails`.
  - After a failure it reads `...; imports are held to it since an import's vkAllocateMemory failed`.
- The existing refusal line (every 10 s while refusing, `:1225`) no longer says `(APS5_HOST_IMPORT_MIB)` whatever the source. It names where its budget came from: `APS5_HOST_IMPORT_MIB`, `the default`, `the host heap's VK_EXT_memory_budget report` or `lowered after vkAllocateMemory failed`. It then adds `; host heap H reports a budget of B MiB and a usage of U MiB` (`budgetSource`, `:1083`).
- A Windows run therefore shows the host heap's budget, its usage and the live imports both at the first moment the report would bite and while refusals happen.

**Debt entry:** the "Host import windows and budget" entry in `docs/dev/debt/libSceAgcDriver.md` now describes both rules, the print, and the feedback described in section 2.

## 2. Why the report is low: what F3 subtracts, and whether it double-counts

**What F3 computes** (`HostImportBudgetFor`, unchanged):
- import room = host heap budget − (heap usage − min(heap usage, live imports)) − budget/8, rounded down to 64 MiB;
- the host heap is the largest heap without `DEVICE_LOCAL`.

**What the spec says the numbers are** (`VK_EXT_memory_budget`):
- `heapUsage` is "an estimate of how much memory the process is currently using in that heap".
- `heapBudget` is "a rough estimate of how much memory the process can allocate from that heap before allocations may fail or cause performance degradation".
- So the budget is an estimate for all the process's allocations, not the point at which imports fail. On the PC, 6400 MiB of imports ran clean, and failures began at 6864 MiB. In the run that refused 85,047 imports, the report allowed 4480 MiB with 3752 MiB live.

**What the code puts into "others"** (the heap usage that is not live imports):
1. **The copies that stand in for refused imports.**
   - A region that is not imported is copied into a `Buffer` with `copyBufferProperties(false)`, which is `HOST_VISIBLE | HOST_COHERENT` (`Graphics/src/GuestBufferMemory.cpp:3509`, used at `:3762` and `:4151`).
   - `Context::BufferMemoryType` (`Graphics/include/Context.hpp:264`) places such buffers in a host-cached type first. On a discrete NVIDIA GPU that is the system heap, the one F3 reads.
   - The buffer pool keeps freed buffers in its retention tiers, so they stay counted.
2. **Heap mirrors.**
   - An address-based build over a heap it cannot import mirrors the heap into a `Buffer` with the default host-visible coherent properties (`:2044`).
   - Their own limit is `APS5_HEAP_MIRROR_MIB`, 24 GiB by default (`:1590`). They land in the same heap.
3. **Device-local allocations moved into a host heap.** `Context::DeviceMemoryType` (`Context.hpp:291`) does this when the device-local heap is over its reported budget.
   - In the run's texture-cache line, the device-local heap used 3367 of 7250 MiB, so this was not active then.
4. **Staging, readback and snapshot buffers**, plus whatever the driver and other APIs in the process hold there.

**Conclusion:** not a double count of memory at any one instant, but a feedback.
- Items 1 and 2 exist because imports were refused. F3 re-reads the report every second.
- So each refusal adds a copy or a mirror to "others", which lowers the next budget, which refuses more.
- The guest bytes are charged as a stand-in copy, and that copy is then held against the import that would replace it. Making the import would not free the pooled copy or the mirror at once, though.
- I can show this mechanism from the code. I cannot show from the code or the documentation that the formula counts any memory twice, and the size of each part needs the Windows numbers. **So the formula is unchanged, as GAC-041 says, and rules 1 and 2 are the fix.**
- Rule 2 means the feedback can only start after a real `vkAllocateMemory` failure. Rule 1 means it never applies to a set budget.

**What the PC run will show:**
- The new lines give B, U and L, so `others = U − L`.
- The existing `[bufferpool]` line (`APS5_PROFILE_DRAW`) gives the pool's retained bytes, and the heap-mirror lines give the mirrors' holdings. Together they show how much of `others` is AnyPS5's own stand-ins.
- If most of it is, a follow-up could subtract those stand-ins from `others`. That is not done here.

## 3. Tests (`tests/BdaResources.cpp`, run inside `agc_driver_graphics`)

**New: `importReportFloorTests(context, access, set)` (`:1200`).**
- The mock context is given a 16 GiB host heap. A fake `vkGetPhysicalDeviceMemoryProperties2` reports that heap at 8 MiB budget and 8 MiB usage, which leaves imports no room.
- Each run uses a fresh fake physical device, so the report is read again.
- Steps:
  1. Three imports must be made.
  2. A mock `vkAllocateMemory` failure follows. It is isolated, far below the budget, so it sets no ceiling.
  3. Then:
     - a set budget (64 × 64 KiB) still makes the next import;
     - the default budget refuses it, because the report now applies.
- **#6479's head, red** (the test added alone, before the fix):
  - set case: `AGC graphics: a set import budget was lowered below 1 imports by a host heap report that leaves imports no room, before any vkAllocateMemory failure`;
  - default case, run with the two calls swapped to reach it: `AGC graphics: the default import budget was lowered below 1 imports by a host heap report that leaves imports no room, before any vkAllocateMemory failure`.
- **With the fix, green.** Both cases pass, and both print the new line:
  - `... leaves imports 0 MiB of the 4 MiB APS5_HOST_IMPORT_MIB sets; the setting stays, as the report never lowers it`;
  - `... of the 8046 MiB of the default; the default stays until an import's vkAllocateMemory fails`;
  - after the failure, `...; imports are held to it since an import's vkAllocateMemory failed`.

**Extended: `importDeviceBudgetTests` (`:1098`)** gains eight cases for `HostImportBudgetWith`, with Resident Evil Village's numbers:
- a set 6400 MiB against a 4480 MiB report stays 6400, before and after a failure, and drops to a 3752 MiB ceiling;
- a default of 5888 MiB stays 5888 before a failure and becomes 4480 after one;
- a report above the default does not raise it, and no report leaves it alone;
- a 3000 MiB ceiling holds below the report.
- These are new API, so they are not red on #6479's head; they compile only with the fix.
- The function's existing `HostImportBudgetFor` cases still pass unchanged.

**"After a near-budget failure, the cap lowers":** #6479's own `importCeilingTests(..., true)` runs on a set budget and still passes. The default-budget case of the new test covers a failure making the cap apply.
