2. **The test drives the subscription through GuestMemory's public API, not through a draw.**

   - The case runs the maintainer's sequence step by step on a real subscription. Its check is on `SubscriptionBumpsSince`, the call whose `false` makes the next proof fall back (ShaderResources.cpp:3898).
   - No hook was added.
3. **Ask 2's premise doesn't hold at this head: `agc_driver_table_index_validation` is already registered.**
   - The default execution-test loop registers it (`CMakeLists.txt:636-642`, Test #1242, all 10 cases, `SKIP_RETURN_CODE 77`).
   - A fragment with `add_test(NAME agc_driver_table_index_validation …)` fails the configure: `add_test given test NAME "agc_driver_table_index_validation" which already exists in this directory`.

4. **Open question: a finer overflow marker** (§7.1). With the asked-for fix, an overflowed subscription keeps falling back while any bump lands in each proof window, even one that is now recorded. Marking the *latest* unrecorded bump clears it as soon as nothing newer than the baseline was lost. It touches the bump path, so I describe it here and did not commit it.

## 3. Why the case doesn't go through a draw

My first version was scene-level:
1. Settle a scene.
2. Overflow its subscription with alternating `NoteGpuPending` bumps.
3. CPU-write the sampled texture.
4. Expect the second draw to fall back.

It was red on **both** the head and the fix. A temporary local trace of every bump, baseline read and trim (not committed) showed why:

```
fill / draw 1:
bump  source=cpu      gen=1028  (unrecorded, marker at 1027)
baseline 1028                                  <- ShaderResources.cpp:4105
bump  source=release  gen=1029  (unrecorded)   <- the full proof replaces the written texture
subscribeIndex                                 <- the proof failed: rebuild, new subscription; no trim on the old one
draw 1: fallback 1, builds 1
draw 2: trim at=1 now=1 (new subscription)  -> accepted
```

- **The bump does land in the window, but the trim never runs.** When anything bound to the subscription changes, the fallback's proof fails, the object is rebuilt, and `build()` resubscribes (:1763 → :3739-3741). The overflowed subscription is dropped before its trim.
- **A GPU store hits the same path.** I tried a pending storage write over the sampled texture and over another table element: baseline 1044, Release bump 1045, rebuild.
- **When nothing changes, nothing bumps between :4105 and :4233.**

So the window can only be hit by another thread's store (a write-watch fault, a driver store, or the GPU-completion pending mark) while the proof runs, and no ordering in the code can force that deterministically. A hook would have to sit in `Revalidate`, which is non-test code. Calling GuestMemory directly reaches the exact state the race leaves, without one.

## 7. Open questions

### 7.1 A finer overflow marker

- **What the asked-for fix does:** it keeps the marker whenever *any* bump follows the baseline. After the first such trim the history has room again, so later bumps are recorded. Even so, the marker only clears at a trim whose proof window saw no bump at all.
- **When that matters:** a subscription whose 64 KiB blocks take steady writes from another thread that don't change what the draw reads. Examples are CPU data sharing a block with a texture, or completion-side pending marks. Such a subscription can keep taking the full proof on every draw.
- **The alternative:** record the *latest* unrecorded generation, not the first. A trim at B then clears the marker exactly when no lost bump is newer than B.
- **Lines it touches:** the bump path `GuestMemory.cpp:170-173` and the trim `:257-261`. The `overflows` count stays one per overflow.
- **Why it's correct:** after `trim(B)` clears, every unrecorded bump is at or before B, and recorded bumps after B are kept. So `SubscriptionBumpsSince(B)` is complete.

**Local experiment, not committed or pushed.** I added a temporary case:
1. overflow;
2. window 1: baseline, bump block 2 (unrecorded), trim;
3. window 2: baseline, bump block 2 (now recorded), trim;
4. ask the next proof.

| trim | after window 1 | after window 2 |
|---|---|---|
| committed fix (2537d44452) | falls back | **falls back**, 0 blocks |
| finer marker | falls back | **partial, 1 block (block 2)** |

With the finer marker applied, all 11 cases still pass, `overflow` included.

**Decision needed:** keep the maintainer's version (as committed), or switch to the finer marker as a follow-up commit.

### 7.2 Keep the fragment?

`main()` already sets `APS5_TABLE_INDEX=1` before the write index's static read, so the property is redundant at run time. It records the mode in the registration, as the maintainer asked. If they would rather not have it, commit 2 reduces to the 77 return.

### 7.3 CI and the new skip

On Linux CI, a skip with this reason is not a device limitation to `check_skips.py`, so it would fail the job. That is intended: the job would otherwise lose the coverage silently.

Main's own `skipped, guest memory has no write watch` tests are `DepthPlaneGuestLayers` and `PartiallyResidentSnapshot`. Their CI passes, so the Linux runner has a write watch. The Windows job allows `agc*` skips, and it builds this test as the `ANYPS5_AGC_EXECUTION_TESTS` stub anyway.
