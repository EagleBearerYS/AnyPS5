# BF-336: GTA V's collect refusals on `comparedWhenShared` pages (read-only design)

worker: cloud-3, 2026-10-31. Read on `upstream/main` **50a261e7e4** (2026-10-31 04:09 +0100) and #12921's head 23ef222060. Paths are under `core/libs/`. Nothing was built or pushed except this file.

## Answer first

**There is no exact, fault-free way to prove a writable shared page unchanged on Windows.**
- **Fault-based tracking already exists on main for shared pages.** That is option (b), and it is exact across every alias. `comparedWhenShared` exists precisely to switch it off for these pages: a resumed write fault in guest code overwrites the guest's red zone on Windows (#361), and that crashed GTA V's open world (#9136).
- **Windows write watch cannot cover a section view (a).** A shared generation (c) misses guest CPU stores.

**Two things are exact and worth doing:**
1. **Make the fallback cheap (d2, below).** Prove a refused surface by comparing its bytes inside the fast proof, instead of failing the whole template into the full walk. Compare only the marked pages; the rest of the range can still be collected.
2. **Prove pages that no guest alias can write by generation, without arming (d1).** How much of GTA V this covers is unknown, and the PC can count it.

**On Linux, #12452 (Tehshortbus, open) is the exact fix for the same shape.** It collects aliased direct memory through every alias with `PAGEMAP_SCAN`, and its message names GTA V. Windows has no equivalent primitive.

## 1. The mechanism on main

### Where a page becomes `comparedWhenShared`

**Marking.** `WindowsMappings::CompareWhenShared` (`prx/libc/include/WindowsMappings.hpp:263-285`) sets `comparedWhenShared` on each page of a range, on its `Physical` slot and its `SharedPage`. It disarms any alias that is already armed: it restores the view's protection with `protectSubpages`, "stop arming a compared shared page", `:281`.

**Callers.**
- **Through `GuestArenaCompareWhenShared`** (`prx/libc/src/GuestArena.cpp:600-602`): **`GuestMemory::Rewatch`** (`prx/libSceAgcDriver/Execution/src/GuestMemory.cpp:1818-1844`, the call is at `:1829`). It marks every range it returns to the write watch. `Rewatch` is called for:
  - **host imports whose deferred settle completed:** `rewatchSettledImports`, `Graphics/src/GuestBufferMemory.cpp:1196`;
  - **retired imports:** `rewatchRetired`, `GuestBufferMemory.cpp:1676`.
- **Through `GuestArenaCompareResidentWhenShared`** (`GuestArena.cpp:604-606`): `GuestMemory::ImportWatched`, for each span that stays watched after a host import (`GuestMemory.cpp:1916`).
- **Who added them:** our #9159 (98adb5f205, d98ee15162, 10-21) and 81aec58343. They put back what main did before #6678, comparing such memory instead of arming it.

**The sharing event.** The mark costs nothing while the memory is a resident (private-backed) run, because `GetWriteWatch` collects it without faults. It bites when the same direct memory gets a second mapping:
- **A second `WindowsMappings::Map` of the same section offset:** this demotes the resident run (`demote`, `:178` and `:198`) into `MapViewOfFile3` views. Each new view inherits the slot's flag (`:128-136`, `:165`) and is created with `unreported = allSubpages` (`:188`, `:217`).
- **`MapAlias`:** this demotes resident pages for a read-write host alias (`:420-423`).

**Why it then stops being write-watched.** On Windows, shared views are tracked by arming. A clearing `Collect` makes **every alias** of a settled subpage read-only (`:576-590`, "arm shared memory write tracking"). A guest store then faults, `HandleWrite` (`:306-321`) bumps the page's generation and restores write access, and the store is resumed. Commit 98adb5f205 states the reason this must not happen for these pages: the resumed fault can overwrite `[rsp-0x80, rsp-0x10)`, the guest's red zone (#361). For pages GTA V stores into, that crashed its inflate_fast every run (#9136).

### What `collectable` and `GuestArenaCollectWrites` refuse

`GuestArenaCollectWrites` (`GuestArena.cpp`) goes to `WindowsMappings::Collect` (`:481-641`).
- **With `clear`:** it first calls `collectable` (`:644-661`), which refuses the **whole** requested range if any 16 KiB view in it is:
  - `PAGE_NOACCESS`;
  - a resident run while `watchResident` is off;
  - **a shared view whose page is `comparedWhenShared`** (`:651`);
  - or if part of the range is neither a view nor a private allocation (`:655-656`).
- **The fresh pre-check** refuses `comparedWhenShared` the same way (`:494`).

So a range with one marked page refuses everything in it. That is the 1,469 mixed ranges in chitters' sample.

### What a refused collect falls back to, for a sampled snapshot

**In the fast proof (`Graphics/src/ShaderResources.cpp`):**
- `fastRevalidate` calls `GuestMemory::CollectWrites` per sampled surface (`:3225`). On 0 it counts the refusal (`:3227`) and fails with `FastFail::Collect` (`:3228`), which **fails the whole template's fast proof**.
- `revalidateFull` (`:3590`) then re-resolves every resource of the template.

**Inside `CollectWrites` (`GuestMemory.cpp:1571-1642`), for a refused range:**
1. It takes the tracker lock (`:1604`).
2. `walkWrites` (`:1553-1569`) bumps `tracker.generation` (`:1554`). `collectWindowsWrites` (`:1508-1533`) calls the arena collect, which takes the `WindowsMappings` mutex, walks the views and refuses.
3. `noteRefusedWalk` (`:1535-1550`) makes two more locked view walks:
   - `TakeUnreportedPages` stamps the pages not yet reported;
   - `ComparedPages` lists every marked 4 KiB subpage and sets `tracker.refused[block] = generation`.
4. It returns 0 (`:1627`).
5. **`refused` makes `UnchangedSince` false over those blocks for any older generation** (`rangeUnchanged`, `:1302-1313`). So every later proof over them refuses too.

**In the full walk, the snapshot's hit path in `cachedTexture` (`ShaderResources.cpp:958-985`):**
1. **`unchanged()` is false** because of `refusedSince`.
2. **`kept()` is false:** `untrackedKey` (`:671-677`) calls `UntrackedHint` (`GuestMemory.cpp:2177-2206`), whose `walkHints` (`:2153-2175`) refuses on the same pages. This is #12921's hint failing, as chitters saw.
3. **That leaves `equalsCommitted()`:** `GuestMemory::EqualsCommitted` (`GuestMemory.cpp:2783-2797`). It calls `FlushGpuWrites`, which waits for recorded work over the surface, then memcmps the whole surface against the retained CPU copy (`it->bytes`).
4. **If the bytes differ,** the snapshot is uploaded again.

**Cost per refusal, as a formula.** Write S for the surface bytes, P₁₆ = S / 16 KiB views, P₄ = S / 4 KiB subpages, and V for the views in the arena.

> **T ≈ W + 3·P₁₆·log V + c·P₄ + S / B**

| term | what it is |
| --- | --- |
| W | the full walk of the whole template, every resource re-resolved; independent of S |
| 3·P₁₆·log V | three view-map walks under the `WindowsMappings` mutex: the refused `Collect`, `TakeUnreportedPages` and `ComparedPages`. A refused `walkHints` adds a fourth when the range has a hint. |
| c·P₄ | the `refused`-map writes, one per 64 KiB block |
| S / B | the memcmp; B is the compare throughput with both buffers from DRAM. **5–10 GB/s is my assumption, not measured.** |

**Locks per refusal:**
- the tracker lock, twice (`CollectWrites`, `UntrackedHint`);
- the `WindowsMappings` mutex, three or four times;
- the texture cache lock in the walk.

**Other costs:**
- **The fast proof records the first refusal only.** It stops at the first failing surface, but the full walk compares every refused snapshot of the template.
- **The global generation is bumped once per refused walk.**

### Linux and macOS

**Linux** has the same limitation by a different route.
- **Why aliases are unregistered:** its write watch uses userfaultfd asynchronous write protection plus `PAGEMAP_SCAN` (`prx/libc/src/GuestWriteWatch.cpp:46-325`), which sees a write only through the mapping that made it.
- **The consequence:** `WatchMapping` (`prx/libkernel/DirectMemory/DirectMemory.cpp:647-664`) **unregisters both** ranges of any two direct mappings that share physical pages. Collects there refuse and the memory is compared.
- **No faults reach user space**, so there is no red-zone issue. The Linux kernel also skips 128 bytes below `rsp` when it builds a signal frame.

**macOS** never registers direct-memory mappings with the write watch. `WatchMapping` and its call (`DirectMemory.cpp:741-742`) are Linux-only, so direct memory is always compared there. Its fault-based watch (`GuestWriteWatch.cpp:329-692`) would be red-zone safe, because xnu also skips the 128-byte red zone.

## 2. The exact options

| option | exact? | cost | failure modes and verdict |
| --- | --- | --- | --- |
| **(a) Windows write watch on shared views** | — | — | **Not available.** `MEM_WRITE_WATCH` is a `VirtualAlloc` allocation type for private memory. The code uses it only when it replaces a placeholder with private memory (`Commit`, `WindowsMappings.hpp:50`, `:55`). Section views come from `MapViewOfFile3` (`mapShared`, `mapRun`), which is documented to take only placeholder, reserve and large-page allocation types; `GetWriteWatch` applies only to `MEM_WRITE_WATCH` allocations. `Collect` reflects this: it calls `GetWriteWatch` only on `privateAllocations` and treats any non-`MEM_PRIVATE` region as a refusal (`:628-632`). Windows exposes no user-mode dirty-bit query for mapped pages; `QueryWorkingSetEx` has none. |
| **(b) Protection-based tracking of shared pages** | **Yes, already on main** | a fault (exception dispatch, the `WindowsMappings` mutex, `VirtualProtect`) per first store into an armed subpage per collect interval, plus one re-protect per alias run at each clearing collect. `VirtualProtect` on a multi-threaded process flushes other cores' TLBs. | **Unsafe for these pages** (see below). `#13293` is not a production fault mode. |
| **(c) A per-page generation bumped by our own writers** | **No** | — | Misses guest CPU stores (see below). |
| **(d) Other ideas** | see below | | |

**More on (b).**
- **What already exists:** `Collect` arms every alias in `page.aliases`, not only the faulting view (`:578-590`). `HandleWrite` bumps the `SharedPage` generation that every alias reads (`:316-319`). Host writes go through `BeginHostWrite` and `EndHostWrite` (`:351-385`), which invalidate and open the armed subpages.
- **Why it is unsafe here:** that is exactly what `comparedWhenShared` turns off. Windows builds the exception frame on the faulting thread's stack, below `rsp`, with no red zone, and user mode cannot redirect that. Re-enabling it is safe only if every guest function that can store into these pages keeps nothing live below `rsp`.
- **What the relinker does about the red zone today:** it rewrites red-zone leaves it recognises (e0ba27fc60, #10999) and refuses some shapes (de3c2d9536). It does not prove that an arbitrary store site is safe.
- **It is also costly for pages written every frame:** for a 1 MiB surface written in full, 256 faults per interval at a few µs each cost more than one memcmp. That is why main stopped write-protecting resident runs (d6e270ea9f, #7473).
- **`#13293`:** it only removes a duplicate CMake registration of the `write_watch` `execute-fault` and `read-fault` test modes (75b97c359a). It adds nothing Windows could use for these pages.

**More on (c).**
- **What it would catch:** only writes through code we control: `BeginHostWrite`/`EndHostWrite`, imports, recorded GPU writes, `SetProtection`, `Map`.
- **What it misses:** guest CPU stores through any writable alias, which are the writers that matter here.
- **When it would be exact:** only for pages no guest alias can write, which is (d1).

**(d) Other options:**
- **(d1) Every alias read-only: exact.**
  - **Why:** if no view of the page has a writable protection, a guest store has to change protection first, and both `SetProtection` (`:224-232`) and `Map` invalidate the page. Host and import writes are bracketed. GPU writes are recorded by the recorder, which `untrackedKey` already reads.
  - **How it would work:** such a page can be proven by `SharedPage::generation` without arming.
  - **Failure modes:**
    - a read-write `MapAlias` (`:403-446`) held for an import: it must count as a writable alias, or bracket its writes as host writes;
    - protection changes made outside `WindowsMappings`.
  - **Scope:** unknown for GTA V. The PC can count, per refused surface, whether any alias is writable.
- **(d2) Compare in place, only the marked pages: exact, because a byte compare is exact.**
  - **The fast proof:** a surface whose collect refuses only on `comparedWhenShared` pages (`ComparedPages` already lists them) is checked with `EqualsCommitted` over those pages. Its unmarked pages are still collected (`collectable` per sub-range instead of the whole range). The rest of the template keeps the fast proof.
  - **What it needs, the same as the full walk's compare path:** the same flush and pending-write rules (`FlushGpuWrites`, `Recorder::SnapshotWriteOverlaps`), and the same committed-range handling.
  - **What it saves:** W per refusal, and the compare of unmarked pages in mixed ranges.
  - **What it does not save:** the memcmp of the marked pages.
- **(d3) "Keep one alias armed and write through it": no.** The guest picks the alias it stores through; we cannot redirect its stores.
- **(d4) Hash instead of compare: no saving.** Hashing reads all the bytes too.
- **(d5) Make the pages private again: no.** Two guest mappings of one direct memory must stay coherent.

## 4. The saving, as a model

At N ≈ 21,000 refusals per 10 s, about 2,100 per second, committer time per 10 s is **N × T**, from item 1.

**The compare term alone (N × S / B, B = 5–10 GB/s assumed):**

| S per refused surface | memcmp each | per 10 s | share of one core |
| --- | --- | --- | --- |
| 64 KiB | 7–13 µs | 0.14–0.28 s | 1.4–2.8 % |
| 256 KiB | 26–52 µs | 0.55–1.1 s | 5.5–11 % |
| 1 MiB | 105–210 µs | 2.2–4.4 s | 22–44 % |
| 4 MiB | 0.42–0.84 ms | 8.8–17.6 s | more than one core |

The last row cannot happen on one committer thread, so GTA V's refused surfaces must be smaller on average, or their compares spread over threads.

**The other terms.** N × W adds the whole-template walk per refusal. W comes from the `[rescache]` "full walk ms by reason: collect" field, which this title's posted lines would show. The map walks are O(P₁₆) map lookups under a mutex, small next to the memcmp for large S.

**What the options would cost instead:**
- **(d2):** N × (S_marked / B), plus a few map walks. It saves N × W, plus the compare of unmarked bytes in mixed ranges.
- **(d1)**, for qualifying pages: O(P₁₆) generation reads; no compare and no walk.
- **(b)**, if the red zone were not an issue: for unchanged pages, about O(P₁₆) like (d1). For a page written every frame, faults × aliases × (2–10 µs dispatch, mutex, `VirtualProtect`, cross-core TLB flush), plus one re-protect per alias run per collect. That loses to a memcmp as soon as most subpages are written each frame.

## 5. Test plan for the best option, (d2)

**Platforms:** Windows for `comparedWhenShared`. The same in-place compare applies to any refused collect, so it also covers Linux aliased memory until #12452 lands, and macOS direct memory.

**Fixtures already on main:**
- `windows_write_watch` `CheckComparedWhenShared` and `CheckComparedPagesReportedOnce` (`core/libs/tests/WindowsWriteWatch.cpp:564-706`);
- `agc_rewatched_direct_shared` (d98ee15162, `tests/Recorder.cpp` ~3258), which maps direct memory resident, rewatches it, then maps it a second time.

**The cases:**

1. **Red on main, unchanged:** a sampled template over a marked, shared direct-memory surface; prove it in one collect epoch, then again in a new epoch with the bytes unchanged.
   - **Today:** `CollectRefusalCounts().sampled` +1, `FastFail::Collect`, `ProofPath::Full`.
   - **With (d2):** `ProofPath::Fast`, one in-place compare counted, no full walk.
2. **Correctness, a write through the other alias:** between proofs, store through the second mapping, and separately through a `MapAlias` alias. The proof must not pass fast, and the texels must be refreshed. This is red if the compare were skipped, and must be green with (d2).
3. **Mixed range:** a surface over one marked and one unmarked page. Only the marked page is compared, counted by bytes. A store into the unmarked page is caught by the collect.
4. **Pending GPU write over the surface:** a recorded write must be flushed or waited before the compare, as `equalsCommitted` does today.
5. **(d1)**, if taken up: a page whose every alias is read-only is proven without a compare. Then `SetProtection` to writable followed by a store must not be proven.

**In a title** (GTA V Story, Windows, `APS5_PROFILE_DRAW`):
- `collect refusals` stays at about 21,000 per 10 s, because the pages are still refused;
- "full by reason: collect" and "full walk ms by reason: collect" should fall towards 0;
- a new count of in-place compares, with their bytes, should match the refusals;
- frame time on the committer should move by about N × W.

**The PC's first measurement is in-title,** and no code exists for it yet: per refused surface, its size S, and whether any alias is writable. That decides (d2) against (d1) and gives the real saving.

## Recommendation

**Do not re-enable arming for these pages (b) on Windows.** The red-zone hazard has no general fix on Windows.

**Take (d2) as the exact cut:** compare the marked pages in place inside the fast proof, collect the rest, and keep the template's fast path. Measure S and the full-walk time per refusal on GTA V first, so the gain is known. Then consider (d1) if the count shows many refused pages without a writable alias.

**For Linux, #12452 already covers the aliased case exactly.**
