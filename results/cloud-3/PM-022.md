## 0. Bottom line

**The Bug Finder's chain is right, with two corrections.**

1. **Why CollectWrites returns 0.** `tracker.covers` fails because some 64 KiB blocks of the heap were taken off the write watch earlier and never put back.
   - On Windows every direct host import of private memory takes its range off the watch. One window import of the heap is enough: a fill, a GPU label, a copy, a sample dump, or a buffer access outside an address-based build.
   - Retiring that import doesn't put the blocks back.
   - So from then on, the heap can't be mirrored again for the rest of the session.
2. **Why it's 1 in 3.** The watch check runs only when a heap mirror is **created** (1749-1757). An existing mirror is reused without it (1720-1726).
   - So the abort needs a window import of the heap **before** the first address-based build that had to mirror it.
   - In the runs that went on, the mirror was made first.

**The runs that go on carry a related failure.**
- Suppose a window import of the heap comes after its mirror exists, at a build where the whole import still doesn't fit.
- The next address-based build then throws `AGC graphics: a heap mirror's range is no longer write-watched` (1556, or 1693 through the address-space cache).
- That is a driver failure rather than the copy-cap abort, but it has the same root. Experiment C (§2.3) reproduces it.

**The copy reason string misleads.** "outside the write-watched arena" (2643) is printed for every heap the mirror refused, whatever the cause. Here the heap is inside the arena and only partly off the watch.

**The red test:** `agc_address_copy_cap` aborts with the same two lines every time: 10 of 10 runs on 2f1597bde and 5 of 5 on eea428ca8.

**The fixes, ranked:**
1. Let the address-based pass evict, at least as the last resort before the copy cap aborts. Also drop a reused heap mirror whose range left the watch, instead of throwing.
2. On Windows, put a range back on the watch once the import that took it off is freed. #4448 does this on Linux only.
3. Mirror a heap that is partly off the watch by comparing those blocks.
4. Refuse the build without aborting. The draw is then skipped.
5. Raise the cap.

Experiment A (`evict = true` at 2610) turns the red test green and keeps all of `agc_driver_graphics` green.

**Overlaps:**
- None of the listed PRs, nor any other PR touching these paths, changes:
  - the import without eviction (2610);
  - the mirror refusal (1753-1757);
  - the throw on a reused mirror (1556, 1693);
  - the abort (2652-2656).
- #6060 and #5851 remove the main Windows trigger on some setups.

## 1. The chain, with file:line

### 1.1 Where a range goes in an address-based build

`GuestBufferMemory::AcquireRegistered` (2508) walks the leased registry once, in address order (loop at 2602-2645). It skips ranges that aren't readable or GPU-visible (2603). Each remaining range goes through four steps.

**a. Import (2606-2620).**
- Tried when `importable` is set (`context.hostImportAlignment != 0`, 2520), through `importAllocation(context, state, range->address, lease, 0, false)` (2610). The last argument is `evict = false`.
- **It's a hit** when a live import covers the whole run (918-920). A window import over the first byte doesn't count; it would be replaced (comment at 916-917).
- **Otherwise `importRunAt` (935) returns null when:**
  - the run is misaligned (945), or a failure for the same run is remembered (946-949);
  - an import overlapping the run, such as a window of it, is held by this build (958-961). This refusal prints nothing;
  - **it's over the budget:** `live + bytes > budget` (963-965).
    - `live` is `liveBytes` minus the overlapping imports it would replace (954-962). With `evict` false nothing else is subtracted.
    - This prints the `[gpu] host import budget` line (at most once per 10 s, 967-974).
    - The refusal isn't remembered (975), so every build retries;
  - on Windows, a page isn't committed or accessible (993-996), or the memory is read-only (1005-1008);
  - creating the import fails (1056-1061; remembered).

**Village's budget line is the budget case:**
- 5080 + 768 = 5848 MiB against a 5840 MiB budget: 8 MiB over.
- Any live window of the heap would have counted as replaced, and then the import fits. Windows are at least 64 MiB (`windowRun`, 867-893; `rangeImportWindow` is 64 MiB, 862).
- So at that refusal no window of the heap was live. Any windows the heap ever had had already retired.
- The idle imports that eviction could have freed were never considered, because `evict` is false (965). `evictable` is at 810-813.

**b. Mirror (2621-2635).**
- Tried when `mirrorsEnabled()` is true (APS5_NO_LEASE_MIRROR unset), through `acquireMirror(context, range, blocks, range->releasable)` (2622). Heaps are the releasable ranges.
- **Reuse:** an existing entry for the same Range object, size, writability and heap flag (1718) is returned as is (1720-1726). **There is no watch check here.**
- **Otherwise it returns null when:**
  - a mirror failure for the range is remembered (1716);
  - the range isn't accessible and isn't a sparse heap (1728-1732);
  - **the range is a heap and `GuestMemory::CollectWrites` over the whole range returns 0** (1749). It counts `++heapUnwatched` and returns null (1753-1757). The sparse-heap version is at 1746;
  - allocating a non-heap mirror's buffer fails (1765-1770).
- Exceeding the heap-mirror budget, or failing to allocate a heap mirror's buffer, throws instead (1758-1761, 1766).

**c. Copy (2636-2644).**
- Everything else is copied on every build (`addCopiedRange`, 2636).
- The reason (2643) is "outside the write-watched arena" for any releasable range.

**d. Abort (2648-2656).**
- The committed bytes of all copies are summed (`AddressCopyOverflow`, 2117-2131).
- If the sum exceeds `APS5_ADDRESS_COPY_MAX_MIB` (default 64, read once per process, 2648-2651), the build prints FATAL and calls `std::abort()` (2652-2656).

### 1.2 Why CollectWrites returns 0 for the heap

`collectWrites` (GuestMemory.cpp:1143; the public `CollectWrites` is at 1203) returns 0 when:
- the size is 0 or overflows (1144);
- the tracker isn't watching at all (1170);
- **`!tracker.covers(address, bytes)` (1170):**
  - on Windows, `coverage.Covers` fails if any 64 KiB block of the range is excluded, or if the range overlaps an arena host region (823-825);
  - on Linux, `GuestWriteWatchCovers` fails if any part of the range isn't registered (827);
- the page walk fails (1191).

For a committed, accessible heap inside the arena, the coverage case is the one that applies.

**Where blocks are taken off the watch.** Only `unwatchLocked` does it (GuestMemory.cpp:1240-1248: `coverage.Exclude` on Windows, `GuestWriteWatchUnregister` on Linux). It is called from:
- **`ImportWatched`, for an import that doesn't stay watched** (GuestMemory.cpp:1309-1313).
  - That is every direct Windows import that has no section alias.
  - `unwatchImports` is always true on Windows (646), so `watchedHostPointer = entry.alias != nullptr || !state.unwatchImports` (1037) is false.
  - On Linux it depends on the import probe (650-671).
- `refreshImports`, which re-applies it for live imports that are off the watch (1142);
- `ImportWatched` again, when the page walk fails for an import that stays watched (GuestMemory.cpp:1315);
- `MarkWritten`, when its collect is incomplete (GuestMemory.cpp:1446-1447).

**Nothing puts the blocks back when the import goes away.**
- `retireImport` (230-242) makes no watch call.
- `coverage.Restore` runs only from `watchPrivateMapping` (GuestMemory.cpp:1030-1042). The arena calls that only for mappings that a fresh `GuestArenaCommit` creates (GuestArena.cpp:390-397).
- So on Windows, once any import of the heap has existed (a window or the whole range), the heap can't be mirrored again until its memory is decommitted and committed again.

**What makes window imports of a heap.** Anything that calls `HostImportFor` (2392-2408), or `importAccess` with an end (1166-1170):
- `Execution/src/VulkanDevice.cpp`:
  - GPU labels: 1974;
  - sample dumps: 2036;
  - `FillBuffer`: 2056 and 2110;
  - `CopyBuffer`: 2422-2423;
  - indirect dispatch arguments: 4164.
- `Graphics/src/Draw.cpp`:
  - `materializeCmaskClear`: 274;
  - `InPlaceDrawInput`: 936;
  - `captureInputs`: 1675.
- `Upload`'s per-region import for buffers that an address-based build doesn't serve: 3509.

None of these checks for a heap mirror first.

### 1.3 The 1 in 3

**The run that aborts:**
1. A window import of the heap, through any path above, happens before the first address-based build that has to mirror the heap.
2. That window retires before the build: evicted at 982, replaced, or dropped on a registry change.
3. The build can't import the whole heap within the budget, can't mirror it (1749-1757), copies 768 MiB and aborts.

**The runs that go on:**
- The first such build comes before any window import, so the mirror is created (CollectWrites is nonzero). Later builds reuse it without a check (1720-1726).
- Those runs stay safe as long as either:
  - no window import of the heap follows; or
  - every later build can import the heap whole. A successful whole import releases the mirror (`releaseImportedMirrors`, called at 2646, defined at 1838-1853).
- Otherwise the next build throws at 1556, or at 1693 through the address-space cache.

**A later abort in the same session:**
- On Windows a successful whole import takes the whole heap off the watch too (GuestMemory.cpp:1309-1313).
- If that import is later evicted and the budget is tight again, the next build aborts the same way.
- This path is less likely, but it has the same root.

## 2. The red test

### 2.1 What it does

`RunAddressCopyCapTests` (`tests/BdaResources.cpp`) runs as `agc_driver_graphics_tests --address-copy-cap` (`tests/Graphics.cpp`) with `APS5_ADDRESS_COPY_MAX_MIB=1`. Its ctest name is `agc_address_copy_cap`.

It recreates Village's state at a smaller scale:

| | Village | test |
|---|---|---|
| heap (one registered range) | 768 MiB | 2 MiB (32 blocks of 64 KiB) |
| live imports before the build | 5080 MiB | 1 MiB idle + 64 KiB busy |
| import budget | 5840 MiB | 3 MiB (`SetHostImportBudget`) |
| amount over | 8 MiB | 64 KiB (fits if the idle import is evicted) |
| heap blocks off the watch | some | 1 (`GuestMemory::Unwatch`) |
| copy cap | 64 MiB | 1 MiB |

What the test does:
1. Map and register three ranges.
   - On Linux: `mmap`, plus `GuestWriteWatchRegister` for the heap.
   - On Windows: the guest arena.
2. Import the idle and busy ranges.
3. Use the busy range 300 times. Past 256 lookups the idle import becomes evictable; the busy one stays protected.
4. Take one block in the middle of the heap off the watch.
5. Run one address-based build.

To pass:
- the heap must be in the BDA table, either imported or mirrored;
- if it's mirrored, the mirror must hold the guest bytes of the block that was taken off the watch.

Notes:
- The test takes the block off the watch directly, not through an import. So it stays red with #6060, #5851 and #4448 applied (§4).
- It turns green under a fix at the import step (eviction) or at the mirror step (mirroring a heap that's partly off the watch).
- It stays red, by design, under:
  - option 4 (skip the draw);
  - option 2 on its own (put blocks back on the watch when an import retires).
- Option 2 needs its own test: import a window of the heap, retire it, then build.
- On a host without the write watch, the test prints a skip line and passes, like the file's other watch tests.

## 3. Fix options, ranked

### 1. Let the address-based pass evict (recommended first)

**What:**
- The smallest form is `evict = true` at 2610.
- A narrower form retries with eviction only when both the import and the mirror were refused and the copy would exceed the cap.
- With either form, also change `acquireMirror`'s reuse path (1720-1726): a heap mirror whose range is no longer `GuestMemory::Watched` is dropped and treated as refused, so the build tries the import instead of throwing at 1556 or 1693.

**Why it's safe:**
- The no-eviction rule came in with e9249a0a4. Its message explains it for imports made at map time only ("the map observer holds no GPU lock", 2434), not for this pass.
- The pass already protects the imports it uses. Imports looked up or made in this build count as held (`pointerHeld`, 806-808; new imports are stamped at 1092), so they're never evicted.
- Every refusal is decided before anything is retired (963-976 come before 977-982).
- A retire moves the epoch (235). `Upload` then re-checks every import it was handed (3504), and retired imports live on through the hold (240).
- Experiment A keeps the suite green.

**Risks:**
- **Churn.** A 768 MiB import can evict many small idle imports, and they re-import on next use. On Windows each re-import takes its range off the watch again.
- **Not always enough room.** If too little is evictable (everything was used in the last 256 lookups, or is held), it can't help. The abort stays as the backstop.
- **A Windows heap ends up import-only.** Once the heap has been imported whole it can never be mirrored again (§1.3), so every later budget squeeze depends on eviction. Two big ranges could evict each other and re-pin on every build: slow, but not a crash.
- **One lost cache publish.** A build that evicts doesn't publish to the address-space cache, because the epoch moved.

### 2. Put a range back on the watch when the import that removed it is freed

This is the root fix on Windows.

**What:**
- When a retired import that took its range off the watch is actually freed (its `RetiredImport` after the hold), restore the coverage of its blocks and re-arm the arena's watch.
- Then stamp those blocks as possibly written, as `watchPrivateMapping` does (GuestMemory.cpp:1034-1039), so the next collect treats them as changed.

**Prior art:** #4448 does exactly this on Linux, in its new `Rewatch`: it re-registers the range and stamps it as an import window, once an import has been idle for 60 frames. On Windows its `Rewatch` does nothing.

**Risks:**
- It must not run while the GPU can still write through the import.
- Someone needs to confirm that the Windows write watch works again on pages that were pinned.
- It needs Windows to build and test.
- It doesn't cover a heap window that is still live. In that case the whole import counts the window as replaced (954-962) and usually fits.

**Pairing:** together with option 1, this removes both the abort and the related throw for good.

### 3. Mirror a heap that is partly off the watch, by comparing those blocks

**What:** accept the heap at 1749-1757, and change both refresh paths (1556, 1693) to compare, on every build, the blocks that are off the watch.

**Risks:**
- **Cost.** It grows with the part that's off the watch. After enough window imports that's most of a 768 MiB heap, compared on every build.
- **Coherence.** While a window import is live, the GPU writes guest memory directly, and address-based draws write the mirror. That gives two device copies of the same bytes, and write-back must not overwrite either one. Today the `Require` at 1556 rules this combination out by throwing.
- It's the most code and the most risk of the five.

### 4. Refuse the build without aborting

**Throwing doesn't work.**
- A draw exception is rethrown (`Execution/src/Driver/Packets/PacketExecution.cpp:301-305`).
- The queue worker then reports it as a driver failure (`Execution/src/Driver/Queues/QueueWorker.cpp:218-221`, into `Driver::ReportFailure` at `Execution/src/Driver/Lifecycle.cpp:180-199`).
- The driver stops, which is no better than the abort.

**A skip needs a verdict that doesn't throw,** such as `DrawVerdict::Nothing` (PacketExecution.cpp:296-297).

**What the draw does then: nothing.**
- It draws nothing and makes none of its storage writes.
- The same happens to every later address-based draw that needs the heap, until the budget frees up.
- The result is silent missing geometry or effects, which can persist.

This is acceptable only as a loud last resort behind option 1.

### 5. Raise APS5_ADDRESS_COPY_MAX_MIB (stopgap)

- Setting it to 1024 avoids the abort, but every address-based build then copies 768 MiB and writes back the writable part.
- It's useful for confirming the diagnosis on Village, not as a fix.

### Whichever option is chosen

- Make the reason string at 2643 say which refusal sent the range to a copy. "heap partly outside the write watch" would have saved a step here.
- Splitting a heap between an import and a mirror is ruled out: the BDA table needs the heap contiguous on the device (`tests/BdaResources.cpp:993`).
