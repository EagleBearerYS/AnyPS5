## Broken by design on Linux

1. **No host copies, and Linux needs udmabuf to import shared memory.** His 68cc97aed ("read every V# at run time through the page table; delete the CPU capture of V#s, snapshots and host copies") makes GuestBufferMemory refuse writable GPU-mapped memory with no host import (Graphics/src/GuestBufferMemory.cpp:2126: `Require(!range->writable && !range->releasable, unservedRange(*range, "only a read-only range of the main image is mirrored"))`). On Linux, shared direct memory is imported only through /dev/udmabuf; without it, main copies, and his branch refuses. This is 248 of the 293 new failures. With udmabuf present this would change, but a stock kernel has udmabuf off or root-only, and this VM cannot load it.
2. **Write guards are Windows-only.** GuestMemory::GuardWrites (Execution/src/GuestMemory.cpp:2001-2009) returns false off Windows. ResidencyGuest::Guard (Graphics/src/ResidencyGuest.cpp:49-52) returns that, and Residency.cpp:522-526 then never admits a CPU-writable page ("unguardable"); :374-379 demotes a guarded page it cannot guard again. UnitShadow.cpp:577-591 never marks a unit guarded. So on Linux no CPU-writable page gets a device mirror, and tests/WriteGuards.cpp is `#ifdef _WIN32`, so nothing catches it.
3. **Commit imports and the guest arena are Windows-only.** 12 of his 29 GPU-path tests skip on Linux for this, three with no message, and check_skips counts 51 unexpected skips. His residency, commit-import and key-table paths have no Linux coverage.
4. **His Linux-only disk-cache size checks are stale** (build failure 1). agc_shader_disk_cache fails on Linux ("rejected ... truncated, corrupt or another format"). So at least one stored record no longer round-trips there, which the Windows build cannot see.
5. **Three guest libc tests segfault on his tree, but pass on main:** guest_pthread_attr, guest_pthread_start and guest_available_cpumask. gdb on guest_pthread_attr_tests shows SIGSEGV in a guest thread started by StartNativeThread (libkernel.prx), at its first `std::call_once` (`std::once_flag::_Prepare_execution`), with fs_base 0x20020b6c0 and rsp 0x200207c18 inside a 2 MiB rw mapping 0x200004000-0x20020c000. His thread-stack commit dbcb4eb67 changes only Windows code. Cause not found.
6. Smaller: agc_driver_bda_import_eviction_tests is built but never registered with ctest. His agc_compute_pipeline_budget test is Windows-only.
