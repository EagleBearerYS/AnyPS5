### What the recompiler stores

The switch is `APS5_DIAG_TABLE_TRACE=<pc>:<byte offset>`. At the image-table read with that pc (here the `image_sample` at 0xfc), every guest lane whose exec bit is set stores what its lookup read. The words go into the program's first bound output buffer (the V# of its first buffer store) at the byte offset. Two regions:

- **Map copy:** at the offset, 1024 words. Group 0's lanes copy `table_map[0..length)`, the map exactly as the shader sees it. Unwritten words stay `0xdeadbeef`.
- **Lane rows:** after the map copy, one 20-word row per lane, at row index `workgroup id × threads + local invocation index`.

Row words:

| # | name | source in SpirvImageEmitter.cpp |
|---|---|---|
| 0 | marker | `0xd1 << 24 \| workgroup << 12 \| subgroup lane << 6 \| local lane` (see below) |
| 1 | lower | the root binary search's `lower` (`LookupTablePointer`) |
| 2-4 | record.low, record.high, record.code | the three words of the selected record (`TableMapAt(selected, 0..2)`) |
| 5 | root.code | the root's code after its fault select |
| 6-9 | child.fault, child.mapStart, child.keys, child.baseLow | the child header's `TableFault`, `TableMapStart`, `TableKeyCount` and `TableBaseLow` (`LookupTableWord`, dynamic header) |
| 10, 11 | child.record, child.mapped | `record` (key offset / stride) and the map word it selects, `mapped` |
| 12, 13 | image.flags, image.element | the image record's flags and element (`EmitTableAccess`) |
| 14 | driver.fault | the driver fault word the element selects |
| 15 | code | the final table code (the image record index) |
| 16 | offset | the key's byte offset (handle argument 0) |
| 17, 18 | pointer.low, pointer.high | the record pointer the root search looked for (handle arguments 1 and 2) |
| 19 | address.low | the T#'s address low that a fault would report |

**The marker** has two lane fields:
- bits 6-11 are the guest lane that subgroup operations use (`EmitSubgroupLocalInvocationId`: at two lanes per invocation, `SubgroupLocalInvocationId + 32 × half`);
- bits 0-5 are the guest lane from `LocalInvocationIndex` (two lanes: host index + 32 × half), the one the guest's output address and the row index come from.

At two lanes per invocation the two fields should be equal for every lane. If they differ on Intel, the 32-invocation workgroup is not one subgroup in index order (see part 2). On lavapipe they differ by design: subgroup 8 gives bits 6-11 = local lane mod 8.

### What the test prints

- **Bases, once:** `trace bases: Table <hi>:<lo>, records <r0> <r1>, palettes <p0> <p1>`.
- **After each dispatch:**
  - `trace map: N words read by the shader, M words at recompile`;
  - the map copy, 8 words per line (`map[i] ...`), with words that differ from the recompile-time map marked `*`;
  - the header `trace rows: marker lower ...`, then one line `trace g<group> l<lane>: <20 words>` per lane.
- **On a failed check:** the failure message ends with that lane's row, so it prints next to the failure line. A forced failure (scratch build, not committed) printed:

**How the trace reaches memory.** In trace mode the test points the output V# at `TraceOutput` instead of `Output`:
- words `[0, 1024)` are the normal output;
- the trace starts at byte 4096.

The test copies the normal words back into the outcome, checks that `Output` stayed `0xdeadbeef`, and then runs its usual checks. The trace stores go through the runtime V# store path (`writeBuffer`), with its bounds check, exactly as the guest's own `buffer_store_dwordx4` does.

**What to look for on Intel**, in order:
1. A row whose words differ from the recomputed lookup. The decoder names the first differing word: a wrong `lower` or record words points at the root search, a wrong `child.*` at the child header, a wrong `mapped`, `element` or `driver.fault` at the image record.
2. A marker whose bits 6-11 differ from bits 0-5.
3. All rows correct while the texel is still base + 0x100. That would put the fault after the lookup, in the descriptor index or sampling.

## Part 2: full subgroups

### What a two-lane wave64 compute program requests today

**Recompile:**
- `target.subgroupSize` is the device's default subgroup size (`state->subgroup.subgroupSize`, `VulkanDevice::buildTarget`).
- A wave64 compute program on a 32-wide host first tries the spanned layout when `target.spannedWaves` is set. That flag is `computeFullSubgroups && !APS5_NO_SPANNED_WAVE` (`VulkanDevice.cpp` ~2416).
- The arm and its sibling fall back, because of the barrier in divergent flow (`Recompiler.cpp` ~719: `targetOptions.spannedWaves = false` and re-emit). That gives `laneCount == 2`.

**SPIR-V:**
- `LocalSize` is `(ceil(threads / 64) × 32, 1, 1)` (`WorkgroupLocalSize`), so 32 here.
- Subgroup operations (ballots, shuffles, buffer `addTid`) use guest lane `SubgroupLocalInvocationId + 32 × half`.
- `LocalInvocationId`/`GlobalInvocationId` come from `LocalInvocationIndex + (index & ~31) + 32 × half`.
- Wave LDS barriers use Subgroup scope (`WaveLdsScope`).

**Result:** `hostSubgroupSize = 32`, `fullSubgroups = false` (`info->fullSubgroups = state.spannedWave`).

**Pipeline create** (`VulkanDevice::computeSubgroupSize` and `computeStageFlags`, `CreateComputePipeline`):
- with `computeWave32` (subgroup size control, 32 within min..max, compute among `requiredSubgroupSizeStages`): `VkPipelineShaderStageRequiredSubgroupSizeCreateInfo{requiredSubgroupSize = 32}` is chained and `stage.flags = 0`. There is no `REQUIRE_FULL_SUBGROUPS` and no `ALLOW_VARYING_SUBGROUP_SIZE`.
- without `computeWave32`: nothing is chained, and the build relies on the default subgroup size being 32.

On Intel ANV that should be required size 32 with flags 0. The Intel log's `Wave32 programs run on subgroups of 32: compute 1` and `spans two full 32-lane subgroups: 1` lines would confirm the device side.

### What changes if two-lane builds also request full subgroups

This is commit `400b86ce93`:
- `SpirvEmitInfo` gains `twoLanes`.
- `Recompile` sets `result.fullSubgroups = emitted.fullSubgroups || (emitted.twoLanes && stage == Compute && request.target.spannedWaves)`.
- It reads `request.target.spannedWaves`, which is already part of the cache key and the request serializer. The emitter's own copy can't be used, because the fallback clears it.

Effects:
- **SPIR-V: none.** The test checks that the module is word-for-word the plain two-lane module.
- **Pipeline create:** `stage.flags` gains `VK_PIPELINE_SHADER_STAGE_CREATE_REQUIRE_FULL_SUBGROUPS_BIT`, next to the existing `requiredSubgroupSize = 32`.
  - The VUID that the local size X be a multiple of the required subgroup size holds, since X is 32 × n for every two-lane build.
  - `computeStageFlags`' `require(computeFullSubgroups && computeSubgroupSize == 32)` holds: `spannedWaves` implies `computeFullSubgroups`, which implies `computeWave32`, and the maximum is at least 32.
- **Pipeline identity:** `fullSubgroups` is mixed into `PipelineVariantId`, so it is a different pipeline. Captures and the journal record the new `stageFlags`.
- **Ballot and shuffle layout, `SubgroupLocalInvocationId`:** unchanged in the module.
  - What the flag adds is a guarantee that each 32-wide subgroup is fully populated at launch. Without it, the spec allows partly populated subgroups even with a required size.
  - It does not by itself make `SubgroupLocalInvocationId` equal `LocalInvocationIndex`. The two-lane code assumes both: ballots use the first, guest builtins and output addresses the second. The trace marker records both per lane.
- **My expectation for ANV:** with required size 32, a 32-invocation workgroup already runs as one SIMD32 thread with every channel enabled. So I don't expect the flag to change ANV's code or the test's result. It turns an assumption into a guarantee. A marker mismatch on Intel would be the sign that it matters.

**The check (red/green):**
- `RunPointerChildKeyTests` now also builds the two-lane module from a full-subgroups target (`spannedWaves = true`, which falls back). It requires `fullSubgroups`, and the same SPIR-V as the plain two-lane build.
- Red with the old recompiler (test change only), both tests:
  `... the two-lane build for a device with full 32-lane subgroups does not request them`.
- Green with the change, both tests, 10 of 10. The 51-test set passes.

**Caveats, if this goes beyond a diagnostic branch:**
- `fullSubgroups` no longer means "the program spans two subgroups". `SpannedBallotSequence.cpp:60` and `LdsMaskWaterfall.cpp:65` use it that way. On a 32-wide full-subgroup device, a program that fell back would now pass their "did not span" check. Both tests skip on lavapipe. A separate spanned indicator would fix that.
- `APS5_NO_SPANNED_WAVE=1` also turns the new request off, since it is keyed on the same target flag.
- I did not bump the disk cache format. An artifact cached before this commit keeps `fullSubgroups = false` until the cache is cleared. The ctest registrations run with `ANYPS5_NO_SHADER_CACHE=1`.

## decode.py

Arguments: the log, then optionally the table index (1), the column stride (32), the addend (0) and the column offset (0). Those are the arm test's values at pc 0xfc.

```python
import re
import sys

NAMES = "marker lower record.low record.high record.code root.code child.fault child.mapStart child.keys child.baseLow child.record child.mapped image.flags image.element driver.fault code offset pointer.low pointer.high address.low".split()
POISON = 0x80000000
MAX_PARENT_KEYS = 524288


def runs(lines):
    found = []
    run = None
    for line in lines:
        if line.startswith("trace map:"):
            run = {"map": [], "rows": []}
            found.append(run)
        elif run is not None and line.startswith("  map["):
            run["map"] += [int(word.rstrip("*"), 16) for word in line.split()[1:]]
        elif run is not None and line.startswith("  trace g"):
            head, words = line.split(":", 1)
            group, lane = map(int, re.findall(r"\d+", head))
            run["rows"].append((group, lane, [int(word, 16) for word in words.split()]))
    return found


def expected(table_map, row, table, stride, addend, column_offset):
    m = lambda index: table_map[index] if index < len(table_map) else None
    header = 8 + 8 * table
    low, high, offset = row[17], row[18], row[16]
    start, stored, fault = m(header), m(header + 1), m(header + 7)
    count = stored if stored <= MAX_PARENT_KEYS and fault == 0 else 0
    lower, upper = 0, count
    while lower < upper:
        middle = lower + ((upper - lower) >> 1)
        record = start + 3 * middle
        less = m(record + 1) < high or (m(record + 1) == high and m(record) < low)
        lower, upper = (middle + 1, upper) if less else (lower, middle)
    selected = start + 3 * lower if lower < count else header
    same = m(selected) == low and m(selected + 1) == high
    missing = m(header + 6) if low == 0 and high == 0 else POISON
    code = m(selected + 2) if lower < count and same else missing
    root = fault if fault != 0 else code
    out = {"lower": lower, "record.low": m(selected), "record.high": m(selected + 1), "record.code": m(selected + 2), "root.code": root}
    if root & POISON:
        return out
    child = root
    child_fault, child_start, keys, base_low = m(child + 7), m(child), m(child + 1), m(child + 4)
    relative = (offset - addend) & 0xffffffff
    record = relative // stride
    in_map = relative - record * stride == 0 and record < keys
    mapped = m(child_start + record) if in_map else m(0)
    word = child_fault if child_fault != 0 else (mapped if in_map else POISON)
    out.update({"child.fault": child_fault, "child.mapStart": child_start, "child.keys": keys, "child.baseLow": base_low, "child.record": record, "child.mapped": mapped, "code": word, "address.low": (base_low + (offset & ~3) + (column_offset & ~3)) & 0xffffffff})
    if word & POISON or word == 0:
        return out
    element = m(word + 2)
    out.update({"image.flags": m(word), "image.element": element})
    if not m(word) & POISON and element < m(2):
        out["driver.fault"] = m(m(5) + element)
    return out


def main():
    path = sys.argv[1]
    table, stride, addend, column_offset = (int(value, 0) for value in (sys.argv[2:] + ["1", "32", "0", "0"][len(sys.argv) - 2:])[:4])
    with open(path) as file:
        lines = file.read().splitlines()
    for number, run in enumerate(runs(lines)):
        good, written, first = 0, 0, None
        for group, lane, row in run["rows"]:
            if row[0] == 0xdeadbeef:
                continue
            written += 1
            wrong = []
            if row[0] >> 24 != 0xd1 or (row[0] >> 12) & 0xfff != group or row[0] & 63 != lane:
                wrong.append("marker")
            for name, value in expected(run["map"], row, table, stride, addend, column_offset).items():
                if value is not None and row[NAMES.index(name)] != value:
                    wrong.append(f"{name} {row[NAMES.index(name)]:#x} expected {value:#x}")
            if wrong:
                first = first or f"g{group} l{lane}: " + ", ".join(wrong)
            else:
                good += 1
        print(f"run {number}: map {len(run['map'])} words, {written} rows written, {good} match the lookup recomputed from the map" + (f"; first mismatch {first}" if first else ""))


main()
```

The decoder doesn't check the marker's subgroup-lane field, because it legitimately differs at subgroup 8. On Intel, compare bits 6-11 with bits 0-5 directly.
