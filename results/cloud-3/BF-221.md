**What rests on more than the function's own source, so a reviewer can weigh it:**

- **The not-initialized check (0x80D90001) first, on all seven AppContent rows.**
  - dlc_emu is a hook that sits on top of the real library, so it doesn't model initialization.
  - The check follows the tree's library-wide recovered guard (`docs/dev/debt/libSceAppContent.md`, Initialization). Commit 20a2488b4b's earlier wording was "Native operations reject uninitialized use with `0x80D90001`".
  - It names the library's native operations as a group, not each function. The census flagged `GetPftFlag` in particular as unknown.
  - If a reviewer wants a per-function source for the guard, the fallback is a throw before initialization, not a guess.
- **Label padding for `Sp` and `Shrink`.**
  - dlc_emu's `valid_app_unified_label` rejects a padded label at every SDK.
  - The tree's done label calls gate the same check at SDK 0x01500000 (`AddcontMount`, `GetAddcontInfo`, `AddcontEnqueueDownload`) or 0x03500000 (`AddcontDelete`, `GetAddcontDownloadProgress`).
  - So the two new rows answer `PARAMETER` from 0x03500000, where every source agrees, and throw for a padded label below it.
  - That is stricter than the census, which accepted below 0x01500000 because the siblings do: no source names that for these two functions, and dlc_emu contradicts it.
- **`GetAddcontInfoListByIroTag` with a list and a null `hitNum`.**
  - It returns 0, as dlc_emu does.
  - The tree's `sceAppContentGetAddcontInfoList` answers `PARAMETER` there, and dlc_emu's own `GetAddcontInfoList` returns 0. The difference is recorded in the debt.
- **`sceRudpGetMaxSegmentSize` reporting the stored value.**
  - Vita3K stores the size in its library state (`RudpState::max_segment_size`, default 1410 at [`#L370`](https://github.com/AndnixSH/Vita3K-PS-Vita-OS-Fork/blob/c86ac732bc811057e690bed280c5076bdf95385e/vita3k/modules/SceRudp/SceLibRudp.cpp#L370), the value the PS5 getter reports, debt `libSceRudp.md:12`).
  - But Vita3K leaves the getter unimplemented ([`#L1080-L1082`](https://github.com/AndnixSH/Vita3K-PS-Vita-OS-Fork/blob/c86ac732bc811057e690bed280c5076bdf95385e/vita3k/modules/SceRudp/SceLibRudp.cpp#L1080-L1082)), and RPCS3 has both as TODO stubs. The getter link is an inference, recorded as one.
  - The stored size survives `sceRudpEnd`, as in Vita3K, whose `sceRudpInit`/`sceRudpEnd` don't reset it.
