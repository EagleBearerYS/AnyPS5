## The fix

**A thread-local scope flag that `indexRevalidate` sets for its own proof.**
- **Declaration:** `thread_local bool indexProof` sits next to `depthGuardRefusals`.
- **Where it is set:** `indexRevalidate` sets it right before its first `fastRevalidate` call. A small `Done` guard resets it when that block exits, on every `return fallback()` too. This is the same guard shape as `ReleaseTextureCaches`'s `releasing` flag in this file.
- **What it gates:**
  - `countFastFail` adds nothing while `indexProof` is set;
  - `countCollectRefusal` returns early;
  - the `depthGuardRefusals` increment in `fastRevalidate`'s storage loop is skipped.
- **What it does not touch:**
  - `fastRevalidate`'s return values, `reason`, `overlapping` and `accepted` are untouched, so no proof outcome changes;
  - every other caller (`revalidateFull`'s two calls) counts as before;
  - the fallback proof counts each refusal once, as with the index off.
- **Why `fastRevalidateEach` needs no gate:** its depth-guard increment is never reached from the index. `revalidateFull` runs `indexRevalidate` only when `EpochRevalidate()` is on, and `fastRevalidate` goes to `fastRevalidateEach` only when it is off.
- **No other reader is affected.** The three counters are read only by the `[rescache]` line and by tests (`CollectRefusalCounts()`, `DepthGuardRefusals()`).

**The test: `agc_driver_resource_cache_collect_refusals_index`.**
- **Mode:** the same `collect-refusals` mode.
- **Properties:** `ENVIRONMENT "ANYPS5_NO_SHADER_CACHE=1;APS5_TABLE_INDEX=1" SKIP_RETURN_CODE 77 TIMEOUT 30`.
- **Windows:** it was added to the WIN32 `PATH=path_list_prepend:$<TARGET_FILE_DIR:libc>` list with its neighbours.
- **Registration:** it is registered right after `agc_driver_resource_cache_collect_refusals`, which keeps its own properties unchanged.

## Left as is (outside the task's scope)

The index's inner proof also runs other profile counters, and these still double when it fails and falls back. Each is in `[rescache]` only.

| counter | site in `fastRevalidate` | when it doubles |
| --- | --- | --- |
| `countPendingFail` (pending foreign, snapshot and T1-eligible) | before `fail(Pending)` | always on that path: a `Pending` failure is always followed by the fallback |
| `countKeysProven` | the keys proofs | only when the inner proof counts it and then fails later |
| `serialSkips` | the unchanged-serial branch | only when the inner proof counts it and then fails later |

- **The simple fix covers only one of them.** Gating `countPendingFail` on the same flag would be a one-line follow-up.
- **The other two need more than the flag.** Gating `countKeysProven` and `serialSkips` would also drop their counts on accepted index proofs, which are single counts today. They would have to be counted after the outcome is known.
