# libSceFios2 (PM-088 classification)

- **What it is:** FIOS2, the SDK file I/O scheduler: sync and async path and handle I/O (FH, DH, File, Directory, Stat, Rename, Delete), op objects with deadlines and priorities, a cache layer, PSARC archive mounts, I/O filters and path overlays, all layered on libkernel file calls. 168 todo, 0 done. Every export in `core/libs/prx/libSceFios2/Export.cpp` is a parameterless placeholder; `docs/dev/debt/libSceFios2.md` says no credible prototypes were found.
- **Counts:** A 0, B-S 0, B-M 0, B-L 0, C 0, D 168.
- **Why all D:** no signature, struct (SceFiosParams, SceFiosOpAttr, SceFiosOpenParams, SceFiosStat, SceFiosDirEntry, SceFiosOverlay, SceFiosDate/Time units) or FIOS error value is in the tree or in a public PS4/PS5 source. Vita-era public layouts are 32-bit and are not evidence for the PS5 ABI. Families (basis column): FH 33, path ops 28, op objects 21, cache 13, archive 10, DH 8, overlay/resolve 8, FH-table helpers 6, date/time 6, the rest are small (params, scheduler, debug, printf, path rules).
- **Title-shipped module:** titles ship `sce_module/libSceFios2.prx` (CUSA02636 in `docs/dev/debt/relinker.md`; relinker tests `test_guest_symbol_names.py`, `RuntimeLayoutTests.cpp`). Under CONTRIBUTING.md the relinker loads the title's copy and leaves the host library out of `DT_NEEDED`, so the host library is only used by titles that ship no copy. Reading a shipped copy (REVERSE_ENGINEERING.md, source 2) is how to settle the ABI. That work is reverse engineering, so it stays D.
- **libkernel calls FIOS could build on once the ABI is known:**
  - `sceKernelOpen/Close/Read/Write/Lseek/Stat/Unlink` in `core/libs/prx/libkernel/File/src/Open.cpp:265,299,320,339,355,404,423`.
  - `sceKernelPread/Pwrite/Preadv/Pwritev` in `File/src/Stdio.cpp:1366,1377,1416,1430` (POSIX branch; the Windows branch is at 1267-1360).
  - `Ftruncate:933`, `CheckReachability:1059`, `Fstat:1070`, `Fsync:1084`, `Getdirentries:1138`/`Getdents:1186` (POSIX; Windows 1117/1132), `Mkdir:1200`, `Rename:1455` and `Rmdir:1463`.
  - Asynchronous I/O: `sceKernelAio*` is fully implemented (`Aio/src/Aio.cpp:234`). FIOS op objects and the non-Sync variants need no new thread pool.
  - Guest paths go through `ResolvePath_nid_no_patch` (`libc/src/General.cpp:682`). Guest-buffer writes already use `GuestArena::HostWrite` inside the kernel calls.
- **Archives and overlays:** the tree has no model for either. `AppArchive` (`libc/include/AppArchive.hpp`, `libkernel/File/src/ArchivedFile.cpp`) is the emulator's own `app0.zar` (ZArchive) read path, not PSARC or SceFiosOverlay. Path resolution has fixed mounts only.
- **Estimated sizes after an ABI read:** FH, File, Directory and Stat Sync families B-M each over the calls above. Async variants and Op* B-M over Aio. Overlays B-M (an ordered prefix-rewrite table in front of ResolvePath). PSARC mounting plus the dearchiver filter B-L.
- **Dependencies:** none for FH/DH/File/overlays. A PSARC dearchiver needs zlib inflate and LZMA. For zlib, the inflater inside 3rdparty/stb (`stbi_zlib_decode_*`) could serve; zstd and ZArchive cannot. There is no LZMA submodule, so that would be a new dependency (for example the public-domain LZMA SDK). mbedtls is irrelevant.
- **Batches:** none. There are no A, B or C rows. The prerequisite is one RE pass over a shipped `libSceFios2.prx` that records prototypes, structs and error codes in the debt file. After that, the first batch would be the FH/File Sync family (about 30 functions: FHOpenSync/CloseSync/ReadSync/WriteSync/PreadSync/PwriteSync, FHSeek/Tell/GetSize/StatSync, FileExistsSync, FileGetSizeSync, ...). Its test would be a new guest test executable driving them against a temp directory. The library has no CMakeLists.txt yet, so that PR also adds one to register the test.
