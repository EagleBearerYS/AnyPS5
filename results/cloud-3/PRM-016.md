## F1 (bea388d1b)

**What changed** (`Graphics/src/ShaderResources.cpp`):

- **A rejected element blocks reuse.** `noteReusable()` no longer marks an address-based build reusable when any image-table element was rejected. A rejected element is one whose `elementTextures` entry stayed unset, for any of these reasons:
  - its surface is not mapped;
  - its texture lookup threw;
  - the table was over capacity;
  - sampler pairing failed;
  - a rejection was replayed from the table cache.

  Sampler-table rejections don't count. They depend only on the descriptor words, which the draw key already covers.
- **A throw refuses the reuse.** On the address path, `Revalidate` now runs `ResumeSpace`, `proveBuild` and `SpaceImportsCurrent` inside `try { … } catch (const std::exception&)`.
  - On a throw it returns false and sets `report->failure = Other`, and the existing `Suspend` guard suspends the space again.
  - `ProcessShutdown` is not a `std::exception`, so a shutdown still unwinds.
- **Cost.** An address-based draw with a rejected table element now builds on every draw.
  - That includes a null element, which is rejected as "not mapped".
  - Before this change, such a draw faulted once and `CompleteUse` then marked it not reusable anyway (PM-047's severity note). So the change only closes the window before that first fault.
  - The non-address template path has the same skip of rejected elements. That path is on main, and I left it alone.

**Test 1** (mock, PM-047's recipe): `addressRejectedTableElementTests` in `tests/BdaResources.cpp`, run by `agc_driver_graphics`.

- **Steps:**
  1. Reserve 64 KiB as PROT_NONE.
  2. Build an address-based draw whose image table's one element points there. The build rejects it as not mapped.
  3. Commit the pages with mprotect, with no registry change.
  4. Call `EndUse`, then `Revalidate`.
- **Red** (bae2cd48e plus the test): `AGC graphics: an address-based draw build whose image table element was rejected as unmapped was reused after the element's surface was committed`
- **Green** (bea388d1b): passes.
- **One change from the recipe:** the range is not registered. A range registered as a reserved heap is caught already, because `serialLoop`'s `DescribeCommitted` check on cut regions sees the commit. Only an unregistered range slips past, because it changes neither the registry generation nor a cut region.

**Test 2** (the throwing case, lavapipe): `ThrowingProof` in `tests/execution/AddressDrawReuse.cpp`, run by `agc_driver_address_draw_reuse`.

- **Steps:**
  1. Build an address-based draw with one sampled image over registered pages.
  2. Call `EndUse`.
  3. Turn the image's memory into a 4x multisampled color target with `MultisampleTargetView`.
  4. Call `Revalidate`.
- **The throw:** the proof's walk calls `cachedTexture`, which throws `AGC graphics: a texture read of 0x…+0x1 overlaps multisampled color target 0x…+0x10000 (4 samples), whose samples are only on the host: guest access to it is not implemented`.
- **Red** (the `noteReusable` part of the fix only, without the catch): `AGC graphics: address draw reuse: the reuse proof of an address-based draw build whose sampled image's memory became a multisampled target threw instead of refusing the reuse`
- **Green** (bea388d1b): passes.
- **Why not PM-047's case** (an accepted element whose surface is decommitted):
  - On this base that case doesn't throw. Texture reads go through `GuestMemory::ReadCommitted`, which fills uncommitted pages with zeros.
  - The mock can't create textures at all: it has no `vkCreateImage` and no detiler.
  - Heap mirrors, whose `prepareRange` does throw on an inaccessible range, need the write-watched guest arena. That exists only on Windows, so those tests are skipped on Linux.
  - A fresh build would hit the multisampled-target throw too. For a table element, it would reject the element instead.

## F3 (merge a937541bd, then 82b35b7a8): done, about 10 lines

**The merge.** Upstream main 5d9dcc42d went in as a merge commit, with no conflicts. On main, a batch whose end or submit fails is discarded: `DiscardUnsubmitted` calls `Recorder::discard`, which destroys the batch and with it its completion lambdas, without running them.

**The fix:**

- `BeginUse` now returns a token: a small struct in a `shared_ptr`. Making it adds to the use count and destroying it subtracts.
- The counter is now a `shared_ptr<std::atomic<std::uint32_t>>` that the token also holds, so the count is never freed before the token. This matters because the closure's members are destroyed in an unspecified order.
- `CompleteUse` no longer subtracts.
- Draw.cpp's completion lambda already owns the token (`hold`). So the count drops at the end of the completion, as before, or when the batch is discarded.
- Size: 2 lines in `ShaderResources.hpp`, +7/−5 in `ShaderResources.cpp`.

**The test** (FailedSubmission style): `addressFailedSubmissionTests` in `tests/BdaResources.cpp`.

- **Steps:**
  1. Build an address-based draw.
  2. Register `OnComplete` with `BeginUse`, the same way Draw.cpp does, then call `EndUse`.
  3. Check that `InUse()` is true.
  4. Make the mock's submit return `VK_ERROR_OUT_OF_HOST_MEMORY`, and check that `Submit` throws.
  5. Expect `!InUse()`.
- **Mock change:** `vkQueueSubmit` in the `tests/Graphics.cpp` mock now returns `mock.submitResult` (default `VK_SUCCESS`). The test sets it through a new `BdaTestAccess::submitResult` hook.
- **Red** (merge a937541bd plus the test): `AGC graphics: an address-based draw build stayed in use after the batch that took it failed to submit`

## P2: real, fixed (3fe43a3ff)

**Cause.** The two paths build the snapshot list differently:

- **A fresh capture** passes `ShaderMemory::Regions()`: the stages' code regions merged with the captured page runs, sorted by address.
- **A decode-cache hit** passes the stages' code regions in stage order, then each stage's matched regions (`memory.insert(… matchedRegions[i] …)` in Execution `Driver/Draw/Draw.cpp`).
- `SameSnapshots` compares the two lists entry by entry. So whenever the orders differ, the first hit after a decode miss refuses the address-based reuse and builds again.

**The test:** `DecodeCacheHit` in `tests/execution/AddressDrawReuse.cpp`.

- **Setup.** It submits a PM4 draw through the driver:
  - registered pixel and vertex shaders, with the pixel shader's code below the vertex shader's;
  - the address-based pixel shader from the file, which stores through the BDA table;
  - a render-target-tiled color target on registered pages, so the draw is resident and recordable;
  - a `RELEASE_MEM` label after the draw. Reading it back through `GuestMemory::Read` syncs the recorder.
- **Sequence:**
  1. A decode miss, which builds.
  2. A second decode miss, which must not build.
  3. A decode-cache hit, which must not build.

  If the third draw doesn't hit the decode cache, that part prints a line and isn't tested.
- **Red** (82b35b7a8 plus the test): `AGC graphics: address draw reuse: a submitted draw that hit the decode cache built its resources again after a decode miss of the same draw`
  - A temporary print (not committed) showed the two lists. The miss passed [header 0x…340, header 0x…3e0, pixel code 0x…500, vertex code 0x…600].
  - The hit passed [0x…600, 0x…340, 0x…500, 0x…3e0].
- **Green** (3fe43a3ff): passes.

**The fix** is one shared ordering, one line. In Execution `Driver/Draw/Draw.cpp`, `snapshot()` now sorts the draw's snapshots by address, then by size, before passing them on. Both paths now produce the same list.

**What it leaves.** Two stages can read adjacent words, or the same words, on one page:

- The miss then has one merged run, where the hit has two entries or a duplicate.
- Such draws still miss the first reuse after a decode miss.
- Merging those runs would need copying, because the regions point into different storage: ShaderMemory's pages for a miss, the draw-cache entry's regions for a hit.
