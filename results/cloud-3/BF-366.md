## 3. The refusal print: a throwaway test

**The fixture:** a new `CheckRefusalPrint` in `tests/execution/NativeMultisampleDepth.cpp`, run with `--refusal-print`. I added it to the branch build only, ran it once and reverted it, so it's not committed or pushed.
- **Setup:** the same as #13021's `CheckDepthPublication` with `depthOnly = true`: the `--publication` main block (GPU lock and `TextureDetiler` context), and its `DepthTarget` fields (`depthSwizzle 24`, `pipeBankXor 0x8c00`, `iterate256`, pipe-aligned HTILE).
- **The target:** a native D32S8 (`VK_FORMAT_D32_SFLOAT_S8_UINT`) target, 4 samples, **256×64**, with a separate stencil plane and a **depth-only HTILE** (`htileStencil = false`, `htileDepthOnly = true`).
  - The stencil plane is memset to the clear value 0x5a, and HTILE starts at 0.
- **The draw:** `NoteDepthSurfaceWrite`, then `DepthRaster` with stencil `ALWAYS/REPLACE 0x20`, the existing fixture's draw (host stencil 0x20 + sample).
  - **First page checked:** the fixture checks, through `MultisampleTextureLayout(kZ64KBX, 1, 4, 256, 64)`, that every byte of the stencil plane's first 4096 bytes is drawn, so none of it is left at 0x5a.
- **The store:** one CPU byte, `0x77` at stencil +0x64 (snapshot 0x5a, host 0x20).
- **The read:** `AgcDriver::GuestMemory::Read(stencilAddress, 4096 bytes)`.

**Result: the read throws the refusal.** Everything it printed (stderr), in full:


**What it shows:**
- **One store taints the whole page.** A single CPU store of a value different from the snapshot is enough to refuse. The page counts as "written by the guest" (1 page, not wholly by driver stores), and the one changed byte (+0x64, 0x77) is taken as the guest's.
- **So the other 4095 bytes are ambiguous.** Each still holds the snapshot value (0x5a) while the host drew something else (0x20–0x23). The write tracking can't tell, byte by byte, that the guest never stored there, so `UnchangedSinceLastCollect(byte)` is false for all of them.
- **The message is misleading for this case.** It speaks of a "same-value guest store", but here no same-value store happened: one different-value byte anywhere in a host-drawn page is enough.
- **The other planes are clean:** depth and HTILE show 0 guest-written pages, so only the touched stencil page is involved.
- **Counters:** "1 publications requested, 0 committed" is this process's first publication.
