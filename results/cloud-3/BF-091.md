## The fix (`ResourceTracker.cpp`, pointer-keyed columns only)

**`PointerRecordOrigin` becomes `PointerRecordReads(value, pointerKeyed, reads)`.**
- **Same walk as before:** Phis, U32 immediates, `LaneMaskWord`s skipped. Each record read must match the previous one: for pointer-keyed columns the same offset and `SameRecordColumn`, otherwise `EquivalentValue`.
- **What changes:** it collects the reads instead of keeping only the last.
- **The low origin** is `reads.back()`, which is the read the old function returned. So shapes without the new arms walk and plan exactly as before.

**(a) Lane-mask ANDs.**
- **The rule:** a `BitwiseAnd32` is taken when at least one operand is a lane-mask operand, by the new `LaneMaskOperand`. That is a `LaneMaskWord`, or an AND or Phi made only of lane-mask words and immediates (walked iteratively, with Phi cycles allowed), with at least one lane-mask word in it.
- **What is walked:** the operand that is not a lane mask is walked on. So record reads in it must still match the column, and anything else still refuses.
- **Refused:** an AND none of whose operands is a lane mask.

**(b1) A Phi high word.**
- **The walk:** for pointer-keyed columns the high word goes through the same walk (`PointerRecordReads(high, true, …)`). Its record reads must match each other. The existing check then requires them to be reads at the low word's offset + 4 that `SameRecordColumn` matches with the low origin. Immediates and lane-mask arms are skipped.
- **A high word that is one read** behaves exactly as with b91f0508d: the column takes its table handle and record offset from that dominating read.
- **A Phi or AND high word** has no single dominating read:
  - The table comes from the first record read (high reads first, then low reads) whose V# words all `Precedes` the descriptor load. `Precedes` is a new block-dominance check: a depth-first search from the entry that avoids the defining block, plus instruction order within a block.
  - This matters because `KeepSourceAlive` emits `ReferenceU32` of those words before the handle.
  - The handle's record-offset arguments get the high word itself, which dominates the load because it feeds it. The GPU path for pointer-keyed columns reads only the handle's arguments 1 and 2, the pointer words (`EmitTableWord` → `LookupTablePointer`).
  - `MatchAffineOffset` (stride and addend) uses the chosen read's offset.
  - If no read's words dominate, the column is refused.

**(b2) The second-buffer arm stays refused.** `ReadConstBuffer(GetBufferResource(LoadAddressU32…), Immediate)` is a read at offset 0, not at the record word's offset + 4, and its table is not `SameRecordColumn`.

## The shaders (synthetic, wave64, in `tests/execution/ImageTable.cpp`)

**Registration.** There are three new flags and ctests:
- `agc_driver_pointer_phi_lane_and_table` (`--pointer-phi-lane-and`);
- `agc_driver_pointer_phi_high_table` (`--pointer-phi-high`);
- `agc_driver_pointer_phi_high_second_table` (`--pointer-phi-high-second`).

They are registered next to `agc_driver_pointer_phi_ballot_table`, in both `set_tests_properties` lists of their siblings: `ENVIRONMENT`/`SKIP_RETURN_CODE`/`TIMEOUT`/`WORKING_DIRECTORY`, and the `if(WIN32)` `ENVIRONMENT_MODIFICATION` PATH list.

**Common frame.** `RunPointerMaskTests` follows BF-086's waterfall shape, assembled with `llvm-mc -mcpu=gfx1030 -mattr=+wavefrontsize64` and branch targets checked with its disassembler:
- **Keys:** lanes 0–31 take key K0 and lanes 32–63 take K1 through `v_cndmask` (`SelectU32`).
- **Loop:** `v_readfirstlane` / `v_cmp_eq_u32_e64` / `s_and_saveexec_b64`, then `s_buffer_load_dwordx2 s[44:45], s[4:7], key<<4 offset:0x8` (the record pointer).
- **The T#:** `s_load_dwordx8` of the T# at pointer + 0x40, then `image_sample_lz`, then `s_andn2_b64 exec` back to the loop head.
- **Per-group words:** each group reads 8 words: K0, K1, a low-word selector (s18), a high-word selector (s19), a mask value (s20) and an aux word (s21).
- **The lane masks** are `v_cmp_lt_u32_e64 s[52:53], v0, s20` and `v_cmp_gt_u32_e64 s[54:55], s20, v0`. s20 is 0 in every run, so every masked pointer word is 0 on any host, whatever its ballot width.

**(a) lane AND:**

```
  s18 == 1: s_mov_b32 s44, 0xea
  s18 == 2: s_mov_b32 s60, s52 ; s21 == 1: s_mov_b32 s60, s54 ; s_and_b32 s44, s60, s52
  s18 == 3: s21 == 2: s_mov_b32 s44, 0x20 ; s_and_b32 s44, s44, s52
```

The low word on aed137caee: `Phi(Immediate, Phi(BitwiseAnd32(Phi(ballot word, ballot word), ballot word), Phi(record read, BitwiseAnd32(Phi(record read, Immediate), ballot word))))`. That is an arm `BitwiseAnd32(<lane-mask Phi>, CompositeExtractU32x4(Ballot(…), Immediate))` with a `BitwiseAnd32(Phi, <ballot word>)` one level deeper.

**(b1) high:**

```
  s18 == 1: s_mov_b32 s44, 0xea
  s19 == 1: s_mov_b32 s45, 0x1234
  s19 == 2: v_xor_b32 v11, s21, v3 ; v_readfirstlane_b32 s26, v11 ; s_lshl_b32 s27, s26, 4 ; s_buffer_load_dword s45, s[4:7], s27 offset:0xc
```

The high word: `Phi(Immediate, Phi(record +4 at pc 0x7c, the same column +4 at pc 0xd0 under a ReadFirstLane(SelectU32(…, BitwiseXor32, …)) key))`. The low word is `Phi(record, Immediate)`.

**(b2) high + second buffer:** (b1) plus `s19 == 3: s_load_dwordx4 s[56:59], s[12:13], 0x0 ; s_buffer_load_dword s45, s[56:59], 0x0`. Here `s[12:13]` is a 64-bit pointer read from SRT+0x40, and the V# behind it is loaded through `LoadAddressU32(GetAddressResource …)`.

**What the tests check:**
- **(a) and (b1):**
  - with every selector 0, the four groups (keys (1,2), (2,1), (1,1), (2,2), so two passes in groups 0 and 1) sample the T# of the record each lane's key selects, checked lane by lane as `--pointer-phi-ballot` does;
  - each arm whose pointer is not a captured one faults as "outside the snapshot", publishes no output, and keeps the artifact id.
- **(a)'s three such arms:** the constant `0xea`, the lane-mask Phi AND for both Phi words, and the record word ANDed with the mask.
- **(b1)'s arms:**
  - the constant low word and the constant high word `0x1234`;
  - the high-word copy under the same key (xor 0) and under the other key (xor 3) both give the unchanged result without recompiling. The two records' pointers share their high word.
- **(b2)** expects `Recompile` to throw `GetImageResource dword 0 is not a valid runtime value` and passes when it does. It fails if the shader plans or is refused for another reason.

**A note on the test design.** I first had a fourth (a) run, the `0x20` arm ANDed with the mask. It faults at the same pointer (`0x…00000000`) as the three runs before it. `AsyncLog::Admit` prints an identical stderr line at most `PrintedRepeats` = 3 times per coalescing window. So that run's fault message was suppressed (its output stayed untouched), and its "outside the snapshot" check failed for that reason alone. I dropped that run; the `0x20` arm stays in the shader's Phi shape.

## FormatVersion: no change (stays at 38 on this branch)

**Only shapes that refused before plan differently:**
- **The low-word walk** is the old one when no `BitwiseAnd32` arm is present: the same order, the same comparisons, and the same origin (`reads.back()`).
- **The AND arms** are new acceptances. Before, `ScalarReadMemory` failed on them and the column was refused.
- **A single-read high word** goes through the same offset + 4 and `SameRecordColumn` check, and gives the same table handle and record offset as with b91f0508d.
- **A Phi or AND high word** was refused before (`ScalarReadMemory` on it fails).
- **Unchanged structures:** `TableColumn` and the plan encoding didn't change.

**A refusal is never cached:**
- In `Recompiler.cpp` on aed137caee, `ResourceProgram` is built in a `try` (~455). The `catch` stores the exception only in the in-memory `CachedSource::planFailure` (~459, under `APS5_NO_FAILURE_MEMO`) and rethrows.
- `ShaderDiskCache::StorePlan` runs only after a successful build (~462). Emission failures are likewise memoized only in memory (~1088).

So a shader the old code refused has nothing on disk to reuse.
