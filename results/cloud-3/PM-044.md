## 1. #6457: host imports as aligned blocks, refusals remembered

### 1.1 Sibling paths on main

These are every call into the import paths at the PR head. "Block" means `importRun` may hand the caller an aligned power-of-two block of adjacent registered ranges instead of one range.

| Caller | Requester | May evict | Block | Refusal remembered |
|---|---|---|---|---|
| `ImportMappedRanges` (map time) | map | no | yes | yes |
| `AcquireRegistered` (address-based build walk) | build | no | yes | yes |
| `UploadFinish` region import | build | yes | yes | no |
| `importJoined` (join at bind) | join | yes | no | no |
| `importAccess`, called by `HostImportFor` | access (the default) | yes | yes | no |
| `StorageTexture::importSegments` (write-back segments, `Texture.cpp:2625`) | segment | yes | yes | no |
| Other `HostImportFor` callers, on the default requester | access | yes | yes | no |
| Step-down inside `importRunAt` | the caller's | the caller's | smaller block | the caller's |

**The other `HostImportFor` callers** are:

- `StoreUncompressedOnGpu` (DCC);
- `materializeCmaskClear`;
- `InPlaceDrawInput`;
- `captureInputs`;
- `Draw`'s indirect arguments;
- `StorageTexture::Refresh`, `upload`, `CopyFrom` and `writeBackLayers`.

**The step-down cases** are:

- a held import halves the block;
- a refusal retries at `min(bytes / 2, room)`;
- a failed block goes to `failedBlocks` and is retried smaller.

What I checked for each path:

- **Refusals are remembered only for the two requests that may not evict**: map time and the build walk. Evicting requests always try again. That is the PR's stated rule, and `stillRefused` lets a request through as soon as the budget changes or live bytes drop below the refusal's.
- **The map-time pre-check covers the whole block.** `ImportMappedRanges` asks `wouldRetireImport` and `AnyPendingOverlaps` about the full block `importRun` would make, not just the one range, before it imports.
- **Reusing a covering block is safe.** A request that an existing block already covers gets that block (`findImport`), whatever requester made it, and it is counted once, under its maker. A block holds only registered ranges of one run, and refresh drops it when the run changes (`sameRun`).
- **Pipelined draws.** Main pipelines 8 draws deep by default (`DrawPipeline::Depth`, `APS5_PIPELINED_DRAWS` unset). A block never replaces an import that a build in flight holds (`pointerHeld`: last use at or after `buildFloor`); it steps down to half instead. Joins may replace held imports, as on main. Both suites below ran at the default depth.
- **The write-back's first try is tagged access, not segment.** `writeBackLayers` first looks the whole surface up as `access`. Only its per-range fallback is `segment`. This matches the PR's definitions: "segment" is a write-back segment; a whole-surface lookup is an access, like `Refresh`, `upload` and `CopyFrom`. `agc_storage_writeback_blocks` counts segments that way. It is not a gap.
- **The block shape is platform-neutral.** Only the page walk, the alias and settle differ on Windows (§4).

### 1.2 Gap: the expand requester no path uses

- **What.** `ImportRequester::Expand` ("expand: a DB expand's store", per `5f532117d`) is declared, named and counted, but no caller passes it, so it can never count.
  - Main has no DB expand.
  - The open DB expand change (#6146, `25594523ae`) stores its planes only where imports already hold them, through `HostImportOverlaps` and the storage write-back. Its `67a68a167` is titled "store expanded planes without making or evicting host imports".
  - So the shutdown line `[gpu] host imports at shutdown` always ends `, expand 0/0/0`, naming a path that does not exist.
- **Fix:** `05474d199` removes the enum value, its name and its report column (3 files, +4 −5). `ImportRequesterCount` goes from 6 to 5. If the DB expand ever makes its own imports, it can add a requester then, together with a caller.
- **Red** (the PR head with only the new test expectation), in `agc_driver_graphics`:
  `AGC graphics: the host import report is wrong: 3 live (3.0 MiB); made 8 (5.1 MiB), refused 7 (3.5 MiB, 4 remembered), failed 3; by requester (made/refused/failed): map 2/0/0, build 5/7/1, access 0/0/0, join 0/0/0, segment 1/0/2, expand 0/0/0`
- **Green** (`review/6457`): these all pass:
  - `agc_driver_graphics`;
  - the 7 other host-import tests and `agc_driver_storage_write_back_overhang` (1 skipped: `agc_host_import_sparse`, as on the PR head);
  - `agc_storage_writeback_blocks`, the one test that loops over `ImportRequesterCount`;
  - `agc_driver_bda_device` and `agc_driver_bda_span_reads`.

### 1.3 Adversarial: what would a better version do?

- **Upgrade blocks lazily.**
  - When a run grows one range per build in ascending order (case A, §1.4), every build re-imports the bigger block. That is 16 MiB imported to end with 4 MiB.
  - A better version would wait until a run stops growing before upgrading, or would import the window-sized block at once when the window fills.
  - I'd argue this is deliberate scope:
    - in a run that only grows, each byte is imported at most once per block size: log2(window ÷ alignment) + 1 = 8 times here, and 4 times on average in case A;
    - each build makes one import;
    - titles mostly register large ranges at once.
  - No commit.
- **Remember refusals by range identity.**
  - Each remembered refusal copies its `Mapped` range list.
  - Keeping the run's generation instead would shrink §1.4's 1.54 MiB. At 12,000 ranges that is not worth the change. No commit.
- **The expand tag** is closed by `05474d199`.
- **Measure Windows settle with blocks.** Bigger blocks reach the settle floor more often (§4). Only the PC can measure this.

### 1.4 Worst-case cost

These ran on mock Vulkan through a scratch harness (`PM044_COSTS`, not committed) in the `agc_driver_graphics` binary, with an 8 MiB window and 64 KiB pieces. They match GAC-026's mock cases.

| Case | Builds | Imports made | Imported | Live at the end | Per build |
|---|---|---|---|---|---|
| A: register 64 pieces one per build, ascending | 64 | 64 | 16.00 MiB for a 4 MiB run | 1 | 72.1 µs |
| B: then remove 32 pieces one per build | 32 | 32 | 7.00 MiB | 1 over the rest | 61.6 µs |

Refusal memory: 12,000 registered 4 KiB ranges, with the budget set to fit 60% of them, then one address-based build:

| Ranges | Remembered refusals | Range references | Memory |
|---|---|---|---|
| separate (gaps between) | 4,800 | 4,800 | about 0.48 MiB |
| contiguous | 8,719 | 52,880 | about 1.54 MiB |

- **Bounds.**
  - A range sits in at most one refusal per block size: log2(8 MiB ÷ 4 KiB) + 1 = 12.
  - Entries are dropped on refresh when the budget changes, when live bytes fall below a refusal's, or when a range changes.
- **Verdict: no fix needed.** Neither cost is unbounded. The amplification in case A trades imported bytes for 64× fewer live imports, so it is the design working as intended, not a leak.

## 2. #6470: pixel shaders the guest does not iterate run once per pixel

### 2.1 Sibling paths on main

Every way a pixel shader reaches a sample input, at the PR head:

| Path | What the PR does | Covered by |
|---|---|---|
| ANCILLARY's sample number (bits 8-11) | `SampleId` only when iterated (`PS_ITER_SAMPLE` on an MSAA draw), else constant 0 (`ConstantFolder`) | `agc_driver_pixel_ancillary_word`, `agc_driver_pixel_sample_iteration` |
| PERSP_SAMPLE, LINEAR_SAMPLE | `InterpolateAtOffset` at sample 0's location (once per pixel), or at the `SampleId`'s entry of a table of the guest's locations (iterated) | module and execution tests |
| PERSP_CENTER, LINEAR_CENTER in an iterated shader | offset 0, so they stay at the pixel centre | module tests |
| POS_X/Y_FLOAT | follow `SPI_BARYC_CNTL` (centre, sample, ULC); a non-iterated shader's "sample" is the centre plus sample 0's offset | execution test (11 draws) |
| Sample-rate shading (`sampleShadingEnable`, `minSampleShading` 1.0) | still only from `state.perSampleShading` = MSAA and `PS_ITER_SAMPLE`; a non-iterated shader no longer gets `SampleId` or `SampleRateShading` | module tests |
| `Sample` decoration, `SamplePosition` built-in | emitted nowhere, on main or the PR | grep |
| Native barycentrics (`fragmentShaderBarycentricEnabled`) | `BaryCoordKHR` with the offsets | module tests here; execution needs the 3070 (§4) |
| Geometry-stage barycentric emulation | offsets apply to the emulated barycentrics | execution test, which runs emulated on this lavapipe |
| Device without `sampleRateShading` | no offsets, default position | module test |
| Host interpolation (no usable barycentrics, MoltenVK), centroid pairs, POS_Z/W | keep the host's default position | documented in the PR's debt entries |
| Draw cache: register key `sameDecode`, `lookupDraw` mixes, compile cache key, request serializer v31, FormatVersion 39 | carry `iteratesSamples`, `positionLocation` and `sampleLocations` | `request_serializer`, `agc_driver_graphics` |
| Registration-time preparation (`ShaderRegistry.cpp:830`) | has no draw MSAA state, so an MSAA draw that reads sample inputs misses the prepared module and compiles at the draw | performance only; the same class as quad masks on main |

`PixelSampleLocations` returns zeros for a draw without sample inputs, and `positionLocation` is read only when the shader loads POS_X or POS_Y. So in a non-iterated draw, a shader that reads neither still has a single key, as on main. §2.2 covers iterated draws.

### 2.2 Adversarial: what would a better version do?

- **Pass sample locations as specialization constants**, like `RasterPrimitive` and `LayerExported`, not in the request and the key.
  - Then one module would serve every location pattern.
  - As written, each distinct pattern compiles its own module, but only for shaders that read PERSP_SAMPLE, LINEAR_SAMPLE or a sample position.
  - A title that jitters programmable sample locations through many patterns would compile one variant per pattern. Checkerboard rendering, with two patterns, costs two.
  - Correctness is the same either way. Changing it means pipeline-creation plumbing and changes to `DrawRegisterKey`, so it is deliberate scope. It is worth a follow-up only if a title shows many patterns.
- **Pack the locations into the key.** The 32 location bytes take 32 key words (`append` per element, as `quadSampleMask` does). Packed, they would take 4: 224 bytes less per pixel key, and the +40 ns in `lookupDraw` (§2.3) would drop to noise. No commit, because:
  - the cache key is built per request, not per draw;
  - `lookupDraw` mixes only with the register key off.
- **Key `iteratesSamples` only when it changes the module.**
  - `DrawDecode` sets `iteratesSamples` for every iterated draw. The other new fields depend on the shader's inputs:
    - `positionLocation` is read only when the shader loads POS_X or POS_Y;
    - `sampleLocations` only when it reads sample barycentrics or sample positions;
    - `rasterPrimitive` and `layerExported` only when it reads the ancillary.
  - The translator uses the flag only for the ancillary's sample number, barycentrics and positions. So a shader that reads none of these compiles the same SPIR-V either way, yet gets a second key, and a second compile, if it also runs in an iterated draw.
  - Iterated draws are rare, and such shaders rarer, so I'd leave it. Conditioning the flag in `DrawDecode` would tie the decoder to the translator's list of iteration-dependent inputs.
- **Prepare MSAA sample-input shaders at registration.** That would need the draw's MSAA state at registration. It is the same gap main has for quad masks, so out of this PR's scope.

### 2.3 Worst-case cost

Measured on lavapipe with a scratch bench:

- 64 instances of a triangle over half of a 64×16 target, at 4x MSAA;
- a pixel shader that only reads the barycentrics;
- each case compiled with offsets (the PR) and without;
- both builds used geometry-stage emulated barycentrics.

| Shader | With offsets | Without | Change |
|---|---|---|---|
| Iterated, PERSP_SAMPLE | 3,875 to 4,627 µs/draw | 3,360 to 3,826 µs/draw | +17.6% median over 9 runs (+11.6% to +32.1%); +614 µs median, about 5 ns per sample invocation |
| Iterated, PERSP_CENTER | 3,409 to 3,853 | 3,526 to 3,772 | −6.4% to +2.1%, noise |
| Once per pixel, PERSP_SAMPLE | 1,467 to 1,612 | 1,451 to 1,595 | +1.1% to +2.2%, noise |

- **Module size:** +151 words (iterated PERSP_SAMPLE), +10 (iterated CENTER), +24 (once per pixel).
- **Table storage:** storing the table through `OpStore` and declaring it with an initializer measured the same (the bench's store and init variants).
- **Cache key:** +34 words per pixel-stage key: `iteratesSamples`, `positionLocation`, and 32 location bytes.
- **Draw lookup:** `lookupDraw` mixes 34 more values, but only when the register key is off (`APS5_NO_DRAW_KEY`).
  - Measured on a 200-mix key, that is +40 ns per lookup (median of 9 runs, +28 to +57 ns).
  - Packing the 32 bytes into 4 words would cut it to about +9 ns, within noise.
  - With the register key on, the default, `sameDecode` compares the three new fields along with the pixel fields it already compared.
- **The PR's gain dwarfs these costs.** On the same bench, a non-iterated shader that reads sample inputs runs once per pixel at about 1,500 µs/draw, against 3,600 µs/draw iterated: 2.4× less work. On main it was forced per-sample.
- **Verdict: no fix needed.** The +17.6% applies only to iterated shaders that read PERSP_SAMPLE or LINEAR_SAMPLE, which need the offset to be right.

## 4. Windows

- **Why nothing ran on the Windows runner.**
  - `build.yml`'s Windows job runs only on a push to main, or on a `workflow_dispatch` from main with PR numbers. Its eligibility gate is `pull_request` or `refs/heads/main`, and the job itself only runs on a push or a dispatch.
  - From the fork, that would need a PR (the task says open none) or a push to the fork's main (not a named branch).
  - A maintainer could run it upstream with "Build" → `pr: 6457 6470`. I posted nothing upstream.
- **What the runner could check anyway.** `check_skips.py --job windows` accepts "any agc* test, which the runner has no Vulkan driver for". So every test either PR adds or changes is skipped there.
  - Its configure also limits `ANYPS5_AGC_EXECUTION_TESTS` to three tests, so `agc_driver_pixel_sample_iteration` is not even built.
  - The runner would compile both PRs and run the non-agc tests (#6470's `request_serializer`).
- **Stand-in here.** I ran mingw-w64 GCC 13.2 `-fsyntax-only` with the Linux build's flags; CI uses WinLibs GCC 15.2.
  - #6457's `GuestBufferMemory.cpp`, `Texture.cpp`, `tests/BdaResources.cpp` and `tests/Recorder.cpp`, on main, the PR head and `review/6457`: 0 errors. `Texture.cpp` has 2 unused-variable warnings on all three, from main.
  - All 22 `.cpp` files #6470 changes, plus its new execution test: 0 errors.
  - One shim: mingw-w64 11's headers lack `PROCESSOR_RELATIONSHIP::EfficiencyClass`, which `CpuTopology.hpp` reads. Neither PR touches that header, so `Reserved[0]` stands in for it in the scratch copies only.
- **What needs the PC's 3070, #6457:**
  - **The page walk.** `VirtualQuery` runs over a whole block: an uncommitted or guarded page anywhere in it fails the block (`failedBlockImport`), and the import is retried smaller.
  - **The alias step-down.** When `GuestArenaMapAlias` throws for a multi-range block, `failedBlocks` records it and a smaller block is tried. Only Windows reaches this. The PR's mapped-views block test (`importBlockMapTests(context, true)`) is `#ifndef _WIN32`, so nothing covers it on Windows.
  - **Settle.** Watched private imports at or above `settleFloorBytes` go through `settleImport`. Blocks are bigger, so they reach it more often. Its cost per import is the number to read.
  - **Command:** `ctest -R "^(agc_driver_graphics|agc_storage_writeback_blocks|agc_driver_host_import.*|agc_host_import.*|agc_driver_storage_write_back_overhang)$"`, then one title run, reading `[gpu] host imports at shutdown`.
- **What needs the PC's 3070, #6470:**
  - **Native barycentrics.** The 3070 has fragment-shader barycentrics, so `agc_driver_pixel_sample_iteration` takes the native `InterpolateAtOffset` path there. Here it ran the geometry-stage emulation, and the native path is covered at module level only.
  - **Command:** `ctest -R "^(agc_driver_pixel_sample_iteration|agc_driver_sample_mask_multisample|agc_driver_pixel_ancillary_word)$"`.
