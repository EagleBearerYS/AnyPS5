## 2. The test (661d3cba8d)

**Where:** `agc_driver_prepared_shaders_abi_deferred_undecodable_state`, which runs `agc_driver_prepared_shaders_tests --abi-deferred-undecodable-state`.
- The function is `AbiDeferredUndecodableState`, at `tests/execution/PreparedShaders.cpp:919`. It sits right after #6366's four "deferred at its ABI call" modes and joins their `foreach` in `CMakeLists.txt`.
- So it gets the same environment: `ANYPS5_NO_SHADER_CACHE=1` and `APS5_NO_FAILURE_MEMO=1`.

**The shader:** `DescribeFront`'s vertex shader (type 2). Its specials route it through geometry, like a real GS-type header:
- `VGT_SHADER_STAGES_EN` = 0x2030 (ES_EN 2, GS_EN, PRIMGEN_EN);
- `GE_CNTL` 0x25b = 0x8040;
- `VGT_GS_OUT_PRIM_TYPE` 0x29b = 1 (lines);
- `GE_USER_VGPR_EN` 0x262 = 0.
- Its context register 0x2ce, which the decode reads as vertices per primitive, is 3.

**Registration leaves it alone.** `PlanRegistered` returns no plan for a geometry routing at registration (`ShaderRegistry.cpp:810`). So nothing is prepared before the ABI call, and the background preparation pool is not involved.

**The call:** `AgcDriverResolveGraphicsStagesAbi_nid_postfix(stages, context, primitive)` with the registers `sceAgcCreatePrimState` passes for a GS-routed stage (`core/libs/prx/libSceAgc/Shader/src/PrimState.cpp:44-61`):
- context: `{VGT_SHADER_STAGES_EN, VGT_GS_OUT_PRIM_TYPE}` from the specials;
- primitive: `{GE_CNTL, GE_USER_VGPR_EN, VGT_PRIMITIVE_TYPE 0x242 = 4}`.

**Only VGT_GS_OUT_PRIM_TYPE is refused.** The combined state reaches the check at `Graphics/src/State.cpp:879` with a triangle-list input and 3 vertices per primitive, so the output type is the only failing term.
- Control (local only, not committed): with 0x29b = 2, the decode gets past that check and refuses at the next one (`:881`, `invalid geometry subgroup output`), because GE_MAX_OUTPUT_PER_SUBGROUP is 0 here.

**What it checks:**
1. The call does not throw. It logs exactly one deferral line, and the line carries the decode's reason, `VGT_SHADER_STAGES_EN=0x2030: unsupported geometry input or output assembly`.
2. A second identical call makes no front-end build (`ShaderRecompiler::FrontEndBuilds()` is unchanged since before the first call) and logs no second deferral line.
3. A DCB draw then routes the stage through the vertex path: `VGT_SHADER_STAGES_EN` 0x2000, the null pixel shader, a three-vertex triangle list.
   - The draw submits and `WaitIdle` returns.
   - `FrontEndBuilds()` grows, because the stage is prepared at its first use.
   - The draw's log has no "has no artifact prepared at registration" line.

**Check 3 sees the deferred flag itself, not just the log line from check 1.** `ReportPreparedAtUse` (`ShaderRegistry.cpp:456`) stays quiet only for a deferred stage. A local variant that skips the ABI calls fails check 3 with:

```
[Shaders/ShaderRegistry.cpp:456 ReportPreparedAtUse] Shader 0x560d05f82000 stage 1 has no artifact prepared at registration for the state of this draw or dispatch; preparing it at use
```

The null pixel program logged nothing in either run, so the build that check 3 counts is the vertex stage's.

## 5. Notes for the PR Manager (no change made for these)

**No ABI key on a refusal.** A refused decode records no ABI key, unlike a failed preparation.
- So a repeated call with the same state decodes again and throws inside again, still preparing and logging nothing.
- The cost is one decode and one caught exception per repeated pipeline-creation call.
- The upside: if the program decode refused because a program was not registered yet, a later call can prepare it.
- It is fine as it is.

**ARCHITECTURE.md doesn't cover the decode case yet.** Its bullet from 8c55d15aa says the ABI key is recorded, so a repeated call prepares nothing. If wanted in the follow-up, one sentence would cover it:
> A combined state that `ResolveGraphicsStagesAbi`'s stage or program decode refuses defers every stage of the call the same way; no ABI key is recorded, so a repeated call decodes again and still prepares nothing.

**The test's draw differs from the game's.** It routes the stage through the vertex path; Resident Evil Village (PPSA01556)'s draws keep their geometry routing.
- The PC's `APS5_DEFER_ABI_PREPARE=1` experiment reached control past the same point, so those draws decode their own state.
- A draw whose own state is refused fails there with the decode's message, as #6366 already does for a stage that cannot be prepared.

## 6. Paragraph for #6366's description

> **A pipeline ABI whose state does not decode also leaves its stages to their first use.** Resident Evil Village (PPSA01556) aborted in its save load, before control, with `AGC graphics: VGT_SHADER_STAGES_EN=0x2030: unsupported geometry input or output assembly`. `sceAgcDriverResolveGraphicsStagesAbi` decodes the stage routing and programs from the stages' registered state and the call's context and primitive registers before it prepares anything, and `DecodeShaderStages` refused that combined state outside the preparation this PR already guards. A refused decode now defers every stage of the call like a stage whose preparation fails: each is logged once with the decode's reason and prepared by the draw that uses it, which decodes its own state; a repeated call prepares and logs nothing. `agc_driver_prepared_shaders_abi_deferred_undecodable_state` resolves a geometry-routed vertex shader whose `VGT_GS_OUT_PRIM_TYPE` the decode refuses, with the registers `sceAgcCreatePrimState` passes: without this commit the exception leaves the call, and with it a later draw prepares the stage at its first use.
