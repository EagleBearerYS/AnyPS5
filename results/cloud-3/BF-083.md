## 4. The `[draw-relocate]` line

**In the plain ctest run, no line prints.** `APS5_PROFILE_DRAW=1 ctest -R '^agc_driver_draw_cache' -V` gave rc=0 with 5 of 5 passing, but no `[draw-relocate]` line. It prints no `[draw-cache]` report either. Each test process lasts about 0.2 s. Both lines print from `maybeReportDrawCache`, on a draw-cache lookup at least 10 s after the driver's counters were created or last reported. The other trigger, 100,000 relocation lookups, is never reached either.

**So I ran a local timing probe,** uncommitted and reverted afterwards:
1. In `tests/execution/DrawCacheRelocation.cpp`, I added `std::this_thread::sleep_for(std::chrono::seconds(11));` before `MovedForwardedWordReachesStageDataHit(libraries);` (and the `<chrono>` and `<thread>` includes).
2. I rebuilt `agc_driver_draw_cache_relocation_tests` and ran `APS5_PROFILE_DRAW=1 ctest -R '^agc_driver_draw_cache_relocation$' -V`. It passed, and the first draw after the pause printed the 10 s report:

```
414: [draw-cache] 49 lookups (10 s): 37 no entry, 12 validated in 12.0 us each (key, lookup and every stage): 17 hits (every stage equal; …), … 5 inserts (10 variants inserted, 0 evicted beyond k, 0 already present, 0 unstable), 5 entries (10 variants, ~0.0 MiB), 0 evictions in total, 0 LRU moves; verify: 0 hits captured again, 0 stages differed
414: [draw-relocate] 32 alias lookups: 5 donors with moved user words, 0 refusals, 5 hits through a relocated entry; 2 shader sets learned, 3 aliases held (0 dropped at the limit) holding 3 entries, 0 of them no longer in the draw cache
```

This shows three things:
- the line prints with the draw cache's 10 s report, in the same lookup;
- it carries "holding N entries, M of them no longer in the draw cache";
- the relocation test does produce relocation: 5 donors and 5 relocated hits.

M is 0 here because the test never evicts. With the probe reverted, `git status` was clean at 604596a88 and the test target was rebuilt from the branch (rc=0).

**For the Village run,** the line needs `APS5_PROFILE_DRAW=1`, and the first one comes with the first draw-cache report, on the first draw-cache lookup at least 10 s after the driver is created. It resets its counts each time it prints, so each line covers the last ~10 s. The alias and entry counts are the live totals.
