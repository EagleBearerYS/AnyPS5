## The rule as implemented

Line numbers are at 219e925509.

- **Colour target identity** (`MultisampleTarget.hpp/.cpp`):
  - `MultisampleColorAlias` gains `active`, the target's identity pointer that the guard ranges already share.
  - It also gains `contents`, a counter the target bumps at every clear (`ApplyFastClear`), `Recreate`, draw mark (both `MultisampleTargetView` overloads, `MultisampleTargetOrderTarget`) and storage view.
  - New `MultisampleColorTargetsOver` returns every distinct colour target over a range. `MultisampleColorTargetOver` now returns its first entry, which is the same result as before: the oldest guarded range's target.
- **`prepareDepthSampling`** (`DepthSurface.cpp:184-190`): at index 0 with a depth-only HTILE, the alias is accepted when exactly one colour target covers the depth plane and it has the target's sample count.
  - It calls `reportAlias(..., "depth")` and records the alias, with its `active`, `contents`, newest content and value, in `DepthSamplingState::depthAlias`.
  - The function then goes on to the HTILE check (`:213-217`), which still refuses unless every word proves the clear against `target.clearDepth`.
  - Any other alias over the depth plane takes the old path and refuses with `depthAliasRefusal`.
- **`CheckCurrent`** (`:450`): at index 0 the alias passes only when exactly one colour target covers the plane and it is the recorded one, with the same `contents`, newest content and value.
  - An absorbed fill changes the newest content and value before it is taken, so a fill of another value also refuses.
  - Anything else reaches the existing `reportAlias` and `depthAliasRefusal`.
- **Unchanged:** HTILE aliases (index 1), the stencil-plane rule (index 2, `aliasedStencil` and `unprovenStencil`; `planeAliased` is still set only there), and every other refusal.
- **Why exactly one target:** `guard()` appends ranges without retiring older overlapping targets, and `MultisampleColorTargetOver` returns the oldest. A new target over the plane next to the recorded one would otherwise be invisible to `CheckCurrent` (case 8).
- **Debt:** #9533's "Native multisampled depth sampling" entry in `docs/dev/debt/libSceAgcDriver.md:26` changes in two places.
  - "any colour target over the depth or HTILE" becomes "any colour target over the HTILE".
  - One sentence is added: "With a depth-only HTILE, one multisampled colour target of the target's sample count over the depth plane is accepted once every HTILE word proves the clear, because every depth sample then reads `DB_DEPTH_CLEAR` and none of the colour target's host-only samples, and it refuses at the next sample once that target clears or draws again or another colour target covers the plane; an alias over tiles HTILE does not prove still refuses."

### What "the import" is

- **Recording:** the alias is recorded when sampling eligibility is recorded. That is `prepareDepthSampling` at the target's first `DepthSurfaceView`, before its first host clear, which is #9533's "initial import".
- **Checking:** `CheckCurrent` runs at every sample (`CachedSampledTexture`) and at a stencil-tested bind.
- **Case 10:** "before the import" therefore means before the first `DepthSurfaceView`. That case passes.
- **Draw after the view:** a draw into the alias after the view refuses at the next sample, even before the first sample and even while HTILE still proves every tile. That is the rule as written ("no newer content since the import"), kept strict. On the console, depth would still read `DB_DEPTH_CLEAR` in that order until a depth write expands a tile, and that is not tracked here.

## Tests

ctest `agc_driver_native_depth_aliased_depth` (`--aliased-depth`) is registered next to `agc_driver_native_depth_aliased_stencil` with TIMEOUT 30, `ANYPS5_NO_SHADER_CACHE=1`, SKIP_RETURN_CODE 77 and the WIN32 PATH prepend. The code is in `CheckAliasedDepth` in `NativeMultisampleDepth.cpp`.

### Shape shared by every case

1. A 5x3 D32S8 target with a separate stencil plane, a pipe-aligned depth-only HTILE and ITERATE_256. Every initial HTILE word is the proving word, and the stencil plane is 0.
2. An R32F colour target (vk format 100, tile mode `RenderTarget`, guarding 0x10000, the whole plane) at the depth plane's address.
   - It is created with `MaterializeMultisampleTargetClear`, given a whole-target fill it absorbs (`MultisampledColorFillAbsorbs` plus both notes), and materialized again.
   - Its newest content is then a clear, like GoT's `newest clear 0` log line. The test asserts this, along with the alias's address, range and sample count.
3. `DepthSurfaceView`.
4. Whole-range fills over the HTILE and the stencil plane through `NoteDepthMetadataFill`, `NoteColorMetadataFill` and a tracked store, the calls `PacketMemory.cpp` and `BufferFill.cpp` make.
5. `CachedSampledTexture`, then one dispatch reading every sample of every pixel (`FetchShader`, float). It expects (DB_DEPTH_CLEAR, 0, 0, 1) in each, never the alias value.
6. The guest depth plane (0x5c) and stencil plane (0) must be unchanged at the end.

### HTILE words

Both DB_DEPTH_CLEAR values run. On a depth-only HTILE, `htileProvesClear` takes the whole word as depth:
- word 0 proves only 0.0;
- word 0xfffffff0 proves only 1.0;
- a word with ZMask 15 proves nothing.

So the task's literal case 1 (DB_DEPTH_CLEAR 1.0 with fills of 0) is the mismatching-clear control, and it refuses. Instead:
- **DB_DEPTH_CLEAR 0.0:** the HTILE words and fill are 0x00000000. This is GoT's literal fill of 0, with the alias holding 0.25.
- **DB_DEPTH_CLEAR 1.0:** the HTILE words and fill are 0xfffffff0, with the alias holding 0.25, so its value still doesn't match.
