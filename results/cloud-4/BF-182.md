## The change (a765ccece)

**What changed in `TryMakeTableColumn`'s nested branch:**
- A user of the V#'s words that is not a buffer handle is now accepted when both hold:
  - the V# is rereadable (`RereadableVsharp`: its four words are `LoadAddressU32` through the record pointer, and not planning-only);
  - the user's uses reach no `GetBufferResource`, `GetAddressResource`, `GetImageResource` or `GetSamplerResource` (new `DataWord`, a walk over uses).
- `PlanTableColumnPass` marks a read planning-only only when every user is a planned handle. So V# A's loads stay emitted for such a user, which reads the guest's V# at dispatch, while the T# and S# take the snapshot.
- If a lane takes the T#-words arm, the image table still faults outside the snapshot.

**Still refused:**
- a V# word that reaches a handle (tested: a read through a V# built from V# A's words with dword 1 masked);
- the key-word and data-read forms (#9969's pinned tests, still green);
- stores through the V#, and other V# origins.

**Debt doc:** the "Nested image tables" entry now says that a V# word used only as data is read again through the guest's pointer at dispatch. It was reworded to stay at 996 characters, so there is no `debt-length` warning.
