### Should fix: JSON memory had no bound but the 256 MiB file cap (fixed, 7db47af9d)

**Code at 9b17080b06:**
- `core/libs/prx/libSceNpTrophy2/src/TrophyPackage.cpp:13`: `MaxJsonDepth = 64` is the reader's only limit.
- `:77` `readValue` builds an 88-byte `Json` for each value; `:125` and `:137` append members and items with no count limit.
- `TitleTrophies.cpp:40`: the only size bound is the file's 256 MiB (`MaxUcpSize`, `TitleTrophies.hpp:19`).
- `TitleTrophies.cpp:52` and `:62`: `loadTitleFile` catches only `std::runtime_error`.

**Evidence:** peak RSS from parsing a `tropconf.json` padded with `"pad":[0,0,…]` inside a valid package, with the package's own `ParseTrophyPackage`, `-O2`:

| tropconf.json | 9b17080b06 | head |
|---|---|---|
| 4 MiB | parsed, +177 MiB (44.4 bytes per input byte) | |
| 16 MiB | parsed, +710 MiB | refused, +94 MiB (`"0,"`) or +134 MiB (`"":0,` members) |
| 64 MiB | parsed, +2752 MiB | |
| 128 MiB | parsed, +5504 MiB | |
| 255 MiB | under `ulimit -v 8 GiB`: **`std::bad_alloc`, not a `runtime_error`** | refused, +0 MiB beyond the file |

- At 255 MiB the items vector alone reaches 2^27 × 88 bytes = 11 GiB, and growing it needs 17 GiB of address space.
- With more memory than that, the title takes it. With less, `bad_alloc` escapes `loadTitleFile` and stops the game at its first trophy query or UDS event, or the OOM killer ends it.
- The only realistic source is a crafted or modded file. A game's own JSON files are small: 1000 trophies at about 30 values each is 30000 values. Still, USAGE says "A missing or malformed `trophyNN.ucp` or `udsNN.ucp` turns off only what it provides", and this was the one way a file could do more.

**Fix:**
- `TrophyPackage.cpp:14` `MaxJsonValues = 1 << 20`.
- `:80` counts each value and fails past the cap, with "the document holds more than 1048576 values". Like any malformed file, the title then runs without it.
- The cap is 35 times the largest trophy file this format allows. A stats file near it would need about 100000 statistics.
- `docs/dev/debt/libSceNpTrophy2.md` gains a "Trophy data limits" entry: the four limits, what a title does past them, and that the console's limits are unknown.

**Test** (`tests/TrophyPackage.cpp:184-189`, `:248-254`, in `np_trophy2_package`):
- exactly 1048576 values parse;
- 1048577 are refused with the message;
- a `tropconf.json` padded past the cap is refused as "tropconf.json is not JSON: the document holds more than 1048576 values".

**Red/green:**
- **Red:** with 9b17080b06's `TrophyPackage.cpp` and the new tests, `np_trophy2_package` "Subprocess aborted": "a document of more than 1048576 values was parsed".
- **Green:** with the fix, Passed (0.45 s).

### Notes, not fixed

1. **A stat update can be checked against a later value.** `NpTrophy2ApplyEvent_nid_no_patch` (`TitleTrophies.cpp:226` and `:237`) stores the event's values, then re-reads every stat to compare conditions.
   - Two threads posting the same stat at once can interleave: A sets 10, B sets 3, and A reads 3. A trophy that 10 reaches then stays locked until the stat reaches it again.
   - A fix is two lines: overlay `changes.updates` on `Values()` before `ReachedTrophies`.
   - Not done: the window needs concurrent posts of one stat, and no test can force the interleaving, so the fix would have no red/green.
2. **A trophy whose stat isn't usable never unlocks, and no line names it.**
   - This happens when `udsStatId` names a stat that has no supported definition (for example `"aggregation":"sum"`) or that no rule writes. Only the stat's own `[trophy]` skip line is printed.
   - With ce30ebdac1 a progressive trophy on such a stat can't unlock by any path: its posted unlock is refused.
   - One load-time line per such trophy would make this visible. This is the documented unsupported-aggregation gap, not a new one.
3. **A platinum that no trophy names in `platinumTrophyId` can never unlock.** A posted unlock is refused, and `PlatinumToUnlock` never selects it.
   - This follows KytyPS5 and the debt entry says so.
   - Whether real `tropconf.json` files always set `platinumTrophyId` can only be checked on real trophy data.
4. **A cosmetic error message.** With the console language en-US (the default), a package without texts says "no tropmeta_<language>.json for en-US, en-US or its defaultLanguage "en-US"" (`TrophyPackage.cpp:516`).
5. **Cost per event:**
   - `Uds::StatEvent` formats every property of every event (`Describe`), even for a title without stat rules.
   - Each changed stat rewrites `.stats.txt` (temp file and rename, no fsync) on the posting thread.

   This only matters at high event rates. Nothing was measured.

## The trophyNN.ucp reader (6a1b673a21)

**Bounds, `ReadUcp`** (`TrophyPackage.cpp:457-484` at 9b17080b06):
- It needs `data.size() >= 0x40` before reading the header.
- `size` must be from 0x40 to the file size.
- `count` is at most 4096, so `count * 0x40` is at most 256 KiB and can't overflow.
- `toc <= size` and `0x20 + count * 0x40 <= size - toc`, so every entry's name, offset and length fields lie inside `size`.
- Each file needs `offset <= size` and `length <= size - offset`, which can't wrap.
- A name without a NUL takes all 32 bytes. A repeated name keeps the first (tested).

**JSON reader:**
- `position` never passes the end: every read checks `position < size` or `size - position`, and `substr` is only called with `position <= size`, so its `out_of_range` can't happen.
- `\u` escapes need 4 hex digits, and surrogates must pair.
- Nesting deeper than 64 levels is refused before recursing further, so 100000 `[` costs 64 frames.
- Numbers keep their text. `Unsigned()` takes the full uint64 range and nothing else.

**Missing files:** a missing file is skipped, with a "[uds] … does not exist" line under `APS5_TRACE_UDS`. An unreadable path, a directory or a file over 256 MiB throws a `runtime_error`, which is caught: "[trophy] … is not used". The guest tests cover missing and malformed files for both kinds.

**Language fallback:**
- The order is the console language, then `en-US`, then `defaultLanguage`, all only as map keys. A `defaultLanguage` of `../../etc/passwd` is only a name to look up.
- An empty console language is skipped.
- `LanguageTag` covers 0 to 30, and `SystemServiceConsoleLanguage` refuses anything outside 0 to 30.

## Statistics unlocks (fd9dcd996f)

- **Aggregations:**
  - Only `"latest"` with `uint32`/`uint64` is used. Every other aggregation or type is skipped with a line (tested at unit and guest level).
  - `minValue`/`maxValue` must fit the type and be in order. Otherwise the stat and its rules are skipped.
- **Thresholds:** `UnlockCondition::Reached` uses `>=`, `>`, `<=`, `<` on uint64. The unit and guest tests check each comparator at, just past and just short of its target.
- **Repeated posts:**
  - `StatStore::Set` writes only a change.
  - `ReachedTrophies` skips unlocked trophies, and `TrophyStore::Unlock` refuses a second unlock under its lock.
  - The guest test checks that the listener sees each unlock once.
- **Out-of-order posts:** the latest post wins, even if lower (tested). An unlock is permanent. The one race is note 1.
- **64-bit values:**
  - Property values are uint64, or int32/int64 that are 0 or more.
  - A uint32 stat refuses values past 4294967295 (tested).
  - `Json::Unsigned` takes 0 to 18446744073709551615 and refuses 18446744073709551616 (tested).
  - `StatStore` stores uint64 (tested with 2^64-1 as a stat id).
  - `TrophyProgress` is `min(stat, target)` in uint64, `NpTrophy2Progress.value` is uint64, and nothing else does arithmetic on a value. `progress_percentage` works on counts: at most 1000 × 6 × 100 = 600000, which fits its uint32.
- **Locking:** `StatStore` and `TrophyStore` take their own mutexes. `Title()` loads once per service label under its mutex, and a load that throws is retried at the next call.

## The refusal (ce30ebdac1)

- `NpTrophy2RecordUnlock_nid_no_patch` is what UDS `_UnlockTrophy` calls. With trophy data, it refuses an id not in the data, a platinum, or a progressive trophy, and prints one line for each.
- The stats path (`TitleTrophies.cpp:238`) and the platinum award call the internal `RecordUnlock`, so neither is refused. The guest stats test unlocks a progressive trophy and the platinum that way.
- **Platinum recursion:** each step unlocks a new trophy, and `PlatinumToUnlock` refuses an unlocked platinum, so the depth is at most the number of platinums. A platinum naming itself stops at once.
- **After the merge,** the recursive `RecordUnlock` for the platinum takes PM-071's recursive dispatch lock a second time. That is allowed, and it can't deadlock with `Title()`'s mutex: nothing takes the dispatch lock while holding `Title()`'s.
