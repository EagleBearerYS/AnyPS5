## 2. What the kernel does: a probe on this VM

I wrote a standalone probe: 4 × 64 KiB of memory, uffd-wp async, write-protected. It writes page 0 and page 0x15000, remaps one page in the fourth block (`MAP_FIXED`), then runs `PAGEMAP_SCAN` with the agc flags (`PM_SCAN_WP_MATCHING | PM_SCAN_CHECK_WPASYNC`).

```
round 0: ioctl -1 errno 1 (Operation not permitted) walk_end +0x40000
  region +0x0..+0x1000
  region +0x15000..+0x16000
round 1: ioctl -1 errno 1 (Operation not permitted) walk_end +0x40000
```

- **On failure** the ioctl returns −1, but it has already written the dirty regions found before the remapped page into the output array, and re-protected those pages. Round 1 finds nothing.
- **`walk_end` says the range end** even though the walk stopped earlier, so it cannot locate the failure.
- **At 81ad915d78**, `scanWritten` ignored those regions and stamped `[cursor, end)` as CPU writes. Every genuine store before the failure was lost into the synthetic stamp, which is the bug the reviewers saw.

## 3. What I built

### 3.1 libc (`GuestWriteWatch.cpp`, `.hpp`)

**New exports:**
- `GuestWriteWatchCollectReporting_nid_postfix(address, bytes, written, unreached, context)`
- `GuestWriteWatchCollectArmedReporting_nid_postfix(...)`

The old `Collect`/`CollectArmed` now delegate with `unreached = nullptr`. Their `written` calls are unchanged, except that a failing scan now also reports the regions found before the failure, which lie inside the range it stamps anyway at the same generation.

**`scanWritten`:**
- The region array is zero-initialised, and re-zeroed after each successful call.
- On an ioctl error it reports each region the kernel wrote out (up to the first empty entry) through `written`. It then calls `unreached(cursor, end)`, then `written(cursor, end)`, which is the old conservative stamp.
- `[cursor, end)` is reported as unreached as a whole, because `walk_end` cannot be trusted (§2). Pages there that the kernel did walk and found clean are therefore compared rather than trusted; the regions it did find stay genuine.

**Other failure points:**
- `takeFresh` protect failure: `unreached` before the old `written` for `[begin, end)` (whole) or for each fresh range.
- `takeFresh` `!covers`: `unreached(begin, end)`, and as before no `written`.
- `CollectArmed` `!covers`: likewise.
- `CollectArmed` with a failing armed sub-range: that sub-range as above, and every later armed sub-range through `unreached` only. Today they get no stamp; their kernel dirty bits are not consumed.

**macOS:** the reporting exports call the existing collect and, on failure (`!covers`), report the whole range unreached.

### 3.2 agc tracker (`GuestMemory.cpp`, `.hpp`)

**`walkWrites` (Linux)** uses the reporting exports, with `stampUnreachedRun` as the second callback.

**Unreached marks:** `WriteTracker::unreachedPages` holds, per 4 KiB page, `{generation, before}`.
- `noteUnreached` runs before the synthetic stamp.
- `before` is the page's genuine CPU stamp at that moment: the `cpuPages` value, or the previous mark's `before` when that value is itself the previous synthetic stamp. A second failed walk therefore never turns an old synthetic stamp into a genuine one.
- A page already marked at the same generation keeps its first `before`. Regions reported earlier in the same walk count as genuine.
- Driver-kind and import-window walks record marks the same way; their synthetic stamps go where they always did.

**New overload `ChangedBlocks(address, bytes, generations, changed, cpu, unknown)`.** Per block with unit generation g:
- **g == 0:** unknown.
- **No unreached mark and no `refused` entry newer than g:** exactly today's `changed`/`cpu`, known.
- **Otherwise, CPU-confirmed (known, written, cpu)** when either holds:
  - a page has a genuine CPU stamp after g (its `cpuPages` stamp, or the mark's `before` when the stamp equals the mark's generation);
  - the block's CPU stamp is newer than every unreached or refused mark in it. Windows refused blocks carry no synthetic stamps, so their CPU pages count as genuine.
- **Else:** unknown.
- It returns false, as the old overload does, when the range isn't watched or covered.

**Unchanged:**
- The old overload and every complete-walk path.
- Other callers of unreached ranges still get the conservative CPU stamps; for example `VulkanDevice.cpp:844` ignores the collect's result.

**Test fake:** `tests/CollectMemoGeneration.cpp` gains the reporting export. Its old `Collect` fake delegates to it.

### 3.3 `StorageTexture::refresh`

`scanBlocks`: when `current == 0` and the new query answers, the new `compareUnknown` runs:
- It compares only runs of unknown blocks inside the scope, with `compareUntracked` (memoised as before) on the bytes saved at the upload or the previous store.
- Unknown blocks outside the scope stay written with cpu set, as today's compared path leaves them.
- `keptAtUnwatch` marks unknown blocks written, as today.
- A changed unknown block gets cpu = 1.
- Known blocks keep the stamps.

**Downstream:**
- `tracked` = true, `compared` = false, and the per-block `unknownBlocks` set the rest.
- `droppable(unit)` reads the compare result for an unknown unit and the tracked rule for a known one.
- `cpuWrote` counts compared blocks.
- The layer-mode recompute of `changed[layer]` from the blocks runs only for layers that touch an unknown block.

**Fallback:** if the query can't answer, or an unknown run can't be compared (no saved bytes), the code falls back to the whole-surface compare. That covers `!covers` and missing bytes.

### 3.4 `StorageTexture::writeBackLayers`, and the extra rule case B needed

On `!walked`, the new `compareUnknown` runs the query (with `cpuBlocks` sized for every block):
- If a selected unit with an unknown block has no saved bytes, it falls back to today's whole compare. That keeps the "outside the watch … throws" behaviour.
- Otherwise it compares only the unknown blocks of the selected units (runs inside `unitRuns`, OR-ed per block), and marks those units `compared`.

**Per block:**
- `byBytes` is `compared[layer]` on the old paths and `unknownBlocks[index]` on the new one.
- `unknown` is `layerGeneration == 0 && !compared` when tracked.
- The `drawn.rect` skip keeps the tracked rule only for known blocks.

**Finding, with controls.** The write-back has always left a stamped block to the CPU only when `!unchangedSinceBaseline(from, to)`, i.e. its bytes differ from the saved ones. That condition is already in the oldest history here, the initial import.
- I added two complete-walk control cases locally; they were not committed.
- **On 81ad915d78:** "complete walk, then a refresh" passes, but "complete walk, then a direct write-back" loses the store, in 3 of 3 runs: `guest memory holds 8 results and 0 stored words, the image 8 results and 0 stored words …`.
- **On the fix:** the same, 3 of 3. Only that control fails.
- So case B could not pass "as on a complete walk". The bytes check on a stamped block lets the results win.

**The rule I added for B,** limited to the failed-walk path: a known block whose CPU flag is set (`cpuSeen`) is left to the CPU whatever its bytes, as the refresh already does.

**Why there and not everywhere:** on the complete path the CPU flag also covers stamps that come from no store, such as a range returning to the watch or synthetic stamps of an earlier failed walk of a larger range. The bytes check is what keeps results over those. Changing it would widen the PR beyond the failed walk.

**Recorded as a new debt entry:** "Same-value CPU stores under a write-back of pending storage-image results". The PR Manager decides whether main's rule should change.

### 3.6 Edge cases left

- **Same-value store in a never-reached page:** a store whose page the walk never reached, of the saved value, is lost, because the block is compared by bytes. That is in the debt entry.
- **Clean pages reported unreached:** on this kernel the whole `[cursor, end)` is reported unreached, including clean pages the kernel did walk. Those blocks are compared rather than trusted, unless the walk saw a CPU store in them.
- **A failed walk of a larger range,** then a successful collect of the surface, still reads the synthetic stamps as CPU stores. The new overload could fix that if the complete paths used it; it is in the debt entry and was not changed.
- **Windows:** not built or run. `refused` is read by the new query, but no test reaches it, as the task said; it is in the debt entry.
