## Short version

- A scaled colour target that must reach guest memory, and a scaled depth plane stored through its mirror, now stay scaled. The store blits the scaled image into a temporary native-size image with the filter demotion uses, and reads that.
  - Covered: a CPU read-back, `FlushDepthPlanes`, and `StoreIdleResults` with pending results.
  - In each case: 0 demotions, the surface stays 1920x1080, and the next draw is still byte-identical to native 1920x1080.
- **Guest bytes of a scaled store = guest bytes of demotion then store**, byte for byte, colour (33,423,360 bytes, FNV `c0e138010e91b58d`) and D32 depth (33,423,360 bytes, FNV `833dac0549e9d545`). Two copies of the same stream in one run; one stores scaled, the other is demoted first.
- A guest write after a scaled colour store demotes it once (`GuestWrite`), and the guest's texels end up in the target.
- **Depth guest write after a store: blocked by a main bug, not by this change.** After any depth plane store (native or scaled), a CPU write to the plane is not seen, so it neither demotes nor reaches the surface, and the next store overwrites it. ## Which store paths stay scaled now, and which still demote

**Stay scaled (stored from a native copy, counted and logged):**
- **Colour: every `StorageTexture` store.**
  - All of them go through `writeBackLayers`:
    - `FlushPending` from CPU reads and the flush hook;
    - `FlushAllPending` from `StoreIdleResults` and the store-at-flip/label options;
    - cache eviction;
    - refresh stores;
    - the block-unit `writeBackWindows` path, including its compute retile that reads image views.
  - `writeBackLayers` (Texture.cpp) now opens a `NativeStore` scope when the image is scaled:
    - `blitImage` (split out of `swapImage`) records a blit of the scaled image into a new native image, LINEAR where the format can filter linearly, otherwise NEAREST, exactly as `swapImage` does on demotion;
    - the texture's image, memory, default view and every view cache are swapped to the native copy for the duration of the store;
    - at scope exit the scaled image and its views come back unchanged. The native image and every view the store created on it go into a `TransientImage` that the active recorder keeps until the batch completes, or that is destroyed at once when the store ran in its own waited batch.
  - The texture's `version` is not bumped, because its own image never changed.
- **Depth: `StoreDepthPlane`**, which is what `FlushDepthPlanes`, idle stores (`FlushAllPending` reaches `FlushDepthPlanes(0, max)`) and `retireStoringStale` use.
  - After the pending fast clear, a `NativePlane` scope blits the scaled plane to a native image with NEAREST and swaps the surface's `image` for `copyPlane`, then restores it.
  - The copy goes into the native mirror `StorageTexture` and from there to guest memory as before.
- **Ordering is safe for both store routes.** The blit is recorded into the active recorder. The CPU store route uses its own `CommandBatch`, whose constructor submits recorded work first, so the blit lands before the read.
- **Log:** `[render-scale] 0x<addr> stored scaled at its native size WxH (<n> scaled stores)`, first 16 then powers of two; counter `RenderScaledStores()`.
- `WriteBack` and `DepthWriteBack` no longer fire anywhere. They stay in the enum so the log names and counter layout don't move.

**Still demote (the guest's bytes or a native-size consumer become the authority), reasons and counters unchanged:**
- colour:
  - `GuestWrite` (upload after a CPU write, tested again here after a scaled store);
  - `StorageAccess` / `ComputeWrite`;
  - `TexelFetch` / `SizeQuery`;
  - `Copy`;
  - `MixedAttachment` / `DepthAttachment` / `FragmentPosition`;
  - `Presentation`.
- depth:
  - `DepthGuestWrite` (`SyncFromMemory`, `StoreBackCovering`, `TakeStorage`);
  - `DepthStorage`;
  - `DepthCopy`;
  - `StencilCopy`.

**"What we stored" is still recorded on the new path.** Both scaled stores run inside the existing store code, so its bookkeeping is unchanged:
- colour: `settle`, `original`, layer generations, `cancelStoredSave`;
- depth: `NoteStored(units, generation)` and the mirror's own state.

The tests prove the stored bytes are not read back as a guest write: after a CPU read-back, a depth store and an idle store, the next draw demotes nothing and still matches native.

## Temporary-image policy and memory cost

- **Freed, not pooled.** One native image per scaled store, freed when the recording that reads it completes (or at once when the store waited on its own batch). Views the store makes on it (the default view, the element views the retile dispatch uses) are freed with it.
- **Peak extra memory for one 3840x2160 target:** one native-size image while its store is in flight.
  - R8G8B8A8 or D32_SFLOAT: 33,177,600 bytes, 31.6 MiB, plus the driver's alignment.
  - D32_SFLOAT_S8_UINT: the depth and stencil planes at native size.
  - This comes on top of the scratch buffers every store already allocated (linear, tiled, and host staging on the CPU route), which are unchanged.
  - An idle store of a scaled colour target plus a scaled depth surface holds two such images until its batch completes.
- **Pooling is possible later.** One image per (format, extent) would avoid allocating per store. I didn't add it: stores of scaled surfaces should be rare once CPU read-backs stop being the common case, and a pool keeps 31.6 MiB per format resident.

### The depth guest-write case, and the main bug that blocks it

Sequence:
1. a 256x128 colour + D32 draw (z 0.5);
2. `FlushDepthPlanes` over the plane;
3. `GuestMemory::Write` of four floats 0.125 at the start of the plane, which includes texel (0, 0);
4. another draw;
5. read the depth.

| Build | `Watched()` on the plane after step 2 | Depth at (0, 0) after step 4 | Guest memory at (0, 0) after another store |
|---|---|---|---|
| branch, switch unset | not printed (0 in the scaled run of the same sequence) | 0.5 (expected 0.125) | not measured on the branch |
| main `b7a451d62b` (throwaway test copy, not committed) | 0 | n/a | 0.5 |
| branch, 0.5 (the case I wrote, removed) | 0 | no demotion fired; the surface stayed scaled | n/a |

**Cause:**
- The plane store makes the depth range a host import, which the write tracker stops watching ("imported ranges are compared").
- `DepthSurface::WrittenUnits` only asks the tracker (`WrittenSince`, `ChangedBlocks`), and `WrittenSince` returns false for unwatched ranges. So `SyncFromMemory` never sees the CPU write, and the next store writes the GPU plane back over it.
- Before any store, the range is still watched, so the existing `depth_guest_write` case demotes correctly.

A fix belongs in main's depth tracking, not in render scale: for a plane the tracker does not watch, compare the guest bytes with what the mirror last stored, as `StorageTexture` does for imported ranges. I didn't make that change here; it touches native depth behaviour outside this task. I'd file it as its own task.

## What this changes about step 2b (integer coordinates, compute)

- **A transient native copy is now a working primitive.** It makes a native-size, read-only view of a scaled surface on demand, with deferred destruction, and costs one blit plus 31.6 MiB for a 4K RGBA8 surface while in use.
- Step 2b can use it for **read-only native consumers instead of demoting**:
  - `TexelFetch` and `SizeQuery` bindings that are only read, and `Copy` / `DepthCopy` / `StencilCopy` sources, could bind a transient native copy. The surface would stay scaled.
  - The cost: that consumer reads an upscale (as it already does after a demotion), plus one blit per access while the surface keeps changing.
  - That is cheaper to build than rescaling integer coordinates in the recompiler, and it covers compute passes that only read the surface.
- **Writes still need either demotion or true scaled coordinates**: storage writes, compute writes, guest writes.
  - True scaled coordinates means per-binding coordinate scaling in the recompiler, plus dispatch grids scaled for surfaces the dispatch writes. That is PM-097's step 2b list, unchanged.
- **Recommended order:**
  1. the main depth-tracking bug above (it loses guest writes natively, too);
  2. transient native copies for read-only `TexelFetch` / `SizeQuery` / copy sources;
  3. only then recompiler coordinate scaling for writes.

  The PC demotion counts on this head should confirm which reasons are left.
