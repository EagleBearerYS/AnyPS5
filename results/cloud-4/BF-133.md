## How the two setkind forms compose

- **Same results for valid kinds.** For kinds 1–4 both store the same `MutexType` value: #8373 writes `(*attr)->type = static_cast<MutexType>(kind)`, and this branch goes through `scePthreadMutexattrSettype`. Both throw for other kinds.
- **They differ only on a null or uninitialized attribute.** #8373's POSIX form sets `errno` to `EINVAL` and returns -1, as FreeBSD does. The SCE form here throws, because the SCE result is unknown.
- **Possible forwarding once #8373 lands.** `scePthreadMutexattrSetkind` could keep its attribute check and return `PosixThread::ToSce(pthread_mutexattr_setkind_np_nid_postfix(attr, kind))`, so one function stores kinds. That needs #8373's `ToSce` (in `Posix/Common.hpp`) and a declaration of the POSIX form in `src/Mutex.cpp`.
