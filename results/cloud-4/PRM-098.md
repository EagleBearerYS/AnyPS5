## 3. The composed constructor check

```
const auto slabBytes = geometry.layerBytes;
Require(clear == nullptr || !packedSlabs.has_value(), "a cleared texture takes no snapshot, so it has no committed slabs");
Require(clear != nullptr ? snapshot.empty() : packedSlabs.has_value() ? slabBytes != 0 && snapshot.size() == packedSlabs->size() * slabBytes : snapshot.size() == guestBytes, "texture snapshot size mismatch");
Require(clear == nullptr || (!depthCompare && !srgbExpand && !IsRepackedTextureFormat(descriptor.format) && !IsBlockCompressed(descriptor.format)), "a cleared texture needs a plain color format");
Require(!packedSlabs.has_value() || (… ascending, last < guestBytes / slabBytes), "texture snapshot slabs are not ascending slabs of the surface");
Require(!packedSlabs.has_value() || !geometry.levelMajor, "… is not implemented");
```

**What each combination means:**

| `clear` | `packedSlabs` | Required snapshot | Source |
|---|---|---|---|
| null | none | the whole guest surface, `guestBytes` | both sides, unchanged |
| set | none | empty, and a plain colour format | #13648, unchanged |
| null | set | one `layerBytes` slab per packed index; ascending, inside the surface, not level-major | #10064, unchanged |
| set | set | refused by the new Require at :368 | the hand edit |

**Why the two cannot combine.** I chose "require that they don't combine": no texture can get both, so there is no case where the clear has to win over slabs.
- **One value of `keys`:** `keys` takes its final value at `ShaderResources.cpp:995`. Nothing in `cachedTexture` assigns it after that; I checked every line from :996 to the function's end at :1171.
- **The slab side:** `slabbed` (:996) requires:
  - `*keys == DccKeys::Uncompressed`;
  - `resource.dccAddress == 0`;
  - `!depthCompare` and `!srgbExpand`;
  - a 3D view.

  `slabs` is computed only when `slabbed` holds (:1020 and :1036).
- **The clear side:** `SampledClearColor` (:544-545) returns a colour only when `IsDccClear(keys)` holds and `keys != ClearRegister`. `IsDccClear` (`DccMetadata.cpp:607`) is true only for Clear0000, Clear0001, Clear1110, Clear1111 and ClearRegister, never for Uncompressed. Both `SampledClearColor` calls (:1019 and :1095) receive that same `*keys`. So `clear` set implies keys not Uncompressed, hence `slabbed` false, hence no slabs, on both the uncached and the cached path.
- **Without DCC metadata there are no clear keys at all:** `textureClearKeys` returns Uncompressed when `dccAddress == 0` (`DccMetadata.cpp:519`).

**Can a partially committed 3D view reach the clear path? Yes, when it has DCC metadata with clear keys.**
- Neither the key scan nor `SampledClearColor` checks the dimension.
- Such a view is never slabbed, because `dccAddress != 0` and its keys are not Uncompressed.
- Before this merge, #10064 sent it to the whole-surface snapshot path. #13648, and now the merge, clear it on the GPU without a snapshot.
- The outcome is therefore that the clear wins, as the task anticipated. It wins because #10064's slab path never takes DCC views, which #10064 never covered. No covered case of either PR changes.

**#13648's semantics without committed-slabs info.** With `packedSlabs` empty:
- :368 always passes;
- :369 reduces to main's `clear != nullptr ? snapshot.empty() : snapshot.size() == guestBytes`;
- :370 is main's line, unchanged.

Because :368 runs first, a future caller that passes both gets the specific message rather than a size mismatch.
