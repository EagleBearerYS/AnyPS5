## The two tests that failed with the switch on

Both asserted main's `ProofPath::Full`. Each now keeps testing what it tests, with either setting.

**`agc_draw_descriptors`, first-layer case** (`imageTableFirstLayerRevalidateTests`, from a71ba9edb9). It checks that proving an image table holding a 2D read of a 2D array keeps the element's base-slice texture.
- **Its element lies outside the write watch** (a static array). On main the fast proof's collect fails there, so the full walk proves it, and the full walk's narrowing is what's tested.
- **With the index on,** that element is on the index's per-element compare, which re-looks it up through `reresolveElements`, the code 8151a19d21 fixed.
- **The case now asserts the path the setting implies:**
  - off: `ProofPath::Full`;
  - on: the index's proof (`ProofPath::Fast`), with `WriteIndexOutcomesCounted().compared` up by exactly one.
  - The texture-unchanged check that follows is unchanged.
- **So with the switch on it tests the same narrowing on the index's path.** Red with the narrowing reverted and the switch on (exit 1): "an image table holding a 2D read of a 2D array was not proven by comparing its unwatched element on the write index's path". With the switch off it stays green.

**`agc_driver_lookup_log_fits_build`** (BF-039). It measures the thread's lookup-log capacity after a build and after a full walk over 1,500 textures. Its `Full` assertions only make sure a full walk ran.

## The SEGFAULT after the throw: a teardown bug of the test, which any failed assertion exposes

**What happens:**
- The case builds a texture from its array texels through its own local `TextureDetiler`, which records a detile dispatch in the recorder's open batch.
- The case's only sync is `recorder.Sync()` at the end of its block, and the `Recorder` lives in `main()`.
- When a `Require` throws, unwinding destroys the case's `ShaderResources` and then its `TextureDetiler`. `TextureDetiler::release()` destroys its pipelines and descriptor pools without waiting for recorded work.
- Then `~Recorder` calls `Sync()`, which submits the open batch. Lavapipe's queue thread crashes running the dispatch.
- gdb: the SIGSEGV is in `libvulkan_lvp.so` on lavapipe's queue thread, while the main thread is in `main[cold]` → `Recorder::~Recorder` → `Recorder::Sync` → `Recorder::finish`. The failure message is lost.

**It is not caused by the index or the throw's reason.** With the index off and a forced `Require(false, …)` right after the build, the case crashed 3 of 3 (exit 139, no message).

**Isolating the destroyed object:**

| guard | forced failure, switch off |
|---|---|
| none | exit 139, 3 of 3 |
| syncs before the detiler is destroyed (after `ShaderResources` is gone) | exit 1 with the message, 3 of 3 |
| syncs only after the detiler is destroyed | exit 139, 3 of 3 |

So the batch outlives the detiler, not the resource set.

**The product is not affected:** the device's own detiler outlives the recorder. The file's other image cases already guard this with `Clear`/`Finish` structs whose destructor syncs.

**Fixed in commit 1, because it hid the index-on red above (a crash instead of the message):** the case got the same `Clear` guard (sync, then clear cached textures), replacing its trailing `ClearCachedTextures`.

### What
A cached draw over an image table proves every sampled texture on every Revalidate: one write-watch collect, one depth-plane flush and one generation compare per element, so the proof grows with the table (main: 1,137 µs of lookup per draw at 4,096 entries in the Village harness).

With `APS5_TABLE_INDEX=1` the build subscribes its watched textures and watched T# table spans to a write index over 64 KiB blocks. Writers bump the subscriptions over the blocks they touch: tracker stamps (CPU and driver), recorded storage writes, unwatch, allocation changes, a texture leaving the cache and a host import over a texture's range.
