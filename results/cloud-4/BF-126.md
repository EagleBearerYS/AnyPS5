## The change (cf5462c2c)

**When the timeout fires** (`WaitMemory.cpp`, right after the `timed out after …ms` line), it prints one more line. It sits inside the existing once-per-label block, so a label that times out repeatedly prints it once per run. The watchdog's per-queue list and the rest of the report are unchanged.

```
[gpu]   label 0x<awaited> wait submitted at stamp <submission.received>: <decision>; stores newest first: stamp N value 0x… queue 0x… opcode 0x…, …; now <current stamp>
```

**The decision** comes from `noteHeldAtSubmit` (`Submission.cpp`). It now records one `SubmitWaitCheck` per `WAIT_REG_MEM`/`_64` cursor in the submission (`Submission::waitChecks`, sorted by cursor, looked up by `findSubmitCheck`). The texts are:
- `checked at submission: value 0x…` (the value it read, which didn't satisfy);
- `held at submission: value 0x…`;
- `not checked at submission (not a memory wait)`;
- `not checked at submission (misaligned or inaccessible)`;
- `not checked at submission (written earlier in the same submission)`;
- `not checked at submission (queue 0x20 serial N writes it)`. The serial is that of the waiting queue's pending submission that writes the dword, or of its running submission.
  - So the worker now keeps `runningSerial` and `runningWrites`, set at dequeue under the driver mutex.
  - When neither holds the write (a deferred completion), the text is `an unfinished queue 0x… submission writes it`.
- `no check at submission recorded` (a landing wait from `landPendingWaits`).

**The stores** are `labelStores` for the awaited dword (and +4 for a 64-bit wait), up to `LabelStoreHistory` (4), newest first, skipping empty slots, or `none recorded`. Each store now keeps its packet opcode:
- `noteLabelStore` and `commitLabel` take it, and `DeferredLabel` carries it;
- `commitDmaStore` records `0x50`, since only `DMA_DATA` reaches it.

**Cost:** at submission, one small vector entry per wait packet, plus the pending-submission search only when the dword has unfinished writes. At runtime, the opcode field. The printing runs only on a timeout.

## The test (in `tests/execution/LabelWaitHistory.cpp`)

**Mode `--timeout-reason`:** a new ctest, `agc_driver_label_wait_timeout_reason`, with `ANYPS5_NO_SHADER_CACHE=1`, skip code 77, timeout 60, and the WIN32 `PATH` line. It sets `APS5_GPU_WAIT_TIMEOUT_MS=100` in-process and captures stderr (`dup`/`dup2`, `_dup`/`_dup2` on Windows).

**Case 1, reading 2's shape:**
1. Queue 0 releases 1 to the label, and the queue goes idle.
2. Queue 0x20 submits a writer that waits on a gate, then releases 2 to the label.
3. Queue 0x20 submits a waiter for 1. Its check at submission is skipped, because the queue's own running submission writes the label.
4. The gate opens, and 2 lands after the waiter's submission. The wait times out legitimately: it should wait.

The test parses the line and requires:
- the writer's serial;
- the store of 2 by queue 0x20, opcode 0x49, after the submission stamp;
- the store of 1 by queue 0x0, opcode 0x49, before it;
- `now` ≥ the newest stamp.

Then it stores 1, and the wait ends.

**Case 2:** a fresh label waited for 1 with no producer. The line must read `checked at submission: value 0x0; stores newest first: none recorded`.

**The exact lines from the green run:**
```
[gpu]   label 0x559729de0000 wait submitted at stamp 4: not checked at submission (queue 0x20 serial 2 writes it); stores newest first: stamp 6 value 0x2 queue 0x20 opcode 0x49, stamp 2 value 0x1 queue 0x0 opcode 0x49; now 6
[gpu]   label 0x559729de0300 wait submitted at stamp 8: checked at submission: value 0x0; stores newest first: none recorded; now 8
```
They end with `label wait timeout reason: a timed-out wait names its submission stamp, the check at submission and the label's stores`.
