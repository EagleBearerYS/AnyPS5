### `sceAgcDriverSetFlip`

**Prototype sources:**
- [SharpProspero `SceAgcDriver.cs:219`](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/Agc/SceAgcDriver.cs#L212-L220) declares `uint sceAgcDriverSetFlip(uint** writeCursorSlot, uint packetSizeInDwords, uint queueType, uint videoOutHandle, int displayBufferIndex, uint flipMode, long flipArg)`.
- [OpenAGC `driver_prospero.c:1679`](https://github.com/OpenAGC/OpenAGC/blob/3c7e8072f0d7684e930454794fd5c02056946d73/src/driver_prospero.c#L1676-L1690) is a disassembly note on ordinal 49 (`cwbxjPSJ7WQ`, 585 bytes). It checks `r8d+2 < 0x12`, which makes the fifth integer argument the display-buffer index, as in SharpProspero's order.
- [REmu `agc_driver.rs:507`](https://github.com/xnetcat/REmu/blob/16d92e3577820815019e6e1efd7c52396acf0613/crates/remu-runtime/src/agc_driver.rs#L507-L522) treats the call as `(buffer, handle, index, mode, arg)`. That conflicts with the register note.

**How it compares with libSceAgc's builder:**
- The tree's `sceAgcDcbSetFlip(CommandBuffer*, handle, index, mode, arg)` (`libSceAgc/DcbState/src/Display.cpp:13`) takes the same flip arguments in the same order.
- The driver form replaces the `CommandBuffer*` with the `(cursor slot, size, queue)` prefix. The tree's done `sceAgcDriverWaitUntilSafeForRendering(uint32_t** command, capacity, mode, handle, index)` (`Submit/src/Dcb.cpp:69`) takes the same prefix.

**Why the answer is not settled:**
- **Return value:** the tree's wait returns 0, but [SharpProspero `DrawCommandBuffer.cs:184`](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Graphics/Agc/DrawCommandBuffer.cs#L182-L201) says the sibling call returns the number of words the packet took. No source gives SetFlip's success value.
- **Index range:** OpenAGC says indices -2..15 are accepted and anything else returns `0x8029000a`. libSceAgc's flip writes any index.
- **Packet and VideoOut:** per OpenAGC, the console writes an 8-dword `IT_RELEASE_MEM` (header `0xc0064900`) and calls `sceVideoOutSubmitEopFlip`. The tree's size getter and libSceAgc use a 6-dword NOP-wrapped flip, which the executor handles.

**What would settle it:** a console run of `sceAgcDriverSetFlip(&cursor, 6, 0, handle, i, 1, 0)` for i = 0, -1 and 16, and for queue 1, recording the return value, the advanced cursor and the words written.

### `sceAgcDriverSetWorkloadsActive` and `sceAgcDriverSetWorkloadComplete`

**Sources:**
- [SharpProspero `SceAgcDriver.cs:236`, `:240`](https://github.com/SvenGDK/SharpProspero/blob/5dfdb4b0b166e83dc9ae275001afb695f12c7174/src/SharpProspero/Interop/Agc/SceAgcDriver.cs#L234-L240) declares `int (void* commandBuffer, uint queueType, uint streamId, uint workloadIndex)` and `int (void* commandBuffer, uint queueType, uint streamId, void* workloadsAddr, uint count)`.
- [OpenAGC `agcdriver.h:116`](https://github.com/OpenAGC/OpenAGC/blob/3c7e8072f0d7684e930454794fd5c02056946d73/include/agcdriver.h#L114-L122) says its one-argument API "is not ABI-compatible with Sony's similarly named multi-argument packet builders".
- OpenAGC models Sony's packet separately (`src/agc_workload_packet.h`, `tools/extract_agc_driver_workload_facts.py`: header `0xC0071E00`) with each registered stream's GPU slot address. The tree doesn't keep that address; `Resource/src/Registration.cpp` keeps only a bitmask.

**Why the arguments don't match libSceAgc's builder:**
- The tree's builders are `sceAgcDcbSetWorkloadsActive(CommandBuffer*, streamId, ids, count)` and `sceAgcDcbSetWorkloadComplete(CommandBuffer*, streamId, workloadId)` (`Workload.cpp:30`, `:41`). They return a packet pointer or null.
- The driver form adds `queueType` and returns an `int` status, with no source for its error values.
- Its first argument is an untyped `void*` named `commandBuffer`, while SharpProspero names the flip's and wait's first argument the cursor slot. So whether it is a `CommandBuffer*` is not shown.

**What would settle it:** the same kind of console run, with a stream registered through `sceAgcDriverRegisterWorkloadStream`.

### Other finding (report only)

The tree's done `sceAgcDriverWaitUntilSafeForRendering` (`Submit/src/Dcb.cpp:69`) takes SharpProspero's argument order, but differs from the public sources on two points:
- **Return value:** it returns 0, where SharpProspero says it returns the packet's word count.

Neither source is a measurement, and I changed nothing.
