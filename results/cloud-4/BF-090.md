     - **What those dwords are:** in a column whose heap is a V#, they are `ReadConstBuffer` reads, and `heapHandle` is their argument 0 (lines 613 and 617).
  3. **The two checks are the same check.** `ValidateSource` calls `SrtWalker::ValidateRuntimeValue` on each dword (246), which builds a fresh `RuntimeValidator` per call (`SrtWalker.cpp:21`). In `SrtRuntimeValidator.cpp`, a `ReadConstBuffer` must have a `GetBufferResource` handle (111-114). It then falls through to `return finish(ValidateArguments(inst, true));` (142), which validates argument 0, the handle. The handle is checked as a descriptor handle (129) and its 4 dword arguments are validated in turn.
     - So a valid T# dword means a valid heap V#. That is exactly what line 650 tests, with the same validator, a fresh instance per call, and `RuntimeValueType::Any` in both.
     - Therefore `selected` ⇒ line 650 succeeds ⇒ the nested branch is skipped ⇒ `parentPointer == nullptr`. Conversely, a nested leaf has a V# that fails validation, so its `direct` fails at 692 and it is never `selected`.
  4. **The other place a parent pointer is set** is `TryMakeIndirectColumn`, at 825: `if (buffer || merged) plan.parentPointer = &pointer;`. `TryMakeTableColumn` returns into it at line 640, before the selected block, and it never sets `selected`.

  6. **Consequence for the materialization loop:** at 151-158, the `column.selected` branches (`Constant(column.addend)` and `KeepSourceAlive(…selection…)`) and the `plan.parentPointer` branch (arguments 1 and 2) are never taken for the same plan.
