## The shaders (synthetic, wave64, in `tests/execution/ImageTable.cpp`)

Both were assembled with `llvm-mc -arch=amdgcn -mcpu=gfx1030 -mattr=+wavefrontsize64 -filetype=obj` (llvm 18.1.3), with branch targets resolved by the assembler and checked with its disassembler. They use BF-091's frame:
- **Keys:** lanes 0–31 take key K0 and lanes 32–63 take K1.
- **Per group:** 4 groups, each reading 8 words: K0, K1, s18, s19, s20, s21, s22, s23.
- **Loop:** a `v_readfirstlane` / `v_cmp_eq` / `s_and_saveexec` waterfall loop.

**`agc_driver_pointer_phi_lane_not_table` (`--pointer-phi-lane-not`), Little Nightmares' shape.** The pointer is at record +0 and +4: `s_buffer_load_dwordx2 s[44:45], s[4:7], key<<4`. The test's table puts each record's pointer in words 0 and 1. The lane mask is `v_cmp_lt_u32_e64 s[52:53], v0, s20`, with s20 = 0, so the masked word is 0 on any host.

```
  s18 == 1: s_mov_b32 s44, 0
  s18 == 2: s_ff1_i32_b32 s60, s52 ; s_lshl_b32 s61, 1, s60
            s21 == 1: s_andn2_b32 s44, s52, s61
            else:     s_not_b32 s61, s61 ; s_and_b32 s44, s52, s61
  s_load_dwordx8 s[36:43], s[44:45], 0x40
```

The low word on the base, from the refusal:

```
Phi(Immediate, Phi(ReadConstBuffer@pc=0x74 (the record word),
  Phi(BitwiseAnd32(CompositeExtractU32x4(Ballot(LogicalAnd), Immediate), BitwiseNot32(ShiftLeftLogical32(Immediate, BitwiseAnd32))),
      BitwiseAnd32(CompositeExtractU32x4(Ballot(LogicalAnd), Immediate), BitwiseNot32(ShiftLeftLogical32(Immediate, BitwiseAnd32))))))
```

That is Little Nightmares' `BitwiseAnd32(CompositeExtractU32x4(Ballot(cond), 0), BitwiseNot32(<lane bit>))` arm, nested in Phis with the record read and `imm 0`.
- **The two arms:** `s_andn2_b32` and `s_not_b32` + `s_and_b32` lower to the same IR.
- **The lane bit:** it is `ShiftLeftLogical32(1, BitwiseAnd32(FindILsb32(…), 31))`, because `s_lshl_b32` masks its shift.
- **The high word:** one direct read at +4, `ReadConstBuffer@pc=0x74(…, ShiftLeftLogical32(ReadFirstLane(SelectU32(…), Phi(…)), Immediate))`.

What the test checks:
- with every selector 0, each lane samples the T# of the record its key selects, checked lane by lane in all 4 groups;
- the zero arm, the `s_not`/`s_and` arm and the `s_andn2` arm each fault as "outside the snapshot", publish no output and keep the artifact id.

These three faults print the same message, which is within AsyncLog's 3 repeats.

**`agc_driver_pointer_vsharp_select_table` (`--pointer-vsharp-select`), Spider-Man 2's shape.** The shader sets up the key before the loop:

```
  v_cmp_gt_u32 vcc, 32, v0 ; v_cmp_gt_u32_e64 s[56:57], 64, v0 ; s_and_b64 vcc, vcc, s[56:57]
  v_add_nc_u32 v10, s16, v9 (v9 = s21 = 0)          ; IAdd32
  v4 = s17, or s23 when s22 == 1 (uniform branch)   ; Phi
  v_cndmask_b32 v3, v4, v10, vcc                    ; at full EXEC, before the loop
  loop entered under s_and_saveexec of two always-true compares
```

Inside the loop:
- **The record pointer:** `s_buffer_load_dwordx2 s[44:45], s[4:7], s24<<4 offset:0x8`.
- **The V#:** `s_load_dwordx4 s[52:55], s[44:45], 0xa0` loads the V# through the pointer.
- **The T#:** `s_buffer_load_dwordx8 s[36:43], s[52:55], s19<<5` reads the T# through the V#.

The IR after the resource pass, read from `APS5_DUMP_IR=all`, is the shape the task names:
- **The key:** `ShiftLeftLogical32(ReadFirstLane(SelectU32(LogicalAnd(UGreaterThan32, UGreaterThan32), IAdd32(…), Phi(…)), Phi(INotEqual32(…), LogicalAnd(…))), 4)`.
- **The rest of the chain:** that key reads the record, the record's words feed a `GetAddressResource`, a `LoadAddressU32` of that pointer gives the V#, and a `ReadConstBuffer` through the V# gives the T#.
- **One difference:** the mask Phi's entry arm is a compare, not a `LogicalAnd` as in Spider-Man 2's chain. The select argument matches.

What the test checks:
- each lane samples images[outer + inner], where outer comes from its key's record and inner from the group;
- after record 1's pointer is moved to the other V#, texels follow without a recompile (same artifact id).

**BF-091's three tests are kept.** `agc_driver_pointer_phi_high_second_table` still expects and gets the refusal.

**Registration.** Both new ctests are registered next to BF-091's, in both `set_tests_properties` lists of the siblings: `ENVIRONMENT`/`SKIP_RETURN_CODE 77`/`TIMEOUT 30`/`WORKING_DIRECTORY`, and the `if(WIN32)` `ENVIRONMENT_MODIFICATION` PATH list.

## The fix (`ResourceTracker.cpp`, pointer-keyed columns only), one commit with its tests

**What counts as a lane-mask operand.** `LaneMaskOperand` used to accept a Ballot word, or an AND or Phi of only Ballot words and non-root immediates. It now accepts:
- a Ballot word, or the loop's **lane bit**: `ShiftLeftLogical32(1, index)`;
- an AND, **OR, NOT** or Phi of only those and non-root U32 immediates;
- with at least one Ballot word or lane bit in it.

**The lane index** (`LaneIndex`) is built from:
- `FindILsb32`, `FindUMsb32` and `ReadFirstLane`;
- through `BitwiseAnd32`, `IAdd32`, `ISub32`, U32 immediates and the arms of `SelectU32`.

That covers `s_ff1_i32_b32`, `s_ff1_i32_b64` (two `FindILsb32`, an add of 32 and selects), `s_bitset0_b32` (`AND 31`), the shift's own `AND 31`, and a `readfirstlane` index.

**How the walk uses it.** `PointerRecordReads` used to skip only a lone Ballot word. It now skips any arm that is entirely a lane-mask operand. The existing AND rule is otherwise unchanged:
- an AND with a record read in it still has that read matched against the column (same offset, `SameRecordColumn`);
- an AND with no lane-mask operand still refuses;
- anything else still refuses.

The high word goes through the same walk, as with BF-091.

**Spider-Man 2's shape needed nothing.** It passes without any tracker change on both bases. #7388 (7fe0790e5, waterfall image tables) is **not** in 59b319a77 but **is** in `pm/7395-restack`, so it passes through #7395/#7223's own pointer support, not #7388's. I kept its test, which guards that chain.

## The disk cache

**No stored plan changes, and no format change.** The restack is at FormatVersion **43** (PRM-048) and stays there. We add no plan field, and `TableColumn` and the encoding are unchanged.
- **The walk for shaders that planned before:**
  - A lone Ballot word is still skipped, now through `LaneMaskOperand`, which returns true for it.
  - Record reads are still matched in the same order.
  - An AND that is now skipped whole was skipped before through the AND rule: both operands were lane masks, or one was an immediate.
  - Any arm that newly counts as a lane mask contains a lane bit, an OR or a NOT, and before this change it reached `ScalarReadMemory` and refused.
  - So every shader that planned before collects the same reads and plans the same column.
- **Shapes that refused before plan now.** A refusal is never cached: `ResourceProgram`'s failure is memoized only in memory, and `StorePlan` runs only after a successful build. BF-091 traced the same code.
