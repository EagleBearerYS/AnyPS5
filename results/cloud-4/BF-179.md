## The change

- **`core/libs/prx/libSceNetCtl/Export.cpp`, `sceNetCtlGetResult` (:584):**
  - **Checks:** the `NOT_INITIALIZED` and null `INVALID_ADDR` checks stay first, unchanged.
  - **Supported events:** an event in `[NET_CTL_EVENT_DISCONNECTED, NET_CTL_EVENT_IPOBTAINED]` (1..3) writes `*result = 0` and returns 0.
  - **Any other event** throws `std::runtime_error("sceNetCtlGetResult: event type N is not implemented")`, as `sceNetCtlGetResultV6` (:789) does.
  - **Numbering:** the IPv4 events use the file's existing constants (`NET_CTL_EVENT_DISCONNECTED = 1`, `NET_CTL_EVENT_IPOBTAINED = 3`, :59-60). Those are the numbers `sceNetCtlCheckCallback` already delivers to IPv4 callbacks, and the ones V6 uses. I found no IPv4 numbering that differs from V6's.
- **`docs/dev/debt/libSceNetCtl.md`:**
  - The Functional line that listed `sceNetCtlGetNatInfo and sceNetCtlGetResult` now names NAT info only.
  - A new `sceNetCtlGetResult` entry, next to V6's, says:
    - it reports no error: events 1-3 write 0, as V6;
    - the per-event error code a console reports, a disconnection's cause in particular, is unconfirmed;
    - the evidence: the V6 precedent, PPSA20052 (Worms Armageddon: Anniversary Edition 01.003.000) calling it 2 s into boot, and PPSA24191 (Monster Hunter Wilds) without a network, with event 1 as its first call;
    - a null result answers `INVALID_ADDR`, and other event types throw.
- **`core/libs/tests/GuestNetCtl.cpp`:** the `logic_error` expectation for event 0 is replaced with:
  - each supported event (1, 2, 3) returns 0 with `*result == 0`;
  - events 0, 4 and −1 throw `sceNetCtlGetResult: event type N is not implemented`, with `*result` left at −1;
  - a null result with event 1 still answers `INVALID_ADDR` before the event is looked at, as does the existing null check with event 0 at the start of `main`.
  - **`NOT_INITIALIZED` is not reachable in a test.** The library starts initialized and `sceNetCtlTerm` is a no-op; the debt page's initialization entry already says so. The check is kept unchanged in the code.
