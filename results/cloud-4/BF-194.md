### `sigreturn` in detail

`SigreturnContext_nid_no_patch` (`UserContext.cpp:252`, declared in `UserContext.hpp`) checks, in `sys_sigreturn`'s order:

| case | answer |
|---|---|
| null context | `EFAULT` |
| `mc_flags & ~_MC_FLAG_MASK` | `EINVAL` |
| `rflags` differing from the current flags outside `PSL_USERCHANGE` (0x254dd5), the mask `setcontext`'s restore already uses | `EINVAL` |
| `%cs` without RPL 3 | throws: FreeBSD also raises `SIGBUS` |
| `_MC_HASFPXSTATE` | throws: the YMM state is not restored here |
| `mc_fpformat` `_MC_FPFMT_NODEV` | keeps the current FPU state |
| `mc_fpformat` other than XMM | `EINVAL` |
| `mc_ownedfp` `_MC_FPOWNED_NONE` | loads the initial state (FCW 0x37f, MXCSR 0x1f80; `__INITIAL_FPUCW__`, `__INITIAL_MXCSR__` in FreeBSD's `x86/include/fpu.h`) |
| `mc_ownedfp` FPU or PCB | loads `mc_fpstate` |
| any other owner | `EINVAL` |

- **Restore:** the registers and the mask then go through `RestoreContext`, which is `setcontext`'s former body, moved out unchanged apart from the FPU source.
- **`mc_len` is not checked,** as in `sys_sigreturn`; `setcontext` (`set_mcontext`) does check it.
- **Bases:** like `setcontext`, it keeps the `%fs` and `%gs` bases that FreeBSD would load from `mc_fsbase` and `mc_gsbase`. `getcontext` here writes 0 there.
- **The debt entry says all of this.**

### What
Finishes six libkernel_sys calls:
- `chown`, `lchown` and `fchownat` return `EPERM` for an owner or group other than the guest's or the unchanged value, after the path lookup, as FreeBSD 11's `chown(2)` does for a caller without the superuser privilege. This is the answer #8457 gives `fchown`.
- `sched_setscheduler` follows FreeBSD 11's `sys_sched_setscheduler`: `EFAULT`, `ESRCH` for another process, `EINVAL` for an unknown policy. Pid 0 sets the calling thread through `scePthreadSetschedparam`.
- `sem_setname` returns `EINVAL` for an invalid semaphore or a null name, and otherwise 0 without keeping the name (listed under Silent stubs).
- `sigreturn` applies FreeBSD 11's amd64 `sys_sigreturn` and `set_fpcontext` checks and restores the context through the path `setcontext` uses.

Values the console's answer is unknown for still throw: a scheduler policy `scePthreadSetschedparam` rejects, the first thread by pid, a non-user `%cs`, an extended FPU state. The debt file has an entry for each.

Related: #8457 (`fchown`), #9187 (`sched_getparam`, `sched_getscheduler`, `sched_setparam`), #9389 (`sigqueue`), #10434 (`linkat`). Each touches the line next to one this PR changes, so whichever merges second needs a one-line merge.
