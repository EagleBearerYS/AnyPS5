## The change (05f97dcd5)

Paths are under `core/libs/prx/libSceAgcDriver/Graphics/`, line numbers on 0f55f38f5.

- **`LookupRecord`** gets `std::array<std::uint64_t, 4> untracked`, next to `generation` (`src/ShaderResources.cpp:421`). The lookups log the key the returned snapshot was made or kept at:
  - **Snapshot hit** (`:910`): `it->untracked`, which the hit has just set to the lookup's key. It is non-zero only when the hit was over a range outside the watch with a hint. This covers a `kept()` hit (`:901`, `it->untracked == untracked && !SnapshotWriteOverlaps`) and a byte-compare hit, whose key was taken before the compare.
  - **New snapshot** (`:964`, `:973`): `entry.untracked`, which `cachedTexture` sets only when no recorded write was pending over the range.
  - **Storage-image views, resident targets and depth lookups** log zeros.
  - **The stage-A fast path** (`fastTexture`) logs zeros. It cannot serve such an entry: it returns at `:4647` when `CollectWrites` is 0, which is always the case outside the watch, so that path is never taken for these entries.
- **The gate** (`resolveImageTables`, `:5138`): `looked->generation != 0` becomes `(looked->generation != 0 || looked->untracked[0] != 0)`. Every other condition is unchanged: the same object, `source == nullptr`, `keys == Uncompressed`, `dccAddress == 0`.
- **The table** (`ReusedTable`, `:1772`): a new `std::vector<UntrackedQuery> untracked` (struct at `:1747`: address, bytes, key).
  - **Watched entries** still push their generation query.
  - **Untracked entries** (`:5142`) push the range the lookup keyed: `looked->resource.baseAddress`, `looked->bytes`. That is `cachedTexture`'s windowed address and adjusted byte count, exactly what its key covered. They also push the key.
  - **Both kinds** still go into `ranges` for the pending-results check.
- **`TableCurrent`** (`:1801`):
  - **Untracked entries** (`:1807`): for each one, `untrackedKey(address, bytes)` must equal the kept key and `!Recorder::SnapshotWriteOverlaps(address, bytes)` must hold. That is the test `kept()` makes for the snapshot cache.
  - **Watched entries** keep `GuestMemory::UnchangedSinceAll(table.queries)`.
  - **No hint:** when the hint is missing (`untrackedKey` returns zeros, for example with `CollectEpoch() == 0` or an odd forget serial), the key can't match a kept non-zero key. Such an entry was refused at the gate in the first place, so behaviour is as now.
- **The count:**
  - **`[textures]` line:** `APS5_PROFILE_DRAW`'s line now reads `image tables N reused, M resolved (K untracked entries kept); …` (format `:407`, counter `tableUntrackedKept` `:386`). Both reuse sites add the reused table's untracked entry count (`:3434`, the fast revalidation, and `:5044`, the rebuild).
  - **Test-visible:** `ImageTableReuseCounts::untrackedKept` (`include/ShaderResources.hpp:148`) through `ImageTableReuses()`.
  - **Refusal classification:** main's `[textures]` line has none; that text is on lane F's tree. So there was none to keep, and none was added.

## Tests (0f55f38f5): `tests/execution/ImageTableReuse.cpp`

| case | with a hint (Windows) | without (Linux, what ran here) |
|---|---|---|

| **(b)** `GuestMemory::Write` over entry 11's texels, then a dispatch | not reused `(0, 1)`, samples the stored texels; the next dispatch reuses again `(1, 0)` | `(0, 1)` then `(0, 1)`; stored texels sampled |
| **(c)** a dispatch whose output buffer is entry 13's texels, then a dispatch sampling 13 | the writer reuses, the reader resolves `(1, 1)`, samples the written texels | `(0, 2)`; written texels sampled |
| **(d)** the watched-memory cases (`RunTests`, unchanged) | as before | as before, passed |
