## The test

**Texture:**
- 256x192, 2D, swizzle mode 24 (SW_64KB_Z_X), identity dst_sel, one level.
- Three cases, each in its own 256 KiB slot so no case can hit another's cached texture:

| case | T# format | read through the fix as | element |
|---|---|---|---|
| 32_UINT | 20 (`Format32UInt`) | `Format32Float` | 4 bytes |
| 32_SINT | 21 (`Format32SInt`) | `Format32Float` | 4 bytes |
| 16_UINT | 11 (`Format16UInt`) | `Format16UNorm` (bbf430e22d) | 2 bytes |

**Memory:** each case runs from two kinds of memory:
- **untracked memory:** a static array, 64 KiB aligned by hand as in `ImagePipeBankXor.cpp`;
- **a guest allocation:** a 1 MiB block registered with `GuestAllocations::Mutation().Add` as in `ImageStoreSint.cpp`. The output buffer sits in the same block.

No depth surface is drawn or registered anywhere in the test.

**Layout:** the texels are written in Z_X order with the driver's own equation table:
- `FindTextureSwizzleEquation(24, element bytes)`, `ThinBlockLayout` and the mip's `blocksPerRow`, as `ImagePipeBankXor.cpp` does;
- 32-bit surfaces span 2x2 blocks of 128x128, the second block row half used;
- 16-bit surfaces span 1x2 blocks of 256x128;
- the rest of each slot is filled with 0xee.

**Pattern:**
- **Edge values:** one texel in 16, where `x % 16 == y % 16`, takes an edge value:
  - 32-bit: 0x00000000, 0x00000001, 0x12345678, 0x7f7fffff, 0x3f800000, 0x80000000, 0xbf800000, 0x00800000, 0x007fffff, 0x80000001, 0x7f800000, 0xff800000, 0x7fc00000, 0x7f800001, 0xffffffff, 0x7fbfffff;
  - 16-bit: 0x0000, 0x0001, 0x1234, 0x7fff, 0x8000, 0x8001, 0xfffe, 0xffff.
- **Other texels:** a hash of (x, y), every 32-bit pattern allowed; 16-bit takes its low half. A misplaced texel therefore shows up as a wrong value.

**Shader:** wave32 compute, 256 threads per group, one group per row (192 groups, `groupIdEnable` x, so tgid.x is s16 after 16 user-data dwords). Assembled with llvm-mc 18.1.3 `-mcpu=gfx1030`:
```
v_mov_b32 v1, s16                                    7e020210
v_lshlrev_b32 v2, 8, v1                              34040288
v_add_nc_u32 v2, v0, v2                              4a040500
v_lshlrev_b32 v2, 2, v2                              34040482
image_load v3, v[0:1], s[4:11] dmask:0x1 unorm 2D    f0001108 00010300
s_waitcnt vmcnt(0)                                   bf8c3f70
buffer_store_dword v3, v2, s[0:3], 0 offen           e0701000 80000302
s_endpgm                                             bf810000
```
Each thread does one `image_load` of texel (x, y) and stores the dword to `output[y * 256 + x]`. The output is pre-filled with 0xa5a5a5a5.

**Check:** every texel of every case must equal its pattern value; a 16-bit value is zero-extended. On a mismatch the message gives the number of differing texels and the first one:
```
<case> SW_64KB_Z_X depth bits from <memory>: N of 49152 texels differ, first (x, y) read 0x..., expected 0x...
```

**Paths each case took** on this machine (`paths.log`, a direct run of the test binary on 7e92c2060, from the driver's `[src/Texture.cpp]` log lines):

| case | untracked memory | guest allocation |
|---|---|---|
| 32_UINT | CPU snapshot, `Texture ... format=22 vk=100` | CPU snapshot, `format=22 vk=100` |
| 32_SINT | CPU snapshot, `format=22 vk=100` | storage image, GPU detile (`StorageTexture ... format=22 vk=100`, "viewed from storage image") |
| 16_UINT | CPU snapshot, `format=7 vk=70` | storage image, GPU detile (`StorageTexture ... format=7 vk=70`, "viewed from storage image") |

So both widths go through both the snapshot and the storage-image path:
- **Snapshot:** a CPU detile and upload.
- **Storage image:** a GPU detile from the host import.
- **Why the guest allocation's first read is a snapshot:** its host import does not exist yet; it exists from the second read on.

The test does not assert the path, because it depends on whether the device can import host memory.
