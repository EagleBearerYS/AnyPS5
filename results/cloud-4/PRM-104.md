## 4. The semantic check, redone at the merge

**Verdict: yes.** Every slot index #7642's `DeviceImageTable` writes stays valid (not freed, not reused) for as long as the table can hand it to a shader.

Lines are in the merged tree: 06eba99c50 + 31f5d0e8dd, with the §1 resolution, the hand edit and the `.get()` at :88. None of the slot-lifetime files below differs between the uncommitted merge and that tree, except `DeviceImageTable.cpp:88`.

1. **What `TextureSlot` returns and keeps** (`G/BindlessHeap.cpp:323–352`):
   - It looks up or claims an image slot for the key `{kind, owner, view, layout}`, where `owner` is the texture seen as its `HeapSlotOwner` (325). It returns the index.
   - `claimSlotLocked` (374–380) records the slot under `ownerSlots[owner]`, and the owner record gets `texture` (348).
   - It sets `owner->heapSlotted` (349).
   - It keeps **no** `shared_ptr`, as before.
   - **dd83293174 changed:**
     - the parameter type (`Texture*` instead of `const std::shared_ptr<Texture>&`);
     - the key's owner type (`const HeapSlotOwner*` instead of `const void*`);
     - the slot now comes from `imagePool`, one pool every image kind shares (`SlotPool::Take`, 395–407).
2. **What frees a slot, and who calls it:**
   - **The release:** `BindlessHeap::ReleaseSlots(owner)` (354–372), which calls `freeSlotLocked` (382–389) for each of the owner's slots: erase the key, clear the record, `imagePool.Free` (bump the generation, push to the free list).
   - **The trigger:** `ReleaseSlots` is called only from `HeapSlotOwner::ReleaseHeapSlots(context)` (`Graphics/include/BindlessHeap.hpp:183–198`), guarded by `heapSlotted.exchange(false)`.
   - **For a `Texture`** (`class Texture : public HeapSlotOwner`, `Texture.hpp:61`), that call is in `Texture::release()` (`G/Texture.cpp:1237–1238`). `release()` runs from `~Texture()` (1163–1164) and from the constructors' `catch (...)` blocks (629, 734, 794, 858, 906, 1136), before any slot can exist.
   - **Other owners** are other objects: `StorageTexture` (6576–6580), `MultisampleTarget` (`G/MultisampleTarget.cpp:759`), `Sampler` (`G/Sampler.cpp:59`) and `PresentationPass::Slot` (`Execution/src/PresentationPass.cpp:143`).
   - **dd83293174 changed:**
     - `ReleaseImageSlots(const void*)` became `ReleaseSlots(const HeapSlotOwner*)`;
     - the `heapSlotted` flag moved from `Texture` into the shared `HeapSlotOwner` base;
     - generations moved from the owner record into the pool.
   - **Still true:** a texture slot is freed only by its texture's destruction. No sweep exists.
3. **The table's hold**, `DeviceImageTable.cpp`, unchanged by #9508's three new commits:
   - `lookupKey` takes the slot with `texture.texture` held by the caller (364).
   - It stores the entry with `std::move(texture.texture)` (370), so **the entry holds the texture**.
   - It returns `DeviceImageValue{*slot, …}` (371).
   - `release` (415–434) and the insert-failure paths (187, 323) move the texture into `recorder.Keep(...)` (432).
   - `Recorder.cpp` is not in #9508's diffs, so `Keep` (2778) and the kept objects' release after the batch's fence, through `DestroyDeferred` (389–399), are as PRM-102 §3.3 describes.
4. **`upload` taking the key out before later draws**, unchanged:
   - `Prepare` (159–) runs `retainSlots` (162, 174) and then `refresh`/`evict`, which drop keys with `keys.Retain` (521, 572).
   - `upload` (575–) records the bucket writes into the open batch before any draw recorded after this `Prepare`.
5. **Teardown order** (`Execution/src/VulkanDevice.cpp`), unchanged:
   - 970: `vkDeviceWaitIdle`;
   - 995: `recorder.reset()`;
   - 1013: `DeviceImageTable::Release(device)`, so the held textures free their slots on a live heap (`ReleaseHeapSlots` uses `BindlessHeap::Existing`);
   - 1014: `BindlessHeap::Release(device)`.

   4243e9c4f1's only `VulkanDevice.cpp` change is `ComputeTarget`'s `HeapComputeEnabled()` → `DescriptorHeapEnabled()` (4169).

**What the shared pool adds.** A slot freed by any owner can now be reused by any image kind. A freed slot of a held texture can't exist, though: steps 1–3 hold, and reuse needs a prior `Free`. So the table can't hand out a slot that has been reused. `NearlyFull()` is still `refusedHeaps != 0` (422–424); the table reads it at 364 and reserves nothing.
