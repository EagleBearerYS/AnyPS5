## The gap, confirmed

Line numbers are in `core/libs/prx/libc/include/WindowsMappings.hpp` at 99aeb0ac56.

1. `CompareWhenShared` (`:189-203`) set the mark only on the `SharedPage` (`page.comparedWhenShared = true`).
2. A `Physical` slot holds its page weakly (`std::weak_ptr<SharedPage> page`, `:572`).
3. When every view of that physical page is unmapped (`reset`, `:928-985`, erases the views; `evict` does so for resident runs), the page expires.
4. The next `Map` of the same section offset gets a new page from `pageOf` (`:95-102`) with `comparedWhenShared = false`.
5. The next clearing collect passes `collectable()` (`:509-525`) and arms the aliases in `Collect`'s alias loop (`:454-466`, "arm shared memory write tracking" at `:463`).

### The alias path

`MapAlias` (`:286-329`) and `mapAliasRuns` (`:987-1010`) don't have the `pageOf` pattern: neither creates a `SharedPage`.
- `MapAlias` demotes resident views in place. `demote` keeps `view.page`, and so its mark.
- It maps the read-write alias as a host-only view that never enters `views`, so it is never armed or collected.

There was nothing to cover there, so the test has no alias case.

## Test: `CheckComparedWhenSharedRemapped` (`core/libs/tests/WindowsWriteWatch.cpp`)

It sits next to #9159's `CheckComparedWhenShared` and is called from `main()` after `CheckResidentOnlyComparedWhenShared`. It runs in the existing WIN32-only ctest `windows_write_watch`, with no new ctest name.

1. Create a 64 KiB `SEC_RESERVE` section and three 64 KiB reservations, then `ForgetSection(section)`, as #9159's test does against handle reuse.
2. `Map` one 16 KiB page of the section, offset 0, resident and watched, into reservation 0. Check it is `MEM_PRIVATE`.
3. `CompareWhenShared` over it, then `Reset` it. That unmaps every view, so the `SharedPage` expires.
4. `Map` the same offset into reservations 1 and 2, resident and watched. The second map shares the first, and both are `MEM_MAPPED`.
5. **Require:**
   - a clearing `Collect` over each view returns `false`;
   - both views stay `PAGE_READWRITE`;
   - a store into one is seen in the other without a fault.
6. **Control:** after both views are reset and `ForgetSection(section)` runs, the same two maps are armed again. The clearing collect succeeds and the alias becomes `PAGE_READONLY`. So the mark is dropped where #9159 would drop it.

### Why single pages at 64 KiB boundaries

Wine 9.0's placeholder view mapping rejects a 16 KiB shared view off a 64 KiB boundary (`map shared guest page: Incorrect alignment`).
- **The full suite can't run under Wine.** Main's and 99aeb0ac56's full `windows_write_watch` stops there at the first shared check (`CheckArmed`), as cloud-5 recorded in BF-109.
- **The new case can.** It maps one page at a reservation's base (64 KiB-aligned) and section offset 0, which Wine maps and shares correctly. Windows accepts the same.

## The fix

At 47c8df4950, +3 lines in `WindowsMappings.hpp`:
- `struct Physical` gains `bool comparedWhenShared = false;` (`:576`).
- `CompareWhenShared` also sets `it->second.slot->comparedWhenShared = true;` (`:197`). Every view has a slot: both `views.emplace` sites in `Map` (`:129` resident, `:149` shared) pass it.
- `pageOf` copies the slot's mark into the `SharedPage` it creates: `shared->comparedWhenShared = slot.comparedWhenShared;` (`:99`).

### Where the mark is cleared

Only on `ForgetSection` (`:245-253`): it erases the section's `Physical` entries (`:251`), and the mark goes with them.
- That is where #9159 drops the page's mark for a new mapping anyway: a `Map` after `ForgetSection` makes a new slot and a new page.
- Views still mapped keep their page, and its mark, until they are unmapped, as under #9159.
- **Callers:** `DirectMemory.cpp:419,1196,1200` (direct memory release) and `Jit.cpp:66`. These are the points where the physical memory stops being the guest's, so I don't see anything else that should clear it.
- **Scope kept:** memory shared before it was ever marked never has the slot mark set, so it keeps today's tracking.

## Other ways a page can still be armed after it was marked

Line numbers are at 47c8df4950.

**`SharedPage` creation sites:**
- **`Map`'s `pageOf`** (`:95-102`): the only one. It now copies the slot's mark.
- `MapAlias`/`mapAliasRuns`, `demote`, `evict`, `Commit` and `SetProtection` create none.

**Arming sites:**
- **`Collect`'s alias loop, `other.armed |= arming`** (`:466`): respects the mark. A clearing All or Armed collect first passes `collectable()`, which returns `false` for a non-resident view whose page is marked (`:518`). A Fresh collect returns `false` on a marked page (`:371`). A non-clearing collect never arms.
- **`armResident`, `it->second.armed |= ...`** (`:691`): arms resident views only (private memory, one view per page). It is governed by `watchResident`, not the mark, which is #9159's documented "never shared" scope. When such a page becomes shared, `demote` resets `armed = 0`, and the mark (on the kept page) governs from then on.

**No other `armed |=` or protect-to-read-only path exists.** `Commit`, `SetProtection`, `Pin`, `HandleWrite`, `BeginHostWrite` and `demote` only clear `armed` or protect writable.

The gaps beyond #9159's two documented scopes ("already shared when imported" and "never imported") were the remap case fixed here and nothing else. A remap after `ForgetSection` is new memory by design.
