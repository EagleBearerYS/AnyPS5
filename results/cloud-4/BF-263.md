## Where the hint is sampled, and the race argument

**The key:**
- **With a write-watch hint** (`UntrackedHint(address, bytes) != 0`): the stamp is `{hint, NewestStamp, ForgetStamp, recorder write note, 1}`.
- **Without one** (Linux, shared pages, host regions): #6192's `{collect epoch, NewestStamp, ForgetStamp, write note, 0}`, unchanged.
- **The last field:** it keeps the two kinds apart, so a hint value can never equal an epoch value.
- **Forgets:** both forms are refused while a forget is in progress, as #6192 does.
- **The check:** `currentUntrackedStamp` recomputes the stamp in the recorded form. A recorded epoch stamp is checked by #6192's epoch rule, and a recorded hint stamp by the hint taken now.

**All four fields of a hint stamp come from the moment just before the bytes were read or compared, not from `captureValidation`.** The task asked for this only for the hint. I did it for the other three fields too, for this reason:
- **#6192 samples them at capture**, which is safe while the epoch bounds the stamp.
- **Once the stamp outlives an epoch,** a driver store (`MarkWritten`) or a forget that lands between the read and the capture would be absorbed the same way as a CPU store.
- **The fields themselves are #6192's;** only the moment they are taken moved.

**Snapshots (`source == nullptr`):**
- **Where:** `cachedTexture` takes main's `untrackedKey` (hint, `NewestStamp`, write note) at the point main takes it, "before the snapshot is read or compared". The range's `ForgetStamp` is taken just before it.
- **Recording:** the lookup record carries them (new `LookupRecord::untracked`) in three cases:
  - a hit kept by `untrackedKey` or by an equal compare;
  - a new snapshot read after it (not when `SnapshotWriteOverlaps` kept main from storing the key);
  - nothing else.
- **Capture:** `captureValidation` uses the record.

**Views (`surface.source != nullptr`) and storage images:**
- **Where the bytes are compared:** in the image's `StorageTexture::compareUntracked`, which the lookup's Refresh reaches for untracked memory.
  - `UnchangedSince` is false for an unwatched range, so Refresh always scans and compares.
  - The in-epoch `provedEpoch` shortcut is armed only by `refreshProved`, which needs `CollectWrites != 0`.
- **What it records:** `compareUntracked` builds its stamp (`{hint != 0, hint, NewestStamp, ForgetStamp, write note}`) before it compares. It stores the stamp in `comparedRanges` only when the bytes compare equal or the memo hits. Every upload, failed compare, save-before-unwatch and stored-save apply clears it.
- **The new accessor:** `StorageTexture::HintedComparison(address, bytes)` returns the hinted entry whose range contains the surface's.
- **Capture:** `captureValidation` takes it, from `surface.source` for a view and from the image itself for a storage element.

**Why a racing CPU store is never absorbed:**
- **The order:** the recorded hint H was taken before the bytes the proof stands on were read or compared.
- **A store after that read:** it leaves a write-watch mark on the page. The next walk of that page's hints stamps a hint generation newer than every earlier one, which is more than H.
- **Within the same epoch:** that walk may not have happened yet, because `UntrackedHint` is memoized per epoch. That is #6192's in-epoch acceptance, unchanged.
- **At the next ordering point:** the check's `UntrackedHint` misses the memo, walks, and sees a hint newer than H, so the proof fails and the walk compares again.
- **The other fields:** the same holds for a driver store (`NewestStamp` moves), a forget (the range's forget slot rises) and a new recorded GPU write (a new note id).
- **Containment:** a containing range's values are at least the surface's own, and any new event produces a value above all earlier ones. So a containing entry can only make the check walk more often, never accept a stale surface.

**What sampling at capture would have broken:** within the epoch, the memo returns the current `newestHint`. That can already include a store made after the compare, because another range's hint walk can collect it, which is exactly what the test's last control does. That stamp would then match forever, and the proof would never walk again.

**Self-check kept:** with `APS5_VERIFY_UNTRACKED_PROOFS=1`, #6192's block cross-checks every fast proof that used an untracked stamp, hinted or epoch, with the full walk. The test is `stamp[0] != 0`, which holds for both forms.

**Known cost:**
- **New storage images:** an image is uploaded, not compared, when it is created or re-uploaded after a change, so it has no hinted entry yet. Its first stamp is the epoch one, and the first proof across an ordering point walks once. That walk's equal compare records the hinted stamp, and later proofs hold across epochs.
- **Snapshots** get their hint at creation.
- **In Village's static menu,** that is one walk per range.

## Test

`agc_untracked_hint_proof` is `agc_driver_recorder_tests --untracked-hint-proof-only`, in the same commit.

**Setup:**
- **Memory:** write-watched memory (`AllocateWatched`), registered and host-imported, then `GuestMemory::Unwatch`ed. On Windows the unwatch starts hints.
- **The template:** two sampled 64 KiB surfaces, both views through their storage images.
- **`hinted`:** `UntrackedHint(block) != 0`. The test prints which rule it expects.

**Steps:**
1. **Red/green:**
   - **Sequence:** fast in the construction epoch, then bump. The first walk after the bump records the compare stamps. Then fast again in that epoch, then bump with no write.
   - **Expected:** the proof is fast exactly when `hinted`. That is fast on Windows with the commit, a full walk on the port (red), and a full walk on Linux on both heads (the epoch rule).
2. **CPU store after a bump:** full walk, and the first surface's storage image re-uploads (`Version()` moves).
3. **`MarkWritten` driver store in the same epoch:** full walk, and new content.
4. **Recorded GPU write note** (`Recorder::NotePendingWrite`) in the same epoch: full walk.
   - **Why not new content at once:** while the write is pending the driver does not take the CPU bytes.
   - **After `Sync` and the ordering point that reaps it:** full walk and new content.
5. **CPU store after the hint is sampled but before the stamp is recorded:**
   - **The hook:** a flush hook fires when the second surface's compare flushes. It stores into the first surface (already compared) and forces a hint walk over the whole block, as another range's walk would.
   - **Expected during that walk:** the first surface is not re-read. After the next bump, the proof walks and takes the new content.
   - **Discriminating:** an implementation that samples the hint at capture would record the advanced hint and stay fast here. The hook is reset with `recorder.Activate()`.
6. **After each control:** `settle` (bump, walk, bump) re-establishes the stamps and checks fast iff `hinted`.

**Constraints:**
- **No assertion that a placeholder or unimplemented path throws.**
- **On Linux:** every step passes under the epoch rule. The same test file applied to the port head would pass on Linux too, because without hints the commit changes nothing there. Red needs the PC.
