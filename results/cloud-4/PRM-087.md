- **The variable:** `error` at both sites. Neither `checkBackupData` nor `restoreBackupData` declares another `error` anywhere in the function, before or after the call.
- **The pattern** is the task's and main's: `SAVE_DATA_ERROR_BUSY` when mounted, `SAVE_DATA_ERROR_INTERNAL` on a host error.

**Why the test changed: a semantic conflict between #13324's test and #12748's test.**
- **What failed:** the merge with only the two call adaptations (f4597bd1c9, not pushed) built, but `guest_savedata_mount_status` aborted on its first run. That was the only failure, 12 of 13 passed, and #13551's equivalent (83c3448112) failed the same way, 13 of 14. The output:

  ```
  [SAVEDATA:native] umountWithBackup point=(null) -> 0x809f0000
  terminate called after throwing an instance of 'std::runtime_error'
    what():  param.json or param.sfo not found
  ```

- **The cause:**
  - The guest path resolver fixes its root on first use: `WorkingDirectory::root = canonical(current_path())` in `core/libs/prx/libc/src/General.cpp:323`.
  - #13324 added `CheckHostMountFailures` to the test. It changes the working directory to `<test root>/mount-host-failures` and calls `ResolvePath_nid_no_patch("/savedata0/probe")` there. That is now the test's first guest-path resolution, so `/app0` maps under `mount-host-failures`.
  - #12748's `CheckBackups` writes `app0/sce_sys/param.json` under the working directory, `<test root>`. So the running title's `checkBackupData` couldn't find it, and AppMetadata threw.
  - `strace` of the failing binary shows the lookups going to `/tmp/anyps5-savedata-mount-status-<n>/mount-host-failures/app0/sce_sys/param.json` and `.../param.sfo`, both ENOENT.
  - Each side passes alone: main has no `CheckBackups`, and the PR head has no `CheckHostMountFailures`.
- **The fix:** `CheckBackups` now writes `param.json` at whatever path the resolver gives for `/app0/sce_sys/param.json`, which is the path AppMetadata reads. `ResolvePath_nid_no_patch` comes from main's own new `#include "prx/libc/include/General.hpp"` in this file.
  - This was the only change I needed. I didn't touch #13324's code or the test's order. `save_root()` is the relative `SAVE_DIR` (`"_sd"`), so main's `_sd` checks don't depend on the resolver root.
  - The file is deleted with the test root at the end of `main()`.
