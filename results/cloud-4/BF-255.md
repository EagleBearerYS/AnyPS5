**`sceSaveDataRestoreBackupData`, as sourced:**
- **Checks:** the same as the check function.
- **Then:** it removes everything in the save directory and copies the backup in (`Restore` L258-277).
- **`INTERNAL`:** when the save directory is missing (`Restore` returns false), and also when a filesystem call fails.
- **Param and size:** the save's param and size files are replaced from the backup. They are separate files next to the save directory on main, where shadPS4 keeps `sce_sys` inside the save directory.

**`sceSaveDataUmountWithBackup`, as sourced:**
- **Before initialization:** `NOT_INITIALIZED` (shadPS4 `Umount` L513).
- **Null mount point:** `PARAMETER`.
- **Otherwise:** it unmounts, backs the save up and posts a type-1 event with the mount's user, the running title and the directory name.
  - **shadPS4:** the backup runs on a thread and its result is dispatched with the request's user, title and directory.
  - **fpPS4:** it unmounts and posts `UMOUNT_BACKUP_END`.
- **A failed copy:** the event's `error_code` is `INTERNAL`, as shadPS4's L167-173 does. The call itself returns OK.

**Where it differs from shadPS4, each said in the debt entry:**
- **Unknown mount point:** returns `NOT_MOUNTED`, reusing main's `sceSaveDataUmount2` code. shadPS4 says `NOT_FOUND`.
- **The copy is synchronous**, with the event queued at once. shadPS4 copies on a thread.
- **Another title's `titleId`:** the check and the restore return `NOT_FOUND`, since main keeps only the running title's saves (as `sceSaveDataDirNameSearch` does).
- **Directory names:** validated as `sceSaveDataMount3` does, so `.`, `..`, separators and unterminated names return `PARAMETER`.

**Reuse:**
- **Main's code, reused:** the mount slots and `isMountedDirectory` (for `BUSY`), `umount2`'s unmount steps, `load_param`/`store_param`/`read_param_file`, `blocks_path`, `RemoveTree`, and the event queue that `sceSaveDataGetEventResult` reads.
- **Added:** `MountSlot` gains `user_id`, set by `mount3`, for the event.
- **Shared name check:** `mount3`, `deleteSave` and `convert` each had a copy of the directory-name check. All three, plus the two new functions, now call one helper with the same rules.

**Where backups live:** `_sd_backup/<dir>/save`, with `save.param` and `save.blocks`.
- **Outside the save:** the title's mount and its used-block count don't see the backup.
- **Staging:** each backup is built in `_sd_backup_tmp/<dir>`, and the previous one is moved to `_sd_backup_old/<dir>` during the swap. These mirror shadPS4's `sce_backup`, `sce_backup_tmp` and `sce_backup_old`.
