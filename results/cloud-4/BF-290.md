## Summary

- On main, a refresh keeps the device alias path (borrowUnits) only when the refreshed surface has a host import (line 2196, and again at 2342-2343 through `direct`).
- Village's re-uploads are CPU uploads (path 2, 2892-2970). BF-292's task quotes the `[storage]` line: `cpu 357 / 5,097 MiB`, of which `flushed 356 / 4,819 MiB`. That is about 14 MiB per upload, which fits whole-image CPU uploads.
  - The upload takes the CPU path only when `HostImportFor(surface)` is null, or the keys are not Uncompressed (2764).
  - In both cases the alias is dropped at 2196, before FlushPending runs. FlushPending then stores the other image's results ("storage refresh", 4,691 MiB), and the refresh re-uploads the image from guest memory ("flushed"), with 0 bytes on the alias path.
  - Which of the two conditions holds for Village's pairs is what the diagnostic prints. The fix covers "no host import"; the keys case is a required refusal (row 11).
- The host-import requirement is not needed for correctness. Without an import, two things go wrong with the alias kept:
  - **Ordering:** on main the units are borrowed before the upload, and without an import the upload is the CPU path. For a 2D image that path replaces the whole image, borrowed units included, with stale guest bytes.
  - **The memory hook:** without an import, the refresh's own guest reads go through the recorder's memory-access hook (`Graphics/src/Recorder.cpp` 1068, `FlushPending(..., nullptr, "memory access", ...)`). These are the compare with the saved bytes (`equalsOriginal`, 2337; it runs because the CPU path leaves `layerOriginal` true) and the CPU upload's `ReadCommitted`. That hook stores the alias anyway, even though the refresh's own flush at 2214 left it out on purpose.
- **Fix:**
  - borrow after the upload, and borrow again the held units the upload replaced;
  - while a kept alias is being refreshed over, a hook flush leaves it out, exactly as the refresh's flush does.
  - Branch `fix/agc-storage-alias-device-handoff`, commit a7e04ab973 on 08a10d2253: 1 file of engine code (`Texture.cpp` +25 −9: refresh, a thread_local next to `refreshing`, one line in FlushPending), plus a test (`Recorder.cpp` +153, `CMakeLists.txt` +3 −1).
  - The test is red on main and green with the change. Each of the three parts has its own red patch (numbers below).
- **Diagnostic:** `diag/village-storage-alias-on-41ef8ff856`, commit 69cc079c0c on 41ef8ff856. Boot with `APS5_TRACE_STORAGE_ALIAS=1` (nothing else needed). It prints the top 8 (refreshed, flushed) pairs with both descriptors and the first condition that refused the alias.
- To see the fix on the Village tree, apply its engine change over the diag branch. It applies cleanly (hunks at offsets −8 and +1):
  `git checkout 69cc079c0c && git diff 08a10d2253 a7e04ab973 -- core/libs/prx/libSceAgcDriver/Graphics/src/Texture.cpp | git apply`

     - it sets `layerPending[unit]` for the written 64 KiB units (3871-3876);
     - it pushes Y into `pending.textures` once, guarded by `dirty` (3909-3920).
2. **The refresh of image X**
   - Refresh (2127) calls `refresh(0, trackedLayers)` (2151).

     - `refreshing = this` (2186) exempts X itself from the flush;

3. **The flush**
   - 2214: `FlushPending(scopeBegin, scopeBytes, alias.get(), "storage refresh", PublishScope::None)`. In FlushPending (4198):
     - `nothingToStore` pretest (4201-4212), skipping `except` (the alias) and `refreshing`;

     - store it: `writeBack(address, bytes)` (4310), with `flushReason = "storage refresh"` (4305).

4. **The write-back of Y**
   - writeBack (5909) selects Y's pending units inside the range and calls writeBackLayers (5965).
   - With a host import, it retiles into the import (6126-6137, writeBackWindows).
   - Without one (6320-6430), the steps are:
     - GPU image -> linear buffer -> retile -> host buffer;
     - `SubmitAndWait` (6395);
     - the CPU stores the bytes that differ from `original` with `GuestMemory::WriteChangedCommitted` (6417), which stamps the 64 KiB blocks.
   - It is counted under "storage refresh" by countStorageWriteBack (196).
5. **Back in X's refresh**
   - The stamps made by Y's store mark X's units changed (2286-2297).
   - The borrow block (2342-2364) runs only if `alias != nullptr && direct`, where `direct` (2342) again requires the host import.
   - Changed units that X holds pending are stored first (2426-2463).
   - Then (2470-2475) `uploadReason = ... flushed ? "flushed" : ...` and `upload(&changed)`.
6. **The upload of X**
   - upload (2676) dispatches by keys and import:
     - fast clear (2706-2762);
     - direct from the host import (2764-2891): per unit through uploadWindows when partial (2776-2795, forgetBorrowed of the uploaded units only), or whole (2799-2891, forgetBorrowed of all units);
     - CPU path (2892-2970), counted as path 2.

     - `forgetBorrowed(0, trackedLayers)` (2908);

     - staging, detile, a copy of the whole image, and `SubmitAndWait` (2913-2966).

   - **The hook inside the refresh:** guest reads go through the recorder's memory-access hook, `Graphics/src/Recorder.cpp` 1040-1068: a `SyncThrough` of pending writers, then `FlushPending(address, bytes, nullptr, "memory access", ...)`. 7. **The device alias path, when taken**
   - The borrow block (2343-2363): the alias's pending units that nothing stamped since its generation, and that X does not hold pending, are marked borrowed and dropped from `changed`.

     - counts it as path 3 under reason "alias";
     - notes `borrowedFrom` / `borrowedUnits` / `borrowedVersion`.
   - Y stays registered and pending. When X is written next, markLayersPending (3881-3891) clears Y's pending flag on the borrowed units ("superseded"), because X now carries those results.

**Cost on main without an import, per refresh of X over Y's results:**
- the writer wait in FlushPending;
- one blocking GPU readback with a CPU store of Y's units (6395, 6417);
- one blocking whole-image CPU upload of X (2964).

**With the alias kept (fix branch):**
- one recorded image copy;
- plus a whole-image CPU upload only when some other unit of X changed (a CPU or driver store), with the hook's `SyncThrough` wait before its read.

**The proof any device handoff must carry**, which the branch keeps for the case it opens (row 12):
- (a) Y's unit is newer than guest memory and than X: Y is pending with a known generation, nothing stamped it since, and X is not pending on it.
- (b) The copy reproduces the guest bytes bit for bit: same tiling, size, element size, layers and mips; both hold texels (keys Uncompressed).
- (c) GPU order:
  - the copy is recorded after Y's writers, in the same recorder;
  - it is recorded after anything that writes X's units in this refresh (the upload);
  - on the CPU path the upload submits and waits on its own batch, so the copy recorded after it runs after it.
- (d) The registry stays truthful: Y stays pending, so a CPU read still stores it, until X is written and supersedes those units (3881-3891).

## 4. Design and implementation

### D1, implemented: borrow without a host import (row 12)

- **Branch:** `fix/agc-storage-alias-device-handoff` (fork EagleBearerYS/AnyPS5), commit a7e04ab973, parent upstream main 08a10d2253.
- **Author and committer:** Yunus Shaikh, unsigned, no trailers.
- **Subject:** `perf(agc): take an aliased storage image's units on the device without a host import`.

Engine change, fix-branch lines in `Texture.cpp`:
- **1767:** `thread_local const StorageTexture* refreshingAlias`, next to `refreshing`.
- **2197:** the alias is dropped only when X's proved keys are not Uncompressed; the `HostImportFor` term is gone.
- **2215-2218:** from the refresh's flush to the end of the refresh, `refreshingAlias` is the kept alias, or nullptr when there is none (RAII, like the `Exempt` that sets `refreshing`).
- **4215:** in FlushPending, `if (except == nullptr) except = refreshingAlias;`. So the hook's flushes during the refresh (`equalsOriginal`, the CPU upload's read, the store of X's own pending units) leave the alias out, as the refresh's own flush does.
  - **Proof:** with the alias kept (main 2196-2206), each of its pending units is either (i) taken on the device by this refresh (new or held borrow), or (ii) stamped since its generation. A stamped unit is one its own write-back would drop: whole 64 KiB units, the droppable rule at main 2406-2413. The same rule is behind main's except at 2214.
  - An untracked alias, an alias unit with generation 0, or a unit pending in both and unstamped refuses the alias entirely (main 2197-2206).
- **2349:** the borrow block runs on `keys == DccKeys::Uncompressed`, where main required `direct`.
- **2358-2363:** a unit already held from the same alias version (`sameBorrow && borrowedUnits[unit]`) is recorded in `heldBorrows` instead of being skipped silently.
- **2472-2490:** the upload runs first.
  - Every upload path calls forgetBorrowed exactly for what it overwrites:
    - the CPU path forgets the whole image, or the selected layers' units;
    - the direct path forgets the uploaded units, or the whole image.
  - So each held unit that is no longer in `borrowedUnits` after the upload is borrowed again.
  - Then borrowUnits runs for the new and the re-taken units.
  - Through an import, a partial upload never touches borrowed units (they are not in `changed`), so the new order gives the same result there.
- Counters are unchanged: the borrow still counts as path 3, reason "alias".

What it does for Village's pattern: refreshing X over Y's pending results without an import now records one `vkCmdCopyImage` of Y's units. On main it ran a writer wait, a blocking readback with a CPU store, and a blocking whole-image CPU upload. Y stays pending until X is written.

**Not changed, and worth knowing:**
- If X's keys are proved Uncompressed at 2197 but `ProvedKeys()` at 2282 says otherwise, the alias is left out of the flushes while the borrow block does not run. Main has the same gap through its import path (the except at 2214 with no borrow). It is unchanged here and only possible for an image with DCC.
- On the non-direct path, units X itself holds pending and that did not change are still stored before the upload (2444-2453). A refresh that only borrows and uploads nothing would not need that store. In the ping-pong pattern X is not pending at its refresh, because Y's borrow and write superseded it, so it should not show.
- Whether Village's pairs have the same shape (rows 4-6) is unknown from the read. The diagnostic below answers it.

### D2, design only: offset aliases (row 3)

The source window per unit is sliceWindows(Y) of the unit's run shifted by the base delta, and the destination is sliceWindows(X) of the run. Allow it when:
- the delta is a multiple of 64 KiB;
- tileMode, pitch, bpp and mip layout are equal;
- the two window lists match one to one in extents.

Medium size; it needs geometry tests per tiling.

### D3, design only: different tiling or element size (rows 5-6), a device retile

1. Give the unit-shadow slab path a device slab without a host import: Y's write-back retiles its units into a device buffer in Y's layout, which is writeBackWindows with a slab target.
2. Register the slab as the newest content of those guest bytes.
3. X's upload detiles from the slab: uploadWindows with a slab source (PublishShadow / AnyShadowedOverlaps today assume an import).
4. The CPU sees the slab only through a flush, which stores the slab to guest memory.

**Proof:**
- the slab bytes equal what Y's write-back would store (same retiler, same keep rules: rows 13-16);
- X's detile of the slab equals its detile of guest memory after that store.

This is the general fix for reinterpreting aliases (for example RGBA8 over R32 with a different tiling). It is several hundred lines and is not on the branch.
