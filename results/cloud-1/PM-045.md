## Answer

At 661d3cba8d, four classes of path could still end a title before the stage's first use. Two of them are reached with no title involvement beyond loading its shaders (C1, C2). All four now defer to first use. Each fix is its own commit with a red/green mode in PreparedShaders.cpp:

| class | commit | what still aborted before first use |
|---|---|---|
| C1 | 19a3e0710 | a failure stored by the background registration preparation, rethrown by the scope that libSceAgc opens around every pipeline ABI call and by every ABI entry point |
| C3 | 502085c15 | PrepareGraphicsStages' vertex-input decode, which runs outside #6366's catch |
| C4 | e986ee0f7 | the rect-list pairing in ResolveGraphicsAbi / ResolvePreparedGraphics (null pixel, stage without artifact, BuildRectListShaders) |
| C2 | f1ad37c3a | registration (sceAgcCreateShader) refusing a pixel or vertex shader whose stage inputs the recompiler does not implement |

Everything else that throws on these paths is one of: a driver failure that already happened, ProcessShutdown, misuse of the ABI (unregistered or replaced header, bad pointer), a malformed header, an internal invariant, or the APS5_SYNC_SHADER_PREPARE debug switch. Those still throw (table below).

For the PM: C1 reverses a decision #6366 states. 8c55d15aa's message says "a failure stored by the shader's registration preparation still propagate[s]", and 695ec6cc4 asserted it (`ExpectFailure(ResolveShaderAbi(store), "is not a valid runtime value")`, removed by C1). The stored exception is rethrown unchanged at the stage's first draw or dispatch, so C1 only moves the abort from pipeline creation to first use. It is a separate commit and can be dropped on its own.

## Ratings

Village pre-creates PSOs for 3,900+ shaders and registers all of them at load.

- C1: reached by any title whose background registration compile fails for a pixel shader without interpolants or a simple vertex shader. This is the #6366 failure ("T# pointer is a phi of user data and a ballot") when registration rather than the ABI prepares the stage. Before: the title ended at sceAgcLinkShaders even if the pipeline was never drawn. Now: the stage's first draw or dispatch rethrows the same stored exception, which is the honest behaviour.
- C3: reached by NGG vertex shaders that use their workgroup (common on PS5), and by mesh/hull/domain stages with statically bound or otherwise unsupported vertex inputs. The draw decodes the same header, so an abort at first use names the same refusal.
- C4: reached by depth-only rect-list pipelines, by stencil-exporting pixel shaders on devices without VK_EXT_shader_stencil_export, by passthrough interpolants, and on devices without tessellation. The draw builds the pair itself, so the honest place to fail is that pair's draw.
- C2: reached at load, before any pipeline, by any registered shader using SAMPLE_COVERAGE or PERSP_PULL_MODEL without interpolants, or statically bound vertex attributes. Registration already defers unsupported instructions through ShaderRecompiler::UnsupportedInstructionError (SR:775-780). C2 adds Graphics::UnsupportedStageInputError for these two decoder gaps only. The malformed-header checks main pins with tests still throw.

## First use names the same cause (step 4)

- C1: SourceHandleFor SR:476 and InvocationFor SR:628 rethrow the stored exception_ptr, so the message is identical. Test: the compute shader's dispatch fails with "is not a valid runtime value".
- C3: Draw.cpp:208 decodes the same header with the draw's user data → SIS:228, the same message once the tables are bound. With null tables the draw names "null vertex attribute table address" (SIS:221-222) first, which is a different but true cause of that draw. Test: a draw with tables bound fails with "statically bound vertex attributes are not implemented".
- C4: DrawRectangle SR:497-506 → ResolvePreparedGraphics → BuildRectListShaders, the same message, because the ABI records no progress for the refused pair. Test: the passthrough rect-list draw fails with "custom per-vertex interpolation is unsupported". The null-pixel draw on the same front succeeds although the passthrough pair and a never-prepared fragment are also recorded on that front.
- C2: decodeDraw (DrawDecode.cpp:127) and Draw.cpp:208 run the same decoders. Test: the draw fails with "unsupported SPI_PS_INPUT_ENA/ADDR bit combination".
- One case would have reported the wrong cause, and C4 fixes it. When a draw builds the rectangles of its front stage it loops over every fragment recorded on that front, so another fragment's pair (one that has no artifact, or that the builder refuses) would have aborted an unrelated draw with that fragment's reason. Now only the drawn fragment's pair can fail a draw. Two mutation runs show it: rethrowing every pair's builder failure, or requiring artifacts for every pair at use, makes the null-pixel draw fail with "Rect-list SPIR-V: custom per-vertex interpolation is unsupported" and "AGC driver: rectangle ABI has missing stage artifacts" respectively.

## Left as is

- Rect-list pairs are built per fragment shader, not per variant. A pixel with both a passthrough variant and a normal one fails the normal variant's rect-list draw with the passthrough reason. This was unreachable before because the ABI aborted first.
- A pair the builder refuses is rebuilt, and refused again, at each later ABI call that touches its front stage. Every refusal check runs before SPIR-V emission (RLS:379-394), so a retry costs only those checks.
- C4 marks a pixel deferred when its rect pair is refused, which also silences that pixel's "has no artifact prepared at registration" note at use.
