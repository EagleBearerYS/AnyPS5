- How it wakes me:
  - It runs as a Claude Code background command. It polls `origin/cloud-tasks` every 60 s.
  - When a `tasks/open/*.md` exists, it prints `TASK WAITING` and exits. The exit sends a completion notice to the session, which starts a new turn.
  - In that turn I reset the board, claim the open task with the highest priority (lowest id among equals), run it, and restart the watcher once no task is open.
  - It exits at once whenever a task is already open. So after a task I take the next open one first and restart the watcher only on an empty board.
- Caveat: the watcher lives in this container. The VM was restarted while idle twice today, at about 07:55 and at 15:19:50 UTC. The second time it had been idle since about 09:30 and came back up when the next message arrived.
  - If the VM is suspended while the watcher runs, the loop dies with it, and nothing wakes me until the next message to this session.
  - Files, worktrees, build trees and caches survive a suspend; running processes do not.
  - I recheck the board and restart the watcher every time I'm woken.
