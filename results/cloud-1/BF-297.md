## How to run it

```
APS5_TRACE_STORAGE_ALIAS=1
```

This is a presence switch. It works without `APS5_PROFILE_DRAW` (an unprofiled boot): the census counts at its own hooks, ahead of the `Profiled()` early returns.

The lines go to the same log as the profile lines (`AgcDriver::ProfilePrint_nid_no_patch`, stderr):
- every 10 s;
- once more at process exit, for the last partial window. A test that runs for less than 10 s still prints.

**With the variable unset**, every hook is one `static const bool` test:
- `storageAliasCensus()`, `Texture.cpp:184`, read once per process;
- in `countStorageUpload` and `countStorageWriteBack` (`Texture.cpp:431, 444`), `StorageTexture::refresh` (`:2477`) and `markLayersPending` (`:4169`).

Two other changes run even when the switch is unset, and both are cheap:
- **A thread-local write per dispatch.** `VulkanDevice::dispatch` and `DispatchRecipe` set the current program address through an RAII `StorageAliasProgramScope` (`VulkanDevice.cpp:5486, 5838`; type at `Texture.hpp:726`).
- **Refusal bookkeeping in `refresh`.** The four alias checks after `pendingAlias()` now also record which one refused (`Texture.cpp:2442-2465`). They run the same tests, in the same order, with the same short-circuiting as the base's single expression (`base Texture.cpp:2187-2199`):
  - `ProvedClearKeys` is evaluated once, and only while an alias is chosen;
  - `HostImportFor` only after the keys check passed.

## The line format

**The summary line, then up to 8 pair lines:**

```
[storage-alias] <window> s[ (at exit)]: storage refresh write-backs <count>/<MiB> MiB, flushed re-uploads <count>/<MiB> MiB; <n> (X, Y) pairs, top <k> by bytes below; write-backs outside a refresh <count>/<MiB> MiB, over the 64-pair table <count>/<MiB> MiB
[storage-alias] <rank>: X <image> | Y <image> | overlap 0x<base>+0x<bytes> | write-back <count>/<MiB> MiB, re-upload <count>/<MiB> MiB | not borrowed: <reason> x<count>[, <reason> x<count>...] | X programs <top 3> | Y programs <top 3>
```

**What `<image>` holds:**

```
0x<base>+0x<bytes> fmt 0x<format> dim <dimension> <width>x<height> d/la <depthOrLastArray> layers <imageLayers> depth <imageDepth> mips <mipCount> tile <tileMode> pitch <mip 0 pitch bytes> dcc yes|no
```
- `dim` is `TextureDimension` (`GuestTextureResource.hpp:56-64`): 0 1D, 1 2D, 2 2D array, 3 cube, 4 3D, 5 1D array, 6 2D MSAA.
- `tile` is `TextureTileMode` (`GuestTextureResource.hpp:11-...`): 0 is linear (`kLinear`). Every other value is a tiled mode, in declaration order.
- `pitch` is mip 0's `pitchBytes` from `DescribeSurface`.

**What X and Y are:**
- **X** is the image whose refresh flushed and then re-uploaded.
- **Y** is the image whose pending results that refresh wrote back.

**What is counted:**
- **The totals** are counted at the same points as the `[storage]` line:
  - **"storage refresh" write-backs:** `countStorageWriteBack` with `flushReason == "storage refresh"`;
  - **"flushed" re-uploads:** `countStorageUpload` with `uploadReason == "flushed"`.
- **A pair's write-back** is Y's write-back.
- **A pair's re-upload** is each "flushed" upload of X made in the refresh that wrote Y back. If one refresh writes back two images, its re-upload counts under both pairs; the totals count it once.
- **"outside a refresh"** counts "storage refresh" write-backs made with no refresh scope on the thread. The only production caller of that reason is `refresh` (`Texture.cpp:2522`), so on Village this should stay 0. In the tests, three `tests/Recorder.cpp` cases call `FlushPending(…, "storage refresh", …)` directly, and those show up there.
- **"over the 64-pair table"** counts write-backs of pairs that found the 10 s table full.

**The programs:**
- **X programs** are the program addresses bound when X's refresh ran: the dispatch whose resource lookup refreshed X. That is `VulkanDevice::dispatch`/`DispatchRecipe`'s `programAddress`, held for the whole call.
- **Y programs** are the program that last marked Y pending (`markLayersPending`), i.e. the dispatch that wrote Y.
- **`none`** means no dispatch was on the thread: a draw, a packet or the flush hook.
- Each pair lists its top 3 per side, as `0x<address> x<count>`.

**The bookkeeping** is a 64-entry table, scanned linearly and reset at each report. Its key is both images' base, bytes, format, dimension, width, height, d/la, mips, tile and DCC (`AliasImage`/`aliasKey`, `Texture.cpp:210-251`; `censusWriteBack` `:364`). The writer map (Y → program) is cleared once it passes 8,192 images. All of it sits behind one leaf mutex, taken only with the switch set (`AliasCensus`, `Texture.cpp:298-313`).

## Why the device alias path wasn't used: each reason string

**How a reason is chosen.** For each pending image Y overlapping X's refresh scope, the census takes the reason at refresh time, under the registry mutex and before the flush (`Texture.cpp:2477-2516`). It replays the conditions of `pendingAlias()` and of `refresh`'s alias checks in their order, and records the **first** one that refuses Y. Y's state is read before its write-back can change it (for example `uploadedKeys` at `Texture.cpp:6142` in the write-back).

**Rows 21–25: the alias was picked, then refused.** `pendingAlias()` picked Y, and a later check in `refresh` dropped it. With the alias dropped, the flush stores Y like any other image.

**When the census shows nothing.** If Y passes everything above, it stays exempt from the flush (`FlushPending(…, alias.get(), "storage refresh", …)`, `Texture.cpp:2522`) and makes no write-back, so no pair is counted. Its units are then borrowed on the device:
- `borrowUnits` (`:6162`, base `:5845`) when `direct` holds (`:2651`, base `:2335`);
- per unit, `aliasTracked && alias->layerPending[unit] && !aliasStamped[unit] && alias->layerGeneration[unit] != 0 && !layerPending[unit]` (`:2661`, base `:2345`).

`borrowUnits` itself refuses nothing (its only check is `Require(!windows.empty(), …)`, `:6165`).

A chosen alias that is kept but then not borrowed, because `direct` fails (the keys or the import changed after the flush), also writes nothing back, so it is not counted either.

## Notes for the boot

- **Reading the lines.** With `APS5_PROFILE_DRAW` also set, the `[storage-alias]` totals should track the `[storage]` line's "storage refresh" write-backs and "flushed" uploads (same counting points). Without it, only `[storage-alias]` prints.
- **What decides the next step** is the "not borrowed" column, for BF-290 and BF-296:
  - **A shape row** (4–17) means the device copy needs a reinterpretation or retile path that `borrowUnits` doesn't have (it is a same-shape `vkCmdCopyImage`).
  - **Rows 18–25** mean the shapes match and something in the state stopped it.
- **Cost with the switch set:** a short linear scan of a 64-entry table per storage refresh write-back, plus one map write per `markLayersPending`, all under one mutex. That is negligible against the MiB-scale write-backs it counts, but it is not free. Boot with the switch only for the census.
