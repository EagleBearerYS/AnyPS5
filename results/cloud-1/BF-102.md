## 2. Step 2 commit and the parked-spare choice

**`98724e39d4` perf(agc): take reused dispatches' spare fault records from the shared fault arena.** 7 files, +262 / −63.

- **`BdaFaultRecord`** (new, `BdaResources.hpp`) is one slot of the device's fault arena, of the build's own slot size:
  - 32 bytes (`sizeof(BdaAbi::Fault)`, stride aligned to `minStorageBufferOffsetAlignment`) for a report-only build;
  - `FaultBufferBytes` (24,620) otherwise.
  - Both sizes come from the same chunks as the builds' own slots.
  - `Descriptor()` is `{chunk buffer, offset, slotBytes}` and `Bytes()` is the slot.
  - `Park()` clears a dirty slot and counts the record as parked; `Unpark()` counts it as in use again.
  - The destructor gives the slot back through `giveSlot`: cleared if dirty, returned to the free list, and a chunk that becomes fully free is dropped.
- **`BdaResources`:**
  - `FaultRecord(context)` replaces BF-099's static `FaultRecord` and `FaultRecordDescriptor`.
  - `CheckFault(BdaFaultRecord&)` replaces `CheckFault(Buffer&)`, and reads only the report for a 32-byte record.
  - The arena helpers `takeFreeSlot`, `giveSlot`, `hasFreeSlot`, `uncountChunk` and `dropIdleArena` are shared by builds' slots and records.
  - An arena is torn down only when it has no holders and no records.
  - `FaultSlotCounts` gains `records`, `recordBytes`, `parked` and `bytes` (chunk bytes).
- **`ShaderResources`** (a 10-line diff against the merge):
  - a new spare takes `bda->FaultRecord(context)` and builds its descriptor set from `Descriptor()`;
  - a reused spare is `Unpark`ed;
  - `~DispatchUse` `Park`s the record before putting the spare back in the build's pool.
- **The slot never moves.**
  - A spare takes its slot when it is created and keeps it until the build's spare pool is destroyed, so its descriptor set binds the slot for good.
  - Nothing reclaims a record's slot. The GPU-lock reclaim covers only builds' holder slots.
- **`APS5_NO_SHARED_FAULT_SLOTS=1`:** a spare gets a dedicated `FaultBufferBytes` buffer, counted as its own chunk, as BF-099 did. The `docs/dev/ENVIRONMENT.md` row now names spare records.

**Parked-spare choice: a parked spare keeps its slot.** Returning is the default, but here it costs measurably, so I chose to keep. The measurement compared the two choices directly on BF-099's harness (§5); "return" ran the first pushed version, `582aeb7073`.

| µs per dispatch, 1 texture, 8 per submission | runs (median of windows 2–6) |
|---|---|
| return slot on park (`582aeb7073`) | 33.0, 31.3, 35.3 |
| keep slot on park | 27.0, 29.3, plus §5's final runs |
| own buffers (`APS5_NO_SHARED_FAULT_SLOTS=1`) | 27.2, 27.6, 28.6, plus §5's final runs |

At 128 textures: return 70.2 and 74.9; keep 68.0; own 68.5 and 71.1.

Why returning costs:
- **Burst size:** the harness reaps uses only at its pending-write flush every 64 submissions, so up to 511 uses are in flight (911 during warm-up).
- **Churn:** with returning, each flush gives back every slot, so whole chunks empty and are dropped (25 → 7 chunks). The next burst creates them again from the buffer pool and zeroes 517,104 bytes for each one. That is about 21 KB of memset per dispatch, plus descriptor rewrites for the spares whose slot moved.
- **A cheaper return doesn't fix it:** zeroing only each slot's must-clean words would not remove the cost, because a full slot's written-page header alone is 16,424 bytes.

Why keeping is acceptable:
- **Memory:** keeping holds the peak burst's slots for the life of the build's spare pool: 44 chunks here, about the same as the own buffers BF-099 kept (§5).
- **The descriptor set dominates anyway:** a parked spare keeps its BF-099 descriptor set either way. On lavapipe that set's pool is 16 MiB at the default image-table capacity (a 16,781,312-byte mapping per set, seen in gdb), far more than the fault slot.
- **Report-only spares:** they hold 32 bytes each in the build's own chunk.

## 3. New case: red and green

**Device case `agc_driver_address_dispatch_reuse` → `spares`** (lavapipe; skipped with `APS5_NO_SHARED_FAULT_SLOTS=1`):
- **Program:** `ReportReaderCode`, a BDA read whose value is stored through a V# in s[4:7], so the build is report-only and takes a 32-byte slot.
- **Setup:** eight blocks of one program, compiled once, with push constants patched per block. Two warm-up dispatches. "Quiet" means every arena record is parked (`parked == records`, bounded poll), because the recorder's release thread drops a batch's uses shortly after WaitIdle.
- **Batches:** two batches of eight dispatches, each under one GpuMutex hold, so all eight uses are in flight together.
- **During each batch:**
  - the spares in use (`records − parked`) number 7, or 8 while the previous use's release still holds the build's own record;
  - each new record is 32 bytes;
  - the arena grows neither chunks nor bytes, because they fit in the build's own chunk.
- **After each batch:** every record is parked, records and recordBytes are unchanged (the slots go back to the build's spare pool, not to the arena), and chunks and bytes don't grow.
- **Second batch:** it takes the parked spares, at most one new record (the 7-or-8 case).
- **Reuse:** 16 reuses, no builds, and the output word is one of the eight blocks' values.

**Mock `faultSlotTests`** (`tests/BdaResources.cpp`, in agc_driver_graphics):
- seven `FaultRecord`s of a report-only build share the build's chunk with range 32: records +7, recordBytes +224, no chunk growth;
- records 1 and 4 share no fault memory with each other or with the build's slot;
- faults written into them (0x7fff88880000 and 0x7fff99990000) each make `CheckFault(record)` reject with its own address;
- record 0 checks clean, and the build's own report still holds 0x7fff55550000;
- two parked records count as parked and keep their slots, and the parked record 1 now checks clean;
- `Unpark` uncounts record 1;
- destroying the records gives every slot back, the parked count included.

## 6. Found on the way: without the image-table cap, BF-099's spares exhaust memory in this harness

**What happened:** the first harness runs left out BF-099's `APS5_IMAGE_TABLE_CAPACITY=4096` (a local patch) and ran at about 100,000 µs per dispatch. RssShmem grew about 200 MB/s until the cgroup OOM killer stopped the run at 13.8 GB. The same happened with spares on their own buffers (`APS5_NO_SHARED_FAULT_SLOTS=1`), so it is BF-099's spare pool, not the arena.

**How it was traced:**
- gdb: every dispatch's `BeginDispatchUse` called `faultRecordBindings`, then `DescriptorCache::AllocateRewritten`, then `Allocate` — a dedicated lavapipe descriptor pool of 16,781,312 bytes, which lavapipe zeroes (about 100 ms).
- The uses are reaped only at the harness's pending-write flush, so the pool grows by one spare per dispatch until then.

**Bound:** the spare pool is bounded only by the number of uses in flight between reaps, and each spare keeps a full descriptor set for the build's life.

**Possible fixes, not done here (outside this task):**
- reap finished batches before creating a spare;
- cap a build's spare pool and fall back to a sync past the cap;
- size a spare's set to the build's table instead of the device capacity.
