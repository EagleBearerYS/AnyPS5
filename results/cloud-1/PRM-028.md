## What it contains

**The fix.** `0beb19604`'s `ShaderResources.cpp` hunk, unchanged; it applied to `89ab0ea75` on its own.
- `CompleteSnapshotWrites(snapshots)` syncs the recorder through every snapshot range that a recorded write overlaps.
- `Revalidate`'s address branch calls it right after the `InUse()` refusal and before `guestMemory.SameSnapshots(snapshots)`.

**Debt line.** `0beb19604`'s debt hunk conflicted, because its context included BF-040's overflow bullet (`9dc75640f`), which is not in #6636. I resolved it on #6636's file: the "Reused address-based draw builds" entry gains the same sentence. "Recorded GPU writes over a snapshot's range are completed before the snapshots are compared, so a capture made before such a write lands is refused rather than proven against the old bytes."

**The draw red.** A new case, `PendingSnapshotWrite`, in `tests/execution/AddressDrawReuse.cpp`, run after `GuestWrite`:
1. The draw's snapshots are the vertex and pixel programs plus 8 bytes over `guest[PointerOffset]`. That is the pointer the pixel shader loads, so it is a live, writable, imported region.
2. The draw runs twice with that capture, so its build is in the cache, and reads 1.0 (color 255).
3. In one GPU-lock scope, without waiting:
   - `device.FillBuffer(guest+0, 16, {pointer to guest+32, …})` records a fill that rewrites the pointer, so it now points at 0.0;
   - the same draw is offered with the old capture.
4. **Required:**
   - the draw reads the new value (color 0);
   - the address reuse counters show exactly one more `Snapshots` refusal and no reuse;
   - `Builds()` goes up by one.
5. The pointer is restored and a final draw reads 1.0 again.

## Red/green

On the same build of this branch, without and with the one line `CompleteSnapshotWrites(snapshots);` (removed for the red run, then restored):

| | result |
|---|---|
| **without the sync (red)** | exit 1: `AGC graphics: address draw reuse: a draw whose captured snapshot a pending GPU write changed was not refused for a changed snapshot and rebuilt (1 reuses, 0 builds)` |
| **with the sync (green, `6e5b5bdf4`)** | exit 0: `address draw reuse tests passed (512 extra registered ranges)` |

In the red run the color check before the counter check still passed. The pointer is read in place, so the reused draw also saw the new pointer. What the sync changes is that the reuse proof no longer passes against memory the fill has not reached yet.

In the green run, the rebuild logs the expected diagnostic once. The capture predates the fill, and the live region serves the GPU: `[gpu] guest snapshot differs from registered memory: snapshot …+0x8 (live region …, writable, host-backed) differs first at +0x0; the live region serves the GPU`.
