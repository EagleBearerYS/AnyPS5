## What changed

`ShaderResources.cpp` (cachedTexture):

- **Eligibility.** A view takes the new path only when all of these hold:
  - it is a sampled k3D view with no storage-image source;
  - the write generation is 0, meaning the range is not wholly watched and committed;
  - its keys are `Uncompressed` and it has no DCC address;
  - it uses neither depth comparison nor sRGB expansion.
- **Slab list.** `committedSlabs` splits the view into its guest slabs (`SurfaceGeometry::layerBytes`):
  - one slice of the Z_X/R_X per-slice branch, or of a linear volume;
  - `blockDepth` slices of a thick volume.

  It keeps every slab with at least one committed page. The ranges come from `CollectCommittedWrites` when it returned them, otherwise from one `GuestMemory::DescribeCommitted`. Selection is by commitment, not by the allocation. When every slab has a committed page, the result is `nullopt` and the main path runs unchanged.
- **Snapshot.** The snapshot packs only those slabs. `readSnapshot` reads each run of adjacent slabs with one `GuestMemory::ReadCommitted` under `ReadSite::TextureRead`, so uncommitted pages inside an uploaded slab still read as zeros.
- **Cache entry** (`CachedTexture::slabs`):
  - A hit also needs `it->slabs == slabs`, so a commit or decommit that changes the set of uploaded slabs always rebuilds. This holds watched or not.
  - On main, `it->committed != committed` only makes `unchanged()` false. The hit still falls through to `kept()`/`equalsCommitted()`, and `EqualsCommitted` compares only committed pages. So main kept a ≤256 KiB snapshot (or an unwatched one) across a decommit and rebuilt only when the bytes had been dropped.
  - The write generation (`CollectCommittedWrites`) already covers only committed pages, which all lie in uploaded slabs.
  - The compare (`equalsCommittedSlabs`) checks the packed bytes run by run.
  - `untrackedKey` stays over the whole range, as on main, and so does the `SnapshotWriteOverlaps` check.
  - `SampledTextureBudget` counts the image's `AllocationBytes()`, which is still the real full-extent image.
  - The ≤256 KiB keep and drop rule now applies to the packed size, the bytes actually held.
- **Disabled path.** `APS5_NO_TEXTURE_CACHE` uses the same packed read.
- **Log line.** A new line next to `covers … MiB`, rate-limited the same way (first 5, then powers of two):
  `[gpu] sampled view 0x… (WxH format F, dimension 4, tile T, slices a..b) uploads the N of its M slabs holding committed guest memory (X of Y MiB) and Z zero-filled slices; K such views`

`Texture.cpp`/`Texture.hpp` (snapshot constructor), new optional parameter `packedSlabs`:

- **Buffers.** Staging, tiled and linear buffers are sized to the uploaded slabs only. Each uploaded layer is detiled from its packed offset, with its real slice index as the swizzle input, into a packed linear slot.
- **Zero-filled layers.** One `DeviceBuffer` of `sliceLinearBytes` is filled with 0 by `vkCmdFillBuffer`, recorded before the existing TRANSFER→COMPUTE barrier. It is then copied with `vkCmdCopyBufferToImage` into each (level, z) the skipped layers have.
  - No clear is used, so BC formats take the same path.
  - The repacked format (`Format10_11_11Float`) needs no repack of the zeros: `RepackTextureWord(0) == 0`.
  - The existing COMPUTE→TRANSFER barrier also gets TRANSFER as a source stage, plus a buffer barrier for the zeros.
- **Recorder.** `Keep` counts the packed sizes, so kept bytes are the real ones.
- **No committed slab at all.** No staging, tiled or linear buffer is made, and the image is all zeros.

## Scope notes

- **Depth copy** can't take a 3D view at all. cachedTexture's `depthCopy` requires a non-3D dimension, and the snapshot constructor refuses 3D depth comparison.
- **Storage-image source:** the texture is a view or copy of a StorageTexture image that already holds the surface, so there is no snapshot to trim. Also, a partially committed range normally fails `HostImportCovers`, so such a view reaches the snapshot path anyway.
- **sRGB expand** could take a partial view, since its blit runs after both copies, but it is left on main's path as asked.
- **DCC:** under clear keys, `FillDccClear` fills the snapshot without reading guest memory, so there is nothing to save. With `Uncompressed` keys over DCC metadata the view is excluded too.
- **Thick 3D** is included, because it was contained: a slab of `blockDepth` slices is uploaded or zero-filled as a whole.
- **Linear 3D** (one slice per slab) is included by the same rule.
- **Arrays and cubes** are unchanged (#9318's).
- **Partial decommit of an uploaded slab** behaves as on main. If the snapshot is still kept for comparison (≤256 KiB packed, or unwatched memory), decommitting part of a slab that stays uploaded keeps the old texels for the decommitted pages. PartiallyResidentSnapshot's "after a page inside it was decommitted" case expects exactly that on main. A whole slab decommitted always rebuilds.
- **Cost:** at most one extra `DescribeCommitted` walk per lookup, and only for k3D views whose range is not wholly watched and committed and whose committed ranges `CollectCommittedWrites` did not return. Uploads read one `ReadCommitted` per run of adjacent committed slabs: a single call for Ghost's leading 157 slices.

## Tests (lavapipe, new modes of `tests/execution/PartiallyResidentSnapshot.cpp`)

The modes are registered as `agc_driver_partially_<mode>`, with SKIP_RETURN_CODE 77, the libc PATH on Windows, and `ANYPS5_NO_SHADER_CACHE=1;APS5_NO_SAMPLED_FROM_STORAGE=1`.

### Cache and memory modes

These use a standalone Context and `CachedSampledTexture`, like the existing cases, with two counters:

- the bytes of the surface seen by the flush hook, which is what the snapshot read;
- `Recorder::OpenKeptBytes()`, which is staging + tiled + linear (+ zeros) kept by the upload.

Every volume is 64 deep. Each committed slab is filled with its own uniform texel pattern.

| mode | surface | committed | bytes read (branch / main) | upload bytes kept (branch / main) |
|---|---|---|---|---|
| `committed-volume` (the reproduction) | R_X (0x1b), format 71 (16_16_16_16 float), 64x64, one 64 KiB slab per slice | slices 0..21 + the first 16 KiB of slice 22 (N=23, last one partial) | 1507328 / 4194304 | 4587520 / 12582912 |
| `committed-volume-thick` | S_X (0x19) thick, 4 slabs of 16 slices (512 KiB each) | slab 0 + half of slab 1 | 1048576 / 2097152 | 3178496 / not reached (main stops at the read) |
| `committed-volume-linear` | linear, 32 KiB slices | 23, last one half | 753664 / 2097152 | 2293760 / not reached (main stops at the read) |
| `committed-volume-compare` | as committed-volume | 3 slabs (packed 192 KiB, so the snapshot is kept for comparison) | 196608 / 4194304 | 655360 / not reached (main stops at the read) |
| control `committed-volume-whole` | as committed-volume | all 64 | 4194304 / 4194304 | 12582912 / 12582912 |
| control `committed-array` | 2D array, 64 layers | 23, last one partial | 4194304 / 4194304 | 12582912 / 12582912 |

Main fails the four reds at the first lookup, on the bytes it read; the controls pass on both trees.

The steps after the first lookup:

- `committed-volume`:
  1. Again: same texture, 0 bytes read.
  2. Commit slice 30: rebuilt, 24 slices read. Again: kept.
  3. Decommit slice 5: rebuilt, 23 slices read. Again: kept.
  4. Commit the rest of slice 22: rebuilt, because a 1.4 MiB snapshot is dropped. Again: kept.
- `committed-volume-compare`:
  1. Commit zero pages in its partial slab: compared run by run (196608 bytes) and kept.
  2. A CPU write: compared and rebuilt (2 x 196608 bytes). Again: kept.

### Sampling modes

These run on a VulkanDevice with the guest compute code from ImageArraySampleOnVolume:

- `image_sample_lz 3d` + `image_load 3d`, or the 2d_array forms;
- `image_sample_l` at LOD 1 for the mipmapped case.

Sampling:

- 256 lanes: 32 per slice, at z = 0, 5, 21, 22, 23, 30, 40, 63.
- At slice centres (r = (z+0.5)/depth), with point filtering.
- That covers the last committed slice, the first uncommitted one and the last one.

Checks:

- Fully committed slabs read their pattern.
- Uncommitted slabs read zero texels.
- The partial slab reads only its pattern or zero, and both occur.
- An FNV-1a hash of every result word is printed.
