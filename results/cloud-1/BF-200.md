**The request pool** (what main's `sceNpCreateRequest`, `sceNpCreateAsyncRequest`, `sceNpDeleteRequest` and `sceNpAbortRequest` do, and what the six now share):
- IDs come from one atomic counter starting at 1 and are kept in `liveRequests`.
- **No limit:** main's pool has none, so there is no limit to follow or test; inventing one would be a guess.
- **Delete:** a live ID is removed and returns 0. An ID never created or already deleted, including 0 and negative IDs, returns `SCE_NP_ERROR_REQUEST_NOT_FOUND` (0x80550014).
- **Abort:** a live ID returns 0 and stays live. Otherwise it returns `REQUEST_NOT_FOUND`.
- **Shared IDs:** because the pool is shared, `sceNpDeleteRequest` accepts an IdMapper or Int ID and the reverse. Whether the console keeps separate pools is unknown, and the debt entry says so.

**Why the two account-ID → online-ID/NpId lookups stay a throw:**
- **No answer on main:** main gives no answer for an account ID mapped to an online ID or NpId. The Int form `sceNpManagerIntGetOnlineIdByAccountId` has no export on main; it is only in #10617's pending list.
- **The input is contested:** the input is an account ID, and both #6990 (a local account ID while offline) and #7412 (a dummy account ID) change only `sceNpGetAccountIdA`, which is main's sole source of one.
- **No PR's answer taken:** following the task, neither PR's answer was used.

**Gaps** (in `docs/dev/debt/libSceNpManager.md`, four new entries, each under 1,000 characters):
- The signatures are unverified.
- The pool is shared.
- The lookups read no argument, so the errors the console would give for a null pointer or an unknown request ID (which `sceNpGetAccountId` checks first) are not returned.
- Nothing is measured on a console.
