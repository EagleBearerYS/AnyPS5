### `ShadowedValue`

PM-051's test. PM-051 never pushed it, so I wrote it from their description, as the steps below. It runs after `ThrowingProof` in `main`.
1. **Setup.** It sets the import watch to Watch on Linux (restored on exit), as #6682's own test does. It takes a fresh write-watched 64 KiB heap, registered writable and holding 1.0, and points the scene's pixel shader at it.
2. **Build and reuse.** The first draw builds and renders 255. If the heap's import ended up compared rather than watched, the test prints that and stops.
3. **Second draw.** It must reuse the build (`Builds()` unchanged) and render 255.
4. **Shadowed results.**
   - Under `GpuMutex`, it makes an R64KBX 128×128 RGBA8 storage image over the heap.
   - It clears the image to 0 on the active recorder and marks it dirty.
   - It writes it back with `FlushPending(..., "storage refresh", PublishScope::None)`, then submits and waits.
   - If the write-back did not go into the unit shadow (`AnyShadowedOverlaps`), the test prints that and stops.
   - The import must still hold 1.0.
5. **The reused draw.** The next draw must reuse the build and render 0, with 0 stored through the BDA table.

- **Skip conditions:** it skips with a printed line when unit shadows, write watching or the detiler are unavailable. On llvmpipe it runs fully.

### PM-051's second test (`--bda-reuse-shadowed-only`): dropped

- It drove `ResumeSpace` on its own and required the import to hold the shadow's results. That is red by design, because the publish runs after `proveBuild`, not inside `ResumeSpace`.
- Turned into a test of the intended behaviour, it would have to drive `Revalidate` with a reusable address-based `ShaderResources`. A real reused draw through `Revalidate` is exactly what `ShadowedValue` does, so the reworked test would add nothing.
- The store direction (a pointer store into a live unit, overwritten by the next publish) has the same cause and the same fix. Covering it would need the scene's store target to sit in a shadowed unit; I left it out.
