## G2: re-plan only what can be imported now

**What changed** (lines on the branch, `core/libs/prx/libSceAgcDriver/Graphics/src/GuestBufferMemory.cpp`):

- **The cached address space's hit check** (:2745, the heap-run path).
  - A heap or sparse mirror whose range has left the write watch (`heapMirrorWatched` false) misses the space only if `importsNow` takes its range (:1843).
  - `importsNow` calls the same `importAllocation(context, state, address, lease, 0, false)` the rebuild's planning loop calls. So:
    - it answers what the rebuild would do;
    - the import it makes is the one the rebuild finds.
  - Otherwise the space is kept, and the refresh brings the mirror up to date in full:
    - `refreshHeapRuns` :1821 through `appendHeapRun` :1670;
    - `refreshSparseMirror` :1788.
  - This was the same drop as in the planning path: on the base, any unwatched heap mirror missed the space, and the rebuild then dropped the mirror.
- **The planning loop** (`AcquireRegistered`) tries the host import of every leased range before it mirrors one.
  - So a range that reaches `acquireMirror` is one the import path just refused.
  - `acquireMirror` therefore returns the existing heap mirror as main does (:1867-1871). The base dropped it when its range had left the watch.
  - `refreshHeapMirrors` (:1683) then refreshes it in full.
- **`bindSparseMirror`** (a heap bound whole through a descriptor) acquires the mirror the same way and refreshes it through `refreshHeapMirrors`. So it keeps the mirror too, as #6546 does.
- **Sparse mirrors** (`refreshSparseMirror` :1788):
  - Pieces that are no longer watched are refreshed in full: committed pieces are copied, and holes are zeroed.
  - Before, G1 returned false there and the range was planned again. That meant a per-build copy of its committed bytes, which counts against the cap.
  - A sparse mirror is still rebuilt when the guest commits past its extent, as before.
- **"Every block counted as written":** `markUnwatched` (:1665) zeroes the mirror's block generations.
  - `ChangedBlocks` then reports every block changed, so the refresh copies them all.
  - It is counted in the `[buffers]` line's `unwatched heaps`, the counter #6546 uses too.
- **Unchanged:**
  - Where the import fits, the range is imported again and its mirror released: `releaseImportedMirrors`, #6646's behaviour.
  - Where no mirror exists yet for an unwatched range, or the registered `Range` object changed, no mirror can be made without the watch, and the range is copied as on main and with #6546.
- **`SetAddressCopyLimit(bytes)`** (:2591; declared in `GuestBufferMemory.hpp`:73) sets the copy cap in-process, as `SetHostImportBudget` sets the budget; 0 means `APS5_ADDRESS_COPY_MAX_MIB`. No new environment variable.
- **Debt note** (`docs/dev/debt/libSceAgcDriver.md`, "Host import windows and budget"): "A heap mirror, sparse or not, whose range has left the write watch is refreshed in full at each use, every block counted as written; a build plans its range again only once the import path takes the range."

## G3: the same-build race

- **Both paths refresh in full; neither returns "not reusable":**
  - `refreshHeapMirrors` (:1673 at 48c17f97dd);
  - `refreshHeapRuns` (:1810).
- **Why not "not reusable":**
  - Both run after the build has planned its regions. `refreshHeapMirrors` runs at the end of the planning loop; `refreshHeapRuns` runs for a cached space already served.
  - So "not reusable" there would mean planning the build again from inside its refresh.
  - A full refresh is correct for that build, whatever took the range off the watch.
  - If a map-time import did, the next build's hit check finds that import (`importsNow`) and plans the range again.
- **The per-mirror collect:**
  - `GuestMemory::CollectWrites` over a run returns 0 without walking any of it once part of it is unwatched.
  - So `appendHeapRun` collects each mirror of such a run on its own. The unwatched one is refreshed in full, and the others by the blocks the CPU wrote.
- **No deterministic test for the race itself:**
  - It needs another thread's map-time import to take a range off the watch between the build's check (the hit check, or the planning loop's import attempt) and its refresh, within one build.
  - The driver has no hook between the two, and a sleep-based test would be flaky.
  - The code the race reaches is the refresh of an unwatched mirror the build kept, through `refreshHeapRuns` (cached) and `refreshHeapMirrors` (not cached). The G2 and run-case tests run exactly that path, deterministically, in both cache modes.

## Second to land with #6636

- **Resolution text**, for whichever of #6636 and #6646 lands second, and for PRM-013's build:

  > `spaceMiss` takes `HostImports&` and returns `SpaceMiss::Unwatched` when one of the space's heap or sparse mirrors has left the write watch (`heapMirrorWatched` is false) and the host import path takes that mirror's range now (`importsNow`; the rebuild then finds the import it made). ## How #6646 and #6546 compose now (for #6646's description)

> #6646 and #6546 both stop a heap mirror whose range has left the write watch from failing the build, and #6646 now never does worse. Where #6546 turns the three `Require`s into a full refresh, #6646 refreshes in full too, and collects each mirror of a run on its own, so that a run's watched mirrors keep their per-block refresh instead of trusting stale stamps. On top of that, #6646 plans the range again when the host import path can take it now, so a heap the budget holds is imported again instead of mirrored. A heap the budget refuses, and every sparse heap, keeps its mirror and is refreshed in full as with #6546, so it never falls back to a per-build copy or reaches `APS5_ADDRESS_COPY_MAX_MIB`. Merged together, the three conflicting hunks in `GuestBufferMemory.cpp` resolve to #6646's side, which already contains #6546's change.
