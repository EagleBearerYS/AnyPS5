## The change does more than the task prescribed: counting alone stays red

The task assumed #6243 gives each CPU-keyed **sampler** read its own selected column, so that unselecting the largest group would bring the sampler count down. On `main` that is not so: **sampler columns are never selected.**

- `ResourceTracker.cpp:724` (on 9062485ebe) sets `column.selected` only under `if (!address && !sampler && ...)`.
- `DirectSampler` (`:1617`) makes an S# whose four words the SRT walker can evaluate a direct sampler, so no column is planned for it at all. `PlanTableColumnPass` plans a sampler column only when `!DirectSampler(...)`.
- `docs/dev/ARCHITECTURE.md:172` already says: "Samplers are not selected: an S# the walker can evaluate is a direct sampler."
- `LargestSelectedGroup` does group sampler columns alongside image columns. But no sampler group ever has a selected member, so it never returns one.

N CPU-keyed reads of one sampler heap are therefore N **direct** samplers, one per distinct S# value. Unselecting image groups changes images and pairs, never samplers.

**Verified:** I built the prescribed change alone: `PlannedWithinLimits` counting distinct samplers and returning false past `MaxSamplers`, with the existing unselect loop. The gap test (40 heap S# reads at keys 1..40) still failed with `sampler resource limit exceeded`, the same as on main. The loop finds no selected group to unselect and returns, and then `AddSampler` refuses.

**So the commit does both:**
1. **Counts samplers.** `PlannedWithinLimits` becomes `PlannedResources()`, which returns `{images, pairs, samplers}` (`PlannedCounts::WithinLimits` checks all three). Samplers are keyed exactly as the pair loop already keys them: a planned column's `source`, or a direct handle by `SameHandle` plus the sample-adjust flag. (`ResourceTracker.cpp:1409-1475` on branch 1.)
2. **Shares a sampler heap's reads through one table when past the limit.** When the estimate's samplers exceed `MaxSamplers`, `LargestDirectSamplerHeap()` (`:1478`) runs:
   - It tries `TryMakeTableColumn(handle, sampler=true)` on every direct S# handle not yet tabled, and restores `m_sources` afterwards.
   - It groups those handles by the column source they would get (same heap V#, stride, addend and offset).
   - It returns the largest group, provided it has at least 2 handles.
   - Those handles go into `m_tabledSamplers`. `PlanTableColumnPass` then plans them as a sampler table column even though they are direct (`:1563`), and the pass re-runs.
   - All of that heap's reads now share one sampler source, keyed by the union of their key domains, the same way an unselected image heap shares one table.

   **The loop (`:1383-1410`):**
   - While samplers are over the limit and a heap with at least 2 direct S# reads is left, table that heap.
   - Otherwise, if images or pairs are over, unselect the largest selected image group, as #7527 did.
   - Otherwise return; `AddSampler` then refuses as today.

   Each step adds handles that were not in its list before, so the loop ends.

**Not changed:**
- `MaxSamplers`, the 32-bit sampler masks, and any shader within all three limits. Such a shader plans exactly as before, from one pass, because the estimate is checked before anything is tabled.
- The image and pair behaviour of #7527: unselecting still runs only when images or pairs are over.

**One behaviour to know about:** an S# that moves into a table is resolved through the sampler table's map. There, an unnormalized or reducing S# is poisoned: it reads zeros and reports a fault when a lane selects it (`ARCHITECTURE.md`, the `ResolveImageTables` paragraph). This only affects shaders that were refused outright before.

## Estimate against `Collect`: same keys, the estimate can only count more

`Collect` (`:2077-2090`) takes the sampler source from `FindTableColumn(*samplerHandle)->source` when the handle has a column. Otherwise it uses `GetHandle(..., GetSamplerResource, 4, ..., sampleAdjust)`, which builds `MakeSource` with the sample-adjust canonicalization and interns it. `AddSampler` (`:1938`) dedups by that source.

The estimate keys samplers the same way, case by case:
- **Column samplers**, including samplers read through `FindTableColumn` and every table-column kind on main: keyed, masked, pointer-indirect (`TryMakeIndirectColumn`), and the new tabled heaps. Both use the same `column->source` from the same final pass, because the final pass's `m_sources`/`m_tableColumns` are what `Collect` sees. The counts are equal.
- **Direct samplers:** the estimate keeps two handles apart unless `SameHandle` holds and the sample-adjust flag matches.
  - Two handles that are `SameHandle` have the same IR words, so with the same flag `Collect` canonicalizes them to the same source. Each estimate class therefore maps to exactly one `Collect` source.
  - Handles that `SameHandle` keeps apart can still canonicalize to one source, for example equal words loaded twice, or dword3 with no border clamp. That only makes the estimate count more.
  - So the estimate never counts fewer samplers than `Collect` adds: it cannot plan a shader that then refuses on samplers. It errs toward tabling.
  - This is the same argument #7527 made for pairs. No new key helper was needed: the sampler key is the `sampler` value the pair loop already computed.
- **Sample-adjust:** keyed by the flag in both places.
- **Nested tables (#9457):** this code is not on main. On branch 2, which carries #9457 through #9749, `Collect`'s sampler path is the same code (`FindTableColumn` → column source, else `GetHandle` → `AddSampler`, `:2435-2446` there). A nested S# column is keyed by its column source in both places.
