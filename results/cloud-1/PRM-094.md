### 5.2 `^(agc|shader)` once

**Count:** "99% tests passed, 1 tests failed out of 1271"; 98 of the passes are skips.

**The failure:**
- `agc_driver_image_table_store_gpu_heap` fails 3/3 on the merge: `image table store: texel 0 of a 16_16_16_16_FLOAT table element holds 0x0000000000000000, expected 0xbc00400038003c00`.
- It runs `agc_driver_image_table_cache_bounds_tests --store-table` with `APS5_GPU_HEAP=1 APS5_VERIFY_GPU_HEAP=1`.

**It is #9508's:**
- I built 95e1f33742 alone in a separate worktree (same flags, target `agc_driver_image_table_cache_bounds_tests`) and ran the same registration.
- It **fails 3/3 there with the same message**, so it is not caused by this merge.

**Why it likely fails on lavapipe:**
- 95e1f33742 adds this test together with its fix ("give heap image tables a uint storage column for raw uint stores").
- The fix is in the heap path only: `ShaderResources::writeHeapTableMap` gets the fifth uint storage column, and `SpirvDescriptors.cpp` `tableHeapSlot` / `TableStorageImagePointer` read part 5 only when `state.tableAccess.heap`.
- Lavapipe has no `VK_EXT_descriptor_heap`, so `DescriptorHeapEnabled()` is false and the test takes the per-draw table path, where nothing changed.
- The test does not skip without the heap: its heap check is only `if (DescriptorHeapEnabled())`, after the texel check.
- So on a device without the heap it still sees the zero texels the commit describes for the heap path.
- That is a reading of the code. I did not trace the per-draw binding.

**Suggested resolution:** for #9508 to decide, either have the test skip without a descriptor heap or give the per-draw table path the same uint storage view. Nothing here touches #9508.
