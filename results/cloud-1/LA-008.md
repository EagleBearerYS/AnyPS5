## Open problems

1. **`agc_driver_image_table`'s graphics part fails with the switch on.**
   - It is a direct `VulkanDevice::Draw`, outside the driver, into a non-resident host array. LA-011's re-prepare doesn't cover such a call, and a result from `Recompile(request)` has no request left to recompile from.
   - Only tests and tools draw this way. The production callers of `Recompile(request)` are `DeviceImageProfile`'s word count and the `ShaderReplay` tool.
   - **Options, none built:**
     1. Serve an unrecorded draw through the device table when all its keys were expected. Prepare the bucket, submit the recorder's open batch before the draw's own batch, bind the heap there, and check the miss ring when it completes. It is a new path in `Graphics::Draw` and `DeviceImageTable`. Through the driver, LA-011 already covers the same case.
     2. Give a direct device-table result its CPU variant, compiled alongside it, or give `VulkanDevice::Draw` a re-prepare callback. That is a second compile, or an API change, for test-only callers.
     3. Change the test so it draws through the driver or into a resident target. That changes what it covers, so it is the test owner's call.
   - I'd take 3, or leave the test failing with the switch on. 1 is a feature, not this port.
2. **`bindless_images`** fails a step earlier than on the base.
   - Iteration 1's expectation is incomplete, so the direct `Recompile(request)` takes the CPU table, and the test asserts the CPU-table artifact both times.
   - The direct path decides per request, while the driver's fallback is per program and sticky.
3. **CPU per draw at N=0 is about 6 µs higher** than the base on both runs here, against about 4 µs measured in the expectation phase. With two runs a side I can't attribute the rest.
4. **A draw outside the recorder expects, inserts and holds its keys** in the device table, though it reads the CPU table.
   - That is what lets part (m)'s next recorded draw hit.
   - A program that only ever draws outside the recorder would hold heap slots it never samples, until eviction.
5. **Copy mode (`APS5_NO_HOST_IMPORT=1`)** was not rerun.
   - On b63fa365d, base and head alike, it rebuilt resources for every draw, including a 1.5 MB V# table copy.
   - It grew lavapipe's `memfd:allocation` mappings by about 5,000 per second, and segfaulted at the 65,530-mapping limit after about 12 s.
6. **The memo keys on all of a program's user data.** A draw whose user data changes every draw misses it, at about 14 µs per expectation on this bench.
7. **A guest write to a T# record between the expectation's read and the GPU's read**, in the same collect epoch, is not seen. The miss ring stays as the safety net. No miss happened in any expectation-on run of this task.
