## 1. Sampler columns: no change

The task says a sampler column whose offset the CPU evaluates still snapshots its whole heap. On 43855cb5e8, and on main, that cannot happen:

- `PlanTableColumns` plans a sampler column only when `DirectSampler` returns false (ResourceTracker.cpp:1304).
- `DirectSampler` (:1337-1345) runs `ValidateSource` over the S#'s four words. That is the same check that makes an image record selected (:657-667).
- So an S# that the walker can evaluate (its words, and with them the offset they are read at) becomes a direct sampler binding with no table and no snapshot.
- Every sampler column is therefore one whose S# words the walker cannot evaluate.

A "selected sampler record" can never arise, so the item-1 sampler tests have no subject: invalid S#, unmapped record, past the heap or the cap, carried offset, written key, per-lane key, GPU sample, and the disk-cache round trip. The direct-sampler path's own tests cover an evaluated S#.

PM-038's Village measurement also found no sampler tables in the title.

**Pin, 3b914c84b:** `verifyEvaluableHeapSamplerDirect` in agc_shader_bindless.
- An S# read with `s_buffer_load_dwordx4` from the heap, at an offset taken from the SRT, is planned direct: `samplers[0].table == NoTable` and no column.
- The same S# keyed per lane (`v_readfirstlane`) is a sampler table.
- Both hold before and after the series; there is no code to make it red.

## 2. Stores, atomics, PCK and BY2/BY4 through a T# whose record the CPU evaluates

**Where it faults:**
- `AssignTables` marks a table image Unsupported when it is used for any of these:
  - a storage operation (`image_store`, image atomics);
  - a packed operation (PCK);
  - BY2/BY4.
- `EmitTableAccess` then emits a table fault: the store is dropped and the read is zero.
- The materializer also rejects packed and BY2/BY4 views of any table image, because they "require a direct image".

#6243 kept that for selected records, although a selected record is one known T#, just as #5188's direct images were.

**Is #5188's direct path contained? Yes.** The direct path is the one every non-table T# takes: `GetHandle` evaluates the eight words and binds a direct image. It supports all of these operations. Item 2 only has to stop the T# from becoming a table column, and #758 already does exactly that for pointer tables (direct-first when the pointer T# validates).

**Design (fe56f6056, ResourceTracker.cpp):**

1. `DirectImageHandles()` is a pre-pass over the image instructions.
   - It looks for operations a table cannot express: Storage class (stores and atomics), `imagePacked`, or `imageByElements != 0` (BY2/BY4, PCK2/PCK4). These are the same conditions `AssignTables` marks Unsupported.
   - For each one whose T# validates as a direct image, it collects the handle. `DirectImage` uses the 8-word `ValidateSource`, as `GetHandle` does.
2. `PlanTableColumns` skips every handle equivalent to a collected one. `SameHandle` checks the same opcode and equivalent arguments, so the loads, samples and stores of one T# agree.
   - Every operation of the shader on that T# is then bound directly. Nothing is half table and half direct.
3. Unchanged:
   - a T# keyed per lane, or by a value the walker cannot evaluate, keeps its table and the `unsupported operation` fault (debt shader.md:37 says so now);
   - a T# that is only read or sampled keeps #6243's selected record.
4. **Cost:** at plan time only (plans are cached), one more walk over the image instructions, plus a `ValidateSource` per table-unsupported instruction.
5. **Trade-off, now in the debt entry:** a direct T# is read when the work is recorded. So for a T# whose key the dispatch itself writes before the store, the T# is read from the key's value before that write, as for any #5188 direct image. The table path would have faulted the store instead.

**Tests (e87f3ae92):**

- `verifySelectedRecordDirectOperations` (agc_shader_bindless) builds four variants of the SRT-keyed program: `image_store`, `image_atomic_add`, `image_load_pck`, and `image_load_by2` (a 16_UNORM record, dmask 0x3).
  - Each must be planned direct (`table == NoTable`, no column).
  - Each must compile with no image-table binding and no table faults, with its record captured.
  - The same four operations keyed per lane must stay a table marked Unsupported.
  - A T# both sampled and stored must be direct for both images.
  - A T# only sampled must still select its record.
- **Red at 43855cb5e8 plus the test.** One instrumented build reported each variant:
  - `selected record direct operations: image_store through a T# whose record the CPU evaluates was planned through an image table`, and the same line for `image_atomic_add`, `image_load_pck` and `image_load_by2`;
  - `selected record direct operations: a T# sampled and stored was planned through an image table for one of its operations`.
- `RunSelectedStoreTests` (agc_driver_image_table, on the GPU through lavapipe) uses a registered 64x4 R32_UINT image in record 9, selected with key `Keys[3]` through `Srt[24] = 12`.
  - 64 lanes `image_store` 0xc0de5eed to row 0; the test then flushes and reads the texels back.
  - Red: `image table selected store: an image_store through a T# whose record the CPU evaluates faulted or was bound through an image table:` followed by `[gpu] deferred write-back failed: image table: ... selected the descriptor at ...: unsupported operation`.
  - Green: no fault, no table binding, and all 64 texels of row 0 hold 0xc0de5eed while the other 192 keep their values.

## 3. PM-035 findings folded in

**Gap 2, `NonUniform` on a selected record (033406265, test 55a09385a).**
- A selected record is one map entry for the whole dispatch, so its descriptor index is dynamically uniform.
- The emitter decorated it `NonUniform` whenever the workgroup spans more than one subgroup, and on every graphics stage. Drivers scalarize such accesses.
- Now the following are undecorated for a selected record:
  - the element index (SpirvImageEmitter.cpp);
  - its access chain and the loaded image (`LoadSampledImageDescriptor`);
  - the sampled image (`MakeSampledImage`).
- Table samplers and tables keyed per lane keep the decoration.
- **Test:** `verifySelectedRecordUniformIndex` compiles the SRT-keyed and the per-lane programs with a 128-thread workgroup and counts `OpDecorate ... NonUniform`. The selected program must have none; the per-lane one must keep it.
- **Red without the change:** `selected record uniform index: the image table index of a selected record in a two-wave workgroup is decorated NonUniform`.

**Gap 7, key domains kept on deselection (6aacf0bab, test 23d6cf684).**
- `CheckTableStores` deselects a selected column whose key the dispatch may write (`SelectionWritten`).
- The column kept the key domains narrowed from that same key buffer, because the domain rule clears them only when the domain's own V# is written. So a shader storing through a pointer still narrowed its whole table on a key it may overwrite. Deselection now clears the domains too.
- **Test:** the key loaded from a constant buffer at an SRT offset has a domain (asserted). With a `global_store_dword` added, `bdaWrites` is set, and the column must be deselected with no domain.
- **Red without the change:** `selected record fallbacks: a key loaded from a constant buffer in a shader that stores through a pointer selected its record or kept its key domain`.
