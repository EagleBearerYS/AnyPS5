### F1: the serial taken at the reap and `CompletedThrough()` at the rewatch

**Is anything outside the active recorder's batches a GPU use that can precede the settle read? On Windows, no:**
- **Main-queue submits outside `Recorder::Submit`:**
  - `CommandBatch::Submit` (`Resources.cpp:375`). Every user calls `SubmitAndWait` under `GpuMutex` (the constructor asserts it, `Resources.cpp:324`). So that work has completed before any rewatch, which also needs `GpuMutex` (`:1039`).
  - The present blit (`VulkanDevice.cpp:3180`) reads images, not imports.
  - The import probe (`:2729`) reads its own scratch.
- **The sparse queue** binds Linux dma-buf chunks only, synchronously (`:684`).
- **The settle queue** carries only reads: of this import (its own batch) or of other imports.
- **`Recorder::Submit`** runs under `GpuMutex` (`Recorder.cpp:161`), as do the reap and the rewatch, so `submissions` can't move between the serial read (`:979`) and the fence check (`:983`).
- **`activeRecorder` is a process global** (`Recorder.cpp:38`), not per thread. A device change drains the settles (`:1550-1553`), so the `recorder == mainRecorder` test only matters across devices.
- **`CompletedThrough()`** counts reaped batches (`Recorder.hpp:88`). It lags GPU completion, which delays a rewatch but never brings it forward.
