## Findings, ranked

### Blocking (fixed on the review branch)

**B1. Restoring a recaptured stage on a draw-cache hit drops its guest-memory snapshots.** The process crashes on lavapipe.

**Code** (fdb45156c):
- `Draw.cpp:485-487`, `:573-582`: path (b) restores `compiledWith`.
- `DrawCapture.cpp:61-64`: the recapture rebuilds `memory`.
- `Draw.cpp:371`: on a hit, `memory` starts with `matchedRegions`.

**What happens:**
1. A stage's patched word is a walk input. On a hit, record *r* has values other than the compiled ones, so it takes path (c) and recaptures the stage.
2. `materializeDrawStage` rebuilds `memory` from what this draw's `ShaderMemory` read. It adds back `matchedRegions[j]` only for stages that were not recaptured (`!recompiled[j]`).
3. The cached stage's own regions came from the entry, not from this `ShaderMemory`, so they are gone from `memory`.
4. A later record at the compiled values takes path (b) and restores the compiled stage. It draws with snapshots that lack the memory that stage was captured against.

**Why it matters:** the snapshots feed only the BDA address space of an address-based build (`ShaderAddressResources.cpp:34`). A stage that reads, through BDA, memory its walk captured outside registered guest memory then reads an unmapped address.
- On a GPU this is `BdaResources::CheckFault`'s "BDA access failed" (`BdaResources.cpp:282`).
- On lavapipe, which runs shaders on the host, the process got SIGSEGV.

**Who can hit it:** only on a hit, only with the switch on, and only for a stage that both walks the patched word and reads its walked memory through BDA. Main never restores a stage, and a miss is safe: its `ShaderMemory` captured the original regions itself.

**Evidence:** `agc_driver_indirect_draw_cache_guards`, new case `RecapturedStageKeepsItsMemory`.
- The vertex shader loads its depth twice through the patched base-vertex word, once with `s_load_dword s12, s[8:9]` and once with `global_load_dword v3, v6, s[8:9]`, and draws z = s12 + v3.
- The depth comes from two 4 KiB pages of unregistered static memory.
- Three draws at the visible page come first; the third hits the cache. Then comes a packet of two records, {clipped page, visible page}.
- **Red** (fdb45156c with the test), 2 runs of 2: `***Exception: SegFault`. A probe showed the three draws passed and the crash came in the two-record packet. The same packet with {clipped, clipped}, path (c) twice, passes.
- **Green** (d2cfe611e), 3/3 runs: the packet draws its second record.
- With `APS5_CACHE_CPU_INDIRECT=0` the case passes on both builds.

**Fix** (d2cfe611e, 3 lines net in `Draw.cpp`):
- Once a record recaptures a stage, the packet's later records recapture it too, as main does.
- The restore, and its full `RecompileResult` copy (`compiledWith`), are gone.
- Reuse is lost only in a packet whose walked values leave the compiled ones and then come back.

### Notes

**N1. Key soundness: no patched word escapes in what I traced and tested.**

The record loop sends a patched word down path (a), pushed only, if it is not set in `walkedWords`. A user word can affect a materialized stage in four ways; the first three are covered:
1. **The SRT walk.**
   - A base-pointer use sets `asBase` (`SrtEvaluator.cpp:205`).
   - Any value use, including a pointer's high word and V# or T# words held in user SGPRs, sets `asValue` (`SrtEvaluator.cpp:422`). Words past 64 set all bits.
   - Uniform-fill and runtime-source evaluation run through the same evaluator with `userDataUse` attached (`Recompiler.cpp:1347`).
2. **The vertex-fetch table pointers** (`DecodeVertexStageInfo`).
   - `Draw.cpp:493-498` adds both pointer pairs at `reg + 8 − firstUserSgpr`, the index `ShaderInputState.cpp` reads (`bufferWord` / `attribWord`).
   - Decode only ever produces embedded fetch.
3. **The ShaderData slots** (push constants or the ShaderData binding).
   - Slot i holds `userData[userDataRegisters[i] − base]` (`DescriptorBindingBuilder.cpp:241-245`), and `shaderDataUserWords` is that list (`:530`).
   - `patchPushedUserWord` writes exactly those slots. The other uses of the snapshot's user data are the result memo's hash and ShaderData itself (`ResourceMaterializer.cpp:799`).
   - The source, variant and disk-cache keys take only the user-data count (`CacheKey.hpp:50`, `:83`).
4. **The draw parameters in `GraphicsCompileContext`.** These matter only for tessellation (`Recompiler.hpp:361-364`), and tessellation, mesh and rect-list draws are excluded (`Draw.cpp:420`).

`fold()` and `ClassifyIndirectDraw` read the patched `userData` per record, as main does.

**Cases run** (all pass on the review head with the switch on and off):
- BF-052's pushed-only and walked-pointer cases.
- A V#-base word: new in 7db1dfca3. The record's base vertex is the base of a V# in four user SGPRs, read with `buffer_load_dword`.
  - **Mutation check:** with `walkedWords` forced to 0 the case fails: "the stage compiled for the V# at 0x32a51000 was reused". BF-052's walked-pointer case fails the same way.
- The walked-pointer-plus-BDA case of B1.

**Not reachable here as a separate case:** a patched word that is only a pointer's high word. That word goes through the same `asValue` path as the V# words. I could not make a second valid high word on this VM for a draw.

**Relocation is consistent.**
- `programs` carry the current register values after `userPatches` (`Draw.cpp:180`), so `compiledValues` are the values the relocated stage stands for.
- `relocateDrawEntry` copies `walkedWords` (`DrawRelocate.cpp:217`).
- The only places that create draw variants are `cacheDrawStages`, which sets the mask, and relocation, which copies it. Any other variant keeps the conservative default of ~0.

**N2. Staleness: a hit's validation covers what a hit reuses.**
- **What it re-reads:** `validateVariant` (`DrawLookup.cpp:120`) re-reads every word of the variant's runs, which hold the stage's captured regions plus its vertex-decode reads (`DrawCapture.cpp:162-165`).
  - A CPU write to a walked word either makes the stage a stage-data hit, with the live words patched in (`EqualData`, `DrawLookup.cpp:124-131`), or misses.
  - The record buffer is read again for every packet, and a pushed-only word reaches nothing the walk read.
- **Test:** new in 7db1dfca3. After the address-reading stage hits, the CPU rewrites its depth word, and the next draw draws the new value. Writing the value back draws again.
- **What it misses:** nothing CPU-path specific; it has the same limits as for direct draws.
- **Verify-mode false alarm:** `APS5_VERIFY_DRAW_ENTRIES=1` prints "stage 0 … of a hit captured differently" for those stage-data hits. Verify compares the unpatched variant, so this is a false alarm that exists on main; the drawn pixels were right.
- **Cost:** the validation costs the ~8 µs BF-052 measured.
- **Unneeded validation:** an entry whose patched register held a stale pointer when inserted also validates that memory on every hit. Its runs come from the pre-loop capture at the register values. That costs reuse, not correctness.

**N3. Growth is bounded. The memory figure undercounts.**
- **Bounds:**
  - at most 4,096 entries, with LRU eviction (`DrawCache.cpp:71`, `:177`; `APS5_DRAW_CACHE_ENTRIES`);
  - at most 4 variants per stage (`DispatchCache.cpp:26`, `DrawCache.cpp:160`; `APS5_DISPATCH_VARIANTS`);
  - a fixed table of 16,384 key sightings (`DrawCache.cpp:112`).
- **Admission:** a key is admitted on its second sighting, so a key that never repeats is never inserted. Village's 559 "no entry" lookups would add nothing.
- **The undercount:** `variantBytes` (`DispatchCache.cpp:63`) counts a variant's words and runs, not the `RecompileResult` it pins: its bindings, guest-descriptor words and push data. The SPIR-V is shared, not copied.
  - So the "~MiB" in the `APS5_PROFILE_DRAW` line is not the cache's footprint. The "~4 GB" BF-052 cites is probably not this figure.
  - BF-052 itself left that link unchecked.
- **No new cap needed.** If Village's private memory grows with the switch on, count `compiled` bytes in the cache accounting or cap it by bytes; that is main's design, not this change's.

**N4. Threads and interactions.**
- **On this base:**
  - an indirect draw drains queue 0's pipeline on entry (`Draw.cpp:38`) and records its records on the worker;
  - insert and lookup take `drawCacheMutex`;
  - `walkedWords` is written before the entry is published.
- **Counter cost:** with the switch on, the three counters take `drawCacheMutex` once per CPU-path packet, even unprofiled (`Draw.cpp:603-607`). That is cheap, but it could be skipped when not profiling.
- **#6931** (a00773731) queues a packet's last drawable record on the committer and returns from inside the record loop. Merged with this change:
  - that return skips BF-052's counter update, which affects statistics only, so the update must move before the return;
  - the committer gets `results` moved in, so the last record's patched push data goes with it;
  - with B1's fix there is no restore copy.
- **Switch matrix:** run with the switch on (the tests set it), plus each of these switches:
  - verification and tracing: `APS5_VERIFY_DRAW_ENTRIES`, `APS5_VERIFY_DRAW_RECIPE`, `APS5_VERIFY_REGISTER_KEYS`, `APS5_TRACE_INDIRECT_DRAWS`, `APS5_TRACE_DRAW_CACHE`, `APS5_PROFILE_DRAW`;
  - cache and key off-switches: `APS5_NO_DRAW_RELOCATION`, `APS5_NO_DRAW_KEY`, `APS5_NO_DRAW_SRT_ENTRIES`, `APS5_NO_DRAW_STAGE_DATA_HITS`, `APS5_NO_DRAW_DATA_HITS`;
  - other settings: `APS5_DRAW_KEY_ALL_USER_WORDS`, `APS5_DRAW_CACHE_ENTRIES=1`, `APS5_PIPELINED_DRAWS=0`, `APS5_NO_WORDWISE_CAPTURE`, `APS5_LOCKED_DRAW_PREPARE`.
- **Results:**
  - `agc_driver_indirect_draw_cache_guards`, which checks pixels, passes under all 16.
  - `agc_driver_indirect_draw_cache_hit` asserts exact insert and hit counts, so it fails under two: `APS5_VERIFY_DRAW_ENTRIES=1` ("inserted 2 draw entries and made 1 draw-cache hits") and `APS5_NO_DRAW_SRT_ENTRIES=1` (no entries). That is the test's expectation, not a wrong draw. CI runs neither.

**N5. With the switch off, the draw path is main** (see S1 for the harness commits).
- With the switch off, the only differences in `Draw.cpp` are three per-packet vectors and a three-entry write array per record. `cacheDrawStages` gets the same arguments.
- `DrawCapture.cpp:159` stores `walkedWords` and `DrawRelocate.cpp:217` copies it. Neither changes a decision.
- The test results agree: the CI mirror with the switch unset has the same per-test outcomes on fdb45156c and on the review head (below).
