**(a) The tree's handle convention.**
- The error constants are already in `core/libs/prx/libSceHmd/Hmd.hpp:12-13`.
- Without a headset, `sceHmdOpen` (Export.cpp:139) never issues a handle. It returns `DeviceDisconnected`.
- The library's implemented handle queries already answer `initialized ? InvalidHandle : NotInitialized` and ignore their pointers:
  - `sceHmdClose` (Export.cpp:147);
  - `sceHmdGetDeviceInformationByHandle` (:161);
  - `sceHmdGet2DEyeOffset` (:370);
  - `sceHmdGetInertialSensorData` (:873).
- The six command queries follow those four. They do not check their descriptor or output for null.
  - Only `sceHmdGetFieldOfView` (:484) checks its output for null first. Its debt entry says it follows shadPS4, not a PS5 measurement.
  - shadPS4 itself only stubs the command queries: `hmd_distortion.cpp` at a808e76 returns `ORBIS_OK`. So it gives no order to copy.
- **Not measured:** whether the console checks a null descriptor or output before the handle. The debt entry now says so.

**(b) The aliases.** The debt (docs/dev/debt/libSceHmd.md, export-table paragraph) records the three `sceHmdDistortion*` command queries as ELF aliases of the `sceHmdGet*` ones. Each alias answers as its twin.

**(c) The VR2D convention.**
- libSceHmd has no implemented `Is*` function of its own.
- The neighbouring `Is*` functions that set the convention are the same four queries in libSceHmd2:
  - `sceHmd2InternalIsGameVr2d` (`WzaEApHnsP8`), `sceHmd2InternalIsMiniAppVr2d` (`dXzQI8QVY7Y`), `sceHmd2InternalIsCommonDlgVr2d` (`cCvFKGqRh1k`) and `sceHmd2InternalIsCommonDlgMiniAppVr2d` (`uj4-2VEAFPU`);
  - all of them answer 0, measured on firmware 13.60 (`Hmd2BeforeInitializeZero`, docs/dev/debt/libSceHmd2.md:36);
  - `sceHmd2Initialize` always fails in the tree (`UnsupportedFeature`, libSceHmd2/Export.cpp:259-261), so they answer 0 every time.
- Nothing runs in VR2D without a headset.
- **Not measured:** libSceHmd's own answers. The debt entry says so.
- If the PM reads "neighbouring" as libSceHmd only, commit 2 is self-contained and can be dropped. Those four would then stay throws.

### What
Ten libSceHmd exports now give their no-headset answers instead of throwing.

- The distortion correction, wide-near correction and 2D VR command queries (`sceHmdGetDistortionCorrectionCommand`, `sceHmdGetWideNearDistortionCorrectionCommand`, `sceHmdGet2dVrCommand` and their `sceHmdDistortion*` export aliases) take a handle that `sceHmdOpen` never issues without a headset.
  - They answer as the library's other handle queries (`sceHmdClose`, `sceHmdGetDeviceInformationByHandle`, `sceHmdGet2DEyeOffset`, `sceHmdGetInertialSensorData`): `NOT_INITIALIZED` before `sceHmdInitialize` and `HANDLE_INVALID` after it.
  - They don't read the descriptor or write the command buffer.
- `sceHmdInternalIsGameVr2d`, `IsMiniAppVr2d`, `IsCommonDlgVr2d` and `IsCommonDlgMiniAppVr2d` return false.
  - Nothing runs in VR2D without a headset.
  - The console answers 0 to the same four queries in libSceHmd2 (`Hmd2BeforeInitializeZero`, measured on firmware 13.60).

The libSceHmd debt file records the open points:
- whether the console checks a null descriptor or output before the handle;
- libSceHmd's own VR2D answers, which are not measured.
