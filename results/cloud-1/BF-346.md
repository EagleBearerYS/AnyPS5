## Per row: what is on main, and why it can't be done here

### `_wait4` (libkernel_sys)

- **On main:** `_wait4_nid_postfix()` takes no parameters and is `NotImplemented` (`AdditionalExports.cpp:202`).
- **The premise "main has no child processes" is false:**
  - **#9133** (fogydes, merged 10-25) added `posix_spawn`/`posix_spawnp` that start real child processes (`libSceLibcInternal/Spawn.cpp`). `waitpid` and `wait` in libkernel reap them: the host `waitpid` on Linux with the signals translated to FreeBSD's numbering, and a child-handle registry on Windows (`libkernel/System/src/Process.cpp:731`).
  - In #9133's own words, "calls without a `posix_spawn` child keep `ECHILD`". So returning `ECHILD` for any pid would be wrong as soon as the guest has spawned a child.
- **So `_wait4` has to share `waitpid`'s model.** That's what #9162 builds:
  - libkernel's `WaitProcess_nid_no_patch` takes `rusage`;
  - libkernel_sys's `wait4_nid_postfix(pid, status, options, usage)` calls it.
- **FreeBSD 11.4:** `_wait4` and `wait4` are the same system call (`syscalls.master` L74, `sys_wait4` → `kern_wait`). libc's `wait4` is a weak alias of the `_wait4` stub.
- **Doing `_wait4` now** would either duplicate `WaitProcess` or conflict with #9162 in `Process.cpp`.
- **Proposed instead:** once #9162 merges, a one-line change makes `_wait4_nid_postfix(int pid, int* status, int options, void* usage)` forward to `wait4_nid_postfix`, plus the same test. Alternatively, ask #9162's author to add `_wait4` to that PR.
- The task's test, `_wait4(-1, &s, WNOHANG, nullptr)` → `-1`/`ECHILD`, would hold either way in a test process with no children.

### `cpuset_getid` (libkernel_sys)

- **On main:** `cpuset_getid` already implements `CPU_WHICH_PID` for the calling process, `id == -1` or its own pid (`libkernel_sys/Cpuset.cpp:84-110`, from #10741):
  - `CPU_LEVEL_ROOT` → 0;
  - `CPU_LEVEL_CPUSET` → the process's set;
  - `CPU_LEVEL_WHICH` → `EINVAL`;
  - unknown pid → `ESRCH`.

  The task's test `cpuset_getid(CPU_LEVEL_CPUSET, CPU_WHICH_PID, -1, &id) == 0` therefore **already passes on main** and can't be red.
- **What's left:** the `CPU_WHICH_TID`, `CPU_WHICH_CPUSET` and `CPU_WHICH_JAIL` scopes throw (`"cpuset_getid other than process"`).
- **#13127** claims `CPU_WHICH_CPUSET`.
- **TID and JAIL can't be modelled here.** The merged review of #10741 rules them out: MarcZX10 asked to "limit claims/behavior to the process-level operations modeled here or add per-thread assignment and verify CPUSET visibility and `CPU_LEVEL_ROOT` semantics". The scopes were then made to throw "because AnyPS5 does not track per-thread cpusets nor cpuset hierarchy visibility". Answering TID from the process's set would go against that.

### `pthread_getaffinity_np` (libkernel)

- **On main:** sets of 8 and 16 bytes are answered, 32 bytes or more return `ERANGE`, and every other size throws (`Thread.cpp:267-279`).
- **This is console behaviour,** not FreeBSD's: [PS5_PayloadSDK's measurement](https://github.com/mihawk-99/PS5_PayloadSDK/blob/3e31e0b1b68ada28beca68adc480cf0c3d17b9df/platform/docs/PROBE.md#L287-L297) on firmware 12.09, merged in **#11431** (p3n1cillin, 10-30). FreeBSD 11.4's `thr_affinity.c` answers the 32-byte `cpuset_t` through `cpuset_getaffinity`, which the console refuses.
- **#11431's review settled the remaining sizes:**
  - MarcZX10: "only 8- and 16-byte success, and 32-byte-or-larger ERANGE, are cited as measured … throw for that unmeasured range";
  - oneandonlydean: the `NotImplemented_nid_no_patch` throw "can stay, and the debt entry already records which sizes are measured";
  - adriadam10 merged it with "unmeasured sizes throw".
- **So following `thr_affinity.c` would contradict the console.** The rule is to throw until the sizes are measured.
- **The task's test** (`pthread_getaffinity_np(pthread_self(), …) == 0` with a CPU set, matching `pthread_setaffinity_np`) already passes on main for 8 and 16 bytes (`GuestAvailableCpumask.cpp`), so it can't be red either.
- **#13908** (open, 10-31) is rewriting this function's copy-out now.
- **What would close the row:** a console measurement of the other sizes, not FreeBSD's source.
