- **How it merged:** on main the function is `splitComputePipeline(..., base)`, and #13931 added the last three arguments to its call. #12840 renames it to `specializedComputePipeline(..., base, bool storePages)` and adds `StorePages = 1` to the replaced constants when asked. The merge has both: the new name and parameter from #12840, and the store arguments from main.
- **Why the StorePages variant gets its own binary:** `PipelineBinaryStore::Key` (`Graphics/src/PipelineBinaryStore.cpp:131–174`) hashes all of these, so a StorePages = 1 specialization gets a different key from the base pipeline:
  - the driver's `vkGetPipelineKeyKHR` key;
  - the full SPIR-V;
  - the layout key;
  - the create flags;
  - the stage name;
  - the subgroup size;
  - every specialization map entry (`constantID`, `offset`, `size`) and the specialization data bytes.
- **What enables the store:** `wantPipelineBinaries` (`VulkanDevice.cpp:1757`) needs all of these, so the store is on by default only on such devices:
  - `VK_KHR_pipeline_binary`;
  - `APS5_NO_PIPELINE_BINARIES` unset;
  - a non-empty `ShaderCacheDirectory()`;
  - no active validation or gfxreconstruct layer older than 1.3.294.
- **lavapipe does not expose `VK_KHR_pipeline_binary`:** it isn't in `vulkaninfo` for Mesa 25.2.8. So the store-on run of #12840's `agc_driver_bda_store_heap_mirror*` couldn't be done here, and they ran with the store off.
