## #5815 `fix(agc): bind a read-only V# over the cached address space through the region that holds it`

**Root cause.** #5428 (972ce1224) let a build's own regions overlap the cached space's base regions (`readsOverBase`). The consumers that assumed the two lists were disjoint went stale.
- The PR fixes `owner()`, the CPU lookup that all eight consumers share, with a holder rule. That is the right place on the CPU.
- The second consumer of the same lists is the BDA table (`AddressRanges` / `CachedAddressTable`, main GuestBufferMemory.cpp:3909-3987). It still emitted overlapping entries.
- The shader searches that table for the last range whose begin is at or below the address (core/shader/recompiler/SpirvBackend/src/SpirvBdaLookup.cpp:88-121). So a BDA store into a writable import could resolve to the read-only copy of a V# across it.

## #6146 `fix(agc): execute the DB's out-of-place depth expand` (+ v3 bac2e3285f)

**Root cause.** Two independent first wrong values:
- **The DB write.** `DepthMaintenanceRejection` takes the compress-disable bits as a no-op without looking at the write base (State.cpp:766). `decodeDepth`'s Z_WRITE_BASE check runs only when tests are on (State.cpp:284, gated at :810).
  - The PR decodes the expand in the precheck (DrawPrecheck.cpp:40-52). That is the right layer, but it recognises one shape (State.cpp:1391-1456).
- **Guest visibility.** `UploadFinish` binds the registered heaps of an address-based build in place and does not store the results pending in them (GuestBufferMemory.cpp:3570-3576).
  - The PR adds an exception list for the expand alone (`unstoredExpands`, `StoreDepthExpandWrites`, v3's `HostImportOverlaps`).
  - **Every other producer kept the hole:** a compute `image_store`, CB resolves (MultisampleTarget.cpp:502), CB metadata passes (Draw.cpp:2687, 2705), resident color targets (Draw.cpp:1534-1538) and #5499's `CopySample`.

**Fixed: gap 1 (high), the exemption reached V#s.**
- A read-only V# inside a registered heap was dropped in one of two ways, so no store ran for it:
  - on the per-build path, it was merged into the heap's hostBacked region (GuestBufferMemory.cpp:3153-3171 at bac2e3285f);
  - inside the cached address space, `addDescriptorRegion` returned before any region was made (:2762-2767 at bac2e3285f).
- The GPU then read the import's older bytes. Written V#s were already stored, through `writes` (:3314).

## #6243 `perf(shader): select the record of a T# whose offset the CPU evaluates`

**Verdict.** It is sound and well tested for its case: a buffer-heap T# keyed by user data, the SRT or a constant buffer, in compute. But it is a fast path inside the table path. It fixes the record offset at plan time (B ResourceTracker.cpp:150), which removes any fallback at capture time. It keeps every table limitation except the snapshot size.
