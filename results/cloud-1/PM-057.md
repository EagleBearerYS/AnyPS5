## The fix (`a7928027f`, 2 files, +60/−1)

- `HostImportBudgetWith` (`:2739`): the budget the report sets after a failure is `std::max(std::min(configured, reported), 1)`. The ceiling path already keeps to at least 1, and a set budget is untouched.
  - **Effect on admission:** none. A 1-byte budget refuses what 0 did, and eviction still needs the same room.
  - **Effect on refusals:** they are remembered again, with budget 1, and answered from memory until the live bytes drop or the budget grows.
- **Tests** (`tests/BdaResources.cpp`, run by `agc_driver_graphics`):
  - **`importDeviceBudgetTests`:** `HostImportBudgetWith(5888 MiB, default, report 0, after a failure, no ceiling)` must not be 0.
  - **`importReportRefusalMemoryTests`** (new). It uses #6479's own mocks: `reportHostHeap` with a heap budget equal to its usage (no room), and `limitImports(0)` for one failure.
    - It registers 24 pieces of 64 KiB.
    - It runs two address-based builds (`AcquireRegistered`), toggling a 25th registration to force the rebuild.
    - The first build must refuse the ranges.
    - The second must answer them all from the refusal memory: tries unchanged, more remembered.

## 3. The "better version" check

- **A shared host-heap governor** would fix the root cause more generally: budget imports, heap mirrors and host-visible stand-ins together from one `VK_EXT_memory_budget` reading, with one failure back-off. Refusing an import moves its bytes into a mirror or a copy on the same heap, and only a joint budget sees that. #6479 governs imports alone, which is why G1's loop and G4 exist.
- **Querying the driver's pinning limit** isn't possible through Vulkan. A failure back-off is the only signal, so #6479's ceiling idea stands.
- **What #6479 needs to stay the better version:**
  - G1 (fixed here);
  - a time-bounded ceiling, or BF-018 part 2, so that G3 doesn't freeze the import set for the session;
  - the mirror budget tied to the same report (G4), or a governor as above;
  - a PC log of the failure codes, to settle G2.
