## #6443's break: `guest_memory_lifetime` (fix pushed)

**Failure (PR tree, every run):** "memory lifetime: child failed during native exit (status=11)".
- The test's child registers an `atexit` probe and `dlopen`s `libguest_memory_lifetime_module.so`, which pulls in `libkernel.prx` (the test executable does not link it). After static destruction, the probe calls `GuestMemoryLifetimeExercise`, which calls `DoMprotect`.
- gdb: SIGSEGV with `si_addr` 0 at `movaps %xmm0,0x38(%rbx)` in `HostStackLimits` (libkernel/Pthread/src/Thread.cpp), called by `GuestThreadStack` <- `DoMprotect` (DirectMemory.cpp:1136) <- `GuestMemoryLifetimeExercise` <- `__run_exit_handlers`.

**Cause:**
- #6443's 8d2053a21 ("keep a host thread's stack range once queried on Linux") caches the range in `static thread_local std::pair<std::uintptr_t, std::uintptr_t> stack`.
- GCC gives the 16-byte object 16-byte alignment (`.tbss` alignment 16 in Thread.cpp.o) and stores it with an aligned `movaps`.
- CI's wild 0.10.0 link puts `libkernel.prx`'s PT_TLS at p_vaddr 0xfa198, which is 8 mod 16, with p_align 0x10, so `stack` lands at TLS offset 0x38.
- When `libkernel.prx` comes in through `dlopen`, its TLS block is allocated dynamically, 16-aligned, and block + 0x38 is 8 bytes off. The first store faults.
- When `libkernel.prx` is a direct dependency, its TLS is static and the variable is aligned; that is why every other libkernel test, `guest_kernel_stack_protect` included, passes.

**Check with GNU ld:** the same unfixed objects relinked without `-B wild` put PT_TLS at 0xfb840 (16-aligned) and `stack` at TLS offset 0x80, and the test passes ("allocation, backing, mapping and explicit free survived native exit"). CI's Linux job links with wild, so it would fail this test on #6443.

**Fix:** fork branch **`followup/6443-main-e1ac3300d3`** at **1af0fa3e4c**: one commit, `fix(libkernel): keep the cached host stack range in two scalar thread-locals`, on #6443's head merged with e1ac3300d3 (b5abb6ee9a).
- `HostStackLimits` keeps `stackLow` and `stackHigh` as two `static thread_local std::uintptr_t` instead of the pair, with the same logic. The store is now two 8-byte `mov`s, with no SSE.
- `guest_memory_lifetime` (already in main) is the red/green test: red on b5abb6ee9a (5/5 alone; failed in the x10 suite), green on 1af0fa3e4c (x10: 10/10).
- On 1af0fa3e4c: `guest_kernel_stack_protect` x10: 10/10. The libkernel suite x10 `--parallel 4`: 146/148 (only the baseline `guest_named_shm_concurrency` and `guest_tcp`).
- Full CI mirror: registration "929 test executable(s), 0 built and not run as recorded, none new"; **1256 passed, 66 skipped, 6 failed / 1328** (186 s); the 6 are the baseline IPv6 and root tests; check_skips the same two baseline skips.
- `python3 tools/check_conventions.py --base HEAD~1 --head HEAD`: "All conventions checks passed". No comment lines added. Committed as Yunus Shaikh, unsigned, no trailers.
- Side note for whoever reports to wild: a PT_TLS whose p_vaddr is not a multiple of its p_align breaks any 16-aligned TLS access in a dlopen'd library linked with it.
