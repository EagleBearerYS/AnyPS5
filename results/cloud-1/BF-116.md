## The test

### `EvictedEntriesServeNoRelocation(bool libraries)` in `DrawCacheRelocation.cpp`

- **How it runs:**
  - `main` now takes `argc`/`argv`.
  - With `--evicted` it opens the device, makes the same pipeline-library or `APS5_NO_GPL` skip decision as before, runs only this case, shuts down, and prints `An evicted draw served no relocation with graphics pipeline libraries`.
  - Without arguments, the existing three cases and `SplitRunsNameTheirSharedWords` run as before.
- **Its steps:**
  1. **Teach the alias** exactly as `MovedDataHitsTheCache` does: `VertexCode` with `PixelCode`, `{1, 0, 0, 0}` at four moved addresses, four draws. It requires 4 lookups, 0 hits and 2 inserts.
  2. **Check the setup.** One more moved draw (`same[4]`, same contents) must hit through relocation: `hits == 1`.
  3. **Evict the taught entries.**
     - Three draws of another identity: `SecondVertexCode`, contents `0.25`, `0.28125` and `0.3125`, each drawn twice at its own address, so each key is admitted on its second sighting.
     - It requires at least 2 evictions and 2 inserts since step 2. In a 2-entry LRU cache, two inserts of other keys leave neither taught entry.
     - The failure message names `APS5_DRAW_CACHE_ENTRIES=2`, for anyone running `--evicted` by hand.
  4. **The check.** One more moved draw (`VertexCode`, a new address `same[5]`, the same contents) must be one more lookup with **no new hit**.

### Changes to the flow you proposed

None of substance; the flow worked as written on the first build.

- **Eviction:** a fixed three pairs, not a loop until `evictions` moves. The count is deterministic in a 2-entry LRU cache, and the test still requires `evictions` to move by at least 2.
- **`others` alignment:** that array is `alignas(16)`, like `UnrelocatedAliasesStayOut`'s `twice`. `same` is unaligned, like `MovedDataHitsTheCache`'s.
