**The walker marks.**
- An SGPR used as the base of a scalar load sets `asBase` (`core/shader/recompiler/Optimization/src/SrtWalker/SrtEvaluator.cpp:206`; the tape does the same at `SrtTape.cpp:395`).
- Any other evaluated `GetUserData` sets `asValue` (`SrtEvaluator.cpp:523`, `SrtTape.cpp:413`).
- An **inline V# held in user SGPRs** is read as a value, so its dword0 and dword1 are `asValue`.
- Relocation treats only `asBase & ~asValue` as relocatable (`src/Driver/Draw/DrawRelocate.cpp:60`).

### 1b. What "data-only hit, stages compiled" means in `APS5_TRACE_DRAW_CACHE`

The 10 s line is printed at `src/Driver/Draw/DrawCacheStatistics.cpp:40`, with this part: `data-only hits (stages: R reused, C compiled; V verified)`.

- **Data-only hit:** the exact register key found no entry, but the shape key found a kept entry with a decode, whose shape matches (`src/Driver/Draw/Draw.cpp:462-466`). Only non-indirect draws get one (`!drawParameters.indirect`, :462). The decode is reused with the user words refreshed; merged pointers are re-read through `InitializeMerged` (:492).
- **Per stage:**
  - **`reused`:** a candidate validated, so the kept variant is used (`Draw.cpp:945`).
  - **`compiled`:** `materializeDrawStage` ran (`Draw.cpp:939`, counted at :946).
- **What "compiled" covers:** the counter counts re-materializations, not SPIR-V compiles. Each one is:
  1. a capture and walk;
  2. a recompiler lookup (full memo, masked memo, or a real compile);
  3. the push-constant and bindings build;
  4. an insert.

  When only a base moved, the recompiler step is usually a masked-memo hit. The cost is the capture, the walk and the materialize, not code generation.
- **`verified`:** draws re-captured under the data-hit verify switch, to check reuse.

### 1c. Why a stage is compiled again when only a buffer base moves

1. **The moved word is in `userDataMask`.**
   - An inline V# base in SGPRs is `asValue` (SrtEvaluator.cpp:523).
   - A pointer base is `asBase` (:206).
   - A word the shader reads at run time is in `userDataRegisterReads`.

   All three end up in the mask (`DrawCapture.cpp:166-167`), so `DrawLookup.cpp:254` drops every kept variant and the stage is materialized again. That is #9853's case: its test requires a rebuild at `tests/execution/DrawDataHitUserWords.cpp:258`.
2. **The variant's runs are pinned to the old addresses.**
   - Even with the mask relaxed, `validateVariant` (`src/Driver/Dispatch/VariantValidation.cpp:92`) compares the pointee runs at the old base.
   - Only the relocation path shifts runs (`DrawRelocate.cpp:179`, the move rule at :218: nonzero, same low 2 bits, relocatable bit). It runs on a register-key miss with an aliased key, not on the data-only path, and only for eligible draws.
3. **Indirect draws get neither path.**
   - Data-only hits are off for indirect draws (`Draw.cpp:462`).
   - A CPU-path indirect draw is not cached at all unless `APS5_DRAW_CACHE_INDIRECT` is set (`DrawCapture.cpp:213`).
   - On the CPU path, every record that patches user words re-materializes each patched program (`Draw.cpp:1133-1179`, with the layout require at :1178).

   Village's menu draws are all indirect (BF-287 census: 835 of 835). So today none of them can reach a data-only stage reuse, whatever the mask says.

**Nothing in the generated code depends on the base.** The binding-plan key drops it, and the module key holds the push offset, pixel packing and vertex selectors. The cost is the materialize path around the recompiler, run once per stage per draw.

### 1d. Where Village's slots 0x08c / 0x00c / 0x090 / 0x102 / 0x00e land

These are shader-bank register offsets (the BF-287 census slots).

| Slot | Stage and user word | Decode site |
|---|---|---|
| **0x08c** | Main stage, user SGPR word 0 (vertex path: program at 0x0c8, RSRC2 0x08b, user data from 0x08c; GS_0 on gfx10 NGG) | `src/Driver/Draw/DrawDecode.cpp:172` |
| **0x090** | Main stage, user SGPR word 4 | same |
| **0x00c** | Fragment, user SGPR word 0 (PS_0) | `DrawDecode.cpp:178` |
| **0x00e** | Fragment, user SGPR word 2 | same |
| **0x102** | The merged hull stage's user-data **address pointer, low half** (with 0x103) | `DrawDecode.cpp:155`, `InitializeMerged` :53-72 |

- **0x102 on Village's draws:** it is read only on tessellation paths. On a vertex-path draw no stage reads it, but it is still in the exact key as an auxiliary word (`DrawRegisterKey.cpp:81`). So a change in 0x102 makes the exact key miss without any stage depending on it. The shape key ignores it, so a data-only hit is unaffected.
- **0x08c / 0x090 / 0x00c / 0x00e:** pointer low halves or V# dword0s. Which one each slot is depends on how the walker marks it, and the code alone can't tell. The switch's per-register counter answers it on a boot:
  - `relocated` means a pointer base (`asBase` only);
  - `forwarded` means a push word;
  - `value` means an inline V# base or another value word.

## 2. The design: the smallest correct change

**Three classes of address-like used word, from cheapest to hardest.**

1. **Forwarded push words:** in `shaderDataUserWords`, and neither `asBase` nor `asValue`. The shader reads them from push data at run time.
   - Reuse the variant and patch the new values into its push constants (`applyShaderDataPatches` exists).
   - **Exact.** No recompiler change.
2. **Relocatable pointer bases:** `asBase & ~asValue`.
   - Shift the variant's runs whose `runBases` is that word by the delta, then `validateVariant` the runs at the new address.
   - Accept only on `Equal`, under the relocation path's move rule: nonzero both ways, same low 2 bits.
   - **Exact.** It reuses `DrawRelocate`'s rule and needs no recompiler change.
3. **V# bases held in SGPRs:** today `asValue`, together with every other value use.
   - Proving one of these is only an address needs walker provenance: a new `UserDataUse` mask, e.g. `asDescriptorBase`.
   - `SrtEvaluator`/`SrtTape` would set it when a user word reaches a buffer descriptor's dword0, or dword1 bits 0-15, and nothing else.
   - The lookup would then patch the variant's `guestDescriptor` dwords 0-1 and the binding base. This is the same patch `MemoPatch` already applies to memo hits.
   - A word that also reaches arithmetic, a compare, or a branch stays `asValue` and stays keyed.

**Indirect draws.** The same reuse must apply to indirect draws, or Village gains nothing:
- allow data-only hits for indirect draws (`Draw.cpp:462`);
- let CPU-path indirect draws be cached (`DrawCapture.cpp:213`);
- in the per-record loop (`Draw.cpp:1133-1179`), use the forwarded/relocated reuse instead of re-materializing.

  The push-word forwarding of upstream #9248 is the record-side half of this.

**What stays in the key.** These go into the stage candidate test, unchanged:
- V# dword1 bits 16-31 (stride, swizzle) and dword3 (format, dst_sel);
- the `num_records` class (zero or nonzero, matching the binding-plan key's present bit);
- the base's low 2 bits;
- every word with any value use;
- every word the walker could not classify;
- the pointee content, through run validation at the new address.

The register key and shape key are unchanged.

**How a value is proven "only an address".**
- From the walker, never from the value: the word's only consumers are a scalar-load base (class 2) or a buffer descriptor's base field (class 3), or it is only forwarded (class 1).
- At lookup:
  - the new value is nonzero, with the same low bits as the old one;
  - the pointee is readable;
  - the shifted runs validate `Equal` at the new address.
- A word that looks like an address (aligned, readable) is never enough on its own. The switch's "stale value" class shows what that heuristic costs.

**Cost per draw.** Not timed here; this is an operation count.
- A loop over at most 64 used words per stage;
- one `DispatchVariant` copy, which shares the compiled result, plus a runs/words vector copy;
- one `validateVariant` over the variant's runs, which a data-only candidate already pays;
- a push-constant memcpy;
- for class 3, one 8-byte descriptor patch.

That replaces a capture, a walk, a memo lookup and a materialize per stage. The counter check below shows the switch avoiding 2047 materializations in the bypass-off test.

**Recompiler and cache impact.**
- **Classes 1 and 2:** none. The switch's recompiler diff is empty.
- **Class 3:**
  - A new mask in `core/shader/recompiler/UserDataUse.hpp`, set in `SrtEvaluator.cpp` and `SrtTape.cpp`. The generated SPIR-V does not change.
  - `SourceVersion` changes automatically with the sources, so old disk-cache files are rejected cleanly (`ShaderDiskCache.cpp:1432`) and rebuilt.
  - `FormatVersion` must be bumped only if the mask is serialized into the cached artifact. Today neither `userDataUse` nor the SRT tape appears in `ShaderDiskCache.cpp` or `ShaderCachePack.cpp`, so no bump.

### What it does when set

**Candidates.** In the data-only candidate block (`DrawLookup.cpp`, switch commit :232-345), a kept variant whose used words differ is no longer dropped. `addressCopy` copies the variant and classifies each differing used word:

| Class | Rule | Effect | `addressReuse` |
|---|---|---|---|
| **forwarded** | Not walked, and present in `shaderDataUserWords` | Patched into the copy's push data (`applyShaderDataPatches`) | 1 (exact) |
| **relocated base** | `relocatableWords` bit set, both values nonzero, same low 2 bits | Runs with that `runBases` shifted by the delta | 1 (exact) |
| **address value** | Anything else whose new value is nonzero and 4-aligned and, with the low 16 bits of the next word as the high half, reads as `GuestMemory::Accessible`. Also the next word of such a differing pair. | Reused unpatched: the stage keeps the old value | 2 (stale value) |
| **refused** | Anything else | The variant is not a candidate | — |

**Validation of the copy.**
- **`Equal`:** accepted.
- **`Differing` with a differing word:** the runs are read again from live memory with `GuestMemory::CopyMapped` and accepted with `addressReuse` 3 (unvalidated). If the runs can't be read, the copy is refused and counted as unreadable.
- **`Inaccessible`:** counted as unreadable and refused.
- **Every other gate outcome:** refused, as on the base.

**Inserts.** In `DrawCapture.cpp`, a draw that reused any stage with `addressReuse` ≥ 2 is not inserted, so a stale stage is never cached under the new words.

**Unset.** Every new branch sits behind `diagStageReuseAddressWords()`, a static `getenv` read once, so the behaviour is the base's. The `^agc` comparison below confirms it.

### Counters (`APS5_TRACE_DRAW_CACHE`, every 10 s, only when the switch is set)

```
[draw-cache] address-word stage reuse (APS5_DIAG_STAGE_REUSE_ADDRESS_WORDS, 10 s): compiles avoided N (exact, stale value, unvalidated), links avoided N (draws with every stage reused), indirect data-only hits N; candidates: exact, stale value, unvalidated, refused, unreadable; differing used words: forwarded, relocated base, address value, refused; inserts skipped after a stale reuse N; by register (forwarded/relocated/value/refused): top 8
```

- **compiles avoided:** stages taken from a classified copy instead of `materializeDrawStage`, split by `addressReuse`.
- **links avoided:** draws where every stage was reused, so the entry's linked pipeline is used without a lookup.
- **by register:** `userDataBase + word − hiddenUserWords`; hidden merged words show as `0xfff`.

### Checks walked so that set never crashes or trips a `Require`

1. **Push layout:**
   - a reused stage's `pushOffset` must match the slot (the candidate block's `pushOffset` test);
   - the push-constant block require in `finishDraw` (`Draw.cpp:963-964` on the base) sees the same sizes, because the copy shares the compiled result.
2. **The `validateVariant` gates:** `QueuedLabel`, `FlushingImage`, `ForgetMoved`, `PublishMoved`/`PendingMoved` (with the gate retry) and `Inaccessible` all refuse. Only `Differing` is accepted unvalidated, and only after a successful live reread.
3. **The pipelined-draw precheck:** `writesBeyondTargets` runs on candidates as on the base.
4. **The CPU-indirect record loop's require** "patched program changed its push constant layout" (`Draw.cpp:1178`) still holds, because the patched path is unchanged.
5. **Stale and unvalidated entries are never inserted**, so the cache never holds a stage keyed to words it was not built for.
