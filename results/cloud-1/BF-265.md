## Per-source reds on cda1b61077

**Method:** the same as BF-230.
- `agc_driver_table_index_validation`'s cases run one at a time, as `runner`, with `APS5_TABLE_INDEX_BREAK=<source>` exported; that drops the source's bumps.
- **Counter mode** asserts the case's source's bump count; **outcome mode** asserts only what the draw sampled and which proof it took.

| case | break | counter mode | outcome mode | message (counter mode, then outcome mode where it differs) |

| cpu | cpu | exit 1 | exit 1 | "cpu write: the draw after a CPU write to the sampled texture still sampled its old texels (brightest 255, accepted 1, …)" |
| table | cpu | exit 1 | exit 1 | "table word: a T# word change in the table did not invalidate the O(1) proof (brightest 255, accepted 1, …)" |
| driver | driver | exit 1 | exit 1 | "driver store: a driver store over a texture did not bump its subscription"; "… the draw after a driver store over a sampled texture took the O(1) proof or rebuilt the object" |

| unwatch | unwatch | exit 1 | exit 0 | "unwatch: leaving the write watch did not bump the texture's subscription" |
| remap | forget | exit 1 | exit 0 | "remap: the free and remap of the texture's range did not bump its subscription" |

| array | cpu | exit 1 | exit 1 | "array: a write to the base slice of a 2D array read as 2D was missed or rebuilt the object" |

- **Every source's case goes red in counter mode with its own source dropped.**
- **Outcome mode stays green for pending, unwatch and remap,** as on BF-230 and BF-124:
  - **`pending` and `unwatch`:** the sweep's collect over a range the write watch no longer covers fails, so the draw falls back. Both outcome cases stay green with every source dropped (`APS5_TABLE_INDEX_BREAK=cpu,driver,pending,unwatch,forget,release,import,compared`: exit 0 each).
  - **`remap`:** the re-registration is fresh, so `cpu` catches it too. With `APS5_TABLE_INDEX_BREAK=cpu,forget` the outcome case goes red (exit 1): "remap: the draw after a remap of the sampled texture took the O(1) proof or sampled the old mapping (brightest 255, accepted 1, …)".
  - So each of the three can only be red on its own bump, which counter mode checks.
- **Specificity:** each case passes with another source dropped (exit 0): cpu with forget, table with pending, pending with cpu, remap with cpu, compared with cpu, driver with cpu, unwatch with cpu, release with import, import with release, array with forget.
- **All cases with nothing dropped:** exit 0, "table index validation tests passed".
