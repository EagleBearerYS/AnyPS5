### What the code does

**Layout** (`include/Evp.hpp`):
- `LibreSslEvpCipher` is LibreSSL's 88-byte `struct evp_cipher_st`, with typed `APS5_VABI` function pointers.
- alvaroelpob's 168-byte `LibreSslEvpCipherCtx` moves here from `EvpCipherCtx.cpp`, unchanged, except that `cipher` is now typed.
- `static_assert`s pin both layouts.
- EVP calls the cipher's `init`, `do_cipher`, `cleanup` and `ctrl` through the descriptor, as LibreSSL does. A cipher a title builds itself therefore works too; the tests use test-defined ciphers.

**Cleanup, free and ctrl:**
- `cleanup` calls the cipher's `cleanup` first; a 0 from it returns 0 and leaves the context as it was.
- It then clears `ctx_size` bytes of cipher data, frees the data through the guest `free`, and clears the 168 bytes.
- `free(NULL)` does nothing.
- `ctrl` returns 0 with no cipher or no cipher `ctrl`, and maps -1 to 0.

**Init:**
- `enc` -1 keeps the direction; any other value is normalised to 0 or 1.
- Passing a cipher cleans up the old one, keeps `encrypt` and the flags across the cleanup, then resets the flags to 0, so padding is back on. It allocates `ctx_size` bytes through the guest `malloc`, sets `key_len`, and runs `EVP_CTRL_INIT` for `EVP_CIPH_CTRL_INIT` ciphers.
- The block size must be 1, 8 or 16.
- The IV setup by mode is exact:
  - CBC, CFB and OFB use `oiv` and `iv`;
  - CFB and OFB also reset `num`;
  - CTR resets `num` and copies only `iv`;
  - `EVP_CIPH_CUSTOM_IV` skips the setup;
  - any other mode fails.
- `init` runs when a key is given or the cipher has `EVP_CIPH_ALWAYS_CALL_INIT`.
- The skip LibreSSL takes for a context that already holds an `ENGINE` is kept.

**Update and Final:** the `evp_enc.c` code, line by line:
- the custom-cipher path;
- the fast path for aligned input;
- the 32-byte buffer;
- PKCS padding and the held-back last block in decryption;
- the padding checks (pad byte 1 to block size, all pad bytes equal);
- the `EVP_CIPH_NO_PADDING` paths.

**CFB8 and CTR:**
- Their `init` is `AES_set_encrypt_key` from #9033, using `ctx->key_len * 8`.
- CFB8 runs `cfbr_encrypt_block` per byte through `AES_encrypt`. The IV shifts in the ciphertext byte, and `num` is untouched.
- CTR is #9033's `AES_ctr128_encrypt`, over `ctx->iv`, `ctx->buf` and `ctx->num`.
- The cipher data is the 244-byte `AES_KEY` inside LibreSSL's 264-byte `ctx_size`.

**GCM** (in its own state of 384 bytes, within the 680-byte `ctx_size`):
- `CRYPTO_gcm128_init`, `setiv` (including the GHASH of IVs that aren't 12 bytes), `aad`, `encrypt`, `decrypt`, `finish` and `tag` all follow `gcm128.c`, with its length limits (AAD 2^61 bytes, message 2^36 − 32) and the -2 for AAD after data.
- `aes_gcm_ctrl` handles:
  - `INIT`;
  - `SET_IVLEN`, allocating through the guest heap above 16 bytes;
  - `SET_TAG` and `GET_TAG`, with their direction and length checks;
  - `SET_IV_FIXED`, including -1, and filling the rest from host entropy when encrypting;
  - `IV_GEN`, with the 64-bit invocation increment;
  - `SET_IV_INV`;
  - `AEAD_TLS1_AAD`, with the length fix-up and its 16 return;
  - `COPY`, re-pointing or duplicating the IV;
  - -1 for any other type.
- `aes_gcm_init_key` handles key and IV in either order, with the saved IV.
- `aes_gcm_cipher` handles:
  - AAD when `out` is null;
  - data;
  - `Final`, which computes the tag when encrypting or checks the set tag when decrypting, and then does not reuse the IV;
  - the TLS record path (in place, the explicit IV, the tag appended or checked, and the plaintext wiped on a mismatch).

**`EVP_cleanup`:**
- **What LibreSSL clears:** `names.c` empties the cipher and digest name tables, the PBE table, a deferred `OBJ_cleanup` and the signature-ID tables.
- **Why there is nothing to clear here:** every export that fills those tables is still a stub on this base (`OPENSSL_add_all_algorithms_noconf`, `SSL_library_init`, `CONF_modules_load_file`, `OPENSSL_load_builtin_modules`, `OBJ_create`, `OBJ_cleanup`, `PKCS12_PBE_add`), so the body is empty.
- **The static descriptors stay valid,** and a test shows it.
- **The debt entry says it must change** once one of those exports fills a table.

### Throws and gaps (all in `docs/dev/debt/libSceLibreSsl.md`, five new entries, each under 1,000 characters)

- **No error codes are queued.** Failures return 0 or -1 as LibreSSL does, but `EVPerror` has no queue to write to, because `ERR_get_error` and `ERR_peek_error` are stubs on this base. #9571 adds an error queue.
- **`ENGINE` isn't implemented:** a non-null `ENGINE` argument to Init throws, and so does a context that holds one, in cleanup. With no `ENGINE` registered, the context's `ENGINE` is null, as in LibreSSL.
- **Inputs where LibreSSL would dereference null or overrun the context throw** (`std::invalid_argument`):
  - null context, length or buffer;
  - a cipher without `init` or `do_cipher`;
  - a negative `ctx_size` at cleanup;
  - a CTR IV longer than 16 bytes;
  - a context whose `buf_len` or block mask no longer fits its cipher;
  - GCM with no cipher data;
  - `IV_GEN` with an IV shorter than 8 bytes;
  - an invocation field longer than the IV.
- **GCM key setup:** a key length the AES setup rejects throws, where LibreSSL would carry on with a stale schedule. This can only happen when a title writes `key_len` itself.
- **The descriptor function pointers are host functions,** not the module's. The cipher data is the port's own layout (the CFB8/CTR schedule is #9033's `AES_KEY`; GCM is its own struct). A title reading `cipher_data` sees different bytes.
- **Nothing is checked on the console.**

**Where:** all the new cases are in the library's existing guest test, `core/libs/tests/GuestLibreSslEvpCipherCtx.cpp` (`guest_libressl_evp_cipher_ctx`). The test reads the context through LibreSSL's byte offsets and builds descriptors with its own 88-byte struct, so it checks the guest ABI independently of `Evp.hpp`.

**Lifecycle (commit A):**
- `cleanup`:
  - the cipher's `cleanup` sees the data before it is wiped;
  - a 0 from it leaves the context untouched;
  - with or without a cipher, or a cipher `cleanup`, the 168 bytes come back cleared;
  - an `ENGINE`, a negative `ctx_size` and a null context throw.
- `free`: `free(NULL)` does nothing, and `free` runs `cleanup` (with either result) before freeing.
- `ctrl`: no cipher or no `ctrl` gives 0; the results 1, 16, 0, -1 and -2 map to 1, 16, 0, 0 and -2; the arguments are passed through; a null context throws.

**Init, Update and Final (commit B):**
- **Padding on, against a test 16-byte block cipher:**
  - plaintexts of 0, 1, 15, 16, 17, 31, 32, 33 and 48 bytes;
  - fed 1, 5, 16 or 64 bytes at a time;
  - through both Encrypt*/Decrypt* and `EVP_Cipher*`;
  - the result is checked against a reference PKCS-padded result.
- **Held-back block:** `final_used`, `buf_len`, `final` and the output per call.
- **Bad padding:** pad bytes 0, 17 and 255, and mismatched pad bytes. A full pad block gives 0 bytes. `Final` fails with nothing decrypted or with a partial block.
- **Padding off:** 32 bytes go through with no hold-back and `Final` outputs 0. 17 bytes make `Final` fail, with `outl` left alone when encrypting and set to 0 when decrypting. Passing a cipher again turns padding back on; Init without a cipher keeps it off.
- **Init fields:**
  - `cipher`, `engine`, `encrypt`, `key_len`, `block_mask`, `buf_len`, `final_used`, `flags` and the cipher data;
  - CBC, CFB, OFB, CTR, stream, ECB and `CUSTOM_IV` handling of `iv`, `oiv` and `num`;
  - `enc` values -1 and 7;
  - GCM mode without `CUSTOM_IV`, a CBC IV of 17 bytes, and block size 4 all fail;
  - a CTR IV of 17 bytes throws;
  - `ALWAYS_CALL_INIT`, `CTRL_INIT` (including a failing `ctrl`), `ctx_size` 0, a failing `init`, no cipher, an `ENGINE` and a null context.
- **Stream cipher:** block size 1, with 1, 4 and 37-byte pieces.
- **Custom cipher:** results passed through, -1, a zero length, a negative length reaching `do_cipher` as `SIZE_MAX`, and `Final` with a null input.
- **Argument errors:** lengths 0 and -1, and null `outl`, input or context, through all three Update and Final forms.

**CFB8 and CTR (commit C):**
- The descriptor fields (NID, block 1, key length, IV 16, flags 0x4003 or 0x4005, `ctx_size` 264, no `cleanup` or `ctrl`) and the same pointer on every call.
- **SP 800-38A CFB8** (F.3.7, 9, 11 and the decrypt cases) **and CTR** (F.5.1–F.5.6) for AES-128, -192 and -256:
  - with `EVP_Encrypt*`, `EVP_Decrypt*`, and `EVP_Cipher*` in both directions;
  - fed 1, 7 or 64 bytes at a time;
  - plus once with padding off (no effect at block size 1).
- **CFB8:** in-place use; the IV ends as the last 16 ciphertext bytes, and `num` is untouched.
- **CTR:**
  - after 18 bytes, `num` is 2, the counter has advanced by 2, and `buf` holds the second keystream block;
  - re-Init without an IV resets `num` and keeps the counter;
  - the counter wraps across 128 bits (all-ones becomes zero);
  - a bad `key_len` fails Init, a null key fails `init`, `num` 16 throws, and missing cipher data throws.

**GCM (commit D):**
- **The descriptors:** NID, block 1, IV 12, flags 0x305476, `ctx_size` 680, with `cleanup` and `ctrl`.
- **Test cases 1–8, 13 and 14:** empty and 16-byte data, 64 and 60 bytes with and without AAD, 8-byte and 60-byte IVs, AES-192 and AES-256.
  - The IV length is set with `EVP_CTRL_GCM_SET_IVLEN`, then key and IV, then AAD with a null `out`.
  - They run through Encrypt*/Decrypt* and `EVP_Cipher*`, fed 1, 7 or 64 bytes at a time.
  - The tag is read with `EVP_CTRL_GCM_GET_TAG` (16 and 12 bytes).
  - Decryption is checked with `EVP_CTRL_GCM_SET_TAG`: without a tag `Final` fails, then succeeds once the tag is set; a flipped bit fails; a 12-byte prefix of a wrong tag fails; a 5-byte prefix of the right tag passes.
  - A second `Final` fails because the IV isn't reused.
  - Cleanup clears the context.
- **ctrl and order:**
  - `SET_IVLEN` 0 and -3 return 0;
  - `SET_TAG` while encrypting, `GET_TAG` before a tag, 17 or 0 bytes, or while decrypting, and an unknown ctrl, all return 0;
  - `IV_GEN` without a fixed IV returns 0;
  - data before the key or the IV fails;
  - AAD after data fails (`EVP_EncryptUpdate` leaves `outl` alone, `EVP_DecryptUpdate` sets it to 0);
  - the IV can be set before the key, and a 60-byte IV is allocated;
  - `EVP_CTRL_COPY` works with both an allocated IV and the context's IV: both contexts finish with the same ciphertext and tag, the copy's IV writes land in its own context, and cleaning up both contexts doesn't free anything twice;
  - with no cipher data, `ctrl` and `do_cipher` throw.
- **TLS records:**
  - **Encrypting:** `SET_IV_FIXED` -1, and `AEAD_TLS1_AAD` returning 16 with the length fixed up. Two records with sequence numbers 1 and 2 match python's AES-GCM, including the explicit IV and the counter advancing by one.
  - **Rejected input:** a bad AAD length or size; `out != in`; a record under 24 bytes, after which the TLS state is kept; and a second record with no new AAD.
  - **Decrypting:** `SET_IV_FIXED` 3 and 5 return 0, and 4 returns 1. A decrypt AAD shorter than the tag is refused. Both records decrypt in place to the plaintext. A record with a flipped tag bit fails, sets `outl` to 0 and wipes the plaintext.

**`EVP_cleanup` (commit E):** after it, the same CTR descriptor is returned and encrypts the F.5.1 block, including on a context set up before the call.

### What
Implements 22 EVP cipher exports of libSceLibreSsl on the cipher-context object from #10488, following LibreSSL 2.5.4 (libressl/openbsd 2e2c612066aa, the version in the firmware 13.40 measurements):
- `EVP_CIPHER_CTX_cleanup`, `EVP_CIPHER_CTX_free`, `EVP_CIPHER_CTX_ctrl` (evp_enc.c)
- `EVP_CipherInit_ex`, `EVP_EncryptInit_ex`, `EVP_DecryptInit_ex`, `EVP_CipherUpdate`, `EVP_EncryptUpdate`, `EVP_DecryptUpdate`, `EVP_CipherFinal_ex`, `EVP_EncryptFinal_ex`, `EVP_DecryptFinal_ex`: buffering, PKCS padding and its checks, `EVP_CIPH_NO_PADDING`, IV setup per mode, and the custom-cipher path, called through the descriptor's function pointers (evp_enc.c)
- `EVP_aes_{128,192,256}_cfb8` and `EVP_aes_{128,192,256}_ctr` on the AES from #9033 (e_aes.c, cfb128.c, ctr128.c; NIST SP 800-38A)
- `EVP_aes_{128,192,256}_gcm`: GHASH and GCTR from gcm128.c, `aes_gcm_ctrl` (IV length, tag, fixed and generated IVs, TLS AAD, copy) and the TLS record path (e_aes.c; NIST SP 800-38D)
- `EVP_cleanup`: nothing in this module can fill the tables LibreSSL's names.c clears yet, so it returns; the debt entry says when that changes

`include/Evp.hpp` holds LibreSSL's 88-byte `EVP_CIPHER` and the 168-byte `EVP_CIPHER_CTX` from #10488. `include/Aes.hpp` shares `AesKey` with `Aes.cpp`. Failures queue no error code, a non-null `ENGINE` throws, and inputs LibreSSL would dereference or overrun throw; the five new entries in `docs/dev/debt/libSceLibreSsl.md` list them.

Related: #10450 (`EVP_CIPHER_block_size`, same `LibreSslEvpCipher` layout), #9571 (CMAC and the CBC descriptors over the same `EVP_CIPHER` layout).

### Tested
Linux x86-64 (Ubuntu 24.04, gcc 13.3.0, wild 0.10.0), no title. `guest_libressl_evp_cipher_ctx` gains 17 cases:
- SP 800-38A CFB8 (F.3.7–F.3.12) and CTR (F.5.1–F.5.6) for AES-128/192/256, through `EVP_Encrypt*`, `EVP_Decrypt*` and `EVP_Cipher*`;
- GCM test cases 1–8, 13 and 14, with the IV length and tag set and read through `EVP_CIPHER_CTX_ctrl`, including wrong and truncated tags;
- GCM TLS records, `EVP_CTRL_COPY`, and the ctrl error returns;
- padding on and off, held-back blocks and bad padding, with a test-defined block cipher;
- the Init mode and IV handling, and the custom-cipher and stream paths.

Each commit's new cases fail against the code before it and pass with it. CI-configured build, then `ctest` as an unprivileged user: 2,054 tests, 1,961 passed, 88 skipped and 5 failed. The five need IPv6, which the test machine lacks: `guest_net_buffer_validation`, `guest_socket_options`, `guest_socket_stream_options`, `guest_socket_address_length` and `guest_tcp`.
