## 1. Measure first (exp/lane-b-host-visible 7e992a8e3)

**How I measured.** I ran `agc_driver_village_draw_cost_tests --cost 20` with `APS5_PROFILE_DRAW=1`, lavapipe and `LP_NUM_THREADS=2`, two runs to completion. One local patch was added and is not committed: a `BdaFault` host-owner tag on the fault buffer. On 7e992a8e3 that buffer is otherwise counted as "shader data".

| run | host-visible peak | shader data (incl. fault) | of which BDA fault buffers | fault share of shader data | live fault buffers |
|---|---|---|---|---|---|
| before 1 | 214.4 MiB | 194.1 MiB | 189.7 MiB | 97.7% | 6,071 |
| before 2 | 224.4 MiB | 203.4 MiB | 198.7 MiB | 97.7% | 6,359 |

Each `BdaResources` owned one buffer of `FaultBufferBytes` = 24,620 bytes, which the pool rounds to 32 KiB. So live fault buffers = live `BdaResources`.

### What lives in the fault buffer (BdaAbi.hpp) and who writes it

| words | contents | written by |
|---|---|---|
| 0–7 | the fault report | `record_bda_fault` (SpirvBdaFault.cpp: CAS on word 0, stores 1–6, OR on 7), the rect-list check (RectListShaders.cpp, words 0–7), and through `record_bda_fault`: image-table faults, unlinked calls and the loop guard |
| 8–9 | written-overflow and written-count words | the written-page record (SpirvBdaLookup.cpp `DefineBdaNoteWrite`), emitted only when the program has `bdaWrites` |
| 10…6153 | written slots and written list | same as words 8–9 |
| 6154 | SRT guard word | guarded SRT reads only (SpirvMemoryInstructions.cpp, `guardedSrtSlots`) |

So a program that never stores through the BDA table and has no guarded SRT read can write only words 0–7: 32 bytes of the 24,620.

### The cache, and who really held the buffers

- **The cache.** `ResourceCache` (ShaderResources.hpp) is an LRU.
  - Size: 1,024 entries (`APS5_RESOURCE_CACHE_ENTRIES`). It doubles up to 16,384 while evicted keys keep coming back, and halves back while under a quarter is used.
  - When it drops an entry: the least recently used one goes when an insert passes the capacity or the image-table element budget. `Clear()` drops a replaced device's entries, and the device clears the cache at teardown.
- **Address-based builds are never cached.** `ShaderResources::noteReusable` returns early on `usesBda`, both on main and on 7e992a8e3. The cache keeps only fault-only builds: rect-list, image-table and SRT-guard builds, and only without `APS5_LOOP_GUARD`.
- **What held the ~6,000 buffers on the bench.** They were address-based draws still in flight, which the recorder keeps until their batch completes. A local counter showed that holders drop each time `finished` advances (22 → 134 → 232 → 344…). The arena's idle-holder reclaim found nothing to take back. Every one of the 22,000 BDA builds was read-only with no SRT guard.

## 2. The cut (keeps every fault report)

### Commit 1 (79b229ad7): a per-device fault arena — candidate (a), plus (b)'s give-back for idle cached holders

**Slots.**
- Fault buffers are slots of 512 KiB host-visible chunks, at `minStorageBufferOffsetAlignment`.
- Each slot is bound with its offset, rewriting only the fault descriptor of the object's own sets (`ShaderResources::prepareFaultSlot`).

**Tracking use.**
- An object notes the serial of each batch it is used in: when it is bound (`Bind`, `PrepareDrawBindings`) and when its writes are marked (`MarkGpuWrites`).
- The recorder reports each batch once its completions ran (`BdaResources::NoteFinished` in `Recorder`'s `Finishing` destructor).

**Reclaim.**
- When no chunk has a free slot, and only under the GPU lock, the arena takes back the slots of the older half of the idle holders.
- An idle holder is one whose last batch finished and whose slot is clean: no unread report, written-page claim or SRT guard.
- Without the lock the arena grows instead.
- A holder that lost its slot takes one again when it is next bound.
- A slot in use never moves, so every report is read from the slot its shader wrote. Per-draw attribution is unchanged.
- A chunk is freed once none of its slots is held.

**Switch.** `APS5_NO_SHARED_FAULT_SLOTS=1` restores one full-size buffer per object. It is documented in ENVIRONMENT.md.

### Commit 2 (2545cdfbd): 32-byte slots for report-only programs — candidate (c), with BdaAbi.hpp unchanged

**The proof.**
- `SpirvFaultReportOnly(words, set, binding)` lives in ShaderAddressResources.cpp and is cached per module hash.
- It proves that a program reaches its fault buffer only through `OpAccessChain` with a constant member 0 and a constant word index below 8, and that it uses those pointers only in loads, stores and atomics.
- Any other reference fails the proof: a computed index, word 8 or beyond, the buffer passed to a function, or a word pointer copied. A literal that happens to equal an id fails it too, which errs to a full slot.

**Binding.**
- `ShaderResources::prepareAddressBindings` ANDs the proof over every stage's fault binding.
- `buildComplete` then makes the `BdaResources` report-only, which binds `sizeof(BdaAbi::Fault)` = 32 bytes.

**Checks on a report-only slot.**
- `CheckFault` reads only the report.
- `markWrittenPages` and `checkSrtGuard` are skipped: those words are not in the slot, and the program cannot write them.
- The clean check, clear and loop-guard reset cover the 32 bytes.

**Arena.** Report-only and full slots come from separate chunks. Reclaim takes back only holders of the requester's slot size.

**Precedent.** The BDA read execution tests (BdaExecution.cpp `RunBdaExecutionTests`) have always bound a `sizeof(Abi::Fault)` buffer to read programs.

### Fault reports kept exactly

| report | how it is kept |
|---|---|
| per-draw attribution | one slot per object, never moved while in use |
| image-table faults | written by `record_bda_fault`, words 0–7; read back through `SetImageTables` |
| SRT guard faults | a guarded program writes word 6154, fails the proof and keeps a full slot; read back through `SetSrtGuards` |
| written list | a program with BDA stores writes words 8+, fails the proof and keeps a full slot |
| loop guard | report words 0–7; the reset clears the slot |

## Tests

### New cases

**`agc_driver_graphics`** (tests/BdaResources.cpp `faultSlotTests`, mock device):
- 256 idle cached `BdaResources` hold fewer than 64 slots, and the reclaim count is non-zero.
- The two oldest are retaken while in flight, survive 64 pressure objects, and report their own addresses (0x7fff11110000, 0x7fff22220000) from one batch.
- A fault-only `ShaderResources` is reclaimed under pressure, rebinds a new slot on `Bind`, and its `CheckFaults` reports 0x7fff44440000, while the build that took its old slot reports 0x7fff33330000.
- A build whose program cannot be read keeps a full 24,620-byte slot.
- 64 report-only objects share one chunk of 32-byte slots, and two neighbours report 0x7fff55550000 and 0x7fff66660000.
- The real rect-list control program (`BuildRectListShaders`) is bound 32 bytes, and its `CheckFaults` reports 0x7fff77770000.

**`agc_driver_bda_device`**, on lavapipe:
- Contract cases: `SpirvFaultReportOnly` accepts the BDA read and fault-sequence programs and rejects store and write programs, a missing binding and unreadable modules.
- Five hand-assembled modules cover: report-word loads, stores and atomics accepted; and rejected for word 8, a computed index, a copied pointer, and the buffer passed to a function.
- Execution case (`RunBdaFaultSlotExecutionTests`): two neighbouring report-only slots of one chunk, two dispatches recorded in one command batch, each faulting at its own address (0x7fff11110000, 0x7fff22220000). Each `CheckFault` reports its own address.
