## B. #6636 with #6628

### The merge of the two heads as given crashes

- `30eb96d70` merged #6628's head into #6636's head without conflicts, and it built.
- `agc_driver_address_draw_reuse` then died with SIGSEGV on every run: 3 under ctest, 2 under gdb.
  - Under gdb, the fault is in an llvmpipe worker thread (`llvmpipe-0`), in JIT code, at `si_addr 0x0`.
  - The crash comes after the scene's first draw; stdout is buffered, so the lines that would place it are lost. The only rebuilds of an unchanged space in that scene are its 63 back-to-back builds (see below).
- `APS5_NO_ADDRESS_DRAW_REUSE=1` still crashes. So #6636's draw reuse is not the cause.
- With `APS5_NO_ADDRESS_SPACE_CACHE=1` or `APS5_NO_BDA_TABLE_CACHE=1`, it no longer crashes. It fails only the counter assertions those switches break.
- **Cause, in #6628 (`7d4360ff8`, "retain BDA table fast path with MSAA guards"):**
  - The lookup by `{space serial, guard generation}` now runs before `tableBytes` is computed. It returns the cached table with `tableBytes` still 0 (`BdaResources.cpp:130-135` on #6628's head).
  - `Table()` returns `{handle, 0, tableBytes}`, so the build binds the page table with a range of 0. llvmpipe reads that descriptor through a null base.
  - On main and on #6636, the space-serial lookup runs after `tableBytes` is set.
  - #6636's back-to-back draws take this path on every rebuild of an unchanged space while the previous build still holds the table: "back to back: 64 draws, 63 builds".
- **Confirmed:** with the size set in that branch, the same binary passes, and the path was taken 63 times.

### The fix commit, on #6628's head (`579e4c43c4`, 2 files, +4)

- `579e4c43c4` fix(agc): bind the whole BDA table a build finds by its space key. Its parent is `00c7025c3a`, so it applies to #6628's branch as is.
- In the space-key hit, it sets `tableBytes = sizeof(Header) + it->ranges.size() * sizeof(Range)`. The entry's ranges are the ranges the table was written with: the filtered ones when spans were excluded.
- Test: #6628's own `snapshotTableTests` (`tests/BdaResources.cpp`, run by `agc_driver_graphics`) already makes build `b` take the space-key table (`spaceTables + 1`). It compared only the buffer handle; it now also requires `b`'s bound range to equal `a`'s.
- **Red on #6628 alone** (`00c7025c3a` plus the test, without the fix line): `agc_driver_graphics` fails with `AGC graphics: a build served the serial-keyed BDA table binds another size than the build that made it`.
- **Green on #6628 alone** (`579e4c43c4`): `agc_driver_graphics` and `agc_driver_sample_multisample_target` passed, 3 runs each.
- 0 added comment lines.
