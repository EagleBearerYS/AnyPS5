## The rule, and why it's safe

**The rule** (`Graphics/src/Draw.cpp`, `prepareDrawInputs`, in the vertex fetch loop):
- For an indirect draw (`args != nullptr`), the fetch's `[address, address + VertexBufferExtent)` is queried with `GuestMemory::DescribeCommitted`. That is the same `describePages` predicate that `CheckRange`'s `verify` uses.
- If the range isn't wholly readable but a readable run starts at `address`, the fetch is cut at that run's end.
- Everything downstream then uses the cut range: the copy plan, the in-place import, `KeepDrawInput`, `inPlaceReads` and the render-target alias check. The draw stays GPU-side.
- Unchanged:
  - with nothing readable at `address`, `CheckRange` throws the same message as before;
  - direct draws keep `VertexBufferReadSize`;
  - a wholly readable range is used whole.

**I chose the cut over the CPU fallback**, because it's safe and it keeps the title's draws GPU-side.

**Why it's safe:**
- **On the console,** the GPU fetches only the vertices the records name, and a fetch from unmapped memory would fault. A valid title never reads past the readable prefix, so no fetch the guest makes is lost.
- **On the host,** these buffers are read only through Vulkan vertex input: `vkCmdBindVertexBuffers`, Draw.cpp:1417, binding the whole buffer from its offset. `robustBufferAccess` is enabled when available (Execution/src/VulkanDevice.cpp:1486), so a fetch past the binding's end returns zero or in-bounds data and never reads host memory.
  - **Copy case:** the bound buffer is the cut copy itself.
  - **Import case:** it is the host import, which covers only mapped guest memory, so even a fetch past the cut but inside the import reads readable memory.
- **No path reads these bindings without vertex-input robustness.** The other way a vertex shader reads vertex data is the recompiler's runtime vertex fetch, which pulls through a V# (`VertexFetch.cpp` asserts it creates no Vulkan vertex attributes). That goes through ShaderResources' buffer bindings, not `prepareDrawInputs`, so this cut doesn't apply to it. Its range handling is separate.

**Counter:** the `[draws]` line's indirect part now reads `gpu-side N (M rewritten, K draw parameters, C clamped, V vertex ranges cut)`, with APS5_PROFILE_DRAW. V counts cut fetches.

## Repro test: `agc_driver_indirect_vertex_past_end`

`tests/execution/IndirectVertexPastEnd.cpp`, at device level like `DrawOffsetIndices.cpp`.

**Setup:**
- **Memory:** BF-029's `TailBlock`, a 64 KiB guest block followed by a PROT_NONE page.
- **Vertex buffer:** six float4 positions in the block's last 96 bytes. Vertices 0–2 are a triangle in cell 1 of a 64×32 target; vertices 3–5 are one in cell 2.
- **Descriptor:** 8 records × 16 bytes, which runs 32 bytes (two records) past the block.
- **Records and index buffer:** inside the block.
- **Vertex shader:**
  1. `v_add_co_u32 v5, null, s16, v5`;
  2. a V# from user data;
  3. `v_cndmask_b32 v3, v8, v5`;
  4. `buffer_load_format_xyzw v[8:11]`, exported as the position.

  The recompiler folds this into one Vulkan vertex attribute with `vertexOffsetSgpr` 16.
- **Classification:** each case is classified by `Driver::ClassifyIndirectDraw`, which must say GPU, and drawn with `VulkanDevice::Draw`. A draw counts as GPU-side when BF-025's `IndirectPassCounters` moves by exactly 1.

**Cases:**

| `DRAW_INDEX_INDIRECT`, base vertex 3 read with draw parameters (BaseVertex) | | cell 2 |

## Cost

- **Query alone, per fetch:** `DescribeCommitted`, 40,000 queries averaged:
  - 0.75–0.85 µs for a wholly readable 96-byte range;
  - 1.2–1.3 µs for a range that reaches the unreadable page, where the OS query answers;
  - 1.2–1.35 µs at the title's shape: 0x280020 bytes declared and 0x280000 readable, in one registered mapping.
- **Per draw:** `APS5_PROFILE_DRAW=1 … --cost 40000` repeats the `DRAW_INDIRECT` case. The `[draws]` line's `vertex` phase (index, layout, fetch loop, copies) is divided by the 10 s window's draws. Each figure is one window.

  | Descriptor | base `d664cd3647` | `511ad9ff7` (cut) | `19b8f822e` (cut + skip) |
  |---|---|---|---|
  | wholly readable (6 records) | 13.29 / 14.02 / 13.37 µs | 15.06 / 15.50 / 15.01 µs | **13.62 / 13.24 / 13.84 µs** |
  | past the block's end (8 records) | throws | 15.59 / 15.79 / 16.31 µs | 17.50 / 15.46 / 15.43 µs |

  - In every cut window shown, every draw was cut, for example `10879 vertex ranges cut` of 10,879 draws. A mixed window at the switch-over is left out.
  - The whole `Graphics::Draw` call is about 870–990 µs here, because the test's target isn't resident and every draw is synchronous.
- **The skip:** the cut alone cost 1.7 µs per draw on a readable range, and 1.9–3.0 µs when it cut (above the task's ~2 µs). So `19b8f822e` skips the later per-copy `CheckRange` wherever the proven fetch ranges cover the copy with no gap.
  - Any other copy range is still checked and fails as before: one that reaches an unreadable fetch base, or a gap between two readable runs (PlanVertexCopies can join a fetch that starts past a short cut).
  - Result: a readable range costs what it did before the fix.
  - A cut fetch still costs about 1.5–2 µs more, for the OS query on the unreadable page. That applies only to draws that would otherwise abort.
- **`19b8f822e`'s checks:**
  - `^agc` 625/629 with 42 skipped: the three known failures, plus `agc_driver_preparation_scope_settle`, which failed in the sweep and passes alone;
  - the four indirect tests ×10: 40/40, and 40/40 with `APS5_PIPELINE_INDIRECT=1`;
  - registration: 920 executables, none new.
