## The cases

### `agc_untracked_hint_proof` (`untrackedHintProofTests`)

All three cases are added after the existing `walkStore` case, before `sampled.reset()`.

**Case A: a store from another thread right after the compare.**
- `WalkStore` gains `value` (default 0x45) and `threaded` (default false). With `threaded` set, `storeDuringWalk` runs its `memset` and its `UntrackedHint` call on a `std::thread` it starts and joins inside the flush hook.
- The case repeats the existing one: `MarkWritten` the second surface, store 0x46 into the first surface while the second is compared, then `recorder.Activate()`.
- Asserts:
  - The walk compared the second surface and was not fast.
  - The first surface was not read again.
  - In the next collect epoch the proof is not fast and the version moved.

**Case B: a store from another thread after a fast proof.**
- Bump, prove once, then require a second proof in the same epoch to be fast. In hint mode this leaves the main thread's hint memo holding that epoch.
- A `std::thread` stores 0x47 and is joined; then the main thread bumps.
- Asserts: not fast, and the version moved.

**Case C: a check on another thread.**
- Bump, prove twice (the second fast), then store 0x48 on the main thread.
- A `std::thread` calls `BumpCollectEpoch` and then `sampled->Revalidate`. Its result and report are carried back, and any exception is rethrown on the main thread.
- Asserts: the revalidation succeeded, its path is not `Fast`, and the version moved.
- `Recorder::Active()` is a process global (`Recorder.cpp:47`), so the other thread uses the same recorder while the main thread waits in `join`.

**Both modes.** Every assertion is "not fast" or "the version moved". With a hint, the store leaves a mark that the next walk stamps. Without one (Linux), the proof follows the collect epoch and the content changed. On this VM the test prints "the block has no write-watch hint", so the epoch rule ran.

### `agc_write_tracking`, `CheckUntrackedHintAcrossThreads` (inside `#ifdef _WIN32`)

The test runs just before `CheckSparseLeafBoundaries`, so that under R2 the first failure is this case rather than the cross-leaf one.

- **Setup:** a two-block arena range is committed, collected once, then `Unwatch`ed.
- **Main thread:** bumps and reads the hint `read`. A `std::thread` stores into the second block and is joined.
- **Same epoch, other thread:** a third `std::thread` calls `BumpCollectEpoch` and reads `other`. Requires `other > read`.
- **Shared stamps:** the main thread, still in its old epoch (memo hit), reads exactly `other`.
- **Next epoch:** after `BumpCollectEpoch`, the main thread reads `other` again.
- **Racing case:**
  - A writer thread stores in a loop until a stop flag is set, then stores once more after seeing the flag. That last store therefore comes after every read.
  - Meanwhile the main thread reads the hint across 50 epochs. Each read must be ≥ the one before.
  - After the writer stops, plus one more epoch, the hint must be greater than every value read before.

Intended target: case A. **Expectation: R1 does not fail case A, and no test in this commit fails it.**

**Where case A's store lands.** I logged the order of calls on Linux; it doesn't depend on hints.
- The walk compares the first surface (it reaches `EqualsCommittedUnsynced`) before the second surface's `FlushGpuWrites` fires the hook. The hook then stores into the first surface.
- Log order (`bf288-sanity-order`, the `BF288` lines):
  - `compare 7f0d01790000 equal-check`, the first surface;
  - `compare 7f0d017a0000 before flush`, the second surface;
  - `hook stores into 7f0d01790000`;
  - `compare 7f0d017a0000 equal-check`.
- So the first surface's hint is read before the store, whether before or after its compare. Its recorded stamp is older than the stamp the hook's walk writes, and the next check is not fast either way.

**Why no deterministic test can catch R1 today.**
- R1 only matters when a store lands between `EqualsCommittedUnsynced` and the hint read of the *same* surface.
- The only test hook in that path is the flush hook, and it runs before both.
- Catching R1 needs either a hook between the compare and the hint (product code, out of scope here) or a probabilistic race test.
- With hint-before-compare (the PR's code) that window is safe by construction: any mark set after the hint walk is still there for the next walk.

## Does the code contradict the reasoning?

No. Each point checks out at fdc70046f8:

1. **`UntrackedHint` walks the range's marks itself** (`GuestMemory.cpp` 2195–2224). `walkHints` calls `GuestArenaCollectWrites_nid_postfix(..., true)` and stamps each page's block with `stampHint` under the tracker lock. A walk that finds marks bumps the generation once.
2. **The only skip is the `thread_local` `threadHintMemo`,** matched on epoch, unwatch serial, mapping generation and range. `currentCollectEpoch` gives a thread that never bumped a fresh epoch per call, so a plain `std::thread` always walks.
3. **`compareUntracked` takes the hint before `EqualsCommittedUnsynced`** (`Texture.cpp` 2615 vs 2625). The proof's recorded stamp is that hint: `captureValidation` takes it from `HintedComparison`, which returns the stamp `compareUntracked` stored.
4. **The stamps are shared.** A walk on any thread stamps the tracker, and `newestHint` reads it, so a memoized thread still sees another thread's newer stamp. The device-free "shared stamps" step checks exactly that.

One correction to the task text: R1 does not fail case A (see Reds), because case A's store comes after the first surface's hint read whichever way the compare and the hint are ordered. That is about the test, not a correctness bug in the PR.
