# BF-040: reuse address-based dispatch builds (stacked on #6636)

## Summary

- **Address-based dispatch builds are now reused** under #6636's rules for draws, with one exception: a dispatch is not refused while an earlier dispatch of its build is in flight.
  - Each concurrent use takes its own fault and written-page record from a per-build spare pool.
  - Faults are reported by the dispatch that made them.
  - `APS5_NO_ADDRESS_DISPATCH_REUSE=1` turns this off.
- **Harness gains.** On BF-033's harness on lavapipe, the driver's time per address-based dispatch falls on every row. With one dispatch per submission:
  - 1 texture: 374 → 77 µs;
  - 16 textures: 519 → 76 µs;
  - 128 textures: 798 → 123 µs;
  - 2,000 textures: 5,032 → 699 µs.

  With 8 dispatches of one program per submission, 16 textures drops from 1,600 to 28 µs and 2,000 textures from 2,232 to 647 µs. The base builds on every dispatch; the branch builds once per run.
- **Two related changes:**
  - a written-page record overflow is survived rather than thrown (commit 1);
  - recorded GPU writes over a snapshot range are completed before the reuse proof, for draws and dispatches (commit 2).
- **Tests:** all six new cases are red on #6636's head and green on the branch.
- **`^agc`:**
  - reuse on: 608/608;
  - reuse off: 608/608;
  - #6636's head: 607/607.

  BF-033's 11 stalling tests pass with reuse on.
- **Recipes stay off** for address-based builds (debt entry updated).
- **Found on the way:** a pre-existing lavapipe crash. A compute shader whose vector global load faults through the BDA table crashes the process (§3).

## 2. The reuse rules as built

A dispatch build follows #6636's rules for draws, with one difference: a dispatch whose earlier dispatch is still in flight is **not** refused.

**When a build is reusable.** `noteReusable` marks an address-based (`usesBda`) compute build reusable when all of these hold:
- `APS5_NO_ADDRESS_DISPATCH_REUSE` is unset. This is a new switch beside #6636's `APS5_NO_ADDRESS_DRAW_REUSE`; each one turns off only its own kind.
- The build has no copied writes.
- It has no multisample sources and the loop guard is off.
- Every image-table element resolved to a texture.
- No texture is refreshed per use.
- Its data buffers fit the refresh limit.
- Every region outside the space has an import or image-mirror serial.

**What a hit proves.** It runs `Revalidate`'s address branch, the same as for a draw:
1. **Not reusable:** refused when an earlier use faulted (`NotReusable`).
2. **Pending writes completed (new, commit 2):** for every snapshot range that a recorded write overlaps, the recorder is synced through it. The comparison then sees the memory the earlier work leaves.
3. **Snapshots:** the snapshot list must repeat the build's, compared live for live regions and against the build's copies otherwise. Refused otherwise (`Snapshots`).
4. **Space:** the cached address space must resume. That fails when the space was replaced, or the device, registry generation or import epoch moved, or a sparse mirror could not be refreshed (`Space`). Resuming stamps the space's imports as recently used and brings writable and heap mirrors up to date, as a build does.
5. **Proof:** the build's image and buffer proof (`Proof`), then the space's imports (`Imports`). A throw anywhere in these is counted as `Threw`.

**What a use does.** The use takes the space for its batch (`BeginUse`, `SpaceHold`) and suspends it right after recording (`EndUse`). Between uses the build pins no guest allocation. A guest free therefore never waits for a cached build, and waits for an in-flight use only until its batch finishes.

**Fault and written-page record per use (commit 3).**
- The build's own fault buffer serves the first use in flight.
- Any concurrent use takes a spare from the build's pool: a 24.6 KiB fault buffer and a descriptor set. The set repeats the build's descriptor writes, with the spare buffer in the fault binding. The build's descriptors never change after the build (`Revalidate` refreshes image contents, not bindings), so a pooled set stays valid.
- The use's completion checks its own record. A fault is reported by the dispatch that made it; it makes the build non-reusable.
- Each use marks the pages that it wrote.
- The spare returns to the pool when the use ends: when its completion ran, or when its batch was dropped without running it. A throw while recording therefore cannot leave the own buffer marked busy.

**Overflow (commit 1).** A written-page record that overflows (more than 2,048 chunks of 32 pages, or a chunk without a free slot in 8 probes) no longer throws. The completion marks:
- the chunks the record holds;
- then every writable range of the build's page table.

That is a superset of what the GPU stored. This applies to every BDA build, reused or not.

**Counters.** Reuses and refusals go to #6636's `AddressReuse` counters. The `[rescache]` line now reads "address-based draws and dispatches". It is still printed from the draw profile, so a dispatch-only run (the harness) shows reuse on the `[rescache] N hits, M misses` line instead.

**Recipes stay off.** Dispatch recipes require a build without completion work (`!NeedsCompletion()`), and an address-based build always has some. A recipe's validation proves neither the space nor the snapshots. The debt entry says so.

### What is refused and why

| refusal | when | why |
|---|---|---|
| not built reusable | copied writes, multisample sources, loop guard, an unresolved table element, a per-use texture refresh, an oversized data buffer, a region without a serial | the reuse proof cannot cover these; unchanged from #6636 |
| `NotReusable` | an earlier use of the build faulted | its fault report and state are no longer trustworthy |
| `Snapshots` | a snapshot differs, including after a recorded GPU write over it completed | the program was specialized on other bytes |
| `Space` | space replaced, device, generation or epoch moved, or a mirror refresh failed | the page table maps something else |
| `Proof` / `Imports` / `Threw` | image/buffer proof failed, an import changed, or the proof threw | as for draws |
| (`InUse`) | draws only | a draw build has one record; a dispatch takes a spare instead |

A refused reuse costs one proof, plus at most a sync through a recorded write that overlaps a snapshot. The decoder's own validation syncs through such a write anyway. It never stalls on the build's previous use.

**A pre-existing lavapipe crash** that the test design had to avoid: a compute dispatch whose **vector** global load (`global_load_dword[x2]`) faults through the BDA table crashes lavapipe with SIGSEGV. The JIT'd shader reads through a null pointer (`vpbroadcastd (%rax)`, `rax=0`). This happens on #6636's head too, with reuse off, for:
- a faulting address taken from the SGPR base;
- a faulting address loaded from memory.

What does not crash:
- A pixel shader with the same instructions faults cleanly (`AddressDrawReuse`).
- A store into a read-only range faults cleanly in compute (reason 2).
- `GuardedNullPointer` faults only through scalar loads and MUBUF.

The fault cases therefore use stores into read-only blocks. The crash is not fixed here; it should be its own task.
