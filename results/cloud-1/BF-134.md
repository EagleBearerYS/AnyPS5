### A1 - the unproven plane rule

- Import (`prepareDepthSampling`, DepthSurface.cpp:162-178). A separate stencil plane (D32S8, depth-only HTILE) covered by a multisampled colour target that `aliasedStencil` does not accept is recorded as unproven instead of refused. "Not accepted" means: newest Drawn or Unknown, a format other than R8_UNORM/R8_UINT, another sample count, or another footprint.
  - `DepthSamplingState::unprovenStencil` keeps the alias as seen at import.
  - The guest plane is not read (`:195`), and the host stencil is initialised to `DB_STENCIL_CLEAR`, not from the alias.
  - The depth or HTILE alias case, and a stencil kept in HTILE, still refuse at import exactly as before.
- Proof (`CheckCurrent`, `:426` / `:449`). The proof is #9533's 90d652a1ed path: `NoteDepthMetadataFill` over the whole plane leaves `stencilClearGeneration` and `stencilClearValue` pending.
  - At the next `CheckCurrent`, the fill byte proves the plane without reading guest memory. `RecordClear(STENCIL)` clears the host stencil aspect to that byte, and `unprovenStencil` is reset.
  - If the colour target is still over the plane, it must confirm the fill: `aliasedStencil` must give the same byte, meaning an R8 target at the same sample count and footprint that absorbed that fill. Otherwise the fill is refused with the stencil alias text.
  - With no colour target left, the existing non-aliased fill proof applies unchanged (GPU fill note or complete tracked store).
- Before the proof, `CheckCurrent` skips the alias check for the unproven plane, so depth sampling and depth-only draws continue.
- Uses that refuse before the proof (`RequireStencilProven`, `:501`):
  - A sample of the stencil plane: any T# at `stencilAddress`, checked in `DepthSurfaceTexture` (`:2403`) before `CheckResource`.
  - A draw with a stencil test, which in Vulkan is also the only way to write stencil. This was cheap to see: `State::stencilTest` is passed through a new `DepthSurfaceView(..., bool stencilTested = false)` parameter (Draw.cpp:2320, :2901), and the refusal applies after the bind's `CheckCurrent`, for sampling-active owners.
  - Both refuse with BF-130's text `native multisample stencil plane aliases a multisampled colour target whose samples are only on the host`. Before that, a stderr line names the colour target's current state, or its import state if it has gone, e.g. `[gpu] native multisample unproven stencil plane 0x...+0x10000 aliases multisampled colour target 0x...+0x10000 (vk format 9, 4 samples), newest drawn`.
- Unchanged: a colour target with matching format and samples whose newest content is a Fill, CMASK FastClear or Clear is proven at import, as in BF-130 (case 0 below).

## Part B - `feat/agc-msaa-d32s8-stencil-view`, head a841bb578 (on 514643ab1)

- **CheckResource** (`:484-492`): a T# at `stencilAddress` is accepted when all of these hold:
  - format 5 (R8_UINT);
  - the surface's extent and samples;
  - 2D MSAA, the target's tile mode (kZ64KBX), and one slice and level;
  - the target's pipe/bank XOR;
  - no metadata (`dccAddress == 0`, not pipe-aligned, no alpha-on-MSB);
  - a separate plane (depth-only HTILE, stencil not in HTILE).

  Other stencil T#s refuse with the existing texts: identity or format mismatch, then array, mip or layout, then metadata or XOR mismatch. ITERATE_256 is not compared, because the decoder refuses it on non-Z formats; the PPSA03208 word 6 is 0.
- **View:** `Sampled` makes a `VK_IMAGE_ASPECT_STENCIL_BIT` view (2D, of a 2D MS image) with the T#'s component mapping. The view is of the host D32S8 image, or of the sample shadow when the device samples through it (lavapipe does). `Sampled` also requires `sampledImageStencilSampleCounts` to include the sample count (`:579`).
- **Binding finding:** an R8_UINT T# is `IrBufferFormat::Format8UInt`, which is `{sampled, uint32}` in RdnaDescriptorFormat.cpp:19, so `SampledTextureNumericClass` gives `Uint` (ResourceMaterializer.cpp:265).
  - The shader therefore declares a uint, multisampled, sampled `OpTypeImage` bound as `DescriptorKind::SampledImage`.
  - A stencil-aspect view of D32_SFLOAT_S8_UINT returns the stencil as an unsigned integer in R, so the view fits the binding.
  - The test reads it through a `uint` 2D MS image and checks R = stencil, G = 0 and A = 1 from the T#'s dst_sel.
  - Validation adds nothing for the stencil views or the two-aspect copy.
- **Shadow:** `refreshSampleShadow(drawn, stencilRead)` (`:1136-1149`). The first stencil read marks the shadow as carrying stencil and forces a refresh; from then on every refresh copies DEPTH|STENCIL in one `vkCmdCopyImage`. `CopySample`, a depth-only use, keeps the default.
- **Unproven plane:** a stencil T# on a plane left unproven by a colour target refuses with part A's text. `RequireStencilProven` runs before `CheckResource`, and `--aliased-stencil` covers it on this head.
- **Test** (`--stencil-view`, new ctest `agc_driver_native_depth_stencil_view`):
  - The fixture is a D32S8 native target with XOR 0x8c00 and a depth-only HTILE, cleared to depth 0 / stencil 0.
  - Stencil references are written per pixel and per sample with REPLACE, 0x10 + pixel*samples + sample, using a dynamic scissor and reference plus per-sample masked pipelines. Depth is offset + (sample+1)/16.
  - One compute dispatch reads both the D32 T# (float MS image) and the R8_UINT 2D MSAA T# at the stencil address (uint MS image), and checks every sample's depth bits, stencil value and mapping.
  - Rounds: the clear first, then two raster rounds (refs +0x80 and offset 1/8 in the second), so both aspects of the shadow are refreshed.
  - Then format, samples, width, tile mode, XOR and metadata variants each refuse with their text.
  - The guest plane is untouched.
  - The loop covers 2/4/8 samples: lavapipe runs 4, with 2 and 8 unavailable; the PC runs the 2-sample case.
  - Finding: lavapipe's 1×1 scissor on an MSAA target leaks samples 1-3 into the pixel to the left and/or above, and depth showed the same leak. The test draws pixels in reverse order so each pixel's own draw lands last. A correct driver is unaffected by the order.
