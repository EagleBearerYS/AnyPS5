# PM-049 (cloud-1): what keeps growing while builds keep refusing host imports

## Answer

- **Refusals keep nothing alive on main.**
  - I ran 14 dispatch and draw series of 8000 builds each, on both arms. Every category is equal at build 1000 and build 8000. RSS moves by at most +12 kB.
  - Those series reach 388,500 and 964,500 refusals.
  - Main does not remember a budget refusal: `importRunAt` counts it and returns null (GuestBufferMemory.cpp:1075-1086).
  - So the refusal count is rebuilds × refused ranges. Every address-space rebuild retries every leased range that is not imported (side8: 1000 rebuilds in 8000 builds, ~388 refusals each).
- **The one thing that grows in the repro is a sparse heap.**
  - A sparse heap is a reserved range registered whole while the guest commits pages on demand.
  - When its committed window moves upward, two things grow:
    1. **The live sparse heap mirror.** It is sized to the highest committed byte, measured from the reservation base, plus an eighth. It never shrinks.
    2. **The buffer pool's large tier.** It keeps every mirror allocation a regrowth supersedes until the tier's 512 MiB budget evicts it, and no later request can reuse one.
  - The guest's committed bytes stay constant in both series:
    - 64 MiB reservation with 2 MiB committed: RSS 143 → 677 MB over 6000 builds.
    - 256 MiB reservation with 4 MiB committed: RSS 145 → 949 MB over 9000 builds.
- **Fix for (2):** fork `fix/agc-refused-import-retention` @ 1c78ff4ec93e. A sparse mirror's buffer now frees its memory when released, instead of going back to the pool.
  - Red/green test: on main the pool holds 3 of 3 superseded mirrors; with the fix it holds 0.
  - With the fix the same series end at 268 MB and 467 MB, and the large tier stays at 0.
  - Growth (1) remains. It needs the mirror re-anchored at its first committed page. That is proposed below, not done.
- **Bug Finder addenda** (answered in [Bug Finder addenda](#bug-finder-addenda)):
  - **Half the import budget:** the memory held for the GPU does not fall; it only moves. Imports pin guest pages that already exist. Mirrors and stand-ins are extra host-visible copies, so a smaller budget adds process memory one for one: +8 MiB of mirrors per halving here.
  - **Descriptor pools:** the `[descriptors]` dedicated-pool figure is a creation count since launch, not live pools.
  - **#6457's refusal map:** it stays at 387-814 entries, about 0.2 MB, because it is bounded by distinct refused runs.
  - **Guest vs host:** the repro prints the guest's committed bytes beside the host categories. For the PC, a counter that walks the guest arena is proposed.
- **The arms are equivalent on Linux.**
  - `perf/agc-async-settle` b62a0572e7 is on neither remote. I re-checked before finishing: the fork has only `verify/perf/agc-async-settle-*` branches.
  - I used d528b4476b instead, the parent of the fork's `verify/perf/agc-async-settle-d528b4476b`.
  - Every line it adds to the import code is under `#ifdef _WIN32`, and `GuestMemory::Rewatch` is a no-op on Linux.
  - Every category matches between the arms, and RSS matches within run-to-run noise.

**Guest memory.**
- One 8 MiB-aligned mapping, memset at start. The heap part is write-watched.
  - Each sample prints `guest[committed …]`: 40.1 MiB (44.1 with the unwatched pieces), constant within a series.
  - In the sparse series it is that plus the committed window, also constant. A decommit does `madvise(MADV_DONTNEED)` before `PROT_NONE`, so decommitted guest pages leave RSS.

  - Import windows are main's default, 8 MiB (VulkanDevice.cpp:1320).
  - Each refusal is counted at its run's size, here the 8 MiB window, so the refused-MiB figure is ~128× the bytes of the refused ranges.

**Builds.**
- *Dispatches:* a 64-lane `global_store_dword` to one of 16 target pieces, on the address-based (BDA) path.
- *Draws:* a vertex shader with `global_load_dword` and `global_store_dword` through s[8:11], and a constant pixel shader, via `VulkanDevice::Draw`.
  - That is the same `Graphics::Draw` that the driver's pipelined draw queue (depth 8, DrawPipeline.cpp:28-37) commits to.
  - The queue itself is bounded at 8 items, so it is not exercised separately.
- **The store targets are in the imported window.** On main, an address-based store to a mirrored range stops the build by design.
  - The message is "stores through GPU-selected descriptors and FLAT/GLOBAL addresses reach only writable ranges imported in place, not ones served by a mirror or a copy".
  - That is why the draw-side8 series stops at its first build with a 4 MiB budget, where nothing is imported.
- Between builds: 4 KiB CPU memsets into 4 pieces. The shader's store is the GPU write.
- `WaitIdle` every 8 builds. Each sample is taken after a `WaitIdle`.

## What grows, what keeps it alive, why nothing reclaims it

File:line references are on main 5d9dcc42d.

### 1. The live sparse heap mirror

- **How it is made.**
  - A reserved range is never imported. Its pages are not all accessible, so `importRunAt` fails it, whatever the budget: GuestBufferMemory.cpp:1138-1141 on Linux, the MEM_COMMIT walk on Windows.
  - `acquireMirror` then makes a sparse mirror (:1846-1854). Its size is `sparseExtent` (:1689-1694): `used = pieces.back().second - base`, plus an eighth, rounded up to 1 MiB, capped at the reservation.
  - The mirror is zeroed beyond the committed pieces (:1899, :1903), so the whole extent is touched, holes included.
- **What keeps it alive:** `Mirrors().entries[range->address]` (:1913), for as long as the reservation stays registered.
- **What would reclaim it:**
  - `sweepMirrors` when the range expires (:1931);
  - `releaseImportedMirrors` (:1956), which never applies here because a sparse range is never imported.
- **Why it never shrinks.** `refreshSparseMirror` replaces the mirror only when a commit passes its end (:1773). Decommits below the end leave it as it is. So the mirror follows the commit high-water mark, not the committed bytes.
- **The fix this needs** (not done):
  - Anchor the mirror at its first committed page, and rebuild it when the committed span leaves it.
  - That changes `addressRange`/`servedEnd` (:4082-4093) and the descriptor views (`region.mirror->base` as the view base, :4060-4061).
  - Only the Windows sparse-heap tests cover those (`sparseHeapMirrorTests`, tests/BdaResources.cpp:1601-1720), so this is proposed here, not done.

### 2. The buffer pool's large tier, holding superseded sparse mirrors

- **Where they come from.**
  - Each regrowth makes a new, larger mirror (:1882) and replaces the entry (:1911-1913).
  - The old mirror lives on until the recorded work that bound it finishes (:1910). Then its `Buffer` goes back to the pool (Resources.cpp:113-116, `cache->Put`).
- **What keeps them alive.**
  - `BufferPool::Put` retains any allocation that fits the tier budget (BufferPool.cpp:319-332).
  - The large tier (≥ 1 MiB, budget 512 MiB, BufferPool.hpp:145) holds exact sizes: `Capacity` returns the size itself (BufferPool.cpp:212), and `Take` looks up that capacity only (:244-246).
  - No later request asks for a superseded extent.
- **What would reclaim them:**
  - LRU eviction when the 512 MiB budget or the slot cap is reached;
  - `trim()`, which runs only after a failed `vkAllocateMemory` (BufferPool.cpp:60-61).
- **Why that doesn't happen sooner:** nothing else evicts.
  - These allocations are host-visible (the `Buffer` default, `HOST_VISIBLE | HOST_COHERENT`). So on the PC they are system memory (GPU shared) that nothing reads, up to 512 MiB per pool.
  - On the PC, the Bug Finder's `[bufferpool]` large tier reads 490-503 MiB, at the cap. That is consistent with the tier being full of dead allocations, but it is not proof that they are superseded mirrors. A per-usage breakdown of the tier would tell (see the last section).

### What stays bounded, and why

- **Refusals:** main makes no allocation per refusal (:1075-1086).
- **Heap mirrors:** one per refused range. A mirror is replaced only when its range changes, swept on expiry, and released on import.
- **Stand-in copies:** made per build (:3527, :3916), kept by their batch, then pooled under the tier budgets. The small tier holds 536 slots / 32.9 MiB in the unwatched series, flat.
- **Snapshot copies:** a cache of 16 MiB and 1024 entries (:1367-1368).
- **Address spaces:** there is one current space; old ones die with their builds. Each space caches at most 64 tables (:4236).
- **BDA tables:** 8 weak entries (Graphics/src/BdaResources.cpp).
- **Draw resources:** released when the batch completes.
  - Copied-writer lists are drained at completion (Draw.cpp:1521-1530, VulkanDevice.cpp:4405-4415).
  - Address-based builds are never cached: `noteReusable` returns early on `usesBda` (ShaderResources.cpp:2081).
- **Import table:** at most the budget.
  - `failed` and `failedJoins` are keyed by base.
  - `parked` fills only on a device change (`refreshImports`, :1225-1229).

## Bug Finder addenda

### Guest arena commits vs host allocations

- **In the repro:** every sample prints the guest's committed bytes (`guest[committed …]`) beside RSS and the host categories.
  - The guest side is constant in every series, the sparse ones included (42.1 / 44.1 MiB), so all growth in the tables is host-side.
  - **What RSS counts here:** lavapipe's device memory shows in RSS but not in RssAnon. As mirrors grow, RSS grows by their bytes while RssAnon stays flat (base series, 8 → 4 MiB budget: RSS +9.1 MB, RssAnon +0.2 MB). So RSS is the host-side figure on this device.
- **A counter for the PC.** Every 10 s, walk the guest arena with `VirtualQuery`:
  - get the range from `GuestArena::GuestArenaRange_nid_postfix(&base, &bytes)` (GuestArena.cpp:324);
  - sum `RegionSize` of `MEM_COMMIT` regions, split by `Type` (`MEM_PRIVATE`, `MEM_MAPPED`);
  - print the result next to `GetProcessMemoryInfo`'s `PrivateUsage` (`PROCESS_MEMORY_COUNTERS_EX`).
  - Private bytes minus the arena's private commit is the host side. If the +140 MB/min is the guest committing its own heap, the arena line rises with it.
  - It costs one `VirtualQuery` per region every 10 s. I can write it as a profile line (`[guestmem] arena committed …`) if wanted. It is not on the branch, which is for the fix.

- **dma-buf is 0 in every series:** this container has no `/dev/udmabuf` ("shared direct memory is copied instead of imported").
- **Reads vs lease.**
  - A build reads 1 range (dispatch: the store target) or 2 (draw: source and target). Both are inside the imported window.
  - The address space it builds covers all ~513 leased ranges: 1-2 imports and 256-512 mirrors.
  - Every build checks every heap mirror (checks per build = mirror count). It copies only the blocks the CPU wrote: 2-4 per build, the CPU memsets that land in mirrored pieces.
  - Imports are refreshed only on a rebuild, which retries every refused range once (the refusal counts).
- **Half the budget only moves the bytes held for the GPU.**
  - Imports plus host-visible copies total 32 MiB at 16, 8 and 4 MiB.
  - Each halving moves 8 MiB from imports, which pin guest pages that exist anyway, to mirrors, which are new copies. So process memory rises by the moved amount: RSS +8.4 MB (16 → 8 MiB) and +9.2 MB (8 → 4 MiB), from the settle arm's base rows.
  - On the PC, a lower `APS5_HOST_IMPORT_MIB` would likewise turn pinned guest pages into extra private copies, not free anything.
- **Two exceptions, both artifacts:**
  - **unwatched at 4 MiB.** No 8 MiB heap window fits the budget, so the budget goes to the 64 unwatched pieces. They do not fill their window, so each is imported alone (GuestBufferMemory.cpp:845). ## Fix

- **Branch:** fork `fix/agc-refused-import-retention` @ 1c78ff4ec93e, one commit on upstream main 5d9dcc42d.
  - Commit: `fix(agc): free superseded sparse heap mirrors instead of pooling them`, by Yunus Shaikh as author and committer, unsigned, no trailers.
  - Files: `Graphics/include/Resources.hpp`, `Graphics/src/Resources.cpp`, `Graphics/src/GuestBufferMemory.cpp`, `tests/BdaResources.cpp`. +80 / −1 lines, no comments.
- **The change:**
  - `Buffer::Unpool()` sets a new `pooled` flag to false. `Buffer::release()` returns a buffer to the pool only while it is still pooled; otherwise it frees the memory as an unpooled buffer does.
  - `acquireMirror` calls `Unpool()` on every sparse mirror's buffer right after making it (GuestBufferMemory.cpp:1890 on the branch). Every release path then frees it: superseded by a regrowth, swept with its range, or dropped on a device change.
  - Non-sparse heap mirrors and stand-in copies still pool as before; a same-size request can reuse those.
- **The test:** `sparseHeapMirrorRegrowthTests` in `tests/BdaResources.cpp`, run by `agc_driver_graphics`.
  - It is Linux-only and needs the write watch; without it the test returns early.
  - It reserves 16 MiB PROT_NONE and write-watches it. It commits pages with `mprotect` + `GuestAllocationsInvalidate` and registers the reservation whole.
  - It grows the mirror 1 → 2 → 3 → 4 MiB, committing the page past its end each time. The suite runs with `APS5_HEAP_MIRROR_MIB=4`.
  - It first drains any 1-8 MiB storage buffers the pool already holds, and puts them back at the end.
  - After each regrowth it asks the pool (`Take`) for the superseded extent.
  - It checks that the heap-mirror count returns to where it started and that no superseded extent was retained.
  - **Red** (main 5d9dcc42d with only the test applied, 3 runs): `AGC graphics: the buffer pool holds 3 of the 3 sparse heap mirrors its regrowth superseded`
  - **Green** (the branch, 3 runs plus the ×10 below): `Graphics validation tests passed`
  - The suite's mock-device leak check (`mock.live == 0`) passes too. A first version unpooled only the superseded mirrors, which left the last, swept mirror in the pool and tripped that check. So now every sparse mirror is unpooled.

## Scene conditions the repro does not cover (for the next run)

- **Windows-only code:**

## Side findings

- **A BDA load from an unregistered guest address crashes lavapipe.**
  - It is a null dereference in JIT code: `vpbroadcastd (%rax)` with rax = 0.
  - It happens on a dispatch or a draw. Repro: `PM049_SOURCE_PIECE=520 PM049_SPARE=128`, with or without `PM049_DRAW=1`. The same load from a registered, mirrored piece works.
  - The BDA ABI defines `FaultReason::Unmapped`, and the byte-read path branches around its load when the translated address is 0 (SpirvBdaRead.cpp:47-63). The dword load here reached address 0, so its path is not guarded the same way; I did not trace it further. On a real GPU that is a read of address 0.
  - Out of scope here; worth its own task.
- **Every guest heap commit or decommit bumps the registry generation** (`GuestAllocationsInvalidate`).
  - That forces a full address-space rebuild, which retries and counts every refused range.
  - So refusal counts track guest heap activity, not draws. In sparse256, 1.73 M refusals in 9000 builds come from 4500 window steps.

void* MapAligned(std::size_t bytes, std::size_t alignment) {
    void* raw = mmap(nullptr, bytes + alignment, PROT_READ | PROT_WRITE, MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    Require(raw != MAP_FAILED, "cannot map the heap");
    const auto begin = reinterpret_cast<std::uintptr_t>(raw);
    const auto aligned = (begin + alignment - 1) & ~(static_cast<std::uintptr_t>(alignment) - 1);
    if (aligned != begin) munmap(raw, aligned - begin);
    if (aligned + bytes != begin + bytes + alignment) munmap(reinterpret_cast<void*>(aligned + bytes), begin + alignment - aligned);
    return reinterpret_cast<void*>(aligned);
}

            if (plain != nullptr) std::memset(plain + (build % unwatched) * Piece, static_cast<int>(build & 0xffu), 4096);
            const auto target = build % targets;
            if (draws) {
                const auto vertexPush = static_cast<std::uint32_t>(results[target].pushConstants.size());
                const std::array<AgcDriver::Graphics::CompiledShader, 2> shaders{{{ShaderStage::Vertex, &results[target], 0u}, {ShaderStage::Fragment, &pixels[target], PixelPushOffset(vertexPush, device->Target())}}};
                device->Draw(state, AgcDriver::Pm4::DrawParameters{0, 3, 0, 1, 0, false, 0, 0}, shaders);
            } else {
                device->Dispatch(results[target], 1, 1, 1, {}, reinterpret_cast<std::uintptr_t>(Code().data()));
            }
            if (build % frame == 0) device->WaitIdle();
            if (sideEvery != 0 && build % sideEvery == 0) {
                if (sideRegistered) Unregister(side);
                else GuestAllocations::Mutation().Add(side, Piece, true, false, true);
                sideRegistered = !sideRegistered;
            }
            if (replaceEvery != 0 && build % replaceEvery == 0 && streamed != 0) {
                auto* piece = replaceImported ? heap + ((replaced++ * 7 + 3) % imported) * Piece : streamPiece(replaced++ % streamed);
                Unregister(piece);
                Register(piece);
            }
            if (streamEvery != 0 && build % streamEvery == 0 && spare != 0) {
                Unregister(streamPiece(0));
                Register(streamPiece(streamed));
                windowBegin = (windowBegin + 1) % streamArea;
            }
            if (sparse != nullptr && sparseEvery != 0 && build % sparseEvery == 0) {
                if (sparseTop + Piece > sparseBytes) {
                    protect(sparseBottom, sparseTop, false);
                    sparseBottom = 0;
                    sparseTop = std::min(sparseWindow, sparseBytes);
                    protect(0, sparseTop, true);
                } else {
                    protect(sparseTop, sparseTop + Piece, true);
                    sparseTop += Piece;
                    if (sparseTop - sparseBottom > sparseWindow) {
                        protect(sparseBottom, sparseBottom + Piece, false);
                        sparseBottom += Piece;
                    }
                }
            }
            if (build % sample == 0) {
                device->WaitIdle();
                const auto seconds = std::chrono::duration<double>(std::chrono::steady_clock::now() - start).count();
                const double guestCommitted = ((8u << 20u) + (pieces + spare + unwatched + 1) * Piece + (sparseTop - sparseBottom)) / 1048576.0;
                std::printf("PM049 build=%llu t=%.1fs sparse=[%zu,%zu)KiB guest[committed %.1fMiB reads %d] %s %s\n", static_cast<unsigned long long>(build), seconds, sparseBottom >> 10u, sparseTop >> 10u, guestCommitted, draws ? 2 : 1, ProcessMemory().c_str(), AgcDriver::Graphics::Pm049Account().c_str());
                std::fflush(stdout);
            }
        }
        device->WaitIdle();
        const auto lastTarget = targetPieces[builds % targets];
        const auto* stored = reinterpret_cast<const std::uint32_t*>(heap + lastTarget * Piece);
        std::printf("PM049 done: piece %zu lane 5 holds %u\n", lastTarget, stored[5]);
        return 0;
    } catch (const std::exception& error) {
        std::cerr << error.what() << '\n';
        return 1;
    }
}

## Appendix B: the counters (temporary, not pushed)

`Pm049Account()` prints one line per sample. Each field reads existing state under its own mutex, except the atomics named below.

- **`imports[…]`** (`Imports()`):
  - live imports split by `entry.dmaBuf` (host-pointer vs dma-buf), with bytes;
  - `parked` count and bytes;
  - `failed` entries and their range references;
  - `failedJoins`;
  - refusals: two atomics bumped beside `importRunAt`'s own static counters.
- **`refusalMap[…] failedBlocks[…]`** (#6457 arm only): `state.refusals.size()` and the summed `ranges.size()` of its entries; the same for `failedBlocks`.
- **`mirrors[…]`** (`Mirrors()`): entries, heap and sparse counts, bytes (all and sparse), `shadow` bytes, `failed`.
- **`mirrorWork[…]`:** `MirrorCounters()` (rebuilds, heap refills, heap checks, blocks copied, sweeps).
- **`snapshotCopies[…]`:** `SnapshotCopyCache()` entries and bytes.
- **`space[…]`:** the current address space's lease size and its imported/mirrored/copied region counts, its table count, and the cache hits and rebuild causes.
- **`buffers[…]`:** four atomics in `Resources.cpp`. They count live `Buffer`s and their allocation bytes, split by the requested `HOST_VISIBLE` bit. They are bumped where `Buffer`'s constructor sets `ready` and in its destructor.
- **`shadows[…]`:** `UnitShadow.cpp`'s slab count and bytes.
- **`descriptorPools[chain dedicated]`:** two atomics in `ShaderResources.cpp`.
  - Incremented beside `++stats.pools` and `++stats.dedicatedPools`.
  - Decremented where `Free` destroys a dedicated pool and in `~DescriptorCache`.
- **`pool[…]`:** per `BufferPool` (a registry of live pools), each tier's slot count and `retainedBytes`, plus the slab blocks' bytes and used slots.
- **Process side, in the repro:** `VmRSS`, `RssAnon` and `mallinfo2()`.
