## 2. The composition

### What the merge does

- **Recording:** `Driver::tagVariantRuns` (`Execution/src/Driver/Draw/DrawRelocate.cpp:59`) copies each capture region's words into `variant.words`. It records the region's shared words at `:93`: `AppendSharedWords(variant.shared, index, offset, region.bytes, supplied)`, where `index` is the **capture-region** index.
  - It then splits the region into runs wherever the user-data base a word was read through changes (`:98-107`, one `runs`/`runBases` entry per stretch).
- **The dispatch path** (`Execution/src/Driver/Dispatch/DispatchInsert.cpp:41`) records `fresh->runs.size() - 1u`, the **run** index. There runs and regions are 1:1, so the two are the same.
- **Every consumer counts runs:**
  - Draw and dispatch hits validate with `regions` built by `Driver::appendEntryRegions` (`Execution/src/Driver/Dispatch/VariantValidation.cpp:12-21`), one region per run. Draw callers: `Execution/src/Driver/Draw/DrawLookup.cpp:118`, `:130`, `:218`.
  - `validateVariant` (`VariantValidation.cpp:103`) calls `VouchSharedRegions(variant.shared, regions.size(), …)`. That copies `SharedWords::region/regions` into `VouchedRegions::begin/end` (`Execution/src/ShaderMemory.cpp:766`).
  - Those indices then:
    - replace runs in `checked`, used for the pending-image and label overlap checks (`VariantValidation.cpp:110-118`);
    - skip regions in `syncPendingRuns` (`:35-38`), so no pending-write sync;
    - skip regions in `validateCaptured` (`Execution/src/Driver/Memory/CaptureValidation.cpp:70-74`), so no content compare. All three are positions in `regions`, that is, runs.

### Q1: are a split variant's shared entries right for `SameCapturedWords` and the other readers of `region`/`regions`?

- **`SameCapturedWords`** (`ShaderMemory.cpp:712`, the draw cache's identity compare at `Execution/src/Driver/Draw/DrawCache.cpp:143`): **yes, it was always right.**
  - It matches entries by `first`/`count`/`offset`/block, word positions in `variant.words`, and never reads `region`/`regions`.
  - `variant.words` keeps the per-region layout whether or not the runs split.
  - The insert compare first requires `kept->runs == fresh->runs`, so both sides have the same layout.
- **`region`/`regions` (the vouch): no, before the fix.**
  - The guard `variant.runs.size() == regions.size()` (`VariantValidation.cpp:103`) is the safety the task describes. It is a tautology on every path that reaches it, because `regions` comes from `appendEntryRegions`.
  - So a split variant **is** vouched, with region-indexed entries read as run indices.
- **Example:**
  - Capture regions: R0, a user-data region read through two relocatable bases, split into runs r0…r3; then R1, a table region inside a supplied block, which is run r4.
  - `shared` = `{region 1, regions 1}`, so the vouch covers run r1, part of R0 and outside the table.
  - r1 then gets no pending-write sync, no captured-word compare, and the block's range stands in for it in the pending-image and label checks.
  - Meanwhile r4, the actual table run, is compared in full: wasted work, but harmless.
- **Effect:** a draw-cache hit can reuse a variant after the guest words of r1 changed. Only the table block's write stamp is checked, and it says nothing about r1.
- **Preconditions:**
  - draw relocation on (the default);
  - a stage eligible for it (`DrawCapture.cpp:165`: no decode reads, no vertex resources);
  - a relocatable user-data base whose reads split a capture region;
  - a supplied block (a shared image table) in a later region.
- **A sub-word region:** with relocation on, a region shorter than a word would emit no run (`DrawRelocate.cpp:98-107`, the loop never runs) and shift the indices the same way. Today's captures can't produce one: `ShaderMemory::collect` (`ShaderMemory.cpp:622-674`) emits whole words, as page word runs and supplied runs cut at page edges. The fix covers that case too.

### Q2: is a relocated hit safe with shared words that point into a table's supplied block?

**Yes.** `Driver::relocateDrawEntry` builds each relocated variant as a new `DispatchVariant` (`DrawRelocate.cpp:216-228`). It copies `runs`, `runBases`, `relocatableWords`, `words`, `forgetSerial`, `compiled`, `shader`, `dataPositions`, `dataSlots`, `flatBinding`, `pushOffset` and `vertexInfo`, but **not `shared`**.
- A relocated hit therefore has no vouched ranges. Its moved runs are synced and compared word for word at the new addresses.
- That omission is what keeps it safe. Copying `shared` would vouch the donor's block range (`block->low/high`, the old guest addresses) in place of the moved runs.
- Stages that didn't move keep the donor's variants unchanged (`:205-207`), with their own unmoved runs.
- The fix below doesn't touch this path.

### The fix

**Branch:** fork `followup/6454-relocation-shared-words` = **e448df1ea** (`fix(agc): record a relocatable draw variant's shared words by run`), one commit on 19907d6ed4. Fix and test are in the same commit.

**Fix** (`DrawRelocate.cpp`, `tagVariantRuns`): the per-region `AppendSharedWords(…, index, …)` call moves into the two places that emit a run.
- On the unsplit path it records `variant.runs.size()`, the run's index, with the region's bytes.
- On the split path it records each stretch's index with its own `region.bytes.subspan(start…, word − start)` words.
- This matches `DispatchInsert.cpp:41` and what every consumer expects.
- An unsplit variant records exactly what it did before.
- Contiguous runs inside one block merge back into the same `first`/`count`/`offset` entry (`AppendSharedWords`' join). So `SameCapturedWords`, and through it the draw cache's identity compare, sees the same entries as before.
- To make the test possible, `tagVariantRuns`' declaration moves to `Driver`'s public members, beside `ClassifyIndirectDraw`, which `tests/execution/DrawOffsetIndices.cpp` already calls the same way.

**Test:** `SplitRunsNameTheirSharedWords` in `tests/execution/DrawCacheRelocation.cpp`. It is CPU-only and runs before the test opens its device; its CMake target gains the recompiler's include directories, as `agc_driver_image_table_cache_bounds_tests` has.
- Region R0 holds 4 data words read through user-data words 0 and 1 (`asBase = 0b11`, reads at word 0 and word 2). Region R1 holds 4 words that lie in a supplied `SrtGuestWords` block.
- `tagVariantRuns` splits R0 into 4 runs, so R1 is run 4.
- The test requires the one shared entry to name run 4, whose guest address is the table's, at the word offset that run starts at.
