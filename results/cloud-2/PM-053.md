## 1. R1: the fix

`passDepthLocations(const Context&, const State&, const Pipeline&)` is in Draw.cpp's anonymous namespace, at `:1893`.
- It returns nothing unless the draw has a multisampled depth target, custom sample locations, and a pipeline that enables them.
- Otherwise it returns `DepthSurfaceSampleLocations` for the depth target, with the pipeline's `HostSampleLocationGrid()` and `SampleLocations(state)`.
- That is `Draw()`'s block from e030401916 `:2274-2279`, unchanged.

**Callers:**
- **`Draw()`** at `:2282`, with `pipelineState`, as before. Its result still feeds both consumers: the lean path's `record.depthLocations`, which `recordDraw` records in the opening draw's afterPass (`:1846-1860`), and the non-lean path's transition (`:2455-2459`).
- **`DrawWithRecipe()`** at `:2702`, with the replay's `state` and the recipe's pipeline. It sets `record.depthLocations` before `recordDraw`.

**The lean path and the non-lean block don't compute the locations.** They only consume `depthLocations` (record it, count two barriers, keep the surface), so there was nothing else to move into the helper.

**Why the helper is right for a recipe** (and so the fallback, `&& !depthLocations` in the gate at `:2311`, wasn't needed):
- **The pipeline is the same one.** `DrawWithRecipe` replays with `recipe.pipeline`, the pipeline the recorded draw built. Its key holds `customSampleLocations` and the locations (`pipelineKey`, `Pipeline.cpp:848-852`), so `SampleLocationsEnabled()` and `HostSampleLocationGrid()` are what `Draw()` read.
- **The locations are the same.** A recipe only serves a draw-cache hit on the same registers. The driver looks it up under the draw's register key, `findDrawRecipe(drawKey, ...)` (`Execution/src/Driver/Draw/Draw.cpp:509-516`), and the sample location registers decode into the state's `sampleLocations`. The recipe's render pass key also mixes in the locations (`Graphics/src/Draw.cpp:55-59`).
- **The depth target is resident.** `DrawWithRecipe` already calls `DepthSurfaceView` for `recipe.hasDepth` (`:2652-2657`) and misses unless it returns the recipe's view. `DepthSurfaceSampleLocations` takes the same two locks (GpuMutex, then the surfaces mutex), in the same order, so the replay adds no new lock order.
- **`state` vs `pipelineState`:** `maskedState` and the proxy masking change only write masks and proxy formats, never the depth target or the sample locations. So `SampleLocations(state)` on the replay equals `SampleLocations(pipelineState)` on the recorded draw.

**Cost:** one more surface lookup per replayed draw, only for multisampled depth at custom sample locations. Every other replay returns at the helper's first line.

## 2. R1: the GPU test

`agc_driver_sample_order_recipe_depth_locations` runs `agc_driver_sample_order_tests --recipe-depth-locations` (`tests/execution/SampleOrder.cpp:1245`, registered at `CMakeLists.txt:1573-1577`). It uses the grid reference's properties: TIMEOUT 30, `ANYPS5_NO_SHADER_CACHE=1`, SKIP_RETURN_CODE 77, and the libc PATH on Windows.

**What it does:**
1. **Skips (77)** without sampleable 2x D32F depth, without custom sample locations at 2 samples (`sampleLocationSampleCounts`, `SampleLocationsCompatibleDepth`), or with `APS5_NO_DRAW_RECIPE`.
2. **Uses a uniform custom 2x pattern:** pixel (0,0)'s Village locations, `0x04, 0x0c`, in every pixel.
   - It is uniform so the pipeline never reorders. On a device without the 2x2 grid, the Village checkerboard would reorder and be refused a recipe.
   - It is custom, so `Draw()` names the locations.
3. **Records:** a full-screen clear to 0.9375 (`Draw`), then the grid reference's two sloped triangles with depth writes (`Draw` with `recipeOut`). It requires a recipe.
   - The triangles' vertices are copied into a guest block. From host heap memory the draw's resources aren't reusable, and no recipe is built: the scratch run showed `reusable=0`, then "the recorded draw built no recipe".
4. **Reads every sample** after the pass ends (`Settle`, `ReadTarget`), then clears again and checks that every sample holds the clear value.
5. **Replays** the triangles through `DrawWithRecipe` as the first draw of a new pass (the `Settle` before it ends the clear's pass). It requires a recipe hit, then ends the pass and reads again.
6. **Places each sloped sample** of both reads with `LocateDepth`, which now takes the pattern (Village's by default): at the guest's location, or at the standard 2x location.
   - If even the recorded draw's samples aren't all at the guest's locations, it skips, as the grid reference does. That device reads such depth back elsewhere despite the transition.
   - Otherwise it requires the replay to match the recorded read bit for bit, and prints the first four differences.

**On lavapipe it skips:** "skipped, the device has no sampleable 2x depth targets". Lavapipe has 1x and 4x depth only, and no VK_EXT_sample_locations.

## 3. Linux red/green: not possible

**No Linux test can run the fixed code.**
- `depthLocations` is set only when the pipeline enables sample locations. That needs VK_EXT_sample_locations at the draw's sample count and a SAMPLE_LOCATIONS_COMPATIBLE depth format: `Pipeline.cpp:121-123` requires both for custom locations.
- Lavapipe (Mesa 25.2.8) reports `VK_EXT_sample_locations no; counts 0x0`.
- Faking the context's counts would hand lavapipe structures and an image flag from an extension it never enabled, which is invalid usage.
- `RecordedDraw` and `passDepthLocations` are internal to Draw.cpp, and the mock-context `Draw()` tests in `tests/Graphics.cpp` stop before recording. So no mock can see a replay's `RecordedDraw`.

**What was run instead: a scratch-only harness check.** A patched copy of the test ran at 4x with the standard locations, without the custom-locations skip and without `LocateDepth`. It was built, run three times, and the file restored. It is not committed. The point was that the PC run can't fail for harness reasons:
- **First version:** `AGC graphics: the recorded draw built no recipe`, exit 1, three of three. A temporary print of the recipe gate showed `cacheable=1 ... reusable=0`: vertices in host heap memory. That is why the test copies them into a guest block.
- **After the guest block:** `reusable=1` on the recorded draw, then
  - `dev: 6005 of 8192 samples below the clear depth`
  - `... the recipe's replay differs from the recorded draw in 0 of 8192 samples`
  - exit 0, with the recipe hit required.
- **Why it isn't a red/green:** at standard locations `depthLocations` is empty with or without the fix.
