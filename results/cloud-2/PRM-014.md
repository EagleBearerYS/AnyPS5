## 1. What is counted, and where

All counts are cumulative relaxed atomics in `GuestBufferMemory.cpp`, in the style of `AddressSpaceCounters`. They are read through `AddressReuseCounters()` (`GuestBufferMemory.hpp:184-199`). They count whether or not the profile is on; only the proof time needs `APS5_PROFILE_DRAW`.

| Count | Where it is counted | What it means |
|---|---|---|
| proofs | `ShaderResources::Revalidate`, address-based path entry (`ShaderResources.cpp:2820`) | cache hits that reach the address-based proof |
| reused | `resolveDrawResources`, the hit (`Draw.cpp:1324`) | the proof passed and the draw took the cached build |
| in use | `resolveDrawResources`, before any proof (`Draw.cpp:1308`), and `Revalidate`'s own `InUse()` | the build's previous draw has not completed |
| not reusable | `Revalidate`, `!reusable` | the build was never reusable, or its draw faulted (`CompleteUse` clears it) |
| snapshots | `Revalidate`, `!SameSnapshots` | the draw's snapshots differ from the build's |
| space | `Revalidate`, `!ResumeSpace`, split by `ResumeSpace` itself (`GuestBufferMemory.cpp:4663-4686`) | the space did not resume, by reason (below) |
| images or buffers | `Revalidate`, `proveBuild` failed for another reason than imports | the image or buffer proof failed |
| imports | `proveBuild` failing with `ProofFailure::Imports`, or `!SpaceImportsCurrent()` | the imports changed |
| moved buffers | `resolveDrawResources`, the proof passed but `MovedReadOnlyBuffers` refused (`Draw.cpp:1326`) | read-only buffers moved, which an address-based build cannot rebind |
| ms in refused proofs | each refusal above that ran a proof (`APS5_PROFILE_DRAW` only: two clock reads per address-based proof) | what the refusals cost before their rebuild |

**The space reasons:**
- **state:** the build is not resumable, for example not uploaded or still holding a lease.
- **replaced:** no current space, or another one.
- **device**, **generation**, **epoch:** the `SpaceMiss` reasons.
- **mirrors:** a sparse mirror that could not be refreshed.

**Two refusals the task's list did not name:**
- **in use, before any proof.** The draw path already refuses an in-use build before calling `Revalidate` (`!cached->InUse()`), and until now counted it nowhere. It is the common case for back-to-back draws.
- **moved buffers:** a passed proof that the hit then refuses.

**Import refusals, in the same window** (`importRunAt`, `GuestBufferMemory.cpp:1096` and `:1113`):
- **budget:** the budget refused the import even with eviction. Held imports are not evictable.
- **held import:** the import would replace an import a build holds (`pointerHeld`).
- Each is also counted when a reused draw held its space at that moment. A reused draw's hold runs from `BeginUse` to `CompleteUse`, the span in which its batch keeps the space. `ResumeSpace` restamps the space's imports, so they stay `pointerHeld` until the next build raises the floor.

**Pin-contention waits:**
- The `[address-sync] leases:` line already prints them, from `CountLeaseOutcome` in `GuestBufferMemory.cpp`, every 10 s. But they are cumulative and on that line's own timer (`VulkanDevice.cpp` prints the separate dispatch-sync line).
- So the new line prints the change in `LeaseCounters().contentionWaits` and `contentionMs` over its own window. That lines them up with the reuse counts without repeating the other line.

## 2. The profile line

- **Placement:** printed by `reportDraw` (`Draw.cpp:569`) right after `[rescache] draws:`, over the same 10 s window.
- **When:** only when the window had an address-based proof or an in-use refusal. Titles without address-based draws see no new line.
- **Tag:** it uses the existing `[rescache]` tag. The test already prints its own `[address-reuse]` summary lines.
- **Cost:** with the profile off it prints nothing and costs only the counters.

**Example from the test**, with `APS5_PROFILE_DRAW=1 agc_driver_address_draw_reuse_tests 512 8000`:
- The test itself reports `each draw waited for: 8000 draws, 0 builds, 8000 reuses` and `back to back: 8000 draws, 7999 builds, 1 reuses`.
- The first 10 s window ended at the scenario after those two loops:
```
[rescache] draws: 8002 hits, 8000 misses, 0 invalidated, 0 uncacheable; validation memo 16001 hits / 1 misses (which key words the misses differ in: the miss churn line)
[rescache] address-based draws: 8002 proofs, 8002 reused; refused: in use 7999, not reusable 0, snapshots 0, space 0 (state 0, replaced 0, device 0, generation 0, epoch 0, mirrors 0), images or buffers 0, imports 0, moved buffers 0; 0.0 ms in refused proofs; host import refusals: budget 0 (0 while a reused draw held its space), held import 0 (0); pin-contention waits 0 (0.0 ms)
```
- **Reading it:**
  - 8000 waited reuses, plus the first back-to-back draw, plus the next scenario's first draw, make 8002.
  - The other 7999 back-to-back draws found the build in use, refused it without a proof, and built anew. The `[rescache]` line counts those as 8000 misses, the first build included.
- **A longer run** (60000 waited draws) printed three windows of about 9000 proofs and reuses each, with no refusals.

## 3. Import refusals by requester: not available on this base

- The task asks for refusals split by `ImportRequester`. That enum and its per-requester counts (`HostImportRequesterCounts`) come from #6457's branch (`fork/review/6457`, e.g. a24aafb75), which is in neither ec17620356 nor bae2cd48ec.
- At ec17620356 the only refusal count is the function-local `refused` in the `[gpu] host import budget` message. It is not per requester, prints at most every 10 s, and only when a refusal happens.
- So the new line counts budget and held-import refusals in total, and those that came while a reused draw held its space. If #6457 lands, its requester counts could sit beside these in the same line.

## 4. The test (`tests/execution/AddressDrawReuse.cpp`)

**What changed:**
- **The program snapshot:** the scene's pixel snapshot reads its bytes from a mutable copy of the program, so the test can rewrite them. The bytes start equal, so nothing else changes.
- **New `ReuseCounters` scenario** (line 373), after `Synthetic`:
  - Four waited draws must count 4 proofs, 4 reuses and no refusal.
  - Two draws with no wait between them must count one reuse and one refusal "in use". This is deterministic: the first draw's completion cannot run before the second draw's lookup. The test's back-to-back loop builds 63 of 64.
  - Then the guest rewrites the pixel program's bytes, and the snapshot changes. The next draw must count exactly one refusal, under "snapshots", and no reuse. The program is then restored.
- **In the existing `GuestWrite` scenario:** the draw after a guest write into memory it reads in place must count one reuse and no refusal. That scenario already required no rebuild; the counts now show why.
- **In the existing `Fault` scenario:** the draw after the faulting draw must count exactly one refusal, "not reusable". That scenario already required the rebuild.

## 6. Cost of the counters

**What the code adds per draw:**
- A reused draw: 4 relaxed atomic increments (the proof, the reuse, and the hold taken and released), and two flag stores.
- A draw refused "in use": 1 relaxed increment.
- A refused proof: 1 to 2 increments.
- An import refusal: 1 to 2 increments and a relaxed load.
- Under `APS5_PROFILE_DRAW` only: two `steady_clock` reads per address-based proof, and one `LeaseCounters()` lock every 10 s for the line.

**How it was measured:**
- I built ec17620356 and c79212a54 in the same tree and saved each one's test binary and `libSceAgcDriver.prx`. `libc.prx` and `libkernel.prx` are byte-identical between the two.
- Then I ran them alternately: 12 rounds of base then head, `agc_driver_address_draw_reuse_tests 512 400`, profile off and then on.
- The test prints the average time of `Graphics::Draw` per draw in its waited loop (every draw reused) and its back-to-back loop (every draw after the first refused "in use" and built).

| Profile | Loop | Base median (spread) | Head median (spread) | Paired head − base, median | Head slower in |
|---|---|---|---|---|---|
| off | waited (reuse) | 48.9 µs (37.3–53.6) | 49.9 µs (42.1–62.1) | +1.6 µs | 9 of 12 |
| off | back to back (in use + build) | 53.0 µs (43.3–66.6) | 59.1 µs (44.9–88.6) | +9.1 µs | 9 of 12 |
| on | waited (reuse) | 85.7 µs (74.3–101.0) | 87.0 µs (76.9–93.6) | −3.5 µs | 4 of 12 |
| on | back to back (in use + build) | 59.9 µs (52.8–78.7) | 63.5 µs (50.3–88.3) | +2.3 µs | 8 of 12 |

- **Noise:** two consecutive base runs differ in the back-to-back loop by a median of 10.1 µs (profile off) and 10.4 µs (on). That is as large as any head − base difference above.
- **The lean:** the back-to-back "head slower" counts lean one way (9 and 8 of 12). That is not significant at 12 rounds (sign test, two-sided p ≈ 0.15), and the code it measures adds one relaxed increment. I'd call it noise. A run on real hardware would settle it if anyone wants it settled.
- **For the tester's question:** the profile-on figures carry the existing `APS5_PROFILE_DRAW` overhead (about 35 µs per reused draw here, on both base and head). The new counters do not change it measurably.
