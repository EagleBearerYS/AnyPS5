## The change
**`NpTrophy2RecordUnlock_nid_no_patch`** is the path UDS's `_UnlockTrophy` uses (Event.cpp:50; unchanged).
- When the service label's trophy data is loaded, it now asks `PostedUnlockRefusal` (TitleTrophies.cpp) first.
- It refuses three kinds of id:
  - an id the data does not have;
  - the platinum (grade 1);
  - a progressive trophy.
- A refusal prints one line, returns false, records nothing and calls no listener. For example:

  ```
  [trophy] ignored the posted unlock of trophy 0 for user 268435456: it is the platinum, which unlocks with the last trophy that names it
  ```
- Without trophy data (a missing or malformed `trophyNN.ucp`), every id of 0 or more is recorded as in part 1.

**`NpTrophy2::RecordUnlock`** (TrophyStore.cpp) is the old body, unchanged in behaviour. Two paths now use it:
- the statistics path (TitleTrophies.cpp:230);
- the platinum award inside it.

So a progressive trophy still unlocks through its statistic, and the platinum still comes with the last trophy that names it. Code size: +30 −10 lines in the 4 files that own this logic (2 headers, 2 sources).

## Tests
**Store level, `np_trophy2_store`, new `testPostedUnlockRules`.** It loads trophy04.ucp and uds04.ucp for label 4 and checks:
- an unknown id, the platinum and a progressive id posted through the export are refused: false, not recorded, no listener call, and each `[trophy] ignored …` line is captured from stderr;
- an ordinary posted trophy is recorded, and the platinum waits;
- the progressive trophy unlocks through its statistic (`NpTrophy2ApplyEvent_nid_no_patch`), and the platinum comes with it;
- the listener sees 1, 3, 2, 0 in that order.

Without trophy data, `testQueries` (label 0, no ucp) still records ids 12, 0 and 5.

**Exports level, `guest_np_trophy_data`.** `UnlockPlatinum` becomes `PostUnlocks`:
- after 1, 2, 3, 6 and 4 are posted, posting the progressive 5, the platinum 0 and the unknown 42 leaves 5 and 0 locked;
- the counts stay at 5 unlocked, 0 platinum, 3 bronze and 84 %;
- the listener saw only 1, 2, 3, 6 and 4.

The progressive-through-statistic and platinum-with-last-trophy checks at the export level were already in `guest_np_trophy_stats` (`UnlockThroughStats`).

**Exports level, `guest_np_trophy_stats`, new `IgnoreOtherAggregations`** (PM-037's missing check). With label 5's uds05.ucp defining stat 10 with `"aggregation":"sum"`, posting COLLECT:
- prints `[trophy] /app0/sce_sys/uds/uds05.ucp: stat 10 has aggregation "sum"; only "latest" is supported`;
- stores no stat and unlocks nothing.

This pins existing behaviour, so it passes on 954118b817 and comes first.
