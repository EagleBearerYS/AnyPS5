# PM-026: a fast bring-up tree for Resident Evil Village

Worker: cloud-2. Base: upstream/main ab9a47684 (2026-10-15). At 00:00Z `git ls-remote` showed main and every PR head below unchanged.

Method:
- Code reading on main. Line numbers are on main unless a commit is named.
- `git merge-tree` for every stacking question.
- CI-mirror builds (Ubuntu 24.04, gcc, Release, `-DANYPS5_ENABLE_SPIRV_TOOLS=ON`, lavapipe) of the merged stack and of the helper patch, each with `ctest -R '^agc'`.

No game data, no PR, nothing posted upstream.

Short answer:
- **The title's cost is #757's image tables.**
  - The profile's capture walk and `resolveImageTables` are the per-draw table snapshot: every record of a table column, re-read on every draw-cache miss.
  - No switch reverts #757. `APS5_NO_IMAGE_TABLES=1` is not the old behaviour: it stops the title at the first shader that selects a texture per lane.
  - Helper patch, pushed to the fork: `test/agc-image-tables-direct-first` (bad2ffdc5). `APS5_IMAGE_TABLES_DIRECT_FIRST=1` keeps every T# the CPU can evaluate out of tables (8 words per draw), and per-lane T#s keep #757's tables. It also logs why table narrowing is skipped.
- **The scene's second cost is the heap walk** (Mirrors.CollectWrites):
  - Cut #1 (B1) removes the repeated walks.
  - `APS5_HOST_IMPORT_MIB=6864` (cloud-3's PM-025 experiment) gets the 768 MiB heap imported, which removes its walk and copies. Pair it with B3.
  - No other switch on main lowers per-draw CPU cost much. Almost every `APS5_*` default is already the fast path.
- **Stack status.** All the clean items stack on main. The only conflicts are in two test files, and keeping both sides resolves them.
  - #5859 breaks SPIR-V validation on current main (106 of the first 166 agc tests fail). A one-line fix repairs it.
  - With that fix, `ctest -R '^agc'` on the whole stack fails 2 of 582 tests, and 41 of the others are skipped, the same 41 as on main. The 2 failures are an environment gap on this VM and the known settle flake.
  - #1201, #1202, #1896, #5609 and #5656 all need porting.

## 1. Speed switches

### Reading Village's profile against the code
- **Shader.DrawStage** is `Execution/src/Driver/Draw/DrawCapture.cpp:16`:
  - `InvocationFor` at :29.
  - The capture walk `shaderMemory.Capture(invocation)` at :48-55. This runs the SRT walk and the image-table snapshot: `ResourceMaterializer::Materialize`, `core/shader/recompiler/Optimization/src/ResourceMaterializer.cpp:1617-1642`, with `TableSnapshotter(...).Run()` at :1630.
  - `Materialize` at :97.
- **It runs only for a stage the draw cache did not serve** (`Execution/src/Driver/Draw/Draw.cpp:299-324`).
  - So 35% (scene) and 55% (title) of every draw in the capture walk means nearly every draw misses the draw cache.
  - Each miss re-reads every table word it captures (about 100k per capture).
- **Resources.Complete** is `Graphics/src/ShaderResources.cpp:1878-2016`, with the zone at :1879. It calls `resolveImageTables` at :1899, defined at :4120.
- **Driver.Draw** is `Execution/src/Driver/Draw/Draw.cpp:14`; **Graphics.Draw** is `Graphics/src/Draw.cpp:1921`.
- **Mirrors.CollectWrites and CompareBlocks are not zone names on main.** Main's zones come only from `PerformanceTimer` scopes (`Execution/include/PerformanceTimer.hpp:263,312`). They are the PC's own instrumentation around:
  - `GuestMemory::CollectWrites` in the heap-mirror code: `Graphics/src/GuestBufferMemory.cpp:1692` (`refreshHeapRuns`, every build), :1555 and :1749.
  - `compareBlocks` (:1509) → `RefreshPool::Run` (:1387) → `compareBlock` (:1355-1373).
- **Village's draws are address-based builds, and those never use the resource template cache.**
  - `ShaderResources::NeverReusable` is true for any shader with a `BdaPagetable` binding (`ShaderResources.cpp:2091-2095`), checked at `Graphics/src/Draw.cpp:1279`.
  - `noteReusable` also returns early for `usesBda` (`ShaderResources.cpp:2065`).
  - So every resource-cache, recipe and Revalidate switch does nothing for these draws.

### Not per draw, but worth knowing
- **`APS5_NO_GPL=1`** (`Execution/src/VulkanDevice.cpp:1370`), set in the Village stack:
  - Per-draw steady state is about the same.
  - Every new pipeline becomes a whole `vkCreateGraphicsPipelines` inside `Graphics::Draw`, on queue 0, under the GPU mutex (`Graphics/src/Pipeline.cpp:523, 972`).
  - Shaders get more specialization variants (`core/shader/recompiler/Optimization/src/DescriptorBindingBuilder.cpp:302-406`).
  - The pipeline store holds at most 1024 entries (`Pipeline.cpp:975-983`).
  - Keep it only if GPL renders wrongly on the PC's GPU.
- **Lazy shader preparation is not on main.** `APS5_RE8_LAZY_PREPARE` is the PC's local patch; #5872 adds `APS5_LAZY_SHADER_PREPARE=1`.
  - Main prepares eagerly on `max(2, cores/2)` pool threads (`Execution/src/Driver/Shaders/ShaderRegistry.cpp:903, 1484-1488`).
  - Submit waits for queued preparation (`Execution/src/Driver/Queues/Submission.cpp:301`).
  - None of this is per-draw cost.
- **`APS5_THREAD_PRIORITY=high`** (`Execution/src/ThreadPriority.cpp:28`): use it only if guest threads preempt the queue-0 worker. Never use `rt`: a 100%-busy worker can hit RLIMIT_RTTIME (:228-262).
- **Profiling costs:**
  - For timing runs, build without `APS5_ENABLE_TRACY` and `APS5_ENABLE_TIMING_LOG` (top-level `CMakeLists.txt:45-46`) and leave `APS5_PROFILE_DRAW` unset. It adds clocks per word read and per lock (`ShaderMemory.cpp:110-112`, `GuestMemory.cpp:303-339`).
  - `APS5_NO_HOOKSYNC_PROFILE=1 APS5_NO_SYNC_SITES=1` lower the cost of a profiling run.

### Disabling checks, validation, revalidation, compares and traces
- **Safe to turn off:** only `APS5_NO_SNAPSHOT_CHECK` (row 5).
- **Already off by default:** every other switch of this kind. That covers `APS5_VERIFY_*`, `APS5_VALIDATE_SYNC_SKIP`, `APS5_VALIDATE_LEGACY`, `APS5_CHECK_INDIRECT_ARGS`, `APS5_BARRIER_VALIDATE`, `APS5_INSERT_COMPARE`, `APS5_IMAGE_TABLE_STRICT` and the `APS5_TRACE_*` family.
- **Slower when set:**
  - `APS5_NO_VALIDATE_SKIP` (`Execution/src/Driver/Memory/WriteEvidence.cpp:67`).
  - `APS5_NO_GATE_RETRY` (:77).
  - `APS5_NO_FAST_REVALIDATE`, `APS5_NO_EPOCH_REVALIDATE` and `APS5_NO_OWN_IMAGE_REFRESH` (`ShaderResources.cpp:2809, 2428, 2382`). These are no-ops for address-based builds (`Revalidate` returns at :2796).
- **Write-evidence knobs:** `APS5_WRITE_EVIDENCE_AFTER` (:87), `_MAX_KIB` (:97), `_SAMPLE` (:92), `APS5_NO_WRITER_KEYED_EVIDENCE` (:39), `APS5_NO_FOREIGN_WRITERS` (:44).
  - They trade GPU waits against reading stale bytes, and they don't touch the profiled CPU items.
  - Leave them alone in a tree meant to find wrong output.

## 2. #757's image tables

### What #757 replaced
- **The merge.** #757 is d9e47d1e9, merged as 763ad20fc on 2026-10-14. The 23be5a02b "m3-P" base is 204 commits before its parent.
- **The old bindless path.** #757 removed the old "bindless images" path: `PlanIndirectImages` with kill switch `APS5_NO_BINDLESS_IMAGES` (`763ad20fc^1:core/shader/recompiler/Optimization/src/ResourceTracker.cpp:1124-1156`).
  - It matched only T#s loaded at `key*32` (same file :463-498, :504-590).
  - It bound them as at most 16 slots, or scanned at most 256 material records keyed through ReadFirstLane.
  - Anything larger threw (`763ad20fc^1:core/shader/recompiler/Optimization/src/ResourceMaterializer.cpp:359, 375, 381`).
- **What main does now.**
  - `PlanTableColumns` (`ResourceTracker.cpp:1270-1307`, called at :117) makes a table column for any T#/S# loaded as `key*stride+addend` or `(key<<n)&mask`, from a buffer heap or a pointer (`TryMakeTableColumn`, :553-669).
  - Every capture snapshots every record of the column (`ResourceMaterializer.cpp:535-709`; up to 65,536 keys, :562-563), unless narrowing applies (:566-568, :467-527).
  - Only pointer tables are "direct first": a T# the CPU can evaluate is not tabled (:615-622).
  - Buffer-heap T#s are tabled even when the CPU could read the one selected T#.

### Is there a switch to fall back? No
`APS5_NO_IMAGE_TABLES` (`ResourceTracker.cpp:1270-1274`) returns before any column is planned. It gives you "pre-bindless", not "pre-#757": the 16-slot / 256-record bindless path is gone. With it set:
- **A T# the CPU can evaluate** (user data, SRT, scalar loads at a uniform offset, uniform ALU; `core/shader/recompiler/Optimization/src/SrtWalker/SrtRuntimeValidator.cpp:55-142`) becomes a direct image.
  - The capture reads the 8 selected words.
  - It renders correctly, and fast.
- **A T# or S# selected per lane** (ReadFirstLane of a lane value, a non-invariant Phi, vector loads) fails in `GetHandle`: `"GetImageResource dword N is not a valid runtime value"` (`ResourceTracker.cpp:1381-1382`).
  - Background preparation logs `Shader 0x... could not be prepared after registration` (`ShaderRegistry.cpp:1053`) and stores the failure (:1063).
  - The first draw that uses it rethrows (`Execution/src/Driver/Packets/PacketExecution.cpp:301-304`).
  - `Driver::ReportFailure` (`Execution/src/Driver/Lifecycle.cpp:181-201`) then fails every flip. The title stops; it does not render wrong.
- **The disk cache is cold on the first run:** the switch is part of the shader disk-cache key (`core/shader/recompiler/ShaderCacheVersion.cmake:49-53`, `ShaderDiskCache.cpp:1254-1268`).

### What Village would lose
- **Which shaders stop:** those that pick a texture per lane, such as waterfall NonUniformResourceIndex loops, per-pixel or per-instance material layers, and visibility-buffer material passes. These stop with the switch.
- **How the old base drew them:** only through the bindless limits. Without #757's tables, nothing on main draws them.
- **I can't see Village's shaders, so the check is empirical:**
  - Run once with `APS5_NO_IMAGE_TABLES=1` and grep stderr for `is not a valid runtime value`.
  - The errors are logged when registered shaders are prepared in the background, before they are drawn (`ShaderRegistry.cpp:1046-1066`).
  - No such line for Village's shaders means the switch alone is a full fallback.

### Why narrowing is probably skipped, and how to see it
**Skip reasons.** `Narrow` gives up when:
- a value key can't be evaluated (`ResourceMaterializer.cpp:476-480`);
- the key's V# is not a buffer (:486-489);
- the key buffer has more than `APS5_IMAGE_TABLE_KEY_SCAN` positions (:494-497);
- GPU writes are pending over the key buffer (:498-501);
- a key page is unmapped (:504-507).

Main counts skips but not their reason (:469).

**My hypothesis for Village (inference):**
- A per-draw material index loaded from a constant buffer at a uniform offset is CPU-evaluable.
- But `MatchKeyDomain` makes a value domain only for a key that does not read through a descriptor: `ValidateSource(...) && !ReadsThroughDescriptor(key)` (`ResourceTracker.cpp:516`).
- Such a key gets a buffer domain over the whole buffer from that offset instead (:521-539). That passes 256 positions in any buffer over about 1 KiB at stride 4, so every capture falls back to reading the whole column.

**The helper patch below logs the reason.**

### The smallest local patch: `test/agc-image-tables-direct-first`
**Branch.** On the fork EagleBearerYS/AnyPS5, head bad2ffdc5: two commits on main ab9a47684, +69/−11. Comment-free, by Yunus Shaikh, unsigned, no trailers. Conventions check passes.

**e471d3e80 `perf(shader): keep CPU-evaluable T#s out of image tables behind a switch`.**
- With `APS5_IMAGE_TABLES_DIRECT_FIRST=1`, main's pointer-table check (`ResourceTracker.cpp:615-622`) also covers buffer-heap images: `if (address || (!sampler && directFirstImageTables()))`.
- A T# whose eight dwords the CPU can evaluate is planned as a direct image, as before #757 for non-`key*32` loads, and as `APS5_NO_IMAGE_TABLES` does.
- A T# selected per lane stays a table, so nothing stops.
- The switch is off by default. When set, it keys the disk cache like any recompiler switch.
- The new test `agc_shader_image_tables_direct_first` (`agc_shader_memory_tests --direct-first`, run with the switch set) checks three things:
  - an SRT-keyed T# is a `GuestImages` binding with no `ImageTable`/`ImageTableMap`;
  - only the selected record and the key are captured (records 0, 1 and 3 are not), and changing the key moves the capture;
  - a lane-keyed T# (`TableWholeCode`) is still a table.

**bad2ffdc5 `feat(shader): name why image table narrowing is skipped`.** The `[image-table] (10 s)` line (`APS5_PROFILE_DRAW`) now ends like:
```
narrowing 0 applied / 34294 skipped: key-scan=34294 (up to 4096 positions, APS5_IMAGE_TABLE_KEY_SCAN 256)
```
(The numbers are illustrative.) The reasons are `value`, `not-buffer`, `key-scan`, `pending-write` and `unmapped`.

**Tested** (CI mirror, lavapipe):
- **New test, red and green:** with the switch it passes; without it, it fails with "image tables direct first: a T# the CPU can evaluate was planned as a table".
- **`ctest -R '^agc'` with the switch off:** 1 failed out of 572 (41 skipped), `agc_driver_preparation_scope_settle`. That test fails 3 of 60 runs on main.
- **`ctest -R '^agc'` with the switch forced on for every test:** 3 failed out of 572.
  - The settle flake.
  - The two tests that assert an SRT-keyed or uniform T# becomes a table: `agc_shader_memory` "uniform table image: the T# read from a constant buffer at a user data offset was not planned as one table column", and `agc_shader_bindless` "image table SRT key: the T# was not planned as a table".
  - Every execution test that renders through tables passes: `agc_driver_image_table`, `_cache`, `_cache_bounds`, `_reuse`, `agc_driver_bindless_images`.
- **Stacking:** the branch merges cleanly onto the stack below and adds no conflict to the #1201, #5609 or #5656 ports.

**What Village would gain:** if its table-indexed images are CPU-keyed:
- each capture reads 8 words per image instead of the column (~100k words);
- the image-table bindings and `resolveImageTables` work for them go away;
- a draw-cache hit compares 8 words instead of the table.

That is the title's 55% + 15% and the scene's 35% + 6%. It is also the difference between the old base (~1 fps) and main (~0.07 fps), if tables are the cause.

**What it loses:** nothing lane-keyed. One difference: a bad T# in a branch the draw doesn't take can now stop the title, where the table only poisoned it.

**Alternative, not written:** drop `&& !ReadsThroughDescriptor(key)` at `ResourceTracker.cpp:516`.
- It keeps tables, but narrows CPU-evaluable keys read through a descriptor to their one record.
- It does not help masked offsets (:653) or columns shared with an unkeyed access (:661-663).
- Risk: `CheckTableStores` (:1339-1352) only guards buffer domains, so a key the shader itself writes could be read before the draw.

### SleglJan's `perf/image-table-snapshot-reuse` (f9c2003df)
**It does not apply to current main.** I fetched it read-only from SleglJan/AnyPS5; its base is 3165 commits behind. A cherry-pick conflicts in 3 files, 7 hunks, 456 lines, the same on main and on the stack:
- `Execution/src/ShaderMemory.cpp`: 2 hunks, 51 lines.
- `tests/ShaderMemory.cpp`: 3 hunks, 249 lines.
- `ResourceMaterializer.cpp`: 2 hunks, 156 lines.

**Half of it is already on main.** Its bulk reader (`SrtRuntime::readWords`) came in with #757 ("Read records in runs through SleglJan's bulk reader"; used at `ResourceMaterializer.cpp:674-675`).

**What is missing** is the per-thread memo, which:
- reuses a column's walk plan (page accessibility, dword runs, record states) when the accessibility answers repeat;
- reuses the per-record lookups when the words read are equal.

**What it would save on Village:** the per-record planning (`locate`/`take`/page checks, :644-670) and the per-record words-index hashing (:681-695) for ~12.5k records per column (~100k words / 8).
- The reads themselves still happen on every capture, with their region bookkeeping.
- The draw-cache hit compare is unchanged, and so is `resolveImageTables` (it already reuses resolved tables within a collect epoch, `ShaderResources.cpp:1393-1472`).
- So it is a fraction of the capture walk, not all of it.
- For CPU-keyed tables, the patch above or narrowing removes the column walk altogether, which makes the port moot. It would still help lane-keyed tables.

## 4. The recipe

This tree is local and not for upstream: PR evidence stays on main. Add one step at a time and measure title fps and scene presents per 10 s. The gains are estimates from the profile and code reading; none was measured on Village.

**Step 0: baseline.**
- Main ab9a47684 plus Village's carry-overs: #5703, #5815, #5671 (union above), #5851, B4 (#6146), the red-zone framing relink and `APS5_NO_GPL=1`.
- Do one diagnostic run with `APS5_PROFILE_DRAW=1 APS5_TRACE_DRAW_CACHE=1 APS5_TRACE_HOST_IMPORT=1`, and keep:
  - `[draw-cache]` miss reasons. Village's capture share says most draws miss; this says why.
  - `[image-table]` snapshots, keys, structural poison, and narrowing applied/skipped.
  - `[capture]`, `[address]` and the `[gpu] host import budget` line.
- Then time with profiling off.

**Step 1: image tables, the title's ~70% (expected to be the largest gain).**
1. **Zero-code check:**
   - Run once with `APS5_NO_IMAGE_TABLES=1` and grep stderr for `is not a valid runtime value`.
   - If no Village shader appears, keep the switch: tables are gone for every T#.
   - Risk: a lane-keyed shader registered later stops the title at its first draw.
   - The shader disk cache is cold on the first run.
2. **Otherwise:** add `test/agc-image-tables-direct-first` (bad2ffdc5) with `APS5_IMAGE_TABLES_DIRECT_FIRST=1`.
   - CPU-keyed T#s become direct; lane-keyed ones keep tables.
   - Its `[image-table]` line names why the remaining tables don't narrow. If it says `key-scan`, also set `APS5_IMAGE_TABLE_KEY_SCAN` above the "up to N positions" it prints.
3. **Expected:**
   - Title: most of the capture walk (55%) and `resolveImageTables` (15%). The old base without #757 ran the title at ~1 fps against ~0.07 now.
   - Scene: up to 35% + 6%.
   - Fewer captured words should also turn misses into draw-cache hits. Check `[draw-cache]` again.

**Step 2: B1 `perf/agc-collect-memo-index` (08f7bccbd).**
- Its own measurement in the scene: 1,640 builds made 559,240 `CollectWrites` calls at 28 µs, which is 26% of the queue-0 worker and ~9.6 ms per build.
- The exact-range index removes the re-walks of runs already walked in the same collect epoch.
- Expected: most of the 26%; the first build of each epoch still walks every run.
- Risk: low. The memo is keyed by epoch and unwatch serial, like the existing ring.

**Step 3: B3 `test/address-copy-cap-fix` (cfe2a4e79), then `APS5_HOST_IMPORT_MIB=6864`.**
- B3 alone: no speed change. It replaces the abort (a 768 MiB heap 8 MiB over budget) with eviction, and re-plans a heap mirror whose range left the write watch.
- The switch imports the 768 MiB heap. Expected (PM-025's bench): the heap's ~0.2 ms walk per collect epoch, plus its dirty-block refresh (1-8 ms per epoch), drops to under 1 µs per build. Read PM-025 §2.4's `[address]` and `[guestmem]` lines in both runs.
- Risks: section 1, row 1. First run: `APS5_TRACE_HOST_IMPORT=1` should show `[gpu] host import of 0x...+0x30000000 ok` (`GuestBufferMemory.cpp:1090`).

**Step 4: B2 `test/agc-image-mirror-epoch-compare` (ce6959aba), then `APS5_MIRROR_REFRESH_THREADS=6`.**
- B2 compares each writable image mirror once per collect epoch unless the driver stored into it.
- Expected: most of CompareBlocks (6%), plus less wall time from the extra helpers if cores are idle.
- Risk: a guest store between two builds of one epoch is seen at the next epoch, the same ordering heap mirrors already have.

**Step 5: registration and boot (no per-draw change).**
- #5872 with `APS5_LAZY_SHADER_PREPARE=1`, in place of the local `APS5_RE8_LAZY_PREPARE` patch.
- #5910 (frees decoded programs after planning).

**Step 6: reconsider `APS5_NO_GPL=1`.**
- If GPL renders correctly on the PC's GPU, dropping it removes whole-pipeline compiles from queue 0 in new scenes. Per-draw cost stays the same.
- Risk: mode-specific shader bugs, and a cold cache once.

**Step 7: ports, once 1-4 are measured.**
- #1201's `02cafe391` (capture walk) and `449e69422` + `cc34394d2` + `31c9a0f2e` (pipelined queue-0 draw commits and their fixes; `APS5_PIPELINED_DRAWS`). Pipelining takes `Graphics.Draw` off a worker that is 100% busy.
- Then `5fe165d37` / #5656 (data-only hits) and #5609's `7f8170685`.
- Each needs a port of 57-361 conflicted lines on current main. Drop #1201's `epochCollectMap` in favour of B1.

**Optional:**
- #5859 + the one-line `EmitBdaAnchors` fix. Required, or every program without 64-bit integers fails validation. It lowers GPU time, not the CPU-bound profile.
- #6060: with #5851 in the tree it only helps non-resident private memory.
