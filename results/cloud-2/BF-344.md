## 2. pthread_getaffinity_np

**Before (main):**
- A set of 8 or 16 bytes is answered.
- 32 bytes or more returns `ERANGE`, as PS5_PayloadSDK measured on firmware 12.09.
- Every other size throws.

**Source:**
- FreeBSD 11.4's [`_pthread_getaffinity_np`](https://github.com/freebsd/freebsd-src/blob/d106002967eff712894ab8b5337bbbff106ce5e0/lib/libthr/thread/thr_affinity.c#L65-L85) calls `cpuset_getaffinity` for the thread.
- [`kern_cpuset_getaffinity`](https://github.com/freebsd/freebsd-src/blob/d106002967eff712894ab8b5337bbbff106ce5e0/sys/kern/kern_cpuset.c#L1089-L1185) does two things:
  - It returns `ERANGE` when `cpusetsize < sizeof(cpuset_t) || cpusetsize > CPU_MAXSIZE / NBBY` (line 1100).
  - Otherwise it copies out exactly `cpusetsize` bytes of a zeroed buffer holding the set (lines 1111-1112 and 1183).
- FreeBSD 11.4's own constants (32 bytes both ways) would refuse 8 and 16, so the console's constants differ. The measured answers fix them:
  - **`sizeof(cpuset_t)` is 8.** A `cpuset_t` is a `BITSET` of longs, so a whole number of 8-byte words, and 8 is accepted. 1 to 7 bytes are below it: `ERANGE`. That matches main's own `cpuset_getaffinity`, whose lower bound is `sizeof(KernelCpumask)`.
  - **The upper bound is between 16 and 31 bytes.** 16 is accepted and 32 refused. So 9 to 15 bytes lie between two accepted sizes and are answered: the set, then zeros up to the requested size.
  - 17 to 31 bytes depend on where the upper bound falls. They still throw, as `pthread_getaffinity_np with a set of 17 to 31 bytes`.

**Change** (`Pthread/Posix/Thread.cpp`):

```
-    if (cpusetSize >= GUEST_CPUSET_BYTES) return GUEST_ERANGE;
-    if (cpusetSize != 8 && cpusetSize != 16) NotImplemented_nid_no_patch("pthread_getaffinity_np with a set other than 8, 16 or 32 bytes and more");
+    if (cpusetSize < sizeof(KernelCpumask) || cpusetSize >= GUEST_CPUSET_BYTES) return GUEST_ERANGE;
+    if (cpusetSize > 16) NotImplemented_nid_no_patch("pthread_getaffinity_np with a set of 17 to 31 bytes");
```

The copy below it was already `memset(cpuset, 0, cpusetSize)` followed by the 8-byte mask, which is what FreeBSD copies out.

**Debt:** `docs/dev/debt/libkernel.md`'s `pthread_getaffinity_np` entry is rewritten gap first, in 910 characters: the 17 to 31-byte throw, the measured sizes, the FreeBSD rule and the constants it implies. Its last sentence, on `pthread_setaffinity_np` and `cpuset_getaffinity`, is unchanged. No debt or todo list on main names the six dropped rows, so nothing was removed.

**Test** (`GuestAvailableCpumask.cpp`, `guest_available_cpumask_tests`, main's existing test for this function): after the 32/33/64-byte `ERANGE` loop, it checks:
- sizes 0, 1 and 7 return `ERANGE`;
- sizes 9, 12 and 15 return 0, with the first 8 bytes equal to the thread's affinity, the bytes up to the size zeroed, and the bytes past it untouched.

## 5. For the Bug Finder

- **The attribute rows' size rule.** #9156's `pthread_attr_getaffinity_np` refuses any set below 32 bytes (`GuestCpusetBytes = 32`). That is FreeBSD 11.4's `kern.sched.cpusetsize`. By the same measurement, the console's kernel `cpuset_t` is 8 bytes, and FreeBSD's `_pthread_attr_getaffinity_np` and `_pthread_attr_setaffinity_np` compare against that size. So #9156 refuses 8 and 16-byte sets that the console's own rule would accept. That is #9156's call, so I changed nothing; it is worth a review note there. peeldealer's branches use 32 too.
- **`pthread_setaffinity_np`** on main still requires exactly 32 bytes (its debt entry says so, unmeasured). By the same FreeBSD rule and the 8-byte `cpuset_t`, the console would refuse 32 there too. It is out of this task's rows and unchanged.
- **#9326's ceiling range** throws outside `SCHED_RR`'s 256 to 767. That matches the measured attribute range. The mutex call's own range is not measured.
