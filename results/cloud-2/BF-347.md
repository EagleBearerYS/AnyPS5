## 5. PR body draft

```
### What
`pthread_getaffinity_np` follows the set sizes measured on a PS5. A set of fewer than 8 bytes or of 24 bytes and more returns `ERANGE`. A set of 8 to 16 bytes gets the thread's mask in its first 8 bytes and zeros up to the requested size. Before, only 8 and 16 were answered, 32 and more returned `ERANGE`, and every other size threw.

- `pthread_getaffinity_np` (libkernel). Source: @rooklz's measurement on a PS5 (https://github.com/boykopovar/AnyPS5/pull/9156#issuecomment-6391607043). Sizes 0, 1, 4, 7, 8, 9, 12, 16, 24, 32, 64 and 128 were tried: 8 to 16 bytes are accepted and zero-filled past byte 8, and below 8 or from 24 up returns `ERANGE`. PS5_PayloadSDK's measurement of 8, 16 and 32 bytes (https://github.com/mihawk-99/PS5_PayloadSDK/blob/3e31e0b1b68ada28beca68adc480cf0c3d17b9df/platform/docs/PROBE.md#L287-L297) agrees. This extends the measured sizes #11431 added.
- 17 to 23 bytes are not measured and still throw. This is recorded in `docs/dev/debt/libkernel.md`, along with `pthread_setaffinity_np`'s unmeasured 32-byte limit and `cpuset_getaffinity`/`cpuset_setaffinity`, which still accept up to 32 bytes.

### Tested
Linux (Ubuntu 24.04, gcc 13.3, CI flags), `guest_available_cpumask`. It checks that 0, 1, 4, 7 and 24 bytes return `ERANGE`, and that 9, 12 and 15 bytes return 0 with the thread's affinity in the first 8 bytes, zeros up to the size, and the bytes past it untouched.
- main + the test: 0/10 (each run stops at the 24-byte case, where main throws)
- this PR: 10/10

Overlap: #13908 changes how this function copies the set out (`EFAULT` for invalid memory). This PR changes only which sizes it accepts. The two merge cleanly.
```
