## 1. The design as built

### 1.1 The reverse index (`Execution/src/GuestMemory.cpp`, API in `Execution/include/GuestMemory.hpp`)

- **A subscription** (`GuestMemory::WriteSubscription`) has:
  - a 64-bit **generation**;
  - its sorted 64 KiB **blocks**;
  - its **sweep spans**: the watched ranges, page-rounded and coalesced across gaps of up to 1 MiB while the merged extent stays watched;
  - a bounded list of **bump records** `(generation, block)`: 1,024 entries, consecutive bumps of the same block merged, then an overflow mark that sends the next check to the fallback.
- **The index** is `unordered_map<block, vector<WriteSubscription*>>` under its own mutex.
  - Lock order: tracker mutex → index mutex, and the `GuestAllocations` registry mutex → index mutex. Nothing takes the tracker or the registry under the index mutex.
  - An atomic count of live subscriptions makes every bump source return after one load when nothing is subscribed.
  - Subscriptions are `shared_ptr`s whose deleter unregisters their blocks.
  - The index object is never destroyed, so a `ShaderResources` released at exit is safe.
- **API:**
  - `SubscribeWrites`, `SubscriptionGeneration`, `SubscriptionSpans`, `SweepSubscription`;
  - `SubscriptionBumpsSince` (false once overflowed), `TrimSubscriptionBumps`;
  - `WriteBlockOf`, `NoteGpuPending`;
  - `WriteIndexCounted`/`ResetWriteIndexCounts` (subscriptions, blocks, bumps, lookups, sweeps, sweep failures, overflows, index time, bumps per source).

**Bump sources:**

| source | hook | covers |
|---|---|---|
| `Cpu` | `WriteTracker::stamp` for stored `Cpu`/`Fresh` stamps | a CPU write the next collect finds (the sweep, any element's or anyone's collect); a fresh registration, i.e. a remap that `DirectMemory` re-registers, whose next collect reports the whole range; the Windows private-mapping observer |
| `Driver` | `WriteTracker::stamp` for `Driver` stamps | `MarkWritten`, `StoreOwnBytes`, `Write`, write-backs: a GPU write that landed and was published |
| `Pending` | `StorageTexture::markLayersPending` → `GuestMemory::NoteGpuPending(surface)` | a GPU storage write recorded and noted as pending |
| `Unwatch` | `unwatchLocked` when it unregisters (Linux) or excludes (Windows) | a host import taking the range off the write watch |
| `Forget` | `ForgetPages`, the `GuestAllocations` invalidator, now registered whenever the index is on (before, only with an arena or image page cache) | a free, a remap, any registry change over the range, before any collect |

- `ImportWindow` stamps do not move `blocks[]`, so they do not bump; `UnchangedSince` ignores them too.
- A cost moves to the writers: one index lookup per stored stamp per block, plus one generation increment and record per subscription over that block (§3).
- **Break switch for the red tests:** `APS5_TABLE_INDEX_BREAK=cpu|driver|pending|unwatch|forget|compared`.
  - `pending` also disables the pending-registry scan in the O(1) check.
  - `compared` disables the compared elements' per-element proof.

### 1.2 Revalidate (`Graphics/src/ShaderResources.cpp`)

- **Subscription at build time** (`subscribeBuilt`, after `buildComplete` of a reusable build) classifies every `textures[i]` from its `validatedTextures[i]` record:

| class | condition | proof on the O(1) path |
|---|---|---|
| subscribed | valid record, not depth, watched, no storage source, no DCC | the subscription's generation |
| **compared** | valid record, not depth, `GuestMemory::Watched` false | today's lookup (`cachedTexture`, which compares the bytes) for that element only; a changed one is re-bound (draw builds) |
| per element | storage-image view, DCC keys, depth, no record | today's `fastRevalidate` predicate, run over that subset only (a new `only` parameter) |

  - **Storage images** always keep today's predicate.
  - **The T# table spans** (the map's `TableBase`/`TableSize` per table):
    - a watched span is subscribed, and its blocks map to a "table" marker;
    - a compared span is copied and compared with `CompareMapped`.
  - **The baseline generation** is taken right after the build and proved with one `UnchangedSinceAll` against the generations the build's own lookups collected.
    - Without it, the "one changed" case never got a subscription: every draw rebuilt before a first Revalidate could subscribe.
    - When it cannot be proved, the first Revalidate's fallback sets the baseline.
- **The O(1) check (`indexRevalidate`):**
  1. **Sweep:** `CollectWrites` per span, memoized per collect epoch. A CPU write found here is stamped, and the stamp bumps.
  2. **Pending:** if `StorageTexture::PendingSerial()` moved since the proof, `ScanPending` over the spans; an overlap goes to the fallback.
  3. **Compared table spans** are compared.
  4. **Generation unchanged:** prove only the compared and per-element subsets, then accept (`IndexAccepted`).
  5. **Generation moved:** take the bumped blocks, map them through the sorted `(block, element)` list to elements, and prove only those elements with today's predicate. A bumped table span, or an overflowed record list, goes to the fallback.
     - If the predicate fails with `Changed`, `reresolveElements` runs `cachedTexture` for the bumped elements only.
     - A new `Texture` replaces the old one, which goes to `recorder.Keep`. `descriptorImages[p]` is rewritten at the element's positions (one replay of `buildComplete`'s write order per object), and `rebound` forces `PrepareDrawBindings` to write a fresh set from then on.
     - The element's record is retaken from the lookup log, and the subset is proved again ("partial").
     - Only draw builds without BDA re-bind. A compute or BDA object binds `_set` directly, so a replacement there goes to the fallback (found by `agc_driver_lookup_log_fits_build`, see §5).
  6. **Anything else** goes to today's path unchanged (fast proof, T1, full walk).
     - Its baseline is the generation read **before** it runs.
     - On success the bump records up to it are trimmed and the compared table copies are retaken.
- **O(N) loops taken out of the index path:**
  - **head:** the `CompletePendingCpuWrites` calls per described range are skipped when no copied writer, draw writer or completion label exists. This is the same early-out each call makes, hoisted.
  - **tail:** the depth-copy refresh walks a list of depth-copy elements instead of all N textures.
  - These two were 92 + 107 µs per draw at N = 4,096.

**What it says:**

- **Unchanged.** Revalidate stops scaling with N except for the sweep.
  - Without an epoch the sweep is one `PAGEMAP_SCAN` over the textures' span. At N = 4,096 that is 256 MiB, ≈ 2–3 ns per page, 198 µs, against main's 4,281 µs of per-element proofs.
  - With an epoch the sweep is a memo hit, and Revalidate is 21.7 µs at N = 4,096 (main: 747 µs under the same memo). Of that, 9.7 µs is the compared table span: 64 KiB compared, because the harness's T# table sits in imported memory.
  - The per-subscription part (generation load, pending serial, two vector copies) is ≈ 1 µs at every N.
- **One changed.** The build disappears.
  - Main rebuilds the whole object on every draw: the lavapipe table-set allocation is 9–68 ms, plus 5–14 ms of `images` at large N.
  - The index re-resolves the one bumped element and re-binds it: `draw` goes from 44 ms to 1.6 ms at N = 4,096, and from 69 ms to 155 µs at N = 8.
- **What remains**, measured:
  - **Index check, one changed:**
    - the sweep: 22 µs at N = 8, 244 µs at N = 4,096;
    - the re-resolve: one `cachedTexture` miss, a new snapshot `Texture` and its upload, ≈ 85 µs at N = 8 and ≈ 350 µs at N = 4,096. It grows with the texture cache's size; not broken down further.
  - **Outside Revalidate, unchanged, epoch, N = 4,096:**
    - `lookup − revalidate` ≈ 216 µs: the draw-resource `ContentKey` over 4,096 × 8 T# words, plus `Find`;
    - `prepare` ≈ 208 µs: the per-draw rewrite of all N descriptors into a fresh set (snapshots are selected);
    - `record` ≈ 348 µs: lavapipe's per-draw descriptor processing.
  - These are BF-037's descriptor-side costs. Its device heap removes `prepare` and most of `record`; keying the cache on the table's identity (a #6454-style vouch) would remove the `ContentKey` part.
  - The validation ceiling is now below the descriptor ceiling.

## 3. Writer-side cost

**What was measured** (`--writer K S 21`):
- K watched blocks, one byte written per block, then `CollectWritesUncached` over the K blocks. Median of 21 rounds.
- S subscriptions each covering all K blocks.
- S = 0 is today's collect: the live-count check returns at once.

| K blocks | S = 0 (today) | S = 1 | S = 16 | S = 64 |
|---|---|---|---|---|
| 16 | 3.5 µs | 5.8 µs (index 2.1) | 6.6 µs (index 3.7) | 12.3 µs (index 9.2) |
| 256 | 28.8 µs | 65.2 µs (index 28.7) | 74.1 µs (index 49.8) | 168 µs (index 152) |
| 4,096 | 401 µs | 796 µs (index 335) | 1,222 µs (index 750) | 3,332 µs (index 2,652) |

- **Per block:**
  - the first subscription costs ≈ 80–110 ns: one index-mutex acquisition and one hash lookup per stamped block, because `stamp()` is called per block;
  - each further subscription over the block costs ≈ 10 ns: a generation increment and a record.
- **Subscribing** costs 1.6–380 µs per subscription for K = 16–4,096 blocks.
- **The collect-epoch memo** does not reduce these: a stamp happens once per written block per collect, wherever it comes from.
- **The worst case** is a title rewriting many blocks that many cached builds subscribe to, i.e. many builds over one streaming texture pool, each block shared by S builds. Its cost is S × blocks written × 10 ns, plus the per-block lock.

## 4. Correctness tests (`agc_driver_table_index_validation`)

**The setup:**
- Each case is an N = 8 table draw over its own watched texture allocation and its own watched T# table, kept alive until the end so addresses are not reused.
- Each case first settles on the O(1) proof (`accepted 1`), then checks its event, then settles again.
- It sets `APS5_TABLE_INDEX=1` itself.
- `outcome` drops the counter-only assertions, leaving only what the draw samples and whether the O(1) proof was taken.

| case | what it checks | green | red with | red message (exit 1) | specificity: green with |
|---|---|---|---|---|---|
| cpu | a CPU write to the sampled texture: the next draw samples the new texels, exactly one bumped element, no rebuild; the next draw is O(1) again; a write to another texture bumps that element only | ✔ | `BREAK=cpu` | "still sampled its old texels (brightest 255, accepted 1, … bumped 0)" | `forget` |
| table | a T# word change in the (watched) table refuses the O(1) proof, as does restoring it | ✔ | `BREAK=cpu` | "a T# word change in the table did not invalidate the O(1) proof (accepted 1 …)" | `pending` |
| pending | an `image_store` dispatch over the texture leaves a pending storage image and bumps the subscription (`Pending`); the draw is not O(1) and samples the stored texel; after `FlushCachedTextures` the write is published (0x12345678 in guest memory) and the draw still samples it, then settles | ✔ | `BREAK=pending` | "the recorded storage write did not bump the subscription over the texture" | `cpu` |
| remap | the texture allocation is removed from `GuestAllocations`, its key block unregistered, replaced by a pre-filled mapping (`mremap` `MREMAP_FIXED`), re-registered and re-added: the subscription is bumped (`Forget`) before any collect, and the draw samples the new mapping | ✔ | `BREAK=forget` | "the free and remap of the texture's range did not bump its subscription" | `cpu` |
| compared | a texture unwatched (`GuestMemory::Unwatch`) before the build stays on its per-element compare inside the O(1) path (`compared 1`); a CPU write to it is drawn without a rebuild | ✔ | `BREAK=compared` | "expected the unwatched element on its per-element proof inside the O(1) path (… compared 0)" | `cpu` |

**Outcome-only red runs:** what each source protects beyond its own counter.
- `remap` with `BREAK=cpu,forget` is red: "took the O(1) proof or sampled the old mapping (brightest 255, accepted 1)".
  - With only `forget` broken the outcome stays correct: the re-registration is "fresh", so the sweep's collect reports the whole range written and the `Cpu` bump catches it. A remap therefore has two sources.
- `compared` with `BREAK=compared` is red: "a CPU write to the compared texture was missed (brightest 255, accepted 1)".
- `pending` with `BREAK=pending` stays green, even with every source broken (`pending,unwatch,cpu,driver,forget`).
  - The store dispatch host-imports the texture allocation, and on Linux that takes the range off the write watch. The sweep's `CollectWrites` over the span then fails (not covered), which is a fallback whatever the bumps say.
  - So in this layout the pending source is caught three ways: the bump, the registry scan, the coverage. The test can only be red on the bump itself.
  - A storage image whose surface stays watched would rely on the bump or the scan alone. I did not build that layout.
- **The T# case** is red under `cpu` only because this test puts the table in a watched allocation, which the shader does not import.
  - In BF-037's layout (§2) the table shares the imported allocation and is compared byte-wise instead; no bump is involved there.
  - Main itself never checks T# words in Revalidate: the driver re-materializes them, and the `ContentKey` misses on a change. So the index's T# coverage only matters to a path that skips re-materialization, e.g. #6454's vouch (§6).

## 6. Prior art and how it composes

- **#6454** (`perf/shader-image-table-reuse-v3-pr`, head `1752c4a89`), `SrtWriteStamp`:
  - The stamp is `{CollectWrites generation over the span, GuestAllocations generation}`.
  - `ShaderMemory::Vouched` re-proves it with `CollectWrites` + `UnchangedSince(span, generation)`, and fails on any allocation change anywhere (the global generation).
  - It vouches for the **T# column**, so the materializer can skip re-reading it. It does not cover the textures the T#s name.
  - I did not reuse it. The index proves the other half, the textures, and the T# span too. The two compose in sequence:
    - the vouch keeps the words, so the `ContentKey` matches and the cached build is found;
    - the subscription proves that build in O(1).
  - **How they could share one mechanism:**
    - A vouch could be a subscription over the column's span (`SrtWriteStamp.generation` = the subscription's generation). That makes the vouch O(1) without the per-span `UnchangedSince`.
    - Its `layout` check becomes the range-local `Forget` bump instead of the global registry generation, which today refuses every vouch whenever anything is mapped anywhere.
  - **The remaining per-draw O(N) after both:** the `ContentKey` hash over N × 8 words, ≈ 200 µs at N = 4,096. A vouched table could key the cache by its identity and the subscription instead.
- **fable-void `0171a4ac80`** (`wip/new-gpu-path`, "check only the device image entries a dispatch names before it runs"):
  - Each device-image entry keeps the `ValidationState` it was last checked at: collect epoch, unwatch serial, depth-surface serial, pending serial, own writes.
  - A dispatch checks only the entries it names.
  - Same family as this design (per-entry last-checked state). **No code taken.**
  - **The difference:** his states are global serials, so any change anywhere re-checks every named entry. The index's are range-local, so only bumped elements are re-checked.
  - **What would carry over** is his scoping (check only what the draw names). Here it would apply to the per-element and compared subsets.

## 7. What a PR version still needs

1. **Memory per subscription.**
   - At N = 4,096 with one block per texture, a cached build holds:
     - `subscribedBlocks`: 16 B per block;
     - the subscription's block list: 8 B per block;
     - `indexElements`: T# words and flags, 44 B per element;
     - `indexImagePositions`: 24 B per element, built on the first re-bind.
   - The shared map adds one pointer per block per subscription plus ≈ 64 B of node per distinct block.
   - That is ≈ 300 KiB per 4,096-element build, plus up to 16 KiB of bump records.
   - **Remedies:**
     - coalesce to allocation ranges and map a bump to elements by binary search on sorted element addresses, instead of per-block pairs;
     - keep the T# words in the compiled program instead of copying them;
     - share one subscription per table identity across builds.
2. **Locking.**
   - The index mutex is taken inside the tracker mutex, once per stamped block, whenever any subscription is live. Writers serialize on it (§3: ≈ 80–110 ns per block for the first subscription).
   - **Remedies:**
     - bump per written run, one lock per walk;
     - a sharded or lock-free block → subscriber map (RCU-style lists);
     - a per-subscription spinlock for the bump records.
   - Readers already use only atomics.
3. **Windows write-watch collect costs** (Windows-only; described, not run):
   - **The sweep** becomes `GetWriteWatch` per span, also proportional to the span's pages, with the single-pass reset. Windows coverage excludes host regions (`GuestArenaHostRegionOverlaps`), so spans split more often and the per-span call count grows.
   - **`watchPrivateMapping`** already stamps `Cpu`, so it bumps.
   - **`Fresh`** (`GuestArenaCollectFreshWrites`) stamps bump too.
   - **To measure:** `--writer` and the `epoch` table on Windows. `GetWriteWatch` over 256 MiB is the number that decides whether the sweep stays per subscription or becomes one global collect per epoch, shared by every subscription.
4. **Sweep granularity.** Per subscription and per epoch, as built. A sparse texture set spread over a large arena gives many spans and many syscalls. A single arena-wide collect per epoch, shared by all subscriptions, makes the sweep O(1) per subscription too.
5. **Pending bumps.**
   - `markLayersPending` bumps on every mark (every dispatch writing the image), so a render target that is also sampled bumps its subscribers every dispatch. Bump only when the pending set over the range changes.
   - Also give a watched storage surface a red test that does not depend on the import's unwatch.
6. **Re-binding compute and BDA objects.** These need a fresh set per dispatch (or update-after-bind) before they can re-bind. Today they fall back.
7. **Reporting.** A `ProofPath` for the indexed and re-bound proofs, `[rescache]` counters for them, and `agc_driver_lookup_log_fits_build`'s expectations under the index.
8. **The `ContentKey`.** It is the next O(N) per draw (§2) and needs #6454's vouch or a table-identity key.
