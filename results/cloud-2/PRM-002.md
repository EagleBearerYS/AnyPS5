## Setup

- Machine: cloud-2, a Linux VM with 4 vCPU Xeon @ 2.10 GHz and 15 GiB RAM. Ubuntu 24.04.5; the kernel boots with ipv6.disable=1. gcc 13.3.0, CMake 3.28.3, Ninja 1.11.1, ccache 4.9.1, lavapipe from Mesa 25.2.8 (LLVM 20.1.2).
- Configure used CI's Linux-job flags: `cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON -DCMAKE_C_COMPILER=gcc -DCMAKE_CXX_COMPILER=g++ -DCMAKE_C_COMPILER_LAUNCHER=ccache -DCMAKE_CXX_COMPILER_LAUNCHER=ccache -DANYPS5_ENABLE_SPIRV_TOOLS=ON`. It was followed by `python3 tools/check_test_registration.py build`, `cmake --build build` and `cmake --build build --target libs`, all in the existing build directory.
- Tests: `ANYPS5_REQUIRE_VULKAN=1 GALLIUM_OVERRIDE_CPU_CAPS=avx MESA_SHADER_CACHE_DIR=<repo>/.mesa-shader-cache ctest --test-dir build --output-on-failure --timeout 120 --parallel 4 --output-junit ctest.xml`, then `python3 tools/check_skips.py build/ctest.xml`. Builds and tests ran as an unprivileged user, as on the CI runners. A and B ran one after the other with nothing else running.
- Submodules: main now has `3rdparty/mbedtls`, which contains its own `framework` submodule, and CI checks out recursively (`submodules: recursive`). With a non-recursive `git submodule update --init`, configure fails with `ModuleNotFoundError: No module named 'mbedtls_framework'` and `.../3rdparty/mbedtls/framework/CMakeLists.txt not found`. `git submodule update --init --recursive` fixes it. Any tree last updated before mbedtls was added will hit this.
