## Notes for when the base merges

These come from reading the two PRs; nothing is built.

- **The extensions the batch needs:**
  - #10395's `EcKey` holds only a group, so this batch adds the private scalar, the public point and the conversion form.
  - Curve arithmetic goes through the `mbedtls` submodule #10395 already links (`ecp`/`ecdsa`/`ecdh`).
  - BIGNUM I/O goes through #9446's exported `BN_bin2bn`/`BN_bn2bin`/`BN_new`, plus the public `BIGNUM` layout's `neg` field.
- **Compressed points:** reading them needs a modular square root that mbedtls does not provide for short-Weierstrass curves. secp224r1 and secp224k1 have p ≡ 1 (mod 4), so they need Tonelli-Shanks; the other 9 curves have p ≡ 3 (mod 4).
- **Known-answer sources:**
  - ECDSA: RFC 6979 A.2.3-A.2.7 for P-192/224/256/384/521. There is none in RFC 6979 or NIST CAVP for secp192k1/224k1/256k1 or brainpool, so those get round-trip and tamper cases only.
  - ECDH: RFC 5903 §8 (P-256/384/521) and RFC 7027 Appendix A (brainpoolP256r1/384r1/512r1).
- **`ECDH_compute_key`'s `KDF`** is a guest callback, so it needs an `APS5_VABI` function-pointer type (the pattern in `libc/src/ApplicationHeap.cpp:19`).
