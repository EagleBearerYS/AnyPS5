## #6641 shutdown against main's new threads

Merged tree: `git merge-tree --write-tree 82ddae75b6 43830b93bd` = 0b9190f759.

`Driver::stop()` is at `core/libs/prx/libSceAgcDriver/Execution/src/Driver/Lifecycle.cpp:103`. #6641 adds four calls to main's sequence, marked below; everything else is main's. It runs in this order:
1. joins the queue workers (`:118-120`);
2. **`DrawPipeline::Queue0().Stop()` (`:122`, #6641)**;
3. `StopWorkerSampler`, `CloseRegistrationPreparation`, **`Graphics::StopPipelineLibraryWorker()` (#6641)**;
4. takes the GPU mutex, then `device.Reset()`, `replacedDevices.clear()`;
5. `Graphics::FlushPipelineJournal()` (#5875);
6. `Graphics::ShutdownGuestBufferWorkers()`, **`Graphics::StopCompareHelpers()` (#6641)**, **`ShaderRecompiler::ShaderDiskCache::Shutdown()` (`:132`, #6641)**;
7. `PerformanceTrace::StopOutput`, `FlushAsyncLog_nid_no_patch`, `StopProfileOutput_nid_no_patch`, then `stopped = true`.

The file paths below are under `core/libs/prx/libSceAgcDriver/`.

What I checked:
- **`DrawPipeline::Stop()` runs once.** It's defined at `Execution/src/Driver/Draw/DrawPipeline.cpp:176`, and its only caller in the tree is `Lifecycle.cpp:122`.
  - `Driver::stop()` holds `shutdownMutex` and returns early on `if (stopped) return;`.
  - Even a second `Stop()` would be harmless: it moves `thread` out under the lock, so a second call finds `!committer.joinable()` and returns.
- **#1747's pipelined dispatch worker is stopped.** It uses the same `Queue0()` committer as draws:
  - users, under `Execution/src/Driver/`: `Dispatch/Dispatch.cpp:286`, `Dispatch/VariantValidation.cpp:84`, `Memory/BufferFill.cpp:196`, `Memory/WriteEvidence.cpp:209` and `Packets/PacketExecution.cpp:34`;
  - `DrawPipeline.cpp:97` is that pipeline's only thread;
  - it stops at `:122`, after the queue workers that feed it have been joined.
- **#4855's submission ring has no thread to stop.**
  - `Execution/src/Driver/Queues/SubmissionRing.cpp` starts no thread; its `Rings` is a leaked singleton (`static auto* value = new Rings;`, `:59`).
  - The queue workers that drain the ring (`Queues/Submission.cpp:462`) are the ones joined at `Lifecycle.cpp:118-120`.
- **The journal flush runs before the disk cache shuts down.**
  - `FlushPipelineJournal` (`Graphics/src/PipelineJournal.cpp:1113`) waits until the writer's queue is empty and nothing is being written.
  - The journal's file, `pipelines.journal`, lives under the disk cache's `EntryDirectory()` (`:563`). The journal encodes module records with `ShaderDiskCache::EncodeResult` when it appends them (`:746`). So flushing before `ShaderDiskCache::Shutdown()` is the right order.
  - The journal's replay workers (`PipelineJournal.cpp:880`) are joined by `~Replay`. `Execution/src/VulkanDevice.cpp:691-694` cancels, waits for and resets the replay at device teardown, which is also before the disk cache shutdown.
  - The journal writer thread (`:566`) is detached on a leaked singleton, as main designed it.
- **Every other driver thread has a stop.**
  - the Recorder release thread: joined in `~Recorder` (`Graphics/src/Recorder.cpp:1153`);
  - the `PipelineCache` saver: joined in `~PipelineCache` (`Graphics/src/PipelineCache.cpp:75-82`);
  - the `VulkanDevice` worker (`Execution/src/VulkanDevice.cpp:157`): device-owned, gone with `device.Reset()`;
  - the GuestBufferMemory threads (main's `ShutdownGuestBufferWorkers`), the WorkerSampler threads (main's `StopWorkerSampler`), and the ParallelCompare helpers (#6641's `StopCompareHelpers`);
  - the async log thread: detached by design, and flushed.

## #6243 FormatVersion against #5875's journal

Merged tree: fbc095de35. #6243 bumps `core/shader/recompiler/ShaderDiskCache.hpp:16` `FormatVersion` from 36 to 37. The journal keeps its own `FileFormat = 3u` (`PipelineJournal.cpp:47`). The pairing is still safe:
- The journal only loads a file whose header says `fileHeader.sourceVersion == ShaderRecompiler::ShaderDiskCache::SourceVersion()` (`PipelineJournal.cpp:580`).
- `SourceVersion()` (`ShaderDiskCache.cpp:1651`) returns `Generated::SourceVersion`. `core/shader/recompiler/ShaderCacheVersion.cmake` builds it as a SHA256 over the recompiler's sources, and the generated `sources.txt` lists `ShaderDiskCache.cpp` and `ShaderDiskCache.hpp`.
- So #6243's record change also changes `SourceVersion()`, and a journal written by main's build is rejected and rebuilt instead of decoded with the new record layout.
- Within one build, journal module payloads are written with `EncodeResult` (`:746`) and read with `DecodeResult` (`:604`) from the same code.
