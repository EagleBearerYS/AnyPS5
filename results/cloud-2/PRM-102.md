## 3. Semantic check: does every slot the table writes stay valid?

**Verdict: yes.** Lines are on the merge 9495b27d06. `G` = `core/libs/prx/libSceAgcDriver/Graphics/src`.

### 3.1 653edfefa1's slot model

- **What `TextureSlot` returns and keeps** (`G/BindlessHeap.cpp:312–327`):
  - It looks up or claims a slot for the key `{kind, texture.get(), view, layout}` and returns its index.
  - `claimSlotLocked` (382–389) records the slot under the owner address (`ownerSlots[texture.get()]`), and line 323 records `owner.texture = texture.get()`.
  - Line 324 calls `texture->MarkHeapSlotted()`.
  - It keeps **no** `shared_ptr`: the slot names its owner by address only.
- **What frees a slot:** only `ReleaseImageSlots(owner)` (357–366), which calls `freeSlotLocked` (391–399) for each of the owner's slots.
  - `freeSlotLocked` erases the key, bumps `owner.generation` and pushes the slot onto `freeSlots` for reuse. `slotSerial` is bumped.
  - `freeSlotLocked` has no other caller. No sweep, heap hold or present sweep is left.
- **Who calls `ReleaseImageSlots` for a texture:** only `Texture::release()` (`G/Texture.cpp:1237–1239`), guarded by `heapSlotted.exchange(false)`. `release()` runs from `~Texture()` (1163–1164) and from the constructor's catch blocks, before any slot can be taken.
  - Other owners are other objects: `StorageTexture` (6582), `MultisampleTarget`'s storage views (`G/MultisampleTarget.cpp:760–761`), `PresentationPass`'s slot, and samplers. The table takes only `Texture`-owned sampled slots.
- **When slots run short:** `NearlyFull()` (419–421) is now `refusedHeaps != 0`.

### 3.2 #7642's table

- **`HeapSlots`** (`G/DeviceImageTable.cpp:85–91`) binds `take` to `heap->TextureSlot`, and `generation`, `serial` and `nearlyFull` to the heap.
- **`lookupKey`:**
  - Line 364: `slots.nearlyFull() ? std::nullopt : slots.take(Runtime::FirstImageBinding, texture.texture, texture.view, texture.layout)`. `texture.texture` is a `shared_ptr<Texture>` held by the caller across the call.
  - Line 370 stores the entry with `std::move(texture.texture)`, so **the entry holds the texture**.
  - Line 371 returns `DeviceImageValue{*slot, mode, 0u, 0u}`. The table writes no sampler slot.
- **The view** comes from `LookupDeviceTableTexture` (`G/ShaderResources.cpp:5630–5675`) as `texture->FirstLayerView()` or `View()` (5669–5671), so the Texture owns it. Depth surfaces and per-use copies are refused there.

### 3.3 Why the slot stays valid

1. **While the entry exists, the slot cannot be freed.**
   - The entry holds the `shared_ptr<Texture>` (370), so `~Texture` cannot run.
   - `Texture::release()` has no other live-object caller.
   - So `ReleaseImageSlots(texture)` cannot run, and the slot cannot reach `freeSlots`.
   - A key shared with a per-draw use of the same texture, view and layout returns the same slot from `textureSlots`, and that slot is freed only at the same `~Texture`.
2. **When the table drops an entry, the texture outlives every batch that could read the old slot.**
   - `release` (415–434) moves the texture into `recorder.Keep(...)` (432). So do the insert-failure paths (187, 323).
   - `Recorder::Keep` (`G/Recorder.cpp:2778–2782`) pushes it to the open batch's `kept`.
   - `kept` is released only in `Recorder::finish` (4159), after the batch's fence: `Reap`'s status check, or the wait at 4219. It is released either directly (4284–4286) or later through `DestroyDeferred` (389–399).
   - So `~Texture`, and with it `ReleaseImageSlots`, runs only after the batch that was open at the release has finished on the GPU, and every earlier batch with it.
3. **No later batch reads the dropped slot.**
   - `Prepare` (159–169) runs `retainSlots → resolve → refresh → evict → upload(recorder)` under the table mutex.
   - `refresh` and `evict` take dropped keys out of the device key table with `keys.Retain` (521, 572), which marks their buckets changed.
   - `upload` (575 on) records the bucket writes into the same open batch, with a transfer→all-commands barrier, before any draw recorded after this `Prepare`.
   - A draw in a later batch therefore sees the key gone and cannot hand a shader the old slot index. A draw in the same or an earlier batch is covered by step 2.
4. **Teardown order** (`Execution/src/VulkanDevice.cpp`):
   - 970: `vkDeviceWaitIdle`;
   - 995: `recorder.reset()`, which drops the kept batches;
   - 1013: `DeviceImageTable::Release(device)`, which drops the held textures, which free their slots on a live heap;
   - 1014: `BindlessHeap::Release(device)`.
   - With the device idle, no shader can read any slot.

This is the same guarantee #7642 relied on before, the held texture plus `Keep`, minus the sweep's delay. With 653edfefa1, a slot can be freed only by its texture's destruction, which the table's hold and the batch's `Keep` both postpone.

**`NearlyFull`:** the table still takes no slot while `NearlyFull()` holds (364) and reserves none, as #7642's description says. The predicate's meaning changed: a heap that refused a slot recovers at twice the margin free. #7642 only reads it.
