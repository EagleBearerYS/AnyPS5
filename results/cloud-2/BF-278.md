## Design

### The mark already exists, at 4 KiB

The task asked for a new 64 KiB-block bitmap that stores set after a successful `Write` lookup. The recompiler already keeps one, finer, and the host already reads it:

- **`BdaAbi.hpp`:** the fault buffer holds a written-page record: `WrittenPageShift = 12` (4 KiB pages), `WrittenChunkShift = 17`, 2048 slots probed 8 deep, an overflow word, a count word and a list.
- **`note_bda_write` (`DefineBdaNoteWrite`):** runs after every successful Write lookup, in every store path:
  - `EmitBdaStoreAt` (dword and byte stores);
  - `EmitBdaDwordWrites` (the first dword, plus the last when the store crosses a page);
  - `EmitBdaAtomic`;
  - `SpirvRuntimeBuffer`'s `atomicAt`.
- **Host:** `BdaResources::markWrittenPages()` reads it first thing in `CheckFault` and calls `GuestMemory::MarkPossiblyWritten` per range. An overflow throws "not implemented", so the record is either complete or the build fails loudly.

So no new buffer, binding or SPIR-V is needed. The change is host-only, and the record is 16 times finer than the asked 64 KiB blocks.

### Commit 1: compare only the stored pages

- **`BdaResources`:** `markWrittenPages` also keeps each range it reads in `writtenPages`, and `TakeWrittenPages()` hands them over (`std::exchange`). Draw.cpp calls `CheckFaults()` before the write-back, so the ranges accumulate until taken.
- **`ShaderResources::WriteBackBuffers`:** after `CheckFault`, calls `guestMemory.NoteAddressStores(bda->TakeWrittenPages())`.
- **`GuestBufferMemory`:**
  - `NoteAddressStores` keeps the merged pages in `storedPages`.
  - `comparedRuns(begin, end, declared)` gives, for one heap mirror span, the declared write ranges plus the stored pages, each clipped to the span and merged.
  - Declared write ranges keep their whole compare, as the task asked.
  - With no record (a write-back that never got `NoteAddressStores`, or a build without address stores), it returns the whole span, as before.
- **Copy-backed mirrors:** the write-back stores only the compared runs, from the mapped mirror buffer against the reference.
- **Resident mirrors:** the write-back reads the compared runs from the readback that `RecordCopyBacks` recorded, or with one `ReadDevice` of `[first run, last run)` when there is none. It then calls `resident->Store` and the store only for those runs.
- **BF-277:** `stored` now collects runs only from the compared pages, and the write-back still notes `outside(stored, declared)` as written back. So only the changed runs inside stored pages are noted.
- **Counters:** `AddressStoreCounters()` reports span, compared, GPU-copied reference and CPU-read reference bytes. The tests and the probe use them.

### Commit 2: the reference is a GPU copy

`takeHeapReferences` used to copy every span on the CPU at upload. It now runs in `UploadFinish` as `addAddressStoreSpans(); takeHeapReferences(); ResidentBuffer::FlushChanged(context); recordHeapReferences();`.

- **When a recorder is active** and the build is not inside a completion (`!Recorder::InCompletion() && Recorder::Active() != nullptr`), `takeHeapReferences` only records the span as pending. Then, after the resident flush, `recordHeapReferences` records the copies into the active batch, before the work:
  - **Resident mirror:** `resident->RecordReadback(commands, begin, bytes)`. It runs after `FlushChanged`, so the reference includes this upload's guest changes.
  - **Copy-backed mirror:** a `TRANSFER_DST` buffer and `CopyBuffer` from the mirror. Heap mirror buffers gain `VK_BUFFER_USAGE_TRANSFER_SRC_BIT`.
  - **Barriers:**
    - before the copies: ALL_COMMANDS|HOST to TRANSFER, SHADER/TRANSFER/HOST_WRITE to TRANSFER_READ;
    - after them: TRANSFER to ALL_COMMANDS|HOST, TRANSFER_WRITE to HOST_READ;
    - `MarkCovered`, and `StagingCopyBackKey` GPU timing.
  - `recorder->Keep` holds each buffer until the batch completes. The write-back reads only the compared runs of it.
- **Ordering:** `UploadFinish` runs in stage B on the recording thread without the GPU mutex. That is the same place `recordGpuCopies` and `completeSpaceWrites` already use `Recorder::Active()`. A synchronous draw's `CommandBatch` submits the active recorder's open batch first (Resources.cpp:363), so the reference copy is ordered before the work there too.
- **CPU fallback:** with no active recorder, or inside a completion, the CPU copy stays, as before (`readReferenceBytes`).

### Sparse, resident and copy-backed mirrors

- **Sparse mirrors:** `addAddressStoreSpans` adds only the committed pieces (`clipPieces(mirror->committed, ...)`). So the reference copy, the compare and the store cover committed runs only; uncommitted holes are never copied or read. Stored pages are clipped to each committed span, and `storeSparse` stores per committed run as before.
- **Resident (sparse-bound) blocks:**
  - `growResident` binds the span before the copy;
  - the reference is the resident buffer's own readback, recorded after `FlushChanged`;
  - the current bytes come from `RecordCopyBacks`' readback, or from `ReadDevice` of only the compared runs.
- **Copy-backed:** the copy runs straight from the mirror buffer, and the current bytes are read from the mapped buffer.

### #8874

#8874's `ReferenceStorage` pools CPU `std::vector` references. The reference is a Vulkan buffer now, so that shape doesn't fit, and nothing depends on #8874. Merged, #8874's pool would apply to the CPU fallback branch only. The GPU references are `Buffer`s held by `recorder->Keep` like the other staging buffers.

### What still costs

- **The GPU reference copy is still the whole span** (pages to be stored aren't known before the dispatch). On lavapipe that is CPU bandwidth; see Cost.
- **On resident mirrors, `RecordCopyBacks` still reads back the whole span** after the work. It is recorded before the record is read, and only the compared runs of it are used.
- **`recordHeapReferences` calls `recorder->Commands()`.** On a draw inside a render pass, that ends the pass before the copies.
- **BF-277's whole-span pending-write note** still serialises a later storing build on the earlier one's span (BF-277 Q2). This change doesn't narrow it.
- **MinGW:** the new `heap ? VK_BUFFER_USAGE_TRANSFER_SRC_BIT : VkBufferUsageFlags{0}` adds one `-Wextra` "enumerated and non-enumerated type in conditional expression" warning. That is the same idiom and warning as GuestBufferMemory.cpp:5006 and :5654 on base.

Every new case checks with `AddressStoreCounters()` that it compared exactly N 4 KiB pages of the span, and that the whole span's reference was a GPU copy (`copiedReference == span`, `readReference == 0`). There is no placeholder-throw assertion.

## Cost

This is BF-273's probe: the same heaps (36 MiB/16 runs, 36 MiB/1, 72 MiB/16, 8 MiB/4), median of 20 after 2 warm-ups. Each dispatch:
- takes its own `Recorder` under the GPU mutex;
- runs `Upload` and `RecordCopyBacks`, then `Sync`;
- on head, calls `NoteAddressStores` with 0, 1 or 16 evenly spread 64 KiB blocks;
- then runs `WriteBack`.

"Extra" is a storing build minus a non-storing build on the same heap.
- **CPU** is the time outside `Sync`.
- **Wait** is `Sync`, i.e. the recorded GPU work. On lavapipe the "GPU" copy is run by llvmpipe's CPU threads.

**GPU copy time on lavapipe:**
- **Copy-backed:** base waits nothing, so the head's extra wait is the reference copy alone: about 4-7 ms per 36 MiB, 13-16 ms per 72 MiB and 1 ms per 8 MiB. That is roughly 5-9 GB/s of llvmpipe CPU copying.
- **Resident:** the head's wait less the base's (base already waits for the whole-span readback) gives the reference readback: about +2-7 ms per 36 MiB, +12-15 ms per 72 MiB and +0.5-1 ms per 8 MiB.
- **A discrete GPU** wasn't available, so I couldn't measure it there.

**Per dispatch in all** (extra CPU plus wait, 1 block stored, 36 MiB/16):
- **resident:** 59-67 ms on base, 11-12 ms on head;
- **copy-backed:** 35-37 ms on base, 5-7 ms on head.

The CPU part alone falls from 35-104 ms to 0.04-0.14 ms at 1 block, and 0.2-0.8 ms at 16 blocks. At 0 blocks the extra CPU is noise around zero.
