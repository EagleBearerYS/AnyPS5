| `EC_POINT_point2oct` | implemented | ec_lib.c → [ecp_oct.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/ec/ecp_oct.c) `ec_GFp_simple_point2oct`. | `EC_POINT_oct2point` | implemented | ecp_oct.c `ec_GFp_simple_oct2point` and `ec_GFp_simple_set_compressed_coordinates`. Errors: an empty buffer gives 100; a bad form, a y bit on form 0 or 4, a wrong length, x ≥ p or y ≥ p, or a hybrid parity mismatch gives `EC_R_INVALID_ENCODING` (102); a compressed x with no square root gives `EC_R_INVALID_COMPRESSED_POINT` (110), after the error-queue clear LibreSSL does. | `EC_KEY_generate_key` | implemented | [ec_key.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/ec/ec_key.c). A null key or a key with no group gives (16, 67) and returns 0. The private key is drawn uniformly from 1 to n−1 with host entropy (`mbedtls_ecp_gen_keypair`), and the key's existing private and public objects are reused, as LibreSSL reuses them. |
| `EC_KEY_check_key` | implemented | ec_key.c, same errors in the same order: a missing group or public key gives 67; infinity gives `EC_R_POINT_AT_INFINITY` (106); off the curve gives 107; a private key not below the order gives `EC_R_WRONG_ORDER` (130); d·G ≠ Q gives `EC_R_INVALID_PRIVATE_KEY` (123). The n·Q = O test is skipped because every on-curve point passes it at cofactor 1. |
| `EC_KEY_get0_public_key` | implemented | ec_key.c. Returns the key's own point, or null. |
| `EC_KEY_set_public_key` | implemented | ec_key.c (`EC_POINT_free` then `EC_POINT_dup`). A null point clears the key's point and returns 0. A key with no group clears it, queues (16, 67) and returns 0. Otherwise it copies the point and returns 1, which also works when given the key's own point. |
| `ECDSA_sign` | implemented | [ecs_sign.c, ecs_ossl.c and ecs_asn1.c](https://github.com/libressl/openbsd/tree/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/ecdsa). `type` is ignored. A key with no group or no private key gives (42, 67), `*siglen = 0` and returns 0. The nonce is uniform from host entropy, through `mbedtls_ecdsa_sign`. The digest is truncated to the order's bit length. The output is DER `SEQUENCE { INTEGER r, INTEGER s }`, unsigned with a 00 pad when the top bit is set. A null `sig` only reports the length. A private key kept from a previous group is reduced mod n first, which is the same arithmetic LibreSSL does mod the order. |
| `ECDSA_verify` | implemented | [ecs_vrf.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/ecdsa/ecs_vrf.c) and ecs_ossl.c `ecdsa_do_verify`. Anything but the exact DER it would write returns −1, matching 2.5.4's decode-and-re-encode compare; this is checked before the key is used. No group or public key gives `ECDSA_R_MISSING_PARAMETERS` (42, 103) and −1. r or s outside 1..n−1 gives `ECDSA_R_BAD_SIGNATURE` (42, 100) and 0. u1·G + u2·Q at infinity gives (16, 106), (42, 16) and −1. Otherwise x mod n = r gives 1, else 0. A public key at infinity computes u1·G, as LibreSSL does. |
| `ECDH_compute_key` | implemented | [ech_key.c](https://github.com/libressl/openbsd/blob/2e2c612066aa993717528a0249c15c51128d61cb/src/lib/libcrypto/ecdh/ech_key.c), in its order of checks: an `outlen` above `INT_MAX` gives (43, 65) and −1; no private key gives `ECDH_R_NO_PRIVATE_VALUE` (43, 100); no group gives (16, 67) then (43, 65); a null or infinity peer, or a private key that reduces to 0 mod n, gives (16, 106) then (43, 101); without a KDF, an output shorter than the field gives `ECDH_R_KEY_TRUNCATION` (43, 104); a guest `malloc` failure gives (43, 65); a failing KDF gives `ECDH_R_KDF_FAILED` (43, 102). The secret is x, left-padded to the field size. Without a KDF, a longer output is zeroed past the secret. The KDF is an `APS5_VABI` guest function pointer, and it receives the secret and the `size_t` output length in guest memory, in one guest allocation. |

Title: `feat(libSceLibreSsl): implement EC points, EC key generation and checks, ECDSA and ECDH`. Head `feat/libressl-ec-keys` (cb785f855); it is stacked on #10395 and is not opened.

```markdown
### What
Implements 11 libSceLibreSsl exports on top of #10395's EC groups and keys, using the mbedtls it already links, for the 11 curves it supports. The exports: `EC_POINT_new`, `EC_POINT_free`, `EC_POINT_point2oct`, `EC_POINT_oct2point`, `EC_KEY_generate_key`, `EC_KEY_check_key`, `EC_KEY_get0_public_key`, `EC_KEY_set_public_key`, `ECDSA_sign`, `ECDSA_verify` and `ECDH_compute_key`.

Behaviour, error codes and their order follow LibreSSL 2.5.4 (openbsd 2e2c612066), the version identified in discussion #8981: `ec_lib.c`, `ecp_oct.c`, `ec_key.c`, `ecs_sign.c`, `ecs_vrf.c`, `ecs_ossl.c` and `ech_key.c`. Return values were also checked against the OpenSSL 1.0.2 manual pages `EC_POINT_new(3)`, `EC_KEY_new(3)` and `ecdsa(3)`.

- **Points:** octet encodings in all three forms, with the y-parity prefix `ecp_oct.c` writes. Compressed points on secp224r1 and secp224k1 (p ≡ 1 mod 4) are decompressed with Tonelli–Shanks, because mbedtls can't. An uncompressed point off the curve is refused but kept, as 2.5.4 keeps it.
- **Keys:** `EcKey` now holds a public point and a generated private scalar. `EC_KEY_check_key` returns LibreSSL's errors in its order, including `EC_R_WRONG_ORDER` for a private key kept from a previous group.
- **ECDSA:** DER signatures. Verification takes only the canonical encoding, as 2.5.4's re-encode check does. The digest is truncated to the order's bit length.
- **ECDH:** the x coordinate padded to the field size, an optional guest KDF called through `APS5_VABI`, and LibreSSL's truncation and zero-fill rules.
- **Throws instead of guessing:**
  - mixing curves;
  - a public or peer key off the curve (LibreSSL multiplies those unchecked);
  - signing with a private key that is a multiple of the order;
  - null pointers LibreSSL dereferences.

`EC_KEY_set_private_key`, `EC_KEY_get0_private_key` and `EC_POINT_mul` still throw: they take a `BIGNUM`. All four entries are in `docs/dev/debt/libSceLibreSsl.md`.

Related: #10395 (base), #9446 (BIGNUM: the private-key accessors, `EC_POINT_mul` and an ECDH known-answer vector wait for it).
```
