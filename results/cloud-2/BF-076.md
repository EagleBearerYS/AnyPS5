## Shape A (Wolverine: record → pointer → V# → S#), commit 2

- **Tracker.** `TryMakeTableColumn`'s nested branch (`ResourceTracker.cpp:643` on f4549448f7) no longer refuses `sampler`.
- **Materializer and emitter.** No change was needed:

  - `ReadColumn` reads 4-dword sampler words.
  - The `fill` lambda turns child codes into sampler records, with the zero S# as the outside code.
  - `EmitTableWord` does the pointer lookup and then the child lookup; sampler emission already passed through it.
- **Limits.** #7223's limits apply unchanged: `MaxNestedKeys`, `MaxParentKeys`, and the 256-entry S# budget.

- **Round-trip test.** Extended with a `nested pointer sampler table` fixture.

## Commit 1: a gap found while testing A

A T# word in a nested child that another instruction also reads crashed lavapipe inside the shader, on f4549448f7 itself. This is #7223's image path, and the same applies to S#.

The cause:
- the child's V# words are planning-only loads, so they are never emitted;
- the extra consumer keeps its descriptor read at runtime, through a V# that exists only in the snapshot.

I checked this was not a test-harness artifact: with the refusal removed and `records`/`palettes` registered as guest allocations, the S# variant still segfaulted.

The fix: the nested branch now refuses a child whose descriptor words feed anything but equal handles, as #7223 already does for a V# with another consumer.

## Shape B (Ratchet & Clank: record → pointer → S# through an address, low word through a Phi), commit 3

It did not need a new map mechanism. It reuses #7223's sorted pointer dictionary for a direct (non-nested) indirect column.

- **Tracker.**
  - `TryMakeIndirectColumn` (`ResourceTracker.cpp:715` on f4549448f7) now accepts a Phi-merged low word for non-buffer columns too.
  - Such a column gets `TableColumn::pointerKeyed`.
  - The handle's arguments 1–2 carry the actual pointer words (`parentPointer`), as for #7223's merged buffer parents.
- **Materializer.**
  - A pointer-keyed column records each record's pointer.
  - The `fill` writes the `(low, high, code)` dictionary with descriptor records (not child headers) as codes.
  - The outside code is the unmapped poison, so a null pointer faults as unmapped.
  - It reads up to `MaxKeys` (65536) records, as other direct tables do.
- **Emitter.** `EmitTableWord` calls `LookupTablePointer` for a pointer-keyed column. A pointer that was not captured faults as outside the snapshot.
- **Coverage.** The same path serves T#s; the test covers both.
- **Formats.** The plan gains `TableColumn::pointerKeyed` and the snapshot gains `ImageTableColumnSnapshot::pointerKeyed` (mixed into the snapshot hash). So:
  - disk-cache `FormatVersion` 37 → **38**, `fieldCount<TableColumn>` 16 → 17, and the minimum encoded size per descriptor source 73 → 74;
  - `ImageTableAbi::Version` 3 → **4**;
  - the decoder rejects a pointer-keyed column that is not a top-level non-buffer indirect column.
- **Debt.** `docs/dev/debt/shader.md` has one new entry and the nested entry updated (T# or S#; consumer refusal).

## Notes

- **Harness.** A runtime BDA read of test memory needs a `GuestAllocations` registration. Without one, the direct (pre-existing, non-Phi) S#-through-pointer form with a second consumer also segfaults lavapipe. With `records` registered, both the direct and the Phi form return correct words. So the shape B consumer case registers `records` for that run.
- **Narrowing.** Key-domain narrowing resolves only selected keys, so the S#-budget case masks the inner key (`s_and_b32 s20, s20, 0x1ff`) to make the child unkeyed.
- **Pre-existing, not changed.** For a direct indirect column (#7223 and main), the descriptor words read through the pointer are not in the table's write-overlap `readRanges`. A dispatch that writes an S# it reads through a pointer is not flagged "written by its own dispatch". Pointer-keyed columns behave the same.
- **Machine.** 4 vCPU Xeon, lavapipe (Mesa 25.2.8, LLVM 20.1.2), no IPv6, no `/dev/udmabuf`. Single runs; times vary.
