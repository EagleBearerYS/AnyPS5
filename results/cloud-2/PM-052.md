## 5. The "better version" check

**A sample-rate pass can't emulate the 2x2 pattern by itself.**
- **Why not:** without the grid, Vulkan fixes where every pixel's samples are tested for coverage. A shader can only remove coverage, not move it.
- **What emulating it in shaders would take:**
  - conservative rasterization;
  - per-sample edge tests at the guest's positions;
  - interpolation at offsets;
  - `FragDepth` for every draw.
- **What that would cost:** early Z and the depth target's plane compression; it would need VK_EXT_conservative_rasterization; and every pixel shader would be rewritten.
- **What it would gain:** it would be exact for any pattern, including those whose pixels hold different positions, which #6683 leaves inexact.

**A composite of four per-class passes** (each pixel class's own uniform locations, other classes masked by FragCoord parity):
- It is exact for colour. The PR's grid reference uses it as ground truth.
- On a SAMPLE_LOCATIONS_COMPATIBLE depth target, four location sets go into one image, and a transition can name only one set without the grid.
- The grid reference skips on the 3070 for exactly that reason: "the device reads depth drawn at custom sample locations back at other locations", even for the composite. So it fails where #6683 is needed.

**For the same-set patterns titles use** (PPSA01556, PPSA27836), #6451 + #6683 is therefore the better design. Depth is drawn with one location set that the transitions can name, and early Z and native rasterization are kept.

**What it needs to stay the better one:**
1. **R1 closed**, so depth stays right in steady state.
2. **Bounded cost (C1, C2):**
   - keep a target in the host order across consecutive passes with the same stand-in, and convert only before a read by index, a copy, a write-back or a pattern change;
   - transition depth at custom locations only before a read, instead of after every pass.
3. **No throw where #6451 ran (S1)**, or a documented one.
4. **D1's doc correction**, so the debt entry says which counts take the stand-in on the reference GPUs.

Patterns whose pixels hold different positions stay inexact. No title is known to use one, and only the costlier designs above would fix them.
