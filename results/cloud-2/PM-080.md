# PM-080: lane B, what fable-void's residency, mirror and import work would cut from Village (cloud-2)

## Summary

- **None of the residency, mirror, admission, page-table, guard or write-watch commits in `ed8f2d7a2e..d8731cc728` removes host memory on main's model by itself.** They build on his residency manager, which is not on main. The device-local mirror pool they fill adds memory, and on Windows device-local bytes count as private bytes (his ba4979e3c: +513 MiB for a 512 MiB buffer).
- **The pieces that do remove memory delete host copies of guest memory.** The largest that ports on its own is the host copy main's sampled-texture cache keeps for every snapshot texture. Every block-compressed texture is a snapshot on main. His in-range ec52e8bac (GPU gather) removes that copy because it sits on his f7594f39c (Oct 14), which replaces the copy with a 64-bit digest.
- **Ported:** f7594f39c onto upstream main c34e9d855, behind `APS5_SAMPLED_DIGEST=1`, on fork branch **`exp/lane-b-sampled-digest`**, head **9859359e4**. It is one commit with his authorship; Yunus Shaikh is the committer, unsigned.
- **Harness numbers:** 96 cached BC textures, 126.0 MiB of guest bytes. With the switch on, the cache holds 0 MiB of host copies instead of 126.0 MiB, and heap in use, RssAnon and private bytes each drop by 126 MiB (2 runs, identical). The new tests fail with only the fix reverted and pass with it.

**How his residency works.** Residency is a subsystem that main does not have. It first appears in his 02827d79f, 4eae29822, 8dee493c7, 9385c93b4 and 013e8f65b, all before the range.
- **Backing store:** every committed or mapped guest view is host-imported when it is committed (c472afc72).
- **Mirrors:** `ResidencyManager` keeps device-local mirrors of 64 KiB pages in 64 MiB chunks.
- **Translation:** shaders reach every guest pointer through a two-level `BdaPageTable`. A resident page maps to its mirror; any other page maps to its import.
- **Write-back:** CPU accesses hit 4 KiB guards. Dirty mirrors are written back on a CPU access, eviction or unmap.
- **What it replaces on main:** the per-build copies, snapshots, staging, unit shadows and host-visible heap mirrors. 68cc97aed alone shrinks `GuestBufferMemory.cpp` from 5,047 to 2,782 lines.
- **A naming trap:** main's "mirrors" (`ImageMirror`, heap mirrors up to `APS5_HEAP_MIRROR_MIB` = 24 GiB) are host-visible copies. His mirrors are device-local page caches.

## 2. Ranking: what could come off Village's ~26 GB on main

**No Village numbers here.** There is no game data on this VM, and none was fetched.
- `APS5_PROFILE_HEAP` and the `[heap]` line are **not on upstream main** (no match on 218aa8f00 or c34e9d855). They come from BF-061's fork branch `exp/shader-heap-counters`.
- `[buffers]` needs `APS5_PROFILE_DRAW=1`. `APS5_TRACE_SUMMARY_EVERY` writes only frame and phase totals.
- **Main never prints the cache's snapshot copies as live bytes.** The port adds them to the `[texture-cache]` line: `(N MiB of host snapshot copies)`.

The bounds below come from main's budgets and his own measurements:

1. **Sampled snapshot copies (f7594f39c, the port): about 1–2 GB.**
   - Main keeps `CachedTexture::bytes`, a copy of each snapshot texture's guest bytes, for the entry's whole life.
   - The cache budget counts only the image, follows the device-local heap and has a 2 GiB floor. Block-compressed formats never take the storage view (`SampledFromStorageEligible`), so a BC-heavy title's cache is mostly snapshots, each carrying an uncounted copy as large as its guest bytes.
   - His title: 1.53 GiB of such copies beside 1,820 MiB of cached images.
   - On Village, read it off the new `[texture-cache] ... MiB of host snapshot copies` figure with `APS5_PROFILE_DRAW=1`.
2. **Plan pruning (cca1f5a8d + 3728570f6):** plans from 1.40 GB to about 0.15–0.4 GB. Recompiler-only, so another lane's port.
3. **Pipeline byte budget (9766ccc19) and the compile-only device for large compute modules (ee3f5e718):** unknown, 0 to several GB of driver memory. Check a menu run for `[dispatch] creating a pipeline for N SPIR-V words` first.
4. **Draw-input copies (131fc8b39 / 3d2000f87):** up to the Recorder pools (1 GiB storage snapshots + 1 GiB draw inputs), but only ranges main cannot bind in place are copied. It depends on residency ordering.
5. **Dirty mirrors replacing unit shadows and staging:** up to about 1–1.5 GB of device-local memory, which counts as private on Windows. It needs the whole residency core.
6. **Aligned import window (f6f526dd6):** tens to hundreds of MiB.
7. **Read-only image mirrors in VRAM (0328cb247), hot pages, page-table patches, guards, write watches, render-target ownership:** about 0 private bytes.
8. **Eager admission and read discovery (the mirror pool):** net **additions**, up to min(imported guest bytes − other VRAM, heap budget − others). That is plausibly 5–9 GB on a 12 GB+ card, all private on Windows. If residency is ever taken, eager admission needs a hard cap or a switch.

## 3. The port: `exp/lane-b-sampled-digest`

**Branch.** Head **9859359e4** on upstream main **c34e9d855**, one commit:
- **Commit:** `perf(agc): keep a digest of each cached sampled snapshot, not its bytes`.
- **Author:** `fablevoid <340827264+fable-void@users.noreply.github.com>`, with his commit date (2026-10-14 20:08:35 UTC).
- **Committer:** Yunus Shaikh, unsigned, no AI trailers.
- **Credit:** the body says "Ported from fable-void's f7594f39c (wip/new-gpu-path) onto main" and lists what was adapted.
- **Size:** 7 files, +189 −19. `tools/check_conventions.py --base c34e9d855`: "All conventions checks passed." No comments added.

**What it does**, behind **`APS5_SAMPLED_DIGEST=1`**. Without the switch the cache keeps the bytes exactly as main does.
- **The entry:** a cache entry for a snapshot texture keeps the surface size and a 64-bit digest instead of `std::vector<std::byte> bytes`. The snapshot is a local of the lookup and is freed once the texture is made.
- **A hit needs the same proof as on main:**
  1. unchanged write stamps;
  2. main's committed-page check;
  3. main's untracked hint;
  4. failing all three, `GuestMemory::DigestCommitted(address, bytes) == digest` through the same flush hook and read site. On main this was `EqualsCommitted(address, bytes)`.
- **`GuestMemory::Digest` / `DigestCommitted`** are his, verbatim:
  - four lanes of a multiply-rotate chain, in which every step is a bijection;
  - `DigestCommitted` hashes what `ReadCommitted` reads, with uncommitted pages as zeros, so a page decommitted since the upload now counts as a change.
- **Counter (new on main):**
  - `TextureCacheUse::snapshotHostBytes`;
  - the `[texture-cache]` line (with `APS5_PROFILE_DRAW=1`) now reads `... N MiB in M entries (K MiB of host snapshot copies), budget ...`.
  - This is the number to read on Village with the switch off to size the win.
- `docs/dev/ENVIRONMENT.md` gains the `APS5_SAMPLED_DIGEST` row.

**Adapted from his commit.**
- **Kept from main:**
  - the `committed` and `untracked` checks, which his base did not have;
  - main's Texture constructor (no `decodedCopy` argument).
- **Added:** the switch, the counter and the test's copies case.

## 4. Tests and red/green

**New ctests.** Both run `agc_driver_sampled_cache_budget_tests snapshot-memory`.
- **`agc_driver_sampled_snapshot_digests`** (with `APS5_SAMPLED_DIGEST=1`):
  1. `digestTests`: `DigestCommitted` equals `Digest(ReadCommitted)` over 4 pages with the third unmapped, whole and at an odd length. Single bytes flipped at offsets 0, page+5, odd−1 and 4·page−1 each change the digest, and restoring them restores it.
  2. Eight 4 MiB snapshots (1024² 32-bit, outside host imports) are cached. The heap must grow by less than one surface, and the counter must read 0 KiB of copies.
  3. An unchanged lookup hits. Bytes flipped at the start, middle and end of a cached surface each make a new texture, and the next lookup hits that new texture.
  4. Clearing the cache leaves 0 counted.
- **`agc_driver_sampled_snapshot_copies`** (no switch): the same, but the counter must read 8 × 4 MiB and the heap must grow by at least that. It guards main's path.

## 5. Harness memory, switch off and on

**The harness.** An uncommitted execution-test source built in the same tree, never pushed: `SampledMemoryHarness.cpp`, using the SampledCacheBudget device scaffolding with BC enabled.
- **Textures:** 96 sampled textures, tile mode 0x1b, full mip chains: 16 × BC7 2048², 32 × BC1 1024² and 48 × BC7 512². That is 126.0 MiB of guest bytes in registered memory outside host imports, so every texture is a snapshot, as BC textures always are on main.
- **Measured:** each is looked up once. The harness then reads mallinfo2 heap in use, `RssAnon` (`/proc/self/status`), private bytes (`Private_Clean` + `Private_Dirty` in `smaps_rollup`, after `malloc_trim`) and the cache's counter.
- **Then:** 8 rounds of re-lookups. Each one hits through the compare, since the memory is not write-watched.
- **Settings:** `APS5_TEXTURE_CACHE_MIB=8192`, lavapipe, 2 runs per arm.

| switch off, run 2 | 126.0 MiB | +379.6 MiB | +129.5 MiB | +274.0 MiB | 524.3 ms | 0.266 ms |

- **Memory:** the switch removes **126.3–126.4 MiB** of heap, private and RssAnon, the textures' guest bytes, and the counter reads 0. The rest of each arm is lavapipe's image memory (122.7 MiB of images, counted the same in both arms).
- **CPU:** a hit that has to prove the surface unchanged by content costs about 7% more with the digest: 0.27–0.28 ms against 0.26 ms per lookup, at an average of 1.31 MiB per surface. First lookups were 14–17% faster, because no zeroed copy is allocated. Single runs on a 4 vCPU VM; times vary.
- **What this means for Village:** the saving equals the guest bytes of the snapshot textures in its sampled cache, which is BC-dominated. Read it off the `[texture-cache]` line with the switch off. His title measured 1.53 GiB.
