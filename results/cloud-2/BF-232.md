## Part 2: why the fast proof's collect fails, and the fixes

**Where it fails:**
- `ShaderResources::fastRevalidate` collects each sampled element at `ShaderResources.cpp:3104` and each storage image at `:3161` (main's lines). A 0 is `FastFail::Collect`, and the proof returns on the first such element.
- A failed walk is never memoized (`GuestMemory.cpp:1556`). So one element that keeps failing fails every proof of its resource set, which fits "no guest writes, yet ~41 failed collects a second".

**Caveats:**
- **The totals overcount.** a9f338d3da's totals count every caller, including the full walk's own collects of all elements, so they will exceed 41/s. The sample ranges repeating at the proof rate are the blocking elements.
- **How the paths were found:** a code read of main, not a profile. I verified the key citations myself; anything marked *inferred* was not.

### The paths, by reason

**U: unwatched.** `!tracker.watched` at `GuestMemory.cpp:1534`.
- **Cause:** Windows `watched = size && GuestArenaWriteWatched` (`:946`), false only under `APS5_NO_WRITE_WATCH`. Linux needs userfaultfd write protection and PAGEMAP_SCAN (`:953`).
- **At a static menu:** it would fail *every* collect, not ~41/s, so it is ruled out.
- **Fix:** none. **Test:** none.
- **Lane P:** with nothing watched, every element is "compared".

**O1: outside, host import left unwatched.** `!tracker.covers` (`:958-964` → `WriteWatchCoverage::Covers`, or Linux `GuestWriteWatchCovers`). It comes from `ImportWatched` (`:1773`) → `unwatchLocked` (`:1715`, `:1800-1801`), which is `Exclude` on Windows (whole 64 KiB blocks) and `Unregister` on Linux.
- **Windows default:** `unwatchImports = true` (`GuestBufferMemory.cpp:1202`).
- **The affected elements are exactly the imported ones:** sampled-from-storage is eligible only over host-imported memory (`ShaderResources.cpp:521`). So every view (`surface.source != nullptr`) and storage image is in such a range.
- **It doesn't clear:** the settle that would re-watch is skipped while a live storage image overlaps (`GuestBufferMemory.cpp:1126-1127`, counted as `settlesKeptCompared`). Imports not 64 KiB-aligned only settle on demand. The import refresh re-applies the Unwatch on each allocation change (`GuestBufferMemory.cpp:2092`, *per the code read*). On Linux `Rewatch` is a no-op.
- **What the full walk does:** a snapshot is kept without a byte compare while the Windows hint key {`UntrackedHint` (`GuestMemory.cpp:2070`; hints start at the Unwatch, `startHints` `:983`), `NewestStamp`, `ForgetSerial`, recorder note} is unchanged (`ShaderResources.cpp:948`, `kept`). A view or storage image goes `UnchangedSince` fails → `Refresh` → `ChangedBlocks` reports untracked → `compareUntracked` (`Texture.cpp:2536`), memoized on the same key, otherwise a byte compare. On Linux the hint is always 0 (`GuestMemory.cpp:2094-2098`), so it byte-compares.
- **Fix A:** in `fastRevalidate`, when the collect fails on a range `Watched()` rejects, accept the element by the same key `kept`/`compareUntracked` recorded at its last proof. That means the hint, the newest driver stamp, the forget serial, and no snapshot write pending in the recorder; for a view or storage image, also the image's compare memo for that key.
  - **Writer cost:** none. The hints are kept from the Unwatch onwards.
  - **Prover cost:** one `UntrackedHint` per element, a GetWriteWatch over the hint blocks, memoized per epoch. That is about the price of the collect it replaces.
  - **Risk:** no new trust. It is the rule the full walk already applies to the same element. A miss would need a CPU write that GetWriteWatch on the excluded private pages doesn't report; shared pages give hint 0 and go on to compare.
  - **Windows only;** Linux gets nothing from it.
- **Test (red/green):** an agc execution test on Windows (or Linux with a forced hint path: not possible, the hint is `#ifdef _WIN32`).
  - Setup: a storage image over a host import left unwatched (the Windows default), sampled as a view in a cached resource set.
  - Red: `Revalidate` twice with no writes; the second is `ProofPath::Full` with `FastFail::Collect`.
  - Green: it is fast.
  - Controls: a CPU write into the import, a `MarkWritten` driver store, and a recorded GPU storage write between the two proofs must each give a full walk and the new content.
- **Lane P:** a sampled texture or view whose range `Watched()` rejects goes to its compared list (`reresolveElements`, a per-element lookup, so the `kept`/`compareUntracked` path), not to the full walk. **Lane P removes it for views and snapshots.** Storage images still go through the per-element proof (`fastRevalidate(..., withStorage = true)`), fail the collect and fall back: **left**.

**O2: outside, after a driver store whose fresh collect failed.** `markWritten` (`GuestMemory.cpp:1945`) unwatches the 64 KiB-rounded span when CollectFresh fails, for example over a block holding compared pages (I1). It restores only on a newer commit generation (`watchPrivateMapping`, `:1331`).
- **Cause:** storage write-back, depth planes or DCC metadata over a block with compared pages. The callers are those of `MarkWritten`, as listed in BF-171 and BF-178.
- **At a static menu:** it persists once set.
- **Fix:** A, since it is the same state (an excluded range with hints from the Unwatch). **Test:** A's controls, plus a write-back over a compared block, then two proofs.
- **Lane P:** as O1.

**O3: outside, never watched.** Windows: a host region from the arena's startup scan (`GuestArenaHostRegionOverlaps`, `GuestArena.cpp:347-352`), *inferred* to be guest static data inside the relinked image. Linux: a range not registered with userfaultfd (only direct-memory and lifecycle mappings register), direct memory aliased at two addresses (both get unregistered), or a range running past its allocation.
- **At a static menu:** it persists.
- **What the full walk does:** `hinted()` refuses host regions, so it is a byte compare (`EqualsCommitted`).
- **Fix D:** a per-element compare in the fast proof in place of the failure.
  - **Prover cost:** the bytes of the element per proof, cheaper than a full walk only when the element is a small part of the set.
  - **Writer cost:** none.
  - **Risk:** low; a compare is ground truth once the recorder's pending writes are synced, as the full walk does.
- **Test:** a texture over unregistered memory (Linux: a direct-memory alias) proven twice: red full, green fast; a CPU write between must fail it.
- **Lane P:** this *is* its compared path (`reresolveElements`). **Lane P removes it for views and snapshots; storage images are left.** This reason is common to both, so lane P's side should own it. Don't build D in the fast proof if lane P lands.

**I1: incomplete, compared-when-shared pages (Windows).** `walkWrites` (`GuestMemory.cpp:1467-1475`) → `WindowsMappings::Collect` → `collectable` (`WindowsMappings.hpp:561`) refuses a non-resident view whose shared page is `comparedWhenShared`. The default single pass (`clear = true`) puts every collect through that gate.
- **The mark is never cleared** (`WindowsMappings.hpp:229-230`; it is inherited by later views of the same page). It is set by `Rewatch` (the whole range, before its walk), by `ImportWatched`'s `CompareResidentWhenShared` for alias-demoted views, and by alias imports of MEM_MAPPED pages.
- **Each failed walk** stamps the unreported compared pages once and sets `refused` again (`noteRefusedWalk`, `GuestMemory.cpp:1449-1464`).
- **At a static menu:** it persists for good.
- **What the full walk does:** a snapshot is byte-compared, since `hinted()` needs excluded blocks. `Refresh` sees the blocks tracked but refused, so it skips `compareUntracked` and does a whole-surface `equalsOriginal` byte compare (`Texture.cpp:2274`) or re-uploads.
- ***Inferred, not checked:*** `Refresh`'s block-unit branch may trust stamps and ignore `refused`.
- **Fix C:** split the range. Collect the non-compared pages as now, and byte-compare only the compared 4 KiB pages (from `GuestArenaComparedPages`) against the snapshot's bytes or the image's original.
  - **Prover cost:** the compared pages' bytes per proof.
  - **Writer cost:** none.
  - **Risk:** medium. It is new code, and the compare must see pending GPU writes first; the page list has to match `refused`.
  - The existing `refused`, `ComparedPages` and `TakeUnreportedPages` give no "known clean" answer, so C is new code.
- **Test (Windows):** an alias import (MapAlias of a MEM_MAPPED page) under a sampled texture, then `Rewatch`, then two proofs: red full, green fast. A CPU write to a compared page between them must give a full walk.
- **Lane P:** the range is `Watched()`, so lane P subscribes it, and `SweepSubscription`'s collect fails the same way and falls back. **Left (and coarser: one span fails the whole proof).** It is common to both, so it belongs on the GuestMemory side: one page-split collect that both `fastRevalidate` and `SweepSubscription` call.

**I2: incomplete, uncommitted or non-private memory inside coverage (Windows).** The same `collectable` gate, for MEM_RESERVE placeholders (reset, a PROT_NONE remap), sparse textures, or a range past its allocation.
- **At a static menu:** it persists.
- **What the full walk does:** `CollectCommittedWrites` (`GuestMemory.cpp:1875`), with the entry keeping its committed ranges, proven by `UnchangedCommittedSince` (`:1888`; `ShaderResources.cpp` `unchanged`). That is stamps only, with no compare.
- **Fix B:** when the collect fails as incomplete, use the committed-range collect and proof the full walk already uses, keeping the ranges in `validatedTextures`.
  - **Prover cost:** about one collect. **Writer cost:** none.
  - **Risk:** low; it is the full walk's rule.
- **Test (Windows):** a texture whose range ends in a reserved, uncommitted page, proven twice: red full, green fast. A CPU write in the committed part must fail it.
- **Lane P:** left (the sweep fails). The fix sits on the GuestMemory side so both use it, as with I1.

**I3: incomplete, `PAGE_NOACCESS` view.** `collectable` and Collect's main loop.
- **Cause:** only guest protection 0. GPU-only access maps to readable (DirectMemory's protection maps), so it is *unlikely* for sampled surfaces.
- **Fix:** none proposed until the profile shows it.

**I4: incomplete, Linux ioctl failure.** `takeFresh` protect or PAGEMAP_SCAN fails, *inferred* to come from a stale userfaultfd registration after a MAP_FIXED remap.
- **Fix:** re-register on the mapping change, on the writer side. **Test:** remap a registered range with MAP_FIXED, then prove.
- **Lane P:** left.

### Ranking by expected Village gain (Windows PC)

**The ceiling,** per 10 s profiled: 414 of 626 full walks after a collect fast-fail × ~1.5 s / 626 ≈ **1.0 s**.

The 0.43 s of `readTarget` collect walks is a different mechanism:
- It is the resident render-target lookups' *successful* walks (699k pages, the `readTarget` phase's "pages walked").
- None of A to D removes it. Only a target-side change would: resident targets in the write index, or a stamp check before the walk.
- Fixing the failures only shrinks it if some of those walks are full-walk refreshes. The `[rescache]` full-walk time from commit 1 shows that share.
