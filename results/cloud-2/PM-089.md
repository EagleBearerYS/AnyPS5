## Method

**Parser**
- `tools/progress.py` from main, unchanged. Its `code()`, `stub_calls()`, `DEFINITION`, `CALL` and `QUALIFIED` run over every `.cpp` of a library directory (skipping `tests/`). This is the same per-file rule `scan_library` uses, cached by blob.
- Each PR is measured as `merge-base(main, head)` → head. That isolates the PR's own change even when its base is old.

**Check against `progress.py` itself**
- I ran main's `progress.py --json --root <worktree>` on the merge-base and head of six PRs, plus `--compare`. All six match this scan exactly:
  - #8923: +27 implemented;
  - #9009: +82 implemented;
  - #9284: +7 implemented, −7 removed;
  - #8472: +196 declared;
  - #7780: −17 done, −17 total;
  - #9504: no change.

**What counts as a claim** (a PM-088 row is claimed when a PR does one of these to that function in that library):
- **implements:** the body no longer reaches `NotImplemented_nid_no_patch`.
- **changes:** the body changed but still reaches it, usually through a branch left throwing. Example: #9200's `lchmod` still throws for a symbolic link on a host that cannot change its mode.
- **moves:** the PR deletes the stub and defines the function in another library directory in the same PR. That is libkernel for 57 libkernel_sys rows (52 implemented there, 5 still todo in #9314), and libSceSaveData.native for #7780's 66 rows.
- **removes:** the stub is deleted with no new definition (#9379 `swapcontext`).

**Matching rule**
- Claims match by function name within the same library, as `progress.py` counts them.
- Only one PR implements an unclaimed row's name in a different library: #8890 (Kraken) adds `pthread_timedjoin_np` to libkernel. That one is noted under KSYS-2.

**Authors and titles**
- "Author" is the most frequent commit author on the PR's commits. This session has no GitHub API access to upstream, so the PR titles shown are each PR's first commit subject.

**Declared exports**
- `progress.py` skips every name ending in `_nid_no_patch`. #9504 ("declare 150 PS5 pending exports", xdCloudy) and #9485 (46, xdCloudy) name their stubs `<lib>Unknown_<nid>_nid_no_patch`, so they **do not lower the badge**.
