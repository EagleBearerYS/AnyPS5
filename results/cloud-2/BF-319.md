## Step 3: the test

**`verifyNestedSnapshotRetry(bool sampler)`** in `tests/ShaderMemory.cpp`: one shared body, with a parameter.

What `sampler = true` changes:
- **Leaves:** S# leaves (`{0x92, (4*256)<<12, 0, 0}`, 4 dwords) instead of T# leaves. The leaves are a flat word vector, so the range and coverage code is shared.
- **Child V#:** stride 16.
- **Nested column:** `sampler = true`, `dwordCount = 4`, `stride = 16`, on the indirect buffer parent column.
- **Plan:** `plan.info.samplers` holds one `SamplerResource{source = 2, table = 0}`, and there are no table images.

**The requirements are unchanged:**
- the epoch is queried;
- an invalidation forces the inner retry and the outer revalidation (`firstReads == 3`);
- every attempt covers the full parent and child ranges, so the budgets reset;
- `Parents` and `Children` keys are captured;
- the stable and retried snapshots are equal.

**Registration:** ctest `agc_shader_nested_sampler_snapshot_retry` runs `agc_shader_memory_tests --nested-sampler-snapshot-retry` with `TIMEOUT 20`, next to #7223's test.

`agc_shader_nested_snapshot_retry` (the image case) passed in the same run.

**It is red, but not on the line the task predicted.** The predicted line was "a single nested table did not check the descriptor epoch". That requirement passes on the base, for this reason:

- **Why the epoch is always queried:** the outer loop in `ResourceMaterializer::Materialize` queries `descriptorScope(…, 0)` before and after the snapshot and again after `TableSnapshotter::Run()`, on every attempt (`ResourceMaterializer.cpp:2777`, `2780`, `2782`). So `epochQueries != 0` holds whether or not the snapshotter checks.
- **The probe:** I replaced the `firstReads` require with a print, as a temporary change I didn't commit:

  | Case | `firstReads`, stable | `firstReads`, invalidated | `epochQueries`, invalidated |
  | --- | --- | --- | --- |
  | image, base | 1 | **3** | 36,700,270 |
  | sampler, base | 1 | **2** | 14,680,119 |

- **What the probe shows:**
  - The `epochQueries` assertion cannot fail in this fixture, in #7223's image case too.
  - Without the fix, the lone nested S# table gets no inner retry.
  - The outer whole-snapshot revalidation still sees the epoch change (`afterTables != afterSnapshot`) and re-runs everything once. With the requires bypassed, the stable and retried sampler snapshots were still equal.
- **So, in this fixture, the gap is not wrong contents.** It is the missing snapshot-level retry:
  - a per-attempt budget reset and force-sync on the third attempt, inside `Run()`;
  - the "multi-table snapshot did not stabilize" bound;
  - and, without it, every invalidation re-runs `materializeSnapshot` as well.
- The fix makes the sampler loop behave like the image loop. The test catches the difference through `firstReads`.

## Step 5: the fix

The sampler loop in `TableSnapshotter::Run()` (`ResourceMaterializer.cpp` ~716) now uses the image loop's test. #7223's image-loop lines are unchanged.

```cpp
if (sampler.source < plan.descriptorSources.size() && plan.descriptorSources[sampler.source].tableColumn.has_value()) {
    const auto& column = *plan.descriptorSources[sampler.source].tableColumn;
    hasIndirect |= column.indirect || plan.descriptorSources.at(column.heapSource).tableColumn.has_value();
}
```
