## 1. Revalidate time by outcome (9ff5a5b2b)

`countRevalidate` (`Graphics/src/ShaderResources.cpp`) still adds every call's time to the one total. It now also adds the time to one of three new totals, chosen by the rule the counts already use:
- **failed:** the object could not be reused;
- **fast:** the stamp proof passed, including after the own-object (T1) refresh;
- **full:** the lookups were repeated and passed.

A fast proof that fails and then takes the full walk is already "full" in `Revalidate` (`finish(fast=false, …)` after `fullWalk()`), so no separate fast-then-full count was needed. Its time includes the failed proof.

Two cases to know when reading the totals:
- A call whose fast proof passed but whose import serial loop then failed counts as **failed**, as it already did in the counts.
- With `APS5_NO_FAST_REVALIDATE=1`, every reused call is "full".

**New line format** (the counts are unchanged; the `time:` field is new):

```
[rescache] revalidate N calls T ms: fast a, full b, failed c; time: fast X ms, full Y ms, failed Z ms; fast-fail by reason: …
```

The three times add up to T, apart from rounding (one clock read per call goes to both).

## 2. Non-vertex indirect draws by kind (73e5b4ec0)

On this tree an indirect draw gets `Path::NonVertexPath` only in `Driver::ClassifyIndirectDraw` (`Execution/src/Driver/Draw/IndirectDraw.cpp`), when `(stages.path != Vertex || rectList) && !meshGpuSide`. `meshGpuSide` is the mesh path's GPU-side form: indexed, `count == 1`, not count-indirect, and no patched base-vertex, start-instance or draw-index location.

The new `Driver::NonVertexDrawKind`, next to it, names what made the draw non-vertex:

| kind | condition |
|---|---|
| rect list | `graphics.rectList` (the vertex path's rect-list draw) |
| tessellation | `stages.path == ShaderPath::Tessellation` |
| geometry | `stages.path == ShaderPath::Geometry` with a `GeometryBack` program: an ES/GS front (binary type 4) followed by its GS back program, i.e. a geometry shader |
| mesh | `stages.path == ShaderPath::Geometry` without one: an NGG vertex front (type 2) run as the mesh stage. This covers GS_EN routing and a vertex program that needs a workgroup. |
| other | any other shader path. Only `ShaderPath::TessellationGeometry` is left, which `DecodeShaderStages` never produces ("combined tessellation and geometry is unsupported"), so this should read 0. |

`ClassifyIndirectDraw` is unchanged. Its unit test (`core/libs/prx/libSceAgcDriver/tests/execution/DrawOffsetIndices.cpp`) calls it directly.

**Where it is counted:** `Driver::draw` passes the kind to `Graphics::CountIndirectDraw` at its two CPU-path counting sites.
- Both sites are the only places a `NonVertexPath` draw is counted, so the kinds always add up to K.
- They are counted under the same lock as K and reset with it every 10 s.
- `CountIndirectDraw`'s new last parameter defaults to `NonVertexDraw::Count`, meaning no kind. Its other callers in `Graphics/src/Draw.cpp` never see `NonVertexPath`.

**New line format.** The kinds are printed right after the count, all five always shown:

```
[draws] … ; indirect: gpu-side G (r rewritten, p draw parameters), cpu-side C ( … non-vertex path K (mesh a, tessellation b, geometry c, rect list d, other e) … ), argument reads R ms; …
```

No test here drives a non-vertex indirect draw for the 10 s the `[draws]` line waits, so this is the format string, not a captured line. `APS5_TRACE_INDIRECT_DRAWS` is unchanged and still prints `cpu (non-vertex path)`.
