## The guard

`unbuilt_exports` can't see visibility: it reads the configured targets' source lists before anything is built.

**A cheap post-build check exists, and I measured one:**
1. For every `.prx`, read the objects of its own target: `build/core/libs/prx/**/CMakeFiles/<target>.dir/**/*.o`, which leaves out static libraries linked in.
2. Collect the unmangled (`extern "C"`) defined `GLOBAL FUNC` symbols that `readelf -sW` marks `HIDDEN`.
3. Fail on any that are missing from `nm -D --defined-only <target>.prx`.

**How it behaves:**
- **Speed:** on this build it reads 368 `.prx` and 555 objects in **1.7 s**.
- **At 71ea0dd037** it finds nothing in any library.
- **On the red build** (the visibility line removed) it fails with exactly `libSceNgs2: 6 [PendingExports.cpp] sceNgs2FftInit … sceNgs2SystemEnumRackHandles`.
- It needs no source parsing.

**An alternative closer to the task's example:** compare each library's `APS5_VABI` definitions, as `progress.py` already finds them, with `nm -D`. That is more exact about what counts as an export, but it needs the source-to-target map that `unbuilt_exports` already builds.

**How it could run:**
- It fits as a ctest registered next to `unbuilt_exports` (Linux only, run on the build directory), or as a step after the build in the Linux job.
- It reads the build tree, not the sources.
- On Windows the same question is about the DLL export table: `objdump -p` against the same definitions.

I didn't add it.
