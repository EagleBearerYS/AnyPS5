## How the test tells the modes apart

**Detecting the mode.** `tableIndexRequested()` parses `APS5_TABLE_INDEX` exactly as #12745's `GuestMemory::WriteIndexEnabled()` does (`Execution/src/GuestMemory.cpp:216-221`): set, not empty, and not starting with `0`.
- It cannot call `WriteIndexEnabled()` itself, because that function does not exist on #12921 alone.
- `ProofReport` (`ShaderResources.hpp:313`) carries only `path` and `failure`, so nothing in the report says which proof ran.

**With the variable off:** every assertion is the old one.
- `followed(x)` returns `!fast()`.
- `hinted ? fast() : followed(false)` is `fast() == hinted`.
- The revalidation test's added clause is `false && …`.

The other changes add no assertion in this mode:
- **`version()` lookups.** The new ones run in both modes. They use the same `FindLive` + `Require(image != nullptr)` that the hint test already ran.
- **The image-cached requirement.** In the revalidation test this requirement is new. The view's storage image is cached there in every run (probe below).

**With the variable on**, a Fast proof is accepted only when the image versions moved the way guest memory did:
- **Store the image can read** (`followed(true)`): the first surface's version advanced and the second's did not.
- **No store, or a store the image must not read yet** (`followed(false)`): neither version moved.
- **Revalidation test:** Fast is accepted only if the version advanced across the store.

A proof that is not Fast (the full walk) passes in both modes, as before. On #12921 alone the variable changes nothing in the driver: the path stays Full and the version advances, and both modes accept that (A1 below).

**Every content and version assertion is unchanged.** These are `version(first) != before` after each store, `version(first) == before` after the walk store, `walkStore.done`, and the same-epoch Fast assertions. No assertion that a path throws was added.

**Two steps the task's rule does not fit literally.** The task says to accept Fast on a store step only if the version advanced. Two store steps advance the version in neither mode, so that rule would fail them. Both use `followed(false)` instead:
- **A recorded GPU write that is still pending** (`NotePendingWrite`). The storage image holds its refresh while a recorder write over its range is pending (`StorageTexture::guestBytesSettled`, `Texture.cpp:5952`). Its version stays put in both modes, and the full walk gives the same version.
  - With the index on, `followed(false)` makes this step fail if the re-lookup took the bytes before the write completed.
  - The next step, after `Sync` and a new epoch, is `followed(true)`: the version has to advance there.
- **The walk store's `MarkWritten(second, 4096)`.** It marks the range but leaves the second surface's bytes as they were. The store-during-walk hook writes the first surface only after the first has been compared. So the step expects both versions unchanged in both modes, which matches the existing `version(first) == before`.

  - `AGC graphics: a sampled template over untracked memory kept its fast proof across a store and a new collect epoch`

**(b) On B, the index re-lookup skips the refresh.**
- **First attempt, not enough.** A `thread_local bool skipViewRefresh` was set around `reresolveElements`' `cachedTexture` call (`ShaderResources.cpp:3717` at `4da064f747`), and `refreshForView` (`:510`) returned early under it. That stayed green ×10.
- **Why.** gdb on `StorageTexture::Refresh` with the index on showed the refresh never goes through `refreshForView`. Its path is `reresolveElements` → `cachedTexture` → `sampledStorageSource` → `cachedStorageTexture` → `Refresh` (the storage cache hit at `:1252`).
- **Final mutation.** The same flag also skips that hit's `Refresh()` / `RefreshLayers()`, so only the index re-lookup stops refreshing; the full walk still refreshes.
- **`APS5_TABLE_INDEX=1`:** both tests 0/10, at the store step.
  - `AGC graphics: a sampled template over untracked memory kept its fast proof across a store and a new collect epoch`
  - `AGC graphics: a CPU store after a collect epoch kept the fast proof`
- **Index off:** both tests 10/10 pass.
