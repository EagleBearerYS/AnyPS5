## Method

- **Classes:** PM-088's classes under BF-208's guide, by four parallel read-only passes, each writing `<library>.tsv` (`function, class, basis`) and `<library>.notes.md`. The guide adds one rule: every cited `path:line` is read from the file.
- **Inputs:** each library's todo list with its definitions' `path:line` and parameters. The input generator counted lines on `progress.py`'s preprocessed text, which joins backslash-continued macro lines. Its numbers were 3 low in `libSceAjm.native/src/Ajm.cpp` and 8 low in `libSceSaveData.native/Export.cpp`. The passes cite the files' real lines.
- **Checks I ran:**
  - **Names:** each table holds exactly its library's todo names once (391 of 391); every class is valid; every C row says "real behaviour" or "silent stub".
  - **Citations:** all 789 citations were checked.
    - 25 failed the first check. Every one is a bare `:line` my heuristic attached to the wrong file: the basis means the source file named just before, or states that a file is absent. None is wrong.
    - 42 `function (path:line)` citations were checked against the cited line. 9 did not name the function on that line; all 9 point at the row's own line or the second of a pair, and I confirmed each by reading it.
  - **Spot-checks by hand: 88 rows.** All 38 non-D rows, and one seeded-random D row per library (50), were read against their declarations, debt lines and neighbours. Two conclusions stand only with caveats:
    - NpParty's two C rows don't know the console's check order (debt `:6`).
    - AutoMounterClient's C row rests on the tree's own UsbStorage model, not a measurement.
- **Claims (the method fix):**
  - **PR state:** the task's GitHub lists were used, **1,292 open** and **455 closed unmerged since 2026-10-11**. That is 1,747 PRs, all fetched with `git fetch upstream refs/pull/<n>/head:refs/remotes/upstream-pr/<n>`, with none missing. Each is measured from `merge-base(2742004ed2, head)` to its head. Only #7267 (closed) shares no history with main and could not be measured.
  - **Definition claims:** BF-208's rules over every changed `.cpp` under `core/libs/prx/` outside tests: implements, changes, declares, moves to another library, or removes the stub. 771 of the 1,747 PRs change a definition there.
  - **Name search:** every added line of every PR's diff was searched for every row's name, with and without `_nid_postfix`. 58 PRs name a row. Rows that are only named are 52 in debt docs and 1 in code (`sceSysUtilSendSystemNotificationWithParams`, in closed #9641 and #9649). These are listed in `claimed_by` and don't block.
  - **Status:**
    - `claimed`: an open PR implements, changes, moves or removes it.
    - `claimed (closed #n)`: only closed PRs do.
    - `unclaimed (declared by #n)`: only a declaration claim, such as #8747's pending exports; listed, and doesn't block.
    - `unclaimed`: nothing above.
  - **Authors:** GitHub logins where BF-188's data block had them; otherwise the head commit's author, marked "(commit author)".
  - **#10541 shows as "removes":** CaganCelik's open PatchCheckerClient change redefines the 12 functions without `APS5_VABI`, so `progress.py` no longer counts them. It is a claim on all 12.
- **Title hits:** BF-188's 47 functions, plus every function name on a line with a PPSA/CUSA title ID under `results/` (17 names, 6 not already among the 47; none of those 6 is in this part).
- **Erratum for BF-208:** BF-208 inferred closed PRs from missing merge refs. GitHub's lists show 17 of the 50 PRs it dropped are open, among them #9826 and #7201. The erratum at the top of `results/cloud-2/BF-208.md` lists what changes: 9 libkernel rows also claimed by #9823, and the claims on three title functions. Its batch B208-1 is unaffected.

## Title hits

Two rows are title functions, and both are D:

**`sceAjmBatchJobControl`** (libSceAjm.native; I#3410, PPSA26344). Unclaimed; no PR changes or names it.
- **The title's recorded call already works.** PPSA26344 passes flags `0x200000006000` with a 16-byte input and an 8-byte result.
  - It was implemented by 7cc6baf118 ("feat(libSceAjm.native): implement the M4AAC decoder"), merged in b52356acca (#5307).
  - `core/libs/tests/GuestAjm.cpp:1249` covers it.
- **Why it still counts as todo:** branches no recorded title reaches throw (`core/libs/prx/libSceAjm.native/src/Ajm.cpp:1816-1819`, `:1577`, `:1586`):
  - flags 0, or bits other than RESET, INITIALIZE and GAPLESS;
  - sideband outputs over 8 bytes;
  - GAPLESS without RESET, where shadPS4 and RPCSX disagree (debt `:18`);
  - the error for a null input;
  - INITIALIZE through Control for codec 23 (debt `:13`);
  - input sizes other than the gapless block plus the codec's parameters.
- **What would close it:** console measurements, or the call sites that reach those branches. If PPSA26344 still stops here, its report needs the flags and both sideband sizes.

**`sceVideodec2GetHevcPictureInfo`** (libSceVideodec2; PPSA02225). Unclaimed; #10091 (xXPBSXx) names it in a debt doc.
- **Why D:** its argument list is unknown (`docs/dev/debt/libSceVideodec2.md:8`), and the tree has no Videodec2 HEVC picture-info layout (`:14`).
- **Everything else exists:**
  - The decoder keeps per-picture pts/dts/attached, IDR and key-frame flags, crop, bit depth, profile and level (`core/libs/prx/libSceVideodec2/Export.cpp:181-190`, `:213-214`, read back at `:708-718`).
  - libSceVdecsw already fills a 0xb8 HEVC picture info, shadPS4's `vdecsw.h` layout, from that same state (`core/libs/prx/libSceVdecsw/Export.cpp:110-135`, `include/Api.hpp:95`).
- **It becomes B-S** once PPSA02225's call site gives the argument registers and `thisSize`: an HEVC branch beside `GetPictureInfo`'s throw (`Export.cpp:659`), and a forward like `GetAvcPictureInfo`'s (`:678`).
- **Caveat:** the two done AVC layouts disagree at offset 0x2c. Videodec2 writes the luma width (`Api.hpp:127`, `Export.cpp:669`); libSceVdecsw writes macroblocks minus 1 (`Api.hpp:80`, `Export.cpp:149`). The same question will come up if Vdecsw's HEVC layout is reused.
