## The rule and why

**Choice:** each `DrawKeySightings` slot now carries an `inserted` byte.
- **Marked:** `insertDrawEntry` calls `NoteInserted(key)` when the draw's entry is inserted, under `drawCacheMutex` as before.
- **The bypass's question:** "was this key seen before" became `AwaitsInsert(key)`, a key the sightings hold whose slot is not marked inserted.
  - `Driver::drawKeySeen` is renamed `drawKeyAwaitsInsert`, the name of what it now answers.
  - It is the term in the `Note(...)` call, `Draw.cpp` L660.
- **Reset:** `SeenBefore` clears the byte when it writes a new key into a slot.
- **Unchanged:** `Holds` keeps its meaning, so `SightingsKeepCollidingKeys` stays unchanged and passes.

**How it plays out:** `Note` runs after the lookup and before the capture admits and inserts the draw (`DrawCapture.cpp` L214 and L289).
- **Second sighting:** the key awaits its insert, so the sighting that admits it still counts as useful. That keeps `ColdScenesKeepTheCacheLookedUp`'s warm-up.
- **After insert:** the slot is marked, and every later sighting of that key counts only if it really hits. If the entry was evicted, or erased or replaced, the sighting is not useful.
- **Re-admission:** `admitDrawKey` still uses `SeenBefore`, so an evicted key is still re-admitted at once. Only the bypass's count changes.
- **Dropped keys:** a key the 4-way sightings table drops and later sees again starts over as new: it counts once, at the sighting that admits it again.

**Why not drop the key from the sightings at eviction:**
- The next sighting would record it as new, so it would not be admitted. The one after would count as useful and admit it again.
- Under a budget smaller than the scene, that is one useful lookup in every two sightings, about 50 %. The bypass would still never start.
- Avoiding the re-admission would need the same per-key state as the flag.
- With the flag, eviction needs no bookkeeping and is O(1). The two lookups are a 4-way scan of one bucket, as `Holds` already did.

## The new test case

**Registration:** `agc_driver_draw_cache_evicted_scene` runs `agc_driver_draw_cache_reuse_tests --evicted-scene`. It is registered like the cold-scene cases:
- `ENVIRONMENT "ANYPS5_NO_SHADER_CACHE=1;APS5_DRAW_CACHE_BYTES=65536"`;
- `SKIP_RETURN_CODE 77` and `FAIL_REGULAR_EXPRESSION "FATAL:"`;
- added to the WIN32 `PATH=path_list_prepend:$<TARGET_FILE_DIR:libc>` list.

`EvictedScenesBypassTheCache` in `DrawCacheReuse.cpp`:
1. **Scene:** 2048 distinct draws (viewport scale 3000.25 to 3512, under llvmpipe's viewport limit), each frame one window, repeated for four frames under a 64 KiB budget. The cache holds about 37 entries.
   - Every frame makes 2048 lookups.
   - From the third frame on there is no hit.
   - Frames 1 and 2 are the warm-up. One entry admitted in frame 1 by its shape sighting hits once early in frame 2, before the budget evicts it.
   - The byte budget evicts at least 2048 entries.
2. **Bypass starts:** after frames 3 and 4, two windows with nothing to hit, the next 2048 draws (a fifth frame) are neither looked up nor inserted.
3. **Bypass ends at 2048 draws:** a window of 2048 draws of one repeated draw is looked up in full. It has 2046 hits (first sighting, then admitted at the second).
4. **A window of real hits ends the bypass:** 10 more draws are all looked up and all hit.
