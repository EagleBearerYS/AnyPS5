## 2. The S1 mock test (`tests/Graphics.cpp`, `sampleOrderTests`)

This is PM-052 §2.2's test, on the existing mock `capable()` context: sampleRateShading, multisampled storage views, and no 2x2 grid at 2 samples.

**The state:** the decoded 2x checkerboard (`village`) with a D32F depth target, `quadSampleMask = {1, 1, 1, 1}`, `pixelEarlyZ` and `depthTest`.

**What it checks:**
- Under the checkerboard's order the mask moves to the pixel shader (`SampleMaskFollowsOrder`).
- `ValidateSampleMask` with a fragment program that writes a guest buffer throws, with "from a pixel program with early depth or stencil tests that writes memory, is unsupported".
- The same draw validates with a fragment program that writes no memory.
- It also validates on the same context with a 2x2 grid at 2 samples, where nothing is reordered and the mask stays static.

**Red/green (Linux):**
- **Red:** `ValidateSampleMask`'s `uniform` set to #6451's `UniformSampleMask(state)`, the condition at 668ecaeca2 (`Pipeline.cpp:161-173` there). Output: `expected graphics rejection: from a pixel program with early depth or stencil tests that writes memory, is unsupported`, exit 1. This is the addendum's "at 668ecaeca2 the same draw validates without a throw".
- **Green at the head:** `Sample order checks passed`, exit 0.
- The patch was reverted, and the tree is clean.

**For the author: the throw's message is wrong for S1.**
- It says "a sample mask that differs between the pixels of a quad", but S1's mask is uniform; it's the order that moves it to the pixel shader.
- The test checks only the part of the message that holds.
- Rewording the message is a code change, so it is left to the author. Suggested: "a sample mask applied in the pixel shader (one that differs between the pixels of a quad, or that the sample order moves), from a pixel program with early depth or stencil tests that writes memory, is unsupported: ...".
