## 2. The PC tests and fix sketches

These are text only and were not built or run. Each test belongs in `tests/Recorder.cpp`, next to `deferredSettleTests`, under `#ifdef _WIN32`, and skips (77) where that test skips.

### 2.1 F1: rewatch only after the main-queue work submitted before the read

**Test** (`--deferred-settle-first-use-only`):
1. Under `GpuMutex`, import a fresh 64 KiB watched block. As in (d), it is compared and its settle is Wanted.
2. Before any further lookup, record a main-queue use long enough to outlast a settle round trip, and `Submit()` it. For example: 4096 `vkCmdCopyBuffer` of the whole import into a 64 KiB scratch buffer, or a dispatch that loops over it.
3. Sleep 1 ms, then poll `HostImportFor` every millisecond.
   - Assert A: no poll finds `Watched(address, unit)` while `recorder.InFlightBatches() != 0`.
   - If the batch finishes before the settle is even submitted, lengthen step 2.
4. Once the block is watched or the batch has finished:
   - `BumpCollectEpoch(); collected = CollectWrites(address, unit); recorder.Sync(); CollectWritesUncached(address, unit);`
   - Assert B: `UnchangedSince(address, unit, collected)`. The test makes no CPU store, so any change is a driver mark that arrived after the rewatch.

**Expected:**
- **At bc27ba7d07:** A fails deterministically, because of the ordering. B shows whether the ordering matters on this driver.
- **With the sketch below:** both pass.
- **If B never fails at the head:** the guard is optional, and debt line 76 should say "until a GPU use completes".

**Sketch:**
- `PendingSettle` (`:177`) gains `std::uint64_t mainSerial = 0`.
- **`submitSettleBatch`:** compute the serial once per batch:
  `const auto* recorder = Recorder::Active();`
  `const auto mainSerial = recorder == nullptr ? 0 : recorder->Recording() ? recorder->OpenSerial() : recorder->Submissions();`
  - Store it with each base (`:931`).
  - It is read under `GpuMutex`, which `settleUnwatchedImports` already requires (`:1001`).
- **`rewatchSettledImports`:** extend the deferral at `:982` to:
  `StorageTexture::AnyPendingOverlaps(span) || (recorder != nullptr && recorder->CompletedThrough() < settle->second.mainSerial)`.
- **Cost:** a rewatch waits for main-queue work recorded before its read went out, at most about a frame. Nothing new blocks.

### 2.2 G4: retirement without the wait

**Test:** 64 rounds of the following, where each round submits a read and then retires the import while the read may still run:
1. Sleep 150 µs.
2. Look up the block. The imports are fresh, so this submits its settle batch.
3. Re-register the block at once.
4. Look up the block again.

Then assert:
- a new `retireWaits` counter stays at 0;
- the last import still returns to the watch.

At bc27ba7d07, `HostImportSettles().waited` grows in each round whose batch was still running. That is timing-dependent but likely on NVIDIA, where a submit round trip takes tens of µs.

**Sketch:**
- `SettleBatch` (`:167`) gains `std::vector<std::shared_ptr<void>> retired`.
- **`retireImport`:** make the `RetiredImport` holder first. If the import's settle is Submitted and its batch is running, push a copy of the holder into that batch's `retired` instead of waiting, and still erase the settle.
- **Releasing the holders:** `reapSettleBatches`, `drainSettles` and `adoptSettleDevice` clear `retired` once the batch's fence has signalled. The recorder's hold keeps its own reference, so the import is freed only after both its main-queue work and the settle read.
- **Counters:** count `retireWaits` separately from the 1 MiB settles, and print `submitted`, `waited`, `retire waits` and `rewatched` in the `[buffers]` line (`:2289`), so a title log shows G4.

### 2.3 G1: restore tracking once a retired import is freed

**Test:**
1. With `SetHostImportBudget(64 KiB)`, import block A. It is compared.
2. Import block B. `retireLeastRecent` evicts A before any lookup submits A's settle.
3. `recorder.Sync()`, then poll lookups of B.
4. Assert `Watched(A, 64 KiB)` and `UntrackedHint(A) == 0`.

At bc27ba7d07, A stays compared. With the sketch it returns to the watch.

**Sketch:** when `retireImport` drops a compared, settle-eligible import, keep `{range, std::weak_ptr to the holder}` in a list. The next poll rewatches a range from that list once all of these hold:
- the holder has expired, so the memory is freed and the driver can no longer mark it;
- no live import overlaps the range;
- no storage results are pending over it (the same deferral as `:982`);
- `Rewatch` succeeds. Its own walk refuses uncommitted pages.

This restore doesn't depend on F1.

### 2.4 G2: settle the whole interior blocks

**Test:**
1. Register and import 160 KiB starting 16 KiB past a 64 KiB boundary, so the import holds exactly one whole block, at +48 KiB from its base.
2. Poll lookups.
3. Assert:
   - the whole block is `Watched`;
   - the two partial blocks are not.

At bc27ba7d07, no settle is queued at all: `HostImportSettles().submitted` doesn't move.

**Sketch:**
- `:1487`: also queue a compared, writable, private, alias-free import under 1 MiB that holds at least one whole 64 KiB block.
- `rewatchSettledImports`: rewatch only `[alignUp(base, 64 KiB), alignDown(base + bytes, 64 KiB))`.
- The import keeps `unwatched` for its edge blocks. A per-import flag stops it from being queued again.

### 2.5 M1, M2 and M3

**M1:**
- Return the failed batch's bases and the wanted list to Wanted for a later poll.
- Drop them only on `VK_ERROR_DEVICE_LOST` or after a few failures.

**M2:**
- Erase the settle only after `Watched(range)` confirms the restore.
- Retry a refused range at later polls, a few times.

**Tests:** both need a fault hook, for example one failed `vkQueueSubmit` or one refused `Restore`. Low priority.

**M3:**
- **Sketch:** when `adoptSettleDevice` finds another device, destroy that device's objects with its own function pointers before switching. That means the batch fences (after the existing wait), the batch target and memory, and the synchronous target, memory and fence. The command buffers go with the old settle pool.
  - This is safe: `settleDevice` is non-null only while that device is alive, because its destructor's `ClearHostImports` resets it before `vkDestroyDevice`.
- **Test (PC, with the validation layer):**
  1. Create device A without a window. Import a block under 1 MiB and poll until a settle batch has been submitted.
  2. Create device B while A is alive, as `AttachWindow` does, and look the block up on B.
  3. Destroy B, then A.
  - At bc27ba7d07 the layer reports A's batch fences and batch buffer as not destroyed. With the sketch it reports nothing.

## 4. Correctness holes checked

| Question | Result |
|---|---|

| A GPU write in that window | **Caught.**<br>• While the blocks are excluded, `MarkWritten` and `storeOwn` record the store as unstamped (`GuestMemory.cpp:1473-1475`, `:1518-1520`), and `newestStamp` includes it.<br>• A recorded store that hasn't completed is in the Recorder's noted ranges, so a CPU read syncs first.<br>• Stamps made at completion after the rewatch land on watched blocks. |
| Pending storage results, unit shadows | **Covered.**<br>• Pending storage results defer the rewatch (`:982`).<br>• Unit shadows can't exist over excluded blocks (debt `:75`), so the missing `AnyShadowedOverlaps` there is not a gap. |

| Users of the unwatch serial | **Conservative.** The rewatch bumps the serial (`GuestMemory.cpp:1344`), so memoised range answers keyed on it (`GuestMemory.cpp:1193-1240`) and proofs that cite it are recomputed. The cost under churn is bf-settle, owned elsewhere. |

## 5. The "better version" check

**Settling at map time is not better overall:**
- **It imports every mapping**, including CPU-only ones. That pins memory against the host-import budget, which would refuse imports long before a title's heaps were all imported.
- **It blocks the guest's mapping call.** The import (and the settle, unless that is deferred anyway) runs inside it, which moves Dripl1x's 19 % loss into the map call.
- **It still needs a later rewatch** unless it waits.
- **Where it wins:** a fresh mapping has nothing derived from it yet, so its "rewatch" costs nothing. #6678 instead stamps whole blocks; that cost is bf-settle.

**#5851 (section aliases for resident direct memory) never needed a settle:**
- **Why:** the driver touches only the alias, so the guest's views stay watched from the start. There is no compare window, no rewatch stamp and no retirement wait.
- **Why it was dropped:** it remapped runs into sections and made 16 KiB `MEM_MAPPED` views that hit a ceiling in vf3 (GAC-024, PM-026). Protection tracking also faults once per page per re-arm. It was reverted for #6060 (GAC-019).

**What #6678 needs to stay the better one:**
1. **Correctness that doesn't depend on the read being the first use:** F1's guard, or the PC showing the guard isn't needed. #5851 had no such dependency.
2. **Retirement that never waits (G4).** #5851 never waited.
3. **A rewatch that doesn't invalidate everything derived (bf-settle, owned elsewhere).** Without it, a map-time settle of fresh mappings is cheaper per import.
4. **Imports retired before their rewatch regaining the watch (G1).** Under #5851, nothing ever left the watch.

The compare window itself is short under main's defaults, because the poll runs at the draw rate (§3).
