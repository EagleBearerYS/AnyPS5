# PRM-005: FSR 1's test pattern, bilinear against EASU, as PNG (cloud-2)

Result: three PNGs from the FSR test's synthetic 960x540 pattern, scaled to 1920x1080 by the branch's production presentation code on lavapipe. They are 8-bit grayscale and each is under 5 KB. Nothing was committed or pushed except this file.

## Head

- `git fetch origin feat/agc-fsr1-presentation-upscaling` then `git checkout --detach FETCH_HEAD`.
- The head is **fea68147aa13be623e28ae3d913aa69066c4b058**, as the task says. It is three commits over upstream e34c479210:
  - d4e992bb7 build(agc): add AMD FidelityFX FSR 1.0.2's shader headers

  - fea68147a test(agc): cover FSR 1 presentation and document ANYPS5_UPSCALE
- Ran `git submodule update --init --recursive`. The tree was clean before the local change and is clean again after it.

## How the frames were rendered

- **Local change:** a local, uncommitted change to `core/libs/prx/libSceAgcDriver/tests/PresentationPass.cpp` (diff below) adds a sample mode to its `--fsr` cases. It runs only when `ANYPS5_FSR_SAMPLES` is set.
  - Built with the existing target in the tree configured with CI's Linux flags: `cmake --build build --target agc_driver_presentation_pass_tests`, 36 s.
  - Run on lavapipe (llvmpipe, LLVM 20.1.2) as an unprivileged user, with:
    ```
    ANYPS5_FSR_SAMPLES=<dir> ANYPS5_NO_SHADER_CACHE=1 ANYPS5_REQUIRE_VULKAN=1 GALLIUM_OVERRIDE_CPU_CAPS=avx build/tests/agc_driver_presentation_pass_tests --fsr
    ```
  - Afterwards the file was restored with `git checkout --` and the target rebuilt from the committed source (10 s). `agc_driver_presentation_pass` and `agc_driver_presentation_fsr` passed both with the change (2/2) and after it (2/2).
- **Source:** the test's own `easuPattern()`, 960x540 and gray. Each value is rounded to 8 bits (`lround(v * 255)`) and stored as a `Bgra8` display buffer in a `B8G8R8A8_UNORM` resident image, the way the test's other SDR cases feed the pass. Its bands:
  - x 0..239: flat, 128.
  - x 240..479: two edge blocks of 51 and 204. The top half has a vertical edge at x = 360; the bottom half has a horizontal edge at y = 405.
  - x 480..719: the thin-line grid, 1-pixel lines of 230 every 8 pixels on a background of 26.
  - x 720..959: a horizontal gradient from 0 to 255.
- **Destination:** 1920x1080 `VK_FORMAT_B8G8R8A8_UNORM` with `VK_COLOR_SPACE_SRGB_NONLINEAR_KHR`, the SDR swapchain format. Each frame was read back after its present. Every pixel of every frame came back with R = G = B and alpha 255.
- **The three paths,** all through production code:
  - **Bilinear:** `PresentationPass::RecordPresent`. This is the path `present()` takes for a resident display buffer when `ANYPS5_UPSCALE` is unset (`drawn`). Its shader blends the four nearest texels at `(pixel + 0.5) * source / size - 0.5`.
    - As a cross-check, today's other default path, the linear blit (`PresentationScaler::RecordBlitFrom` with `VK_FILTER_LINEAR`), gives the same frame within 1 level. 18,364 of the 2,073,600 pixels differ, each by 1.
  - **EASU + RCAS:** the calls `present()` makes under `ANYPS5_UPSCALE=fsr` (the test's `fsrPresent`). `PresentationPass::RecordStage` writes a 960x540 stage. `PresentationUpscaler::RecordPresent` then runs EASU to 1920x1080 and RCAS into the destination.
    - The sharpness comes from `SelectUpscaleMode("fsr", nullptr)`, which gives 0.20 (the default), and `SelectUpscaleMode("fsr", "2.0")`, which gives 2.00 (the weakest). These are the values `ANYPS5_UPSCALE=fsr` selects with `ANYPS5_FSR_SHARPNESS` unset and set to 2.0.
- **Crop for A and B:** output x 800..1119 and y 720..899, which is source x 400..559 and y 360..449. It holds the grid and an edge:
  - The left half is the bottom edge block. Its horizontal 51/204 edge runs across at output y = 810, 90 px down.
  - The right half is the first 160 px of the grid. Its lines fall every 16 output pixels: x = 960, 976, ... 1104 and y = 720, 736, ... 896.
- **Scaling:**
  - A and B: each crop is enlarged 2x by nearest neighbour, so each pixel becomes a 2x2 block and the crop becomes 640x360. Two panels sit side by side with a 4-px black (0) gap, 1284x360 in all.
  - C: the whole EASU + RCAS frame at 0.2, averaged over 2x2 boxes with halves rounded up (`(a + b + c + d + 2) // 4`), giving 960x540. No crop was needed.
- **Encoding:** Python's standard library only (`zlib`, `struct`, `hashlib`, `base64`).
  - The PNGs are 8-bit grayscale (colour type 0). That loses nothing here, since every pixel had R = G = B and alpha 255.
  - Each row uses whichever PNG filter (None/Sub/Up/Average/Paeth) gives the smallest sum of absolute bytes, then zlib level 9.
  - Each PNG was decoded back with a stdlib decoder (chunk CRCs checked, filters undone) and gives back exactly its source pixels. The base64 is wrapped at 76 characters.

## What the frames measure

These are 8-bit levels from the read-back 1920x1080 frames.

| Pair | Largest difference | Mean difference | Pixels that differ |
|------|--------------------|-----------------|--------------------|
| bilinear vs EASU + RCAS 0.2 | 40 | 3.78 | 584,539 |
| EASU + RCAS 0.2 vs 2.0 | 18 | 0.91 | 580,759 |
| bilinear vs EASU + RCAS 2.0 | 34 | 2.88 | 345,189 |
| bilinear pass vs linear blit | 1 | 0.009 | 18,364 |

The flat band (x 4..471) is 128 everywhere in all four frames.

Profiles across the two features in the crop, with x or y increasing to the right:

```
horizontal edge 51/204, column 880, y 804..816
  bilinear   51  51  51  51  51  89 166 204 204 204 204 204 204
  easu-0.2   51  51  51  51  42  65 190 212 204 204 204 204 204
  easu-2.0   51  51  51  51  50  70 184 205 204 204 204 204 204
grid line 230 on 26, row 820, x 1050..1062
  bilinear   26  26  26  26  26  77 179 179  77  26  26  26  26
  easu-0.2   26  26  26  26  21  49 219 219  49  21  26  26  26
  easu-2.0   26  26  26  26  25  52 211 211  52  25  26  26  26
```

The vertical edge (row 300, x 714..726) has exactly the same values as the horizontal one.

- **Edges:** bilinear spreads each edge over two output pixels, at 89 and 166. EASU + RCAS at 0.2 makes them steeper, at 65 and 190, with a one-pixel halo on each side: 42 against 51 and 212 against 204.
- **Grid lines:** the lines peak at 179 with bilinear and at 219 with FSR at 0.2; the source is 230. Next to each line, the background dips to 21 against 26.
- **Sharpness 2.0:** the edge pixels are 70 and 184 and the lines peak at 211. Every halo drops to 1 level.
- **Where the halo comes from:** the halo shrinks from 5–9 levels to 1 when only RCAS's sharpness changes, so it comes from RCAS, not EASU. EASU's pass takes no sharpness.

The committed test printed this on the same run (its float pipeline, `agc_driver_presentation_fsr`):

```

RCAS 1:1: sharpness 2.0 changes the image by at most 0.0241; edge contrast 0.2331 in the source, 0.2349 at sharpness 2.0, 0.2482 at 0.2; a flat 0.5 region stays uniform at 0.49966 and 0.49917
```
