## Summary

- **Root cause:** main gave the ancillary input's sample field the host's `SampleId` in every pixel shader.
  - Vulkan turns on sample shading for any shader that uses `SampleId`, so these shaders ran once per sample on every multisampled draw.
  - That happened even when the guest runs them once per pixel (PS_ITER_SAMPLE clear), and it moved `FragCoord`, and so POS_X/Y_FLOAT, off the pixel centre.
- **The fix:** the request now says whether the guest iterates. When it doesn't:
  - the sample number is 0;
  - PERSP_SAMPLE and LINEAR_SAMPLE are interpolated at sample 0's offset;
  - POS_X/Y follow `SPI_BARYC_CNTL`.
- **Iterated shaders** keep `SampleId`. Their sample barycentrics now come from the guest's location for that sample, and their centre barycentrics and positions stay at the pixel centre.
- **Cost on lavapipe, Village's input shape (0x2301) at 4x:**
  - not iterated: 4 → 1 fragment invocations per pixel, 9.54 → 5.79 ms (−39%);
  - iterated: +8% for the explicit offsets.
- **With #5907** (proposal minus the ANCILLARY+POS rule) merged locally, Village's exact 0x2301 draw decodes, and its request is once per pixel at the centre. Details in §6.

## 1. Root cause and the fix

### Root cause on main 0029e62f9 (the cited files are unchanged since ff23657f34)

- **Where `SampleId` comes from.** `core/shader/recompiler/Optimization/src/ConstantFolder.cpp:389` (the field lowering) and `:861` (the whole-word composition) give the ancillary's sample field (bits 11:8) the `SampleId` builtin in every pixel shader. `SpirvModuleSetup.cpp:299` then declares `SampleRateShading`.
- **What Vulkan does with it.** It says: "If a fragment shader entry point statically uses an input variable decorated with a BuiltIn of SampleId or SamplePosition, sample shading is enabled and a value of 1.0 is used instead of minSampleShading" ([primsrast.adoc L2394-L2397](https://github.com/KhronosGroup/Vulkan-Docs/blob/193ebe195f47ffc5004683d1659e71c725658c4d/chapters/primsrast.adoc#L2394-L2401)). The pipeline's own `sampleShadingEnable` (`Pipeline.cpp:464`, from PS_ITER_SAMPLE) no longer matters then.
- **The effect.** Every shader that reads the sample field, or the whole ancillary word, ran once per covered sample on a multisampled draw. The console runs it once per pixel when PS_ITER_SAMPLE is clear.
  - Under that forced sample shading, `FragCoord`, which POS_X/Y_FLOAT read directly (`InstructionTranslator.cpp:355`), is at the sample, not the centre.
  - The sample number was the host sample rather than 0.
- **The `sampleShading` flag is dead state.** The task asked about it (`ShaderInputState.cpp:162` → `psSampleShading`, `ShaderInputInfoBuilder.cpp:143`). Only the request serializer and the cache key carry it; the translator and the SPIR-V backend never read it. It produces no `Sample` decoration and no sample-rate shading.
  - So on main, PERSP_SAMPLE and LINEAR_SAMPLE are plain `BaryCoordKHR` / `BaryCoordNoPerspKHR` (`InstructionTranslator.cpp:347`).
  - Vulkan puts plain inputs "at an implementation-defined position within the fragment area" ([shaders.adoc L3093](https://github.com/KhronosGroup/Vulkan-Docs/blob/193ebe195f47ffc5004683d1659e71c725658c4d/chapters/shaders.adoc#L3093-L3110)).
  - lavapipe uses the pixel centre, both once per pixel and under sample shading. That is never sample 0 with the standard 2x, 4x or 8x patterns.
- **No other trigger exists.** `SamplePosition` and `Sample`-decorated inputs are never emitted. Vulkan says a `Sample` decoration "may" enable sample shading (L2398-L2401). The ancillary fold is the only `SampleId` source left after the fix, besides the iterated table read below.

### The fix

It all happens in one place, the translator's pixel entry prologue, fed by the request.

**Commit 1** (`feat(agc)`, request plumbing; changes no generated code). `ShaderPixelStageInfo` gains three fields:
- `iteratesSamples` = `State::perSampleShading`, that is, PS_ITER_SAMPLE on a multisampled draw.
- `positionLocation`: `SPI_BARYC_CNTL.POS_FLOAT_LOCATION` (bits 17:16) and `POS_FLOAT_ULC` (bit 20), from PAL's header and LLPC's use of them. A missing register reads as the pixel centre (`InitialContextRegisters` lacks 0x1b8), and the reserved value 3 throws.
- `sampleLocations[32]`: four quad pixels × 8 samples, in the `PA_SC_AA_SAMPLE_LOCS` nibble format.
  - Once per pixel it holds each pixel's sample 0; when iterated, every sample.
  - It is all zeros when the shader reads no sample barycentric and no position at the sample, so other shaders keep sharing cache entries.

The fields join the shader cache key (`CacheKey.hpp`), the draw cache hash and compare (`DrawLookup.cpp`, `DrawRegisterKey.cpp`) and the request serialization (version 31; main is 30, and no open PR uses 31). Devices with `sampleRateShading` now advertise `InterpolationFunction` (`VulkanDevice.cpp`, `ShaderDeviceProfile.cpp`, and the pixel validator's allow-list in `ShaderValidation.cpp`).

**Commit 2** (`fix(recompiler)`):
- **Ancillary sample number:** `SampleId` only when `iteratesSamples`, else the constant 0, in both ConstantFolder paths. The flag is carried as `IrProgramMetadata::pixelIteratesSamples`.
- **PERSP_SAMPLE and LINEAR_SAMPLE** become new offset kinds. The backend emits `InterpolateAtOffset(gl_BaryCoord*, offset)`:
  - once per pixel, the offset is sample 0's;
  - iterated, it is the offset of the host's `SampleId`, read from a Private table of the guest's locations;
  - when the locations differ between the pixels of the 2x2 quad, the table is indexed by `FragCoord` parity too.
- **PERSP_CENTER and LINEAR_CENTER** in an iterated shader: `InterpolateAtOffset(…, 0)`, the pixel centre.
- **POS_X/Y_FLOAT:**
  - centre: `FragCoord` once per pixel, `floor(FragCoord) + 0.5` when iterated;
  - sample: `FragCoord` when iterated, centre + sample 0's offset once per pixel;
  - centroid: `FragCoord`;
  - ULC: `floor(FragCoord)`.
- **`FormatVersion` 39.** Main (0029e62f9) is 36. #6243, #6280 and #6412 set 37, and PM-038 reserves 38; GAC-033's task text also expects GAC-031 at 39. No open PR sets 39: #6032 touches the line but keeps 36.
- **Where offsets apply:** only where the device can honour them, that is with `InterpolationFunction` and the fragment-shader-barycentric path (native or emulated). Hosts that interpolate attributes on the host (MoltenVK) keep the default positions. The ancillary fold applies everywhere.

### Choosing the interpolation (the task asked to weigh the options)

| option | needs | forces | with the guest's own locations |
|---|---|---|---|
| `Sample` decoration on `BaryCoordKHR` | nothing extra | "may" enable sample shading (L2398), so per-sample again | host sample positions |
| `InterpolateAtSample(bary, 0)` | `InterpolationFunction` (sampleRateShading) | nothing | evaluates at the host's sample 0. Vulkan defines custom locations for rasterization only, and `SamplePosition` is poison with them ([interfaces.adoc L4880-L4884](https://github.com/KhronosGroup/Vulkan-Docs/blob/193ebe195f47ffc5004683d1659e71c725658c4d/chapters/interfaces.adoc#L4880-L4884)), so the host position can't be relied on or checked |
| **`InterpolateAtOffset(bary, guest offset)`** (chosen) | `InterpolationFunction` | nothing | exact by construction: the offset is the guest's `PA_SC_AA_SAMPLE_LOCS` value. Offsets are sixteenths in [-0.5, 0.4375], inside the guaranteed `minInterpolationOffset`/`maxInterpolationOffset` with `subPixelInterpolationOffsetBits` ≥ 4 |

[GLSL_EXT_fragment_shader_barycentric issue 2](https://github.com/KhronosGroup/GLSL/blob/0099bf83b0288469917fc2e2972cb0a2b74d6711/extensions/ext/GLSL_EXT_fragment_shader_barycentric.txt#L286-L299) names `interpolateAtOffset(gl_BaryCoordEXT, offset)` for barycentrics away from the default position.

The console side is inferred, not measured:
- **Ancillary sample number.** The ISA guides call it the iterated sample number. LLPC reads `gl_SampleID` from Ancillary[11:8] only in shaders it runs at sample rate ([RegisterMetadataBuilder.cpp](https://github.com/GPUOpen-Drivers/llpc/blob/40cb8d95ad8d6f7f1652e3fd47d39667594cce08/lgc/lowering/RegisterMetadataBuilder.cpp#L767-L799) sets `PS_ITER_SAMPLE` when `gl_SampleID` or a sample-rate input is used).
- **Barycentrics.** LLPC interpolates undecorated inputs at `InterpPerspSample` under sample-rate shading and `InterpPerspCenter` otherwise. So PERSP_SAMPLE is "the iterated sample", which in a non-iterated wave is taken to be sample 0, as fdfawef324 also infers.
- **No hardware statement.** Nothing I found states the non-iterated value on hardware. §7 has the alternative reading.

## 4. Cost and gain (measured)

**Setup:**
- lavapipe (Mesa llvmpipe) on this VM's 4 vCPUs.
- A 512×256 full-screen triangle with no attachments, through barycentric emulation.
- The shader reads PERSP_SAMPLE, POS_X/Y and, in the first rows, ANCILLARY (Village's 0x2301 shape). It does a little ALU work and stores its slot.
- Time is one draw plus `WaitIdle`. lavapipe shades on the CPU, so this is its GPU time.
- Each value is the median of the per-round p50s: 8 rounds × 20-50 draws (3 rounds for the no-ANCILLARY rows), alternating main and fix.
- main is ff23657f34 built in its own tree; fix is this branch before the rebase, code-identical to the head. The 66 commits main gained since then touch no shading path. Harness: `PixelSampleCost.cpp`, not committed.

| shader | samples | guest iterates | invocations/pixel, main → fix | main ms | fix ms | change |
|---|---|---|---|---|---|---|
| PERSP_SAMPLE + POS + ANCILLARY | 4 | no | **4.000 → 1.000** | 9.54 | 5.79 | **−39%** |
| PERSP_SAMPLE + POS + ANCILLARY | 4 | yes | 4.000 → 4.000 | 9.31 | 10.05 | +8% (the explicit per-sample offsets) |
| PERSP_SAMPLE + POS + ANCILLARY | 1 | no | 1.000 → 1.000 | 5.58 | 5.49 | within noise |
| PERSP_SAMPLE + POS | 4 | no | 1 → 1 (no `SampleId` on main either) | 5.13 | 5.38 | +5%, within the ±15% round-to-round spread |
| PERSP_SAMPLE + POS | 1 | no | 1 → 1 | 5.18 | 4.74 | within noise |

- **2x** can't be drawn on lavapipe. By construction, the ancillary shapes go from 2 to 1 invocations per pixel; the per-invocation part is about 10 ns on lavapipe ((9.54 − 5.58) ms / 393216 extra invocations).
- **The gain is the main point.** Every multisampled draw whose shader reads the ancillary's sample field or whole word, without PS_ITER_SAMPLE, did N× the fragment work on main. That includes RE4's 0x2001 pass and Village's 0x2301 once #5907 lets it draw.
- **The cost is small.** It is one `InterpolateAtOffset` per sample-barycentric pair, about 1.4 ns per invocation on lavapipe in the iterated row, plus a private-table load when iterated.
- **Real GPUs:** WINDOWS: the 3070 numbers are the coordinator's.

2. **PERSP_SAMPLE / LINEAR_SAMPLE.**
   - Before: plain barycentrics, which Vulkan's one-sample rule puts at the single (custom) sample, sample 0's location ([shaders.adoc L3105-L3110](https://github.com/KhronosGroup/Vulkan-Docs/blob/193ebe195f47ffc5004683d1659e71c725658c4d/chapters/shaders.adoc#L3093-L3110); #5907 requires `sampleLocationSampleCounts` to include 1).
   - Now: interpolated explicitly at sample 0's offset per quad pixel. Same position, without relying on that rule.
3. **POS_FLOAT_LOCATION = sample** without iteration: centre + sample 0's offset. Before, it was `FragCoord`, the centre.
4. **PS_ITER_SAMPLE on that path.** #5907 forces `perSampleShading` false, so the request says not iterated, and the sample number is 0. That matches #5907's "sample 0's invocation reaches the targets".
5. **Unchanged: PERSP_CENTER / LINEAR_CENTER** on this path still land at sample 0's location by the one-sample rule. #5907's debt entry says so. Fixing it would need the request to say that the host's single sample is off-centre, so that centre pairs take offset 0. With this branch that is a small follow-up on #5907's side: carry the locations for centre reads when `samples == 1 && customSampleLocations`, and set the centre offset kinds then.
6. **#5907's `SampleDependentInputs`.** Its current head already narrowed the refusals to centroid + SAMPLE_COVERAGE (`SampleZeroRefusedInputs`), and SAMPLE_COVERAGE alone when iterated. With this branch, the PERSP/LINEAR_SAMPLE and ANCILLARY acceptances become exact instead of approximations.
   - Centroid stays refused without iteration: the centroid of the N-sample coverage isn't sample 0.
   - SAMPLE_COVERAGE stays refused (§7).

## 7. Adversarial review

1. **Is sample number 0 right for every non-iterated shader?**
   - What supports it: the field is documented as the iterated sample number. LLPC only reads it as `gl_SampleID` in shaders it marks `PsIterSample`. A pixel the hardware doesn't iterate has no other number to report.
   - The alternative reading: the first covered sample. That would differ only for pixels whose sample 0 is uncovered.
   - Neither is measured on gfx1013. It is called out as inferred in the debt entry. A one-draw console check would settle it: a non-iterated 4x shader that writes Ancillary[11:8] over a triangle edge.
   - PERSP_SAMPLE follows the same inference, as fdfawef324's does.
2. **Can a title get per-sample execution without PS_ITER_SAMPLE?**
   - PAL enables iteration only through `PA_SC_MODE_CNTL_1.PS_ITER_SAMPLE` (or its own `ForceSampleRateShading`, which sets the same bit), with `DB_EQAA.PS_ITER_SAMPLES` = log2 of the pixel shader samples.
   - SAMPLE_COVERAGE doesn't iterate. LLPC reads it as the pixel's coverage and itself masks it with `1 << gl_SampleID` when running at sample rate ([LowerInOut.cpp L2534-L2573](https://github.com/GPUOpen-Drivers/llpc/blob/40cb8d95ad8d6f7f1652e3fd47d39667594cce08/lgc/lowering/LowerInOut.cpp#L2534-L2573)), so the raw input holds the whole pixel's coverage even in an iterated wave.
   - On the host, SAMPLE_COVERAGE is still untranslated (reads 0) and isn't refused on main. That is a separate gap, not this root cause.
   - Mapping it to Vulkan's `SampleMaskIn` would be right once per pixel but wrong when iterated (Vulkan gives only the shaded sample's bit). So it needs its own change: `SampleMaskIn` once per pixel, and the quad's coverage when iterated.
   - `DB_EQAA.PS_ITER_SAMPLES` below the sample count (fewer invocations than samples) is not modelled; it is documented.
3. **Shaders that read the ancillary for the layer only.**
   - The field lowering never gave a layer-only read `SampleId`; it uses `Layer × LayerExported`.
   - A whole-word read (passed through memory, or a mask the masked-select pass keeps) used to get `SampleId` for the sample field and so ran per sample; now it reads 0 there.
   - Covered by `pixel_ancillary` `ExportedWholeWord` and `ExtractVector(16, 11)` with `Iterated=false`.
4. **The general version is what's built.**
   - Every sample-dependent input follows the guest's iteration mode in the pixel prologue:
     - the ancillary sample field (both lowering paths);
     - the sample pairs, at the guest's locations, standard or custom, per quad pixel and per sample;
     - the centre pairs when iterated;
     - POS by `SPI_BARYC_CNTL` (centre, sample, centroid, ULC).
   - The request carries the mode once, and the cache keys follow.
   - The generalisation also covers #5907's one-sample path: one sample with custom locations carries sample 0's location.
5. **Other things tried against it:**
   - **1-sample draws:** they no longer need `SampleRateShading` to read the ancillary.
   - **Devices without `sampleRateShading`:** the device test asserts no offsets and no capability.
   - **MoltenVK:** host interpolation, no offsets, default positions as before.
   - **SPIR-V 1.3:** a vector `OpSelect` with a scalar condition was rejected, which the new custom-location module check caught. The quad selection now indexes the table instead.
   - **Cache sharing:** shaders that read no sample input carry zero locations, so they keep sharing.
   - **Out-of-range indexing:** `SampleId` ≤ 7 and quad ≤ 3 stay inside the table.
   - **Two remaining approximations, both documented:** a centroid position is `FragCoord`, not the covered centroid; and ULC with iteration gives the pixel corner, per the register name.

## PR text draft

Title: `fix(recompiler): run a pixel shader the guest does not iterate once per pixel`

```markdown
### What

A pixel shader that reads the ancillary input's sample number ran once per sample on every multisampled draw, even when the console runs it once per pixel.

The cause: the recompiler gave that field (bits 11:8) the `SampleId` builtin, and Vulkan enables sample shading for any fragment shader that uses `SampleId` ([spec](https://github.com/KhronosGroup/Vulkan-Docs/blob/193ebe195f47ffc5004683d1659e71c725658c4d/chapters/primsrast.adoc#L2394-L2397)). That happened whatever `PA_SC_MODE_CNTL_1.PS_ITER_SAMPLE` said. So these shaders did N× the fragment work, and `FragCoord`, and with it POS_X_FLOAT and POS_Y_FLOAT, moved from the pixel centre to the sample.

- The recompile request now carries three things:
  - whether the guest iterates the shader (PS_ITER_SAMPLE on a multisampled draw);
  - where `SPI_BARYC_CNTL` puts POS_X/Y_FLOAT (`POS_FLOAT_LOCATION`, `POS_FLOAT_ULC`);
  - the guest's sample locations for each pixel of the 2x2 quad, when the shader reads a sample input.
- **A shader the guest doesn't iterate:**
  - the sample number is 0, so the shader runs once per pixel;
  - PERSP_SAMPLE and LINEAR_SAMPLE are interpolated at sample 0, with `InterpolateAtOffset` by the guest's offset from `PA_SC_AA_SAMPLE_LOCS`;
  - POS_X/Y are at the pixel centre, at sample 0, or at the upper-left corner, as `SPI_BARYC_CNTL` says.
- **An iterated shader:**
  - keeps `SampleId`;
  - its sample barycentrics are interpolated at that sample's guest location (plain barycentrics under sample shading are at an implementation-defined position; lavapipe uses the centre);
  - its centre barycentrics and POS_X/Y stay at the pixel centre.
- The offsets need the device's `sampleRateShading` (`InterpolationFunction`) and the fragment-shader barycentric path. Devices without them keep the host's default positions.
- Request serialization version 31; shader disk cache format 39.
- Effect on open PRs: #5907's sample-zero path no longer has to refuse ANCILLARY with POS_X/Y_FLOAT (PPSA01556's 0x2301 pass, PPSA07411's 0x2001 pass). The sample-index refusals in #6196 and #5915 become unnecessary for draws the guest doesn't iterate.
- Unchanged: centroid inputs, the ancillary's render-target index and primitive class, single-sample draws, and `DB_EQAA.PS_ITER_SAMPLES` (still not read). SAMPLE_COVERAGE stays untranslated, as before.
```
