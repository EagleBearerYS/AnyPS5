## The variant, and why

**I chose the first one: keep `VertexFetchOutOfRange` as it was, and add a GPU-path predicate next to it.** Both changes are in `Graphics/include/VertexInput.hpp:233-242`:

```cpp
inline bool VertexFetchOutOfRange(const ShaderRecompiler::VertexAttribute& attribute) {
    const auto stride = (attribute.resource.fields[1] >> 16u) & 0x3fffu;
    const auto select = VertexBufferOutOfBoundsSelect(attribute);
    return stride == 0 && (select == 2u || select == 3u) && attribute.resource.fields[2] == 0;
}

inline bool IndirectVertexFetchOutOfRange(const ShaderRecompiler::VertexAttribute& attribute) {
    const auto stride = (attribute.resource.fields[1] >> 16u) & 0x3fffu;
    return VertexFetchOutOfRange(attribute) || (attribute.resource.fields[2] == 0 && stride != 0 && VertexBufferOutOfBoundsSelect(attribute) <= 1u);
}
```

The one call site is in `prepareDrawInputs` (`Graphics/src/Draw.cpp:1170` on main, `:1212` on exp):

```cpp
if (NullVertexDescriptor(attribute) || (args != nullptr ? IndirectVertexFetchOutOfRange(attribute) : VertexFetchOutOfRange(attribute))) {
```

- **Direct draws** (`args == nullptr`) are back to exactly what they did before BF-031:
  - `VertexBufferReadSize` sizes the fetch, and `fetchValid` is `min(0 × stride, bytes) = 0`;
  - so the attribute gets its own zero-padded copy, `CopyZeroPaddedDrawInput` with 0 valid bytes;
  - every fetched vertex reads zero in bounds, on any GPU.
- **Indirect draws** keep BF-031's zero binding. Their counts aren't known here, and `VertexBufferExtent` would throw "empty or oversized vertex buffer descriptor" for 0 records.
- **Nothing else changes:**
  - no other caller of either predicate in the driver;
  - the zero-stride shape and null descriptors are the same as before;
  - the vertex input layout and `VertexInputCache` are untouched, so `agc_vertex_input` passes;
  - the existing `VertexFetchOutOfRange` assertions in `tests/Graphics.cpp:6887-6898` and `tests/VertexInput.cpp:145-149` are the zero-stride ones and still hold.
- **Why not the alternative:** an exact stride-0 binding for the GPU path would put a per-draw decision into the layout key, which `VertexInputCache` keeps independent of the record count. That's a larger change, and it's what BF-031 dropped after `agc_vertex_input` failed.

**What the GPU path's fetch past vertex 0 returns:** the same as with BF-031.
- The binding is the format-sized `zeroVertexBuffer` (one element, 16 bytes for this test's format), at the descriptor's stride.
- Vertex index 0 reads zero in bounds. Every higher index is out of bounds and reads what robust buffer access returns: zero on lavapipe, while Vulkan also allows (0,0,0,x).
- With first vertex 6, every vertex of the test's GPU-side draws is past index 0.
- Only GPU-side indirect draws of this shape are affected, and they aborted before BF-031.

## The test

`tests/execution/IndirectVertexPastEnd.cpp`:
- **Can lavapipe show the w? No.** It returns zero for an out-of-bounds vertex fetch: BF-031's mutant run with the descriptor's stride kept passed the cell checks. So the format-sized zero buffer and the zero-padded copy draw the same picture there, and a w = 1 can't appear.
- **What it asserts instead**, before each draw that has the 0-record attribute: the decision `prepareDrawInputs` makes for the attribute the recompiler produced from that descriptor.
  - For a direct draw: `!VertexFetchOutOfRange(attribute)`, which means a zero-padded copy, not `zeroVertexBuffer`. Failure message: "the direct draw would bind the format-sized zero buffer, read out of bounds past its first vertex, instead of a zero-filled copy of every vertex it fetches".
  - For an indirect draw: `IndirectVertexFetchOutOfRange(attribute)`.
- **New case:** a direct draw with OOB select 1, alongside the existing select 0 one.
- The cell checks are unchanged: every 0-record case must still land its triangle in cell 3.

I didn't find a counter or test hook that reports which buffer a direct draw binds. The `indirectVertexRangesCut` profile counter is only printed under `APS5_PROFILE_DRAW`. So the test checks the predicate, which the one call site uses for `args == nullptr`.
