## 1. The change

```diff
-    constexpr std::uint32_t side = 256;
-    constexpr std::size_t bytes = side * side * 4;
-    void* block = AllocateWatched(bytes, 65536);
+    constexpr std::uint32_t width = 1024;
+    constexpr std::uint32_t height = 512;
+    constexpr std::size_t bytes = width * height * 4;
+    constexpr std::size_t allocated = bytes + 65536;
+    void* block = AllocateWatched(allocated, 65536);
 ...
-        ~Release() { ReleaseWatched(block, bytes); }
+        ~Release() { ReleaseWatched(block, allocated); }
 ...
-    resource.width = side;
-    resource.height = side;
+    resource.width = width;
+    resource.height = height;
```

- `bytes` (2 MiB) is still what the test registers (`mutation.Add(block, bytes, ...)`), imports, fills, checks byte by byte, and covers with the image.
- `allocated` is only what `AllocateWatched` and `ReleaseWatched` take:
  - On Windows that's the arena allocation and commit.
  - On Linux it's the `mmap` and the write-watch registration.
- `AllocateWatched` still checks that the whole allocation is watched.

## 2. Why the import is settled now, and is one import

Line numbers are at c4bce94c42.

- **The settle rule** (`GuestBufferMemory.cpp:1145-1146`, Windows only):
  ```cpp
  const bool settled = entry.alias == nullptr && state.watchPrivateImports && writable && bytes >= settleFloorBytes;
  const bool watchedHostPointer = entry.alias != nullptr || !state.unwatchImports || settled;
  ```
- **How it played out on the 3070:**
  - The probe said imports keep the watch, so `watchPrivateImports` is set.
  - The test printed `host imports are compared`, so `unwatchImports` is set.
  - So the 256 KiB import was neither settled nor watched, and `Watched(address, bytes)` was false. That produced `skipped, the heap is not imported or not watched`.
- **What changes at 2 MiB:**
  - The arena commits private read-write pages (`GuestArenaCommit`, `libc/src/GuestArena.cpp:390-396`). So the import is writable and needs no alias.
  - The 3070's skip agrees: an aliased import would have stayed watched even at 256 KiB.
  - The 2 MiB import passes the floor, so it is settled and stays watched.
  - The unit shadow can engage: `ShadowDestinationFor` needs a watched range (`UnitShadow.cpp:531`).
- **The import is exactly the registered range:**
  - The tests leave the import window at 0.
  - The range window is 64 MiB (`GuestBufferMemory.cpp:970`), so a 2 MiB range is never cut into cells.
  - The default budget is at least 6 GiB (`:954-968`).
- **GAC-044's adjacency:**
  - `continuesRun` (`:812`) and `importRun` (`:826`) join registered ranges that touch.
  - In `--bda-shadowed-results-only` the heap is the only range the process registers.
  - Its allocation ends one unregistered 64 KiB block past the range. So nothing the arena places after it (it allocates upward) can continue it, in any placement.
- **The `" address 1/"` assertion still holds:**
  - `UploadFinish` makes one `PublishShadowsOnly` over the heaps' span.
  - `PublishShadow` publishes each overlapping shadow once (`UnitShadow.cpp:474-491`), and there is one shadow per import.
  - The reason count goes up once per `publishUnits` call (`:356`), not once per unit.
  - So one 2 MiB import still counts one address publish.
- **The slab:** 2 MiB is 32 units, inside one 8 MiB slab (128 units). So the write-back never meets `ShadowDestinationFor`'s cross-slab refusal (`:543`).
