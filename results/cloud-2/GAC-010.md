## Risks for a Windows game run
1. **681fcee86 is not in either tree.**
   - Its own message: when an expanded plane's write base crosses the edge of two registered ranges imported apart, or of an imported range and a mirrored or copied one, `StoreDepthExpandWrites` (in `UploadFinish`, which #6146 edits) does not store it.
   - "An address-based build then read the imported part in place, so copies of the write base right after the expand held the guest bytes: zeros in the tests, the symptom of Resident Evil Village's copy shader at its write base."
   - So that Village symptom can come back on these trees.
   - The only conflict is the header hunk above. Keeping both declarations takes it in if you want it: `struct RegisteredPiece {...};` from main, then `bool HostImportOverlaps(const Context&, std::uint64_t, std::size_t);` from the fix.
   - It is based on 9f03c4fe0, 190 commits behind main. Main's ea3a2152d now writes storage images back across adjacent registered ranges through each range's import, so the fix's assumption (one import holds the whole plane) should be re-checked against that code.
2. **The Windows import path is touched by five picks in one file, `Graphics/src/GuestBufferMemory.cpp`.** The hunks are textually apart and compile together, but they meet in one address-based build on Windows:
   - #5851: `importRunAt`'s Windows branch. A resident direct-memory run is imported through a section alias and stays watched.
   - B3: `importRunAt` counts budget refusals. `AcquireRegistered` re-tries an import with eviction when a copy would pass `APS5_ADDRESS_COPY_MAX_MIB`. `acquireMirror`/`refreshHeapRuns` re-plan a heap mirror whose range left the watch.
   - B2: `AcquireRegistered` and `prepareRefresh`; a writable image mirror is compared once per collect epoch.
   - #6146: `UploadFinish` stores expanded planes into imports ahead of address-based builds.
   - #5815: the address-space region lookups, `dissolveSpace`, `takeHeapReferences` and `WriteBack`.
   - A B3 eviction can retire a #5851 alias import, and the range then goes back to a mirror or a copy. #6146's expand stores look for the import that holds the plane at that moment.
   - None of the Windows branches (the section alias, `GetWriteWatch`) run on this Linux CI.
   - On the first Windows run, `APS5_TRACE_HOST_IMPORT=1` shows the import, alias and `imported by evicting idle imports` lines.
   - If `APS5_HOST_IMPORT_MIB` is raised (PM-026), which ranges are imported changes for all of the above.
3. **`Execution/src/GuestMemory.cpp`: #5671 and B1.**
   - #5671 saves pending storage results in every 64 KiB block that leaves the write watch. B1 adds the exact-range collect memo.
   - B1's entries are keyed by collect epoch and unwatch serial, so an unwatch retires them. Low risk.
4. **`Execution/src/Driver/Shaders/ShaderRegistry.cpp`: #5872 and #5910** (the local lazy commits on the fallback).
   - #5872's `APS5_LAZY_SHADER_PREPARE` branch calls `PlanRegistered` and drops the plan. #5910 only turns `PlanRegistered`'s decoded program into a local. No shared state.
   - With `APS5_LAZY_SHADER_PREPARE=1`, registration still decodes and validates; preparation moves to first use.
5. **`Graphics/src/State.cpp`: the three experiments in `DecodeState` and #6146 in `DecodeDepthExpandPass`.** Different functions.
   - The experiments turn three of main's refusals into fallbacks:
     - a depth-only pass rasterized with its depth target's samples (`APS5_RE8_STRICT_DEPTH_SAMPLES=1` refuses);
     - colour/depth agreement below PA_SC_AA_CONFIG (`APS5_RE8_STRICT_COLOR_SAMPLES=1` refuses);
     - pixel (0,0)'s sample locations instead of a per-pixel grid (`APS5_RE8_STRICT_SAMPLE_LOCATIONS=1` keeps the grid).
   - These cause the two agc failures above. They are the only picks that change what renders compared with main.
6. **Switches.**
   - `APS5_IMAGE_TABLES_DIRECT_FIRST=1` and `APS5_NO_IMAGE_TABLES=1` both key the shader disk cache, so the first run with either is cold.
   - With `APS5_NO_IMAGE_TABLES=1` set (tonight's e34 test), there are no tables, so the helper's switch has nothing to do. Don't read results from a run with both set as the helper's.
