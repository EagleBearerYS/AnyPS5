### 1.2 How a mirror whose range left the watch gets there

- **`acquireMirror`** (GBM:1820) looks at the watch only when it **makes** a heap mirror: `CollectWrites`, then `generation == 0` at GBM:1869 returns null and the range is copied. It returns an existing non-sparse mirror as it is (GBM:1837).
- **The address-space cache** (GBM:2706, `else hit = true;`) is taken while the device, the registry generation and the imports epoch hold. The epoch moves only when an import retires (`retireImport`, GBM:246) or imports are cleared (GBM:2321). Making an import doesn't miss the cache.

### 1.3 What takes a range off the watch, and why it stays off

- **The only way off** is `unwatchLocked` (GM:1300), which bumps `UnwatchSerial` (GM:1304 Windows, GM:1306 elsewhere). Its callers:
  - `ImportWatched` (GM:1325) for an import that does not keep the watch (GM:1369-1371);
  - `ImportWatched` for one that does keep it, but whose pages weren't all watched before or whose write walk fails (GM:1375);
  - `MarkWritten` when a driver store's write collection is incomplete (GM:1507);
  - `GuestMemory::Unwatch` (GM:1316), whose only production caller re-unwatches the imports that still stand when the registry changes (GBM:1258).
- **Which imports keep the watch, on Windows:**
  - an import keeps the watch only through a shared alias or when it is settled;
  - `settled` (GBM:1145) needs `watchPrivateImports` (the probe, GBM:755), a writable private range, and at least `settleFloorBytes` = 1 MiB (GBM:654);
  - otherwise `watchedHostPointer` (GBM:1146) is false and `ImportWatched` (GBM:1152) takes the range off.
- **Elsewhere:** every import takes its range off while imports are compared (`APS5_WRITE_WATCH_IMPORTS=unwatch`, or the probe).
- **Nothing puts a range back.** `retireImport` (GBM:241) frees the import and moves the epoch, and the range stays unwatched.

So on main:
1. A build, which may not evict (GBM:2775), refuses range R for the budget and mirrors it (GBM:2787).
2. A buffer, texture or fill access imports R (`HostImportFor`, GBM:2558; it may evict to fit) without keeping the watch, for example below the settle floor.
3. Then either:
   - the next build hits the cache, because nothing retired since, and `refreshHeapRuns` throws; or
   - later evictions retire R's import, the next build refuses R again and reuses the mirror (GBM:1837), and `refreshHeapMirrors` throws.

`agc_heap_mirror_unwatched_import` is the first path, on main. The fix closes both.

### 1.6 What the fix does not cover

- **What the re-plan can do:** import the range (only if the budget holds it, since the build does not evict), else copy it.
- **The copy cap:** `AddressCopyOverflow` (GBM:2233) aborts a build whose copies add up to more than `APS5_ADDRESS_COPY_MAX_MIB` (64 MiB).
- **The consequence:** a refused heap larger than that, once its range has left the watch, still stops the build. The message becomes `FATAL: an address-based build copies 769 MiB ... past 64 MiB (APS5_ADDRESS_COPY_MAX_MIB); the largest: 0x230200000+0x30100000 ...` instead of the Require.
- **What is not on main or in the fast tree:** the explorer tree's 237166cb1, which made a build evict idle imports instead of copying past the cap. That's why the 2026-10-14 message's "eviction as the last resort" is not part of this port.
- **GAC-041** (cloud-3's `fix/agc-host-import-budget-floor`, ac9ccfb89c) keeps a set `APS5_HOST_IMPORT_MIB` over the device report. With 6400 MiB, the build at 63505 would have imported the 769 MiB range (3752 + 769 < 6400), not mirrored it. That makes this case rarer; it doesn't remove it.
- **If the log says "no":** the 769 MiB case needs one of these:
  - that change;
  - the 2026-10-13 approach (keep the mirror and compare the blocks outside the watch);
  - a larger copy cap, at the cost of copying the range every build.

## 2. The fix and the tests, as ported

**Fix (e9ff3b176, GBM +22/-4, plus one debt sentence).** It is the 2026-10-14 fix 18c114bced as described in the task. The task text is the only source for it.
- `ImageMirror` gains `std::atomic<std::uint64_t> watchedSerial`.
- `heapMirrorWatched(mirror)` compares it with `GuestMemory::UnwatchSerial()`. It calls `GuestMemory::Watched(base, bytes)` again only when some range has left the watch since, and it stores the serial when the mirror's range is still watched.
- `acquireMirror` reuses a heap mirror only when `heapMirrorWatched` holds.
- Its `generation == 0` path drops the registry's stale heap mirror (`heapBytes`, `entries.erase`, `++version`, with the reference released after the lock) and returns null, so the pass imports or copies the range.
- A new heap mirror stores the serial read before its collect.
- `AcquireRegistered`'s cache hit requires every `heapMirrors` entry to pass `heapMirrorWatched`. A miss here counts in no `rebuilt*` counter.
- Debt "Host import windows and budget": "A heap mirror whose range has left the write watch since its last use is dropped and its range planned again."
- **Cost:** while no range leaves the watch, two atomic loads per heap mirror per cache hit and per reuse: the global serial (acquire) and the mirror's (relaxed).

**Which branch carries it: the BDA branch.**
- `spaceMiss`, `SpaceMiss` and `ResumeSpace` exist only there, and this PR, based on main, has nothing to put the check in.
- Whichever lands second resolves the two conflict hunks below. If the BDA branch rebases on this PR, or merges it, its resolution is:

```cpp
enum class SpaceMiss { None, First, Device, Generation, Epoch, Unwatched };

SpaceMiss spaceMiss(const Context& context, const GuestBufferMemory::AddressSpace* current, std::uint64_t generation, const HostImports& state) {
    if (current == nullptr) return SpaceMiss::First;
    if (current->device != context.device) return SpaceMiss::Device;
    if (current->generation != generation) return SpaceMiss::Generation;
    if (current->importsEpoch != state.epoch) return SpaceMiss::Epoch;
    if (!std::all_of(current->heapMirrors.begin(), current->heapMirrors.end(), [](ImageMirror* mirror) { return heapMirrorWatched(*mirror); })) return SpaceMiss::Unwatched;
    return SpaceMiss::None;
}
```

The `switch` in `AcquireRegistered` then needs `case SpaceMiss::Unwatched: break;`, and `heapMirrorWatched` must be defined above `spaceMiss`; the merge puts it there. This branch's `else hit = std::all_of(...)` goes away with the `switch`.

## PR text draft

Title: `fix(agc): plan a heap again when its mirror's range has left the write watch`

```markdown
### What

Resident Evil Village (PPSA01556) stopped before the title with a driver failure:

VILLAGE: 

An address-based build serves a registered range that the host import budget refuses from a heap mirror, refreshed from the write watch. `acquireMirror` looked at the watch only when it made the mirror, and the address-space cache only compared the device, the registry generation and the import epoch. A range leaves the watch for good when a host import that does not keep the watch covers it: on Windows, a direct import of private memory that is not settled (below the 1 MiB settle floor, or any import when imports cannot be settled); elsewhere, any import while imports are compared. Retiring the import does not put it back. The next build that reused the mirror, from the cache or from the mirror registry, threw "a heap mirror's range is no longer write-watched" from the heap refresh. A lower import budget makes this far more likely: more ranges are refused and mirrored, and more imports are made and evicted around them.

- A heap mirror records the unwatch serial at which its range was last seen fully watched. Reusing it, and taking a cached space that holds it, compare that serial with `GuestMemory::UnwatchSerial()`, and look at the watch again only when some range has left it since.
- A mirror whose range is no longer fully watched is not reused and the cached space is not taken. The pass plans the range again: an import if the budget holds it, else a copy.
- The registry drops such a mirror when its range is refused, so its buffer does not stay allocated.
- While no range leaves the watch, the cost is two atomic loads per heap mirror per cache hit or reuse.
- Unchanged: a refused heap that is no longer watched is copied, so one larger than `APS5_ADDRESS_COPY_MAX_MIB` still stops the build, now at the copy cap with its range named.

    - `agc_heap_mirror_unwatch_no_space_cache`: the same without the address-space cache.
    - `agc_heap_mirror_unwatched_import`: the heap is imported without the watch (`ImportWatch::Unwatch`) once the budget holds it; the next build takes the import instead of the cached mirror. Not registered on Windows, where the mock cannot model a settled import.
```
