## Step "First": what main can import and sample

`prepareDepthSampling` (`DepthSurface.cpp:95-133`) decides eligibility once, when the target is created (`DepthSurfaceView`, :1929-1943):

| Requirement | Line | Refusal text if missed |

| 2, 4 or 8 samples | :101 | "unsupported native depth sample count" |
| D16 or D32 only | :102 | "native multisample stencil or depth format import is not implemented" |
| Z_X swizzle (24), one slice | :103 | "native multisample depth arrays or non-Z_X layout are not implemented" |

**Depth+stencil HTILE** is refused on `main`, at :106. **Depth-only HTILE** D32 at 4 samples is accepted.

- format 22 (32_FLOAT);
- `k2DMsaa`, `kZ64KBX`, one mip and one slice;
- `dccAddress == htileAddress`, `dccPipeAligned` equal to the HTILE's, the same `iterate256`, the same XOR, no `dccAlphaOnMsb`.

## Why commit 2 can't be green on main

### With the fix

1. With `noteMetadata = true`, `storeBufferFill` calls `Graphics::NoteDepthMetadataFill(base, bytes, pattern[0])` after the store (`BufferFill.cpp:422-423`).
2. `NoteDepthMetadataFill` on `main` refuses any fill that overlaps a native target's HTILE (`DepthSurface.cpp:2357`):

   ```
   if (target.samples != 1u && target.htileAddress != 0u && address < target.htileAddress + HtileMetadataBytes(target.extent) && target.htileAddress < address + bytes) surface->sampling.Refuse("native multisample depth metadata fill transition is not implemented");
   ```

3. `CheckCurrent` (:340) then throws that text on the next sample.

`main` tests this as intended behaviour: `NativeMultisampleDepth.cpp:965-967` creates a target, calls `NoteDepthMetadataFill(target.htileAddress, HtileMetadataBytes(extent), 0u)` and requires `TargetRefuses(..., "metadata fill transition")`. That test passed above.

### Without the fix (main today)

1. The queued fill isn't noted, but `VulkanDevice::FillBuffer` still records it (`VulkanDevice.cpp:2562-2564`):

   ```
   if (uniform) recorder.NotePendingWordFill(address, bytes, pattern[0]);
   else recorder.NotePendingWrite(address, bytes);
   GuestMemory::MarkWritten(address, bytes);
   ```

2. `CheckCurrent` therefore refuses with one of two texts:
   - while the fill is still pending in the driver's recorder: "external GPU writes over native multisample depth are not implemented" (:343);
   - once it has landed and bumped the HTILE generation: "guest writes over native multisample depth are not implemented" (:366).

`main` also tests the first: `NativeMultisampleDepth.cpp:962-963` (`QueueTargetByteWrite` then `TargetRefuses(..., "external GPU writes")`).

### So on main the case is red both ways

- **Without the fix:** "external GPU writes…" or "guest writes…".
- **With the fix:** "native multisample depth metadata fill transition is not implemented".

No data is sampled silently wrong on either tree.

### Other orderings don't help

- **The fill before the creating draw** (the initial-import order): the fill lands before `prepareDepthSampling`, which runs `SyncThrough`, `FlushGpuWrites` and reads the words (:117-129). The words prove the clear, the target imports, and the sample reads `DB_DEPTH_CLEAR`. That is the same with or without the note, because `NoteDepthMetadataFill` finds no surface yet. Not red.
- **JJenkx's three refills after creation:** refused on both trees, as above.
