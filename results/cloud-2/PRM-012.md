## 3. The non-baseline failure: `agc_driver_mesh_index_cache` on #6636

**The failing lines** (full run; the test's whole output after the device and write-watch lines):
```
[Shaders/ShaderRegistry.cpp:790 operator()] Shader 0x556aaad7e700 could not be prepared at registration (its program address is not in the shader registers); preparing it when it is used
[Shaders/ShaderRegistry.cpp:790 operator()] Shader 0x556aaad7e300 could not be prepared at registration (its program address is not in the shader registers); preparing it when it is used
LLVM ERROR: Cannot emit physreg copy instruction
```
The ctest status is `Subprocess aborted***Exception` (0.4 s). The device is `llvmpipe (LLVM 20.1.2, 256 bits)`: lavapipe's LLVM backend aborts the process while compiling the test's mesh shaders.

**Rerun alone at the head:**
- `ctest -R '^agc_driver_mesh_index_cache$' --repeat until-fail:5` stopped at the first run with the same abort.
- Five separate runs: **5 of 5 aborted** (`Subprocess aborted***Exception`, 0.38-0.43 s each, `LLVM ERROR: Cannot emit physreg copy instruction`).

**On the merge base 44df21632125dbe3113a19173e7ebb879da53003:**
- Built only `agc_driver_mesh_index_cache_tests`, in the same tree.
- **5 of 5 aborted the same way** (`LLVM ERROR: Cannot emit physreg copy instruction`). So the failure is not #6636's.

**Why the three heads differ:**

| Commit on upstream/main | What it did | In #6636's base 44df216321 | In #6646's base ce991f1ec2 | In #6454's base 4eb91eacdf |
|---|---|---|---|---|
| 4e82f15c9 `fix(agc): validate mesh index descriptors on cached draws` | added the test (`tests/execution/MeshIndexCache.cpp`) | yes | yes | yes |
| b8db74198 `Revert "fix(agc): validate mesh index descriptors on cached draws" (#5791)` | removed it | **no** | yes | yes |
| d92ebfa88 `fix(agc): validate mesh index descriptors on cached draws (reapply #5791)` | brought it back, skipping on llvmpipe | **no** | no | yes |

- **#6636**'s base has the test without the llvmpipe skip, so it aborts.
- **#6646**'s base has no such test: it isn't in its `ctest.xml`.
- **#6454** and current main skip it on llvmpipe.

So on #6636, a merge of upstream/main (or a rebase) turns the abort into the expected skip. The PR's own three commits don't touch mesh shaders (they change `GuestBufferMemory`, `ShaderResources`, `Draw.cpp` and their tests).

**Environment note:** this run's VM has a different host CPU from my earlier runs today (`Intel Xeon @ 2.10GHz`, now with SHA and RDPID). The abort reproduces at both #6636's head and its base on it.
