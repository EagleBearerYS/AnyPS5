## Step 1: execution test — e0ba27fc60

`test(relinker): run red-zone leaves under writes below rsp, framed and unframed`.

New file: `core/relinker/codegen/tests/RedZoneFramerExecutionTests.cpp`, registered as ctest `red_zone_framer_execution` (`SKIP_RETURN_CODE 77`, `TIMEOUT 60`). It is registered only when the system is Linux on x86_64; on other builds the file is still a plain program that prints a skip and returns 77.

How the test runs:

1. **Build an image** the way the structural test does: a caller with one `call` per leaf at offset 0, then the leaves from 0x40.
2. **Load it** into a 64 KiB RWX arena, with a small runner. The runner:
   - passes 0x1111, 0x2222 and 0x3333 in rdi, rsi and rdx, and 0x4444 in rbx;
   - sets TF around the call.
3. **Frame it** (framed runs only):
   - `FrameRedZoneFunctions` runs on that image.
   - The displacements are written first, the way Conversion.cpp applies them to `sourceBytes` before the patcher builds the trampolines.
   - Each site then gets what `WindowsTrampolineBuilder` does: an OriginalBytes check, the body copied to a stub area, `ApplyStubRelocations`, the return rel32, and the site filled with 0x90 plus `e9 rel32`.
4. **Clobber:** a SIGTRAP handler fills `[rsp-0x80, rsp)` with 0xa5 at every instruction whose RIP is inside the arena. It clears TF once RIP leaves the arena.

Each leaf must:

- return the expected value unframed and without the clobber;
- return a different value unframed under the clobber;
- be framed (`Report.Framed` equals the number of leaves);
- return the expected value framed, both with and without the clobber.

## Step 2: operand stub sites — 259bb69d65

`feat(relinker): move rsp operands that cannot keep their encoding to stubs`.

**Which operands go to a stub:** an rsp operand whose encoding cannot hold the moved displacement. That is:

- an 8-bit displacement that the shift takes past 0x7f;
- `(%rsp)` with mod 0;
- `(%rsp,%idx,s)` with no displacement.

Each such operand is no longer a skip reason in the leaf loop; its instruction index is recorded instead.

**Forming the sites:** this runs after the prologue and exit checks pass (`RedZoneFramer.cpp`, `OperandStub`).

- A site starts at the operand's instruction.
- It covers the following instructions until it is at least 5 bytes long.
- Each covered rsp operand is re-encoded by `withDisplacement`:
  - it copies up to the displacement;
  - it sets ModRM mod to 1 when the moved displacement fits in 8 bits, and to 2 otherwise;
  - it writes the new displacement, then the rest of the instruction (an immediate, for example).
- The other instructions are copied as they are.
- The stub is the re-encoded instructions, then the jump back (`ReturnBranchOffset`, `e9`), through the existing `TrampolineSite` path.
- In-place moves for operands inside a site are dropped, since the stub carries them. Otherwise the displacement write would change the site's OriginalBytes.

**Site rules:**

| Rule | How it is enforced |
|---|---|
| Branch targets | No direct branch target may lie inside the site except at its first byte (`targetInside`). |
| Covered instructions | Must be contiguous and `ControlFlowKind::Sequential`, with no rip-relative operand and no instruction that frees the allocation. **Choice: branches, rets and rip-relative instructions are refused, not relocated.** |
| Overlap | No overlap with the prologue site, any exit site, an earlier operand site of the leaf, or an existing (`--to-intel`) site. |
| Forms | Legacy, REX and VEX forms are re-encoded. EVEX keeps the old reason "rsp operand that cannot move with rsp", because its disp8 is scaled. |
| No room | When no site fits, the leaf is skipped with the new reason **"rsp operand that cannot move and has no room for a stub"**. |

## Step 3: game patches over framer writes — 10fedd32e3

`fix(relinker): refuse game patches over red-zone frame sites and moved displacements`.

- **`WriterSites`** gains `RedZoneSites` and `RedZoneDisplacements`. Both are spans and both have `= {}` (see Checks).
- **`CheckOverlaps`** adds them as writers named "red-zone frame site" and "red-zone moved displacement".
- **Conversion.cpp:**
  - It keeps the displacements outside the `if (options.FrameRedZone)` block.
  - It passes the framed sites as `std::span(trampolines).subspan(intelSites)`, which are the sites appended after the `--to-intel` ones, to the existing post-relink `CheckOverlaps` call.
- **Scope:** a game patch is refused when it overlaps a prologue, exit or operand stub site, or a moved displacement.
  - Game patches are applied before framing, and the framer reads the patched bytes.
