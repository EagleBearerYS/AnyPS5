## 1. Where the plane is unwatched after a store

**The mechanism (both platforms).**
- A depth plane store goes through the plane's mirror, a `StorageTexture` (`StoreDepthPlane`, `DepthSurface.cpp` ~763 on main).
- The mirror's write-back imports the range (`HostImportFor`, `Texture.cpp:5520` on main). `ImportWatched(…, staysWatched = false)` then drops the range from the tracker (`GuestMemory.cpp:1587`).
- After that:
  - `WrittenSince` and `ChangedBlocks` return "not written" for ranges the tracker doesn't cover (`GuestMemory.cpp:1935`, `:1948`).
  - `DepthSurface::WrittenUnits` (`DepthSurface.cpp:850` on main) and `OverwrittenInMemory` (`:588`) ask nothing else.
- So the import's watch decision is what matters.
- The import covers the guest allocation (or the block import), not the plane exactly. So "size" and "alignment" below are those of the imported range.

**Linux** (`decideImportWatch`, `GuestBufferMemory.cpp:1148`; per-import choice `:1755-1756`):

| Import kind | Watched after the store? |
|---|---|
| Host-pointer import (private or anonymous guest memory) | No, if the import probe sees write protection resolved by a GPU read or write, or if the probe fails (`:1185-1188`). Yes otherwise, or with `APS5_WRITE_WATCH_IMPORTS=watch`. |
| dma-buf import (memfd-backed shared memory, non-NVIDIA with the dma-buf extensions) | No, unless the dma-buf probe sees protection kept and CPU stores visible (`:1195`). Without `/dev/udmabuf` the probe fails, so no. |
| any import with `APS5_WRITE_WATCH_IMPORTS=unwatch` | No |

- **Sizes:** no size or alignment dependence on Linux. Any plane whose import is unwatched is affected.
- **This VM** (lavapipe): the probe prints "host imports resolve write protection: yes (0 of 4 scratch pages written after a GPU read, 4 after a GPU write, 0 after the import); imported ranges are compared". The tests saw both planes, 256x128 (131072 bytes) and 1920x1080 (8847360 bytes), "outside the write watch" right after their first store.
- **Existing coverage misses this.** For the same reason, main's own `agc_driver_depth_plane_buffer_memory` prints "guest memory is not write-watched here: a buffer write into the depth plane is not exercised" and skips its guest-write half.

**Windows** (`decideImportWatch` `:1150-1170`; per-import choice `:1751-1753`; deferred settles `:1838`; rewatch `:1110-1132`), by reading the code:

| Imported memory | Watched after the store? |
|---|---|
| Shared section views (not private-writable: `MEM_MAPPED` direct memory) | Yes: imported through an alias, and "separate shared aliases retain guest write tracking" |
| Private writable memory, when the probe fails or there is no settle queue (`watchPrivateImports` false) | No, at every size |
| Private writable, `watchPrivateImports` true, import ≥ 1 MiB (`settleFloorBytes`) | Yes when the settle at import succeeds (`settled`, `:1751`). No if the settle fails. |
| Private writable, `watchPrivateImports` true, import < 1 MiB, base and size 64 KiB-aligned | No at the store. It is queued for a deferred settle (`:1838-1846`), but `rewatchSettledImports` skips a range any live `StorageTexture` overlaps ("kept compared under a storage image", `:1120`). The plane's mirror is such an image for the surface's whole life, so it stays unwatched. |
| Private writable, `watchPrivateImports` true, base or size not 64 KiB-aligned | No: never queued for a settle |
| `APS5_NO_DEFERRED_SETTLES=1` | Imports under 1 MiB are not queued, so they stay unwatched |

## 2. The fix

**`StorageTexture::CompareUnwatched(std::span<std::uint8_t> changed)`** (`Texture.cpp:2449`, declared `Texture.hpp:364`):
- It marks, per 64 KiB block of the surface, the blocks whose guest bytes differ from what the image holds as `original`.
- It compares only units whose `layerOriginal` holds, through the existing `compareUntracked(…, memoize = true)`. That is the same comparison and the same `comparedRanges` memo the mirror's own `Refresh` uses for unwatched ranges.
- It marks the units kept at unwatch, as `Refresh` does.
- Units whose write-back save is still pending (`layerOriginal` false until `applyStoredSave`) are not compared. They read as unwritten, as they do on main.
- It keeps no copy of its own. The mirror's `original` is exactly what the last store wrote, because the GPU write-back to an unwatched import saves the stored bytes into `original` (`prepareStoredSave` and `applyStoredSave`).

**`DepthSurface::WrittenUnits`** (`DepthSurface.cpp:852`):
- When the tracker is on but doesn't cover the plane (`WriteWatched() && !Watched(…)`), it fills the changed units from `UnwatchedUnits` (`:888`) and returns.
- `UnwatchedUnits` maps the mirror's 64 KiB blocks onto the plane's units. Units are 64 KiB at a 64 KiB-aligned base, otherwise one unit for the whole plane.
- The mirror must exist and cover exactly the plane. Otherwise the answer is main's (nothing written).

**`UnwatchedBlocks`** (`:874`) runs the comparison with the surface marked `syncing`. The comparison goes through the flush hook, and `FlushDepthPlanes` skips a syncing surface, so it can't store this plane in the middle of its own check.

**Who gets the answer:**
- `SyncFromMemory` (per bind, `:2006` on main), `FlushDepthPlanes` (which syncs before it stores, `:2131`) and `retireStoringStale` (`:1836`) all call `WrittenUnits`.
- `OverwrittenInMemory` (`:589`) is the only gate into `retireStoringStale`: it decides whether a sampled view retires the surface. It asks the same comparison for the depth plane (`:592`); main asked only `WrittenSince`. The stencil plane has no mirror and keeps main's check.

**Cost:**
- The comparison runs only when the plane is unwatched.
- Its result is cached in `comparedRanges` under the existing stamp: epoch or untracked hint, newest stamp, forget serial, and the recorder's newest write note. So binds within one collect epoch compare once.
- On Linux there is no untracked hint (`UntrackedHint` returns 0), so the stamp is the collect epoch, and each new epoch compares the plane once. The colour path already does the same for storage images over unwatched imports.

**Counter:** `DepthPlaneStoreStatistics::syncs` (`DepthSurface.hpp:30`) counts `SyncFromMemory` copies (`DepthSurface.cpp:930`).

**Where they live.**
- Main has no `depth_guest_write` case; that name is in Cloud 4's `exp/render-scale` `RenderScale.cpp`.
- The new cases are modes of main's existing `DepthPlaneBufferMemory.cpp`, the depth-plane guest-write test.
- Each is registered as its own ctest, `agc_driver_depth_plane_unwatched_<case>`.
- Planes are Z64KBX D32 over write-watched, 64 KiB-aligned memory, which leaves the watch at its first store here.

**The cases:**
- **(a) `--unwatched-draw`, 256x128:**
  1. a draw writes 0.5;
  2. `FlushDepthPlanes`;
  3. a CPU store of 0.125 into the first 4 floats (texel (0, 0) and its three Z-order neighbours);
  4. a draw at depth 0.25, LESS, no depth write, must pass at all texels but those 4;
  5. a later store must keep 0.125.
- **(b) `--unwatched-store`, 256x128 (two 64 KiB units):**
  1. the store;
  2. a draw writing 0.25 everywhere (all units stale);
  3. the CPU write;
  4. `FlushDepthPlanes`.
  - Memory must then hold 0.125 at the 4 floats, 0.5 in the rest of unit 0 (the CPU-written unit is synced, not stored), and the GPU's 0.25 in unit 1.
- **(b2) `--unwatched-retire`:** the same, but the store is `retireStoringStale`. It is reached by a two-level view of the plane through `DepthSurfaceTexture`, which must return null (surface retired); memory is then checked as in (b).
- **(c) `--unwatched-large`, 1920x1080 (8847360 bytes):** (a) and (b) on two planes. Both planes were "outside the write watch" after their store here.
- **(d) `--unwatched-unchanged`:**
  - a store, then 8 draws with no CPU write, then a read;
  - `DepthPlaneStoreCounts().syncs` must not move, nor `stores` or `units`;
  - the read stores nothing, and memory keeps 0.5.

## 4. Cost per bind (1920x1080 D32, no CPU writes)

**The measurement.**
- `--bind-cost 1000`, not a ctest: `DepthSurfaceView(context, target, false)` 1000 times under `GpuMutex`, after the plane's store and one draw.
- It was measured in two ways: within one collect epoch, as binds inside one packet see it; and with a new collect epoch before every bind, the worst case.
- Main = the red build (main's product code and the same harness). Two runs each:

| Build | One collect epoch | A new epoch per bind | Unwatched comparisons |
|---|---|---|---|
| main (red), run 1 | 1099 ns | 912 ns | 0 |
| main (red), run 2 | 952 ns | 809 ns | 0 |
| fix, run 1 | 4596 ns | 1178234 ns | 1 / 1000 |
| fix, run 2 | 4625 ns | 936989 ns | 1 / 1000 |

- **Within an epoch:** the first bind compares the plane, and every later one hits the `comparedRanges` memo. That is about +3.5 µs per bind, including the first compare spread over 1000 binds.
- **A new epoch:** each bind compares the whole 8.4 MiB plane, about 0.9–1.2 ms here (memcmp at about 8–9 GB/s on this VM).
- **In a title:** on Linux, epochs move per packet and wait (`Driver::bumpEpoch`), and there is no untracked hint. So each unwatched depth plane costs one full compare per epoch while it is bound, and a few µs per further bind. That is the same rule the colour path already applies to storage images over unwatched imports.
- **Windows:** where the tracker has a write hint for the range, `UntrackedHint` returns it (by reading the code), which keeps the memo valid across epochs until the CPU writes.
- **Not done:** reducing the per-epoch cost further needs a hint on Linux. Re-protecting the imported pages after the store settles would do it, as Windows' settle does. I did not attempt that here.
