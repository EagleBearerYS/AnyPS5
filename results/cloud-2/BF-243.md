## The rule

**`sameDepthAlias`, `DepthSurface.cpp:103-111` at 037d7e35dc** (called at `:454`, depth plane only). Only `refilled` changes:

```cpp
const bool refilled = recorded.newest == MultisampleColorContent::Clear && current.newest == MultisampleColorContent::Fill && current.fills > recorded.fills && current.fills - recorded.fills == current.sameRun && current.filledBytes >= current.bytes;
return current.active == recorded.active && current.contents == recorded.contents && (current.newest == recorded.newest || refilled) && sameValue;
```

96cf351df8 had `current.fills == recorded.fills + 1u` where 037d7e35dc has the two `fills`/`sameRun` terms.

**`MultisampledColorFill::sameRun`** (`MultisampleTarget.hpp:61`, read through `SameRun()` at `:53`, and reported as `MultisampleColorAlias::sameRun`, `:78`, by `Alias()` at `MultisampleTarget.cpp:558`). It changes in `NoteFill` (`MultisampleTarget.cpp:1128-1148`), which first counts `noted` (`:1131`) for any fill overlapping the target:
- **A whole fill** sets `sameRun = filled == pattern ? sameRun + 1 : 1` (`:1146`): one more if it repeats the pending pattern, otherwise 1.
- **A partial fill, or a fill over a target whose footprint isn't modelled,** sets it to 0 (`:1142`, `:1136`).
- **Applying the pending fill** (`TakeFill`, `:1152`) or **discarding it** (`Discard`, `:1159`) sets it to 0. A recreate makes a new `MultisampledColorFill`, so it starts at 0.

**Why every fill since the import is in the run:**
- **At import the recorded newest is Clear,** so no fill is pending. Only `TakeFill`, `Discard` or a fresh object leave nothing pending, and all three leave `sameRun` at 0.
- **So `current.fills − recorded.fills == current.sameRun`** says every fill noted since the import is in one run of whole fills of the newest pattern.
- **`sameValue`** says that pattern decodes to the recorded clear bit for bit, as in 96cf351df8.
- **`filledBytes >= bytes` and `contents` unchanged** carry over from 96cf351df8, as does condition 4: the final `UnchangedSinceAll` over the HTILE at `:506`.

**Why a run is as safe as one fill:**
- An absorbed whole fill writes no guest memory (`BufferFill.cpp:391`) and doesn't bump `contents`. It only sets the pending pattern.
- Repeating the same pattern over the same range leaves that state identical.
- A run that hides an earlier partial or other-value fill doesn't match the count, so it still refuses.

**`fills > recorded.fills`:** it only keeps the subtraction from wrapping; `noted` never decreases.
