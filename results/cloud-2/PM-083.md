**Main's #6931 behaviour is kept as it is, with or without the knob:**
- The start-of-packet drain for an indirect draw whose argument or count range overlaps a pending write, or for every indirect draw under `APS5_NO_PIPELINED_INDIRECT`, is main's code unchanged. It now sits in a local `drainIndirectArguments` helper.
- The CPU path is main's unchanged. It reads the records on the packet worker, draws all but the last drawable record inline after `drainBeforeInline`, and enqueues the last one.

**#1896's GPU-side half, behind `APS5_PIPELINE_INDIRECT=1`:**
- The start-of-packet drain is skipped. That holds unless `APS5_NO_PIPELINED_INDIRECT` is set, since that switch is #6931's own opt-out.
- A CPU-path draw then runs the same overlap check at the top of its CPU-path block, just before it reads its records. A drain there counts as `IndirectArgsDrain`.
- An indirect draw that the device reads its own arguments for now takes main's direct-draw enqueue (`if (pipelined && (!drawParameters.indirect || pipelineIndirect) && …)`). That replaces `drainBeforeInline()` plus inline recording, and it counts `IndirectCommit`.
- **My addition:** its argument range and, when present, its count range are appended to the commit's held reads (`QueuedDrawReadRanges` plus the two ranges). Main has since gained held reads (00053a3f6) to keep later stores out of a queued draw's inputs, and #1896 predates it. Without this, a GPU-side indirect commit's arguments would be the one input of a queued draw that isn't held.
- #1896's validated-hit overlap drain (`DrainIfOverlaps(memory, regionBounds, Capture)`, then translate again) is taken behind the knob.

**Dropped:** #1896's CPU-side block, which read and expanded the argument records on the worker and enqueued them as one commit (`ExpandedDraw`, `enqueueExpanded`). #6931 covers that path, and keeping both would have changed #6931's default path. The extra `Drain(Indirect)` that #1896 put at the top of the CPU block goes with it.
