## The red, and why (a)

I chose **(a), the mismatch counter**. Its plain-build red is the exact signal the bug produces:
- Without the fix, the adopting dispatch's regions point into the freed one-word `liveWords`, and `AddSnapshot` compares those freed bytes with the live region.
- On Linux the comparison differs every time. glibc frees that 4-byte vector into its tcache, which stores its free-list pointer in the first 8 bytes of the block, overwriting the word. The difference is always at `+0x0`.
- (b) needs a snapshot with no live owner. The upload would then copy the freed bytes, and the output would be wrong only when those bytes changed. That is the same dependency on the allocator, plus a less direct check, so it adds nothing over (a).

**Plain-build red** (f5fd23ee3 with `Dispatch.cpp` set back to main's, test and accessor kept; CI's Linux configure; `ctest -R '^agc_driver_dispatch_data_hit_words$'` ×20 as `runner`): **0 passed, 20 failed**. Every run prints these two lines (addresses replaced by ADDR):

```
[gpu] guest snapshot differs from registered memory: snapshot ADDR+0x4 (live region ADDR+0x10000, writable, host-backed) differs first at +0x0; the live region serves the GPU (1 mismatches so far; APS5_SNAPSHOT_CHECK_FATAL=1 fails the dispatch instead)
dispatch data hit words: data hit 1, resolved ahead on the compute queue: its snapshots differ from the registered memory serving them (1 snapshot mismatches)
```

**Plain-build green** (f5fd23ee3): `--repeat until-fail:20` → **20 of 20 passed**. One direct run prints `dispatch data hit words: 4 data hits resolved ahead read their own live words` / `dispatch data hit words tests passed`, and no "guest snapshot differs".

**Windows caveat (not run here).** The red needs the freed word to read differently from guest memory when `AddSnapshot` compares it.
- glibc guarantees that on Linux (above).
- On Windows the CRT heap frees a 4-byte block into the low-fragmentation heap. As far as I know, that heap marks free blocks in a bitmap and leaves their contents alone. Then the freed word still holds the same value, the compare agrees, and the test passes on the Windows runner without the fix.
- So the Windows red is likely not deterministic. It can't be made so from the test: `libSceAgcDriver` is a SHARED library (`CMakeLists.txt:262`), so the test can't replace the allocator the driver uses.
- If the PC's Windows run without the fix passes, the dependable signal there is the Linux red plus ASan (below). A deterministic Windows red would need a check on the pointers themselves: for example, a count of adopted data-hit regions that don't lie in the adopted `liveWords`. That costs production code, so I didn't add it without a decision.
- `APS5_SNAPSHOT_CHECK_FATAL=1` still hides the bug. The mismatch throws before it's counted, and the resolved-ahead rethrow re-runs the dispatch. The ctest entry doesn't set it.
