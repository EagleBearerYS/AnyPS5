## 1. The gap

**At 22cead42b2,** in `core/shader/recompiler/Optimization/src/ResourceMaterializer.cpp`:
- `deviceInterfaceImage` (2693–2699) clears `source` and `firstUsePc`, and sets `table` to 0 when it isn't `NoTable`.
- `mixImageInterface` (2701–2724) mixes every other field of `ImageResource` (`IrMetadata/Resources.hpp:66–115`) except five:
  - `adjustedSample` (Resources.hpp:97);
  - `dimensionQueryOnly` (:100);

- `RegisterDeviceImageInterface` (2745–2766) compares with the defaulted `operator==` (Resources.hpp:114). So two device-table images, or two mode lists, that differ only in one of those five get one id. The second registration then throws at 2757.

## 3. Persistence

**The id is stored in two places:**
- **In the SPIR-V:** `SpirvImageEmitter.cpp:2002` computes `DeviceImageInterfaceId(base, modes)`, and :2006–2007 emit its two halves as constants in the device image lookup key.
- **In the cached compile result:** `Recompiler.cpp:1396–1398` fills `result.deviceImageInterfaces`, which `ShaderDiskCache.cpp:704` writes and `:753` reads back. The driver names the interfaces from it (`HeapStages.cpp:866`).

The registry itself is only in memory. It is refilled each time a result is built (`Recompiler.cpp:1395`), including when the SPIR-V comes from the cache (`:1389`).

**Why a changed id can't meet an old entry:**
- Every disk cache entry carries `FormatVersion` **and** `SourceVersion()` in its header (`ShaderDiskCache.cpp:1478`). A load with either one different is rejected (`:1491`).
- Entries live in a directory named after `SourceVersion()` (`:1514`, and `:1657` for the prebuilt cache), and both go into the key (`:1950–1951`, `:1971–1972`).
- `SourceVersion()` returns `Generated::SourceVersion` (`:1942–1944`). That is a SHA-256 manifest over the recompiler's sources (`ShaderCacheVersion.cmake:36–45`).
- The build's list (`shader_recompiler_agc_driver_generated/sources.txt`, 259 sources) includes `Optimization/src/ResourceMaterializer.cpp`, `SpirvBackend/src/SpirvImageEmitter.cpp`, `Recompiler.cpp` and `ShaderDiskCache.cpp`.
- So this change gives a new `SourceVersion`. An entry whose SPIR-V or result holds an old id is never loaded alongside the new registry.
- The payload layout doesn't change, only the id values.

**So no `FormatVersion` bump is needed,** and #7642 stays at 62. Any pipeline keyed by SPIR-V words also follows, because the ids are constants in that SPIR-V.
