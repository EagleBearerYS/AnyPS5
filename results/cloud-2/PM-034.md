## How the checks were made
- **Merges:**
  - `git merge-tree --write-tree upstream/main <head>`.
  - For the build, a local `git merge --no-ff` onto d92a8dad39 for each candidate, kept as `scratch/pm034-<name>` and not pushed.
  - Trophies part 2 was merged after part 1. v3 carries #6146, so its merge brings both.
- **Builds and tests:** the CI-mirror script, which runs CI's configure, then `tools/check_test_registration.py build`, then `cmake --build`, then `--target libs`. Then `ctest -R <own tests>` and `ctest -R '^agc'`, as the runner with CI's environment.
- **Windows traps:** a scan of each candidate's added lines against its base (3rdparty excluded):
  - `alignas(` with a value above 8192 or not a literal;
  - the identifiers `far`, `near` and `small`, outside comments and strings;
  - `thread_local`;
  - `long` other than `long long` and `long double`, and `%l[diouxX]` formats;
  - a list of POSIX-only calls and headers, with the `#if` nesting each sits under.
  - Each hit was read by hand.
- **Reaching `windows.h`:** preprocessing with MinGW's macros and a stub `windows.h`, with stubs made on demand for other missing headers, and `-H` for the include chain. The Windows CI job is MinGW g++ (winlibs 15.2.0, UCRT), which defines `far` and `near` as empty in `minwindef.h`.
- **Conventions:** upstream/main's copy of `tools/check_conventions.py`, run in a checkout of each head, with `--base upstream/main` and with each branch's own base.
- **Actions:** the fork's Build and Verify finding runs.
  - A Build that merges a PR names it in its eligibility job log: "PR #N at <sha> merged into main at <sha>". That is how runs were matched to heads.
  - Verify finding runs name the head in their branch (`verify/<branch>-<short sha>`); I checked the verify commit's parent.
  - No Build run is on any candidate branch itself. Fork PRs: #23 is trophies part 1, #19 is FSR at fea68147a, #22 is #6146.
