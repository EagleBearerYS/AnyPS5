## 1. #6636 `perf(agc): reuse address-based draw builds whose inputs are unchanged`

**Verdict: gaps found.** The reuse re-runs, inside the same GPU lock hold, every check a cache-hit build makes, in practically the same order. That covers space identity and import epoch, mirror refreshes, pending writes, snapshots, images, V# bases and the fault buffer. Two checks a reuse repeats compute a guest buffer's size their own way instead of the build's (F2, fixed):
- **The moved-buffer check** sees any buffer whose descriptor reaches past its allocation as moved, so such a draw is never reused.

### 1.4 A better version?

A newer PR could make address-based draws cheap to build instead of reusing them, or reuse them more often:
- **Several uses in flight.** One fault buffer and written-page record per in-flight use (a small ring per build) would let a once-per-frame draw reuse while the previous frame is still on the GPU (P1). Today the gain comes mostly from draws repeated within a frame.
- **One proof, not parallel copies.** F2 is what parallel copies of a build check cost: two reuse-time checks each recomputed a buffer's size their own way. The reuse should call the build's own computations, as the fix now does for buffer sizes.
- To stay the better one, #6636 needs:
  - the F2 fix;
  - a decision on F1: re-prove poisoned elements in both walks, and treat a throwing `cachedTexture` as "not reusable";
  - a ring of fault records, if back-to-back reuse matters.

## 2. #6641 `fix(agc): stop and join the driver's thread pools at shutdown`

**Verdict: gaps found.** Two more driver-owned threads have the same failure mode and are now stopped and joined (T1, T2). More threads outside the driver can be alive or starting at exit. The most likely to hit the PR's exact mechanism is libc's exit waiter (T3), which only Windows can show.

### 2.1 The mechanism

- winpthreads initializes a statically initialized condition variable at its first wait, under its global `cond_locked` spinlock.
- ExitProcess kills the other threads. If one dies inside that first wait, `cond_locked` stays locked.
- The next DLL-detach destructor of a static condition variable that was never waited on then spins on it forever.
- So any host thread that can be in its *first* wait on a condition variable while the process exits can hang the exit.

### 2.3 Correctness holes and races at shutdown

- **T1's shutdown race (fixed):** a deferred completion could run on the committer after `Driver::stop` had reset the device and while static destructors ran. The committer now runs the commits still queued before the device is reset.
- **Order in `Driver::stop` after the fix:**
  1. the queue workers are joined;
  2. the committer is stopped, after it runs what is queued (commits need the GPU lock, so this comes before `stop` takes it);
  3. the samplers and preparation pools close;
  4. then, under the GPU lock: the device reset, the buffer workers, the library worker, the compare helpers and the cache writer.
- **After the shutdown:** a commit enqueued after the stop runs on the caller, and a cache store is written on the caller. Neither starts a thread.
- **One precondition:** `DrawPipeline::Stop` must not run under the GPU lock, as `Drain` already requires. `Driver::stop` is its only caller.

### 2.4 A better version?

The root cause is process-wide: any thread in its first condition-variable wait at exit. Joining threads one site at a time (#6641, and this branch) cannot cover guest threads or SDL. More general fixes:
- **Leave without DLL detach.** Once the shutdown hooks have run and stdio is flushed, end the process with `TerminateProcess` (libc's `LibcTerminate` already does this for `_Exit`). No static destructor runs, so nothing waits for `cond_locked`. The cost: anything that relies on a static destructor to finish its output, such as `CaptureTrace`'s worker, would need an explicit shutdown hook first.
- **Waits that need no lazy initialization.** `LibcAwaitExit` could park on a Win32 event or a sleep loop instead of `std::atomic::wait` (T3).
- **To stay the better one,** #6641 needs at least a test that `AgcDriverShutdown_nid_postfix` leaves no driver thread running. This branch adds that for the committer and the cache writer. It also needs a decision on T3, the exit waiter guest threads park in.
