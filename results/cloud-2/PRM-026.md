## Commit 1: teardown

- **`stop()`** (`Lifecycle.cpp`), right after its `if (stopped) return;` and before `LibcRequestShutdown` and the worker joins:
  - clears the hook (`GuestArenaSetHostWriteHook_nid_no_patch(nullptr)`);
  - calls `GuestMemory::StopHostWrites(1000)`.
- **`StopHostWrites`** sets a stopped flag (seq_cst), then waits up to 1 s, in 1 ms sleeps, for the in-flight count to reach 0.
  - It returns false when the bound expires, and `stop()` then logs `[driver] a host write was still inside the driver's hook 1 s into the shutdown; stopping without waiting for it` and continues.
- **`PrepareHostWrite`**, after its `ownHostWrite`/`bytes == 0` return:
  - counts itself in flight through an RAII object (seq_cst increment, decrement on exit);
  - then returns if the flag is set.
- **Ordering:** the increment-then-check against set-then-wait (both seq_cst) means either the call sees the flag, or `stop()` sees the call in flight.
- `~Driver` still clears the hook first, as before.

**Test (`host write after shutdown`):**
- dispatches a storage image's write over a 128 KiB surface;
- records its store with `StorageTexture::FlushPending`, and checks that guest memory is still untouched (the store is recorded, not landed);
- calls `AgcDriverShutdown_nid_postfix()` (`Driver::Shutdown`);
- installs a counting flush hook (`GuestMemory::SetFlushHook`), makes a 64 KiB host write over the range, and requires 0 calls.

**Change from the plan, and why:** the plan said to observe `FlushForAccess`'s `hookCalls` (`Recorder.cpp:1005`). That counter has no accessor at `082c3268a`, and a red at that commit has to compile there. So the test counts at the flush hook itself, the only way `PrepareHostWrite` reaches `FlushForAccess`. After `stop()` the recorder is gone, so replacing the hook loses nothing the test needs.

## Commit 2: the lock check

- **`PrepareHostWrite`**, right after the `ownHostWrite` return: if `GuestMemory::GpuMutex().HeldByThisThread()`, it calls `noteLockedHostWrite`.
- **`noteLockedHostWrite`:**
  - **Without `APS5_ASSERT_GPU_LOCK`:** it increments a counter and logs the first occurrence once, then the host write continues (no throw):
    - `[lock] a host write of 0x10000 bytes at 0x7fb9ed1d0000 was made under GuestMemory::GpuMutex on thread tagged 0xffffffff; it waits for GPU work with the mutex held (counted, logged once)`
  - **With `APS5_ASSERT_GPU_LOCK=1`** (the switch `AssertGpuLockHeld` reads), it prints this line and aborts:
    - `[lock] ASSERT: a host write of 0x10000 bytes at 0x7f26204f0000 was made under GuestMemory::GpuMutex on thread tagged 0xffffffff`
    - Running the test with the switch exits with 134 at that line.
- **Accessor:** `std::uint64_t GuestMemory::LockedHostWrites()`.
- **Debt** (`docs/dev/debt/libSceAgcDriver.md`): a new bullet right after #6926's pending storage-image results entry:
  - "Host writes into guest memory (libSceAgcDriver) must not be made under the GPU mutex or another driver lock; one made under the GPU mutex is counted (`GuestMemory::LockedHostWrites`) and logged once, and aborts under `APS5_ASSERT_GPU_LOCK=1`."

**Test (`host write under the GPU mutex`):**
- `AgcDriverWaitIdle_nid_postfix()` so that the driver and its hook are installed;
- a 64 KiB host write while holding `GpuMutex` (a `lock_guard`) must return and move the count by exactly 1;
- a host write without the mutex must not move it.

**The red** is on a synthetic base, as planned: `2ff4ed647` plus the accessor alone (a counter nothing increments) plus the test.

## Commit 3: the counters

- **When:** under `APS5_PROFILE_DRAW`, `PrepareHostWrite` reads the thread's waited milliseconds before and after `FlushGpuWrites`.
- **What it counts:** calls, calls that waited (difference > 0), total waited time, and the longest single wait.
- **Accessors:** `GuestMemory::HostWritesCounted()` (a `HostWriteCounts` struct) and `GuestMemory::HostWriteReport()` (the line).
- **Printing:** one `[hostwrite]` line every 10 s, through `ProfilePrint_nid_no_patch` with a 10 s `lastReport` compare-exchange, the way the `[rescache]` and `[guestmem]` lines do it. The first counted call prints at once.
- **Without the switch,** `PrepareHostWrite` calls `FlushGpuWrites` exactly as before.

**Change from the plan:**
- **First attempt:** the plan's fallback, reading ShaderMemory's provider through a new `ShaderMemory::WaitedMs()`.
  - That broke the link of `agc_write_tracking_tests`: `collect2: error: ld returned 1 exit status`.
  - That target compiles `GuestMemory.cpp` without `ShaderMemory.cpp`.
- **As committed:** GuestMemory has its own provider, `GuestMemory::SetWaitedMsProvider`.
  - `Lifecycle.cpp` sets it next to ShaderMemory's, with the same `Graphics::Recorder::ThreadWaitedMs`.
  - So it is the same function, set at the same place, and no link dependency on ShaderMemory.

**Test (`host write waits`):** the test sets `APS5_PROFILE_DRAW=1` at start.
- A 64 KiB host write over a range whose storage-image store is recorded (`FlushPending`, memory still untouched) must count one call, one waited call, and more waited time.
- A host write over an idle surface must count one call and no wait.
- The test then prints `HostWriteReport()`.

**Lines from the green run:**

- The first `[hostwrite]` line is the 10 s profile printer, firing on the first counted call.
- The second is the line the test prints after both writes.
- No red is claimed for commit 3. It adds a feature, and its test needs the new accessors.
