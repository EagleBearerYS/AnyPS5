## 2. Details

### 2.1 #6455: sibling paths on main (5d9dcc42d2)

**Every store path the tracker has:**

| Path | Stamps a partly watched store? |
|---|---|
| `MarkWritten` (`GuestMemory.cpp:1487` on main) | Fixed by #6455. |
| `storeOwn` / both `StoreOwnBytes` (`:1443`, `:1471`, `:1478` on main) | Fixed by #6455, including the Linux shared-backing write, which the write watch never sees. |
| `watchPrivateMapping` (Windows, `:1043`) | Not affected: it stamps every block of the mapping. |
| `Rewatch` (#6678) | Not affected: whole restored blocks only. |
| `stampWrittenRun` walks: `CollectWrites`, `ImportWatched`, the absorbs in `storeOwn` | Not stores. `CollectWrites` returns 0 for a partly watched range without walking, so the CPU writes there stay dirty for the next collect of a watched range. `ImportWatched` unwatches what it can't walk. |

**The callers on main,** none of which checks `Watched()` before storing, so none bypasses #6455:
- **VulkanDevice** labels: `:2084`, `:2093`; sample dumps: `:2125`; fills: `:2306`; CPU copies: `:2441`; transfer copies: `:2547`.
- **Graphics:** `Draw.cpp:263` (CMASK proofs), `BdaResources.cpp:322`, `DccMetadata.cpp:257`, `GuestBufferMemory.cpp:4284`, `:4372`, `:4402` (write-backs), `Texture.cpp:4115`, `:4242`, `:4692`, `:4811`, `Recorder.cpp:3210` (completion stores).
- Where a caller uses the returned generation (`VulkanDevice.cpp:2547`), 0 still means "untracked", as before.

**Readers that gain from the fix:**
- the CMASK proof's `StoredOver` (`Draw.cpp:185`);
- the texture edge checks (`Texture.cpp:1922`, `:3355`, `:4609`);
- `UnchangedSince` / `UnchangedSinceAll` for vouched columns and cached ranges.

**`StoredAllSince` (the native depth clear's HTILE proof, `DepthSurface.cpp:215`)** can now see pieces from a partly watched store. Those bytes were stored, so the proof stays sound.

**Ordering against pending GPU writes and labels:** most of these calls stamp at record time, next to a pending-write or label note that the flush hook syncs before a read. The partly watched path keeps that contract: same lock, same generation bump, and still 0 returned with an unstamped note.

**Windows granularity:** `WriteWatchCoverage` excludes whole 64 KiB blocks aligned to the arena base, the same blocks as the tracker's. So `covers(first, 1) || covers(stop - 1, 1)` is exact per block, as 89778ecda says.

**Better version?** No other open PR stamps partly watched stores. The scan covers PRs open on 2026-10-15T16:05Z plus #6455/#6475/#6678, fetched now; the PRs touching `GuestMemory.cpp`'s tracker are #6346, #6308 and #6678.
- **Alternative 1: stamp every block of every store and drop the watch lookups.** Simpler, but it allocates tracker leaves (Linux) and driver-piece entries for unwatched memory, which GPU write-backs hit constantly.
- **Alternative 2: let `unchanged()` consult the hashed unstamped-store slots.** It would close the hole too, but conservatively and coarsely. It gives `StoredOver` and #6346 no pieces, and it fails proofs on slot collisions.
- **So #6455 is the better version.** To stay that way it needs to land before #6678 (N3) and to keep recording pieces per block, which #6346 relies on (N4).

### 2.2 #6475: sibling paths on main

**Every guest read a capture makes now runs the guard:**
- page reads: `ShaderMemory.cpp:192`, once per page and capture, as before #1193;
- raw words: `:253`;
- synced and verified words, through `GuestMemory::Read`;
- word-wise pages: per word. The observed `before` copy is followed by a guarded `Read`.

**What feeds captures is guarded too:**
- the initial snapshots (`Draw/Draw.cpp:215`, `Dispatch/Dispatch.cpp:250`) are shader code, headers and decode reads (`ShaderInputState.cpp:238`, `:249`), and those reads go through `GuestMemory::Read`;
- `DataHitVerification.cpp:15` builds a fresh `ShaderMemory`, so it goes through `page()`.

**Readers that run `FlushGpuWrites` without `Read`,** where the guard matters:

| Reader | Status |
|---|---|
| Shader capture | Fixed by #6475. |
| `VariantValidation.cpp:56` and the capture validations | R1. |
| `CopyDrawInput`'s snapshot reuse and `InPlaceDrawInput` (`Draw.cpp:898`, `:931`) | R3. |
| `syncRange` (mirrors, `GuestBufferMemory.cpp:1593`) | R3. |
| Texture snapshots (`Texture.cpp:2091`, `:2117`) | Guarded per use by `ShaderResources.cpp:575` / `:939`. |
| Display buffers (`DisplayBuffer.cpp:251`, `:269`; `VulkanDevice.cpp:2843`) | Single-sample. |
| Shader code (`ShaderRegistry.cpp:82`) | Not data a target can hold. |

**R1 in detail.** A variant or draw-cache stage capture is revalidated by `validateCaptured` / `captureStable` / `validateVariant`, or vouched by stamps.
- None of them runs `GuardRead`. A per-region guard there would take a shared lock and scan the guarded ranges for every region of every validated draw while any target lives (Village always has one), which is the per-use cost the PR avoids.
- **Cheap exact design, if the author wants R1 closed:**
  1. count target and depth guard registrations in a global epoch: `MultisampleTarget.cpp:260`, and the depth guard's registration;
  2. store the epoch with each capture;
  3. run `GuardRead` over a capture's regions only when the epoch moved since.
- **Test sketch (Linux, `agc_multisample_guest_access`):**
  1. dispatch a shader whose SRT lies just past a 4x target's memory, so the variant is cached;
  2. create a second 4x target over that memory;
  3. dispatch again with the same SRT pointer and expect the CPU-read refusal.
  - At 07a4ac7e15 the variant is served (red). With the epoch it throws (green).
- **Not built here:** it is pre-existing, needs recycled memory, and the dispatch-cache test harness it needs is large.

**Better version?** Two candidates, neither better:
- **Guard inside `FlushGpuWrites`.** It would cover every raw-read path at once, but `FlushGpuWrites` also runs before writes (`GuestMemory::Write`, `WriteChanged`) and on hot paths. A write overlapping a target would then fail as "a CPU read", and every flush would pay the scan.
- **Guard inside `EqualsCommitted` / `CompareMapped`.** It covers R1, at the per-region cost above.

So #6475's targeted guard, once per page per capture, is the better version. It stays better if the validation reuse (R1) is documented or epoch-guarded. No other open PR in the scan touches `ShaderMemory.cpp`'s guard. #6312 touches `ShaderMemory.cpp` for heap allocations only.
