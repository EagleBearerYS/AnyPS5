## Design

- **Statistics** (`OverlayStatistics`):
  - Each present records its time and two running totals, GPU and driver.
  - FPS is (n − 1) / span over the presents of the last second.
  - Frame times go in a 120-entry ring; min, avg and max are taken over the ring.
  - GPU and driver ms per frame are each total's growth over that second, divided by the frames.
- **Sources:**
  - **GPU total:** grows where `APS5_PROFILE_GPU` already adds each batch's span from its first to its last command (`Recorder::readGpuTiming`).
  - **Driver total:** grows in `Driver::timed` by the packet workers' dispatch and draw time, which is the `[gpu] worker` line of `APS5_PROFILE_DRAW`.
  - Both use relaxed atomics and cost nothing without their variable. Each line is shown only when its variable is set.
- **Text:**
  - The 5x7 bitmap font is glyph data in `PerformanceOverlay.cpp`, written for this. It covers the digits, `A D E F G I M N P R S U V X`, `.`, `:`, `/` and space.
  - `LayOutOverlay` turns the panel, the text lines and the graph into rectangles; glyph rows become horizontal runs.
  - The integer scale is about height / 480: 2 at 720p and 1080p, 3 at 1440p, 5 at 2160p. It is reduced until the panel fits the window.
  - The panel goes in the corner `ANYPS5_OVERLAY_POS` names, 4 units from the edges.
- **Drawing:**
  - `PerformanceOverlay` draws the rectangles as instanced quads from a per-slot host-visible vertex buffer.
  - It uses one render pass with LOAD/STORE, a render area equal to the panel, and alpha blending: the panel is black at 60%, text white, the graph green.
  - It has its own pipeline and does not use the title's pipeline cache.
  - When the overlay is shown, `VulkanDevice::present` changes its tail. On the presentation-pass path that pass ends in `COLOR_ATTACHMENT_OPTIMAL`. On the blit and clear paths the overlay pass replaces the `TRANSFER_DST`→`PRESENT_SRC` barrier. In both cases the overlay pass moves the swapchain image to `PRESENT_SRC`.
  - When the overlay is hidden, the present does one relaxed atomic load and records exactly the commands it recorded before.
- **HDR10:** the palette is converted from BT.709 to BT.2020 and PQ-encoded, with white at 203 nits (`PqReferenceWhiteNits`, the BT.2408 reference white). sRGB swapchain formats get linear values.
- **Control:**
  - `ANYPS5_OVERLAY=1` shows the overlay from the first frame.
  - F10 toggles it at any time through `AgcDriverTogglePerformanceOverlay_nid_postfix`. The key is `InputControl::TogglePerformanceOverlay`: keyboard only, as `ToggleFullscreen` is, and it can be moved in `anyps5-input.ini`.
  - Statistics restart each time the overlay is shown again.
  - An invalid value of either variable stops the game at its first frame with an error naming the variable, as `ANYPS5_LANGUAGE` does.

## Unsure / decisions

- **F10 without the variable:** F10 also works when `ANYPS5_OVERLAY` is unset; the variable only sets the start state. If the overlay should be possible only with the variable, F10 needs a check.
- **Separate render pass:** blit and clear presents never run the presentation pass, so the overlay is its own render pass right after the frame reaches the swapchain image, on all three paths. On the presentation-pass path it could be a second draw inside that pass instead; I kept one code path.
- **What FPS counts:** every present on the presenting thread, including clear presents (no display buffer), rather than the guest's flips.
- **GPU line:**
  - It is the sum of batch spans (first to last command) completed in the last second, divided by the presents.
  - Overlapping batches of different queues are both counted, so with async compute it can exceed the frame time.
  - The present blit and the overlay itself are not included.
  - It trails a change by up to a second.
- **Driver line:** dispatch and draw time of all packet workers on all queues, without their waits, per frame.
- **HDR10 brightness:** 203 nits for white is a choice. The panel is blended in PQ space, so it darkens less, perceptually, than the SDR panel does. I have not seen it on an HDR monitor (no Windows or HDR display here).
- **Not built or run on Windows (MinGW) or a hardware GPU.** No platform-specific code was added.
- **Graph scale:** the full height is the larger of the slowest frame and twice the average.
