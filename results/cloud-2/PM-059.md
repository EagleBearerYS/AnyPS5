## 2. Correctness

- **No remembered refusal can answer a request that would now succeed.**
  - The memory check (`:1154`) runs after the same-run hit and the failure checks, and before the held loop.
  - While `epoch`, `liveBytes`, the window and the horizons hold, the block's overlapping imports, `replaced` and `evictable` are fixed. So the refusal and the room it leaves are fixed, except that a lower budget lowers the room by the same amount.
  - A newly held overlapping import only sends the request down to smaller blocks with less room.
  - Main's `expandedWindow` held rule (`:1173`) only allows replacing an import when a recorder is active. If the recorder goes away, the request returns `nullptr` either way.
- **The branch's rule is exact.** A remembered refusal now reproduces the scan's own decision (`:1159-1161`), with `room' = room − (stored budget − budget)`:
  - if the run can step down and the containing range fits in `room'`, it steps down to `min(bytes / 2, room')`, exactly as the scan would;
  - otherwise it is refused.

  Refusals are now recorded before a step-down (`:1206`), so each block a chain tries is remembered. A chain that ends in an import makes one, and that changes `liveBytes` and ends the block's memory. The step-down always halves or more, so it terminates.
- **Existing tests still pass.**
  - `evictingRefusalRangeTests`: a 128 KiB range is refused, then a 64 KiB range of the same block steps down.
  - `evictingRefusalWindowTests`: the window is set after the refusal.
- **G3 keeps join memories apart** (`joined` compared at lookup). A join skips the held-import check and never steps down, so its refusal must not answer a non-joined request for the same run.
- **The merge of main is complete.**
  - For `GuestBufferMemory.cpp`, `GuestBufferMemory.hpp`, `tests/BdaResources.cpp` and the debt doc: every line main added since the merge base (0029e62f97) is in a3fefab585, and no line main removed is still there.
  - The resolved `importRunAt` keeps main's held rule with `expandedWindow` and its step-down on a held import (`:1173-1177`), and #6730's memory check and insert.
- **A related observation.** An import inside a block survives only while the whole block is skipped (a failed block, or a remembered non-evicting refusal): `refreshImports` retires it once its block forms. That is why G2 needs a stepped-down walk to show up.

## 3. Composition with BF-019

**Would BF-019 alone make this memory unnecessary? No; they compose.**
- BF-019 (cloud-2, `perf/agc-evict-space-only-imports` a612fca7b2, on 4ee79e522e) turns the frozen-budget refusals into one eviction each.
- The refusals that remain still benefit from the memory:
  - nothing evictable because every candidate is young;
  - candidates held back by BF-019's warm-up or window guards;
  - repeats inside one upload.

**What #6730 needs once BF-019 lands:**
1. **A textual rebase.** `git merge-tree` of a612fca7b2 with a3fefab585 conflicts in `evictingRefusalCurrent` and in the debt-doc paragraph. The resolution is the union: `budget <= refusal.budget` (BF-020) and `state.spaceBuilds < refusal.opens` (BF-019).
2. **Exactness is already handled.** BF-019 added `EvictingRefusal::opens` and the guarded-import horizon, so the memory stays exact under the guards. With this branch, a stepped-down remembered refusal is still correct under the guards: the room is fixed while the memory is current.
3. **Its value shifts.**
   - Under BF-019, imports that only the space keeps young have an old `lastUse`, so `readyHeld` has passed. A remembered refusal made while a build holds them ends at the next floor rise, which comes at every `UploadFinish`.
   - That is correct when the guards are open: the request can then win by evicting.
   - While BF-019's guards are closed, it ends early for no gain. The refinement belongs in BF-019's `evictableBytes`: a held import whose `lastUse` is old and whose `spaceUse` is recent should go into the guarded horizon (`opens`, `spaceUse + 257`) rather than `readyHeld`.
4. **This branch's three commits and BF-019 also conflict textually.** `git merge-tree` of a612fca7b2 with a48aa76933 conflicts in three places, each resolved as a union:
   - the struct's last field: keep both `opens` and `joined`;
   - `evictingRefusalCurrent`: BF-020's budget rule plus `spaceBuilds < opens`;
   - the insert line, which G2 moved before the step-down and BF-019 extended with `opens`: keep G2's position with both fields.

   Not merged or tested together.
