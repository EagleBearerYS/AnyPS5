What KytyPS5 (source 1) established:
- **Unlock event.** The event is `_UnlockTrophy`, and the trophy id is its `_trophy_id` property, read only as int32. A missing or negative id is rejected (libTrophy.cpp `NpUniversalDataSystemPostEvent`).
- **CreateEvent ownership.** `CreateEvent` copies `prop` into the event, and `*prop_ptr` is the event's own property object (`*prop_ptr = &(*new_event)->properties`).
- **Contexts.** UDS contexts carry `(user_id, service_label)`, which is the trophy key.
- **Stat-driven unlocks.** Other events unlock trophies only through two files:
  - the title's stat rules in `sce_sys/uds/udsNN.ucp`: `stats_definition.json` `statDefinitionArray`, aggregation `latest`, and `stats_extraction.json` `statsExtractionRuleArray`, where `condition.eventName` plus `action.input` give `action.output.statId`;
  - the trophy's `unlockCondition` in `sce_sys/trophy2/trophyNN.ucp`: `udsStatId`, `targetValue`, `comparator` (ge/gt/le/lt) and `progressive`.
- **The `.ucp` container.** It starts with big-endian magic 0xB228C60A and version 1, then a size at 0x08, an entry count at 0x10 and a TOC offset at 0x14. Entries are 0x40 bytes from TOC+0x20: a 32-byte name, a big-endian offset and a big-endian length.
  - The trophy data is `tropconf.json`: `trophies[]` with `id`, `grade` from "PGSB", `groupId`, `hidden`, `hasReward`, `platinumTrophyId` and `unlockCondition`.
  - The text is `tropmeta_<lang>.json`: `titleMetadata.name`, `trophyMetadata[]` and `groupMetadata[]`.
- **Storage.** KytyPS5 stores unlocks in JSON (`unlockedTrophies`, `unlockedAt`) with RTC ticks.
- **Unverified parts.** Its error codes are not confirmed anywhere else: 0x80553104 invalid context, 0x80553120 context not registered, 0x8055310a invalid user, 0x80553105 too many contexts, 0x80553121 already registered. Requiring `RegisterContext` before `PostEvent` is also KytyPS5's own choice.

**I copied no code.** Only interface facts were used (names, keys, layout).

**Not established publicly, and how the design handles it:**
- The console's argument checks and error codes for UDS and Trophy2. The current return codes are kept.
- The signature of the `sceNpTrophy2RegisterUnlockCallback` callback. It is still never called.
- The properties of `_UpdateTrophyProgress`. The event is logged, not interpreted.
- The output of `EventToString` and `EventEstimateSize`. Both are unchanged: `{}` and 3.
- Whether a title may destroy `*prop_ptr` or `value_ptr` pointers. Destroying a pointer that the Create function did not return does nothing.

**Not consulted:** github.com/peterpuppy/bm. AnyPS5's debt notes cite it as an "SDK 12.000 reference", which looks like leaked SDK documentation.

## Design

**UDS (`libSceNpUniversalDataSystem`)**
- `include/UdsEvent.hpp` and `src/UdsEvent.cpp` give events and property objects real contents. These replace the empty structs in `SceTypes.hpp`.
  - A property value is a `std::variant` of int32, uint32, int64, uint64, float, double, bool, string, binary bytes, a nested object or a nested array.
  - Objects keep their keys in insertion order. Setting a key again replaces its value in place.
- `Uds::RecognizeTrophyEvent` returns:
  - `Unlock`, for `_UnlockTrophy` with an int32 `_trophy_id` of 0 or more;
  - `Malformed`, with the reason, for an `_UnlockTrophy` with no id, a non-int32 id or a negative id;
  - `Progress`, for `_UpdateTrophyProgress`, with the id when there is one;
  - `None` for everything else. Names are compared exactly.
- `Uds::Describe` prints an event as `name {json}`, with binary values shown as `<N bytes>`.
- **Exports**
  - `CreateEvent` copies `prop` and returns the event's own property object through `prop_ptr`, as KytyPS5 does.
  - `SetObject`, `SetArray` and the array forms store a copy of `value` and return the stored copy through `value_ptr`, so the title can keep filling it.
  - The typed setters store the typed value. Strings and bytes are copied.
  - A registry (`Uds::Owned<T>`) owns what `CreateEvent`, `CreateEventPropertyObject` and `CreateEventPropertyArray` return. `Destroy*` frees those. Any other pointer, such as an event's property object or a stored child, does nothing because its owner frees it. The old code called `delete` on such pointers.
  - `CreateContext` hands out ids 1, 2, ... and remembers the user and service label. The first id is still 1. `DestroyContext` forgets the context. Registration is not tracked.
- **`PostEvent`**
  - A null event, or one that `CreateEvent` did not create or that was destroyed, throws. Every other post returns success, as before.
  - With `APS5_TRACE_UDS` set it prints `[uds] context N posted <name> {json}`.
  - An `Unlock` on an existing context goes to `NpTrophy2RecordUnlock_nid_no_patch(user, label, id)`.
  - An unlock on an unknown context, or a malformed unlock, prints `[trophy] ignored <event> posted to context N: <reason>`.
  - The first `Progress` event per trophy id prints `... : trophy progress is not recorded`.
  - Other events do nothing more.
- `EstimateSize`, `ToString`, the handles, `Initialize` and the stats are unchanged.

**Trophy2 (`libSceNpTrophy2`)**
- **The store.** `NpTrophy2::TrophyStore` (`include/TrophyStore.hpp`, `src/TrophyStore.cpp`) keeps one file per user and service label.
  - The file is `<dir>/<user id>_<service label>.txt`, one `<trophy id> <RTC tick>` line per trophy, sorted by id.
  - It is loaded on first use and cached under a mutex.
  - A damaged line, a duplicate id or a negative id throws with the file name and line number. An unreadable file throws too.
  - It is written to `<file>.tmp` and then renamed over the file. Both the file and a newly created directory go through `RecordWrittenPath_nid_no_patch`, like every other host write.
- **Where the title's store lives.** `TitleStore()` is at guest `/_trophy`, which is next to save data's `/_sd` in the run directory that holds `app0/`.
- **Time.** Unlock time is the RTC tick: microseconds since 0001-01-01 UTC, which is the Unix epoch tick 62135596800000000 plus microseconds since 1970. This matches libSceRtc's current tick.
- **`NpTrophy2RecordUnlock_nid_no_patch(user, label, id)`** records the unlock. A trophy that is already unlocked returns false and logs nothing.
  - A new unlock is logged as `[trophy] <title id> unlocked trophy <id> for user <user>`, with the title ID from `param.json`.
  - It then calls each listener with `NpTrophy2Unlock {titleId, userId, serviceLabel, trophyId, tick}`, outside every lock and after the record file is written.
- **Contexts.** `sceNpTrophy2CreateContext` hands out ids 1, 2, ... and keeps the user and service label. The first id is still 1. `DestroyContext` forgets the context.
- **Queries.**
  - `GetTrophyInfo` and the single entry of `GetTrophyInfoArray` (trophy 0) report `unlocked` and `timestamp_tick` from the store.
  - `GetGameInfo` reports `unlocked_trophies`.
  - Everything else stays the old placeholder: names, descriptions, grades, groups, icons, the number of trophies, the grade counts, `progress_percentage`, group data and progress values.
  - An unknown context reports no unlocks.
  - Return codes are unchanged.
- **The hook for the pop-up.** `NpTrophy2AddUnlockListener_nid_no_patch(listener, context)` returns an id, and `NpTrophy2RemoveUnlockListener_nid_no_patch(id)` removes it. A null listener or an unknown id throws. These are `_nid_no_patch` symbols, so another library can import them by name.

**Titles that post no trophy events.** Every return code is the same as before.
- The context ids a title sees are the same unless it creates a second context.
- For any other event, `PostEvent` costs one registry lookup, an `APS5_TRACE_UDS` check and a name comparison.
- Previously an invalid event pointer was ignored; now it throws, as the rest of the library already does for invalid arguments.

## What a Village (PPSA01556) run must log

I can't run Village here because there is no game data. On the Windows coordinator:
1. Use a build of this branch and run with **`APS5_TRACE_UDS=1`**.
2. **The title reaches the new code** if any line `[uds] context <n> posted <event> {...}` appears. Any event Village posts counts, trophy or not. It means `sceNpUniversalDataSystemPostEvent` runs with the event's real name and properties.
3. **An unlock was recorded** when the line is `[trophy] PPSA01556 unlocked trophy <id> for user 268435456`. At the same time `_trophy/268435456_<label>.txt` appears in the run directory, next to `_sd/`. The label is 0 for a title's main trophy set (`trophy00.ucp`).
4. **The reason is printed** when the line is `[trophy] ignored _UnlockTrophy ... posted to context N: <reason>`. The reason can be a missing, non-int32 or negative id, or a context that does not exist.
5. **Village may unlock through statistics instead.** In that case a trophy moment shows `[uds]` lines with other event names but no `_UnlockTrophy`. Village then needs the stat-rule follow-up below.
6. **Earlier blockers.** If no `[uds]` line appears at all with the variable set, Village never posts on this build. Check the earlier blockers first.

Without the variable, only the `[trophy]` lines are printed.

## Left for follow-ups

1. **Trophy data parser** (`sce_sys/trophy2/trophyNN.ucp`; container and JSON keys as in source 1)
   - Fill the query placeholders from it: names, descriptions, grades, groups, hidden and reward flags, the number of trophies, the grade counts, `progress_percentage`, group data and icons.
   - Make `GetTrophyInfoArray` list every trophy.
   - Unlock platinum when all the others are unlocked.
   - The record format and `TitleStore()` stay as they are; the parser only adds a per-title "package" next to them.
2. **Stat-driven unlocks** (`sce_sys/uds/udsNN.ucp`)
   - Evaluate `statsExtractionRuleArray` on each posted event in the `TrophyEventKind::None` branch of `post()` in UDS `src/Event.cpp`. Keep the stats per user and label.
   - Compare against each trophy's `unlockCondition`, then call `NpTrophy2RecordUnlock_nid_no_patch`.
   - Report stat values as trophy progress. `_UpdateTrophyProgress` stays log-only until its properties are known.
3. **Pop-up** (after upstream #6012, the performance overlay, merges)
   - libSceAgcDriver calls `NpTrophy2AddUnlockListener_nid_no_patch` when the overlay is created, and links libSceNpTrophy2 so the symbol resolves.
   - The listener runs on the game thread that posted the event. It must only queue `{titleId, trophyId, tick}` under a mutex.
   - The presentation pass draws the queued toasts for a few seconds with the overlay's text renderer (`OverlayContent` lines), whether or not F10 shows the statistics.
   - It reads "Trophy 12 unlocked" until the parser gives names and grades.
4. **`sceNpTrophy2RegisterUnlockCallback`**: call it from the same listener path once its callback signature is known publicly.
5. **Error codes**: adopt the console's UDS and Trophy2 errors (unknown context, unregistered context, malformed unlock) if a public source confirms KytyPS5's values.
