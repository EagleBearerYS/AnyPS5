## The fix

Changed `sceSaveDataRegisterEventCallback` (`core/libs/prx/libSceSaveData.native/Export.cpp`, L1763), +3 −2:

```cpp
auto& callbacks = Callbacks();
std::lock_guard calling(callbacks.calling);
std::lock_guard slots(g_slots_mutex);
if (g_initializations == 0) return SAVE_DATA_ERROR_NOT_INITIALIZED;
if (callback == nullptr) return SAVE_DATA_ERROR_PARAMETER;
std::lock_guard lock(callbacks.mutex);
callbacks.callback = callback; callbacks.userdata = userdata;
```

**How it closes the race:**
- The final `sceSaveDataTerminate` holds `g_slots_mutex` (L1297) from its check through `--g_initializations` and `DetachEventDelivery()`.
- Registration now checks the count and stores the callback under the same mutex.
- So a registration either completes before that terminate, which then clears the callback, or runs after it and sees NOT_INITIALIZED.
- The window MarcZX10 described (the check before any lock, then the store after the detach) is gone.

**Lock order, with no inversion:** registration takes `calling` → `g_slots_mutex` → `callbacks.mutex`.
- **The delivery thread** holds `calling` while a callback runs. A callback that calls into SaveData then takes `g_slots_mutex`, so the order is the same.
- **`sceSaveDataTerminate`** takes `g_slots_mutex` → `callbacks.mutex` in `DetachEventDelivery`. It releases `g_slots_mutex` before `JoinEventDelivery`, and it never takes `calling`.
- **`sceSaveDataInitialize3`** and `DeliverEvent` go `g_slots_mutex` → `callbacks.mutex`.
- **Unregister** goes `calling` → `callbacks.mutex`.
- No path holds `g_slots_mutex` while it waits for `calling` or for the delivery thread.

**Semantics kept**, all checked by the existing cases in the same binary:

| Behaviour | Covered by |
| --- | --- |
| NOT_INITIALIZED before initialization | `CheckRegistration`, and after a terminate in `CheckIdleTerminateAndRestart` |
| PARAMETER for a null callback | `CheckRegistration` |
| A second registration replaces the first | `CheckUnregister` |
| Unregister needs no initialization | `CheckRegistration` |
| A terminate from inside the callback is BUSY and doesn't deadlock | `CheckTerminateFromCallback`, under its watchdog |
| Completions not yet delivered are dropped on unregistration | unchanged code |

## The regression test

Added to `core/libs/tests/GuestSaveDataEventCallback.cpp`: `CheckRegisterRacingFinalTerminate()`, run last in `main`.

**Setup:** the loop runs **200 iterations**. Each one starts at zero initializations and calls `sceSaveDataInitialize3`. Two **guest threads** (`scePthreadCreate`) wait on a shared start flag; one calls `sceSaveDataRegisterEventCallback(Stale, …)` and the other calls the final `sceSaveDataTerminate()`.

**Even iterations (100) widen the window, using only public API.** No library hook was needed.
1. Before the race, a `Holding` callback is registered and a backup is triggered. `Holding` keeps the SaveData delivery thread inside the callback, so the thread holds `calling`.
2. A registration that has passed its check therefore waits on `calling` until the terminate has finished.
3. The test waits until the racing terminate has reached zero, using the side-effect-free probe `sceSaveDataDeleteTransactionResource(0) == NOT_INITIALIZED`.
4. It then calls `sceSaveDataTerminate()`, which returns NOT_INITIALIZED only after taking `g_slots_mutex`. This orders it after the terminate's detach.
5. Only then is `Holding` released.

**Odd iterations (100) are a plain race,** with no held thread.

**What every iteration asserts:**
- the terminate returns OK;
- the registration returns NOT_INITIALIZED or OK;
- then `sceSaveDataInitialize3` runs again, a backup completes (`raced`), a `Fence` callback is registered and a second backup (`fenced`) completes;
- the test waits for `Fence`, which runs after any delivery queued for `raced` because the delivery thread is FIFO;
- and it asserts that `Stale` was called **0** times. So an OK registration counts only if that terminate cleared its callback.

**Each iteration** cleans up with an unregister, a drain of the polled events and the final terminate. It runs under a 10 s watchdog, so a deadlock fails the test instead of hanging it.

**Build change:** the test executable now also links `libkernel`, for `scePthreadCreate` and `scePthreadJoin`.
