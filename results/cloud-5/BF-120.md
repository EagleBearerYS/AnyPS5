## Main changes since 10-15 that touch the fix's logic

1. **`aa2b7ce7ef` (#6646, merged 10-19): a refused heap's mirror is kept once its range leaves the write watch.** It is refreshed in full instead of being planned again. This commit also added `SetAddressCopyLimit`.
   - **Effect on the fix:** eviction now runs only for ranges no mirror serves, which is what it is for.
   - **Effect on `fee10f45f3`'s remembered variant:** that variant builds once with the heap mirrored and then unwatches a block. On `main` the kept mirror now serves that second build, with no copy and no eviction, so on the port the variant failed with `the heap is neither imported nor mirrored`.
   - **Re-staged variant:**
     - The first build runs with the block already unwatched, under `SetAddressCopyLimit(2 × heap)`: the heap is refused, remembered and copied, with no mirror.
     - An unrelated non-GPU registration then forces the next build to plan again. Otherwise the address-space cache reuses the first plan and skips the cap check.
     - That next build runs under the 1 MiB cap. It must be answered from the remembered refusal (`remembered` count +1) and evict.
   - The cap override now drives eviction too (above).
2. **`4a84bbf917` (10-15): non-evicting budget refusals are remembered.** `importAllocation` answers a later build from that memory and never reaches `importRunAt`'s budget check. The port counts that path in `budgetRefusals`. **Without that hunk the remembered test aborts** (shown below).
3. **`4ee79e522e` (10-16): evicting refusals are remembered.** While nothing has changed, the eviction retry can now be answered from memory with a refusal and no scan. The range is then copied and the build aborts, as before: nothing gained there, nothing lost.
4. **`a24aafb75c` (10-15): covering-import shortcut.** An evicting import also becomes `covering`, so the rest of its run reuses it.
5. **`5f532117d3` (10-15): requesters.** The retry is `ImportRequester::Build`.
6. **The budget itself (`98c72e9f83`, and `f970620d95` / #6472, which keeps half the host heap out).** The default is lower on machines with a large host heap, so there are more refusals and more cases where the fix applies.
7. **#7844 (open, head `2af7b9bfb8`): keeps at most 4 GiB of the host heap out of the budget**, which raises it on 32 GB machines. It doesn't interact with the fix's logic, but it edits the same one-line debt entry, so whichever lands second gets a one-line conflict there.

## Step 2: `307bf8157a`

**What changed.** `AddressCopy` gains two fields, `heap` and `overBudget`, both defaulting to false, so the existing aggregate uses still compile. Previously the copy loop called `heapCopyReason(overBudget, GuestMemory::Watched(range))` for every copied releasable range on every plan. Now it records `reason = nullptr, heap = true, overBudget`. `AddressCopyOverflow` evaluates `GuestMemory::Watched(copy.begin, copy.end − copy.begin)` only for the copies its report lists, and only when the total is over the cap.

**Test.** The `AddressCopyOverflow` unit block in `RunBdaResourceTests` (part of `agc_driver_graphics`) now also checks that a deferred heap copy is named `import over the host import budget, heap not fully write-watched` and `heap not fully write-watched`. With the report using the stored reason instead, `agc_driver_graphics` fails with `the copy limit does not name a copied heap's reason`.

It separated cleanly, so it stays its own commit.
