## 1. The mask check

**Answer: no.** For a store redirected into a store page for an unbound block of a *resident* mirror, the shader did **not** set the mask bits. The redirect and the mask are separate flags of the range.

**The shader** (`core/shader/recompiler/SpirvBackend/src/SpirvBdaLookup.cpp`, from `fbb103c45f`):
- **The call:** a write calls the store-page function when the range has `Spill | Masked` (`:269-276`).
- **Inside it:**
  - the mask bits are OR-ed only when the range has `BdaAbi::Masked` (`:123-132`);
  - the store is redirected into the page only when it has `BdaAbi::Spill` (`:134`).

**The driver's range flags** (`Graphics/src/GuestBufferMemory.cpp`, `AddressRanges`):
- copy-backed heap mirrors: `Masked` only (`:6108`);
- a resident mirror's unbound pieces: `Spill` only (`:6120`).

So on 425cd9d8b0 the redirected stores wrote the page's data and left its mask empty, and the write-back could only guess the written bytes by comparing with zeros (`:6489`).

**The fix needs no shader change:** the unbound pieces now carry `Spill | Masked`. The shader then fills the mask as it does for copy-backed mirrors. The existing shader test (`tests/BdaExecution.cpp:548`, `Spill`-only and `Masked`-only ranges) still covers each flag on its own.

## 2. The fix

```diff
-                        if (!bound) piece.permissions |= ShaderRecompiler::BdaAbi::Spill;
+                        if (!bound) piece.permissions |= ShaderRecompiler::BdaAbi::Spill | ShaderRecompiler::BdaAbi::Masked;
```

**In `WriteBack`:** one helper, `maskedOriginal(entry, at, first, current)`, gives the comparison bytes. It flips each masked byte so it compares unequal, and keeps every other byte equal to `current`. `storeChanged`/`storeSparse` therefore store exactly the masked bytes.
- **The unbound-block path** (was `store(first, current, std::vector<std::byte>(current.size()))`) and **the copy-backed path** (its inline loop) both use the helper.
- **Counters:** `spilledBytes` and `comparedBytes` are unchanged for the unbound path (the page range), `maskedBytes` still counts only copy-backed write-backs, and `RequireCompared`'s resident `masked == 0` check still holds.
- **Cost:** a spill store now also ORs its mask bits (one or two atomics on the pool), as copy-backed stores already do.

**Why the old comparison held until now:**
- **At refresh:** `bindHeapBlocks` (`:2846-2865`) binds every block whose guest bytes aren't all zero. So an unbound block is all-zero when the build starts, and the comparison with zeros was the comparison with the uploaded bytes.
- **Where it broke:** the guest bytes can become non-zero only by a CPU write during the dispatch. A GPU store of 0 there must still land at write-back, as on the copy-backed path, which writes the masked bytes over CPU writes made during the dispatch.

## 5. For the PR description: exhaustion

**What a title sees:**
- **The dispatch:** a dispatch that stores through addresses into more distinct 4 KiB pages of heap mirrors than the store page table holds fails on the GPU with the `StorePages` fault. `BdaResources::CheckFault` (`:372-374`) throws "BDA store at 0x… into a heap mirror found none of the *N* store pages free (APS5_BDA_STORE_PAGES)".
- **Lost stores:** `WriteBackBuffers` (`ShaderResources.cpp:5878-5890`) rethrows before `WriteBack`, so none of that dispatch's stores into heap mirrors reach guest memory.
- **The stop:**
  - the queue worker catches the error and calls `Driver::ReportFailure` (`QueueWorker.cpp:308-311`);
  - that prints it once, fails every video output and pending flip, and drops the queued work (`Lifecycle.cpp:294-314`);
  - later driver calls rethrow it.

  So the title stops with that message.
- **The workaround:** raise `APS5_BDA_STORE_PAGES` (default 1024; clamped to 64-65536; each slot costs 4 KiB + 128 B of mask + 4 B of key in a host-visible pool).

**When it happens:**
- **The limit isn't exactly the pool size.** A page takes a slot by 16 linear probes from a Fibonacci hash (`BdaAbi::StorePageProbes`). So a dispatch can be refused before every slot is used.
- **Simulated with the shader's hash** (exact `StorePageHash`/probe rule):

  | Page set | 64 slots | 1024 slots |
  | --- | --- | --- |
  | Consecutive pages | 63-64 fit | 987-990 fit |
  | Every 16th page | 63 fit | 969 fit |
  | Randomly scattered pages: first refusal | median 53 (min 34) | median 605 (5th percentile 478, min 322) |

- **The test's 64 consecutive pages fit at 64 slots.** With the default 1024, a dispatch storing to roughly 500-600 scattered pages can already be refused.

**Is a fallback feasible?**

| Option | Verdict |
| --- | --- |
| **Recover the failing dispatch** | **Not without re-running it.** Its stores are only in the pool, and the unbound blocks are backed by the shared zero memory, which a store must not touch. A re-run after binding the blocks isn't safe for shaders with atomics or other non-idempotent writes. |
| **Bind the blocks before the dispatch and take the masked/bound path** | Needs to know the pages in advance. The declared write ranges can be whole heaps (2 GiB resident spans in the budget test), so binding them costs 64 KiB of device memory per block, plus a `vkQueueBindSparse` that first `Sync`s the recorder (`ResidentBuffer::Bind`, `ResidentMirror.cpp:459-480`). Feasible only for small declared ranges. |
| **Raise `StorePageProbes`** (e.g. probe the whole table) | **The cheapest real improvement:** refusals then come only when the pool is full. It is a recompiler change (the probe bound is in the shader, so the shader cache format moves), and the worst-case probe loop grows with the table |
| **Size the pool from the last refusal** (double the slots for later builds of the same pipeline) | Doesn't save the failing dispatch |

**Not built:** none of these is small and safe for this PR. The `StorePageProbes` change is the one to consider next.
