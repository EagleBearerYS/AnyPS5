### Resolution #3, Buffer.cpp: the report on both register paths

- **By reading:** `reportRegisteredSize` is called in `CommitBufferGroup` right after `cfg.width` and `cfg.height` are set. That is after every check that can throw (closing, slot, index, occupied buffers, `DescribeVideoOutBuffer`, `AgcDriverCheckGuestMemory`), so it reports only a registration that succeeds. Both `sceVideoOutRegisterBuffers2` (Buffer.cpp:164) and main's PS4 `sceVideoOutRegisterBuffers` (#5991, Buffer.cpp:214) go through it. The call in `sceVideoOutSubmitChangeBufferAttribute2` is unchanged. The function only reports for the main bus with the variable set, and two static atomics make each outcome ("as ANYPS5_OUTPUT_RESOLUTION reports" / "although ... reports") print at most once per process.
- **By running it:** a scratch probe (built in the scratch tree only, then deleted; not committed or pushed) opened the main port under Xvfb with `ANYPS5_OUTPUT_RESOLUTION=1280x720` and registered four sets, at 1280x720, 1280x720, 64x64 and 128x64, once through the PS4 path and once through the PS5 path:

  | path | lines printed |
  |---|---|
  | PS4 `sceVideoOutRegisterBuffers` | set 0: "[videoout] display buffers registered at 1280x720, as ANYPS5_OUTPUT_RESOLUTION reports"; set 2: "[videoout] display buffers registered at 64x64 although ANYPS5_OUTPUT_RESOLUTION reports 1280x720; they are presented and scaled to the window as before"; nothing for sets 1 and 3 |
  | PS5 `sceVideoOutRegisterBuffers2` | the same two lines, at the same two sets |
  | either path, variable unset | none |

  So it prints once per outcome on both paths.
- **Should a test cover the PS4 path?** Yes, I'd add one. `guest_video_out_output_resolution` registers only through `sceVideoOutRegisterBuffers2`, and none of the output resolution tests checks the report. A PS4-path case in that test (a 1280x720 registration through `sceVideoOutRegisterBuffers` under `ANYPS5_OUTPUT_RESOLUTION=1280x720`, checking that `sceVideoOutGetResolutionStatus` still reports 1280x720) would guard #5991's path. Checking the stderr line itself would need the test to capture stderr, which these tests don't do today. I did not add it: nothing is broken, and the task pushes only fixes.
- **Docs:** `docs/dev/debt/libSceVideoOut.md` and `docs/user/USAGE.md` keep both sides (diffed against main: main's text is unchanged and the branch's sections are added).
