## What limits samplers: one more cap than the task lists

The masks are not the only 32/64 cap. **`BindingAllocator` caps every shader, with or without registration modules, at `RuntimeAbi::SamplerHeapCapacity` = 64 samplers**, table samplers included. The check is `info.samplers.size() > SamplerHeapCapacity` → "shader binding layout exceeds runtime metadata capacity", and the cap is the size of the `ShaderData` sampler metadata array.

Each **direct** sampler also takes **two** elements of the 64-element sampler heap, an original and a point copy. That gives "shader sampler pairs exceed runtime heap capacity" past **32 direct samplers**. `DescriptorBindingBuilder` then compacts the elements a shader does not use:
- A sampler keeps both elements when it is paired with an image-table image, or with both a filtered image and one that needs the point copy (integer, converted or depth).
- Otherwise it keeps one.

So the sampler-heap element index, which is what the element masks are indexed by, is at most 63. The sampler resource index, which is what the resource masks are indexed by, is also at most 63.

What main's 32-bit masks allowed:
- **≤ 32 samplers in all** (`MaxSamplers`).
- **≤ 32 sampler-heap elements** ("prepared sampler mask capacity exceeded" compares the element count with `MaxSamplers`). That is as few as 16 direct samplers when each keeps both elements.
- Resource-indexed shifts (`1u << pair.sampler`) that would have been undefined past 31 had the tracker not refused first.

**Choice: 64-bit masks, `MaxSamplers` = 64 (= `SamplerHeapCapacity`), `MaxSampledPairs` = 256, `MaxImages` unchanged (64).**
- **Why not 128 behind a wider type:** a 128-bit or list representation with `MaxSamplers` = 128 would only change which refusal a 65-to-128-sampler shader gets. `BindingAllocator` refuses it anyway, because the runtime ABI holds 64 sampler metadata entries.
- **What 128 would really take:** growing `ShaderData` (`RuntimeAbi.hpp`: the `samplers` array, its layout `static_assert`s, `Version`), the per-stage sampler-heap descriptor counts the driver sizes against `maxPerStageDescriptorSamplers`, and only then the masks. That is a runtime-ABI change with a per-draw `ShaderData` cost. I left it for the PM.
- **Headroom:** Rift Apart's 63 fits by one, as the task said of 64-bit masks.
- **Per-draw cost:** see the benchmark below; a 64-bit word walked by set bits is cheaper than the 32-iteration loops it replaces.
- **No silent truncation:**
  - `ResourceMaterializer.cpp` has `static_assert(ShaderInfo::MaxSamplers <= std::numeric_limits<std::uint64_t>::digits)` next to the resource-indexed shift.
  - The element-mask capacity check is now `binding.resources.size() > std::numeric_limits<std::uint64_t>::digits`, with its old text.

**`MaxSampledPairs` = 256:** 112 fits with headroom. Nothing sizes an array by it. Its users are `AddSampledPair`, `PlannedWithinLimits` and the selected-records pair test (below).

**`FormatVersion` 44 → 49:** serialized `DescriptorBinding::imageSamplers` is now 64-bit (`writer.Values(std::span<const std::uint64_t>)`).

### `agc_shader_sampler_limits` (`agc_shader_memory_tests --sampler-limits`, next to #7527's selected-records modes, same properties)

**1. The Rift Apart shape.**
- **Program:** one per-lane record (key from `v_readfirstlane`, 4096-byte stride, one record). It holds 51 T#s at 32-byte steps and 60 S#s at 16-byte steps from 2048, read as 60 table sampler columns at distinct offsets, plus 3 direct S#s from the SRT.
- **Pairs (112):**
  - image *i* with column *i* (51);
  - images 0–8 with columns 51–59 (9);
  - direct sampler 0 with images 0–18, 1 with 19–35, 2 with 36–50, plus 2 with image 0 (52).
- **Plan requirements:**
  - 63 samplers (60 through the table), 51 images and 112 pairs;
  - the direct samplers at **resource indices 60–62** (past 31, so the 64-bit resource masks are used);
  - the three direct samplers bound as 6 sampler elements, in order (checked by their S# words);
  - each of the 51 image-table elements, identified by its T#'s height field, with **exactly** its direct samplers' elements (3 << 2d, plus 3 << 4 on image 0).

**2. Element bits 32 and up, direct images.**
- **Program:** 20 direct samplers, each paired with an 8_8_8_8_UNORM image and a 32_UINT image (so each keeps both elements: 40), plus a third image paired only with samplers 16–19.
- **Requirements:** the first two images' masks are bits 0–39, and the third's **exactly bits 32–39**.

**3. Element bits 32 and up, image table.**
- **Program:** 18 direct samplers paired with two image-table images (alternating).
- **Requirements:** 36 elements; each table element's mask is exactly its samplers' bits, up to bit 35.

**4. Refusals past the new limits.** The texts are unchanged:
- 62 table columns plus 3 direct = 65 samplers → `sampler resource limit exceeded`;
- 51 images × 6 table samplers = 306 pairs → `sampled image/sampler pair limit exceeded`;
- 33 direct samplers → `shader sampler pairs exceed runtime heap capacity: 33 samplers`.

### `agc_driver_many_direct_samplers` (new execution test `tests/execution/ManyDirectSamplers.cpp`, registered by the execution-test glob with the standard properties)

**Shader:** a lavapipe compute dispatch of 64 lanes, mirroring `ImageTable.cpp`'s `DirectCode` encodings. It loads 17 direct S#s from the SRT.
- **Samplers 0–15:** each samples a float image A (adding its red into a sum) and a 32_UINT image B (adding into an integer sum), so each keeps both elements: elements 0–31.
- **Sampler 16:** samples only A, so it is **element 32**.
- **Output:** sampler 16's RGBA, plus the two sums.

**Checks:**
- **Pairing:** 33 sampler elements; element 32 holds sampler 16's S# words; A's mask is bits 0–32 and B's bits 0–31; every lane's integer sum is 16 × its B texel, read through the 16 point copies.
- **Border colour through element 32:** sampler 16 is an opaque-white CLAMP_BORDER S# and samples outside the image.
  - Every lane reads (1, *, *, 1). R32_FLOAT keeps red and alpha of the border.
  - The red sum of samplers 0–15 is bit-exact.
  - **Control:** a clamping S# at element 32 reads the edge texel (63.25).
- **Forced degamma through element 32:** sampler 16 has FORCE_DEGAMMA (word0 bit 20) on an 8_8_8_8_UNORM A.
  - Every lane's sample and sum is **bit-identical** to the same texels as 8_8_8_8_SRGB, and green is below the undecoded value.
  - B is not paired with sampler 16, because forced degamma on a 32_UINT image is refused separately ("…has no sRGB view…").
- **Border swizzle through element 32:** an alpha-moving BC swizzle on A paired with an opaque-black border on sampler 16 is refused with `moves the alpha channel is sampled through an opaque black border`. The control with a clamping S# there is not refused.
- **Not testable on lavapipe:** filter min/max and non-seamless cube use the same widened loop and mask, but no observable refusal can be produced here. lavapipe has min/max filtering for these formats and `VK_EXT_non_seamless_cube_map`. Those two are covered by reading the code only.

### #7527's selected-records tests, adapted to the new pair limit

- **Why they needed changing:** `verifySelectedRecordsWithinLimits` derived its pair limit as `MaxSampledPairs / 2` (two samplers per read).
  - At 256 that is 128 reads. The 64-image limit would hit first, and the keys would run past the fixture's 128-word SRT.
- **The change:**
  - `TableManyKeyCode` now takes a sampler count. Six more S#s are loaded into s64–s87 from SRT words 116–139, which are zeroed and given `0x92`, and the SRT grows to 160 words.
  - The pair variants sample each read through **8** samplers: 32 reads hit 256 pairs while still under 64 images.
  - The expectations scale with it: at the limit, `samplers × limit` pairs; past it, one merged table with `samplers` pairs; the direct variant has `2 × samplers + 1`.
  - The image variants are unchanged (one sampler).
- **Result:** all four pass on branch 1 (`agc_shader_selected_records_pair_limit` 7.6 s, `direct_pair_limit` 7.5 s, the image ones about 1.4 s).

**Per-draw cost of the mask loops.** This is a synthetic micro-benchmark, not a driver run:
- **Method:** the old and new bodies of the loops the driver runs per bound sampled image, for 64 images per draw, `g++ -O3`, three runs.
  - The loops are `ForcesDegammaOn`, `RequireFilterMinmax`, and the sampler-source flag loop.
  - `RequireBorderSwizzle` and `RequireNonSeamlessCube` return before their loops for the common BC swizzle and non-cube images.
- **Results:**

| masks | old (32-bit, `element < 32u` loops) | new (64-bit, set bits only) |
|---|---|---|
| 2 bits per image (one sampler's two elements, the common case) | **≈ 4.7 µs per draw** (4659–4691 ns) | **≈ 0.2 µs per draw** (199–209 ns) |
| 32 bits per image (worst under the old cap) | ≈ 4.4–4.7 µs | ≈ 4.6–4.8 µs (within run-to-run noise) |

- **Memory:** each mask is 8 bytes instead of 4: 4 more bytes per bound image in `DescriptorBinding`, `ReusedTable` and the serialized artifact, and one more content-key word per image.
