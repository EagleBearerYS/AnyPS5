## 2. The first PR: an app0 overlay

**Title:** `feat(libc): shadow app0 files with an app0-overlay directory`

### Behaviour

1. **Discovery.**
   - If a directory named `app0-overlay` sits beside `app0/` (the guest root, where `app0.zar` is also looked for), it is the overlay.
   - Nothing else turns it on, so there is no new variable.
   - At first use, AnyPS5 prints one `app0 overlay: <path>` line, like the relinker's `Patches:` line. It then prints one `app0 overlay: /app0/<guest path> -> <host path>` line the first time each shadowed file is resolved, so a user sees whether the title actually opened the file.
2. **Precedence.** For a guest path under `/app0`:
   - **overlay file:** when the overlay has a *regular file* at that path, matched case-insensitively by the same `ResolveHostPath` the base uses;
   - otherwise the **app0 directory on disk**;
   - otherwise **`app0.zar`** (unchanged).
   - The overlay therefore also replaces files that live only in `app0.zar`.
3. **Directories never come from the overlay.** `/app0/X` for a directory resolves to the base as today, so `opendir`/`getdirentries` listings are unchanged.
4. **Shadow only.** A regular file in the overlay with no counterpart in app0 (disk or `app0.zar`) stops the title at first use with an error that names the file.
   - Without this, a listing would miss a file that opens.
   - Adding files with merged listings, as shadPS4 does, is a later PR. It would be needed for a `UECommandLine.txt` that a dump lacks.
5. **No code in the overlay.** An overlay file that starts with an ELF magic or a PS5 SELF magic is refused at the same check. The relinker's `ElfReader.cpp:85` already knows `0x1d3d154f` and `0xeef51454`.
   - Modules are relinked at conversion, and `dlopen` resolves through `ResolvePath_nid_no_patch` (`libkernel/Module/src/DynamicLoader.cpp:182,192`). Without this rule, an overlaid `.prx` would be looked up as a relinked module beside the overlay.
   - Code changes stay with `--patches`.
6. **Symbolic links.** A symbolic link inside the overlay is refused, matching USAGE's rule that app0 must not contain symbolic links on Linux (#7592).
7. **Writes.** A write open of a shadowed file writes the overlay copy. This matches today's behaviour for loose app0 files, which AnyPS5 does not make read-only (only `app0.zar` descriptors get `EROFS`). Record it in `docs/dev/debt/libc.md`.

### Hook points (a701f9f788)

- **`core/libs/prx/libc/src/General.cpp:297` `HostPath(WorkingDirectory&, names, module)`.**
  - **Today:** `ResolveAlias` → `ProvidedPath` → `ResolveHostPath(state.root, names, module)`.
  - **Change:** insert one lookup after `ResolveAlias`, for `names[0]` equal to `app0` (`SameName`, case-insensitive). It returns `ResolveHostPath(overlayRoot, names[1..])` when that is a regular file.
  - **Why here:** every guest path API funnels through this function:
    - `ResolvePath_nid_no_patch` (:682), `ResolvePathOrRelinkedModule_nid_no_patch`, `ResolveArchivedPath_nid_no_patch` and `ResolveDiskPath_nid_no_patch` (:674);
    - the libkernel callers `File/src/Open.cpp:279,425,445` (`sceKernelOpen` and module loads), `File/src/Stdio.cpp` (stat, fopen and friends, 14 call sites), `Apr/src/Apr.cpp:119` (APR reads) and `libc/src/Directory.cpp:207` (`opendir`);
    - AppContent, AvPlayer, Font, Ngs2, NpTrophy, PlayGo, SaveData and others. `git grep -l -E 'Resolve[A-Za-z]*Path[A-Za-z]*_nid_no_patch'` lists 24 production `.cpp` files besides `General.cpp`, not counting headers and tests.
- **`ResolveDiskPath_nid_no_patch("/app0")`** (used by `AppArchive.cpp:40` and `Stdio.cpp:1147` `InsideApp0`) resolves a directory, so it is unaffected by rule 3.
- **`Resolve(...)` :325** uses `HostPath` for `..` and trailing-dot directory checks. These are directories only, so it is unaffected.
- **`AppArchiveRefuseOnly_nid_no_patch`** (called at :684/:690): an overlay host path is not an archive path, so an overlaid archive-only file is no longer refused. That is the intent.
- **Not found:** any `openat`-family export that resolves relative to a directory descriptor's host path and so bypasses `HostPath`.
  - `File::DirectoryDescriptorPath` is used only on directory descriptors: `File/src/Stdio.cpp:187` (times), `:203` (sync), `:1125` and `:1144` (listings), and `DescriptorControl.cpp:590,602`.
  - A reviewer should confirm this on the PR.

  - `draw_resolution_scale_x/y` are integers 1–7 and "Requires sparse binding (Vulkan) or tiled resources (D3D12)".

  - It only scales up.
- **RPCS3** (0dec46b12e):
  - "Resolution Scale" runs 25–800 %, default 100, and "Minimum Scalable Dimension" runs 1–1024, default 16, so small targets are left unscaled ([system_config.h:171,174](https://github.com/RPCS3/rpcs3/blob/0dec46b12e856756ba04271207a99a1de2208720/rpcs3/Emu/system_config.h#L171-L174)).
  - Artifacts at some scales are reported in [rpcs3#5878](https://github.com/RPCS3/rpcs3/issues/5878).
- **yuzu** (source unreachable; secondary article):
  - "Project ART" offered 0.5x/0.75x downscaling and 2x–6x.
  - It blacklists a render target that is flushed to the CPU or used to compose a texture, and then every target drawn with a blacklisted one.
  - Paper Mario: The Origami King broke because of compute output ([wccftech](https://wccftech.com/yuzu-nintendo-switch-emulator-introduces-improved-resolution-scaling-feature/amp/), [boilingsteam](https://boilingsteam.com/yuzu-switch-emulator-introducing-project-art/)).
- **Ryujinx** (source unreachable; secondary article and a docs mirror):
  - Scales "compatible render targets".
  - It blacklists textures read with `texelFetch` outside non-indexed fragment and compute use, and bindless textures get no fallback.
  - Non-power-of-two scales break spatial effects ([dsogaming](https://www.dsogaming.com/?p=141884)).
  - Config `ResScale`/`ResScaleCustom` ([mirror docs](https://www.mintlify.com/yakushabb/mirror-ryujinx/user-guide/graphics-settings)).
- **LayeredFS** (Atmosphère 6b0c077b4c): "fs_mitm ... enables LayeredFS to function, which allows for replacement of game assets" ([ams_mitm.md:11](https://github.com/Atmosphere-NX/Atmosphere/blob/6b0c077b4c608a3a2ee712b8dc35fee87ceb62e8/docs/components/modules/ams_mitm.md#L11)).

**What internal scaling takes, from the above:**
- render-target and depth images at the scaled size;
- viewport and scissor scaling;
- integer-coordinate shader access (`texelFetch`, image load and store, size queries) rescaled or blacklisted;
- compute dispatch grids sized by the CPU at native resolution;
- copies and resolves between scaled and unscaled surfaces;
- CPU readback of a scaled target, which needs a blacklist or a downscale on flush.

**Known failure modes:**
- half-pixel offsets becoming full-pixel;
- one-pixel effects;
- non-integer scales;
- compute-written output;
- cube or array targets.

### 5. AnyPS5 feasibility (a701f9f788)

**(a) app0 overlay**
- **Hook:** `libc/src/General.cpp:297` `HostPath`. Everything else follows from the single funnel described in section 2.
- **Size:** about 150–250 production lines plus a ~250-line test.
- **Risks:**
  - module files, handled by refusing them;
  - listings, handled by shadow-only;
  - writes, recorded as debt;
  - a possible descriptor-relative open that bypasses `HostPath`, which was not found.
- **Test:** the table in section 2.

**(b) Unity boot.config**
- **Recipe:** (a) plus a USAGE paragraph: copy the title's `Media/boot.config`, edit the key, put it in `app0-overlay/Media/`.
- **Rejected alternative:** an env var that rewrites the key would sit in the same `HostPath` hook as a synthesized file (like the `AddPathProvider_nid_no_patch` providers, :579, which today only supply *missing* files). It is rejected under the rule quoted in section 1.
- **Test:** the user's PC run (`RES:` line).

**(c) Unreal**
- **Code:** nothing to build. Arguments already pass through `getargv` (Process.cpp:313-319).
- **If a `UECommandLine.txt` turns out to be read:**
  - the overlay PR's per-file trace line would show the open;
  - an overlay that *adds* files (merged listings, like shadPS4's fs.cpp:428-453) is the follow-up.
- **Test:** a synthetic overlay-add case like `guest_app_overlay_added`, inverted.

**(d) Generic render-target scaling**

The hooks would be:
- **render-target and depth creation:** `Graphics/src/Resources.cpp:269` `RenderTarget::RenderTarget`, `Texture.cpp` (5839 lines), `DepthSurface.cpp` (2584) and `MultisampleTarget.cpp` (1293);
- **viewport and scissor:** `State.cpp:1542-1549`, which builds `viewport` and `scissor` from the registers and `renderExtent`;
- **descriptors for sampling scaled images:** `ShaderResources.cpp` (5696);
- **integer-coordinate image operations in the recompiler:** `RdnaDecoder/src/RdnaImageOpDecoder.cpp`, `Translation/src/MemoryInstructions/ImageInstructions.cpp` and `SpirvBackend/src/SpirvImageEmitter.cpp`, plus a shader disk cache `FormatVersion` bump;
- **compute dispatch grids:** `Draw.cpp` (3129) and the dispatch path;
- **CPU-coherent guest memory:** `GuestBufferMemory.cpp` (5490), `Execution/src/GuestMemory.cpp` (2518) and write tracking. A scaled image cannot be written back byte-exact, so it needs a yuzu-style blacklist on CPU read.
- **presentation:** `Execution/src/PresentationPass.cpp`.

Size and risks:
- **Size:** several thousand lines over months.
- **Risks:**
  - every failure mode listed in section 4;
  - for downscaling: lost detail and texel-addressed effects;
  - any heuristic must be general, because per-title lists are forbidden.
- **Test:** synthetic AGC streams in `tests/execution` that draw a 3840x2160 target at scale 0.5 and compare the result against a native 1920x1080 render on lavapipe. Plus the `VK_LAYER_KHRONOS_validation` run that AGENTS.md requires, comparing `main` and the change for new `VUID-` errors.
