## 1. Retired HTILE fill (`CheckCurrent` `gpuFill`, #9533's code)

### Cause

A whole HTILE or stencil-plane fill is proven in one of two ways:
- **By its write note.** `NoteDepthMetadataFill` takes it from `LastWriteNote`, or `CheckCurrent` takes it later from `fillNoteAfter`; both read only writes that are still pending. Once it has the note, a retired fill is accepted through `newestHtileNote == 0`.
- **By `StoredAllSince(metadata, clearGeneration)`.** This counts only driver stores stamped **after** the generation that the note collects.

A fill whose stores land **before** its note has neither proof once it retires. Two such cases:
- **A CPU fill.** In `BufferFill.cpp`, if `FillBuffer` returns false because the HTILE has no host import, the bytes go through `GuestMemory::Write`, and only then is `NoteDepthMetadataFill` called.
- **A GPU fill whose batch left the open batch before the note.** `LastWriteNote` only sees the open batch's last write. `clearFillFloor` (`NewestWriteNote`, which also reads in-flight batches) then equals the fill's own note, so `fillNoteAfter` can never find it.

The reporter's reading, "the fill retired before `CheckCurrent` caught its note", is right only for this case. A fill that the note did see is accepted on #9533 after it retires: that's the control below, and it passes.

### Red on #9533 `a7697941f3`

The new cases are in `CheckEligibility` (`agc_driver_native_multisample_depth`) and in `--separate-stencil`.
- **Fill stored before its note, then lookup:** `AGC graphics: native multisample depth clear has no complete tracked HTILE store`, exit 1. This is the reporter's message.
- **The same, with that case removed, at the next case** (`QueueTargetWordFill`, then `recorder.Submit()`, then the note, then `recorder.Sync()`, then lookup): the same message, exit 1.
- **Control:** a fill noted while still pending, then retired before the first lookup, is accepted on #9533. That run passes to the end.
- **Stencil plane** (`--separate-stencil`, new `PlaneFault::StencilFillStoredFirst`): `AGC graphics: native multisample stencil plane fill has no complete tracked store`, exit 1.

### Their change as written (Red B)

On #9533 their change is `gpuFill = clearPattern && (newestHtileNote == 0u || (clearFillNote != 0u && queuedFill))`, with the same change for stencil.

**Depth:** the existing contract case stops being refused. That case notes a whole fill with no store, while the HTILE words already prove the clear and nothing is pending. The test stops with `multisample target refusal did not match no complete tracked HTILE store:` (empty, meaning accepted).

This is the task's negative case: stale HTILE equal to the clear's words, with no fill ever run. A clear is then consumed on words that this fill never stored.
- **Where it breaks:** whenever the note comes before its fill runs. One example is `preparePacketMemory`'s note at `PacketMemory.cpp:74` (not pipelined) while a `CheckCurrent` runs before the fill. The clear can then be applied before its own fill and before work queued ahead of it.
- **What I couldn't build:** a single-threaded production sequence that turns this into silent loss. It is a contract break that a race can reach.

**Stencil:** `StencilFillUnstored` (note, no store) gets past the store check. It is refused only by the later value check (`stencil plane does not hold its fill value`), because the bytes happen to differ. Stale bytes equal to the fill value would be accepted.

## 2. Buffer write over a host-written native depth surface (`UploadFinish`, main's code)

### Probe on main `5454cd2e45`

The probe (in `/home/user/logs/b267/run/bf276/`, not committed) does this:
1. A native 4× D32 surface is imported.
2. `DepthRaster` renders depth 0.25 into the host image, and `NoteDepthSurfaceWrite` marks it.
3. A `GuestBufferMemory` declares a write over the second half of the surface, then `Upload`/`WriteBack`.

On main, the write is refused with `AGC graphics: sample-preserving guest publication of native multisample depth is not implemented`. The surface stays resident, and a guest read is refused too. That matches the reporter's stop.

### Their change as written

`RetireResidentDepth_nid_no_patch` retires the guards over each write range without checking `hostWritten`, and `UploadFinish` calls it instead.
- **Buffer write:** served, and the surface is retired (`resident 0`).
- **Guest read of the half the buffer never stores:** served, and it returns `0x100b0601`. That is the guest bytes from before the render, not the rendered 0.25 depth.
- **Rebind:** imports a new surface from that stale memory.

The rendered samples outside the stored bytes are gone, with no error. `WriteBack` stores only the bytes the shader changed, and nothing published the host samples first. The upload's reference, and any read of those bytes by the shader, are stale too.

### Verdict and caution

**Wrong.** Retiring a written native depth surface for a buffer write silently drops the host's newer depth samples:
- in every byte the shader doesn't overwrite;
- in the whole surface if the declared range is wider than the actual stores.

The driver can't know the stores cover the surface. The right form is to publish the host samples to guest memory before retiring, which is what the refusal names.

**Open PRs that do this:**
- **#9950** (Dean Galvin, `c8fa65d134`) and **#10469** (Ondra97, `30155b56eb`), both titled "publish a written native multisample D32 depth surface to its guest planes on access".
- **What they change:** `RequireNoResidentDepthRead` publishes and then retires, instead of refusing, so `UploadFinish`'s declared writes are covered without a new entry point.
- **Status:** both merge cleanly with main.
- **Limit:** they cover D32; D16 would still be refused.

### Their change as written

- **Texture site:** refused with `native multisample depth sampled identity or format mismatch`.
  - `DepthSurfaceTexture` takes the MSAA branch for a native MSAA surface, and `CheckResource` requires an MSAA view of the same identity.
- **Storage site:** refused with `storage image access to a multisampled depth surface is not implemented`.
  - `Storage()` → `RequireStorable` requires `samples == 1`. #9742 has the same requirement.
- The surface stays resident. The buffer write and guest read are refused as on main.

So for a native MSAA surface, trying the depth handlers first serves nothing; only the refusal text changes. MSAA views were already tried first (L716).

### Verdict and caution

**Wrong**, for two reasons:
1. **It has no effect on native MSAA surfaces.** That should not be what let the run continue past t=302.8 s. Change 2's silent retire is the likelier reason later accesses got through.
2. **Where a depth handler does return**, for a single-sample depth surface at the view's base, the reorder skips `RequireNoMultisampleTarget` entirely. That includes the MSAA colour-target guard (`RequireNoMultisampleColorTarget`) over the view's bytes. I did not build a case for this.

**The right path:**
- **#9950 / #10469:** the guard publishes, and the view then reads current guest memory.
- **#12612** (milescoviello, `d948d3052d`, "read sample 0 of a native multisampled depth surface through a 2D image", merges cleanly with main): serves the single-sample texture view directly.
- **Storage views:** these still need `RequireStorable` support for multisampled surfaces.
