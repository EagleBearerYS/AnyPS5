## The question: does #7002 publish a 2-sample colour target that aliases a native multisample depth plane, and what happens to the depth side?

Line numbers are on `test/ghost-7002` `f690250faf`.

### From the code

1. **The guarded read.** `GuestMemory::Read` (`Execution/src/GuestMemory.cpp:2644`) calls `GuardRead` (`:2646`, `:2636`). That calls the installed read guard (`MultisampleTarget.cpp:1334`), `guardReads` (`MultisampleTarget.cpp:1110`), which #7002 turns into `SynchronizeMultisampleTargetRead_nid_no_patch` (`:1711`). On main and on #9742, `guardReads` is `RequireNoMultisampleTarget(address, bytes, "a CPU read")`, the source of the tester's refusal.

2. **The depth side comes first.** `SynchronizeMultisampleTargetRead_nid_no_patch` first calls `RequireNoResidentDepthRead_nid_no_patch(address, bytes)` (`:1714`, defined at `DepthSurface.cpp:2162`). This is the same gate main runs first inside `RequireNoMultisampleTarget` (`:1867`) and the one #11369 added for GPU buffer writes (`GuestBufferMemory.cpp:5419`).
   - **Which depth surfaces it covers:** resident depth guards exist only for sampling-eligible multisampled depth. Each one covers the depth plane, HTILE and stencil ranges (`DepthSurface.cpp:2289-2291`). The #9742 alias is one of them, once HTILE proves the clear.
   - **Host-written depth:** if any overlapping guard's surface was written by the host since import, it throws "sample-preserving guest publication of native multisample depth is not implemented" (`DepthSurface.cpp:2172`) before anything is published.
     - Host writes are draws with depth or stencil writes (`Draw.cpp:2858`, `:3601` → `NoteDepthSurfaceWrite`, `DepthSurface.cpp:2181`), depth copies (`:683`) and storage write-back (`:864`, `:882`, `:2950`).
   - **Not host-written:** otherwise every overlapping guard's surface is retired (`DepthSurface.cpp:2175-2178`), without throwing.

3. **Then the colour publication.** Each active colour owner whose guarded range overlaps the read goes through `PublishMultisampleTargetColor_nid_no_patch` (`:1735` → `:1684`). That calls `ColorSnapshot` (`:582`), runs `RequireNoResidentDepthRead_nid_no_patch` again over the target (`:1690`, now a no-op), checks that no other active colour owner overlaps (`:1695`), and calls `PublishColorSnapshot` (`:600`).
   - `PublishColorSnapshot` writes the changed bytes through `GuestMemory::StoreOwnBytes` (`:617`) and retires the colour owner (`:631`).
   - The read finishes with `RequireNoMultisampleTarget(address, bytes, "a synchronized guest read")` (`:1736`).

4. **The two depth guards never run on this path.**
   - "guest writes over native multisample depth are not implemented" (`requireUnwritten`, `DepthSurface.cpp:148`/`:151`, and `:532`) runs only when a resident depth is sampled and its planes changed. By the time the colour bytes land, that depth surface has been retired, so nothing samples it.
   - The next bind creates a new surface and imports again. The import reads HTILE and no compressed Z planes, so the colour bytes now in the plane do not matter while HTILE still proves the clear.

5. **What this means for the tester's read.** On main, that read had already passed the same depth gate: the error was the colour refusal, not the depth one. So no host-written resident depth overlapped it.
   - With #7002, the depth side at that read is unchanged from main: un-written depth over the range is retired, as on main.
   - #7002 then publishes the colour alias instead of refusing, provided the snapshot's conditions hold. Any of these refuses instead:
     - the target is R_X tiled with no DCC and no CMASK (`:583`);
     - it was initialised from guest bytes (`:584`);
     - the guest bytes still equal the import-time bytes or a known whole fill (`:587`, `:926`);
     - the whole footprint is writable registered guest memory (`:608`);
     - no pending GPU or storage writes overlap it (`:614`, `:616`);
     - no other live colour owner overlaps it (`:1695`);
     - the read is not inside a recorder completion (`:1726`).
   - The error does not say whether the Ghost of Tsushima target has CMASK or DCC. If it does, the read will refuse with "guest color snapshots with unsupported tiling or multisample metadata are not implemented".

### Diagnostic case (test branch only)

- **Where:** `NativeMultisampleDepth.cpp` `CheckAliasedDepthRead`, mode `--aliased-depth-read`, ctest `agc_driver_native_depth_aliased_depth_read`.
- **Setup:** #9742's colour-alias-over-native-depth setup, with an R32F colour target holding 0.25 over a D32/D32S8 plane whose HTILE proves the clear, in all 8 `aliasedDepthHtiles` layouts and words.
  - The guest depth plane was filled with 0x5c bytes.
  - The depth was imported and sampled: every sample read `DB_DEPTH_CLEAR`.
  - Then the colour target was "drawn": `MultisampleTargetView`, then a host-only `vkCmdClearColorImage` to 0.75, so the samples are host-only and differ from anything the guest knows.
  - Optionally `NoteDepthSurfaceWrite` marks the depth host-written.
  - Then `GuestMemory::Read` over the whole plane.
- **Detiler:** the context is given a `TextureDetiler`, as the driver's own context has one. Without it, publication refuses with "multisample color sample readback requires a texture detiler".
- **Samples:** llvmpipe has only 4-sample colour, so 2 and 8 samples report as unavailable. The code path does not depend on the sample count.

**Reading the output:**
- **Not host-written:** the depth guard is retired and the host-only colour samples (60 = 5×3×4) are published into the depth plane.
  - The plane's other 16324 words (padding of the 64 KiB block-aligned footprint) take the whole-range colour fill the setup noted (0x3e800000 = 0.25). This is #7002 preserving "a known full color-fill pattern".
  - In the harness, as in #9742's test, that fill was only noted and never stored, so this padding write is a fixture artefact.
  - HTILE and stencil are untouched. The colour owner is retired.
  - The next depth bind creates a new surface that samples `DB_DEPTH_CLEAR` again.
- **Host-written:** the read refuses at the depth gate, before publication. Guest memory, the depth guard and the colour owner are all unchanged.
- **Neither path** reaches "guest writes over native multisample depth are not implemented".
