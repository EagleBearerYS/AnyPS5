## The fix: (b), plus a refusal mark

### Why not (a)

(a) stamps the covered blocks as CPU-written at every refused collect. Compared shared memory is refused at every collect, every epoch, because refused walks are never memoized. What that costs each consumer:

- **Depth surfaces: a correctness regression, not just a cost.**
  - `SyncFromMemory` → `WrittenUnits` (`DepthSurface.cpp:842-855`) stores `TrackerGeneration()` as the unit generation.
  - With a fresh CPU stamp at every refused collect, `WrittenSince` is true at every bind.
  - So every bind runs `ClearStale(changed)`, a mirror `Refresh` and `copyPlane`. The depth is reloaded from guest memory, and depth the GPU drew but has not stored is dropped.
- **Storage textures: (a) adds nothing.**
  - After the first refusal their layer generations are the collect's 0 (`Texture.cpp:2109-2118`, `4705`, `4859`, `4867`, `4986`, `5013`, `5173`, `5479`). `cpuWrote` and `droppable` both need a nonzero generation (`Texture.cpp:2218`, `2294`).
  - So (a) and (b) both end at the `equalsOriginal` compare that 1ad5f29e20 already does.
- **Sampled cache, tables, buffers and the dispatch cache:** they compare once their generation is 0, the same with (a) or (b).

### Why (b) alone is not enough

(b) is a one-time CPU stamp at the first refused collect after a page becomes compared and shared. That is exactly main's "first collect after the demotion reports the pages written", and it covers every pre-sharing generation.

The task's safety argument for (b) is "entries made after a refused collect carry generation 0". The audit found that this fails for two consumers:

- **Dispatch cache.**
  - A variant's generation is the *maximum* of its spans' collects (`DispatchInsert.cpp:69`).
  - A refused span's 0 hides behind another span's nonzero generation.
  - The lookup validates that span with `UnchangedSince(span, max)` (`DispatchLookup.cpp:63-66`).
- **Depth surfaces.**
  - `WrittenUnits` and `NoteStored` take `TrackerGeneration()` (`DepthSurface.cpp:844`, `1794`, `2068`), not the collect's result.

Once the report is taken, nothing stamps compared memory again. A later CPU store would then validate as unchanged against those generations.

### What was built (commits 1 and 2)

**1. The report (b), in `WindowsMappings`.**
- Each `View` gets an `unreported` subpage mask. It is set when:
  - `demote()` turns a view of a compared page into a shared view;
  - `CompareWhenShared` marks a page for the first time: all its non-resident views are flagged, but marking an already-compared page re-flags nothing;
  - `Map` creates a new non-resident view of a compared page.
- `ComparedPages(address, bytes, pages, count, unreported)` either lists the compared shared subpages of a range, or takes and clears the unreported ones. It uses the same paging protocol as `Collect`.
- It is exported as `GuestArenaComparedPages_nid_no_patch` and `GuestArenaTakeUnreportedPages_nid_no_patch`.

**2. The refusal mark, in `GuestMemory`.**
- On Windows, a refused `walkWrites` now calls `noteRefusedWalk`, which does two things:
  - stamps the taken subpages through `stampWrittenRun` (`StampKind::Cpu`, so `noteCpuStore` plus the block stamp);
  - records `WriteTracker::refused[block] = generation` for every 64 KiB block that holds a compared shared page of the range.
- `rangeUnchanged` (which serves `UnchangedSince` and `UnchangedSinceAll`) and `UnchangedCommittedSince` return false when a mark is newer than the generation.
- So compared shared memory never validates by stamps against any generation, whatever its source: a collect before the sharing, the newest of several collects, `TrackerGeneration()`, or `MarkWritten`. Those callers compare bytes instead.
- `WrittenSince`, `ChangedBlocks`, `StoredOver` and `NewestStamp` stay stamp-only on purpose. They drive reloads and drops (the storage `droppable` rule, depth `ClearStale`), and reading marks there would be (a)'s regression.

### Costs

These are analytical, not timed. The path is Windows-only and this VM runs Linux. Neither (a) nor a (b)-only variant was built for timing.

- **Every `UnchangedSince*` call, on both platforms:** one `std::map::lower_bound`. On Linux the map is always empty; on Windows it holds one entry per 64 KiB block ever refused.
- **Each refused walk (Windows):**
  - two extra `WindowsMappings` calls, one mutex acquisition each, walking the views in the range;
  - before, a refused walk stopped at the first non-collectable view, so it now costs about what a successful collect's view walk costs;
  - lock order is unchanged (tracker, then mappings), the same as `Collect`.
- **Compared shared memory with no stores:** no new stamps after the report. The test asserts this: two more refused collects leave `WrittenSince` false and `ChangedBlocks` unchanged with cpu 0. So storage textures and depth surfaces do not reload or drop each epoch. `UnchangedSince` is false, so validations compare, which generation-0 entries at 1ad5f29e20 already do after the first refused lookup.

### Behaviour changes and the remaining gap

- **Native MSAA depth now throws over compared shared memory.**
  - The `Require(UnchangedSince…)` checks at `DepthSurface.cpp:349`, `359` and `366` throw "guest writes over native multisample depth are not implemented" at the first check after a refused collect.
  - At 1ad5f29e20 they trusted the missing stamps.
  - On main, the first collect after the demotion reports the pages written, so the same `Require` fails at the sharing. With the fix, `MultisampleTarget.cpp:482` behaves the same way: `StoredOver` sees the report stamp.
- **Gap, not fixed, and the same at 1ad5f29e20: depth surfaces miss CPU stores after the transition.**
  - `OverwrittenInMemory`'s `depthMemory` is the refused collect's 0, and `WrittenSince(…, 0)` is false.
  - `WrittenUnits` holds a `TrackerGeneration()` with no stamps after it.
  - This is how depth already treats unwatched memory (`ChangedBlocks` false → no change). (a) would catch these stores, at the cost above.
  - Suggested debt line for `docs/dev/debt/libSceAgcDriver.md`, if the PM wants it in the PR: "A depth surface over Windows direct memory that is compared once shared sees CPU writes made after the sharing no more than over unwatched memory: its generations come from refused collects (0) or `TrackerGeneration()`, and nothing stamps compared memory after the one report at the sharing."
