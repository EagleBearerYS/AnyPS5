- The debt entry was added under "Unknown function info".

**`sceNetConfigGetIfFlags` (implemented for `lo0`, commit e9db171018)**
- **The answer:** interface 0 writes **0x8049** (`IFF_UP | IFF_LOOPBACK | IFF_RUNNING | IFF_MULTICAST`) and returns 0.
- **Sources:**
  - **Interface 0 is `lo0`** in the `sceNetGetIfName` table already on main (`lo0`, `eth0`, `eth1`, `dbg0`, `wlan0`, …, which follows shadPS4).
  - **FreeBSD 11.4 `sys/net/if_loop.c`:** `lo_clone_create` sets `ifp->if_flags = IFF_LOOPBACK | IFF_MULTICAST`. `loioctl`'s `SIOCSIFADDR` case adds `IFF_UP` and `ifp->if_drv_flags |= IFF_DRV_RUNNING`.
  - **`sys/net/if.c`, `SIOCGIFFLAGS`:** reports `if_flags | if_drv_flags`, split across `ifr_flags` and `ifr_flagshigh`.
  - **`sys/net/if.h`:** `IFF_UP` 0x1, `IFF_LOOPBACK` 0x8, `IFF_DRV_RUNNING` 0x40 (`IFF_RUNNING` is its alias), `IFF_MULTICAST` 0x8000.
- **Every other interface throws** ("interface N is not implemented"). The library models no other interface.
  - **`eth0`** would follow libSceNetCtl's one wired host interface. That needs a new NetCtl hook on the lines where #9578 (ours) adds `NetCtlHostIpv4Gateway_nid_no_patch`, so it waits on #9578.
  - **`wlan0` and the rest** exist on a console, but the library has nothing to answer them from.
- **A null pointer throws.** Calls before `sceNetInit` are answered the same way, which is unverified. Both are in the debt entry.

**Kept as throws**
- **`sceNetGetIfnameNumList`:** no source fixes its return value (a count or 0), its short-buffer behaviour or its `flags`. shadPS4 only stubs it.
  - Under the library's model the list would be `lo0` plus the NetCtl host interface. A console also lists `wlan0` and other interfaces the library cannot see.
  - The answer would be a guess.
- **`sceNetConfigGetDefaultRoute6`:** the tree has nothing to answer it from.
  - `sceNetCtlGetStateV6` reports whether the host has an IPv6 address, but nothing knows an IPv6 gateway.
  - `sceNetCtlGetInfoV6` throws for every code. `sceNetConfigGetIfaddr6` throws.
  - The no-route answer is unmeasured even for IPv4: #9578's own `sceNetConfigGetDefaultRoute` throws "the answer without an IPv4 default route is not implemented".
  - It waits on an IPv6 host model and a measured no-route answer.
- **`sceNetEtherStrton` (the non-ASCII branch):** the task asked for FreeBSD 11's `ether_aton` rules, but the console does not parse like `ether_aton`.
  - **The [firmware 13.60 probe](https://gist.github.com/orezraey/789290577123af3c45b340d6db6f395c/71e0a6215c7ee86f49fdb31de989dd2b50720b7a) #8204 follows** tested 22 strings, all 7-bit ASCII. It returns 0 with unrelated bytes for `"0:1:2:a:B:f"`, `"0:1:2:3:4"` and even `""`. FreeBSD's `sscanf("%x:%x:…")` parses the first and rejects the others.
  - **No byte 0x80–0xFF was ever tested.**
  - **Conclusion:** giving non-ASCII digits `ether_aton`'s answer, rejection, would contradict the parser family the probe measured, so it would be a guess. The branch and the existing debt entry stay as they are; #8204's code is unchanged.
