## Part A

**Reproduction at 9d659c509:**
- A temporary probe sat next to #8224's two alias cases in `tests/Graphics.cpp` (`resourceTests`, ctest `agc_driver_graphics`) and called the public `MovedReadOnlyBuffers` directly, with no draw template needed.
- It built a mock-Vulkan `ShaderResources` whose read-only (`bufferWritten = {false}`) stride-60, 4-record buffer runs 8 bytes into `state.color`, #8224's accepted case. Then it asked with the same stages and target. It printed:

  `PROBE MovedReadOnlyBuffers: 1 moved`
  `PROBE   allocation 0 address 0x5624b2ed6e18 size 240 (target 0x5624b2ed6f00, buffer 0x5624b2ed6e18)`

- So one moved entry of 240 bytes, at the buffer's own address: the build bound 232 bytes (cut at the target), and the check compared that with the descriptor's 240.
- On the draw path that becomes a template hit with the buffer "moved".
  - `CheckBufferAliases`, with #8224's cut, passes it.
  - The hit then rebinds all 240 bytes, 8 of them over the render target.

**Fix (28af929a0):**
- `ShaderResources::BytesUpToTarget(address, bytes, stride, target)` holds #8224's cut condition. It cuts only with a target, a stride, a base below the target, and less than one stride into it.
- `addGuestBuffer`, `CheckBufferAliases` (Draw.cpp) and `MovedReadOnlyBuffers` all call it.
- `MovedReadOnlyBuffers` takes `const ColorTarget* target`. `Draw.cpp`'s cached-build hit passes `&state.color`, exactly as the build passes `&target` for every draw.
- A buffer that runs a whole stride or more into the target is not cut, so it fails the alias checks as before.
- Files: ShaderResources.hpp (+2 −1), ShaderResources.cpp (+8 −4), Draw.cpp (+2 −2), tests/Graphics.cpp (+26).

**The test**, in `agc_driver_graphics` after #8224's two alias cases, on one cached build of the 8-bytes-in buffer:
- the same words list nothing moved;
- the buffer moved to run 4 bytes in is listed at the target minus 236, with 236 bytes (the cut);
- moved to run a whole stride (60) in, it is listed with all 240 bytes (not cut).
