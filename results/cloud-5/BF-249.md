## What counts as a hit now

A looked-up draw (`stageEntries`, `Draw.cpp:656`) counts as a hit for the window when any of these is true:

1. **The whole draw hit.** `drawHit` (`DrawLookup.cpp:167`): every stage matched a cached variant of the draw key's entry.
2. **The whole draw hit in verify mode.** `verifyHit` (`DrawLookup.cpp:212`), as before.
3. **A stage was reused although the draw key missed.**
   - When the register key misses, `draw` finds the cached entry of the same shape (`Draw.cpp:467-473`, `dataEntry`, counted as a data-only hit).
   - `lookupDraw` validates each stage's cached variants against current memory. Every variant that validates `Equal` becomes a candidate (`DrawLookup.cpp:228-250`; the candidate is recorded at `:248`).
   - `finishDraw` then uses that candidate instead of recompiling the stage (`Draw.cpp:929-935`, `reused[i] = true`). The `[draw-cache]` line reports these as "data-only hits (stages: N reused, …)" (`dataStagesReused`).
   - The window counts the draw as a hit when at least one stage has such a candidate (`Draw.cpp:664`).

**Why this, and not the counter the task named:**
- The task named the stage hits the `[draw-cache]` line reports as "stage hits by variant rank". That counter (`variantHitsByRank`, `DrawLookup.cpp:180-184`) is incremented only inside `if (drawHit)`, so it never counts anything a whole-draw hit doesn't already count.
- The stage reuse a bypass switches off on draws whose whole-draw key misses is the data-only path above. A bypassed draw has `registerKey` false, so it gets no `dataEntry`, no candidates and no reuse (`Draw.cpp:394-395`).
- On a whole-draw miss, stages that validated before the missing one (`matched[i]`) are **not** reused. Every stage without a data candidate is recompiled (`Draw.cpp:945`); those matches only lend their memory regions to the capture (`DrawCapture.cpp:124`). So they do not count.

**Edge cases where a counted candidate is not used:**
- A candidate whose push offset differs from the stage's push cursor is not used (`Draw.cpp:929`).
- With `APS5_VERIFY_DRAW_DATA_HITS`, candidates are rebuilt and compared instead of used (`:930`, `:948`).

Both still count as hits. The candidate exists and validated equal, the same way `verifyHit` counts for whole draws, and counting at lookup keeps a single `Note` per lookup in one place (`Draw.cpp:664`, before the draw may be handed to the finisher).

## Test: red and green

`StageHitsKeepTheCacheLookedUp`:
1. Closes the current window with whole-draw hits: `2048 - lookups % 2048` cached draws.
2. Submits 2048 draws of the cached shape with 2048 new pixel user words. All 2048 keys miss with no whole-draw hit or insert; each reuses its vertex stage from the cached draw (`dataHits` +2048, `dataStagesReused` +2048).
3. Requires the next draw to be looked up and to hit.

`ConcurrentNotesCloseEachWindowOnce` is the unit-level race check:
- Four threads each note 64 windows of hits into one `DrawCacheBypass(100)`. A window then needs all 2048 of its lookups to hit, so any window closed short, or closed twice, starts a bypass.
- It requires no bypass afterwards. Then 2048 misses must close exactly one window and bypass exactly 16384 draws.
- It needs no timing or sleeps. With the CAS it holds for every interleaving.
