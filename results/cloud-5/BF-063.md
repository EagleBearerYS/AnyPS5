- **The change:** a new header-only `TouchedTable<T>` (`Execution/include/TouchedTable.hpp`).

  - **The first write** commits under a mutex, re-checks, then sets the bit with release order. It is thread safe and idempotent, and costs one acquire load after the first time.
  - **Run scans and range queries** treat untouched pages as zeros, and a clear skips them.
  - **Linux is unchanged:** the page-state table stays on the heap (`calloc`) and the tracker keeps its leaves.
  - The now-wrong comment above `allocate()` is removed.

## 1. The tables, their readers and writers

### Page-state table (`PageSpan`, `PageStates`)

- **Allocation:** `PageSpan::allocate()` (~372). It makes one byte of access flags per 4 KiB page: `PageReadable | PageWritable`, zero while unknown.
  - `PageStates::initialize()` makes it for the arena (`GuestArenaRange`). On Windows it makes a second one for the main image.
- **Load:** `PageSpan::load`, called by `describePages`. That is reached from `verify` (`CheckRange`, `Accessible`), `DescribeCommitted`/`CommittedRanges`, `CompareMapped`, `CopyMapped` and the `WriteChanged*` paths.
- **Run scan:** `PageSpan::runEnd`, "end of the run of pages equal to `value`", with an 8-byte wide fast path. It is called by `describePages` after a non-zero load.
- **Store:** `PageSpan::store`, called by `PageStates::record` once a VirtualQuery (Windows) or procmap query (Linux) has described a readable region. It writes one byte per page of the whole region.
- **Bulk clear:**
  - `PageSpan::forget`, from `ForgetPages` (libc's registry invalidator);
  - `record`'s own forget when the allocation generation moved during the query.

### Write tracker block tables (`WriteTracker`, Windows branch)

- **Allocation:** `initialize()` assigns `size / 64 KiB + 1` zeros to each of `blocks`, `cpuBlocks` and `hintBlocks`.
- **Loads:**
  - `stampOf` (via `newestStamp` and the single-block `unchanged` path);
  - `cpuStampOf`;
  - `hinted` (`hintBlocks[block] == 0`).
- **Range queries:**
  - `unchanged` (`std::none_of` over `blocks[first..last]`);
  - `newestHint` (max over `hintBlocks`).
- **Stores:**
  - `stamp` (collects, `MarkWritten`, import windows);
  - `startHints`;
  - `walkHints`.
- **Locking:** all of these run under the tracker mutex.
- **Bulk clears:** none.

## 2. The change

- **`TouchedTable<T>`** (header only, no comments):
  - `Allocate(entries, TableBacking::Heap | Reserved)`;
  - `Load`, `Store`, `Clear`, `RunEnd` (with the same 8-byte wide fast path), `AnyOf`, `Max`;
  - `Touched`, `CommittedBytes`, `Reservation`, `ReservedBytes`.
- **The `Reserved` backing:**
  - On Windows: `VirtualAlloc(MEM_RESERVE)`, then `VirtualAlloc(MEM_COMMIT)` per 64 KiB page.
  - On other systems: `mmap(PROT_NONE, MAP_NORESERVE)`, then `mprotect` read-write per page. This lets the same logic be tested on Linux.
  - A failed commit throws "cannot commit a page of a guest memory table".
- **`PageSpan`** forwards `load`, `store`, `runEnd` and `forget` to the table: `Reserved` on Windows, `Heap` on Linux.
- **`Pages()`** now returns a leaked singleton (`new PageStates`).
  - The old table was a raw pointer that was never freed, so workers verifying ranges at exit never touched freed memory.
  - The new table frees itself, so the object holding it must not be destroyed at exit.
- **The write tracker's three tables** are `TouchedTable<std::uint32_t>` with the `Reserved` backing:
  - `none_of` becomes `!AnyOf(...)`;
  - the max loop becomes `Max(...)`;
  - indexing becomes `Load`/`Store`.
  - A failed reservation is an error ("cannot reserve the write tracker's block tables"), where `assign` threw `bad_alloc` before.
- **`GuestMemory::TableReservations()`** returns each table's reservation for the commit-charge check: the arena and image page-state tables, and on Windows the tracker's three tables.

## 4. Tests and red/green

**`agc_touched_table`** (`tests/TouchedTable.cpp`, linked like `agc_write_watch_coverage`):
1. **Commit charge:**
   - A 250 MiB `Reserved` byte table starts with 0 bytes committed, from both the table's bitmap and the system's view.
   - 64 scattered regions of 16 entries commit **4,096 KiB (64 table pages)**, and the system reports 4,096 KiB.
   - 100,000 random loads, three run scans and a full clear commit nothing more.
2. **Equivalence:**
   - It covers byte and 32-bit tables, `Reserved` and `Heap`, each against a `std::vector`, over 200,000 random operations.
   - Stores never touch every third table page, so 1,728 of 2,624 KiB end up committed and untouched pages are read and scanned throughout.
   - Final contents must match.
3. **Concurrency:** 8 threads write first into the same 32 table pages. No value is lost, and each page is committed once.

**`agc_write_tracking`**, new Windows-only `CheckTableCommitCharge`, run first:
- It allocates 32 64 KiB regions spread across the arena (`GuestArenaAllocateAtOrAbove` at `base + k × size / 32`).
- For each region it calls `Accessible`, writes it, then calls `MarkWritten` and `CollectWritesUncached`.
- Then, for every table from `TableReservations()` larger than 16 MiB, it requires the committed bytes by VirtualQuery to be at most 4 × 32 table pages (8 MiB). It prints each table's committed KiB.
- Finally it releases the regions.
