## What the switch skips

The switch is `APS5_DIAG_SKIP_STORAGE_ROUNDTRIP` (presence), read once by `skipStorageRoundTrip()` at `Texture.cpp:85`. With it unset, every changed condition evaluates exactly as on the base. Line numbers are on `f9d2749fb8`.

1. **The "storage refresh" write-backs.** `StorageTexture::refresh` (`Texture.cpp:2211-2212`): when another image has results pending over this image's memory (`otherPendingOverlaps()`, `Texture.cpp:2495`), the refresh doesn't call `FlushPending(…, "storage refresh", …)`.
   - Those results stay pending on the GPU.
   - That `FlushPending` is the only production caller with the reason "storage refresh" (the others are in `tests/Recorder.cpp`). So every write-back counted under that reason in `[storage]` is gone.
   - The DCC clear hand-over path (`handOverKeys`) is left as on the base.
2. **The "flushed" uploads, and the same traffic coming back as "store".** `refresh` (`Texture.cpp:2364`): when the flush was skipped, the surface is treated as unchanged unless:
   - the DCC keys changed (`keysChanged`),
   - the CPU wrote the memory (`cpuWrote`),
   - or the image was never uploaded (`generation == 0`).

   The refresh then takes the base's unchanged branch (`Texture.cpp:2368-2376`): it adopts the current layer generations, takes the refresh proof, and returns before `writeBackLayers`, `borrowUnits` or `upload`.
   - The "flushed" reason (`Texture.cpp:2470`) needs `flushed == true`, which a skipped flush never is.
   - Without the unchanged rule, a later hook flush of the other image's results would stamp the memory, and the next refresh would upload with reason "store" instead. The rule removes that too.
   - CPU-written, keys-changed and first uploads still happen ("cpu", "keys", "untracked").
3. **`FindPendingSlice`** (`Texture.cpp:4738`). Skipping the flush can leave two pending array images over one slice; normally the refresh flush stores the older one first. With the switch set, `FindPendingSlice` returns the last pending array image holding the slice, the most recently marked one, instead of throwing "…which one holds its results is not modeled".
   - It is reached from `VulkanDevice.cpp:3313`, the resident present of a display buffer.
