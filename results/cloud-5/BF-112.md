## The change (`SampleOrders::Depth` and `CopyImage`)

1. **Copy usage.**
   - `copySampledOnly(context, format, samples)` is true when all of these hold:
     - the format's optimal-tiling features include `TRANSFER_DST` and `SAMPLED_IMAGE`;
     - `vkGetPhysicalDeviceImageFormatProperties(format, 2D, OPTIMAL, TRANSFER_DST | SAMPLED, 0)` succeeds;
     - its `sampleCounts` include the target's count.
   - **When true:** the copy is created with `TRANSFER_DST | SAMPLED` only, and sampled in `GENERAL` as before.
   - **When false:** the copy keeps `DEPTH_STENCIL_ATTACHMENT | TRANSFER_DST | SAMPLED`, and for each draw it goes `GENERAL` (for the copy) → `DEPTH_STENCIL_READ_ONLY_OPTIMAL` (for the draw), with both descriptors naming that layout. Its next use moves it back to `GENERAL`.
   - The copy now tracks its current layout in place of the old `general` flag. Every transition names all aspects of the format, BF-110's fix.
2. **Binding 1:** the depth pass writes both bindings for every method. The depth-only method gets the depth view in binding 1.

**Which path each format took on lavapipe (4x; it has no 2x):**

| format | method | path |
|---|---|---|
| D32_SFLOAT (126) | depth | sampled-only, `GENERAL` |
| D16_UNORM (124) | depth | sampled-only, `GENERAL` |
| D32_SFLOAT_S8_UINT (130) | depth / stencil export / stencil bits | sampled-only, `GENERAL` |
| D16_UNORM_S8_UINT (128) | all | not reached: can't be sampled at 4x here |

- No format took the read-only-layout path naturally.
- So the second mode below refuses the sampled-only usage, which draws that path on lavapipe too. All five passes then took it, and their round trips held.

## The test (two new modes, ctests in the WIN32 `PATH` list)

- **`agc_driver_sample_order_depth_copy_usage`** (`--depth-copy-usage`):
  - Gives the pass a context whose `deviceProc` records `vkCreateImage`, `vkCreateImageView` and `vkUpdateDescriptorSets`, and whose table records graphics `vkCmdBindDescriptorSets`.
  - Runs `DepthSwaps` over every depth format and method the device samples.
  - Takes the pass's own set: bound at the graphics bind point, holding sampled-image writes.
  - Fails when:
    - binding 0 or 1 of that set is unwritten;
    - the copy behind its views has `DEPTH_STENCIL_ATTACHMENT` usage while `TRANSFER_DST | SAMPLED` is legal;
    - the copy is sampled in a layout other than its path's.
  - It prints each format's path.
- **`agc_driver_sample_order_depth_copy_usage_refused`** (`--depth-copy-usage-refused`): the same, with the context's `imageFormatProperties` refusing `TRANSFER_DST | SAMPLED`, so the read-only-layout path is checked and drawn.

**The 5 s timeout:**
- On lavapipe, a CPU rasterizer, the GPU-assisted shaders outlasted `CommandBatch::Wait`'s fixed 5 s `vkWaitForFences` on their first, uncached run (`AGC graphics: vkWaitForFences graphics: Vulkan result 2`). On a real GPU these instrumented draws take milliseconds, so a 680M is unlikely to need more.
- If it does fail with `Vulkan result 2`, there is **no environment variable** for it today. The only way is to edit `5'000'000'000ULL` in `CommandBatch::Wait` (`core/libs/prx/libSceAgcDriver/Graphics/src/Resources.cpp`) and rebuild.
- The sample-order tests are also registered with a 30 s ctest `TIMEOUT`, which ctest's `--timeout` doesn't override. If a GPU-assisted run hits that, run the test executable directly with `ANYPS5_NO_SHADER_CACHE=1`, from a shell where ctest's `PATH` (the libc DLL directory) is set.
- A device loss shows as `Vulkan result -4` (`VK_ERROR_DEVICE_LOST`), not 2.
