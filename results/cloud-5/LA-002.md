## What I changed from his code, and why

1. **Plain storage buffers, no device addresses.** His lookup loads the header, the buckets and the ring through `ConvertUToPtr` from the table map's `HeaderDeviceLow/High` (`LoadDeviceWord`, `DeviceWordPointer`, `StoreDeviceWord`). Here the buckets are set 3 binding 0 and the ring is set 3 binding 1, read with `OpAccessChain` on `StorageBufferBlockType` (struct of uint[]). So `EmitBaseHeader` is unchanged (he forced `Int64` + `PhysicalStorageBufferAddresses` for device images) and his `PhysicalStorageBufferAddresses` condition on the option is dropped. The `CapabilityInt64` condition stays, as the task asks.
2. **No table map for device images.** His shader reads the sampler class from `HeaderSamplerClasses` in the map and the device header address from `HeaderDeviceLow/High`, and his `ResolveImageTables` still filled a map header for device tables. Here a device-table image gets no map record, a program whose only tables are device tables gets no `ImageTableMap`, `ImageTable` or `SamplerTable` binding, and `ImageTableAbi` is untouched (his v5 bump is not needed). Snapshot and map sizing use a new `snapshottedTableCount` that counts only CPU tables, instead of his resize-then-skip.
3. **The sampler class is a specialization constant computed by the recompiler.** His driver filled the classes from its `Sampler` objects (`DeviceTableSamplerClass`). Here `DeviceSamplerClass(words, integerBorder)` (DescriptorBindingBuilder.cpp) derives the same bits from the S# words, and `Prepare` emits `DeviceSamplerClassBase + sampler` for each sampler paired with a device-table image. The integer/float border bit follows the VkSampler the stage binds for that sampler (its element-0 and point elements). One difference: `SamplerNonSeamlessCube` is set from the S#'s DISABLE_CUBE_WRAP bit whatever the device supports, where his set it only without `VK_EXT_non_seamless_cube_map`; the driver (LA-003) decides with its own extension support.
4. **Faults go to the ring.** His shader recorded a fault through the fault buffer (`RecordBdaFaultWords`, `FaultReason::ImageTable`). Here a hit with a nonzero fault reads zeros and appends a ring record with `FaultFlag` in its pc word, as the design says.
5. **The 15-word key.** His d35b01a5b8 hashed an 11-word key; the base's `DeviceImageTableAbi` v2 has 15 words. The lookup fills the S# words 11-14 with constant zeros, and the ring record carries all 15.
6. **A null T# does no lookup.** His code called the lookup for every lane and only suppressed recording. Here the probe loop starts done when the T# is null (`active` parameter), so a null T# reads no bucket.
7. **Heap arrays, not table arrays.** The base has no `EmitTableImageCall`; its `EmitImage` switches on the mode inline. The device access sets `SpirvTableAccess::device`, and `LoadSampledImageDescriptor` then indexes `deviceHeapVariables` (set 2, `OpTypeArray` of `GpuImageHeapSlots` at `BindingNumber(Stage::Fragment, kind)`) instead of the runtime `table_images_*` arrays. The mode switch, the zero result for an invalid selector and `TableModeEmitted` are main's. Only `SampledImageArrayDynamicIndexing` (plus `ShaderNonUniform`/`SampledImageArrayNonUniformIndexing` where main's table path adds them, and `SPV_EXT_descriptor_indexing` below SPIR-V 1.5) is needed; no `RuntimeDescriptorArray`.
8. **The qualifying rules** (tracker): his `PlanDeviceColumns` took every non-sampler column, pointer ones included (read through BDA). Here a column qualifies only when it is not `address` (LoadAddressU32) or `indirect`; `DeviceAccess` also refuses a depth compare and a constant S# with FORCE_UNNORMALIZED. A runtime unnormalized S# paired with any table image is refused at materialization by main's `ProveUnnormalized` ("samples an image selected at run time"), exactly as on the CPU path. His compute-only restriction is dropped (1ffc203905). GPU-mode stages are skipped before tracking: `target.gpuResolvedImages` with a vertex, pixel or compute stage passes `deviceImageTables = false` to `Track` (a compute stage with a device column always has a sampled image, which is what makes it GPU mode).
9. **Invariants.** `AssignTables` fails if a device-table image would be a storage, written, packed or byte-element image (the qualifying rules make that unreachable), and `EmitDeviceTableAccess` fails on an unsupported operation or no modes. `ImageTableAbi::MaxModes` (a map limit) does not apply to device tables.
10. **The interface id** mixes every `ImageResource` field of the base, including three his tree did not have (`singleMipPlaneBiasCompatible`, `flatVolumeLineCompatible`, `cubeFaceCompatible`); a collision of two different interfaces still throws.
11. **Specialized modules.** `buildSpecializedModule` lists each descriptor variable's binding number and `DescriptorBindingBuilder::Select` requires each to be in the prepared plan. The variables of sets 2 and 3 are left out of that list when the artifact has `deviceImageTables` (they belong to the driver). Without this the first compile failed with "specialized module bindings disagree with the prepared plan".
12. **SPIR-V 1.3.** His `OpSelect` of a `uvec4` with a scalar condition is SPIR-V 1.4; spirv-val rejected it on the 1.3 test target. The condition is now a `bvec4`.

**His later fixes** (task step 6): a0080950fe, 3daa17f303, 364095abda and cad925c70d all change the CPU pre-pass of 81119eea49's run-time T# design (`ExpectedDeviceImages`, `deviceImagesComplete`, phi and lane-select expansion, candidate expectations) and the driver's insert-before-use. This piece has no pre-pass: a miss is resolved after its batch. None applies, so none was taken. a0080950fe has no shader-side change to miss records; its shader-visible part is the pre-pass completeness flag.

## The ABI as implemented (for LA-003 and LA-004)

- **Names and values (as the task fixed them):** `RuntimeAbi::DeviceHeapSet = 2u`, `DeviceTableSet = 3u`, `DeviceTableBucketsBinding = 0u`, `DeviceTableRingBinding = 1u` (right after `GpuDataSet`); `PipelineSpecialization::DeviceSamplerClassBase = 58368u`; `SpirvTarget::deviceImageTables` (after `gpuConstantsVerify`, in `RecompileCacheKey` next to `gpuResolvedImages`); `CompiledShaderArtifact::deviceImageTables` (after `samplerSlotDword`; copied to `RecompileResult`).
- **Added:** `ImageResource::deviceTable` (after `tableOperation`); shader disk cache `FormatVersion` 40 -> 41 (the field is encoded in the info and the artifact codecs); `ResourceMaterializer::DeviceImageInterfaceId(image, modes)`, `RegisterDeviceImageInterfaces(info)`, `FindDeviceImageInterface(id)` returning `std::shared_ptr<const DeviceImageInterface>{id, image, modes}` (image and modes normalized: `source`, `firstUsePc` zero, `table` 0); `DeviceSamplerClass(std::span<const std::uint32_t, 4>, bool integerBorder)` and exported `ImageShapeForResource`, `ReducesBetweenTexels` (DescriptorBindingBuilder.hpp). Reviewed names for the cache key: `ResourceMaterializer::FindDeviceImageInterface`, `ResourceMaterializer::TryRuntimeImageMode`, `ImageShapeForResource`, `ReducesBetweenTexels`.
- **When a stage has device tables:** `result.deviceImageTables` is true. Only when `target.deviceImageTables` is set, the target has `CapabilityInt64`, and the stage is not vertex/pixel/compute under `target.gpuResolvedImages`.
- **Set 3 binding 0 (buckets):** `StorageBuffer`, `NonWritable`, a struct of `uint[]`. The shader reads word `HeaderMask` (3) and `HeaderRingCapacity` (6) of the 16-word header, and bucket `b` at words `HeaderWords + b * BucketWords` (16 + 20b): key words 0-14, `StateWord` 15 (`LiveState` = 1), `SlotWord` 16, `ModeWord` 17, `FaultWord` 18 (only tested for nonzero). Probing: `home = Hash(key) & mask`; buckets `(home + step) & mask` for `step < ProbeSteps` (16); it stops at the first non-live bucket or a match.
- **Set 3 binding 1 (ring):** `StorageBuffer`, a struct of `uint[]`, bound by the driver at the batch's chunk (dynamic offset). One `OpAtomicIAdd` (Device scope, relaxed) on word `RingCountWord` (0) per append; when the old count is below `HeaderRingCapacity`, words `RingRecordsWord + i * RecordWords` (4 + 16i) + 0..14 get the key and + `RecordPcWord` (15) gets the pc, with `FaultFlag` (0x40000000) or-ed in for a fault record. The count keeps counting past the capacity (overflow = count - capacity).
- **Set 2 (heap):** for each kind used by a device-table image's emitted modes (`TableModeEmitted`: not MSAA, not FMASK), one `UniformConstant` `OpTypeArray(ImageType(mode), 4096)` at binding `RuntimeAbi::BindingNumber(Stage::Fragment, kind)` = 65 + kind, i.e. exactly `BindlessHeap::HeapLayout()`'s sampled-image bindings. The heap samplers are not declared: sampling uses the stage's own direct sampler. The index is the bucket's slot (0 when invalid).
- **The key:** words 0-7 the eight T# dwords as the program loaded them (an R128 column's words 4-7 are whatever the program has, normally zero); words 8-9 the low and high halves of the interface id (a module constant); word 10 the sampler class (the spec constant for an op with a sampler, 0 for loads and queries); words 11-14 zero. Hash: `DeviceImageTableAbi::Hash`.
- **The mode word** indexes `FindDeviceImageInterface(id)->modes`; a mode that is not emitted, or past the list, reads zeros (the switch's default).
- **Results:** a null T# (`word0 == 0 && (word1 & 0xff) == 0`) does no probe, records nothing, reads zeros. Valid = active && hit && fault == 0. A miss or a fault reads zeros and appends (only lanes with EXEC set, only non-null T#s).
- **Interface ids:** the ids in a module are those of the compiled variant's info (`variant.info.info`), which are registered in `materializeResult`. The capture plan's `ImageResource` is not the same object (its `numericClass` is set later), so its `DeviceImageInterfaceId` differs: the driver must use the id from the ring record.
- **The table V#** is an ordinary scalar buffer of the stage (`info.buffers`, read with the program's own `s_buffer_load`s), bound and copied by main's buffer path, so it needs no host import (the "copied ranges" rule).
- **Device features a device-table module needs:** `shaderSampledImageArrayDynamicIndexing`, `shaderSampledImageArrayNonUniformIndexing` where the stage is non-uniform, and stores/atomics in the stage (`fragmentStoresAndAtomics`, `vertexPipelineStoresAndAtomics`) for the ring.

## Open problems

- **Fault records per lane.** Every lane that hits a faulted bucket appends one; a full-screen draw over a rejected texture fills the ring at once (later records are counted, not stored). The driver decodes first-per-key, so this costs ring space, not correctness.
- **Unnormalized S#s.** A runtime S# with FORCE_UNNORMALIZED paired with a device-table image is refused at materialization, as main refuses it for any table image; fable-void's later ports (0d921f9838 ...) are where that would change.
- **`SamplerNonSeamlessCube`** now means "the S# disables cube wrap"; LA-003 must check `VK_EXT_non_seamless_cube_map` itself before rejecting a cube texture.
- **GPU-mode fallback:** when PR 6947's allocator falls back from GPU mode for a vertex or pixel stage, that stage keeps the CPU table path (the decision is made before tracking).
- **Module size:** the compute test program has two lookup calls (its body is emitted twice for wave64 on a 32-wide subgroup, as with the option off).
- **Nothing in the driver sets the option yet** (LA-003 adds the table, LA-004 wires `APS5_GPU_PATH=1`), so the mirror below runs the switch-off path only.
