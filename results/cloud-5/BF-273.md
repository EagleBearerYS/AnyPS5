## Design

**What it does.** When a build's shaders can store through addresses (`!bdaReadOnly`), `UploadFinish` adds the served spans of every writable heap mirror in the build to `writes`, just before `takeHeapReferences()`. That covers the cached space's `base` regions and the per-build `regions`.

Everything else comes from existing code once the spans are in `writes`:
1. **References:** `takeHeapReferences` captures a reference for each span (`heapReferences`). For resident mirrors, `growResident` binds the span.
2. **Write permission:** `AddressRanges` marks the spans `Write`. It already grants Write to write intervals inside writable mirrors.
3. **Table cache:** the table cache key (`AddressTableKey`) includes `writes`, so a build with stores never reuses a read-only table.
4. **Write-back:** `WriteBack` diffs each span against its reference, and `storeChanged`/`storeSparse` write only the bytes the GPU changed. A CPU store made elsewhere in the mirror during the dispatch is therefore kept.
5. **Proofs:** `ShaderResources` already breaks proofs for `usesBda && !bdaReadOnly`.

**Which regions qualify.** `region.mirror` must be set, with `heap`, `writable` and `region.writable` all true. The span is `[region.begin, servedEnd(region))`.

**What still refuses, unchanged:**
- copies (no mirror);
- read-only heap mirrors (`!mirror->writable` or `!region.writable`);
- image (non-heap) mirrors;
- bytes past `servedEnd`;
- holes of a sparse mirror.

**Sparse mirrors** (a heap with uncommitted holes, `mirror->sparse`):
- Only `clipPieces(mirror->committed, begin, servedEnd)` is added, i.e. the committed runs up to the served end.
- `servedEnd` is the mirror's extent: the end of the last committed run plus 1/8, rounded up to 1 MiB and capped at the reservation.
- A store into a hole, or past the extent, stays outside the Write set and still fails with the existing message.
- A run the guest commits later is picked up once the mirror is rebuilt for the new committed set (`refreshSparseMirror`/`acquireMirror`, as today).

**Unresident runs.** This applies to resident mirrors, i.e. devices with `sparseBinding`, `sparseResidencyBuffer` and aliased residency. lavapipe has none, so it serves copy-backed mirrors.
- A resident mirror starts with only the guest's nonzero blocks bound.
- `takeHeapReferences` calls `growResident(mirror, {{begin, served}})` for each write span. So every committed block of a writable heap mirror is bound before an address-storing dispatch. Without that, Vulkan would drop stores to unbound blocks.
- The cost is device memory and heap-mirror budget up to the committed size of the mirror.

The BDA table build itself costs about 0.005 ms more.

**Which dispatches pay it.** Every address-based build whose program stores through an address (`!bdaReadOnly`) and whose lease contains writable heap mirrors pays it. The cost scales with the committed bytes of **all** writable heap mirrors in the build, not the bytes the shader stores to.
- Read-only programs and builds without heap mirrors pay nothing.
- I can't count such dispatches per frame for PPSA02225 without the title. Even one per frame is about 33 ms, two frames at 60 Hz.
- So the cost is large for this heap, and the branch is a correct baseline, not the final speed.

**Narrowest scope I'd propose (not built).** The BDA table cannot narrow it: it maps the whole lease because the shader computes addresses at run time. So the scope has to come from what was actually stored.
1. **Dirty blocks from the shader.**
   - **Where:** `core/shader/recompiler/SpirvBackend/src/SpirvBdaLookup.cpp`.
   - **What:** after a successful Write lookup, set one bit per 64 KiB block in a small bitmap buffer next to the table (an atomic OR).
   - **Then:** `WriteBack` diffs, and `takeHeapReferences` keeps, only the marked blocks.
   - **Why `core/shader`:** only the shader knows which addresses it stored to. That is the one `core/shader` change, and this branch does not make it.
2. **Reference by GPU copy.** Take the reference capture with `vkCmdCopyBuffer` from the mirror into a pooled reference buffer before the dispatch, instead of a CPU copy. This composes with #8874's reference pool.
   - Together with (1), the CPU work becomes proportional to the blocks stored, not to 36 MiB.
