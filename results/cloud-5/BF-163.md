## 1. Red test

**Case:** `CheckImportAliasDemotedComparedWhenShared` in `core/libs/prx/libSceAgcDriver/tests/WriteTracking.cpp`.
- **Run as:** a new Windows-only ctest, `agc_import_alias_shared`, which is `agc_write_tracking_tests --import-alias-shared` with the same `SKIP_RETURN_CODE 77`, `TIMEOUT 20` and `PATH` as #9159's `agc_rewatched_direct_shared`.
- **Level:** the AGC write tracker, because `GuestMemory::ImportWatched` is the code that marks. The import callback is a fake (`[] { return true; }`), so no Vulkan device is needed.
- **Real order:** the test calls `GuestArenaMapAlias_nid_postfix` and then `ImportWatched(..., staysWatched = true)`, as `importAllocation` does (`GuestBufferMemory.cpp:1737` and then `:1758`).
- **Wine constraint:** every view is a single 16 KiB page at a 64 KiB boundary.
- **Fixture:** five 64 KiB slots of one arena allocation and three 64 KiB sections, each `GuestArenaForgetSection`'d after creation (against handle reuse, as #9159's case does).

**The case:**
1. `GuestArenaMapDirect` maps one page, which must be resident (`MEM_PRIVATE`) and `Watched`. `CollectWritesUncached` collects it once (≠ 0).
2. `GuestArenaMapAlias` over the page must demote it (`MEM_MAPPED`).
3. `ImportWatched(base, page, fake)` must succeed and leave it `Watched`.
4. **Require:**
   - the guest view is still `PAGE_READWRITE` after the import;
   - a clearing `GuestArenaCollectWrites(..., clear = true)` over it returns **false** (refused);
   - the view is still `PAGE_READWRITE`;
   - `CollectWritesUncached` is 0;
   - a guest store is seen through the alias, with no fault.

**Control 1 (memory shared before the alias keeps today's tracking):**
- A second section page is mapped direct twice, so `Map`'s shared path demotes it and both views are `MEM_MAPPED`.
- `MapAlias` and `ImportWatched` follow.
- **Require:** the clearing collect returns **true**, and both views become `PAGE_READONLY` (armed).

**Control 2 (a record left by an earlier alias does not survive the guest sharing the page):**
- A third section page is mapped direct, `MapAlias`'d (demoted), and the alias is unmapped with no import, as a failed import does.
- The page is then mapped a second time by the guest. `MapAlias` and `ImportWatched` follow.
- **Require:** the clearing collect returns **true**, and both views are armed.
- **It has teeth:** a build with only the fix's `aliasDemoted = false` line in `Map` removed fails with `memory a second mapping shared after an earlier alias demoted it stopped being collected`.

## 2. The fix (`WindowsMappings.hpp`, +6/−3)

- **The record:** `View` gains `bool aliasDemoted = false`. `demote(address, bool alias = false)` sets `view.aliasDemoted = alias` for every page of the run it demotes, and `MapAlias` calls `demote(address + done, true)`.
- **The mark:** `CompareWhenShared(..., residentOnly = true)`, which is `GuestArenaCompareResidentWhenShared` as `ImportWatched` calls it (`GuestMemory.cpp:1603`), now marks views that are resident **or** that an alias demoted: `if (residentOnly && !resident && !aliasDemoted) continue;`. The mark sits on the page and on BF-162's slot as before, and un-arms any armed alias.
- **Guest sharing clears the record:** `Map`'s shared path clears `aliasDemoted` on every existing view of a physical page it maps again (`views.at(alias).aliasDemoted = false;` after the `demote` loop). That page is then shared by the guest, and keeps today's tracking.
- **Scope kept:**
  - **Marked:** pages that were resident until the import's own alias demoted them, and only for the spans `ImportWatched` kept watched (its existing call site).
  - **Not marked:** memory the guest already shared (a second mapping) before the alias (control 1).
- **Scope widened in one corner:** a page that an earlier alias demoted, whose import failed or was not kept watched, and which the guest has not mapped again, is marked by a later import that keeps it watched. The suggested `ResidentSpan` approach would leave it unmarked. I think that is right, because only our alias ever shared that page with anything, but it is a judgement call.

### ImportWatched, importAllocation, or neither?

**Neither on its own:**
- **`importAllocation`** can record `GuestArenaResidentSpan` before `MapAlias`. But it doesn't know which spans `ImportWatched` keeps watched (it drops spans whose walk fails). It could only mark after `ImportWatched` returns, outside the tracker lock and after the import's own walks have armed the pages.
- **`ImportWatched`** knows which spans stay watched and marks them under the tracker lock. But it runs after the alias has demoted the pages, so it can't see that they were resident. It would need the spans passed in through a new parameter. Then a test could only reach the fix by repeating `importAllocation`'s recording, and the red at 47c8df4950 would be a compile error, not the failure above.

**Why libc:** recording at the demotion itself (`MapAlias` → `demote`) and honouring the record in the resident-only mark that `ImportWatched` already applies leaves both AGC sites unchanged. It marks at the same moment, under the same lock, as #9159's mark, and the test reaches it with today's API.

## 3. Audit of `demote` callers (1ad5f29e20)

`demote` has three callers in `WindowsMappings.hpp`. `demote` keeps `view.page`, so a page marked before keeps its mark (and BF-162's slot keeps it across remaps).

| caller | when | can the page be armed afterwards without having been marked? |
|---|---|---|
| `MapAlias` `:308` | an import over a range that is not all writable private memory (`GuestBufferMemory.cpp:1737`) | **Fixed for spans the import keeps watched.** Still yes when the import fails after the alias (`importAllocation` unmaps it at `GuestBufferMemory.cpp:1792`), or when `ImportWatched` drops the span because its walk fails (`GuestMemory.cpp:1596`, `:1601`). The pages stay demoted and unmarked until a later import keeps them watched. Alias imports always pass `staysWatched = true` (`watchedHostPointer = entry.alias != nullptr \|\| …`, `GuestBufferMemory.cpp:1752`) |
| `Map`'s shared path `:142` | a second guest mapping of a physical page whose existing view is resident | **Yes.** The page mapped twice is guest-shared, so arming it unmarked is #9159's "already shared" scope by design. But `demote` demotes the **whole resident run** containing that page, so every other page of the run also becomes a single-view shared page, unmarked unless an import had marked it, although the guest maps it only once |
| `breakRun` `:776`, from `reset` `:938`/`:939`, i.e. from `Map` (`:85`), `Reset` (`:76`) and `Commit` (`:52`) | a mapping, reset or commit whose boundary falls strictly inside a resident run | **Yes.** The whole run is demoted, and the pages outside the reset range stay mapped once, as shared views, unmarked unless marked before |

**Paths that arm a page, from BF-162 and re-checked:**
- `Collect`'s alias loop, `other.armed \|= arming` (`:467`), respects the mark through `collectable()` (`:519`) and the Fresh check (`:372`).
- `armResident` (`:693`) arms only resident views.

**The list that can be armed without having been marked:**
- `breakRun`'s surviving pages;
- the rest of a resident run that `Map`'s shared path demotes for one doubly mapped page (and that page itself, by design);
- `MapAlias` pages whose import fails or loses its watch.

## 5. Diagnostic branch `test/9136-shared-arming-diag` (8c97f618e9, on the fix)

Only `WindowsMappings.hpp` and `GuestArena.cpp` change.

**What `HandleWrite` prints:** on each resumed write into a non-resident (shared) view, it counts, and for the first 64 and then every 1000th it prints one line to stderr. The fields are:
- the address and page base;
- the page's alias count;
- the slot's `stored`;
- `comparedWhenShared`;
- `aliasDemoted` (whether `MapAlias` demoted the view, the fix's flag);
- the last arming collect's collection (`All`/`Armed`/`Fresh`, or `none`), its caller, and its range.

**How the arming collect is recorded:** in `Collect`'s alias loop where it arms (`armedBy`, `armedCaller`, `armedFrom`, `armedTo` on `View`). The three `GuestArenaCollect*Writes_nid_postfix` exports pass their caller.

**Not `_ReturnAddress()`:** Ubuntu's mingw-w64 declares `_ReturnAddress` in `intrin.h`, but GCC doesn't provide it, so linking fails with `undefined reference to '_ReturnAddress'`. I used `__builtin_return_address(0)`, which is its GCC form. The caller is the AGC function that called the export: `collectWindowsWrites` or `walkHints`, so it tells which of those two collected, not which higher-level caller.

**Checked under Wine:**
- **Probe:** a scratch copy of the test, not committed, that stores into control 1's armed page with a vectored handler calling `GuestArenaHandleWrite`.
- **It printed:** `[shared-arming] resumed write 1 at 0x200010008: page 0x200010000 aliases 2 stored 1 comparedWhenShared 0 aliasDemoted 0 armed by All collect from 000000014001944e over 0x200010000-0x200014000`.
- **The committed test still passes** with the diagnostic.
