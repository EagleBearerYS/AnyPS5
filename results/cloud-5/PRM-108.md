- A copy-backed writable mirror is writable: `Write`, plus `Masked`.
- Its masked bytes are written back.
- Real shader stores into copy-backed mirrors are covered by `agc_driver_bda_store_heap_mirror*`, which forces copy-backed mirrors with `SetResidentAddressSpaceLimit(1)`.

## 2. The fix

**The structure:** the writable section (old `:2881-2923`) becomes `writableMirror(bool forceCopy)`. It runs twice:
1. inside `const AddressSpaceLimit limit(1);`, a local RAII guard that restores `SetResidentAddressSpaceLimit(0)`, the same pattern `BdaStoreHeapMirror.cpp:152-156` uses. This forces a copy-backed mirror;
2. with the mirror the context gives.

Each pass starts by refilling the 128 KiB with `0x11`, so neither pass depends on the other's bytes.

**Pass 2 today:** on today's mock context it is copy-backed too, since the mock has no sparse residency. The resident expectation applies only if that context gains sparse residency, where these unit tests run.

**What each pass checks:**
- **The kind:** `HeapMirrorsWithin(address, address + bytes)`. It requires one mirror, and a copy-backed one in the forced pass.
- **For a resident mirror:** `held.bytes == bytes` (every block bound, which nonzero guest bytes give at creation). Then `Read|Write` is the exact expected value for every part.
- **For a copy-backed mirror:** the expected value is `Read|Write|Masked`.
- **The three stores are reported as the BDA reports them:**
  - `stored[offset] = value` at 16, 1000 and 65536+2000;
  - one `GuestBufferMemory::StorePage` per 4 KiB page (two pages), with the stored bytes' mask bits and `data` = the page's bytes after the stores, as `collectStorePages` builds them;
  - `NoteAddressStores` with those pages, `NoteStorePages`, then `WriteBack()`.
- **Every failure message names the kind:** "a copy-backed writable heap mirror …" or "a resident writable heap mirror …".
