- **`316cea8d7` (ours, new): exactness of the trimmed copy.** With his two commits, the copy keeps a value the evaluator does not read as a leaf without arguments. Two questions the walk asks on main still read below such a leaf:
  - `ResolveInvariantPhi` compares a phi's incoming values with `EquivalentValue`, which follows arguments. Two leaves with the same opcode look equal in the copy where they differ in the program, so a phi whose incoming values differ only below a vector load resolved in the plan but not in the program, and the plan decided a condition the program leaves open.
  - `LoadedFromMemory` (used by the evaluator and by the tape's `node.loaded`) looks for a read from memory anywhere below a raw read's handle. A handle that reaches memory only below a leaf, for example through a select arm the active mask never takes, lost it in the copy. The read from a null base then counted as a null root: the tape refused, the condition stayed open, and the read was not recorded in `SrtUserDataUse`, where the program decides the condition and records the read.

  `ownPlanValues` now checks both after copying. A phi copied in part must resolve in the copy to the copy of what it resolves to in the program; otherwise it is copied whole. A raw read's handle must be loaded from memory in the copy whenever it is in the program; otherwise the values on its shortest path to a read from memory keep their arguments (or the handle is copied whole if that path is already kept). The copy is then made again. Both checks only add values, so the loop ends, at worst with the whole copy. `Detail::IsMemoryRead` names the opcodes `LoadedFromMemory` and the path stop at; `LoadedFromMemory` uses it too, with the same result.

## Disk cache format

No bump. `FormatVersion` stays **42** in `core/shader/recompiler/ShaderDiskCache.hpp`.

- The stored plan's layout is unchanged. `encodePlan` writes every value with its arguments, and a leaf is just a value with 0 arguments. Phis are never trimmed (`Reads(Phi)` is `Arguments`), so `PhiBlockCount == ArgumentCount` still holds. `DecodePlan` has no arity check, and `agc_shader_disk_cache`'s plan round trips pass.
- The contents do change (fewer values), but old entries cannot be served. Every cache file and the cache directory are keyed by `SourceVersion`, a SHA-256 of every recompiler source, `ResourceMaterializer.cpp` and `SrtEvaluator.cpp` included. `unwrapEntry` rejects an entry whose header `sourceVersion` differs (`ShaderDiskCache.cpp:1358` on main), and the directory is `root/hex(SourceVersion())`. With `core/shader/recompiler/ShaderCacheVersion.cmake` run on clean worktrees with the same inputs, **main e0e57a327 gives `0x7d307d8d96e4f582` and this branch e20ec3f02 gives `0xe17868262d586a79`**. A plan written by main therefore never loads on the branch.
- Main's own history agrees: the last three `FormatVersion` bumps (c97e5e033, 1ed8eb6d8, 6d9222082) each changed the encoder (a new field written), not just a plan's contents.

## Retained values and time

Neither main nor the fork has a counter, so I measured with a local patch that is **not on the branch**. It is saved as a diff and was reverted after each run. In `ExtractPlan` it logs each plan's values, operand slots, bytes and `ownPlanValues` time:
- Bytes are `values × sizeof(IrValue) + operand and phi-block slots × 8 + compact plan`.
- The time is `steady_clock` around the `ownPlanValues` call.

On the branch the patch also extracts main's whole copy of the same plan, then compares the two. It compiles both to SRT tapes and compares them node by node (op, clean, loaded, component, argument count, base word, arguments, immediate). It also walks both with `SrtWalker::EvaluateRuntimeSources` over 8 deterministic runtimes, through both the interpreter and the tape, and compares results, flat words, active sources, poison, null roots and `SrtUserDataUse` reads. Each measured run is one full `ctest --parallel 4` on this machine, as `runner`.

On plans that do trim (big closures under conditions), the copy does less work than main's, which this suite cannot show.
