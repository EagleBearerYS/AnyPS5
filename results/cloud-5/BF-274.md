## Cause: a test teardown bug, not reachable in production

**What crashes.** The test's last step invalidates the surface's own 64 KiB and calls `image->Refresh()`. That compares the surface again and records a detile dispatch into the active recorder, using the test's local `TextureDetiler`. That batch is not submitted when the function returns.

**Teardown order.** Locals are destroyed in reverse order of declaration:
1. **`detiler`** goes first, because it is declared after the `Unregister` guard. `TextureDetiler::~TextureDetiler` → `release()` destroys its pipelines, descriptor pools and layouts at once, with no wait.
2. **`unregister`** goes next. `GuestAllocations` `Remove` → `GuestAllocationsRequireUnpinned_nid_postfix` → `WaitForLeasesAndImports` → `Recorder::Sync()` submits the pending batch.
3. **lavapipe's queue thread** then executes it and binds the destroyed pipeline.

**Evidence** (gdb with the matching `mesa-vulkan-drivers-dbgsym` 25.2.8-0ubuntu0.24.04.4, build ID `b3fb0cf7…`, on `6f467a2ef4`):
- **Crash site:** thread 2 (`vk_queue_submit_thread_func` → `lvp_queue_submit` → `lvp_execute_cmd_buffer`) gets SIGSEGV in `handle_compute_shader` at `lvp_execute.c:536`, called from `handle_compute_pipeline`.
- **Main thread:** it is in `vkWaitForFences` ← `Recorder::finish` ← `Recorder::Sync()` ← `WaitForLeasesAndImports`. That is the stack the task reports.
- **Pipeline match:** a breakpoint on `lvp_DestroyPipeline` fires exactly once before the crash, from `TextureDetiler::release` ← `~TextureDetiler` ← `untrackedForgetTests`, for pipeline `0x555555732890`. The crashing command binds that same pipeline (`cmd->u.bind_pipeline.pipeline` = `0x555555732890`).
- **BF-263's guess, refined:** the work in flight is the re-upload recorded after the surface's own 64 KiB was invalidated. What breaks is the detiler's pipeline lifetime, not the surface memory. The test never frees `block` on Linux, and `Remove` already syncs before dropping imports.

**Why production can't reach it:**
- `VulkanDevice` owns the only `TextureDetiler` (`state->detiler`, `VulkanDevice.cpp:2193`).
- `~State()` (`:855`) calls `vkDeviceWaitIdle` in its body.
- The members are then destroyed with `recorder`, which is declared after `detiler`, going first.

So no detiler is ever destroyed under pending recorded work. That makes the fix test-only.

**Reproducibility:** `port/6192-main` `275b675006` crashed in 20 of 20 runs (SIGSEGV, exit 139). `6f467a2ef4` crashed on the first run under ctest and on each of 3 runs under gdb.

## Fix

```cpp
void untrackedForgetTests(const Device& device, Recorder& recorder) {
    ...
    TextureDetiler detiler(base);
    struct Finish {
        Recorder& recorder;
        ~Finish() { recorder.Sync(); }
    } finish{recorder};
    ...
```

- The `--untracked-forget-only` call site now passes the `recorder` that `main` activated.
- `Finish` is declared after the detiler, so it runs before the detiler is destroyed. The recorded work therefore completes while its pipelines still exist.
- Because it is a destructor, it also runs when a `Require` throws, so a failing check is reported instead of being hidden by the crash.
- This is the same `Finish` idiom the file already uses (`Recorder.cpp:730`). The neighbouring untracked tests get the same effect from their `Clear` guards (`recorder.Sync()`).
- Every check the test makes is kept, and the test still prints "untracked comparison memo: ok".
