# BF-286 result (cloud-5)

## Verdict

The deadlock is not the tracker lock. It is a two-lock cycle between the **host imports lock** (`Imports().mutex`, `Graphics/src/GuestBufferMemory.cpp`) and the **GPU mutex**, closed by **`ec6ceece96`** (#10026). The unwatch hook is the bridge between them.

- **The edge that `ec6ceece96` adds:** `StorageTexture::SaveBeforeUnwatch` now also enters the GPU mutex to hash a *live* storage image of more than 1 MiB (`GenerationBaselineBytes`) that overlaps the range leaving the write watch. On main it entered it only for *pending* images.
- **The thread that runs the hook without the GPU mutex:** the import at map. The GPU-map observer imports a new GPU mapping without the GPU lock first, holding the host imports lock while it imports.
  - The import at map already declined when the hook would take the GPU lock. Main's `e56a7c2351` added that guard, `ImportMappedRanges`' `AnyPendingOverlaps` check, together with the hook.
  - `ec6ceece96` made the hook take the GPU lock in a second case that the guard doesn't check.
- **The cycle:**
  - The import at map holds the host imports lock and waits for the GPU mutex in the hook.
  - Any GPU-mutex holder that looks up a host import (`HostImportFor`, or the observer's own retry under the GPU lock) waits for the host imports lock.
  - Everything else that needs the GPU mutex stops behind them: the draw committer, presents, label commits, and the queue worker once the draw pipeline is full.
- **It isn't Windows-only.** The test goes red on Linux (lavapipe) every time: 20 of 20 on #10026's head and 20 of 20 on #7048's head.

**The fix** (one commit, in #10026's code): the import at map also declines when the hook would hash a live image over the run, using the predicate the hook itself uses. The map observer then retries under the GPU lock, which takes the locks in the draw path's order (GPU, then imports). The test is green 20 of 20 on both branches.

### Tracker lock

## 2. The cycle per stack set

**What gdb shows on Linux for the cycle the test builds:**
- The import-at-map thread: `Mutex::lockContended < GpuMutexType::lock < StorageTexture::SaveBeforeUnwatch < GuestMemory::ImportWatched < importRunAt < importAllocation < ImportMappedRanges`.
- The GPU-lock holder: `Mutex::lockContended < Graphics::HostImportFor`.
- Both wait in `AgcDriver::Mutex::lockContended`.

The reporter's frames are partial Release symbols. A frame named `GuestMemory::flushHook` can't be a real frame: `flushHook` is a `std::atomic` variable, so it's a nearest-symbol name.

### Own base (#7048's head on `ba5b533` + libSceMouse)

- **Main thread** (`lockContended < GpuMutexType::enter < "flushHook"`): the import at map.
  - The GPU-map observer (`Driver/Lifecycle.cpp:209-233`) imports on the mapping thread itself whenever `StackHoldsImport()` (`Lifecycle.cpp:99`, enough stack left), so a guest thread mapping GPU memory runs it inline.
  - It holds the host imports lock (GBM:4215) and waits for the GPU mutex in `SaveBeforeUnwatch` (Tex:4499).
  - The `FlushGpuWrites` → flush-hook path can't be this frame's cycle: its callers (`GuestMemory::Read`, `PrepareHostRead`) hold none of the other locks.
- **Queue worker 0x0** (`lockContended < "collectWrites"`): holds the GPU mutex for a draw and waits on an `AgcDriver::Mutex`.
  - It can't be the tracker lock in a deadlock: no tracker holder ever waits on another lock (section 1, and the probe).
  - So it's the host imports lock in `HostImportFor`, behind a misnamed frame.
- **Cycle:** main (imports → GPU) against worker 0x0 (GPU → imports).

### bb04a4f1ea + #7048 (4 threads)

- **Main thread** (`GpuMutexType::enter`): the import at map, as above. It holds the host imports lock and waits for the GPU mutex.
- **"Presenter"** (`GpuMutexType::enter < flushHook`, with a `commitLabel` lambda on the stack): most likely the **draw committer** running a label commit.
  - `commitLabel` is enqueued as a pipeline commit (`PacketMemory.cpp:420-422`) and takes the GPU mutex first (440).
  - It waits for the GPU mutex, so it doesn't hold it.
- **Queue worker 0x0** (`DrawPipeline::Enqueue < Driver::finishDraw`): waits for room in the full pipeline (`DrawPipeline.cpp:313`) behind the stuck committer.
  - It doesn't hold the GPU mutex: `Enqueue` throws rather than wait when it does (309).
- **The fourth thread** (`Mutex::lockContended`, caller unresolved): **holds the GPU mutex** and waits for the host imports lock that the main thread holds.
  - Main and the presenter wait in `enter`, which blocks only a thread that doesn't hold the GPU mutex. The worker can't hold it either. So the fourth thread is the only possible holder.
  - It can't be waiting on the tracker lock (no tracker holder ever blocks), so it waits on the host imports lock.
  - Candidates for that thread are any GPU holder that looks up an import: the draw finisher, a compute queue worker, the presenter, or a second mapping's observer retry under the GPU lock (`Lifecycle.cpp:214-215`).
- **Cycle:** main (imports → GPU) against the fourth thread (GPU → imports). The presenter and worker 0x0 are blocked behind it.
- **Why nothing is logged** and `APS5_STALL_WATCHDOG_SECS` doesn't fire: it's a lock cycle on host threads, not a stalled queue wait.

### What the freezes need

A GPU mapping whose import run overlaps a live storage image of more than 1 MiB.
- The run is the new mapping plus any contiguous registered ranges; `importRun` extends it past the new range.
- One way to get there: an image in the texture cache whose memory was unmapped and mapped again at the same address.
- The test builds exactly that case.
- The first title-menu hover and the save load (`catnames_*.txt`) are both points where Mewgenics can map new GPU memory. The file reads themselves are not on the cycle. I can't confirm that mapping from the reports without a dump.

## 4. The test

`agc_storage_import_at_map_unwatch_lock_order`, run as `agc_driver_recorder_tests --import-at-map-lock-order-only`, in `tests/Recorder.cpp`.
- **Registration:** like `agc_storage_pending_after_unwatch` (`SKIP_RETURN_CODE 77`, `TIMEOUT 30`, the Windows `PATH`).
- **Dispatch:** before `main()` takes the GPU lock for the Recorder sections, like `deferredSettleTests`. It isn't in the argument-less full run, which holds the GPU lock throughout.

**For each case:**
1. Allocate 4 MiB of write-watched memory.
2. Create a live 1024×1024 storage image over it **before** registering the memory, so its upload copies instead of importing. This is the cached image over a range mapped again.
3. Register the memory and confirm it isn't imported.
4. Install a wrapper hook that flags a call from the mapping thread, then calls the real `StorageTexture::SaveBeforeUnwatch`.
5. Release the GPU lock and start two threads:
   - **holder:** locks `GpuMutex()`; waits until the mapping thread has run the hook or has returned; then calls `HostImportFor` for the range; then releases the lock.
   - **mapper:** once the holder holds the lock, calls `ImportMappedRanges(context, ranges, generation, false)` without the GPU lock. If that declines, it retries under the GPU lock, as the map observer does (`Lifecycle.cpp:213-215`).
6. **Watchdog:** if both threads haven't finished within 10 s, print which of them got how far and `std::_Exit(1)`. ctest doesn't hang.
7. After both threads finish, require the range to be imported.

**The two cases:**
- `ImportWatch::Unwatch`: the import leaves the write watch, so the hook runs from `beforeUnwatch`.
- `ImportWatch::Watch` with `SetImportWalkFailureForTest(1, 0)`: the import stays watched, its first window walk fails, and the hook runs from `leave` under `Suspension`.
- The second case is checked separately: run first, it is red on its own.

**The red line, on both PR heads:**

```
(m) an import at map that leaves the write watch: deadlock, neither thread finished in 10 s: the import at map ran the unwatch hook and did not return, the thread holding the GPU lock did not get its host import
```

With the second case run first (a temporary reorder, not committed), on #10026's head:

```
(m) an import at map that stays watched and whose first page walk failed: deadlock, neither thread finished in 10 s: the import at map ran the unwatch hook and did not return, the thread holding the GPU lock did not get its host import
```

No assertion is about a placeholder or a throw.
