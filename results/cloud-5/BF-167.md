## What it records

`enum class Demotion { None, Alias, SecondMappingPage, SecondMappingRun, BreakRunMap, BreakRunReset, BreakRunCommit }`.

| field on `View` | set where | meaning |
|---|---|---|
| `demotedBy` | `demote(address, reason, doubled)` | why the view stopped being resident |
| `mapStored` | at the view's creation in `Map` | the physical slot's `stored` when this `Map` ran |
| `mapResident` | the same | whether that `Map` made it resident (`1`) or shared (`0`) |

**Callers of `demote`:**
- `MapAlias` passes `Alias`. BF-163's `aliasDemoted` is now `reason == Alias`, so the fix behaves as before.
- `Map`'s shared path passes `SecondMappingPage` with the doubly mapped page. `demote` stores `SecondMappingPage` on that page and `SecondMappingRun` on every other page of the run it demotes.
- `breakRun` passes the reason `reset` was given: `Map` → `BreakRunMap`, `Reset` → `BreakRunReset`, `Commit` → `BreakRunCommit`.
- **`breakRun(Commit)` can't happen in this code.** `Commit` calls `reset` only for placeholder (`MEM_RESERVE`) spans. A resident run is committed private memory, so neither end of such a span can lie strictly inside a run. The counter should stay 0, and it is there so a non-zero value would show I'm wrong.

**How a write is classified** (the `cause` printed and counted):

| state of the view | printed as |
|---|---|
| `demotedBy` set | its value |
| never demoted, and its `Map` made it shared | `sharedFromStart`. With `mapStored 1` it is the second view of a page that was already stored (for example the new view of a second mapping); with `mapStored 0` it is a page mapped shared from the outset (`GuestArenaMap`, a file) |
| never demoted, but its `Map` made it resident | `none`. This shouldn't occur for a shared view |

**Totals:** printed at the first resumed write, then whenever 10 s have passed since the last totals line, and at the 64th and every 1000th write.

```

```

- **When the 10 s check runs:** on each resumed write; the counts only change then. A crash loses at most the last 10 s of counting, and the per-write lines for the first 64 writes are each flushed.
- **Output path:** every line is `std::fprintf(stderr, ...)` followed by `std::fflush(stderr)`.
  - libc on Windows is compiled with `-include prx/libc/include/HostStandardStreams.hpp` (`core/libs/CMakeLists.txt:86`), where `stderr` is `HostStandardErrorFile_nid_no_patch()`. So these lines go to the kept host standard error, which is `anyps5.log` for a `--windows-gui` build.
  - The header compiles with that `-include` as well.
- **`collect from <caller>`:** the export's `__builtin_return_address(0)`. In a game run it is an address inside `libSceAgcDriver`: `collectWindowsWrites` for `CollectWrites` and its kin, or `walkHints` for `UntrackedHint`.

### The Wine limit, and how the probe works around it

Wine 9.0 maps a 16 KiB shared view only at a 64 KiB boundary (`map shared guest page: Incorrect alignment`, as in BF-109, BF-162 and BF-163). Demoting a resident run of two or more pages maps its second page at +16 KiB, so Wine can't run that.
- **`secondMapping(run)`:** needs another page of a run, so it fails under Wine. The probe shows the failure.
- **`breakRun`:** needs a boundary strictly inside a run. The probe gets one with a single-page run by passing `Reset` or `Map` an address 4 KiB into the page.
  - `breakRun` demotes the run (the page at 64 KiB maps), and `reset` then throws `cannot release part of a host allocation` on the unaligned address.
  - The demoted view stays and is attributed.
  - That unaligned call exists only to reach the real `reset` → `breakRun` → `demote` path under Wine. In a game the boundary is a 16 KiB page inside a multi-page run.

   - **Expect** `comparedWhenShared 0` (the page was armed).

     - `alias`: an import's alias whose import failed or lost its watch; BF-163's fix covers the kept-watched case;
