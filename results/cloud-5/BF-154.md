## The change (`IntermediateRepresentation/src/IrProgram.cpp`)

**One predicate** in the file's anonymous namespace, the union of the five validator blocks:

```cpp
bool carriesMemoryInfo(IrOpcode opcode) {
    return opcode == IrOpcode::ReadConstBuffer || AddressOpcodeInfoOf(opcode).access != AddressAccess::None || BufferComponentCount(opcode) != 0u || SharedComponentCount(opcode) != 0u || ImageOpcodeInfoOf(opcode).access != ImageAccess::None;
}
```

**The printer.** `ProgramToString` appends `memoryToString` to every line whose opcode passes the predicate:
- ` [pc=0x%08x off=0x%x]`: the pc from `MemoryFlags::pc`, the offset from `memoryInfo[index].offset`. Values only, never the index.
- ` [pc=0x%08x mem=?]` when `index >= memoryInfo.size()`, without reading memoryInfo.
- Every other line is byte-for-byte as before.

**The validator.** Each of the five blocks (ReadConstBuffer, address, buffer, shared, image) began with the same check, `if (memoryIndex >= memoryInfo.size()) fail("<op> has an invalid memory-info index")`. That check is now done once, before the first block, as `if (carriesMemoryInfo(op) && index >= size) fail(...)`, with the same message; the per-block copies are gone.
- **Behaviour is identical.** In every block the index check came first, and nothing between blocks can throw. So an out-of-range index fails with the same message at the same point (the first block that applied), and an in-range index runs the same per-kind checks as before.
- `ReadConstBuffer` is also in `BufferComponentCount` (`BufferAccessOf` lists it). The explicit term only mirrors the validator's first block; the union is the same either way.

**`secondaryOffset` (`off2`) is never printed: no IR opcode uses it.**
- The DS pair forms (`ds_read2*`, `ds_write2*`, `ds_wrxchg2*`) are split by translation (`SharedMemoryInstructions.cpp` `dsRead2`, `dsWrite2`, `dsWrxchg2`) into two shared ops. Each op carries its own `offset`, the second with `second.offset = memory.secondaryOffset`.
- `ds_*_src2` moves its source offset into `offset` and zeroes `secondaryOffset`.
- **No reader:** nothing in `SpirvBackend/` or `Optimization/` reads `MemoryInfo::secondaryOffset`. `git grep` finds only the decoder, `SharedMemoryInstructions.cpp` and `ShaderDiskCache.cpp`'s serializer.
- **Why not print it anyway:** the split halves still carry the pair's `secondaryOffset` in their metadata. Printing it would show `off2` on single-offset ops and suggest an access they don't make.
- The pair shows up instead as two lines with different `off=`; the test checks that (below).

**No other dump changes.** Block headers, argument formatting and non-memory lines are unchanged.

## Test: `ir_dump_memory` (`core/libs/tests/IrDumpMemory.cpp`)

**`CheckOffsets`** translates three instructions through `TranslationContext` (the same harness as `ScalarCall`/`ScalarSwappc`'s `TranslateDump`), then requires each opcode's lines, in order, to end with the expected bracket:

| instruction | pc | expected lines |
|---|---|---|
| `s_load_dword s4, s[0:1], 0x54` | 0x12de0 | one `LoadAddressU32 … [pc=0x00012de0 off=0x54]` |
| `s_buffer_load_dwordx4 s[12:15], s[8:11], 0x60` | 0x12de8 | four `ReadConstBuffer … [pc=0x00012de8 off=0x60]`, `off=0x64`, `off=0x68`, `off=0x6c` |
| `ds_read2_b32 v[2:3], v1 offset0:3 offset1:9` | 0x12df0 | two `LoadSharedU32 … [pc=0x00012df0 off=0xc]`, `off=0x24` |

It also requires `  %1 = GetScalarRegister s0 (U32; uses=1)\n` unchanged, so non-memory lines get no bracket.

**`CheckMissingMemoryInfo`** translates the `s_load_dword`, then clears `memoryInfo`. The dump must show ` [pc=0x00000040 mem=?]`, and `ValidateProgram(program, false)` must throw exactly `LoadAddressU32 has an invalid memory-info index`. That covers the refactored validator path.
