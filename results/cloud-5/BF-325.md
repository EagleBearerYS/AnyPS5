### What the GPU-heap stack's space reuse does (#9508 head 82f76ffa75, raghav314's commit)

**Which builds are reusable** (`ShaderResources::noteReusable`, #9508 `ShaderResources.cpp:2779-2789`):
- `spaceReusable = drawBuild && usesBda && bdaReadOnly && !SpaceReuseDisabled() && guestMemory.SpaceOnly() && !HasCopiedWrites() && multisampleSources.empty() && !(bda && LoopGuardEnabled())`.
- Such a build sets `spaceReuse = reusable = true`.
- `SpaceReuseDisabled()` is `!GpuHeapEnabled()` (`:2824-2826`), so **all of this happens only with `APS5_GPU_HEAP`**.
- `SpaceOnly()` (`GuestBufferMemory.cpp:4932`) requires `space != nullptr && lease.empty() && regions.empty() && space->sparseMirrors.empty() && space->copied.empty()`. That is: no own regions, no copies.
- `NeverReusable` exempts read-only BDA programs (no `bdaStores`) from the BDA refusal (`:2819`).

**The proof on a hit** (`Graphics/src/Draw.cpp:1911-1933` in #9508):
1. `RetakeSpace()` (`GuestBufferMemory.cpp:4977-5027`): the same cached space (`releasedSpace.lock()` equals `spaces.current`), with the same device, registry generation and import epoch. It stamps the imports, refreshes the writable and heap mirrors, then re-checks the epoch.
2. **`SnapshotsServedInPlace(snapshots)`** (`GuestBufferMemory.cpp:5029-5039`). For every snapshot of the new draw:
   - `baseOverlap(...) == BaseOverlap::Inside` with a live owner (writable, host-backed or mirror);
   - no unit shadow over it;
   - a `memcmp` against live memory.

   **No index or address match with the build at all.** That is BF-323's S2m rule (a moved snapshot accepted if it is live in the same space), here applied to every snapshot.
3. `Revalidate`, then `MovedReadOnlyBuffers`.
   - The `usesBda` early return is lifted for `spaceReuse` builds (`:5819`), so changed data words go through `PrepareDrawBindings`.
   - That function's `usesBda` return is lifted the same way (`:5945`).
4. After recording, `keepRecordedDraw` releases the space into the recorder (`recorder.Keep(ReleaseSpace())`, `Draw.cpp:2214`), so the build pins nothing between draws.

**What it doesn't cover** (relative to BF-325):
- **The default path (no `APS5_GPU_HEAP`)** is untouched: BDA draws there are still never reusable.
- **No per-use fault record.** There is no `InUse` or use count. Concurrent uses of one build share the build's fault buffer, and the stack doesn't contain #8963 (918b1eeb5d isn't an ancestor of 82f76ffa75). BF-325's S2 is not there.
- **No reuse or refusal counters,** no `CompleteSnapshotWrites` sync, and no tests of reuse across moved snapshots that I found (`SnapshotsServedInPlace` appears in no test file of the stack).
- **Storing BDA programs** stay non-reusable.

**fable-void's fork:** `wip/new-gpu-path` (b6fab39bf6, 10-19; the only fable-void branch past 10-16 besides `fable/main`, which is in upstream main) has 2dc969248a "build shader resources once per program" (10-17): a per-program object cached per device, with a per-use page table and fault record. It is a different structure (no `MovedReadOnlyBuffers`/`PrepareDrawBindings` path, no snapshot proof). PM-086 found it doesn't cherry-pick onto main. Already known from BF-322 §6.
