## 2. Once-per-ABI first use (4eeeeb643)

**The race at dae468d26:**
- The first use swaps `deferredAbis` out under the shader's mutex, unlocks, and prepares.
- A second queue reaching the same shader meanwhile sees an empty list and no entry yet. Under the lock it prepares an artifact of its own for the use (not counted as "own", since its `preparedAtUse` is empty) and pushes it.
- The first use then drops its duplicate entry and matches the second queue's artifact instead of its own.

**The guard:**
- `PreparedShaders` gets `bool deferredPreparing`, guarded by the shader's existing `mutex`. `PrepareDeferredAbis` now takes the caller's `unique_lock`.
- The first caller swaps the list out, sets the flag, unlocks, prepares every deferred ABI, relocks, and publishes all entries together (the per-entry duplicate check is kept).
- A use that finds the flag set waits on the shader's existing `settled` condition until it clears, then matches the published entry.
- An RAII guard clears the flag and calls `notify_all` on every exit, exceptions included.

**Failure:**
- A preparation error is caught per ABI and logged, as before. The flag still clears, so waiters wake.
- If no entry matches, every use, the first one included, prepares its own artifact for the use: the retry. Nobody waits forever.
- The failure path has no dedicated test.

**Hot path:** after the first use the check is `!deferredAbis.empty() || deferredPreparing`. It reads one more bool under the mutex that the lookup already holds: no new lock, atomic or allocation.

**Deadlock check:**
- `PlanRegistered` and `PrepareRegistered` take no snapshot mutex.
- A waiter blocks the same way `AwaitRegisteredPreparation` already blocks on a registration preparation, which runs the same `PrepareRegistered`. So the guard adds no new lock order.

**The test:** `agc_driver_prepared_shaders_abi_deferred_concurrent_lazy` (its own ctest in the same commit; `PreparedShaders.cpp --abi-deferred-concurrent`; the WIN32 `PATH` modification is included).
- Setup:
  - `NarrowConstantStoreFixture` compute shader, registered under `APS5_LAZY_SHADER_PREPARE=1` with its ABI resolved, so the ABI is deferred.
  - Four threads behind a `std::barrier` submit its first dispatch on queues 0x20 to 0x23 at once, each into its own 64 KiB output.
  - Environment: `ANYPS5_NO_SHADER_CACHE=1;APS5_NO_FAILURE_MEMO=1;APS5_LAZY_SHADER_PREPARE=1;APS5_SUSPEND_DRAIN=1`.
- It checks:
  - every output is correct;
  - exactly one first use, which found its artifact, and no own preparation;
  - every front-end build and prepared entry came from the deferred ABI;
  - exactly one deferred entry was used by all four dispatches (the existing matched-entry counter): each queue got the same prepared entry.
- Single-queue reference: `2 front-end builds, 2 prepared entries, 1 first uses, 1 found, 0 own`.

**Red/green, same test, 20 runs each:**
- Red, with `ShaderRegistry.{hpp,cpp}` reverted to dae468d26: **20/20 failed** with
  `four queues making the first use of one deferred ABI at once did not prepare it once (2 front-end builds, 2 prepared entries, 1 first uses, 0 found, 0 own, 0 entries used)`
- Green at 4eeeeb643: **0/20 failed**; every run printed
  `concurrent first use of a deferred ABI: 2 front-end builds, 2 prepared entries, 1 first uses, 1 found, 0 own, 1 entries used`
- On this 4-vCPU VM the race was deterministic: the first use's preparation is slow enough that the other queues always arrive during it.

## 3. The deferred-ABI line (1ba22061e)

- **Switch:** `APS5_PROFILE_DRAW`. `ReportDeferredAbiUses` returns at once unless it is set (`static const bool profile = std::getenv("APS5_PROFILE_DRAW") != nullptr`, the same form `VulkanDevice.cpp` uses).
- **Output:** the line goes through `AgcDriver::ProfilePrint_nid_no_patch`, like the `[rescache]` lines in `VulkanDevice.cpp` and `ShaderResources.cpp`, instead of `std::fprintf(stderr, ...)`.
- The counters keep counting either way; the tests read them, not the line. No test reads the line, so no registration changed.
- Checked on the new test:

  - with `APS5_PROFILE_DRAW=1`: `[shaders] deferred ABIs: 1 prepared at first use, 1 found their artifact there, 0 prepared their own; 1 of the 2 entries prepared from them never matched a use`.
